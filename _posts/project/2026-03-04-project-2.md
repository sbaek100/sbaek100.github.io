# 2부. 주제 선정 및 비즈니스 분석

---
## 1. 비즈니스 모델(Business Model)이란?

### 정의

> **비즈니스 모델(Business Model)** 이란, 조직이 **어떻게 가치를 창출하고, 전달하고, 포착하는지**를 설명하는 틀(Framework)임.

쉽게 말하면 "우리는 누구에게, 무엇을, 어떻게, 얼마에 제공하는가?" 에 대한 답변임.

### 왜 보안 프로젝트에서 비즈니스 모델을 알아야 하나?

보안 위협은 **비즈니스 자산(Asset)** 을 노림. 따라서:
- 비즈니스 모델을 모르면 → 어떤 자산이 중요한지 모름
- 어떤 자산이 중요한지 모르면 → 어디에 보안을 적용해야 하는지 모름
- 결과적으로 → 보안 프로젝트의 방향 자체가 틀어짐

```
[비즈니스 모델 이해의 중요성]

비즈니스 모델 이해
       ↓
핵심 자산(Core Asset) 파악
       ↓
위협(Threat) 식별
       ↓
보안 요구사항(Security Requirements) 도출
       ↓
프로젝트 설계
```

## 2. 비즈니스 모델 캔버스(BMC, Business Model Canvas)

### 개요

> **BMC(Business Model Canvas)** 는 알렉산더 오스터왈더(Alexander Osterwalder)가 2010년에 제안한 비즈니스 모델 시각화 도구임. 9개의 블록으로 비즈니스 전체 구조를 한 장에 표현함.

### BMC 9개 블록 상세 설명
![](/assets/img/posts/2026-03-04-project-2-1772543204048.png)

| 블록 | 설명 | 정보보안 관련 예시 |
|------|------|-----------------|
| **고객 세그먼트(Customer Segments)** | 우리가 가치를 제공하는 대상 | 중소기업 IT 담당자, 개인 사용자 |
| **가치 제안(Value Propositions)** | 고객 문제를 해결하는 방법 | 실시간 위협 탐지, 개인정보 보호 |
| **채널(Channels)** | 고객에게 가치를 전달하는 경로 | SaaS 플랫폼, API, 모바일 앱 |
| **고객 관계(Customer Relationships)** | 고객과 유지하는 관계 유형 | 자동화 알림, 전문가 컨설팅 |
| **수익 흐름(Revenue Streams)** | 돈을 버는 방법 | 구독료, 라이선스 판매 |
| **핵심 자원(Key Resources)** | 비즈니스에 필요한 핵심 자산 | 보안 DB, AI 모델, 전문 인력 |
| **핵심 활동(Key Activities)** | 가치 제공을 위한 핵심 활동 | 위협 인텔리전스 수집, 분석 |
| **핵심 파트너(Key Partners)** | 핵심 공급자 및 파트너 | CVE 제공 기관, 클라우드 벤더 |
| **비용 구조(Cost Structure)** | 사업에 드는 주요 비용 | 서버 비용, 보안 연구 인력 |

### 실습: 정보보안 스타트업 BMC 예시

**주제**: "중소기업 대상 클라우드 보안 모니터링 서비스"

| 블록 | 내용 |
|------|------|
| 고객 세그먼트 | 클라우드를 사용하는 직원 50인 이하 중소기업 |
| 가치 제안 | 저렴한 비용으로 전문가 수준의 보안 모니터링 제공 |
| 채널 | 웹 대시보드, 모바일 앱, Slack 알림 |
| 고객 관계 | 자동화 리포트, 월 1회 보안 리뷰 |
| 수익 흐름 | 월정액 구독(SaaS) |
| 핵심 자원 | SIEM 엔진, 위협 인텔리전스 DB, 보안 전문가 |
| 핵심 활동 | 로그 수집 및 분석, 위협 탐지 룰 업데이트 |
| 핵심 파트너 | AWS, Azure, KISA(한국인터넷진흥원) |
| 비용 구조 | 클라우드 인프라 비용, 인건비, 위협 DB 구독 |

## 3. 정보보안 프로젝트 주제 선정 기준

### 좋은 주제의 조건

| 조건 | 설명 | 나쁜 예 | 좋은 예 |
|------|------|---------|---------|
| **문제 명확성** | 해결하려는 보안 문제가 구체적임 | "보안을 향상시킨다" | "웹 앱의 SQL 인젝션 자동 탐지 시스템 구축" |
| **실현 가능성** | 학기 내에 구현 가능한 범위 | "국가 사이버 방어 시스템 구축" | "소규모 네트워크 IDS 구현" |
| **보안 관련성** | 정보보안의 핵심 요소 포함 | "성적 관리 시스템 개발" | "성적 관리 시스템의 인증 및 접근통제 구현" |
| **측정 가능성** | 결과를 수치로 평가할 수 있음 | "보안이 좋아진다" | "오탐률(False Positive) 5% 이하 달성" |
| **독창성** | 기존 도구의 단순 설치가 아님 | "Kali Linux 설치 및 사용" | "Kali Linux 기반 자동화 취약점 스캔 플랫폼 개발" |

## 4. 주제 선정 프로세스

### 단계별 프로세스

```
1단계: 문제 발굴 (브레인스토밍)
   → 일상에서 보안 문제 찾기
   → 뉴스, CVE 데이터베이스, 보안 컨퍼런스 참조

2단계: 범위 설정 (Scoping)
   → 학기 기간(12~16주) 내 구현 가능한가?
   → 팀원 수와 기술 수준에 맞는가?

3단계: 타당성 검토 (Feasibility)
   → 필요한 도구와 환경이 준비되는가?
   → 참고 자료(논문, 오픈소스)가 있는가?

4단계: 주제 확정 및 문서화
   → 프로젝트 제안서(Project Proposal) 작성
   → 문제 정의, 목표, 기대 효과 명시
```

### 프로젝트 제안서(Project Proposal) 양식

```
## 프로젝트 제안서

### 1. 프로젝트 제목
예: 머신러닝 기반 네트워크 이상 탐지 시스템 개발

### 2. 문제 정의 (Problem Statement)
현재 어떤 보안 문제가 존재하는가?

### 3. 해결 방안 (Proposed Solution)
어떻게 해결할 것인가?

### 4. 기대 결과물 (Deliverables)
- 소프트웨어/시스템:
- 보고서:
- 발표 자료:

### 5. 활용 기술 (Technology Stack)
- 언어:
- 프레임워크:
- 도구:

### 6. 일정 (Schedule)
| 주차 | 활동 |
|------|------|
| 1~2주 | |
| 3~4주 | |

### 7. 팀 역할 분담
| 이름 | 역할 |
|------|------|
```

## 핵심 용어 정리

| 용어 | 영문 | 설명 |
|------|------|------|
| 비즈니스 모델 | Business Model | 가치를 창출·전달·포착하는 방법의 틀 |
| BMC | Business Model Canvas | 9개 블록으로 비즈니스를 시각화하는 도구 |
| 가치 제안 | Value Proposition | 고객에게 제공하는 핵심 가치 |
| 고객 세그먼트 | Customer Segments | 서비스 대상 고객 집단 |
| 수익 흐름 | Revenue Streams | 고객으로부터 수익을 얻는 방법 |
| 핵심 자산 | Core Asset | 비즈니스에서 가장 중요한 보호 대상 자원 |
| 오탐 | False Positive | 정상을 위협으로 잘못 탐지하는 것 |
| 미탐 | False Negative | 실제 위협을 탐지하지 못하는 것 |
| 프로젝트 제안서 | Project Proposal | 프로젝트의 목표·범위·방법을 정의한 문서 |
