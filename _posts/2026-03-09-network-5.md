# OSI 1~4계층 심화 & Packet Tracer Simulation Mode 실습

---

# 1장. 1~4계층 심화 학습

---

## 1.1 1계층 물리 계층 — 비트와 신호

1계층은 데이터를 **물리적 신호로 변환하여 전달**하는 가장 하위 계층임.

**비트(Bit)와 신호 변환:**

```
디지털 데이터:  1  0  1  1  0  0  1  0
                |  |  |  |  |  |  |  |
전기 신호:     +5V 0V +5V +5V 0V 0V +5V 0V
```

**케이블 종류 상세:**

| 종류 | 특징 | Packet Tracer 사용 |
|---|---|---|
| UTP (Straight-Through) | PC↔스위치, PC↔허브 연결 | ✅ Day1에서 사용 |
| UTP (Crossover) | 같은 종류 장비끼리 연결 | ✅ PC↔PC 직접 연결 시 |
| 광케이블 (Fiber) | 장거리, 고속, 빛 신호 | ✅ 라우터 간 연결 가능 |
| Serial (WAN) | 라우터 간 WAN 연결 | ✅ Day4 WAN 구성 시 |

> **Packet Tracer 팁**: Connections 패널에서 `Auto` 케이블을 선택하면 자동으로 올바른 케이블 종류를 선택해줌. 초보자에게 편리함.

---

## 1.2 2계층 데이터링크 계층 — MAC 주소와 스위치 동작

**MAC 주소 테이블 학습 과정:**

스위치는 처음 전원이 켜지면 MAC 주소 테이블이 비어있음.  
데이터가 들어올 때마다 학습하여 테이블을 채워감.

```
[초기 상태] MAC 주소 테이블 (비어있음)
PC0(00:AA:BB) → SW Fa0/1으로 데이터 전송

[1단계] SW가 Fa0/1 포트로 데이터 수신
  → 출발지 MAC(00:AA:BB)이 Fa0/1 포트로 들어왔음을 학습
  → MAC 테이블: 00:AA:BB → Fa0/1 저장

[2단계] 목적지 MAC을 테이블에서 검색
  → 테이블에 없으면: 모든 포트로 전달 (플러딩, Flooding)
  → 테이블에 있으면: 해당 포트로만 전달 (포워딩, Forwarding)
```

**ARP (Address Resolution Protocol):**

ARP는 **IP 주소로 MAC 주소를 알아내는 프로토콜**임.

```
Ping을 보내기 전 ARP 과정:
1. PC0 → 네트워크 전체 브로드캐스트: "192.168.1.20의 MAC 주소가 뭔가요?"
2. PC1 → PC0에게만 유니캐스트: "나야! 내 MAC은 00:BB:CC:DD:EE:FF"
3. PC0 → ARP 테이블에 저장 후 Ping 전송

이 과정이 Ping 첫 번째 실패의 원인임!
```

## 1.3 3계층 네트워크 계층 — IP와 라우팅

**TTL (Time to Live):**

TTL은 패킷이 네트워크에서 무한히 순환하는 것을 방지하는 값임.  
라우터를 하나 거칠 때마다 TTL이 1씩 줄어들며, 0이 되면 패킷을 버림.

```
PC0 (TTL=128) → Router A (TTL=127) → Router B (TTL=126) → Server
```

**Ping 결과의 TTL 의미:**

- `TTL=128`: 같은 LAN 안에서 통신 (Windows 기본값 128)
- `TTL=127`: 라우터 1개를 거쳐서 통신
- `TTL=64`: Linux/Mac 서버 응답 (Linux 기본값 64)

## 1.4 4계층 전송 계층 — TCP 3-Way Handshake

TCP는 데이터 전송 전 **반드시 연결을 먼저 수립**함. 이 과정을 **3-Way Handshake**라고 함.

```
[클라이언트]              [서버]
     |                     |
     |----  SYN  -------->  |   ① 클라이언트: "나 연결하고 싶어" (SYN)
     |                     |
     |<-- SYN + ACK ------  |   ② 서버: "알겠어, 나도 연결할게" (SYN+ACK)
     |                     |
     |----  ACK  -------->  |   ③ 클라이언트: "확인했어, 연결 완료!" (ACK)
     |                     |
     |===== 데이터 전송 ===  |   ④ 이제 데이터 전송 가능
```

- **SYN (Synchronize)**: 연결 요청
- **ACK (Acknowledge)**: 수신 확인
- **SYN+ACK**: 요청 수락 + 상대방 연결 요청

> **왜 3번인가?**  
> 2번이면 서버 → 클라이언트 방향 연결이 확인되지 않음.  
> 3번으로 양방향 연결이 모두 확인됨.

# 2장. Packet Tracer Simulation Mode 실습

---

## 2.1 Simulation Mode란?

Packet Tracer에는 두 가지 동작 모드가 있음.

| 모드 | 설명 |
|---|---|
| **Realtime Mode** (기본) | 실제 네트워크처럼 즉시 동작. 패킷 이동 과정 보이지 않음 |
| **Simulation Mode** | 패킷의 이동을 단계별로 멈추고 관찰 가능. OSI 계층별 PDU 내용 확인 가능 |

> **Simulation Mode = 패킷 트레이서의 핵심 기능**  
> Ping 한 번에 패킷이 어떤 계층에서 어떤 헤더를 가지고 이동하는지 눈으로 직접 확인 가능함.

---

## 2.2 실습 준비

Day 1 과제에서 만든 파일을 열거나, 새로 아래 구성을 만들어야 함.

**필요한 토폴로지:**

```
[PC0]                    [PC1]
IP: 192.168.1.10         IP: 192.168.1.20
    |                         |
    └────────[Switch0]─────────┘
```

---

## 2.3 Step-by-Step 실습 — Simulation Mode 패킷 추적

---

### Step 1 — Simulation Mode 진입

1. Packet Tracer 우측 하단의 **`Simulation`** 탭 클릭
   - 또는 키보드 단축키 `Shift + S`
2. 화면 우측에 **Event List** 패널이 열림
3. 작업 공간의 토폴로지가 느려지거나 멈춘 것처럼 보이면 정상

> **Event List 패널 설명**  
> - `Visible Events`: 어떤 프로토콜의 패킷을 볼지 선택  
> - `Play`, `Back`, `Auto Capture` 버튼으로 패킷 이동 제어

---

### Step 2 — 이벤트 필터 설정 (ICMP만 보기)

처음에는 모든 프로토콜 패킷이 보여 복잡함.  
ICMP(Ping)만 보도록 필터를 설정함.

1. Event List 패널 하단의 **`Edit Filters`** 클릭
2. **`Show All/None`** 버튼으로 전체 해제
3. **`ICMP`** 체크박스만 선택
4. 창 닫기

---

### Step 3 — Ping 패킷 생성

1. `PC0` 더블클릭 → **`Desktop`** 탭 → **`Command Prompt`**
2. 아래 명령어 입력

```
ping 192.168.1.20
```

3. 패킷이 즉시 전송되지 않고 **Event List에 이벤트가 하나 추가**됨

---

### Step 4 — 패킷 단계별 추적

#### 방법 A: 수동 단계 이동 (권장)

1. Event List 하단의 **`Capture/Forward`** 버튼을 한 번씩 클릭
2. 클릭할 때마다 패킷이 한 단계씩 이동함
3. 토폴로지에서 패킷 이동 경로가 **주황색 봉투 아이콘**으로 표시됨

#### 방법 B: 자동 재생

1. **`Auto Capture / Play`** 버튼 클릭
2. 패킷이 자동으로 이동함
3. **`Speed`** 슬라이더로 속도 조절 가능

---

### Step 5 — PDU 내용 확인 (핵심!)

패킷 아이콘(봉투)을 **클릭**하면 PDU(Protocol Data Unit) 정보 창이 열림.

**OSI Model 탭:**

```
Layer 7: Application  — HTTP 요청 등 (ICMP 사용 시 비어있음)
Layer 4: Transport    — ICMP는 전송 계층 없음 (TCP/UDP 아님)
Layer 3: Network      — IP 헤더 (출발지/목적지 IP 확인 가능)
Layer 2: Data Link    — Ethernet 헤더 (출발지/목적지 MAC 확인 가능)
Layer 1: Physical     — 비트 신호 (In/Out Port 정보)
```

> **확인 포인트**  
> - 3계층: SRC IP = 192.168.1.10, DST IP = 192.168.1.20 확인  
> - 2계층: SRC MAC = PC0의 MAC 주소, DST MAC = PC1의 MAC 주소 확인  
> - 스위치에서: 2계층까지만 처리하고 3계층은 처리 안 함 (확인!)

---

### Step 6 — 스위치에서 패킷 확인

패킷이 Switch0에 도달했을 때 클릭하여 PDU 확인.

**확인할 내용:**

1. 스위치는 **2계층(데이터링크)** 장비임
2. PDU 창에서 **Layer 1, Layer 2만 처리**하는 것을 확인
3. Layer 3(IP)는 스위치가 **보지 않음** → 스위치는 MAC 주소만 봄

```
Switch0에서 패킷 처리:
Layer 2: 목적지 MAC 확인 → MAC 테이블 검색 → 해당 포트로 전달
Layer 1: 전기신호로 변환하여 전송
Layer 3 이상: 처리하지 않음 (스위치는 모름)
```

---

### Step 7 — Realtime Mode로 복귀

1. 우측 하단 **`Realtime`** 탭 클릭
2. 정상 동작 모드로 복귀

---

## 2.4 ARP 프로세스 관찰 (선택 실습)

Ping 전에 ARP 요청이 먼저 발생하는 것을 관찰할 수 있음.

1. Simulation Mode 진입
2. `Edit Filters` → **`ICMP` + `ARP`** 두 가지 선택
3. PC0에서 `ping 192.168.1.20` 실행
4. Event List에서 **ARP가 먼저 발생**하고, 그 다음 ICMP 발생 확인

**관찰 결과:**

```
[이벤트 순서]
1. ARP Request  (PC0 → 브로드캐스트): "192.168.1.20 MAC 주소 알려줘!"
2. ARP Reply    (PC1 → PC0): "여기야! MAC = 00:XX:XX:XX:XX:XX"
3. ICMP Echo Request  (PC0 → PC1): Ping 패킷
4. ICMP Echo Reply    (PC1 → PC0): Ping 응답
```

> 이것이 **Ping 첫 번째가 실패하는 이유**임.  
> ARP 요청 → 응답 시간 동안 첫 번째 Ping이 timeout 되는 경우가 있음.
