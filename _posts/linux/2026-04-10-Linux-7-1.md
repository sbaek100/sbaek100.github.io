# 보안 로그 분석 실습 - GitHub 셸 파일 내려받기와 Ubuntu 명령어 30문제

이번 자료는 앞에서 배운 `pwd`, `cd`, `mkdir`, `cat`, `grep`, `sed`, `awk`, `cut`, `sort`, `uniq`, `wc`, `find`, `stat`, `du`, `tar`, `chmod`, `bash` 명령을 실제 시나리오에 연결해서 연습하는 7주차 실습 자료이다.

실습의 시작점은 아래 GitHub 파일이다.

- GitHub 페이지: [setup-security2-env.sh](https://github.com/sbaek100/security-training/blob/main/setup-security2-env.sh)
- Raw 파일: [raw setup-security2-env.sh](https://raw.githubusercontent.com/sbaek100/security-training/main/setup-security2-env.sh)

이 스크립트는 `~/security2` 아래에 다음과 같은 보안 실습용 데이터를 만든다.

- 웹 접근 로그: `access.log`
- 오류 로그: `error.log`
- 인증 로그: `auth.log`
- 시스템 이벤트 로그: `system_events.log`
- 설정 파일: `sshd_config`, `php.ini`, `nginx.conf`, `redis.conf`, `mongod.conf`, `apache2.conf`
- 샘플 증적: `database_dump.sql`, `vulnerability_scan.txt`, `network_capture_summary.txt`, `suid_files.txt`, `backup_script.sh`, `suspicious_script.sh`

> 주의
>
> 이 스크립트는 실서비스 구축용이 아니라 취약점 분석과 로그 분석 연습용이다.
> 개인 Ubuntu VM 또는 실습 서버에서만 실행하고, 운영 서버에서는 실행하지 않는다.
{: .prompt-danger }

## 시나리오

여러분은 사내 보안팀 신입 분석가이다.

웹 서버에서 이상한 접근이 발견되었고, 선임이 GitHub에 올려둔 실습용 셸 스크립트를 내려받아 동일한 환경을 빠르게 재현하라고 지시했다. 여러분의 목표는 다음과 같다.

1. GitHub에서 실습 스크립트를 내려받는다.
2. 스크립트 내용을 확인한다.
3. 실행 권한을 부여하고 실행한다.
4. 생성된 `~/security2` 환경을 Ubuntu 명령어로 조사한다.
5. 의심스러운 흔적을 찾고 요약한다.
6. 마지막에 증적을 압축해 보관한다.

## 사전 실습 준비

아래 명령은 문제를 풀기 전에 한 번만 준비하면 된다.

```bash
cd ~
mkdir -p ~/linux7-lab
cd ~/linux7-lab
pwd
```

예상 화면:

```bash
/home/ubuntu/linux7-lab
```

## 사전 실습 1. `wget`으로 GitHub 셸 파일 내려받기

문제를 풀기 전에 먼저 실습 환경을 직접 만들어 두어야 한다.
아래 명령을 순서대로 실행해서 GitHub의 셸 스크립트를 내려받는다.

```bash
cd ~/linux7-lab
sudo apt update
sudo apt install -y wget
wget https://raw.githubusercontent.com/sbaek100/security-training/main/setup-security2-env.sh
ls -l setup-security2-env.sh
```

예상 화면:

```bash
Saving to: 'setup-security2-env.sh'
-rw-r--r-- 1 ubuntu ubuntu ... setup-security2-env.sh
```

## 실습 마무리 점검

아래 항목을 직접 확인하면 이번 실습을 제대로 끝낸 것이다.

- GitHub raw URL에서 셸 스크립트를 내려받았다.
- `cat`, `grep`, `stat`으로 스크립트 내용을 확인했다.
- `chmod +x` 또는 `bash`로 스크립트를 실행했다.
- `~/security2` 디렉터리 구조를 확인했다.
- `access.log`, `error.log`, `sshd_config`, `redis.conf`, `mongod.conf`, `crontab.txt`를 조사했다.
- 실패 로그인, SQL 오류, 인증 비활성화, 외부 통신 흔적, 수상한 SUID 파일을 찾았다.
- 마지막에 `tar -czvf`로 증적을 압축했다.
