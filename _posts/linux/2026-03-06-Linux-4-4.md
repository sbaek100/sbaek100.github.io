# 리다이렉션 쉽게 이해하기

리눅스에서 명령어를 실행하면 결과가 보통 화면에 나온다.  
그런데 때로는 그 결과를 **파일에 저장**하고 싶고, 때로는 **에러만 따로 모으고** 싶고, 때로는 **화면에도 보면서 파일에도 저장**하고 싶다.

이렇게 **입력과 출력의 방향을 바꾸는 것**을 리다이렉션이라고 한다.

---

# 1장. 먼저 생각할 것: 명령어의 입력과 출력

명령어는 보통 세 가지 흐름을 가진다.

```mermaid
flowchart LR
    A["키보드 입력"] --> B["명령어"]
    B --> C["정상 결과"]
    B --> D["에러 메시지"]
```

- 입력: 키보드로 넣는 값
- 정상 결과: 화면에 보이는 일반 결과
- 에러 메시지: 잘못된 경로, 권한 문제 같은 오류

리눅스에서는 이 셋을 이름으로 구분한다.

| 이름 | 뜻 | 기본 위치 |
|---|---|---|
| `stdin` | 표준 입력 | 키보드 |
| `stdout` | 표준 출력 | 화면 |
| `stderr` | 표준 에러 | 화면 |

> `stdout` 과 `stderr` 는 둘 다 화면에 보이지만, 실제로는 서로 다른 통로이다.
{: .prompt-info }

### 따라하기 한 번

```bash
# 정상 결과와 에러를 일부러 같이 만들어 보는 예제
ls /etc/passwd /no_such_file
```

정상 결과 한 줄과 에러 문장이 함께 보이면, `stdout` 과 `stderr` 가 둘 다 화면으로 나오고 있다는 뜻이다.

---

# 2장. stdout - 정상 결과를 파일에 저장하기

## 2.1 `>` 는 덮어쓰기

```bash
# 현재 폴더 목록을 화면 대신 list.txt 파일에 저장
ls > list.txt
```

뜻:

- `ls` 결과를 화면 대신 `list.txt` 에 저장한다.
- 파일이 이미 있으면 기존 내용을 지우고 새로 쓴다.

### 따라하기 한 번

```bash
# 현재 작업 폴더 경로를 here.txt에 저장
pwd > here.txt

# 저장된 내용을 다시 화면에 확인
cat here.txt
```

현재 폴더 경로가 `here.txt` 안에 들어 있으면 성공이다.

## 2.2 `>>` 는 이어쓰기

```bash
# 현재 날짜/시간을 log.txt 뒤에 추가
date >> log.txt

# 한 번 더 추가
date >> log.txt
```

뜻:

- 기존 파일 뒤에 내용을 계속 추가한다.

### 따라하기 한 번

```bash
# 첫 줄 저장 (새 파일 만들기)
echo "first" > memo.txt

# 두 번째 줄 이어서 추가
echo "second" >> memo.txt

# 파일 내용 확인
cat memo.txt
```

`first` 와 `second` 두 줄이 모두 보이면 성공이다.

---

# 3장. stdin - 파일 내용을 입력으로 사용하기

## 3.1 `<` 는 파일을 입력으로 넣기

```bash
# memo.txt 내용을 wc -l 명령의 입력으로 넣어서 줄 수 세기
wc -l < memo.txt
```

뜻:

- `memo.txt` 내용을 `wc -l` 에 입력으로 넣는다.
- 줄 수를 센다.

### 따라하기 한 번

```bash
# input.txt 파일 만들기
cat > input.txt << 'EOF'
apple
banana
cherry
EOF

# input.txt를 입력으로 넣어 줄 수 세기
wc -l < input.txt
```

결과가 `3` 이면 성공이다.

---

# 4장. stderr - 에러만 따로 저장하기

## 4.1 `2>` 는 에러 저장

```bash
# 없는 경로에서 발생한 에러만 errors.txt에 저장
ls /good /bad 2> errors.txt
```

뜻:

- 에러 메시지만 `errors.txt` 에 저장한다.

초보자에게는 아래 예제가 더 이해하기 쉽다.

### 따라하기 한 번

```bash
# 정상 파일 1개와 없는 파일 1개를 같이 확인
# 이때 에러 메시지만 errors.txt에 저장
ls /etc/passwd /no_such_file 2> errors.txt

# 에러 파일 내용 확인
cat errors.txt
```

없는 파일에 대한 에러 문장이 보이면 성공이다.

## 4.2 `/dev/null` 은 버리는 곳

```bash
# 검색 중 생기는 권한 에러는 버리고
# 정상 검색 결과만 화면에 출력
find / -name "passwd" 2>/dev/null
```

뜻:

- 에러는 보이지 않게 버리고
- 정상 결과만 화면에 보이게 한다.

### 따라하기 한 번

```bash
# / 전체에서 passwd라는 이름의 파일 검색
# 에러 메시지는 /dev/null로 보내서 화면에 안 보이게 함
find / -name "passwd" 2>/dev/null
```

권한 에러 문장이 줄어들면 성공이다.

---

# 5장. stdout 과 stderr 를 함께 생각하기

명령어는 정상 결과도 만들고 에러도 만들 수 있다.

예를 들어:

```bash
# 정상 결과와 에러를 동시에 만들기 위한 예제
ls /etc/passwd /no_such_file
```

이 명령은

- `/etc/passwd` 는 정상 결과
- `/no_such_file` 는 에러

를 동시에 만든다.

그래서 둘을 따로 저장할 수도 있고, 같이 저장할 수도 있다.

### 따라하기 한 번

```bash
# 하나는 있는 파일, 하나는 없는 파일
# 결과와 에러가 함께 나온다는 점을 확인
ls /etc/passwd /no_such_file
```

이 명령을 실행했을 때 한쪽은 정상 결과, 한쪽은 에러라는 감각만 잡아도 충분하다.

---

# 6장. 정상 결과와 에러를 따로 저장하기

```bash
# 정상 결과는 out.txt에 저장
# 에러 메시지는 err.txt에 따로 저장
ls /etc/passwd /no_such_file > out.txt 2> err.txt
```

뜻:

- 정상 결과는 `out.txt`
- 에러 메시지는 `err.txt`

### 따라하기 한 번

```bash
# 정상 결과와 에러를 서로 다른 파일로 나누어 저장
ls /etc/passwd /no_such_file > out.txt 2> err.txt

# 정상 결과 파일 확인
cat out.txt

# 에러 파일 확인
cat err.txt
```

`out.txt` 에는 `/etc/passwd`, `err.txt` 에는 에러 문장이 있으면 성공이다.

---

# 7장. 정상 결과와 에러를 같은 파일에 저장하기

## 7.1 `2>&1` 이란?

이 표현은 처음 보면 어렵지만, 초보자는 이렇게 기억하면 된다.

> `stderr` 도 `stdout` 이 가는 곳으로 같이 보내라

```bash
# 정상 결과를 all.txt로 보내고
# stderr도 stdout이 가는 같은 곳(all.txt)으로 보냄
ls /etc/passwd /no_such_file > all.txt 2>&1
```

뜻:

- 정상 결과도 `all.txt`
- 에러도 `all.txt`

### 따라하기 한 번

```bash
# 정상 결과와 에러를 한 파일에 같이 저장
ls /etc/passwd /no_such_file > all.txt 2>&1

# 한 파일에 함께 들어갔는지 확인
cat all.txt
```

정상 결과와 에러 문장이 한 파일 안에 같이 보이면 성공이다.

## 7.2 순서가 중요하다

아래처럼 쓰는 것이 올바른 형태이다.

```bash
# 1) 정상 결과를 먼저 파일로 보내고
# 2) 에러도 그 결과가 가는 같은 곳으로 보낸다
명령어 > 파일 2>&1
```

처음에는 이유를 깊게 따지기보다, **같이 저장하고 싶으면 이 순서를 그대로 외우는 것**이 좋다.

### 따라하기 한 번

```bash
# 올바른 순서로 함께 저장
ls /etc/passwd /no_such_file > right_order.txt 2>&1

# 파일 안에 결과와 에러가 모두 들어 있는지 확인
cat right_order.txt
```

정상 결과와 에러가 한 파일에 같이 들어 있으면 올바른 순서로 실행된 것이다.

# 8장. `&>` 는 더 짧게 쓰는 방법

```bash
# 정상 결과와 에러를 모두 all2.txt에 저장
ls /etc/passwd /no_such_file &> all2.txt
```

이 명령은 아래와 거의 같은 뜻이다.

```bash
# 위 명령을 풀어서 쓰면 이런 뜻
ls /etc/passwd /no_such_file > all2.txt 2>&1
```

### 따라하기 한 번

```bash
# 짧은 문법(&>)으로 한 파일에 모두 저장
ls /etc/passwd /no_such_file &> all2.txt

# 저장 결과 확인
cat all2.txt
```

결과와 에러가 함께 저장되면 성공이다.

---

# 9장. tee - 화면에도 보고 파일에도 저장하기

## 9.1 tee란?

보통 `>` 를 쓰면 화면에는 안 나오고 파일에만 저장된다.  
그런데 `tee` 를 쓰면 **화면에도 보이고 파일에도 저장**된다.

```bash
# ls 결과를 화면에도 보여주고
# 동시에 list.txt에도 저장
ls | tee list.txt
```

뜻:

- `ls` 결과를 화면에 보여주고
- 동시에 `list.txt` 에도 저장

### 따라하기 한 번

```bash
# 현재 날짜/시간을 화면에 출력하면서
# today.txt 파일에도 저장
date | tee today.txt

# 저장된 내용 다시 확인
cat today.txt
```

날짜가 화면에 보이고, 파일에도 저장되어 있으면 성공이다.

# 10장. 자주 쓰는 리다이렉션 기호 정리

| 기호 | 쉬운 뜻 | 예 |
|---|---|---|
| `>` | 결과를 파일에 새로 저장 | `ls > a.txt` |
| `>>` | 결과를 파일 뒤에 추가 | `date >> log.txt` |
| `<` | 파일 내용을 입력으로 사용 | `wc -l < a.txt` |
| `2>` | 에러만 파일에 저장 | `ls bad 2> err.txt` |
| `2>/dev/null` | 에러 버리기 | `find / 2>/dev/null` |
| `2>&1` | 에러를 결과와 같은 곳으로 보내기 | `cmd > all.txt 2>&1` |
| `&>` | 결과와 에러를 함께 저장 | `cmd &> all.txt` |

### 따라하기 한 번

```bash
# sample.txt에 한 줄 저장
echo "hello" > sample.txt

# 파일 내용을 입력으로 넣어서 줄 수 세기
wc -l < sample.txt
```

각 기호를 외우기 어렵다면, 먼저 `>` 와 `<` 만 직접 해보며 방향이 바뀐다는 느낌을 잡으면 된다.

# 11장. 아주 쉬운 실전 예

## 11.1 결과만 저장

```bash
# 현재 폴더 목록을 files.txt에 저장
ls > files.txt
```

### 따라하기 한 번

```bash
# 결과를 파일로 보내기
ls > files.txt

# 파일 내용 확인
cat files.txt
```

## 11.2 에러만 저장

```bash
# 없는 파일에 대한 에러만 err.txt에 저장
ls /no_such_file 2> err.txt
```

### 따라하기 한 번

```bash
# 에러 메시지를 err.txt로 보내기
ls /no_such_file 2> err.txt

# 저장된 에러 확인
cat err.txt
```

## 11.3 결과와 에러를 따로 저장

```bash
# 정상 결과는 out.txt
# 에러는 err.txt
ls /etc/passwd /no_such_file > out.txt 2> err.txt
```

### 따라하기 한 번

```bash
# 두 파일로 나누어 저장
ls /etc/passwd /no_such_file > out.txt 2> err.txt

# 정상 결과 보기
cat out.txt

# 에러 보기
cat err.txt
```

## 11.4 결과와 에러를 함께 저장

```bash
# 정상 결과와 에러를 한 파일에 저장
ls /etc/passwd /no_such_file > all.txt 2>&1
```

### 따라하기 한 번

```bash
# 한 파일에 모두 저장
ls /etc/passwd /no_such_file > all.txt 2>&1

# 저장 결과 확인
cat all.txt
```

## 11.5 화면에도 보고 파일에도 저장

```bash
# 디스크 사용량을 화면에 보여주면서
# disk.txt 파일에도 저장
df -h | tee disk.txt
```

### 따라하기 한 번

```bash
# 화면에도 출력하고 파일에도 저장
df -h | tee disk.txt

# 저장된 파일 내용 확인
cat disk.txt
```

# 12장. 핵심만 다시 기억하기

- `>` : 결과를 파일에 저장
- `>>` : 결과를 파일 끝에 추가
- `<` : 파일 내용을 입력으로 넣기
- `2>` : 에러를 파일에 저장
- `/dev/null` : 버리는 곳
- `2>&1` : 에러도 결과와 같은 곳으로 보내기
- `tee` : 화면에도 보고 파일에도 저장

# 13장. 다음에 직접 해볼 것

아래 명령을 직접 한 번씩 입력해 보면 감이 빨리 잡힌다.

```bash
# 현재 폴더 경로 저장
pwd > here.txt

# 파일 새로 만들기
echo "hello" > a.txt

# 같은 파일 뒤에 내용 추가
echo "world" >> a.txt

# 파일 내용을 입력으로 넣어 줄 수 세기
wc -l < a.txt

# 정상 결과와 에러를 따로 저장
ls /etc/passwd /no_such_file > out.txt 2> err.txt

# 정상 결과와 에러를 한 파일에 함께 저장
ls /etc/passwd /no_such_file > all.txt 2>&1

# 화면에도 보면서 파일에도 저장
date | tee today.txt
```
