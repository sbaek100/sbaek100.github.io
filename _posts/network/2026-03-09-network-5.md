# Simulation Mode로 패킷 흐름 직접 보기

4강에서 배운 OSI 7계층이 실제로 어떻게 동작하는지, Packet Tracer의 Simulation Mode로 눈으로 확인함.  
패킷이 어디서 어디로 가는지, 각 장비에서 무슨 일이 일어나는지 한 단계씩 따라가 봄.

---

## 오늘 실습 구성

```
[PC0]                    [PC1]
IP: 192.168.1.10         IP: 192.168.1.20
    |                         |
    └────────[Switch0]─────────┘
```

이전 시간에 만든 파일을 그대로 사용함.  
없으면 PC 2대 + Switch 1대로 새로 만들고 IP 주소를 설정함.

---

# 1장. Simulation Mode란?

---

Packet Tracer에는 두 가지 동작 모드가 있음.

| 모드 | 설명 |
|---|---|
| **Realtime Mode** (기본) | 실제 네트워크처럼 즉시 동작. 패킷이 어디로 가는지 안 보임 |
| **Simulation Mode** | 패킷이 한 단계씩 이동. 각 장비에서 무슨 일이 일어나는지 볼 수 있음 |

> Simulation Mode = 패킷을 슬로우모션으로 추적하는 기능

---

# 2장. Simulation Mode 시작하기

---

## Step 1 — Simulation Mode 진입

1. Packet Tracer 화면 **오른쪽 아래** 를 봄
2. `Realtime` 옆에 **`Simulation`** 탭이 있음
3. **`Simulation`** 탭 클릭

   ![](/assets/img/posts/2026-03-09-network-5-1774428096702.png)

4. 오른쪽에 **Event List** 창이 열림
5. 작업 화면의 시간이 멈춘 것처럼 보이면 정상

---

## Step 2 — Event List 창 구성 이해하기

Event List 창에서 자주 쓰는 버튼:

| 버튼 | 역할 |
|---|---|
| **Capture/Forward** | 패킷을 딱 한 단계 앞으로 이동 |
| **Auto Capture / Play** | 패킷이 자동으로 계속 이동 |
| **Reset Simulation** | 지금까지 이동한 패킷 기록을 전부 지우고 처음부터 |
| **Edit Filters** | 어떤 종류의 패킷을 볼지 선택 |

> 처음엔 **`Capture/Forward`** 를 한 번씩 눌러가며 천천히 보는 것이 가장 좋음

---

## Step 3 — 필터 설정 (ARP + ICMP만 보기)

처음에 모든 프로토콜을 켜두면 화면이 너무 복잡해짐.  
Ping과 관련된 것만 보도록 필터를 설정함.

1. Event List 아래쪽 **`Edit Filters`** 버튼 클릭

   ![](/assets/img/posts/2026-03-09-network-5-1774428145769.png)

2. **`Show All/None`** 버튼 클릭 → 전부 체크 해제됨
3. **`ICMP`** 체크박스 클릭 (Ping 패킷)
4. **`ARP`** 체크박스 클릭 ("어디 있어?" 물어보는 패킷)

   ![](/assets/img/posts/2026-03-09-network-5-1774428178719.png)

5. 창 닫기

---

# 3장. Ping 패킷 보내기

---

## Step 4 — Ping 명령 입력

1. **PC0** 더블클릭
2. **Desktop** 탭 → **Command Prompt** 클릭
3. 아래 명령어 입력 후 엔터

```
ping 192.168.1.20
```

   ![](/assets/img/posts/2026-03-09-network-5-1774428258215.png)

4. 창을 닫지 않고 그대로 둠
5. Event List를 보면 **이벤트가 1개 추가됨**

   ![](/assets/img/posts/2026-03-09-network-5-1774428264936.png)

> Ping 명령을 입력해도 바로 보내지 않고 대기 상태가 됨.  
> `Capture/Forward` 를 눌러야 한 단계씩 움직임.

---

# 4장. 패킷 한 단계씩 따라가기

---

## 4.1 전체 흐름 미리 보기

Ping 하나가 완성되기까지 아래 순서로 일어남.

```
① ARP Request  — PC0가 "PC1 어디 있어?" 전체에 물어봄
② ARP Reply    — PC1이 "나 여기!" 하고 PC0에게 대답
③ ICMP Echo Request  — PC0가 PC1에게 Ping 보냄
④ ICMP Echo Reply    — PC1이 PC0에게 Ping 응답
```

---

## Step 5 — ARP Request 관찰 (PC0 → Switch0 → 전체)

**`Capture/Forward`** 버튼을 한 번 클릭함.

작업 화면에서 **PC0에서 봉투 모양 아이콘** 이 Switch0으로 이동함.

봉투 아이콘을 **클릭** 하면 **PDU Information** 창이 열림.

   ![](/assets/img/posts/2026-03-09-network-5-1774428390119.png)

### PDU Information 창 — OSI Model 탭

탭 이름 | 설명
---|---
**OSI Model** | 각 계층에서 무슨 처리가 일어났는지
**Inbound PDU Details** | 이 장비로 들어온 패킷의 내용
**Outbound PDU Details** | 이 장비에서 나가는 패킷의 내용

**OSI Model 탭에서 확인할 것:**

- Layer 3 (Network): SRC IP = `192.168.1.10`, DST IP = `192.168.1.20`
- Layer 2 (Data Link): DST MAC = `FFFF.FFFF.FFFF` ← 이게 핵심!

> `FFFF.FFFF.FFFF` 는 **Broadcast 주소**임.  
> "이 LAN 안의 모든 PC에게 보내" 라는 뜻임.  
> PC0가 PC1의 MAC 주소를 아직 모르기 때문에 전부에게 물어보는 것임.

창을 닫고 **`Capture/Forward`** 를 한 번 더 누름.

---

## Step 6 — Switch0에서 Broadcast 퍼지는 장면

이번엔 Switch0에서 봉투가 **PC1과 PC0 양쪽으로 퍼지는 것** 이 보임.

Switch0 위에 도착한 봉투를 클릭함.

**OSI Model 탭에서 확인할 것:**

- Layer 1, Layer 2만 처리됨
- Layer 3(IP) 이상은 처리하지 않음

> 스위치는 IP 주소를 볼 줄 모름.  
> MAC 주소(2계층)만 보고 전달함.  
> 처음엔 PC1의 MAC 주소를 모르기 때문에 연결된 모든 포트로 전달함.

---

## Step 7 — ARP Reply 관찰 (PC1 → PC0)

**`Capture/Forward`** 를 계속 누르면 PC1에서 봉투가 생겨 PC0 방향으로 돌아옴.

PC1에서 나온 봉투를 클릭함.

**OSI Model 탭에서 확인할 것:**

- Layer 2: DST MAC = PC0의 MAC 주소 (이번엔 Broadcast가 아님!)
- Layer 3: SRC IP = `192.168.1.20`, DST IP = `192.168.1.10`

> PC1이 "나는 여기 있고, 내 MAC 주소는 이거야" 하고  
> PC0에게만 **직접(Unicast)** 대답하는 것임.

---

## Step 8 — ICMP Echo Request 관찰 (Ping 본체)

ARP가 끝나고 나면 이제 진짜 Ping 패킷이 출발함.

PC0에서 새 봉투가 나옴. 이 봉투를 클릭함.

**OSI Model 탭에서 확인할 것:**

- Layer 3: SRC IP = `192.168.1.10`, DST IP = `192.168.1.20`
- Layer 2: DST MAC = PC1의 MAC 주소 (이번엔 Broadcast 아님!)

> ARP 덕분에 이제 PC0가 PC1의 MAC 주소를 알게 됐음.  
> 그래서 이번엔 PC1에게만 바로 보냄.

**`Capture/Forward`** 를 눌러 Switch0 → PC1까지 이동시킴.

Switch0에서 봉투를 클릭해 확인:

- 이번엔 봉투가 PC1 **한 쪽에만** 전달됨
- ARP 때와 달리 Broadcast로 퍼지지 않음

---

## Step 9 — ICMP Echo Reply 관찰 (Ping 응답)

PC1에 봉투가 도착하면 PC1이 응답 봉투를 만들어 PC0 쪽으로 보냄.

PC1에서 나온 봉투를 클릭함.

**OSI Model 탭에서 확인할 것:**

- 이번엔 SRC IP와 DST IP가 반대로 바뀜
  - SRC IP = `192.168.1.20` (PC1)
  - DST IP = `192.168.1.10` (PC0)

**`Capture/Forward`** 를 눌러 PC0까지 돌아오는 것 확인.

PC0의 Command Prompt 창에서:

```
Reply from 192.168.1.20: bytes=32 time<1ms TTL=128
```

이 한 줄이 나오면 Ping 1개가 완료된 것임.

---

## Step 10 — 나머지 Ping 3개도 확인

Ping은 기본적으로 4번 보냄.  
**`Capture/Forward`** 또는 **`Auto Capture / Play`** 로 나머지 3개도 진행함.

두 번째 Ping부터 확인할 것:

- ARP 과정이 **사라짐** (이미 MAC 주소를 알기 때문)
- ICMP만 바로 보내고 받음
- Event List에서 ARP 없이 ICMP만 오가는 것 확인

# 6장. ARP 과정만 따로 확인하기 (심화)

---

ARP가 처음엔 Broadcast, 두 번째엔 Unicast인 것을 비교해서 확인하는 실습임.

1. **`Reset Simulation`** 클릭 (기존 이벤트 전부 초기화)
2. Edit Filters → **ARP만** 체크 (ICMP 해제)
3. PC0에서 `ping 192.168.1.20` 입력
4. **`Capture/Forward`** 눌러 ARP 패킷만 추적

**확인할 장면:**

| 단계 | 봉투 방향 | DST MAC |
|---|---|---|
| ARP Request (PC0 → Switch0) | 전체로 퍼짐 | `FFFF.FFFF.FFFF` (Broadcast) |
| ARP Reply (PC1 → PC0) | PC0에게만 | PC0의 MAC 주소 (Unicast) |

   ![](/assets/img/posts/2026-03-09-network-5-1774429099806.png)

> 이것이 첫 번째 Ping이 가끔 실패하는 이유임.  
> ARP 요청과 응답이 오가는 동안 시간이 걸려 첫 번째 Ping이 timeout 되는 경우가 생김.

# 7장. 스위치 직접 다루기 — CLI와 MAC 테이블

---

## 7.1 스위치 CLI란?

스위치도 내부에 운영체제가 있음.  
**CLI(Command Line Interface)** 를 통해 스위치에 명령어를 입력해서 상태를 확인하거나 설정을 바꿀 수 있음.

Packet Tracer에서는 스위치를 더블클릭하면 CLI 탭에 접근할 수 있음.

---

## Step 12 — 스위치 CLI 접속

1. **Realtime Mode** 상태에서 진행함
2. **Switch0** 더블클릭
3. 상단 탭에서 **`CLI`** 클릭
4. 검은 화면에 아래 메시지가 보임

```
Would you like to enter the initial configuration dialog? [yes/no]:
```

5. `no` 입력 후 엔터
6. 아래와 같은 프롬프트가 나타남

```
Switch>
```

> `Switch>` 가 보이면 CLI에 접속된 것임.  
> 이 상태는 **일반 사용자 모드** 로, 조회 명령만 가능함.

---

## 7.2 CLI 모드 구조

스위치 CLI에는 3가지 모드가 있음.

| 모드 | 프롬프트 | 설명 |
|---|---|---|
| 일반 사용자 모드 | `Switch>` | 기본 상태 확인만 가능 |
| 관리자 모드 | `Switch#` | 모든 조회 명령 사용 가능 |
| 설정 모드 | `Switch(config)#` | 스위치 설정 변경 가능 |

**관리자 모드로 전환:**

```
Switch> enable
Switch#
```

> `enable` 명령을 입력하면 `Switch>` 가 `Switch#` 으로 바뀜.  
> 앞으로 나오는 명령어는 모두 `Switch#` 상태에서 입력함.

---

## Step 13 — 포트 연결 상태 확인

스위치에 어떤 포트가 연결됐는지 확인하는 명령어임.

```
Switch# show interfaces status
```

결과 예시:

```
Port      Name               Status       Vlan       Duplex  Speed Type
Fa0/1                        connected    1          a-full  a-100 10/100BaseTX
Fa0/2                        connected    1          a-full  a-100 10/100BaseTX
Fa0/3                        notconnect   1          auto    auto  10/100BaseTX
...
```

| 항목 | 설명 |
|---|---|
| **Port** | 포트 이름 (Fa = FastEthernet) |
| **Status** | `connected` = 케이블 연결됨 / `notconnect` = 연결 안 됨 |
| **Vlan** | VLAN 번호 (지금은 1번만 있음) |
| **Speed** | 연결 속도 |

> PC0가 Fa0/1, PC1이 Fa0/2에 연결됐다면 두 줄이 `connected` 로 보임.

---

## Step 14 — MAC 주소 테이블 확인

스위치가 기억하고 있는 PC들의 MAC 주소 목록을 보는 명령어임.

```
Switch# show mac-address-table
```

**Ping을 한 번도 보내지 않은 상태:**

```
Mac Address Table
------------------------------------------
Vlan    Mac Address       Type    Ports
----    -----------       ----    -----
```

아무것도 없음. 스위치가 아직 아무것도 모르는 상태임.

**Ping을 한 번 보낸 후:**

```
Mac Address Table
------------------------------------------
Vlan    Mac Address       Type    Ports
----    -----------       ----    -----
   1    00d0.bc12.3456    DYNAMIC Fa0/1
   1    00e0.a3cd.7890    DYNAMIC Fa0/2
```

| 항목 | 설명 |
|---|---|
| **Vlan** | 어느 VLAN에 속한 주소인지 |
| **Mac Address** | PC의 고유 MAC 주소 |
| **Type** | `DYNAMIC` = 통신 중에 자동으로 학습한 주소 |
| **Ports** | 이 MAC 주소가 연결된 포트 |

> `Fa0/1` 에 PC0의 MAC, `Fa0/2` 에 PC1의 MAC이 기록됨.  
> 스위치는 이 표를 보고 패킷을 어느 포트로 보낼지 결정함.

---

## Step 15 — MAC 테이블이 채워지는 과정 직접 확인

MAC 테이블이 비어있다가 통신 후 채워지는 것을 직접 확인함.

### ① MAC 테이블 초기화

```
Switch# clear mac-address-table dynamic
```

확인:

```
Switch# show mac-address-table
```

아무것도 없어야 함.

### ② PC0에서 Ping 보내기

**PC0** 더블클릭 → **Desktop** → **Command Prompt**

```
ping 192.168.1.20
```

### ③ MAC 테이블 다시 확인

Ping이 끝난 뒤 Switch0 CLI로 돌아와서:

```
Switch# show mac-address-table
```

이번엔 PC0, PC1의 MAC 주소가 테이블에 채워져 있음.

> 스위치가 ARP 패킷을 통해 "Fa0/1 포트에서 이 MAC이 왔구나" 하고 자동으로 학습한 것임.

---

## 7.3 자주 쓰는 스위치 명령어 정리

| 명령어 | 설명 |
|---|---|
| `enable` | 관리자 모드로 전환 |
| `show interfaces status` | 포트 연결 상태 확인 |
| `show mac-address-table` | MAC 주소 테이블 확인 |
| `clear mac-address-table dynamic` | MAC 테이블 초기화 |
| `show running-config` | 현재 스위치 설정 전체 보기 |
| `exit` | 이전 모드로 돌아가기 |

> 명령어가 너무 길면 앞 글자만 입력하고 **Tab** 키를 누르면 자동완성 됨.  
> 예: `sh mac` + Tab → `show mac-address-table`

# 오늘 실습 정리

| 확인 항목 | 내용 |
|---|---|
| Simulation Mode 진입 | 오른쪽 아래 Simulation 탭 |
| 이벤트 필터 설정 | Edit Filters → ICMP, ARP 선택 |
| 패킷 단계 이동 | Capture/Forward 버튼 |
| PDU 내용 확인 | 봉투 아이콘 클릭 → OSI Model 탭 |
| ARP Broadcast | DST MAC = FFFF.FFFF.FFFF |
| ARP Reply | DST MAC = PC0 MAC (Unicast) |
| ICMP 전송 | ARP 이후 MAC 알고 나서 바로 전달 |
| 스위치 동작 | Layer 1~2만 처리, Layer 3 처리 안 함 |
| 스위치 CLI 접속 | Switch 더블클릭 → CLI 탭 → enable |
| 포트 상태 확인 | show interfaces status |
| MAC 테이블 확인 | show mac-address-table |
| MAC 테이블 초기화 | clear mac-address-table dynamic |

> **다음 강의 예고**  
> 6강에서는 실제 Windows PC에서 친구 PC에게 Ping을 보내고 파일을 주고받는 실습을 함.
