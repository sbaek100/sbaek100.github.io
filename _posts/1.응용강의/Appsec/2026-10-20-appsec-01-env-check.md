>
> 소요 시간은 15~20분이며, **한 번만 하면 학기 내내 다시 하지 않습니다.**
{: .prompt-info }

## 0. 누가 이 글을 봐야 하나

| 상황 | 할 일 |
|---|---|

## 1. 이 과정이 전제하는 환경 규격

**02강부터의 모든 실습이 아래 값을 그대로 사용합니다.** 하나라도 다르면 명령을 복사해 붙여 넣었을 때 동작하지 않습니다.

| 항목 | 값 | 비고 |
|---|---|---|
| 가상화 프로그램 | VirtualBox | 0-2에서 설치 |
| **Ubuntu 서버** | **`192.168.56.30`** | 서비스를 올리는 대상 |
| Ubuntu 계정 / 호스트명 | **`student`** / `ubuntu-lab` | 0-2에서 지정 |
| Ubuntu 버전 | Ubuntu Server 24.04 LTS | 그래픽 환경 없음 |
| **Kali Linux** | **`192.168.56.10`** | 점검·공격 측. **이 과정에서는 필수** |
| 어댑터 1 | NAT | 인터넷(패키지 설치) |
| 어댑터 2 | 호스트 전용 어댑터 | 실습망 `192.168.56.0/24` |

```
        [ 윈도우 호스트 192.168.56.1 ]
                    │
   ┌────────────────┴────────────────┐
   │   호스트 전용 네트워크 192.168.56.0/24
   └───┬────────────────────────┬────┘
       │                        │
 ┌─────┴──────┐          ┌──────┴───────┐
 │ Kali       │  점검·공격 │ Ubuntu       │
 │ .56.10     │ ────────→ │ .56.30       │
 │ (도구·GUI) │           │ (FTP·DNS·웹) │
 └────────────┘          └──────────────┘
```

> **주소 대역이 `192.168.56.x`인 이유**
> VirtualBox는 호스트 전용 네트워크에 사용할 수 있는 주소를 `192.168.56.0/21`로 제한합니다. 이 범위를 벗어난 주소는 적용되지 않으므로, 다른 대역을 임의로 쓸 수 없습니다. 자세한 내용은 **0-1 제3절**에 있습니다.
{: .prompt-warning }

## 2. 점검 ① — Ubuntu 서버 확인

Ubuntu에 로그인하여(윈도우 터미널에서 `ssh student@192.168.56.30`) 다음을 확인합니다.

```bash
# === Ubuntu에서 실행 ===
whoami                                   # student
hostname                                 # ubuntu-lab
ip -br addr | grep 192.168.56            # 192.168.56.30/24
grep PRETTY /etc/os-release              # Ubuntu 24.04.x LTS
systemctl is-active ssh.socket           # active
```

- `192.168.56.30`이 보이지 않으면 **0-3 제2절**의 netplan 설정을 다시 수행합니다.
- 마지막 줄에서 `ssh`(서비스)가 아니라 **`ssh.socket`** 을 조회한 이유는, Ubuntu 24.04가 소켓 활성화 방식을 쓰기 때문입니다. 접속이 없을 때 `ssh.service`는 `inactive`가 정상입니다.

## 3. 점검 ② — Kali Linux 준비 (이 과정의 필수 항목)

> **리눅스 기초 0강에서는 Kali가 "선택"이었습니다.** 그러나 **이 과정에서는 필수입니다.** 와이어샤크로 패킷을 들여다보고(02-3·06-3), 브라우저로 HTTPS 경고를 확인하고(06-2), 서버로 접속해 공격을 재현하는 작업이 모두 Kali에서 이루어지기 때문입니다.
{: .prompt-danger }

### 3.1 Kali가 없다면 — 설치

**0-2 제3절**의 절차를 그대로 수행합니다. 요약하면 다음과 같습니다.

1. [Kali 다운로드 페이지](https://www.kali.org/get-kali/)에서 **[Virtual Machines] → VirtualBox** 용 `.7z` 파일을 받는다.
2. 7-Zip으로 압축을 풀면 `.vbox`와 `.vdi` 파일이 나온다.
3. VirtualBox 관리자에서 **[추가(Add)]** 로 `.vbox` 파일을 등록한다.
4. 기본 계정 `kali` / `kali` 로 로그인한다.

### 3.2 네트워크 어댑터 구성

가상 머신을 **종료한 상태**에서 **[설정] → [네트워크]** 를 아래와 같이 맞춥니다.

| 어댑터 | 연결 방식 | 비고 |
|---|---|---|
| 어댑터 1 | **NAT** | 인터넷 |
| 어댑터 2 | **호스트 전용 어댑터** | **Ubuntu와 같은 이름의 어댑터를 선택** |

> 두 가상 머신이 **서로 다른 호스트 전용 어댑터**를 선택하면 통신되지 않습니다. 목록에 어댑터가 여러 개면 이름을 반드시 확인합니다.
{: .prompt-warning }

### 3.3 Kali에 고정 IP 지정

Kali는 NetworkManager를 사용하므로 `nmcli`로 설정합니다(**0-3 제3절**과 동일).

```bash
# === Kali에서 실행 ===
IFACE2=$(ls /sys/class/net | grep -v lo | sed -n '2p')
echo "호스트 전용 인터페이스: $IFACE2"

sudo nmcli con add type ethernet ifname "$IFACE2" con-name labnet ip4 192.168.56.10/24
sudo nmcli con up labnet

ip addr | grep 192.168.56.10
```

비밀번호를 물으면 `kali`를 입력합니다. 마지막 줄에서 `192.168.56.10`이 보이면 성공입니다.

```bash
# === Kali에서 실행 ===
ping -c 3 192.168.56.30
```

```bash
# === Ubuntu에서 실행 ===
ping -c 3 192.168.56.10
```

**양방향 모두 응답이 와야 합니다.** 실패하면 다음을 순서대로 확인합니다.

| 확인 | 방법 |
|---|---|
| 두 VM이 같은 호스트 전용 어댑터인가 | VirtualBox [설정] → [네트워크] → 어댑터 2의 **이름** |
| 주소가 제대로 붙었는가 | 각 VM에서 `ip -br addr` |
| 방화벽이 막고 있는가 | 다음 절(점검 ④)에서 해결 |

## 5. 점검 ④ — 방화벽 개방 ★가장 중요

> **리눅스 기초 6강을 수강했다면 Ubuntu에 방화벽(ufw)이 켜져 있고, `SSH(22번)만 허용된 상태`입니다.**
> 이 상태에서는 FTP·DNS·웹 등 이 과정의 실습이 **전부 무응답(timeout)으로 실패합니다.** 서버 설정이 잘못된 것으로 오해하기 쉬운, 가장 흔한 함정입니다.
{: .prompt-danger }

### 5.1 현재 상태 확인

```bash
# === Ubuntu에서 실행 ===
sudo ufw status verbose
```

`Status: inactive`이면 5.3절로 건너뜁니다. `Status: active`이면 아래를 수행합니다.

### 5.2 실습망에서 오는 접속만 허용 (권장)

```bash
# === Ubuntu에서 실행 ===
sudo ufw allow from 192.168.56.0/24
sudo ufw status numbered
```

이 한 줄의 의미는 **"실습망(`192.168.56.0/24`) 안에서 오는 접속은 모두 허용하고, 그 밖은 기존 정책대로 차단한다"** 입니다.

> **왜 포트를 하나씩 열지 않고 출발지로 여는가**
> 이 과정에서 쓰는 포트는 21·22·25·53·80·443·3306으로 많고, 특히 **FTP는 데이터 전송 시 임의의 높은 포트를 추가로 사용**합니다(패시브 모드). 포트를 하나씩 열면 FTP 파일 목록 조회에서 원인 모를 멈춤이 발생합니다.
>
> **출발지(실습망)를 기준으로 여는 방식**은 이 문제를 한 번에 해결하면서, 실습망 밖에서 오는 접속은 그대로 차단하므로 안전합니다. 이는 리눅스 기초 6강에서 배운 **출발지 제한 규칙**(`ufw allow from 대역`)을 그대로 응용한 것입니다.
{: .prompt-tip }

### 5.3 확인

```bash
# === Ubuntu에서 실행 ===
sudo ufw status
```

`Anywhere    ALLOW    192.168.56.0/24` 항목이 보이면 됩니다.

> 방화벽을 아예 끄는 방법(`sudo ufw disable`)도 있으나 **권장하지 않습니다.** 마지막 회차(10-2)에서 방화벽 하드닝을 다루므로, 켜 둔 채로 진행하는 편이 학습에 유리합니다.
{: .prompt-warning }

## 6. 점검 ⑤ — 이전 실습 잔재 정리

리눅스 기초 과정에서 만든 것 중 이 과정과 충돌할 수 있는 항목을 정리합니다.

```bash
# === Ubuntu에서 실행 ===
# ① 웹 서버 중복 확인 — 6강 종합실습에서 nginx를 설치했다면 제거한다
dpkg -l | awk '$2 == "nginx"'
sudo apt purge -y nginx nginx-common 2>/dev/null; sudo apt autoremove -y

# ② 80·443 포트를 아무도 쓰고 있지 않은지 확인
sudo ss -tlnp | grep -E ":80|:443" || echo "80/443 비어 있음 — 정상"
```

- **06-2에서 Apache를 설치**하므로, nginx가 남아 있으면 **같은 포트를 두 프로그램이 차지하려 하여 충돌**합니다.
- 리눅스 기초 부록에서 만든 **Metasploitable 2는 이 과정에서 사용하지 않습니다.** 자원 절약을 위해 꺼 두어도 됩니다.

## 7. 점검 ⑥ — SSH 접속 방식 사전 안내

리눅스 기초 6강에서 **키 기반 인증**을 구성했다면 알아 둘 사항이 있습니다.

| 시점 | 접속 방식 |
|---|---|
| 지금 ~ 07-2 | 기존 방식(키 또는 비밀번호) 그대로 사용 |
| **07-3 이후** | **비밀번호 + OTP 6자리(2단계 인증)** 로 변경됨 |

07-3에서 `AuthenticationMethods keyboard-interactive`를 적용하므로, **그 시점부터는 키만으로 접속되지 않습니다.** 이는 오류가 아니라 실습의 목적입니다. 07-3에는 원상 복구 절차가 함께 실려 있습니다.

> 설정을 바꾸는 실습을 할 때는 **VirtualBox 콘솔 창을 열어 두십시오.** 원격 접속이 끊겨도 콘솔로는 언제든 들어갈 수 있습니다.
{: .prompt-warning }

## 8. 최종 점검 — 한 번에 확인하기

Ubuntu에서 아래를 복사해 실행하면 모든 항목이 한 번에 판정됩니다.

```bash
# === Ubuntu에서 실행 ===
echo "===== 애플리케이션 보안 실습 환경 점검 ====="

[ "$(whoami)" = "student" ] \
  && echo "[정상] 계정 student" || echo "[확인] 계정이 student가 아님: $(whoami)"

ip -br addr | grep -q "192.168.56.30" \
  && echo "[정상] Ubuntu 주소 192.168.56.30" || echo "[확인] 실습망 주소 미설정"

ping -c 1 -W 2 192.168.56.10 > /dev/null 2>&1 \
  && echo "[정상] Kali(192.168.56.10)와 통신" || echo "[확인] Kali 미가동 또는 IP 미설정"

ping -c 1 -W 2 8.8.8.8 > /dev/null 2>&1 \
  && echo "[정상] 인터넷 연결(패키지 설치 가능)" || echo "[확인] NAT 어댑터 점검 필요"

if FW=$(sudo -n ufw status 2>/dev/null); then
  if echo "$FW" | grep -q "inactive"; then
    echo "[정상] 방화벽 비활성 — 별도 개방 불필요"
  elif echo "$FW" | grep -q "192.168.56.0/24"; then
    echo "[정상] 방화벽 활성 + 실습망 허용 규칙 있음"
  else
    echo "[조치] 방화벽이 켜져 있고 실습망 규칙이 없음 → 5.2절 수행"
  fi
else
  echo "[확인] sudo 권한으로 다시 실행할 것"
fi

dpkg -l | awk '$2 == "nginx"' | grep -q "^ii" \
  && echo "[조치] nginx가 남아 있음 → 6절 수행" || echo "[정상] 웹 서버 중복 없음"
```

**모든 줄이 `[정상]`이면 02강으로 넘어갈 준비가 끝난 것입니다.**

## 9. 자주 발생하는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| Kali에서 Ubuntu로 `ping`은 되는데 **서비스 접속만 안 됨** | 방화벽이 해당 포트를 차단 | 5.2절의 실습망 허용 규칙 추가 |
| FTP 로그인은 되는데 **`ls`에서 멈춤** | 패시브 모드 데이터 포트 차단 | 5.2절의 **출발지 기반 규칙**으로 변경 |
| 두 VM이 서로 `ping` 안 됨 | 서로 다른 호스트 전용 어댑터 선택 | 3.2절에서 어댑터 **이름**을 일치시킴 |
| 주소를 `192.168.0.x`로 넣었더니 적용 안 됨 | VirtualBox의 대역 제한 | `192.168.56.0/21` 범위 안에서 지정 |
| `apt install`이 실패함 | NAT 어댑터 미설정 | 어댑터 1이 **NAT**인지 확인 |
| Kali에 와이어샤크가 없음 | 최소 설치본 사용 | `sudo apt update && sudo apt install -y wireshark` |
| 교재 명령에 `192.168.0.30`이 보임 | 옛 판본 | 현재 판본은 모두 `192.168.56.30`. 브라우저 새로고침 |
