> 이 실습은 **Kali(192.168.0.10)** 에서 진행합니다. (정적분석 규칙 다운로드를 위해 인터넷 필요 — 어댑터1 NAT)
{: .prompt-info }

## 0. 목표

**정적분석(SAST)** 도구 `semgrep` 으로 **코드를 실행하지 않고** 취약점을 자동으로 찾아내고, 고친 코드와 비교합니다.

---

## 1. (Kali) semgrep 준비

`pipx` 를 이용하면 복잡한 설치 없이 도구를 바로 실행할 수 있습니다.

```bash
# === Kali에서 실행 ===
sudo apt update
sudo apt install -y pipx
```

> `pipx run <도구>` 는 도구를 임시로 내려받아 실행합니다(시스템을 어지럽히지 않음). 첫 실행은 다운로드로 1~2분 걸릴 수 있습니다.
{: .prompt-tip }

---

## 2. (Kali) 취약한 코드 점검

```bash
# === Kali에서 실행 ===
cd ~/secure-lab

pipx run semgrep --config=p/python vuln.py
```

`--config=p/python` 은 파이썬 보안 규칙 묶음을 가져와 검사하라는 뜻입니다.

### 2.1 결과 읽기

`vuln.py` 에서 다음과 같은 경고가 뜹니다.

```
vuln.py
  ❯ 명령어 삽입 위험: os.system 에 사용자 입력이 결합됨
      6│ os.system("ping -c 1 " + host)
  ❯ 하드코딩된 비밀번호 가능성
      4│ PASSWORD = "admin1234"
```

- 코드를 **실행하지 않고도**, `os.system` 결합과 하드코딩 비밀번호를 잡아낸 것입니다.
- 각 경고에는 **줄 번호** 와 **무엇이 문제인지** 가 표시됩니다.

---

## 3. (Kali) 고친 코드와 비교

```bash
# === Kali에서 실행 ===
pipx run semgrep --config=p/python safe.py
```

- `safe.py` 는 `os.system` 결합·하드코딩 경고가 **사라지거나 크게 줄어듭니다.**
- 입력 검증(`ipaddress`)과 안전한 API(`subprocess` 리스트 인자)를 적용했기 때문입니다.

> 🟢 **정적분석의 가치**: 사람이 일일이 안 봐도, 수천 줄 코드에서 위험 패턴을 **자동·반복적으로** 찾아 줍니다. 개발 초기에 돌릴수록 좋습니다(08-1: 일찍 막을수록 싸다).
{: .prompt-tip }

---

## 4. (참고) 폴더 전체 한 번에 검사

```bash
# === Kali에서 실행 ===
pipx run semgrep --config=p/python .
```

- `.`(현재 폴더)를 주면 폴더 안 모든 파이썬 파일을 한꺼번에 검사합니다. 실제 프로젝트에선 이렇게 전체를 점검합니다.

---

## 5. 정적분석 vs 동적분석 (복습)

| 이번 실습 | 다음(09장) |
|---|---|
| **정적분석(SAST)**: 코드를 **안 돌리고** 검사 (semgrep) | **동적분석(DAST)**: **실행하면서** 검사 |
| 취약 패턴을 코드에서 탐지 | 실제 동작·시스템콜을 관찰 |
