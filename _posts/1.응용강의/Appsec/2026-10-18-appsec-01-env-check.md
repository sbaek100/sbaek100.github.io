> 이 과정의 FTP(02강)·메일(03강) 실습은 **VirtualBox의 "NAT 네트워크"** 하나로 Ubuntu와 Kali를 연결한 환경에서 진행합니다.
> 이 글에서는 그 환경을 만들고, **이 과정을 진행할 수 있는 상태인지 점검**합니다.
>
> 소요 시간은 20~30분이며, **한 번만 하면 학기 내내 다시 하지 않습니다.**
{: .prompt-info }

## 0. 누가 이 글을 봐야 하나

| 상황 | 할 일 |
|---|---|
| **Ubuntu·Kali VM이 이미 있다** | 2절부터 순서대로 수행하여 네트워크를 **NAT 네트워크**로 바꾸고 주소를 맞춘다. |
| **리눅스 기초 0강 환경(호스트 전용 어댑터, `192.168.56.x`)을 쓰고 있다** | 2절에서 어댑터를 NAT 네트워크로 바꾸고, 3·4절에서 주소를 `192.168.0.x`로 다시 지정한다. |
| **VM이 아직 없다** | 먼저 **[리눅스 기초] 0강**으로 Ubuntu Server를 설치하고, 4.1절로 Kali를 준비한 뒤 이 글을 수행한다. |

## 1. 이 과정이 전제하는 환경 규격

**02강부터의 모든 실습이 아래 값을 그대로 사용합니다.** 하나라도 다르면 명령을 복사해 붙여 넣었을 때 동작하지 않습니다.

| 항목 | 값 | 비고 |
|---|---|---|
| 가상화 프로그램 | VirtualBox | |
| 네트워크 방식 | **NAT 네트워크** | 이름 `LabNet`, 대역 **`192.168.0.0/24`** |
| 게이트웨이 | `192.168.0.1` | VirtualBox가 자동으로 제공 |
| **Ubuntu 서버** | **`192.168.0.30`** | 서비스를 올리는 대상 |
| Ubuntu 계정 | **`student`** | |
| Ubuntu 버전 | Ubuntu Server 24.04 LTS | 그래픽 환경 없음 |
| **Kali Linux** | **`192.168.0.10`** | 점검·공격 측. **이 과정에서는 필수** |
| 어댑터 | **어댑터 1 하나만 사용** | 두 VM 모두 **NAT 네트워크 → `LabNet`** |

```
                    인터넷
                      │
        ┌─────────────┴─────────────┐
        │  VirtualBox NAT 네트워크   │
        │  LabNet 192.168.0.0/24     │
        │  게이트웨이 192.168.0.1     │
        └────┬──────────────────┬────┘
             │                  │
       ┌─────┴──────┐    ┌──────┴───────┐
       │ Kali       │ →  │ Ubuntu       │
       │ .0.10      │    │ .0.30        │
       │ (도구·GUI) │    │ (FTP·메일)   │
       └────────────┘    └──────────────┘
```

> **NAT 네트워크를 쓰는 이유**
> 같은 NAT 네트워크에 붙은 VM끼리는 **서로 통신**할 수 있고, 동시에 게이트웨이(`192.168.0.1`)를 통해 **인터넷(패키지 설치)** 도 됩니다. 어댑터 하나로 두 가지가 해결되므로, 인터페이스가 하나뿐이라 와이어샤크에서 캡처할 카드를 고를 때도 헷갈리지 않습니다.
{: .prompt-tip }

> **일반 "NAT"와 "NAT 네트워크"는 다릅니다.**
> 어댑터의 연결 방식을 그냥 **NAT** 로 두면 VM마다 따로 격리되어 **Kali와 Ubuntu가 서로 통신하지 못합니다.** 반드시 **NAT 네트워크** 를 선택하고, 두 VM 모두 **같은 이름(`LabNet`)** 을 지정해야 합니다.
{: .prompt-danger }

## 2. 준비 ① — NAT 네트워크 만들기와 어댑터 연결

### 2.1 NAT 네트워크 만들기

VirtualBox 관리자에서 다음을 수행합니다.

1. **[파일] → [도구] → [네트워크 관리자]** 를 엽니다.
2. **[NAT 네트워크]** 탭에서 **[만들기]** 를 누릅니다.
3. 아래와 같이 설정하고 **[적용]** 을 누릅니다.

| 항목 | 값 |
|---|---|
| 이름 | `LabNet` |
| IPv4 접두사 | **`192.168.0.0/24`** |
| DHCP 사용 | **해제** (두 VM 모두 고정 주소를 쓰므로) |

> 메뉴 이름과 위치는 VirtualBox 버전에 따라 조금 다를 수 있습니다. **"NAT 네트워크"** 탭을 찾으면 됩니다.
{: .prompt-info }

### 2.2 두 VM의 어댑터 연결

가상 머신을 **종료한 상태**에서 Ubuntu·Kali **각각** **[설정] → [네트워크]** 를 아래와 같이 맞춥니다.

| 어댑터 | 설정 |
|---|---|
| 어댑터 1 | 연결 방식 **NAT 네트워크**, 이름 **`LabNet`** |
| 어댑터 2 이상 | **사용 안 함** (리눅스 기초 0강의 호스트 전용 어댑터가 있으면 체크 해제) |

> 두 VM이 **서로 다른 NAT 네트워크 이름**을 선택하면 통신되지 않습니다. 목록에 NAT 네트워크가 여러 개면 이름을 반드시 확인합니다.
{: .prompt-warning }

## 3. 준비 ② — Ubuntu 서버 주소 지정

VM을 켜고 **VirtualBox 콘솔 창**에서 `student`로 로그인합니다. (주소를 바꾸기 전이므로 원격 접속 대신 콘솔을 씁니다.)

### 3.1 고정 IP 지정 (netplan)

```bash
# === Ubuntu에서 실행 ===
IFACE=$(ip -br link | awk '$1 != "lo" {print $1; exit}')
echo "인터페이스: $IFACE"          # 보통 enp0s3

sudo tee /etc/netplan/99-labnet.yaml > /dev/null <<NETPLAN
network:
  version: 2
  ethernets:
    $IFACE:
      dhcp4: false
      addresses: [192.168.0.30/24]
      routes:
        - to: default
          via: 192.168.0.1
      nameservers:
        addresses: [8.8.8.8]
NETPLAN

sudo chmod 600 /etc/netplan/99-labnet.yaml
sudo netplan apply
```

- 파일 이름을 `99-`로 시작하는 이유는, netplan이 파일을 이름순으로 읽어 **나중 파일의 값으로 덮어쓰기** 때문입니다. 설치 때 만들어진 기존 파일(`50-cloud-init.yaml` 등)을 지우지 않고도 이 설정이 우선 적용됩니다.
- 리눅스 기초 0강에서 만든 **호스트 전용 어댑터용 설정**(`192.168.56.30`)이 남아 있어도, 2.2절에서 어댑터 2를 껐으므로 영향이 없습니다.

### 3.2 확인

```bash
# === Ubuntu에서 실행 ===
whoami                                   # student
ip -br addr | grep 192.168.0             # 192.168.0.30/24
ip route | grep default                  # default via 192.168.0.1
grep PRETTY /etc/os-release              # Ubuntu 24.04.x LTS
systemctl is-active ssh.socket           # active
```

- 마지막 줄에서 `ssh`(서비스)가 아니라 **`ssh.socket`** 을 조회한 이유는, Ubuntu 24.04가 소켓 활성화 방식을 쓰기 때문입니다. 접속이 없을 때 `ssh.service`는 `inactive`가 정상입니다.

## 4. 준비 ③ — Kali Linux 준비 (이 과정의 필수 항목)

> **이 과정에서 Kali는 필수입니다.** 와이어샤크로 FTP·SMTP 패킷을 들여다보고, 서버로 접속해 공격을 재현하는 작업이 모두 Kali에서 이루어지기 때문입니다.
{: .prompt-danger }

### 4.1 Kali가 없다면 — 설치

1. [Kali 다운로드 페이지](https://www.kali.org/get-kali/)에서 **[Virtual Machines] → VirtualBox** 용 `.7z` 파일을 받는다.
2. 7-Zip으로 압축을 풀면 `.vbox`와 `.vdi` 파일이 나온다.
3. VirtualBox 관리자에서 **[추가(Add)]** 로 `.vbox` 파일을 등록한다.
4. 2.2절대로 어댑터 1을 **NAT 네트워크 → `LabNet`** 으로 지정한다.
5. 기본 계정 `kali` / `kali` 로 로그인한다.

### 4.2 Kali에 고정 IP 지정

Kali는 NetworkManager를 사용하므로 `nmcli`로 설정합니다. 어댑터가 하나이므로 인터페이스는 **`eth0`** 입니다.

```bash
# === Kali에서 실행 ===
sudo nmcli con add type ethernet ifname eth0 con-name labnet \
  ipv4.method manual ipv4.addresses 192.168.0.10/24 \
  ipv4.gateway 192.168.0.1 ipv4.dns 8.8.8.8 \
  connection.autoconnect-priority 100
sudo nmcli con up labnet

ip -br addr show eth0
```

비밀번호를 물으면 `kali`를 입력합니다. 마지막 줄 결과가 아래처럼 나오면 성공입니다.

```
eth0             UP             192.168.0.10/24 fe80::.../64
```

- `connection.autoconnect-priority 100`은 재부팅 후에도 기존 자동(DHCP) 연결보다 **`labnet` 연결이 먼저 선택**되도록 하는 값입니다.
- 이 `eth0`이 02·03강에서 **와이어샤크로 캡처할 인터페이스**입니다.

## 6. 점검 ② — 방화벽 개방 ★가장 중요

> **리눅스 기초 6강을 수강했다면 Ubuntu에 방화벽(ufw)이 켜져 있고, `SSH(22번)만 허용된 상태`입니다.**
> 이 상태에서는 FTP·메일 등 이 과정의 실습이 **전부 무응답(timeout)으로 실패합니다.** 서버 설정이 잘못된 것으로 오해하기 쉬운, 가장 흔한 함정입니다.
{: .prompt-danger }

### 6.1 현재 상태 확인

```bash
# === Ubuntu에서 실행 ===
sudo ufw status verbose
```

`Status: inactive`이면 6.3절로 건너뜁니다. `Status: active`이면 아래를 수행합니다.

### 6.2 실습망에서 오는 접속만 허용 (권장)

```bash
# === Ubuntu에서 실행 ===
sudo ufw allow from 192.168.0.0/24
sudo ufw status numbered
```

이 한 줄의 의미는 **"실습망(`192.168.0.0/24`) 안에서 오는 접속은 모두 허용하고, 그 밖은 기존 정책대로 차단한다"** 입니다.

> **왜 포트를 하나씩 열지 않고 출발지로 여는가**
> 이 과정에서 쓰는 포트는 21·22·25·53·80·443·3306으로 많고, 특히 **FTP는 데이터 전송 시 높은 번호의 포트를 추가로 사용**합니다(패시브 모드). 포트를 하나씩 열다가 하나라도 빠뜨리면 FTP 파일 목록 조회에서 원인 모를 멈춤이 발생합니다.
>
> **출발지(실습망)를 기준으로 여는 방식**은 이 문제를 한 번에 해결하면서, 실습망 밖에서 오는 접속은 그대로 차단합니다. 02·03강 본문에서는 학습을 위해 `ufw allow from 192.168.0.10 to any port 21` 처럼 **Kali 한 대·포트 하나씩** 여는 규칙도 직접 넣어 봅니다. 두 규칙이 함께 있어도 문제없습니다.
{: .prompt-tip }

### 6.3 확인

```bash
# === Ubuntu에서 실행 ===
sudo ufw status
```

`Anywhere    ALLOW    192.168.0.0/24` 항목이 보이면 됩니다.

> 방화벽을 아예 끄는 방법(`sudo ufw disable`)도 있으나 **권장하지 않습니다.** 마지막 회차(10-2)에서 방화벽 하드닝을 다루므로, 켜 둔 채로 진행하는 편이 학습에 유리합니다.
{: .prompt-warning }

## 7. 점검 ③ — 이전 실습 잔재 정리

리눅스 기초 과정에서 만든 것 중 이 과정과 충돌할 수 있는 항목을 정리합니다.

```bash
# === Ubuntu에서 실행 ===
# ① 웹 서버 중복 확인 — 6강 종합실습에서 nginx를 설치했다면 제거한다
dpkg -l | awk '$2 == "nginx"'
sudo apt purge -y nginx nginx-common 2>/dev/null; sudo apt autoremove -y

# ② 80·443 포트를 아무도 쓰고 있지 않은지 확인
sudo ss -tlnp | grep -E ":80|:443" || echo "80/443 비어 있음 — 정상"
```

- **06-2에서 Apache를 설치**하므로, nginx가 남아 있으면 **같은 포트를 두 프로그램이 차지하려 하여 충돌**합니다.
- 리눅스 기초 부록에서 만든 **Metasploitable 2는 이 과정에서 사용하지 않습니다.** 자원 절약을 위해 꺼 두어도 됩니다.

## 8. 점검 ④ — 접속 방식 안내

### 8.1 윈도우에서 SSH로 접속하려면 (선택)

NAT 네트워크 안의 VM 주소(`192.168.0.30`)는 **윈도우 호스트에서 직접 보이지 않습니다.** 윈도우 터미널에서 접속하려면 **포트 포워딩**을 추가합니다. 실습은 VirtualBox 콘솔이나 Kali에서 해도 되므로 이 단계는 선택입니다.

1. **[네트워크 관리자] → [NAT 네트워크] → `LabNet`** 선택 → **[포트 포워딩]** 탭
2. 아래 규칙 추가 후 **[적용]**

| 이름 | 프로토콜 | 호스트 IP | 호스트 포트 | 게스트 IP | 게스트 포트 |
|---|---|---|---|---|---|
| ubuntu-ssh | TCP | `127.0.0.1` | `2222` | `192.168.0.30` | `22` |

```powershell
# === 윈도우 터미널에서 실행 ===
ssh -p 2222 student@127.0.0.1
```

### 8.2 2단계 인증 적용 이후

리눅스 기초 6강에서 **키 기반 인증**을 구성했다면 알아 둘 사항이 있습니다.

| 시점 | 접속 방식 |
|---|---|
| 지금 ~ 07-2 | 기존 방식(키 또는 비밀번호) 그대로 사용 |
| **07-3 이후** | **비밀번호 + OTP 6자리(2단계 인증)** 로 변경됨 |

07-3에서 `AuthenticationMethods keyboard-interactive`를 적용하므로, **그 시점부터는 키만으로 접속되지 않습니다.** 이는 오류가 아니라 실습의 목적입니다. 07-3에는 원상 복구 절차가 함께 실려 있습니다.

> 설정을 바꾸는 실습을 할 때는 **VirtualBox 콘솔 창을 열어 두십시오.** 원격 접속이 끊겨도 콘솔로는 언제든 들어갈 수 있습니다.
{: .prompt-warning }

## 9. 최종 점검 — 한 번에 확인하기

Ubuntu에서 아래를 복사해 실행하면 모든 항목이 한 번에 판정됩니다.

```bash
# === Ubuntu에서 실행 ===
echo "===== 애플리케이션 보안 실습 환경 점검 ====="

[ "$(whoami)" = "student" ] \
  && echo "[정상] 계정 student" || echo "[확인] 계정이 student가 아님: $(whoami)"

ip -br addr | grep -q "192.168.0.30/" \
  && echo "[정상] Ubuntu 주소 192.168.0.30" || echo "[확인] 실습망 주소 미설정 → 3절 수행"

ping -c 1 -W 2 192.168.0.10 > /dev/null 2>&1 \
  && echo "[정상] Kali(192.168.0.10)와 통신" || echo "[확인] Kali 미가동 또는 IP 미설정"

ping -c 1 -W 2 8.8.8.8 > /dev/null 2>&1 \
  && echo "[정상] 인터넷 연결(패키지 설치 가능)" || echo "[확인] NAT 네트워크·게이트웨이 점검 필요"

if FW=$(sudo -n ufw status 2>/dev/null); then
  if echo "$FW" | grep -q "inactive"; then
    echo "[정상] 방화벽 비활성 — 별도 개방 불필요"
  elif echo "$FW" | grep -q "192.168.0.0/24"; then
    echo "[정상] 방화벽 활성 + 실습망 허용 규칙 있음"
  else
    echo "[조치] 방화벽이 켜져 있고 실습망 규칙이 없음 → 6.2절 수행"
  fi
else
  echo "[확인] sudo 권한으로 다시 실행할 것"
fi

dpkg -l | awk '$2 == "nginx"' | grep -q "^ii" \
  && echo "[조치] nginx가 남아 있음 → 7절 수행" || echo "[정상] 웹 서버 중복 없음"
```

**모든 줄이 `[정상]`이면 02강으로 넘어갈 준비가 끝난 것입니다.**

## 10. 자주 발생하는 문제

| 증상 | 원인 | 조치 |
|---|---|---|
| 두 VM이 서로 `ping` 안 됨 | 연결 방식을 **NAT**(네트워크 아님)로 선택 | 2.2절에서 **NAT 네트워크 → `LabNet`** 으로 변경 |
| 두 VM이 서로 `ping` 안 됨 | 서로 다른 NAT 네트워크 이름 선택 | 2.2절에서 **이름**을 일치시킴 |
| Kali에서 Ubuntu로 `ping`은 되는데 **서비스 접속만 안 됨** | 방화벽이 해당 포트를 차단 | 6.2절의 실습망 허용 규칙 추가 |
| FTP 로그인은 되는데 **`ls`에서 멈춤** | 패시브 모드 데이터 포트 차단 | 6.2절의 **출발지 기반 규칙** 추가 |
| `apt install`이 실패함 | 게이트웨이·DNS 미지정 | 3.1절 `via: 192.168.0.1`, `nameservers` 확인 |
| 재부팅 후 Kali 주소가 바뀜 | 기존 자동(DHCP) 연결이 먼저 선택됨 | `sudo nmcli con up labnet` 후 4.2절의 `autoconnect-priority` 확인 |
| 윈도우에서 `ssh student@192.168.0.30` 안 됨 | NAT 네트워크 안은 호스트에서 직접 안 보임 | 8.1절 포트 포워딩 후 `ssh -p 2222 student@127.0.0.1` |
| Kali에 와이어샤크가 없음 | 최소 설치본 사용 | `sudo apt update && sudo apt install -y wireshark` |
| 교재 명령에 `192.168.56.x`가 보임 | 호스트 전용 어댑터 기준 옛 판본 | 현재 판본은 Ubuntu `192.168.0.30`, Kali `192.168.0.10` |
