## 0. 오늘의 그림

지금 우리 방화벽은 다리를 **세 개** 걸치고 있습니다. 1-1편에서 약속한 **관제망 다리**는 아직 놓지 않았습니다.

```text
                    [ OPNsense 방화벽 ]
   어댑터1 NAT ───── WAN   (인터넷)
   어댑터2 ───────── LAN   192.168.57.1   → soc-wan  [ Kali 57.10 ]
   어댑터3 ───────── OPT1  192.168.59.1   → soc-dmz  [ waf 59.30 ] [ victim 59.20 ]
   어댑터4 ───────── OPT2  192.168.58.1   → soc-lan  [ soc 58.100 ]   ← 오늘 놓습니다
```

오늘 **어댑터 4** 를 꽂아 관제망 다리를 놓고, 그 끝에 SIEM 서버를 세웁니다.

> **왜 관제망을 따로 두나요? 그냥 DMZ에 두면 안 되나요?**
>
> 세 가지 이유가 있습니다.
>
> 1. **로그는 공격자가 가장 먼저 지우려는 것**입니다. 침입한 서버 안에 로그가 그대로 있으면 지워집니다. 다른 망의 다른 서버로 **즉시 밀어 올려** 두어야 증거가 남습니다.
> 2. **관제 서버 자체가 공격 표면이 되면 안 됩니다.** SIEM에는 모든 시스템의 기록이 모이므로, 여기가 뚫리면 조직 전체가 노출됩니다. 그래서 노출망과 분리하고, 바깥에서 들어오는 길을 만들지 않습니다.
> 3. **로그는 한 방향으로만 흐릅니다.** DMZ의 서버들이 관제망으로 **밀어 올리기만** 하고, 관제망에서 DMZ로 들어가는 길은 막습니다. 오늘 방화벽 규칙을 그렇게 만듭니다.
{: .prompt-tip }

## 1. 이론 ① — SIEM은 무엇을 하는 물건인가

### 1.1 우리가 지금 겪고 있는 문제

3단계를 마친 지금, 공격 한 건을 조사하려면 이렇게 해야 합니다.

| 알고 싶은 것 | 지금은 어디를 봐야 하나 |
| --- | --- |
| 누가 포트를 훑었나 | OPNsense 화면 → Suricata Alerts |
| 웹 공격이 몇 번 왔나 | waf 서버에 SSH 접속 → `modsec_audit.log` |
| 그 사이에 무엇을 눌러 봤나 | waf 서버 → `juice_access.log` |
| 방화벽이 무엇을 막았나 | OPNsense 화면 → Firewall Live View |

화면 네 개, 서버 두 대, 로그 파일 세 개. **사람이 밤새 지켜볼 수 없습니다.** 그리고 시계가 서로 조금씩 달라 순서를 맞추기도 어렵습니다.

### 1.2 SIEM의 다섯 가지 일

**SIEM(Security Information and Event Management)** 은 이 문제를 다섯 단계로 풉니다.

| 단계 | 하는 일 | 우리 실습에서 |
| --- | --- | --- |
| ① **수집** | 여러 장비의 로그를 한곳으로 모음 | 에이전트가 OPNsense·waf의 로그를 밀어 올림 (4-2) |
| ② **정규화** | 형식이 제각각인 로그에서 "출발지 IP·시각·행위"를 뽑아 같은 모양으로 | 디코더가 담당 (4-3) |
| ③ **상관분석** | 흩어진 사건을 묶어 의미를 만듦 | "같은 IP가 1분에 5번 차단됨 → 지속 공격" (4-3) |
| ④ **가시화** | 사람이 한눈에 보게 | 대시보드 (4-3) |
| ⑤ **대응** | 정해진 조건에서 자동으로 조치 | **5단계에서 AI가 판단하고 차단** |

> **"로그를 모으는 것"과 "SIEM"은 다릅니다.** 로그만 모으면 파일이 한곳에 쌓일 뿐입니다. SIEM은 ②~③, 즉 **뜻을 부여하고 사건으로 묶는 일**을 합니다. 4-2에서 로그를 모으고도 화면에 아무것도 안 뜨는 경험을 하게 되는데, 그것이 바로 "②③이 없으면 무슨 일이 생기는가"입니다.
{: .prompt-info }

## 2. 이론 ② — Wazuh를 쓰는 이유

### 2.1 무엇으로 이루어져 있나

| 구성요소 | 하는 일 | 어디에 |
| --- | --- | --- |
| **Wazuh agent** | 감시 대상에 설치되어 로그를 읽어 밀어 올림 | OPNsense · waf 서버 (4-2) |
| **Wazuh server(manager)** | 받은 로그를 디코딩하고 규칙에 대조해 **경보**를 만듦 | soc 서버 |
| **Wazuh indexer** | 경보를 저장하고 검색 가능하게 함(OpenSearch 기반) | soc 서버 |
| **Wazuh dashboard** | 웹 화면 | soc 서버 |

뒤의 셋을 한 대에 몰아 넣는 것을 **단일 노드(all-in-one)** 구성이라고 하며, 오늘 그렇게 설치합니다.

### 2.2 왜 Wazuh인가

| 이유 | 설명 |
| --- | --- |
| **무료·오픈소스** | 기능 제한 없이 전부 씁니다 |
| **에이전트가 강력함** | 로그 수집뿐 아니라 파일 무결성 감시·취약점 점검까지 한 도구로 |
| **Suricata를 이미 안다** | `eve.json` 을 넣으면 **기본 제공 규칙**이 바로 해석합니다 (2-3에서 로그 형식을 JSON으로 맞춘 이유) |
| **OPNsense 공식 플러그인이 있다** | 방화벽에 에이전트를 GUI로 붙일 수 있습니다 (4-2) |
| **★ API가 있다** | 외부 프로그램이 경보를 읽어 갈 수 있습니다 — **5단계에서 AI가 이 API로 경보를 가져갑니다** |

> **마지막 줄이 이 강의에서 Wazuh를 고른 결정적 이유입니다.** 4단계의 목적은 예쁜 화면이 아니라, **AI가 읽을 수 있는 형태로 사건을 정리해 두는 것**입니다.
{: .prompt-tip }

### 2.3 메모리 계획 — 오늘부터 VM이 다섯 대입니다

Wazuh 단일 노드의 공식 권장 사양은 **에이전트 1~25대 기준 4 vCPU · 8 GiB RAM · 디스크 50 GB(90일 보관)** 입니다. 우리는 에이전트가 **두 대**뿐인 실습이라 **6 GB · 2 vCPU** 로 진행하지만, 호스트 메모리를 미리 계산해 두어야 합니다.

| VM | 지금까지 | 4단계 권장 | 비고 |
| --- | --- | --- | --- |
| OPNsense | 2048 | 2048 | 그대로 |
| Kali | 3072 | **2048** | 공격만 보내면 되므로 줄여도 됩니다 |
| victim | 2048 | 2048 | 그대로 |
| waf | 1536 | **1024** | Nginx만 도므로 가능합니다 |
| **soc** | — | **6144** | 오늘 새로 만듭니다 |
| 합계 | | **약 13.3 GB** | |

> **★ 호스트가 16 GB 미만이면 이렇게 하세요.**
>
> - **다섯 대를 동시에 켜지 않습니다.** 공격을 보낼 때만 Kali를 켜고, 대시보드를 볼 때는 Kali를 끕니다. 로그는 이미 SIEM에 올라가 있으므로 나중에 봐도 됩니다
> - soc를 **4096 MB** 로 낮춰도 설치는 됩니다(느려집니다). 그 아래로는 Wazuh 인덱서가 잘 뜨지 않습니다
> - 오늘(4-1)은 victim·waf를 **꺼 두어도 됩니다.** 필요한 것은 OPNsense·soc·Kali 세 대뿐입니다
{: .prompt-warning }

## 3. 따라 하기: 방화벽에 관제망 다리 놓기

> ### 따라 하기 3-1. OPNsense에 어댑터 4 추가
>
> **목적** 방화벽이 관제망에도 발을 딛게 합니다.
{: .prompt-tip }

**1단계.** OPNsense를 정상 종료합니다. **콘솔 메뉴 `5`(Power off)** 를 쓰거나, 웹 화면 왼쪽 메뉴의 **Power → Power off** 를 씁니다.

> **전원을 강제로 내리지 마세요.** 방화벽은 설정을 파일로 들고 있어, 강제 종료하면 최근 설정이 날아갈 수 있습니다.
{: .prompt-warning }

**2단계.** VirtualBox에서 `firewall` VM 선택 → **설정 → 네트워크 → 어댑터 4** 탭:

| 항목 | 값 |
| --- | --- |
| 네트워크 어댑터 사용하기 | **체크** |
| 다음에 연결됨 | **내부 네트워크** |
| 이름 | **`soc-lan`** |

**3단계.** VM을 시작합니다.

> 📷 **필요 이미지 ①** — `firewall` VM의 어댑터 4가 내부 네트워크 `soc-lan` 으로 지정된 화면.
{: .prompt-tip }

> ### 따라 하기 3-2. 새 인터페이스 할당(OPT2)
>
> **목적** 방금 꽂은 랜카드를 OPNsense가 쓰게 만듭니다.
{: .prompt-tip }

**4단계.** Kali 브라우저에서 OPNsense(`https://192.168.57.1`)에 로그인 → **Interfaces → Assignments**.

**5단계.** 목록 아래쪽에 아직 할당되지 않은 장치 **`em3`** 이 보입니다. (2-1편에서 본 것처럼 `em0`·`em1`·`em2` 가 어댑터 1·2·3이므로, 새로 꽂은 어댑터 4는 **`em3`** 입니다.)

- 왼쪽 드롭다운에서 **`em3`** 선택 → **`+`** 버튼 → **Save**
- 새 인터페이스 **`OPT2`** 가 생깁니다

**6단계.** 왼쪽 메뉴 **Interfaces → [OPT2]** 로 들어가 아래처럼 설정합니다.

| 항목 | 값 |
| --- | --- |
| **Enable** | **체크** |
| Description | **`SOCLAN`** |
| IPv4 Configuration Type | **Static IPv4** |
| **IPv4 address** | **`192.168.58.1`** / **`24`** |
| IPv4 Upstream Gateway | (비워 둠) |

**7단계.** **Save** → 위쪽에 뜨는 **Apply changes** 를 누릅니다.

**8단계.** 확인합니다. **Lobby → Dashboard** 의 Interfaces 위젯에 `SOCLAN` 이 `192.168.58.1` 로 보이면 성공입니다.

> **다리를 놓았을 뿐, 문은 아직 없습니다.** OPNsense는 새 인터페이스에 규칙이 **하나도 없으면 전부 차단**합니다(2-1편에서 OPT1이 그랬던 것과 같습니다). 5장에서 필요한 문만 열어 줍니다.
{: .prompt-info }

## 4. 따라 하기: SOC 서버(VM5) 만들기

| 항목 | 값 |
| --- | --- |
| 이름 | **`soc`** |
| 운영체제 | Ubuntu Server 24.04 LTS |
| 메모리 | **6144 MB** (최소 4096) |
| 프로세서 | **2** |
| 디스크 | **40 GB** (동적 할당) |
| IP | **192.168.58.100** (`soc-lan`) |
| 계정 | `student` / `student1234` |

> ### 따라 하기 4-1. VM 생성과 Ubuntu 설치
{: .prompt-tip }

**1단계.** VirtualBox **새로 만들기(New)** → 1-3편에서 받은 Ubuntu Server ISO 사용, **Skip Unattended Installation 체크**, 이름은 **`soc`**.

**2단계.** 하드웨어를 위 표대로 지정합니다. **디스크를 40 GB로 넉넉히 잡으세요.** SIEM은 로그를 쌓는 장비라 디스크가 부족하면 인덱서가 멈춥니다.

**3단계.** **설정 → 네트워크**:

- **어댑터 1**: **NAT** (설치용 — 오늘 안에 끕니다)
- **어댑터 2**: **내부 네트워크**, 이름 **`soc-lan`**

**4단계.** Ubuntu Server를 설치합니다. 1-3편·3-1편과 같은 순서이며, 계정만 다시 확인합니다.

| 항목 | 값 |
| --- | --- |
| Your server's name | **`soc`** |
| Pick a username | `student` |
| Password | `student1234` |
| SSH 설치 | **Install OpenSSH server 체크** |

> ### 따라 하기 4-2. 고정 IP와 NAT 끄기
>
> **목적** 관제망 주소를 못박습니다. **Wazuh를 설치하기 전에 반드시 끝내야 합니다.**
{: .prompt-tip }

> **★ 순서를 지키세요 — IP를 먼저, 설치를 나중에.**
>
> Wazuh 설치 프로그램은 **설치 시점의 IP 주소로 인증서를 만들고 설정 파일에 적어 둡니다.** NAT 주소(10.0.2.15) 상태에서 설치한 뒤 IP를 바꾸면, 인덱서가 없는 주소에 매달리려다 **기동에 실패합니다.** 반드시 IP를 먼저 확정하세요.
{: .prompt-danger }

**5단계.** 서버를 끄고, VirtualBox에서 **어댑터 1(NAT)의 "네트워크 어댑터 사용하기" 체크를 해제**한 뒤 다시 켭니다.

```bash
sudo poweroff
```

**6단계.** 내부망 랜카드 이름을 확인합니다.

```bash
ip -brief address
```

`lo` 를 뺀 나머지 하나(대개 **`enp0s8`**)가 어댑터 2입니다.

**7단계.** 고정 IP를 지정합니다.

```bash
sudo tee /etc/netplan/99-soc.yaml >/dev/null <<'EOF'
network:
  version: 2
  ethernets:
    enp0s8:
      dhcp4: no
      addresses: [192.168.58.100/24]
      routes:
        - to: default
          via: 192.168.58.1
      nameservers:
        addresses: [192.168.58.1]
EOF
sudo chmod 600 /etc/netplan/99-soc.yaml
sudo netplan apply
```

**8단계.** 확인합니다.

```bash
ip -brief address show enp0s8
ping -c 2 192.168.58.1
```

`192.168.58.100/24` 가 보이고 방화벽(58.1)에 핑이 닿으면 됩니다.

> **핑이 안 가면** 3-2의 인터페이스 활성화(Enable 체크)와 Apply를 다시 확인하세요. 같은 망 안이라 방화벽 규칙과는 무관합니다.
{: .prompt-warning }

## 5. 따라 하기: 관제망 방화벽 규칙

관제망은 **가장 안쪽 망**입니다. 그런데 지금은 규칙이 없어 **아무 데도 못 갑니다.** Wazuh를 내려받아야 하므로 필요한 문만 엽니다.

> ### 따라 하기 5-1. 별칭 추가
{: .prompt-tip }

**1단계.** **Firewall → Aliases → + Add** 로 두 개를 만듭니다.

| 항목 | 값 |
| --- | --- |
| Name | **`soc_host`** |
| Type | Host(s) |
| Content | `192.168.58.100` |
| Description | 관제 서버 |

| 항목 | 값 |
| --- | --- |
| Name | **`wazuh_ports`** |
| Type | Port(s) |
| Content | `1514`, `1515` (한 줄에 하나씩) |
| Description | Wazuh 에이전트 통신·등록 |

**2단계.** 목록 아래쪽 **Apply** 를 누릅니다. (`wazuh_ports` 는 다음 시간에 씁니다.)

> ### 따라 하기 5-2. OPT2 규칙 만들기
>
> **목적** 관제망이 "필요한 것만" 하게 만듭니다.
{: .prompt-tip }

**3단계.** **Firewall → Rules → OPT2** 에서 아래 다섯 규칙을 **이 순서대로** 만듭니다. 공통 항목은 Interface `OPT2`, Direction `in`, Source `OPT2 net` 입니다.

| 순서 | Action | Protocol | Destination | Port | Description |
| --- | --- | --- | --- | --- | --- |
| 1 | **Pass** | TCP/UDP | **This Firewall** | `53` | `soc dns` |
| 2 | **Pass** | TCP | **This Firewall** | `443` | `soc to fw api` |
| 3 | **Block** | any | **OPT1 net** | — | `block soc to dmz` |
| 4 | **Block** | any | **LAN net** | — | `block soc to wan-side` |
| 5 | **Pass** | TCP | any | **`dmz_out_ports`** | `soc update` |

**4단계.** 순서를 드래그로 맞추고 **Apply** 를 누릅니다.

> **왜 이 순서인가요?** 먼저 맞는 규칙이 이깁니다.
>
> - **3·4번(차단)이 5번(업데이트 허용)보다 위**에 있어야 합니다. 5번은 "어디로든 80·443"이라 아래에 두지 않으면 **관제망에서 DMZ의 웹(WAF 80)으로도 갈 수 있게** 됩니다. 로그는 에이전트가 **밀어 올리는** 것이므로, 관제망에서 DMZ로 들어갈 일은 없습니다
> - **2번(방화벽 443)은 5단계를 위한 문**입니다. AI가 판단을 내린 뒤 **OPNsense API를 호출해 공격자 IP를 차단**하려면 이 길이 필요합니다. 오늘 미리 열어 두고, 5단계에서 실제로 씁니다
{: .prompt-tip }

**5단계.** soc 서버에서 확인합니다.

```bash
ping -c 3 8.8.8.8      # 실패해야 정상 (ICMP는 허용하지 않았습니다)
sudo apt update        # 성공해야 정상 (53 · 80 · 443만 열어 두었습니다)
```

## 6. 따라 하기: Wazuh 설치

Wazuh는 **설치 도우미 스크립트** 하나로 서버·인덱서·대시보드를 한 번에 올릴 수 있습니다.

> ### 따라 하기 6-1. 설치 도우미 실행
{: .prompt-tip }

**1단계.** soc 서버에서 실행합니다.

```bash
curl -sO https://packages.wazuh.com/4.14/wazuh-install.sh
sudo bash ./wazuh-install.sh -a
```

> **★ "사양이 권장에 못 미친다"는 경고가 나오면** — 우리 VM은 공식 권장(4 vCPU · 8 GiB)보다 작으므로 도우미가 경고하거나 멈출 수 있습니다. 그때는 검사만 건너뛰고 진행합니다.
>
> ```bash
> sudo bash ./wazuh-install.sh -a -i
> ```
>
> `-i` 는 **사양 검사만** 건너뛸 뿐 설치 내용은 같습니다. 다만 메모리가 정말 부족하면 인덱서가 기동 중에 죽으므로, VM 메모리는 **최소 4096 MB, 가능하면 6144 MB** 를 주세요.
{: .prompt-warning }

**2단계.** 10~20분 정도 걸립니다. 화면에 인덱서 → 서버 → 대시보드 순서로 진행 상황이 나옵니다.

**3단계.** 마지막에 이런 안내가 나오면 성공입니다.

```text
INFO: --- Summary ---
INFO: You can access the web interface https://<wazuh-dashboard-ip>
    User: admin
    Password: <생성된 비밀번호>
INFO: Installation finished.
```

> **★ 이 비밀번호를 반드시 적어 두세요.** 화면을 놓쳤다면 아래 명령으로 다시 볼 수 있습니다.
>
> ```bash
> sudo tar -O -xvf wazuh-install-files.tar wazuh-install-files/wazuh-passwords.txt
> ```
{: .prompt-danger }

**4단계.** 세 서비스가 모두 떴는지 확인합니다.

```bash
systemctl is-active wazuh-indexer wazuh-manager wazuh-dashboard
```

`active` 가 세 번 나와야 합니다.

> **설치가 실패하거나 중간에 멈춘다면**
>
> | 증상 | 원인 | 조치 |
> | --- | --- | --- |
> | 다운로드가 안 됨 | 5장 규칙 문제 | soc에서 `sudo apt update` 가 되는지 먼저 확인 |
> | 메모리 부족으로 인덱서가 죽음 | RAM 부족 | VM 메모리를 6144 이상으로. `free -h` 로 확인 |
> | 중간에 끊겨 다시 하고 싶음 | 부분 설치 상태 | `sudo bash ./wazuh-install.sh -u` 로 **깨끗이 지운 뒤** 다시 실행 |
> | `wazuh-indexer` 가 `activating` 에서 멈춤 | 기동에 시간이 걸림 | 2~3분 기다린 뒤 `journalctl -u wazuh-indexer -n 50` 확인 |
{: .prompt-warning }

> ### 따라 하기 6-2. 재부팅해도 살아나는지 확인
{: .prompt-tip }

**5단계.** 실습 환경은 껐다 켜기를 반복하므로, 자동 시작을 확인해 둡니다.

```bash
sudo systemctl enable wazuh-indexer wazuh-manager wazuh-dashboard
sudo reboot
```

**6단계.** 다시 로그인해 4단계의 `systemctl is-active` 를 한 번 더 실행합니다. 부팅 직후에는 인덱서가 뜨는 데 1~2분 걸립니다.

## 8. 따라 하기: 스냅샷과 점검

**1단계.** soc 서버를 종료합니다.

```bash
sudo poweroff
```

**2단계.** VirtualBox에서 `soc` 선택 → **스냅샷 → 만들기** → 이름 **`soc-wazuh-ready`**. OPNsense도 인터페이스가 늘었으니 **`fw-soclan`** 으로 하나 저장해 두면 좋습니다.

점검 목록:

- [ ] OPNsense에 어댑터 4를 꽂고 **OPT2 = 192.168.58.1** 로 활성화했다

- [ ] soc의 NAT 어댑터를 끄고, **IP를 확정한 뒤에** Wazuh를 설치했다
- [ ] OPT2 규칙 다섯 개를 **차단이 허용보다 위**에 오도록 배치했다
- [ ] soc에서 `ping 8.8.8.8` 은 실패하고 `apt update` 는 성공한다
- [ ] `wazuh-indexer` · `wazuh-manager` · `wazuh-dashboard` 가 모두 `active` 다
- [ ] Kali 브라우저에서 `https://192.168.58.100` 로그인에 성공했다
- [ ] Agents 화면이 **비어 있는 것**을 확인했다 (다음 시간의 출발점)
- [ ] admin 비밀번호를 안전한 곳에 적어 두었다
