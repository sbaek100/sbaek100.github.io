## 2. 이론: 가상머신(VM)과 가상 네트워크

보안관제 실습을 하려면 **방화벽·공격자·웹 서버·관제 서버**처럼 여러 대의 컴퓨터가 동시에 필요합니다. 이걸 다 사면 비용이 큽니다. 이 문제를 푸는 기술이 **가상화(Virtualization)** 입니다.

- **가상머신(VM)**: 내 컴퓨터의 CPU·메모리·디스크를 조금씩 떼어 만든 "소프트웨어로 된 가짜 컴퓨터". 노트북 한 대 안에 여러 대의 컴퓨터를 만듭니다.
- **하이퍼바이저(Hypervisor)**: VM을 만들고 실행해 주는 관리 프로그램. 우리는 무료인 **Oracle VM VirtualBox**를 씁니다.

> **비유**: 노트북 = 큰 건물, VM = 그 안을 칸막이로 나눈 여러 개의 방. 각 방은 서로 독립적으로 동작합니다.
{: .prompt-tip }

VM끼리 통신하려면 **가상 네트워크(가상 랜선)** 로 묶어야 합니다. VirtualBox에는 여러 연결 방식이 있는데, 우리 실습에는 두 가지만 씁니다.

| 연결 방식 | 외부 인터넷 | VM끼리 통신 | 우리 쓰임 |
| --- | --- | --- | --- |
| **NAT** | O (나감) | X | 프로그램 설치(apt·docker)용 임시 인터넷 |
| **내부 네트워크(Internal Network)** | X (완전 차단) | O (같은 이름끼리) | 실습용 폐쇄망. 공격·로그 트래픽이 여기로만 흐름 |

우리 방침은 이렇습니다. **각 VM은 어댑터 2개**를 가집니다.

- **어댑터 1 = NAT**: 프로그램을 내려받는 동안만 쓰는 진짜 인터넷. 외부에서 우리 VM으로 들어올 수는 없습니다.
- **어댑터 2 = 내부 네트워크**: 실습의 진짜 무대. 공격도 로그도 전부 이 폐쇄망 안에서만 오갑니다.

> ⚠️ **가장 중요한 안전 원칙**: 우리가 만드는 공격 트래픽은 **내부 네트워크 밖으로 절대 나가지 않습니다.** 본인이 소유한 이 랩 안의 표적만 공격합니다. 동의 없이 외부 시스템을 스캔·공격하면 「정보통신망법」 위반입니다.
{: .prompt-danger }

## 3. 우리가 5단계 동안 만들 전체 구성 (★ 모든 강의의 기준표 ★)

아래 표는 **이 과정 전체에서 변하지 않는 약속**입니다. 앞으로 모든 강의에서 IP·계정·역할은 이 표를 그대로 따릅니다. **헷갈릴 때마다 이 페이지로 돌아오세요.**

### 3.1 최종 네트워크 세그먼트

| 세그먼트 | 내부 네트워크 이름 | 대역 | 역할 |
| --- | --- | --- | --- |
| **공격망(WAN)** | `soc-wan` | 192.168.57.0/24 | 외부(인터넷)를 흉내 낸 구간. 공격자 Kali가 여기 있음 |
| **관제망(LAN)** | `soc-lan` | 192.168.58.0/24 | SIEM·AI 관제 서버, 관리자만 있는 안전한 안쪽 망 |
| **노출망(DMZ)** | `soc-dmz` | 192.168.59.0/24 | 웹으로 공개되는 WAF·표적 서버가 있는 위험 구간 |

> **DMZ(비무장지대)** 란, 외부에 서비스를 공개해야 하므로 어쩔 수 없이 위험에 노출되는 구간입니다. 회사 웹서버가 대표적입니다. 그래서 안쪽 관제망(LAN)과는 방화벽으로 분리합니다.
{: .prompt-tip }

### 3.2 최종 VM 목록 / 사양 (16GB 호스트 기준)

| VM      | 이름         | 역할            | OS                  | RAM     | 세그먼트 · 고정 IP                   |
| ------- | ---------- | ------------- | ------------------- | ------- | ------------------------------ |
| **VM1** | `attacker` | 공격자(Red)      | Kali Linux          | 3072 MB | soc-wan · **192.168.57.10**    |
| **VM2** | `firewall` | 방화벽 + IDS/IPS | OPNsense            | 3072 MB | 각 망의 관문 · **57.1 / 59.1**       |
| **VM3** | `waf`      | 웹 방화벽         | Ubuntu Server 24.04 | 1536 MB | soc-dmz · **192.168.59.30**    |
| **VM4** | `victim`   | 표적 웹서버        | Ubuntu Server 24.04 | 2048 MB | soc-dmz · **192.168.59.20**    |
| **VM5** | `soc`      | SIEM + AI 관제  | Ubuntu Server 24.04 | 6144 MB | soc-lan · **192.168.58.100**   |

> **VM2(방화벽)의 IP가 여러 개인 이유**: 방화벽은 여러 망에 동시에 다리를 걸치고 있어서, **망마다 IP를 하나씩** 가집니다. 각 망의 컴퓨터는 이 주소를 자기 **게이트웨이(바깥으로 나가는 문)** 로 씁니다. 2단계에서 공격망 쪽 다리(**192.168.57.1**)와 노출망 쪽 다리(**192.168.59.1**)를 세우고, 관제망 쪽 다리(**192.168.58.1**)는 SIEM 서버를 만드는 4단계에서 추가합니다. 인터넷 연결용 다리는 VirtualBox NAT가 맡습니다.
{: .prompt-info }

> OPNsense는 이 다리들에 `WAN`·`LAN`·`OPT1` 이라는 **역할 이름**을 따로 붙입니다. VirtualBox 망 이름(`soc-wan` 등)과는 별개의 이름이며, 어느 망에 어느 역할 이름을 줄지는 **2-1편에서** 이유와 함께 정합니다.
{: .prompt-tip }

> **16GB 메모리 안내**: 5대를 항상 동시에 켤 필요는 없습니다. 강의마다 "오늘 켜는 VM"만 켜세요. 오늘은 아직 한 대도 만들지 않습니다.
{: .prompt-warning }

### 3.3 계정(자격증명) 약속

| 시스템 | 아이디 | 비밀번호 |
| --- | --- | --- |
| Kali (VM1) | `kali` | `kali` (공식 이미지 기본) |
| Ubuntu (VM3·VM4·VM5 공통) | `student` | `student1234` |
| OPNsense 웹관리 | `root` | `opnsense123` (2단계에서 설정) |

> 위 비밀번호는 **격리된 실습 전용**입니다. 실제 운영 환경에서는 절대 이런 단순한 값을 쓰지 않습니다.
{: .prompt-danger }

### 3.4 오늘 만드는 것은 여기까지 (1단계 임시 구성)

방화벽(OPNsense)은 2단계에서 세웁니다. **그 전까지는** 공격자와 표적을 같은 노출망(`soc-dmz`)에 두어, 방어 장치가 하나도 없을 때 공격이 얼마나 쉽게 통하는지 눈으로 확인합니다.

| VM | 1단계 임시 IP | 최종 IP(2단계 이후) |
| --- | --- | --- |
| `attacker`(Kali) | 192.168.59.10 | 192.168.57.10 (공격망으로 이사) |
| `victim`(표적) | **192.168.59.20** | 192.168.59.20 (그대로) |

> 표적 서버의 IP(**59.20**)는 처음부터 끝까지 바뀌지 않습니다. 2단계에서 방화벽을 끼워 넣을 때 **공격자만** 바깥 공격망으로 옮깁니다.
{: .prompt-info }

## 5. 따라 하기: 내부 네트워크 3개 만들기

VirtualBox의 **내부 네트워크(Internal Network)** 는 별도로 "만드는" 과정이 없습니다. VM의 어댑터 설정에서 **이름을 처음 입력하는 순간 생성**됩니다. 그래서 오늘은 앞으로 쓸 **세 개의 이름을 미리 약속**해 두는 것이 핵심입니다.

| 이름(정확히 이대로 입력) | 대역              | 용도                       |
| -------------- | --------------- | ------------------------ |
| `soc-wan`      | 192.168.57.0/24 | 공격망                      |
| `soc-lan`      | 192.168.58.0/24 | 관제망                      |
| `soc-dmz`      | 192.168.59.0/24 | 노출망 (오늘 임시로 공격·표적을 함께 둠) |



> **왜 `192.168.0.x`·`192.168.1.x`를 안 쓰나요?** 이 대역은 집 공유기가 흔히 씁니다. 실습망과 겹치면 "지금 접속한 게 내 실습 VM인지 집 공유기인지" 헷갈립니다. 그래서 잘 안 겹치는 `57·58·59` 대역을 골랐습니다.
{: .prompt-tip }

내부 네트워크는 **DHCP(자동 IP 배정)가 기본으로 없습니다.** 즉 IP가 저절로 안 붙습니다. 우리는 오히려 이게 좋습니다 — 위 기준표대로 **고정 IP를 직접 손으로 지정**할 것이기 때문입니다. IP를 손으로 넣는 방법은 다음 두 시간(Kali·Ubuntu)에서 각각 다룹니다.

> 지금은 이름 세 개(`soc-wan`, `soc-lan`, `soc-dmz`)만 기억해 두면 됩니다. 실제 연결은 VM을 만들 때 어댑터 2번에 이 이름을 골라 주는 것으로 이뤄집니다.
{: .prompt-info }
