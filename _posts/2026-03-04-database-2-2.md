# 1단계. 데이터베이스 만들기

데이터베이스는 테이블을 담는 **폴더**라고 생각하면 됨.
실습용 폴더를 하나 새로 만드는 과정임.

```sql

```

```sql
SHOW DATABASES;
```

# 3단계. 출석부 테이블 만들기

## 자료형(Data Type) 이란? 

테이블을 만들 때 각 항목에 **어떤 종류의 데이터를 넣을지** 미리 정해야 함.
엑셀에서 셀 서식을 숫자 / 텍스트 / 날짜로 지정하는 것과 같은 개념임.

| 자료형 | 의미 | 사용 예 |
|--------|------|---------|
| `INT` | 정수 (소수점 없는 숫자) | 번호, 나이, 점수 |
| `VARCHAR(숫자)` | 글자 (길이가 달라도 됨) | 이름, 학과명 |
| `CHAR(숫자)` | 글자 (길이가 항상 고정) | 전화번호, 학번 |
| `DATE` | 날짜 | 2026-03-07 |
| `ENUM(값1, 값2, …)` | 정해진 값 중 하나만 입력 가능 | 출석 / 지각 / 결석 |

> 💡 `VARCHAR` 와 `CHAR` 의 차이
> - `VARCHAR(20)` : "김민준" 3글자를 넣으면 3글자 공간만 사용함
> - `CHAR(10)` : 내용이 3글자여도 항상 10글자 공간을 차지함
> - 학번처럼 **길이가 항상 같은 값**은 `CHAR`, 이름처럼 **길이가 다를 수 있는 값**은 `VARCHAR` 를 사용함

---

## 만들 출석부의 항목

| 항목 이름 | 의미 | 예시 |
|-----------|------|------|
| `id` | 자동으로 붙는 번호 | 1, 2, 3 … |
| `name` | 이름 | 김민준 |
| `dept` | 학과 | 컴퓨터과, 보안과 |
| `phone` | 전화번호 | 010-1234-5678 |
| `status` | 출석 상태 | 출석 / 지각 / 결석 |
| `check_date` | 날짜 | 2026-03-07 |

> 💡 학번은 따로 넣지 않음. `id` 가 1, 2, 3 … 순서로 자동 부여되므로 학번 역할을 대신함.

---

## 실행할 SQL

```sql
CREATE TABLE attendance (
    id          INT          NOT NULL AUTO_INCREMENT,
    name        VARCHAR(20)  NOT NULL,
    dept        VARCHAR(20)  NOT NULL,
    phone       CHAR(13),
    status      ENUM('출석','지각','결석') NOT NULL DEFAULT '출석',
    check_date  DATE         NOT NULL,
    PRIMARY KEY (id)
);
```

**각 줄 설명:**

| 줄 | 설명 |
|----|------|
| `id INT NOT NULL AUTO_INCREMENT` | 번호. 자동으로 1씩 늘어남. 비워두면 안 됨 |
| `name VARCHAR(20) NOT NULL` | 이름. 최대 20글자. 비워두면 안 됨 |
| `dept VARCHAR(20) NOT NULL` | 학과. 최대 20글자. 비워두면 안 됨 |
| `phone CHAR(13)` | 전화번호. 13글자 고정. 비워도 됨(NULL 허용) |
| `status ENUM(...) DEFAULT '출석'` | 출석 상태. 출석/지각/결석 중 하나만 입력 가능. 생략하면 자동으로 '출석' 입력 |
| `check_date DATE NOT NULL` | 날짜. 비워두면 안 됨 |
| `PRIMARY KEY (id)` | id 를 이 테이블의 대표 번호(기본키)로 지정 |

실행 후 테이블 구조를 확인함.

```sql
DESC attendance;
```

# 4단계. 학생 10명 입력하기

```sql
INSERT INTO attendance (name, dept, phone, status, check_date) VALUES
    ('김민준', '컴퓨터과',  '010-1234-5678', '출석', '2026-03-07'),
    ('이서연', '보안과',    '010-2345-6789', '출석', '2026-03-07'),
    ('박지호', '컴퓨터과',  '010-3456-7890', '지각', '2026-03-07'),
    ('최수아', '정보과',    '010-4567-8901', '출석', '2026-03-07'),
    ('정우진', '보안과',    '010-5678-9012', '결석', '2026-03-07'),
    ('한예은', '컴퓨터과',  NULL,            '출석', '2026-03-07'),
    ('오승현', '정보과',    '010-7890-1234', '출석', '2026-03-07'),
    ('윤채원', '보안과',    '010-8901-2345', '지각', '2026-03-07'),
    ('임도현', '컴퓨터과',  '010-9012-3456', '출석', '2026-03-07'),
    ('강하린', '정보과',    '010-0123-4567', '결석', '2026-03-07');
```

> 💡 `id` 는 적지 않아도 됨. `AUTO_INCREMENT` 설정 덕분에 1번부터 자동으로 번호가 붙음.
> `한예은(6번)` 의 전화번호는 `NULL` 로 비워 뒀음. 전화번호를 모르는 경우를 표현한 것임.

---

## ENUM 에 없는 값을 넣으면?

`status` 는 `'출석'`, `'지각'`, `'결석'` 세 가지만 허용함.
아래처럼 다른 값을 넣으면 MySQL이 오류를 발생시킴.

```sql
-- ⚠️ 아래는 오류가 발생하는 예시 (직접 실행해 볼 것)
INSERT INTO attendance (name, dept, status, check_date)
VALUES ('테스트', '컴퓨터과', '조퇴', '2026-03-07');
```

**오류 메시지 예시(Workbench 하단부):**

![](/assets/img/posts/2026-03-04-database-1-4-1772850370193.png)

```
Error Code: 1265. Data truncated for column 'status' at row 1
```

> 💡 `ENUM` 은 **입력 실수를 DBMS가 자동으로 막아주는 안전장치**임.
> '출석', '지각', '결석' 이외의 값(예: '조퇴', '병결', '공결')은 절대 들어갈 수 없음.
> 허용할 값을 추가하려면 테이블 구조 자체를 수정해야 함.

# 6단계. 내용 수정하기

## 6-1. 정우진(5번)의 출석 상태를 '결석' → '지각' 으로 바꾸기

```sql
-- 수정 전 확인
SELECT * FROM attendance WHERE id = 5;
```

![](/assets/img/posts/2026-03-04-database-1-4-1772850460271.png)


```sql
-- 수정 실행
UPDATE attendance SET status = '지각' WHERE id = 5;
```

```sql
-- 수정 후 확인
SELECT * FROM attendance WHERE id = 5;
```

![](/assets/img/posts/2026-03-04-database-1-4-1772850478223.png)

**수정 후 결과:** `정우진 | 지각` 으로 바뀐 것을 확인할 수 있음.

## 6-2. 한예은(6번)의 전화번호 추가하기

```sql
-- 수정 전 확인 (phone 이 NULL 인 것을 확인)
SELECT * FROM attendance WHERE id = 6;
```

```sql
-- 전화번호 추가
UPDATE attendance SET phone = '010-6789-0123' WHERE id = 6;
```

```sql
-- 수정 후 확인
SELECT * FROM attendance WHERE id = 6;
```

![](/assets/img/posts/2026-03-04-database-1-4-1772850510471.png)

**수정 후 결과:** `한예은 | 010-6789-0123` 으로 전화번호가 채워진 것을 확인할 수 있음.

> ⚠️ `WHERE id = 번호` 를 반드시 붙여야 함. WHERE 없이 실행하면 **전체 학생의 데이터가 바뀌어 버림.**

# 7단계. 데이터 삭제하기

## 강하린(10번) 한 명 삭제하기

```sql
-- 삭제 전 확인
SELECT * FROM attendance WHERE id = 10;
```

![](/assets/img/posts/2026-03-04-database-1-4-1772850525165.png)

```sql
-- 삭제 실행
DELETE FROM attendance WHERE id = 10;
```


```sql
-- 삭제 후 전체 확인 (9명으로 줄어든 것을 확인)
SELECT * FROM attendance;
```

![](/assets/img/posts/2026-03-04-database-1-4-1772850544342.png)

**삭제 후 결과:** 총 9명만 남고, `id = 10` 행이 사라진 것을 확인할 수 있음.

> 💡 삭제 후 새 학생을 추가하면 `id` 는 10이 아니라 **11부터** 시작함.
> 한 번 사용된 번호는 다시 쓰이지 않는 것이 MySQL의 기본 동작임.

# 8단계. 테이블 삭제하기

실습이 끝났으면 테이블을 삭제함.
테이블을 삭제하면 그 안의 데이터도 함께 모두 사라짐.

```sql
-- 삭제 전 테이블 목록 확인
SHOW TABLES;
```

```sql
-- 테이블 삭제
DROP TABLE IF EXISTS attendance;
```

```sql
-- 삭제 후 테이블 목록 확인
SHOW TABLES;
```

**삭제 후 결과:** `Empty set` 이 출력되면 테이블이 완전히 삭제된 것임.

| 명령어 | 무엇이 사라지나 | 되돌릴 수 있나 |
|--------|----------------|---------------|
| `DELETE FROM attendance WHERE id = 10` | 10번 행 하나 | 가능 |
| `DELETE FROM attendance` | 데이터 전체 (테이블 틀은 남음) | 불가 |
| `DROP TABLE attendance` | 테이블 전체 (틀까지 모두) | 불가 |

> ⚠️ `DROP TABLE` 은 되돌릴 수 없음. 삭제 전에 반드시 `SHOW TABLES;` 로 이름을 한 번 더 확인할 것.
