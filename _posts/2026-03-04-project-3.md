# 3부. 보안 위협 분석(참고)
---
## 1. 보안 모델링(Security Modeling)이란?

### 정의

> **보안 모델링(Security Modeling)** 이란, 시스템에 존재하는 **보안 위협을 체계적으로 식별하고 분석**하여, **보안 설계의 기초 자료**를 만드는 활동임.

### 왜 보안 모델링이 필요한가?

보안 취약점은 **개발 이후에 발견될수록 수정 비용이 기하급수적으로 증가**함. (IBM 연구 기준, 배포 후 발견된 버그는 설계 단계 대비 약 30배 비쌈)

```
[보안 결함 수정 비용 증가 추이]

설계 단계:   비용 1x   ← 여기서 잡는 것이 가장 저렴
개발 단계:   비용 6x
테스트 단계: 비용 15x
배포 이후:   비용 30x  ← 이미 사고가 난 후라면 더 큼
```

### 보안 모델링의 목표

1. 공격자(Attacker)의 시각으로 시스템을 바라봄
2. 보호해야 할 자산(Asset)을 명확히 함
3. 위협(Threat)을 체계적으로 나열함
4. 위협별 대응 방안을 도출함

## 2. 위협 모델링(Threat Modeling) 기법

### 대표적인 위협 모델링 기법 비교

| 기법 | 개발 주체 | 특징 | 적합한 대상 |
|------|---------|------|-----------|
| **STRIDE** | Microsoft | 위협 유형 분류 기반, 직관적 | 소프트웨어 개발 프로젝트 |
| **PASTA** | OWASP | 비즈니스 임팩트 중심, 7단계 프로세스 | 엔터프라이즈 애플리케이션 |
| **LINDDUN** | 연구 기관 | 프라이버시 위협에 특화 | 개인정보 처리 시스템 |
| **TRIKE** | 오픈소스 | 위험 기반(Risk-based) 분석 | 위험 관리 중심 조직 |
| **OCTAVE** | CMU | 조직 전체 위험 평가 | 대규모 기업 |
| **VAST** | ThreatModeler | 자동화, 대규모 Agile 환경 | DevSecOps 조직 |

> **[Opinion]** 학부 수준의 프로젝트에서는 STRIDE가 가장 직관적이고 배우기 쉬워 가장 먼저 적용하기 좋음.

## 3. STRIDE 기법 상세

### STRIDE란?

> **STRIDE** 는 Microsoft가 개발한 위협 분류 체계로, 6가지 위협 유형의 앞 글자를 딴 약어임.

![](/assets/img/posts/2026-03-04-project-3-1772543410004.png)


| 알파벳 | 위협 유형 | 영문 | 설명 | 침해하는 보안 속성 |
|--------|---------|------|------|----------------|
| **S** | 스푸핑 | Spoofing | 다른 사람이나 시스템인 척 위장 | 인증(Authentication) |
| **T** | 변조 | Tampering | 데이터나 코드를 무단으로 수정 | 무결성(Integrity) |
| **R** | 부인 | Repudiation | 자신의 행위를 부정함 | 부인방지(Non-repudiation) |
| **I** | 정보 유출 | Info Disclosure | 권한 없는 자에게 정보 노출 | 기밀성(Confidentiality) |
| **D** | 서비스 거부 | Denial of Service | 서비스 가용성 방해 | 가용성(Availability) |
| **E** | 권한 상승 | Elevation of Privilege | 허가되지 않은 권한 획득 | 권한부여(Authorization) |

### STRIDE 위협 예시 — 웹 로그인 시스템

```
[로그인 시스템 데이터 흐름]
사용자 → [로그인 폼] → [인증 서버] → [데이터베이스] → [세션 관리]
```

| STRIDE | 공격 시나리오 | 대응 방안 |
|--------|------------|---------|
| **S (스푸핑)** | 피싱 사이트로 사용자 유도, 세션 하이재킹 | HTTPS 강제, 이중 인증(2FA) |
| **T (변조)** | 전송 중 패킷 변조, 쿠키 변조 | HMAC 서명, 입력값 검증 |
| **R (부인)** | "나는 그 작업을 하지 않았다" 주장 | 감사 로그(Audit Log) 저장 |
| **I (정보 유출)** | SQL 인젝션으로 DB 데이터 탈취 | 매개변수화 쿼리, 암호화 |
| **D (서비스 거부)** | 브루트포스 공격으로 서버 마비 | 계정 잠금, CAPTCHA, Rate Limiting |
| **E (권한 상승)** | 일반 사용자가 관리자 권한 획득 | RBAC(역할 기반 접근 제어) |

### DFD(데이터 흐름도, Data Flow Diagram)와 STRIDE

STRIDE는 DFD의 각 요소에 체계적으로 적용함.

| DFD 요소 | 설명 | 적용 가능한 STRIDE |
|---------|------|-----------------|
| **외부 엔티티(External Entity)** | 시스템 외부의 행위자 (사용자, 외부 시스템) | S, R |
| **프로세스(Process)** | 데이터를 처리하는 기능 | S, T, R, I, D, E |
| **데이터 저장소(Data Store)** | 데이터를 저장하는 곳 (DB, 파일) | T, R, I, D |
| **데이터 흐름(Data Flow)** | 요소 간 데이터 이동 경로 | T, I, D |

## 4. 자산(Asset) 식별

### 자산이란?

> **자산(Asset)** 이란, 조직에 가치가 있어 **보호할 필요가 있는 모든 것**임.

### 자산의 유형

| 분류 | 유형 | 예시 |
|------|------|------|
| **정보 자산** | 데이터, 코드, 문서 | 고객 DB, 소스코드, 계약서 |
| **하드웨어 자산** | 물리적 장비 | 서버, 네트워크 장비, 스토리지 |
| **소프트웨어 자산** | 시스템, 애플리케이션 | OS, ERP, 웹 서버 |
| **서비스 자산** | 네트워크, 클라우드 | DNS, CDN, API 서버 |
| **인적 자산** | 사람, 전문 지식 | 개발자, 보안 담당자 |
| **평판 자산** | 브랜드, 신뢰 | 서비스 신뢰도, 기업 이미지 |

### 자산 중요도 평가 예시 (CIA 기준, 5점 척도)

| 자산 | 기밀성(C) | 무결성(I) | 가용성(A) | 총점 | 등급 |
|------|---------|---------|---------|------|------|
| 고객 개인정보 DB | 5 | 5 | 4 | 14 | 최상 |
| 웹 서버 | 2 | 4 | 5 | 11 | 상 |
| 사내 공지 게시판 | 1 | 2 | 3 | 6 | 하 |

*(5: 매우 높음 ~ 1: 매우 낮음)*

## 5. 위험(Risk) 평가

### 위험의 구성 요소

> **위험(Risk)** = **자산의 가치(Asset Value)** × **위협의 가능성(Threat Likelihood)** × **취약점의 심각도(Vulnerability Severity)**

```
[위험 계산 공식]
Risk = Impact × Likelihood
```

### 위험 평가 매트릭스(Risk Matrix)

![](/assets/img/posts/2026-03-04-project-3-1772583785866.png)
### 정량적 vs 정성적 위험 평가

| 구분 | 정량적(Quantitative) | 정성적(Qualitative) |
|------|-------------------|------------------|
| **방법** | 숫자로 표현 (금전적 손실) | 등급으로 표현 (상/중/하) |
| **장점** | 객관적, 비용 계산 가능 | 빠르고 간단 |
| **단점** | 데이터 수집 어려움 | 주관적 판단 개입 |
| **예시** | ALE = SLE × ARO | 위험 = 상/중/하 |

### 위험 분석 공식 및 정의

| **용어**  | **풀이**                            | **의미**                               |
| ------- | --------------------------------- | ------------------------------------ |
| **SLE** | **Single Loss Expectancy**        | 특정 자산에 **사고가 한 번 발생했을 때** 입는 금전적 손실액 |
| **ARO** | **Annualized Rate of Occurrence** | 1년 동안 해당 사고가 **발생할 것으로 예상되는 횟수**     |
| **ALE** | **Annual Loss Expectancy**        | 1년 동안 발생할 전체 **기대 손실액** (예산 편성의 기준)  |

#### 공식 (The Formula)

가장 핵심이 되는 관계식은 다음과 같습니다.

$$
ALE = SLE \times ARO
$$

또한, **SLE**를 구하기 위해서는 자산의 가치와 노출 계수를 알아야 합니다.

$$
SLE = Asset Value \times Exposure Factor (EF)
$$

> - **Asset Value (자산 가치):** 하드웨어, 데이터, 브랜드 가치 등>     
> - **Exposure Factor (노출 계수):** 사고 발생 시 자산이 손실되는 비율 (0%~100%)>

### STRIDE 위협별 위험 평가 예시 (온라인 쇼핑몰)

| 위협             | 자산       | 발생 가능성 | 영향도 | 위험 등급 | 우선순위 |
| -------------- | -------- | ------ | --- | ----- | ---- |
| SQL 인젝션 (T, I) | 고객 DB    | 높음     | 높음  | 매우 높음 | 1    |
| DDoS (D)       | 웹 서버     | 중간     | 높음  | 높음    | 2    |
| 세션 하이재킹 (S)    | 인증 서버    | 중간     | 중간  | 중간    | 3    |
| 내부자 정보 유출 (I)  | 거래 내역 DB | 낮음     | 높음  | 중간    | 4    |
