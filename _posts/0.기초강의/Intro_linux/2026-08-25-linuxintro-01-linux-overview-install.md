# 제1절. 리눅스의 이해

---

## 1.1 운영체제의 개념

컴퓨터는 중앙처리장치(CPU), 주기억장치(메모리), 보조기억장치(디스크), 입출력 장치로 구성된다. 이러한 하드웨어는 그 자체로는 아무런 작업도 수행하지 못하며, 이를 제어하고 자원을 배분하는 소프트웨어가 필요하다. 이 소프트웨어를 **운영체제(Operating System, OS)** 라 한다.

운영체제가 수행하는 주요 기능은 다음과 같다.

| 기능 | 설명 |
|---|---|
| 프로세스 관리 | 어떤 프로그램에 CPU를 얼마나 할당할 것인지 결정한다. |
| 메모리 관리 | 각 프로그램이 사용할 메모리 영역을 배정하고 보호한다. |
| 파일 시스템 관리 | 데이터를 파일 단위로 저장하고 검색할 수 있도록 한다. |
| 장치 관리 | 키보드·디스크·네트워크 카드 등을 프로그램이 사용할 수 있게 한다. |
| 사용자 인터페이스 제공 | 사용자가 명령을 내리고 결과를 확인할 수 있는 창구를 제공한다. |

윈도우(Windows), macOS, 리눅스(Linux)는 모두 이러한 기능을 수행하는 운영체제이다.

---

## 1.2 리눅스의 위치와 활용 범위

리눅스는 일반 사용자에게 다소 생소하게 느껴질 수 있으나, 실제로는 매우 광범위하게 사용되고 있다.

| 분야 | 구체적 사례 |
|---|---|
| 모바일 | 안드로이드 운영체제는 리눅스 커널을 기반으로 한다. |
| 인터넷 서비스 | 대규모 웹 서비스의 서버 대부분이 리눅스로 운영된다. |
| 네트워크 장비 | 가정용 공유기, 기업용 라우터의 내부 운영체제 |
| 임베디드 시스템 | 스마트 TV, 차량 인포테인먼트, 산업 제어 장치 |
| 고성능 컴퓨팅 | 세계 슈퍼컴퓨터 상위 500대 전부가 리눅스를 채택하고 있다. |
| 클라우드·컨테이너 | 클라우드 인스턴스와 컨테이너 기술의 기반 환경 |

따라서 정보기술 분야의 실무에서 리눅스는 선택 사항이 아니라 기본 소양에 해당한다.

## 1.3 윈도우와 리눅스의 비교

학습자 대부분이 윈도우에 익숙하므로, 두 운영체제의 차이를 먼저 정리한다.

| 비교 항목 | 윈도우 | 리눅스 |
|---|---|---|
| 라이선스 | 상용(유료) | 대부분 무료·오픈소스 |
| 소스 코드 | 비공개 | 공개 |
| 주된 조작 방식 | 그래픽 사용자 인터페이스(GUI) | **명령행 인터페이스(CLI)** |
| 저장 장치 표현 | `C:`, `D:` 등 드라이브 문자로 분리 | **`/`(루트)를 정점으로 하는 단일 트리** |
| 파일명 대소문자 | 구분하지 않음 | **구분함** |
| 관리자 계정 | Administrator | **root** |
| 주된 사용 영역 | 개인용 컴퓨터 | 서버·임베디드·클라우드 |

> **유의 사항**
> 리눅스는 대소문자를 엄격히 구분한다. `Data.txt`와 `data.txt`는 서로 다른 파일이며, 명령어 역시 `ls`는 동작하지만 `LS`는 동작하지 않는다. 초심자가 가장 빈번하게 겪는 오류의 원인이므로 반드시 유의해야 한다.
{: .prompt-warning }

## 1.4 리눅스의 계층 구조

리눅스 시스템은 하드웨어를 중심으로 세 개의 계층이 겹겹이 감싸는 구조를 이룬다.

```
 ┌─────────────────────────────────────────────┐
 │  응용 프로그램                                │
 │  (웹 서버, 편집기, 데이터베이스 등)             │
 ├─────────────────────────────────────────────┤
 │  셸(Shell)                                   │
 │  사용자의 명령을 해석하여 커널에 전달           │
 ├─────────────────────────────────────────────┤
 │  커널(Kernel)                                │
 │  프로세스·메모리·파일 시스템·장치 관리          │
 ├─────────────────────────────────────────────┤
 │  하드웨어 (CPU, 메모리, 디스크, 네트워크 카드)   │
 └─────────────────────────────────────────────┘
```

각 계층의 역할은 다음과 같다.

| 계층             | 역할                                            | 비유        |
| -------------- | --------------------------------------------- | --------- |
| **커널(Kernel)** | 하드웨어를 직접 제어하는 핵심부. 엄밀한 의미의 '리눅스'는 이 커널을 가리킨다. | 자동차의 엔진   |
| **셸(Shell)**   | 사용자가 입력한 문자열을 해석하여 커널에 전달하는 명령 해석기            | 운전대와 페달   |
| **응용 프로그램**    | 사용자가 실제로 이용하는 프로그램                            | 오디오·공조 장치 |

셸(Shell)이라는 명칭은 '껍데기'를 뜻하며, 커널(Kernel, 알맹이)을 감싸고 있다는 데에서 유래하였다. 사용자는 커널에 직접 접근하지 못하고 반드시 셸을 거쳐야 하는데, 이러한 구조가 리눅스 보안의 출발점이 된다.

---

> ### 따라 하기 1-1. 리눅스의 세 계층 확인하기
>
> **목적** 커널·셸·응용 프로그램이 실제로 어떤 이름으로 존재하는지 명령어로 확인한다.
{: .prompt-tip }

**1단계.** 커널의 버전을 확인한다.

```bash
uname -r
```

> `uname`은 **u**nix **name**의 약어이며, `-r`은 **r**elease(배포 번호)를 의미한다. `6.8.0-xx-generic`과 같은 형태로 출력되며, 이것이 현재 동작 중인 커널이다.

**2단계.** 셸의 종류를 확인한다.

```bash
echo $SHELL
```

> `echo`는 문자열을 화면에 출력하는 명령이고, `$SHELL`은 로그인 셸 경로를 담고 있는 변수이다. 일반적으로 `/bin/bash`가 출력된다.

**3단계.** 응용 프로그램의 실체를 확인한다.

```bash
which ls
```

> `which`는 해당 명령어의 실행 파일이 어디에 있는지 알려 준다. `/usr/bin/ls`가 출력되며, 이는 `ls`가 디스크에 존재하는 하나의 프로그램임을 의미한다.

**4단계.** 세 계층의 정보를 한 번에 확인한다.

```bash
uname -a
```

> `-a`는 **a**ll(전부)의 약어이다. 출력은 왼쪽부터 커널 이름, 호스트 이름, 커널 배포 번호, 빌드 정보, 하드웨어 아키텍처(`x86_64`), 운영체제 순이다.

> **확인 사항** 커널 버전, 셸 경로, `ls`의 실제 위치를 각각 다른 명령으로 확인하였다면 성공이다.
{: .prompt-tip }

## 1.5 리눅스의 역사와 라이선스

### 1.5.1 발전 과정

| 연도 | 사건 |
|---|---|
| 1969 | 벨 연구소에서 **유닉스(UNIX)** 개발 |
| 1973 | 유닉스를 C 언어로 재작성하여 이식성 확보 |
| 1983 | 리처드 스톨만이 **GNU 프로젝트** 시작 |
| 1991 | 리누스 토르발스가 **리눅스 커널** 최초 공개 |
| 1992 | 리눅스 커널을 GPL로 배포하여 GNU 유틸리티와 결합 |
| 2004 | **우분투(Ubuntu)** 최초 배포 |
| 2024 | **Ubuntu 24.04 LTS(Noble Numbat)** 배포 |

여기서 반드시 구분해야 할 개념이 있다. **유닉스는 상용 운영체제의 계보이고, 리눅스는 유닉스의 설계 철학과 인터페이스를 따르되 코드는 새로 작성한 독립적 구현**이다. 즉 리눅스는 유닉스의 후손이 아니라, 유닉스의 규격을 공유하는 별개의 운영체제이다.

또한 엄밀히 말하면 리눅스는 커널의 이름이며, 여기에 GNU 프로젝트가 제작한 유틸리티가 결합되어야 완전한 운영체제가 된다. 이 때문에 GNU 진영에서는 **GNU/Linux**라는 명칭을 권장한다.

### 1.5.2 자유 소프트웨어와 GPL

자유 소프트웨어 재단은 사용자가 누려야 할 네 가지 자유를 정의하였다.

| 구분 | 내용 |
|---|---|
| 자유 0 | 목적을 불문하고 프로그램을 **실행**할 자유 |
| 자유 1 | 프로그램의 동작을 **연구하고 수정**할 자유 |
| 자유 2 | 복제본을 **재배포**할 자유 |
| 자유 3 | 수정한 판본을 **배포**할 자유 |

리눅스 커널이 채택한 **GPL(GNU General Public License)** 의 핵심은 **카피레프트(copyleft)** 이다. GPL 소프트웨어를 수정하여 배포하는 경우, 그 파생물 역시 GPL로 공개하여야 한다. 이 조항이 리눅스 생태계가 특정 기업에 독점되지 않고 발전할 수 있었던 제도적 기반이 되었다.

| 라이선스 | 카피레프트 강도 | 특징 |
|---|---|---|
| GPL | 강함 | 파생물도 반드시 동일 조건으로 공개 |
| LGPL | 약함 | 라이브러리 링크 시 독점 배포 허용 |
| BSD / MIT | 없음 | 저작권 표시만 유지하면 독점 소프트웨어에 포함 가능 |
| Apache 2.0 | 없음 | 특허 관련 조항을 명시 |

> **자주 출제되는 개념**
> GPL로 배포된 프로그램을 수정하여 **판매하는 것은 가능하다.** 다만 판매 시 소스 코드를 함께 제공하고 동일한 GPL 조건으로 배포해야 한다. GPL은 '무상'이 아니라 '자유'를 규정하는 라이선스이다.
{: .prompt-warning }

## 1.6 배포판의 이해

커널만으로는 시스템을 운영할 수 없으므로, 커널·유틸리티·패키지 관리자·설치 프로그램을 하나로 묶어 배포한다. 이를 **배포판(Distribution)** 이라 한다. 배포판의 계열은 **패키지 관리 방식**을 기준으로 구분한다.

| 계열 | 대표 배포판 | 패키지 형식 | 저수준 도구 | 고수준 도구 |
|---|---|---|---|---|
| **데비안 계열** | Debian, **Ubuntu**, Linux Mint | `.deb` | `dpkg` | `apt` |
| **레드햇 계열** | RHEL, Rocky, Fedora | `.rpm` | `rpm` | `dnf`(구 `yum`) |
| 슬랙웨어 계열 | Slackware | `.tgz` | `pkgtool` | `slackpkg` |
| 기타 | Arch, openSUSE, Gentoo | 각기 다름 | `pacman`, `zypper` | — |

우분투의 버전 표기는 **배포 연도.월** 형식을 따른다. `24.04`는 2024년 4월에 배포되었음을 의미하며, 짝수 해 4월 판본은 **LTS(Long Term Support, 장기 지원)** 로 지정되어 5년간 표준 보안 갱신을 제공한다. 서버 환경에서는 잦은 재구축을 피하기 위해 LTS 판본을 선택하는 것이 원칙이다.

---

> ### 따라 하기 1-2. 배포판 정보 확인하기
>
> **목적** 현재 시스템이 어떤 배포판이며 어떤 버전인지 확인한다.
{: .prompt-tip }

**1단계.** 배포판 표준 정보 파일을 확인한다.

```bash
cat /etc/os-release
```

> `cat`은 con**cat**enate(연결하다)의 약어로, 파일 내용을 화면에 출력한다. 출력 중 `VERSION="24.04.3 LTS (Noble Numbat)"` 형태의 항목을 확인한다. `Noble Numbat`은 Ubuntu 24.04의 별칭이다.
>
> 세 번째 자리의 숫자(`.3`)는 **포인트 릴리스** 번호로, 그동안의 보안 갱신을 반영하여 재배포한 판본을 의미한다. 내려받은 시점에 따라 `24.04.1`, `24.04.2` 등으로 다를 수 있으며, 앞의 `24.04`가 동일하면 같은 판본이다.

**2단계.** 배포판 정보를 요약해서 확인한다.

```bash
lsb_release -a
```

> `lsb`는 **L**inux **S**tandard **B**ase의 약어이다. 명령이 존재하지 않으면 `sudo apt install lsb-release`로 설치할 수 있다.

**3단계.** 호스트 전반의 정보를 한 번에 확인한다.

```bash
hostnamectl
```

> 컴퓨터 이름, 운영체제, 커널, 하드웨어 아키텍처를 정리된 형태로 출력한다.

**4단계.** 패키지 관리 도구가 무엇인지 확인한다.

```bash
which apt dpkg
```

> 두 명령의 경로가 출력되면 데비안 계열임을 확인한 것이다. `rpm`이나 `dnf`는 존재하지 않는다.

> **확인 사항** 배포판이 Ubuntu 24.04 LTS이고 데비안 계열이며 `apt`를 사용한다는 사실을 명령어로 확인하였다면 성공이다.
{: .prompt-tip }

# 제2절. 명령행 인터페이스의 이해

---

## 2.1 명령행 인터페이스와 프롬프트

리눅스 서버는 대부분 그래픽 환경 없이 문자만으로 조작한다. 이러한 방식을 **명령행 인터페이스(Command Line Interface, CLI)** 라 한다.

사용자가 로그인하면 다음과 같은 문자열이 표시되며, 이를 **프롬프트(prompt)** 라 한다.

```
student@ubuntu-lab:~$
```

프롬프트는 짧지만 네 가지 정보를 담고 있다.

```
 student  @  ubuntu-lab  :  ~  $
    │      │      │       │  │  │
    │      │      │       │  │  └─ 권한 구분 기호
    │      │      │       │  └──── 현재 작업 디렉터리
    │      │      │       └─────── 구분자
    │      │      └─────────────── 호스트(컴퓨터) 이름
    │      └────────────────────── "~에 소속된"의 의미
    └───────────────────────────── 로그인한 사용자 이름
```

| 구성 요소 | 의미 |
|---|---|
| 사용자 이름 | 현재 로그인한 계정 |
| `@` | "~에 소속된"을 뜻하는 구분자 |
| 호스트 이름 | 이 컴퓨터에 부여된 이름 |
| 현재 디렉터리 | `~`는 해당 사용자의 홈 디렉터리를 나타내는 약칭이다. |
| **`$` 또는 `#`** | **`$`는 일반 사용자, `#`는 관리자(root)를 의미한다.** |

> **가장 중요한 확인 습관**
> 프롬프트 마지막 한 글자를 항상 확인하는 습관을 들여야 한다. `$`는 일반 사용자이므로 실수하더라도 피해가 자신의 파일에 한정되지만, `#`는 관리자이므로 잘못된 명령 하나가 시스템 전체를 손상시킬 수 있다.
{: .prompt-warning }

---

> ### 따라 하기 1-3. 프롬프트 해석과 사용자 확인
>
> **목적** 프롬프트가 표시하는 정보를 명령어로 각각 확인하고, 관리자 전환 시 프롬프트가 변화하는 것을 관찰한다.
{: .prompt-tip }

**1단계.** 현재 로그인한 사용자를 확인한다.

```bash
whoami
```

> `whoami`는 "who am i(나는 누구인가)"를 붙여 쓴 명령이다. 프롬프트의 `@` 앞부분과 일치하는지 확인한다.

**2단계.** 컴퓨터 이름을 확인한다.

```bash
hostname
```

> 프롬프트의 `@` 뒷부분과 일치하는지 확인한다.

**3단계.** 현재 작업 디렉터리를 확인한다.

```bash
pwd
```

> `pwd`는 **p**rint **w**orking **d**irectory(현재 작업 디렉터리를 출력하라)의 약어이다. `/home/student`와 같이 출력되며, 프롬프트의 `~`가 바로 이 경로의 축약 표기임을 알 수 있다.

**4단계.** 관리자로 전환하여 프롬프트의 변화를 관찰한다.

```bash
sudo -i
```

> `sudo`는 **s**uper**u**ser **do**(관리자 권한으로 실행하라)의 약어이다. 비밀번호를 요구하면 **자신의 비밀번호**를 입력한다. 입력 중 화면에 아무 문자도 표시되지 않는 것은 정상 동작이다.

```bash
whoami
```

> `root`가 출력되고, 프롬프트 기호가 `$`에서 `#`로 변경된 것을 확인한다.

**5단계.** 원래 계정으로 복귀한다.

```bash
exit
```

> 프롬프트가 다시 `$`로 돌아왔는지 확인한다.

> **확인 사항** `whoami`의 출력이 '자신의 계정 → root → 자신의 계정' 순으로 변하고, 프롬프트 기호가 `$ → # → $`로 변화하였다면 성공이다.
{: .prompt-tip }

> **참고 — 우분투에서 `su -`가 동작하지 않는 이유**
> 우분투는 보안 정책상 root 계정에 비밀번호를 설정하지 않고 잠가 둔다. 따라서 `su -`로는 관리자가 될 수 없으며, 모든 관리 작업은 `sudo`를 통해 수행한다. 이렇게 하면 누가 언제 어떤 관리 명령을 실행했는지 기록이 남아 감사(audit)가 가능해진다.
{: .prompt-info }

---

## 2.2 명령어의 구조

리눅스 명령어는 다음과 같은 일정한 형식을 따른다.

```
 명령어   [옵션]      [인자]
   ls      -l  -h      /etc
    │       │            │
    │       │            └── 인자(argument): 명령이 작용할 대상
    │       └─────────────── 옵션(option): 동작 방식을 조정하는 값
    └─────────────────────── 명령(command): 실행할 프로그램
```

옵션의 표기 방식은 두 가지가 있다.

| 형식 | 표기 | 예시 |
|---|---|---|
| 짧은 옵션 | 하이픈 1개 + 알파벳 1글자 | `ls -l`, `ls -a` |
| 긴 옵션 | 하이픈 2개 + 단어 | `ls --all`, `du --max-depth=1` |

짧은 옵션은 하나로 묶어 쓸 수 있다. `ls -l -a -h`와 `ls -lah`는 동일한 명령이다.

---

## 2.3 도움말 조회 방법

명령어의 옵션을 모두 암기할 필요는 없다. 리눅스는 체계적인 도움말 체계를 갖추고 있다.

| 명령 | 설명 |
|---|---|
| `man 명령어` | 매뉴얼 페이지 표시. 가장 상세한 공식 문서 |
| `명령어 --help` | 간략한 사용법 요약 |
| `whatis 명령어` | 한 줄 설명 |
| `type 명령어` | 내부 명령인지 외부 명령인지 판별 |

매뉴얼은 주제별로 **섹션(section)** 이 구분되어 있다.

| 섹션 | 내용 |
|---|---|
| 1 | 일반 사용자 명령 |
| 5 | **파일 형식 및 설정 파일** |
| 8 | 시스템 관리자 명령 |

동일한 이름이 여러 섹션에 존재하는 경우 섹션 번호를 명시한다. `man passwd`는 `passwd` 명령을, `man 5 passwd`는 `/etc/passwd` 파일의 형식을 설명한다. 이 구분은 3강에서 계정 파일을 학습할 때 유용하게 활용된다.

`man` 화면은 `less`라는 페이지 표시 프로그램으로 출력되며, 다음 키로 조작한다.

| 키 | 동작 |
|---|---|
| `Space` | 다음 화면 |
| `b` | 이전 화면 |
| `/문자열` | 아래 방향 검색 |
| `n` | 다음 검색 결과 |
| `g` / `G` | 문서 처음 / 끝 |
| **`q`** | **종료** |

---

## 2.4 명령행 편집 단축키

효율적인 작업을 위해 다음 단축키를 익혀 두어야 한다.

| 키 | 동작 | 활용 상황 |
|---|---|---|
| **`Tab`** | 이름 자동 완성 | **오타를 줄이는 가장 효과적인 수단이다.** |
| `↑` `↓` | 이전 명령 불러오기 | 동일한 명령을 반복할 때 |
| `Ctrl + R` | 이전 명령 검색 | 오래전에 사용한 명령을 찾을 때 |
| `Ctrl + A` / `Ctrl + E` | 행의 처음 / 끝으로 이동 | 긴 명령을 수정할 때 |
| `Ctrl + U` / `Ctrl + K` | 커서 앞 / 뒤 삭제 | 입력을 취소할 때 |
| **`Ctrl + C`** | **실행 중단** | **화면이 멈춘 것처럼 보일 때** |
| `Ctrl + L` | 화면 지우기 | 화면이 복잡할 때 |
| `Ctrl + D` | 입력 종료(로그아웃) | 세션을 종료할 때 |

---

> ### 따라 하기 1-4. 도움말과 단축키 익히기
>
> **목적** 매뉴얼을 조회하고 자동 완성 기능을 체험한다.
{: .prompt-tip }

**1단계.** 자동 완성 기능을 사용한다.

터미널에 `hist`까지만 입력하고 `Tab` 키를 누른다.

```bash
hist
```

> `history`로 자동 완성되는 것을 확인한다. 이어서 `Enter`를 눌러 실행하면 지금까지 입력한 명령 목록이 출력된다.

**2단계.** 후보가 여러 개일 때의 동작을 확인한다.

`ls`까지 입력하고 `Tab` 키를 **두 번** 누른다.

```bash
ls
```

> `ls`, `lsblk`, `lscpu` 등 `ls`로 시작하는 명령 목록이 표시된다.

**3단계.** 매뉴얼을 조회한다.

```bash
man ls
```

> 화면 내에서 `/-a`를 입력한 뒤 `Enter`를 눌러 `-a` 옵션 설명을 검색한다. `q`를 눌러 종료한다.

**4단계.** 섹션이 다른 매뉴얼을 비교한다.

```bash
man 1 passwd
```

```bash
man 5 passwd
```

> 전자는 비밀번호를 변경하는 **명령**을, 후자는 `/etc/passwd` **파일의 형식**을 설명한다. 각각 `q`로 종료한다.

**5단계.** 간략 설명과 명령 종류를 확인한다.

```bash
whatis pwd
```

```bash
type pwd
```

```bash
type -a ls
```

> `pwd`는 `pwd is a shell builtin`으로 출력된다. 셸에 내장된 명령이라는 의미이다.
>
> `ls`는 다음과 같이 **세 줄**이 출력된다.
>
> ```
> ls is aliased to `ls --color=auto'
> ls is /usr/bin/ls
> ls is /bin/ls
> ```
>
> 첫 줄은 우분투가 `~/.bashrc`에 기본 등록해 둔 **별칭**이다. 색상 표시 옵션을 자동으로 붙여 주기 위한 것으로, 별칭이 있으면 그것이 가장 먼저 적용된다. 이어지는 두 줄이 실제 실행 파일의 위치이며, **`ls`는 디스크에 실행 파일이 존재하는 외부 명령**임을 확인할 수 있다.
>
> `-a`(**a**ll) 없이 `type ls`만 실행하면 별칭 한 줄만 표시된다. 별칭은 제4강 2.7절에서 상세히 다룬다.

> **확인 사항** `Tab` 자동 완성을 사용해 보았고, `man 1 passwd`와 `man 5 passwd`의 내용이 서로 다름을 확인하였다면 성공이다.
{: .prompt-tip }

# 제3절. 부팅 과정과 시스템 상태

---

## 3.1 부팅의 정의와 단계

**부팅(Booting)** 이란 컴퓨터의 전원을 인가한 시점부터 운영체제가 완전히 동작하여 로그인 프롬프트가 출력될 때까지의 과정을 말한다. 이 과정은 다음 다섯 단계로 이루어진다.

```
 ① BIOS / UEFI
      하드웨어 자체 점검(POST) 수행, 부팅 장치 선택
                    ↓
 ② MBR (디스크 첫 번째 섹터)
      부트로더의 위치와 파티션 정보 확인
                    ↓
 ③ 부트 로더 (GRUB)
      부팅 메뉴 표시, 커널을 메모리에 적재
                    ↓
 ④ 커널 (Kernel)
      CPU·메모리 초기화, 하드웨어 인식, 루트 파일 시스템 마운트
                    ↓
 ⑤ systemd (PID 1)
      서비스(데몬)를 순차적으로 기동
                    ↓
              로그인 프롬프트
```

각 단계의 세부 동작은 다음과 같다.

| 단계 | 수행 내용 |
|---|---|
| **BIOS/UEFI** | ROM에 저장된 펌웨어. 전원을 켜면 가장 먼저 동작하여 메모리·키보드 등 하드웨어 상태를 점검한다. |
| **MBR** | **M**aster **B**oot **R**ecord. 하드디스크 0번 섹터에 위치하며, 부트로더와 파티션 테이블 정보를 담는다. |
| **GRUB** | 커널 이미지를 메모리에 적재하고 제어권을 커널에 넘긴다. 여러 운영체제가 설치된 경우 선택 메뉴를 제공한다. |
| **커널** | CPU 레지스터 초기화, 메모리 관리 체계 구성, 장치 인식, 루트 파일 시스템 연결, 최초 프로세스 생성 |
| **systemd** | PID 1번 프로세스. 기본 타깃에 따라 필요한 서비스를 병렬로 기동한다. |

> **용어 정리 — 데몬(Daemon)**
> 사용자와 직접 상호작용하지 않고 배경에서 지속적으로 실행되며 서비스를 제공하는 프로세스를 말한다. 명칭이 대부분 `d`로 끝나는 특징이 있다. 예를 들어 `sshd`는 원격 접속을, `systemd`는 시스템 관리를 담당한다.
{: .prompt-info }

---

## 3.2 부트 매니저 GRUB

**GRUB(GRand Unified Bootloader)** 는 우분투를 비롯한 대부분의 리눅스 배포판이 채택한 부트로더이다. GRUB의 주요 기능은 다음과 같다.

- 여러 커널 또는 여러 운영체제 중 부팅 대상을 선택하게 한다(멀티 부팅).
- 커널에 부팅 파라미터를 전달한다.
- 시스템 장애 시 복구 모드로 진입할 경로를 제공한다.

GRUB의 설정 파일은 두 종류이며, **어느 파일을 편집해야 하는지 구분하는 것이 매우 중요하다.**

| 파일 | 편집 여부 | 설명 |
|---|---|---|
| `/etc/default/grub` | **편집 대상** | 메뉴 대기 시간, 기본 항목, 커널 파라미터 등 |
| `/etc/grub.d/` | 편집 대상 | 메뉴 항목을 생성하는 스크립트 |
| `/boot/grub/grub.cfg` | **편집 금지** | 위 두 곳으로부터 자동 생성되는 최종 설정 파일 |

`/etc/default/grub`을 수정한 뒤에는 반드시 다음 명령으로 최종 설정 파일을 재생성해야 한다.

```bash
sudo update-grub
```

> **유의 사항**
> `/boot/grub/grub.cfg`를 직접 편집하면 다음 커널 갱신 시 `update-grub`이 실행되면서 수정 내용이 모두 소실된다. 반드시 `/etc/default/grub`을 수정한 뒤 `update-grub`을 실행하여야 한다.
{: .prompt-warning }

또한 GRUB은 부팅 대상을 선택할 권한을 제공하므로, 물리적 접근이 가능한 공격자에게는 강력한 도구가 된다. 커널 파라미터에 특정 값을 추가하면 인증 절차 없이 관리자 셸을 획득할 수 있기 때문이다. 따라서 물리 보안이 확보되지 않은 환경에서는 GRUB 메뉴 편집에 별도의 비밀번호를 설정하는 것이 권장된다.

---

## 3.3 런레벨과 systemd 타깃

시스템이 어떤 상태로 동작하고 있는지를 나타내는 개념을 **런레벨(Runlevel)** 이라 한다. 전통적인 SysV init 방식에서는 0부터 6까지의 숫자로 표현하였으며, systemd로 전환된 이후에는 **타깃(Target)** 이라는 명칭으로 대체되었다. 다만 호환성을 위해 양자의 대응 관계가 유지되고 있다.

| 런레벨 | 명칭 | 설명 | systemd 타깃 |
|---|---|---|---|
| 0 | 종료(Halt) | 시스템 종료 상태 | `poweroff.target` |
| 1 | 단일 사용자 모드 | 복구 모드. 최소한의 서비스만 동작 | `rescue.target` |
| 2 | 다중 사용자 모드 | 네트워크 서비스 비활성화 | `multi-user.target` |
| **3** | **다중 사용자 모드** | **텍스트 모드(CLI). 서버 기본값** | **`multi-user.target`** |
| 4 | 미사용 | 사용자 정의 가능 | `multi-user.target` |
| **5** | **그래픽 모드** | 런레벨 3 + X 윈도 | **`graphical.target`** |
| 6 | 재부팅 | 시스템 재시작 | `reboot.target` |

---

## 3.4 시스템 종료와 재부팅

| 명령 | 설명 |
|---|---|
| `sudo shutdown -h now` | 즉시 종료(`-h`는 **h**alt, 정지) |
| `sudo shutdown -r +10 "점검"` | 10분 뒤 재부팅(`-r`은 **r**eboot) 및 접속자 통보 |
| `sudo shutdown -c` | 예약된 종료 취소(`-c`는 **c**ancel) |
| `sudo poweroff` | 즉시 전원 차단 |
| `sudo reboot` | 즉시 재부팅 |

> **유의 사항**
> 전원 버튼을 눌러 강제로 종료하면 메모리 버퍼에 남아 있던 데이터가 유실되고 파일 시스템이 손상될 수 있다. 반드시 위 명령을 사용하여 종료하여야 한다.
{: .prompt-warning }

---

> ### 따라 하기 1-5. 부팅 설정과 시스템 상태 확인
>
> **목적** GRUB 설정 파일의 구조를 확인하고, 현재 시스템의 타깃과 부팅 소요 시간을 조회한다.
{: .prompt-tip }

**1단계.** 편집 대상 GRUB 설정 파일을 확인한다.

```bash
cat /etc/default/grub
```

> `GRUB_TIMEOUT`(메뉴 대기 시간), `GRUB_CMDLINE_LINUX_DEFAULT`(커널 파라미터) 항목을 확인한다.

**2단계.** 자동 생성되는 파일의 경고 문구를 확인한다.

```bash
sudo head -10 /boot/grub/grub.cfg
```

> `head -10`은 앞 10줄만 출력하라는 뜻이다. 파일 상단에 "DO NOT EDIT THIS FILE"이라는 문구가 기재되어 있음을 확인한다.

```bash
wc -l /boot/grub/grub.cfg
```

> `wc`는 **w**ord **c**ount의 약어이고 `-l`은 **l**ines(행 수)이다. 수백 행에 이르는 이 파일이 사람이 작성한 것이 아님을 알 수 있다.

**3단계.** 실제로 커널에 전달된 파라미터를 확인한다.

```bash
cat /proc/cmdline
```

**4단계.** 현재 기본 타깃을 확인한다.

```bash
systemctl get-default
```

> 서버 환경에서는 `multi-user.target`이 출력되며, 이는 전통적 런레벨 3에 해당한다.

```bash
runlevel
```

> `N 3` 또는 `N 5` 형태로 출력된다. 앞의 `N`은 이전 런레벨이 없음(부팅 후 변경 없음)을 의미한다.

**5단계.** 런레벨과 타깃의 대응 관계를 직접 확인한다.

```bash
ls -l /lib/systemd/system/runlevel*.target
```

> `runlevel5.target -> graphical.target`과 같이 화살표로 연결된 것이 보인다. 옛 명칭을 현재 명칭으로 연결해 둔 것이다.

**6단계.** 부팅 소요 시간을 분석한다.

```bash
systemd-analyze
```

```bash
systemd-analyze blame | head -10
```

> `blame`은 각 서비스의 기동 소요 시간을 내림차순으로 출력한다. 부팅이 지연될 때 원인을 파악하는 표준 도구이다.

> **확인 사항** 편집 대상 파일은 `/etc/default/grub`이고 자동 생성 파일은 `/boot/grub/grub.cfg`이며, 현재 타깃이 `multi-user.target`임을 확인하였다면 성공이다.
{: .prompt-tip }

---

> ### 따라 하기 1-6. 안전한 종료와 재부팅
>
> **목적** 예약 종료를 설정하고 취소하는 절차를 실습한 뒤, 정상적인 방법으로 재부팅한다.
{: .prompt-tip }

**1단계.** 5분 뒤 재부팅을 예약한다.

```bash
sudo shutdown -r +5 "실습용 재부팅 예약"
```

> 접속 중인 사용자 전원에게 메시지가 전달된다.

**2단계.** 예약을 취소한다.

```bash
sudo shutdown -c
```

> **반드시 취소하여야 한다.** 취소하지 않으면 5분 뒤 실제로 재부팅된다.

**3단계.** 현재 가동 시간을 기록한다.

```bash
uptime
```

**4단계.** 정상적으로 재부팅한다.

```bash
sudo reboot
```

**5단계.** 재접속 후 가동 시간이 초기화되었는지 확인한다.

```bash
uptime
```

> **확인 사항** 예약 종료가 정상적으로 취소되고, 재부팅 후 가동 시간이 수 분 이내로 초기화되었다면 성공이다.
{: .prompt-tip }

# 제4절. 저장 장치와 파일 시스템

---

## 4.1 단일 트리 구조

윈도우는 저장 장치마다 `C:`, `D:`와 같은 드라이브 문자를 부여한다. 반면 리눅스에는 드라이브 문자가 존재하지 않으며, 모든 저장 장치가 **`/`(루트)를 정점으로 하는 하나의 트리**에 연결된다.

```
 [윈도우 방식]              [리눅스 방식]

 C:\                        /
 ├─ Windows                 ├─ home     ← 하드디스크 연결
 ├─ Users                   ├─ mnt
 │                          │   └─ usb  ← USB 저장 장치 연결
 D:\  (두 번째 디스크)        └─ media
 E:\  (USB)                     └─ cdrom ← 광학 매체 연결
```

저장 장치를 트리의 특정 디렉터리에 연결하는 행위를 **마운트(mount)** 라 하고, 연결되는 그 디렉터리를 **마운트 지점(mount point)** 이라 한다.

---

## 4.2 파티션과 파일 시스템

저장 장치를 사용하려면 세 단계를 거쳐야 한다.

| 단계 | 행위 | 설명 |
|---|---|---|
| ① 파티션 | 디스크를 구획으로 나눈다 | 하나의 디스크를 논리적으로 분할 |
| ② 파일 시스템 생성 | 각 구획을 포맷한다 | 파일을 저장할 수 있는 형식을 부여 |
| ③ 마운트 | 트리에 연결한다 | 특정 디렉터리에서 접근 가능하게 함 |

리눅스는 저장 장치를 `/dev` 디렉터리 아래의 장치 파일로 표현한다.

| 장치명 | 의미 |
|---|---|
| `/dev/sda`, `/dev/sdb` | 첫 번째, 두 번째 디스크 |
| `/dev/sda1`, `/dev/sda2` | `sda` 디스크의 첫 번째, 두 번째 파티션 |
| `/dev/nvme0n1p1` | NVMe 방식 디스크의 파티션 |
| `/dev/mapper/...` | LVM 논리 볼륨 |

주요 파일 시스템은 다음과 같다.

| 파일 시스템 | 특징 | 주 사용처 |
|---|---|---|
| **ext4** | 저널링 지원, 안정성 검증 충분 | **우분투 기본값** |
| xfs | 대용량에 유리 | 레드햇 계열 기본값 |
| **swap** | 메모리 부족 시 사용하는 보조 공간 | 스왑 영역 |
| vfat / exfat | 윈도우 호환. 권한 정보를 저장하지 못함 | USB 이동 매체 |
| iso9660 | 광학 매체 표준(읽기 전용) | ISO 이미지 |

**저널링(Journaling)** 이란 실제 쓰기 작업을 수행하기 전에 변경 계획을 별도 영역에 먼저 기록하는 기법이다. 정전이나 비정상 종료가 발생하더라도 이 기록을 재생하여 신속하게 일관성을 회복할 수 있다.

---

## 4.3 주요 디렉터리의 용도

리눅스의 디렉터리 구조는 **FHS(Filesystem Hierarchy Standard)** 라는 표준으로 규정되어 있다. 상세한 내용은 2강에서 다루며, 여기서는 개요만 정리한다.

| 디렉터리 | 용도 |
|---|---|
| `/etc` | 시스템 전역 **설정 파일** |
| `/home` | 일반 사용자의 홈 디렉터리 |
| `/root` | **관리자(root)의 홈 디렉터리** |
| `/boot` | 커널 이미지와 부팅 관련 파일 |
| `/dev` | 장치 파일 |
| `/proc` | 커널과 프로세스 정보를 담은 **가상 파일 시스템** |
| `/var` | 로그·스풀 등 크기가 변동하는 데이터 |
| `/tmp` | 임시 파일 |
| `/usr` | 사용자용 프로그램과 라이브러리 |

> **혼동하기 쉬운 개념**
> `/`(루트 디렉터리)와 `/root`(관리자 홈 디렉터리)는 전혀 다른 대상이다. 전자는 파일 트리의 최상위이고, 후자는 관리자 계정의 개인 작업 공간이다.
{: .prompt-warning }

---

> ### 따라 하기 1-7. 디스크 구조와 파일 시스템 확인
>
> **목적** 설치 시 결정된 파티션 구성과 파일 시스템 종류를 명령어로 확인한다.
{: .prompt-tip }

**1단계.** 블록 장치의 계층 구조를 확인한다.

```bash
lsblk
```

> `lsblk`는 **l**i**s**t **bl**oc**k** devices(블록 장치 목록)의 약어이다. 디스크와 그 하위 파티션이 트리 형태로 출력된다.

```bash
lsblk -f
```

> `-f`는 **f**ilesystem의 약어이다. 각 파티션의 파일 시스템 종류, UUID, 마운트 지점까지 함께 출력되므로 설치 결과를 파악하는 데 가장 유용하다.

**2단계.** 파일 시스템별 사용량을 확인한다.

```bash
df -hT
```

> `df`는 **d**isk **f**ree(디스크 여유 공간)의 약어이다. `-h`는 **h**uman-readable(사람이 읽기 쉬운 단위), `-T`는 **T**ype(파일 시스템 종류)을 의미한다.

**3단계.** 특정 디렉터리가 차지하는 용량을 확인한다.

```bash
sudo du -sh /var/log
```

> `du`는 **d**isk **u**sage(디스크 사용량)의 약어이며, `-s`는 **s**um(합계만 출력)을 의미한다.
>
> `sudo` 없이 실행하면 합계 앞에 `du: cannot read directory '/var/log/private': Permission denied`와 같은 행이 함께 출력된다. `/var/log` 아래에 root만 읽을 수 있는 디렉터리가 포함되어 있기 때문이며, **오류가 아니라 권한 체계가 정상 동작하고 있다는 증거**이다. 이 원리는 제3강에서 다룬다.

> **`df`와 `du`의 구분**
> - `df` : **파일 시스템 전체**의 사용량 (건물 전체 주차장 현황)
> - `du` : **특정 디렉터리**의 사용량 (내 차 한 대가 차지하는 면적)
>
> 시험에서 두 명령의 구분을 묻는 문항이 자주 출제된다.
{: .prompt-warning }

**4단계.** 부팅 시 자동 마운트 규칙을 확인한다.

```bash
cat /etc/fstab
```

> `fstab`은 **f**ile **s**ystem **tab**le(파일 시스템 표)의 약어이다. 각 행은 `장치 / 마운트지점 / 파일시스템 / 옵션 / dump / fsck순서`의 6개 필드로 구성된다.
>
> 장치를 `/dev/sda1` 대신 `UUID=...`로 지정하는 이유는, 디스크를 추가하거나 순서가 변경되어도 UUID는 고정되기 때문이다.
>
> **이 파일을 잘못 수정하면 부팅에 실패할 수 있으므로 지금은 읽기만 한다.**

**5단계.** 스왑 영역과 메모리를 확인한다.

```bash
swapon --show
```

```bash
free -h
```

**6단계.** 가상 파일 시스템의 존재를 확인한다.

```bash
cat /proc/cpuinfo | head -12
```

```bash
cat /proc/uptime
```

> `/proc`은 디스크에 실재하지 않는 **가상 파일 시스템**이다. 커널이 메모리상의 정보를 파일 형태로 노출하는 창구이며, "모든 것은 파일이다"라는 유닉스 철학이 구현된 대표적 사례이다.

> **확인 사항** 루트 파일 시스템의 장치명·파일 시스템 종류·사용률을 설명할 수 있고, `df`와 `du`의 차이를 구분할 수 있다면 성공이다.
{: .prompt-tip }

## 단계 1. 작업 공간 준비

```bash
mkdir -p ~/lab01
```

> `mkdir`은 **m**a**k**e **dir**ectory(디렉터리를 생성하라)의 약어이며, `-p`는 **p**arents(상위 디렉터리까지 함께 생성)를 의미한다.

```bash
cd ~/lab01
```

> `cd`는 **c**hange **d**irectory(디렉터리를 변경하라)의 약어이다.

```bash

# 제6절. 자주 발생하는 오류와 대응 방법

---

| 화면에 출력된 메시지 | 원인 | 대응 방법 |
|---|---|---|
| `command not found` | 명령어 오타 또는 미설치 | 철자와 대소문자를 확인한다. `Tab` 자동 완성을 활용한다. |
| `Permission denied` | 권한 부족 | 명령 앞에 `sudo`를 붙인다. 상세한 원리는 3강에서 다룬다. |
| `No such file or directory` | 경로가 존재하지 않음 | `ls`로 대상의 존재 여부를 먼저 확인한다. |
| `Is a directory` | 디렉터리를 파일처럼 다룸 | `cat` 대신 `ls`를 사용한다. |
| 화면이 정지한 것처럼 보임 | 명령이 실행 중 | **`Ctrl + C`** 를 눌러 중단한다. |
| `:` 기호만 표시되고 진행되지 않음 | 페이지 표시 상태(`less`) | **`q`** 를 눌러 종료한다. |
| `sudo` 실행 시 비밀번호가 화면에 보이지 않음 | **정상 동작이다** | 보안을 위해 입력 내용을 표시하지 않는 것이므로 그대로 입력하고 `Enter`를 누른다. |

## 8.1 핵심 개념 정리

| 구분 | 요점 |
|---|---|
| 리눅스의 정의 | 리눅스는 커널의 명칭이며, GNU 유틸리티와 결합하여 완전한 운영체제를 구성한다. |
| 계층 구조 | 하드웨어 → 커널 → 셸 → 응용 프로그램의 4계층으로 이해한다. |
| 라이선스 | GPL의 핵심은 카피레프트이며, 파생물에도 동일한 자유를 강제한다. |
| 배포판 | 패키지 관리 방식으로 계열을 구분한다. Ubuntu는 데비안 계열이며 `apt`를 사용한다. |
| 프롬프트 | 사용자·호스트·현재 위치·권한 구분 기호의 네 정보를 담는다. `$`는 일반 사용자, `#`는 관리자이다. |
| 부팅 과정 | BIOS → MBR → GRUB → 커널 → systemd → 로그인의 5단계로 진행된다. |
| GRUB 설정 | `/etc/default/grub`을 수정하고 `update-grub`으로 반영한다. |
| 파일 시스템 | 모든 저장 장치는 `/`를 정점으로 하는 단일 트리에 마운트된다. |
