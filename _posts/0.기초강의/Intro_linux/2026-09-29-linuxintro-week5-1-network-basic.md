컴퓨터는 홀로 작동할 때보다 다른 컴퓨터와 연결되어 정보를 주고받을 때 그 가치가 커진다. 본 강의에서는 리눅스가 네트워크에 어떻게 연결되어 있는지를 **개념부터 확인 명령까지** 순서대로 학습한다.

# 제1절. 네트워크 기본 개념

---

## 1.1 주소와 이름

네트워크에서 데이터를 주고받으려면 보내는 곳과 받는 곳을 정확히 식별할 수 있어야 한다. 이 식별을 담당하는 개념들을 우편 배달에 비유하면 이해하기 쉽다.

| 개념 | 정의 | 비유 | 예시 |
|---|---|---|---|
| **IP 주소** | 네트워크에 연결된 컴퓨터를 식별하는 번호 (IP = internet protocol) | 건물의 주소 | `192.168.0.30` |
| **서브넷 마스크** | IP 주소에서 네트워크 부분과 컴퓨터 부분의 경계 | 같은 동네의 범위 | `255.255.255.0`(=`/24`) |
| **게이트웨이** | 바깥 네트워크로 나가는 출구 (공유기 주소) | 동네의 정문 | `192.168.0.1` |
| **DNS 서버** | 도메인 이름을 IP 주소로 바꾸어 주는 서버 (DNS = domain name system) | 전화번호부 | `8.8.8.8` |
| **포트 번호** | 한 컴퓨터 안에서 서비스를 구분하는 번호 | 건물 안의 호실 번호 | `80`, `443` |
| **MAC 주소** | 네트워크 장치에 새겨진 고유한 물리 주소 (MAC = media access control) | 장비의 제조 번호 | 48비트 |
| **루프백** | 컴퓨터가 자기 자신을 가리키는 주소 | — | `127.0.0.1` |

사람이 도메인 이름(`www.example.com`)을 입력하면, 컴퓨터는 먼저 DNS 서버에 물어 그에 해당하는 IP 주소를 알아낸 뒤, 그 주소를 향해 데이터를 보낸다. 즉 **이름을 주소로 바꾸는 과정**이 통신에 앞서 항상 일어난다.

> **[그림 5-1] 필요**
> 사용자가 도메인 이름을 입력하면 DNS 서버에 질의하여 IP 주소를 얻고, 게이트웨이를 거쳐 목적지에 도달하는 과정을 IP 주소·게이트웨이·DNS 서버의 위치와 함께 표현한 개념도.
{: .prompt-tip }

---

## 1.2 사설 IP 주소

가정이나 학교의 내부 네트워크에서는 인터넷 전체에 공개되지 않는 **사설 IP 주소**를 사용한다. 실습 환경에서 자주 보게 되는 대역은 다음과 같다.

| 클래스 | 대역 | CIDR 표기 |
|---|---|---|
| A | 10.0.0.0 ~ 10.255.255.255 | `10.0.0.0/8` |
| B | 172.16.0.0 ~ 172.31.255.255 | `172.16.0.0/12` |
| **C** | **192.168.0.0 ~ 192.168.255.255** | **`192.168.0.0/16`** |

가정용 공유기가 컴퓨터에 나누어 주는 주소는 대부분 `192.168.x.x` 형태의 C 클래스 사설 대역이다.

## 1.3 포트 번호와 주요 서비스

하나의 컴퓨터(IP 주소 하나)가 웹 서비스와 원격 접속 서비스를 동시에 제공할 수 있는 까닭이 바로 **포트**이다. 같은 건물이라도 호실 번호로 방문 대상을 구분하는 것과 같다. 포트 번호는 0부터 65535까지의 값을 가지며, 주요 서비스의 번호는 익혀 둘 필요가 있다.

| 포트 | 서비스 |
|---|---|
| **22** | SSH(원격 접속, SSH = secure shell) |
| **53** | DNS(이름 해석) |
| 67 / 68 | DHCP(주소 자동 할당) |
| **80** | HTTP(웹) |
| **443** | HTTPS(암호화된 웹) |
| 3306 | MySQL·MariaDB(데이터베이스) |

이 대응 관계는 `/etc/services` 파일에 정의되어 있다.

{: .prompt-tip }

# 제2절. 네트워크 상태 확인

---

## 2.1 신형 명령 iproute2

Ubuntu 24.04에는 과거에 쓰이던 `ifconfig`·`netstat` 같은 구형 명령이 기본으로 설치되어 있지 않다. 현재의 표준은 `iproute2` 계열의 `ip`·`ss` 명령이다.

| 구형 명령 | **신형 명령** | 용도 |
|---|---|---|
| `ifconfig` | **`ip addr`** | 인터페이스와 IP 주소 조회 |
| `route -n` | **`ip route`** | 라우팅 테이블과 게이트웨이 |
| `netstat -tulnp` | **`ss -tulnp`** | 개방된 포트 조회 |

---

## 2.2 주요 확인 명령

| 명령 | 기능 |
|---|---|
| `ip addr` (또는 `ip a`) | 인터페이스별 IP 주소 조회 |
| `ip -br addr` | 간략 형식(**br**ief)으로 조회 |
| `ip route` | 라우팅 테이블과 기본 게이트웨이 |
| `ping -c 4 대상` | 대상까지의 도달 가능성 확인 |
| **`ss -tuln`** | **개방된 포트 조회** |
| `hostname` | 컴퓨터의 이름 조회 |

`ss` 옵션의 의미는 다음과 같다.

```
 ss -tuln
     ││││
     │││└─ n : numeric   이름 대신 번호로 표시
     ││└── l : listen    대기 중인 소켓만
     │└─── u : UDP
     └──── t : TCP
```

> **[그림 5-2] 필요**
> `ip addr` 출력 화면에서 IP 주소(inet)·인터페이스 이름·MAC 주소(link/ether)의 위치를 각각 표시하여 설명한 이미지.
{: .prompt-tip }

---

## 2.3 단계적 진단 절차

네트워크가 잘 되지 않을 때 원인이 어디에 있는지를 좁혀 나가는 표준 절차가 있다. **이 순서를 익히면 어떠한 장애도 원인 구간을 단계적으로 찾아낼 수 있다.**

```
 ① ping 127.0.0.1        실패 → 네트워크 소프트웨어 자체의 문제
          ↓ 성공
 ② ip addr               IP 없음 → 주소를 받지 못한 문제
          ↓ 주소 존재
 ③ ping 게이트웨이         실패 → 공유기·케이블·내부망 문제
          ↓ 성공
 ④ ping 8.8.8.8          실패 → 외부 회선 문제
          ↓ 성공
 ⑤ ping example.com      실패 → DNS 문제
```

> **가장 흔한 증상의 해석**
> "IP 주소로는 통신이 되는데 도메인 이름으로만 실패한다"는 증상은 대부분 **DNS 문제**이다. 이름을 IP로 바꾸는 단계에서만 실패하고 있기 때문이다.
{: .prompt-tip }

---

> ### 따라 하기 2-1. 내 컴퓨터의 네트워크 상태 확인
>
> **목적** 자신의 IP 주소·게이트웨이·개방 포트를 확인하고, 5단계 진단 절차를 수행한다.
{: .prompt-tip }

**1단계.** 인터페이스와 IP 주소를 간략 형식으로 확인한다.

```bash
ip -br addr
```

> `lo`는 루프백(자기 자신)이고, `enp0s3`·`ens33` 등이 실제 네트워크 인터페이스이다. 인터페이스 이름이 `eth0`이 아닌 이유는 systemd의 **예측 가능한 인터페이스 이름** 규칙 때문이다.

**2단계.** 상세 정보를 확인한다.

```bash
ip addr show
```

> `inet` 다음에 표시되는 값이 IP 주소이며, `link/ether` 다음의 값이 MAC 주소이다.

**3단계.** 라우팅 테이블과 기본 게이트웨이를 확인한다.

```bash
ip route
```

> `default via 192.168.0.1 dev enp0s3` 형태의 줄이 기본 게이트웨이이다. 바깥으로 나가는 모든 통신이 이 주소를 거친다.

**4단계.** 5단계 진단 절차를 순서대로 수행한다.

```bash
ping -c 3 127.0.0.1
```

> ① 루프백. 실패하면 네트워크 소프트웨어 자체의 문제이다.

```bash
ping -c 3 $(ip route | awk '/default/ {print $3}')
```

> ② 게이트웨이. 실패하면 내부망 문제이다. `$( )` 안의 명령이 게이트웨이 주소를 자동으로 뽑아낸다.

```bash
ping -c 3 8.8.8.8
```

> ③ 외부 IP. 실패하면 외부 회선 문제이다.

```bash
ping -c 3 www.example.com
```

> ④ 도메인. 여기서만 실패하면 DNS 문제이다.

**5단계.** 개방된 포트를 확인한다.

```bash
ss -tuln
```

> 현재 이 컴퓨터에서 외부 연결을 기다리고 있는 포트 목록이 표시된다.

> **확인 사항** 자신의 IP 주소와 게이트웨이를 확인하였고, 5단계 진단이 모두 성공하였다면 정상적으로 인터넷에 연결되어 있는 것이다.
{: .prompt-tip }

# 제3절. 호스트 이름과 DNS 조회

---

## 3.1 호스트 이름

**호스트 이름(hostname)** 은 네트워크에서 컴퓨터를 사람이 알아보기 쉽도록 붙인 이름이다. 본 실습 환경의 호스트 이름은 `ubuntu-y1`이며, 프롬프트의 `@` 뒤에 그대로 표시된다.

| 명령 | 기능 |
|---|---|
| `hostname` | 현재 호스트 이름 조회 |
| `hostnamectl` | 호스트 이름과 시스템 정보 조회 |
| `sudo hostnamectl set-hostname 이름` | 호스트 이름 변경 |

---

## 3.2 이름 해석의 순서

컴퓨터가 도메인 이름을 IP 주소로 바꿀 때는 **DNS 서버에 묻기 전에 먼저 로컬 파일 `/etc/hosts`를 참조**한다. 이 순서는 `/etc/nsswitch.conf` 파일의 `hosts: files dns` 설정으로 정해진다. `files`(즉 `/etc/hosts`)가 `dns`보다 앞에 있으므로 파일이 먼저 참조된다.

| 파일 | 역할 |
|---|---|
| **`/etc/hosts`** | 로컬 이름 해석 표. **DNS보다 먼저 참조된다** |
| `/etc/resolv.conf` | DNS 서버 목록(자동으로 관리됨) |
| `/etc/nsswitch.conf` | 이름 해석 순서를 정의 |

---

## 3.3 DNS 조회 명령

| 명령 | 기능 | 비고 |
|---|---|---|
| `nslookup 도메인` | DNS 조회(간략) | `bind9-dnsutils` 설치 필요 |
| `dig 도메인` | DNS 조회(상세) | `bind9-dnsutils` 설치 필요 |
| `resolvectl query 도메인` | DNS 조회 | 기본 설치되어 있음 |
| `getent hosts 도메인` | 이름 해석 결과 조회 | 기본 설치되어 있음 |

> **`dig`·`nslookup`은 기본 설치되어 있지 않을 수 있다**
> Ubuntu 24.04에서 이 명령이 `command not found`로 나오면, 다음 명령으로 설치한다. `bind9-dnsutils` 패키지가 `dig`·`host`·`nslookup` 세 명령을 함께 제공한다.
>
> ```bash
> sudo apt install -y bind9-dnsutils
> ```
>
> 설치가 곤란하면 기본 포함된 `resolvectl query 도메인` 또는 `getent hosts 도메인`으로 대체할 수 있다.
{: .prompt-warning }

---

> ### 따라 하기 3-1. 호스트 이름과 DNS 조회
>
> **목적** 호스트 이름을 확인하고, 도메인 이름이 IP 주소로 변환되는 과정을 확인한다.
{: .prompt-tip }

**1단계.** 호스트 이름을 확인한다.

```bash
hostname
```

> `ubuntu-y1`이 출력된다. 프롬프트의 `@` 뒤 이름과 일치함을 확인한다.

**2단계.** DNS 조회 도구를 설치한다.

```bash
sudo apt install -y bind9-dnsutils
```

> 이미 설치되어 있으면 그대로 진행된다.

**3단계.** 도메인 이름을 IP 주소로 조회한다.

```bash
nslookup www.example.com
```

```bash
dig www.example.com +short
```

> `dig`에 `+short`를 붙이면 결과 IP 주소만 간략히 표시된다.

**4단계.** 기본 설치 명령으로도 조회한다.

```bash
resolvectl query www.example.com
```

> 어떤 DNS 서버가 응답하였는지까지 함께 표시한다. 별도 설치가 필요 없는 대체 수단이다.

**5단계.** `/etc/hosts`가 DNS보다 먼저 참조됨을 확인한다.

```bash
cat /etc/hosts
```

```bash
echo "127.0.0.1 mytest.local" | sudo tee -a /etc/hosts
```

```bash
getent hosts mytest.local
```

> DNS에 존재하지 않는 이름임에도 `127.0.0.1`로 해석된다. `/etc/hosts`가 DNS보다 먼저 참조되었기 때문이다.

**6단계.** 실습으로 추가한 줄을 제거한다.

```bash
sudo sed -i '/mytest.local/d' /etc/hosts
```

> **확인 사항** 도메인 이름이 IP 주소로 조회되고, `/etc/hosts`에 등록한 이름이 DNS보다 먼저 해석되는 것을 확인하였다면 성공이다.
{: .prompt-tip }

# 제4절. Desktop의 GUI 설정과 명령행 확인

---

## 4.1 NetworkManager

Ubuntu Server 판은 `netplan`이라는 설정 파일로 네트워크를 관리하지만, **Ubuntu Desktop 판은 NetworkManager라는 도구가 네트워크를 자동으로 관리**한다. 화면 오른쪽 위의 네트워크 아이콘을 눌러 나타나는 **설정(Settings) → 네트워크(Network)** 화면이 바로 NetworkManager의 그래픽 조작 창이다.

초보자는 IP 주소를 직접 편집하기보다, 대부분의 경우 **자동(DHCP) 설정을 그대로 두고** 그래픽 화면에서 연결 상태만 확인하면 충분하다. 명령행에서는 앞 절에서 익힌 `ip addr`·`ip route`로 그 결과를 확인한다.

---

## 4.2 그래픽 설정과 명령행의 관계

그래픽 화면에서 무엇을 바꾸든, 그 결과는 결국 `ip addr`·`ip route`가 보여 주는 값으로 나타난다. 즉 **그래픽 설정 창과 명령행 확인 명령은 같은 대상을 서로 다른 방식으로 다루는 것**이다.

| 목적 | 그래픽(NetworkManager) | 명령행 |
|---|---|---|
| IP 주소 확인 | 설정 → 네트워크 → 톱니바퀴 → 세부 정보 | `ip addr` |
| 게이트웨이 확인 | 세부 정보의 "기본 라우트" | `ip route` |
| 연결 목록 확인 | 네트워크 화면의 연결 목록 | `nmcli connection show` |
| 연결 상태 확인 | 네트워크 화면의 켜짐/꺼짐 | `nmcli device status` |

명령행에서 NetworkManager를 직접 다루는 도구는 `nmcli`(NetworkManager command line interface)이다. 초보 단계에서는 상태 조회 용도로만 사용하고, 설정 변경은 그래픽 화면으로 수행하는 것을 권장한다.

> **[그림 5-3] 필요**
> Ubuntu Desktop의 설정 → 네트워크 세부 정보 창과, 같은 정보를 보여 주는 `ip addr` 터미널 출력을 나란히 배치하여 대응 관계를 표시한 이미지.
{: .prompt-tip }

---

> ### 따라 하기 4-1. GUI 정보와 명령행 결과 대조
>
> **목적** 그래픽 설정 화면의 정보와 명령행 결과가 서로 일치함을 확인한다.
{: .prompt-tip }

**1단계.** 명령행에서 연결 상태를 확인한다.

```bash
nmcli device status
```

> 각 인터페이스가 `connected` 상태인지 표시된다.

**2단계.** 연결 목록을 확인한다.

```bash
nmcli connection show
```

**3단계.** 명령행으로 확인한 IP 주소를 기록한다.

```bash
ip -br addr
```

> **확인 사항** 화면 오른쪽 위 네트워크 아이콘에서 설정 → 네트워크 세부 정보를 열어, 그 IP 주소가 위 `ip -br addr` 결과와 일치함을 확인하였다면 성공이다.
{: .prompt-tip }

# 제5절. 종합 실습 — 나의 네트워크 상태 보고서

---

> **실습 시나리오**
>
> 학습자는 자신의 컴퓨터가 인터넷에 어떻게 연결되어 있는지를 한눈에 보여 주는 **간단한 상태 보고서**를 작성한다. 본 절에서 학습한 확인 명령을 하나의 스크립트로 묶는다.
{: .prompt-info }

**1단계.** 실습 디렉터리로 이동한다.

```bash
cd ~/lab05
```

**2단계.** 상태 보고 스크립트를 작성한다.

```bash
cat > ~/lab05/netreport.sh << 'EOF'
#!/bin/bash
# 네트워크 상태 보고서
# 리눅스 기초 5주차-1 종합 실습

echo "=================================="
echo "  네트워크 상태 보고"
echo "  호스트 이름: $(hostname)"
echo "  점검 일시  : $(date '+%Y-%m-%d %H:%M:%S')"
echo "=================================="
echo

echo "[1] IP 주소"
ip -br addr | grep -v "^lo" | awk '{print "  인터페이스: " $1 "  주소: " $3}'
echo

echo "[2] 기본 게이트웨이"
echo "  $(ip route | awk '/default/ {print $3}')"
echo

echo "[3] 외부 통신 상태"
ping -c 1 -W 2 8.8.8.8 > /dev/null 2>&1 \
  && echo "  인터넷 연결: 정상" || echo "  인터넷 연결: 실패"
getent hosts www.example.com > /dev/null 2>&1 \
  && echo "  DNS 조회   : 정상" || echo "  DNS 조회   : 실패"
echo

echo "[4] 개방된 포트"
ss -tlnH | awk '{print "  " $4}' | sort -u
EOF
```

**3단계.** 실행 권한을 부여한다.

```bash
chmod 750 ~/lab05/netreport.sh
```

**4단계.** 스크립트를 실행한다.

```bash
~/lab05/netreport.sh
```

> IP 주소·게이트웨이·인터넷 연결·DNS 조회·개방 포트가 하나의 보고서로 출력된다.

> **종합 실습 완료 기준**
> 1. IP 주소와 게이트웨이가 출력되었다.
> 2. 인터넷 연결과 DNS 조회가 모두 "정상"으로 표시되었다.
> 3. 개방된 포트 목록이 출력되었다.
{: .prompt-tip }

# 제6절. 자주 발생하는 오류와 대응 방법

---

| 화면에 출력된 메시지 / 증상 | 원인 | 대응 방법 |
|---|---|---|
| `ip: command not found` | 드물게 `iproute2` 미설치 | `sudo apt install -y iproute2` |
| `nslookup: command not found` | `bind9-dnsutils` 미설치 | `sudo apt install -y bind9-dnsutils` 또는 `resolvectl query`로 대체한다. |
| `dig: command not found` | `bind9-dnsutils` 미설치 | 위와 동일하게 설치한다. |
| `Network is unreachable` | IP 주소를 받지 못함 | `ip addr`로 주소 할당 여부를 확인한다. |
| `Name or service not known` | **DNS 문제** | `resolvectl status`로 DNS 서버를 확인한다. |
| IP로는 되나 도메인만 실패 | **DNS 문제** | DNS 서버 설정을 확인한다. |
| `ping` 게이트웨이 실패 | 케이블·공유기·내부망 문제 | 물리적 연결과 공유기 상태를 확인한다. |
| GUI에서 켰는데 연결 안 됨 | 자동 주소 할당 지연 | 잠시 기다린 뒤 `nmcli device status`로 확인한다. |

# 제7절. 요약

---

## 7.1 핵심 개념 정리

| 구분 | 요점 |
|---|---|
| 주소 체계 | IP는 컴퓨터를, 포트는 서비스를 식별한다. 게이트웨이는 바깥으로 나가는 출구이다. |
| 이름 해석 | 도메인 이름은 DNS 서버가 IP 주소로 바꾸며, 그전에 `/etc/hosts`가 먼저 참조된다. |
| 상태 확인 | `ip addr`로 주소를, `ip route`로 게이트웨이를, `ss -tuln`으로 포트를 확인한다. |
| 진단 절차 | 루프백 → IP 주소 → 게이트웨이 → 외부 IP → 도메인 순으로 원인 구간을 좁힌다. |
| Desktop 설정 | Ubuntu Desktop은 NetworkManager가 관리하며, 그래픽 설정 결과를 명령행으로 확인한다. |

---

## 7.2 본 강의에서 학습한 명령어

| 명령어 | 기능 |
|---|---|
| `ip -br addr` / `ip addr` | IP 주소 조회 |
| `ip route` | 라우팅 테이블·게이트웨이 조회 |
| `ping` | 도달 가능성 확인 |
| `ss -tuln` | 개방된 포트 조회 |
| `hostname` | 호스트 이름 조회 |
| `nslookup` / `dig` | DNS 조회(`bind9-dnsutils` 설치 필요) |
| `resolvectl query` / `getent hosts` | DNS 조회(기본 설치) |
| `nmcli device status` | NetworkManager 연결 상태 조회 |
