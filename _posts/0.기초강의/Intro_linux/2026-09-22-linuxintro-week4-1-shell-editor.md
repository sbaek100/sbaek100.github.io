> 1. 셸(shell)의 역할을 설명하고, 현재 사용 중인 셸이 bash임을 확인할 수 있다.

{: .prompt-info }

지금까지 입력한 명령어들은 모두 **셸(shell)** 이 해석하여 실행한 것이다. 셸의 동작 원리를 이해하면, 명령어를 하나씩 암기하여 사용하는 단계에서 벗어나 **여러 명령어를 조합하여 새로운 작업을 구성하는** 단계로 나아갈 수 있다.

또한 리눅스의 설정은 대부분 텍스트 파일에 저장되므로, 편집기를 다룰 수 없으면 어떤 설정도 변경할 수 없다. 본 강의는 Ubuntu Desktop 24.04 LTS 환경을 전제로 하며, 초보자에게 적합한 `nano`를 중심으로 다루고, 모든 리눅스 환경에 기본 탑재된 `vi`는 최소한의 조작만 익힌다.

Ubuntu Desktop에서는 화면 왼쪽의 프로그램 목록 또는 "프로그램 표시"에서 **터미널(Terminal)** 을 실행하면 셸을 사용할 수 있다. 본 강의의 모든 실습은 이 터미널에서 진행한다. 실습 계정은 `student`, 호스트명은 `ubuntu-y1`이며, 프롬프트는 다음과 같은 형태로 표시된다.

```
student@ubuntu-y1:~$
```

# 제1절. 셸의 이해

---

## 1.1 셸의 역할

**셸(shell)** 은 사용자가 입력한 문자열을 해석하여 커널(kernel)에 전달하는 **명령 해석기(command interpreter)** 이다. 명칭은 '껍데기'를 뜻하며, 알맹이에 해당하는 커널을 감싸고 있다는 점에서 유래하였다.

```
 사용자 입력  →  [ 셸 ]  →  커널  →  하드웨어
                   │
                   ├─ ① 명령·옵션·인자 분리
                   ├─ ② 확장 처리(와일드카드, 변수, 명령 치환)
                   ├─ ③ 입출력 방향 설정(리다이렉션·파이프)
                   ├─ ④ 프로그램 실행
                   └─ ⑤ 결과를 화면에 전달
```

셸의 역할은 단순한 전달에 그치지 않는다. 명령을 실행하기 **전에** 여러 가지 변환 작업을 수행한다.

| 셸이 수행하는 확장 | 예시 | 결과 |
|---|---|---|
| 와일드카드 확장 | `rm *.txt` | 실제 파일 목록으로 치환하여 `rm`에 전달 |
| 변수 치환 | `echo $HOME` | `echo /home/student` |
| 명령 치환 | `echo $(date)` | `date`를 실행하여 그 출력으로 치환 |
| 리다이렉션 설정 | `ls > list.txt` | 출력 방향을 파일로 변경 |
| 파이프 연결 | `ls \| grep txt` | 앞 명령의 출력을 뒤 명령의 입력으로 연결 |

> **셸의 확장 처리를 이해하면 설명되는 현상**
> `rm *.txt`에서 `*.txt`를 해석하는 주체는 `rm`이 아니라 **셸**이다. `rm`은 이미 확장이 완료된 파일명 목록만 전달받는다.
>
> 그러므로 조건에 맞는 파일이 하나도 없으면 셸이 확장하지 못하고 `*.txt`를 문자 그대로 전달하며, 그 결과 `rm: cannot remove '*.txt'`라는 오류가 발생한다.
{: .prompt-tip }

---

## 1.2 셸의 종류와 bash

리눅스에는 여러 종류의 셸이 존재하나, 오늘날 대부분의 배포판이 기본으로 사용하는 대화형 셸은 **bash**이다. bash는 **B**ourne **A**gain **SH**ell의 약어로, 최초의 표준 셸인 sh(Bourne Shell)를 개선하여 다시 만들었다는 의미이다.

| 셸 | 경로 | 특징 |
|---|---|---|
| sh (Bourne Shell) | `/bin/sh` | 최초의 표준 셸 |
| **bash** (Bourne Again Shell) | `/bin/bash` | **대부분의 배포판 기본 대화형 셸** |
| dash | `/bin/dash` | 경량·고속. 우분투의 시스템 스크립트 실행용 |
| zsh (Z Shell) | `/bin/zsh` | 강력한 자동 완성. macOS 기본 셸 |

Ubuntu에서 사용자가 터미널을 열면 bash가 실행된다. 다만 시스템 내부의 부팅 스크립트는 속도가 빠른 dash로 실행되며, 이 때문에 `/bin/sh`는 bash가 아니라 dash에 연결되어 있다.

> **자주 출제되는 개념**
> Ubuntu에서 `/bin/sh`는 bash가 아니라 **dash**로 연결되어 있다. 부팅 스크립트를 신속하게 실행하기 위한 선택이다. bash 전용 문법이 필요한 스크립트라면 첫 행에 반드시 `#!/bin/bash`를 명시하여야 한다.
{: .prompt-warning }

## 1.3 현재 셸의 확인

| 명령 | 조회 대상 |
|---|---|
| `echo $SHELL` | **로그인 셸**(`/etc/passwd`에 기록된 값) |
| `ps -p $$` | **현재 실행 중인** 셸(`$$`는 현재 셸의 프로세스 번호) |
| `cat /etc/shells` | 로그인 셸로 허용된 경로 목록 |
| `echo $BASH_VERSION` | bash의 버전(bash가 아니면 빈 값) |

- `echo`는 뒤따르는 문자열을 화면에 출력하는 명령이다(영어 echo = 메아리).
- `ps`는 **p**rocess **s**tatus의 약어로, 실행 중인 프로세스를 조회한다.

---

> ### 따라 하기 4-1. 현재 셸 확인
>
> **목적** 현재 사용 중인 셸이 bash임을 여러 방법으로 확인한다.
{: .prompt-tip }

**1단계.** 실습 디렉터리를 생성하고 이동한다.

```bash
mkdir -p ~/lab04 && cd ~/lab04
```

> `mkdir`(**m**a**k**e **dir**ectory)로 디렉터리를 만들고, `-p` 옵션은 상위 경로가 없어도 함께 생성한다. `&&`는 앞 명령이 성공했을 때만 뒤 명령을 실행한다.

**2단계.** 로그인 셸과 현재 셸을 조회한다.

```bash
echo $SHELL
```

```bash
ps -p $$
```

> `$SHELL`은 로그인 시 지정된 셸의 경로를, `ps -p $$`는 지금 이 순간 실제로 실행 중인 셸을 보여 준다.

**3단계.** bash 버전을 확인한다.

```bash
echo $BASH_VERSION
```

> `5.2.x` 형태의 버전이 출력되면 현재 셸이 bash라는 뜻이다.

**4단계.** 허용된 로그인 셸 목록과 `/bin/sh`의 실체를 확인한다.

```bash
cat /etc/shells
```

```bash
ls -l /bin/sh
```

> `/bin/sh -> dash`로 출력된다. Ubuntu가 부팅 성능을 위해 채택한 구성이다.

> **확인 사항** `$SHELL`과 `ps -p $$`의 차이를 설명할 수 있고, 현재 셸이 bash임을 확인하였다면 성공이다.
{: .prompt-tip }

# 제2절. 환경 변수와 별칭

---

## 2.1 변수의 정의와 사용

변수는 값을 담아 두는 저장 공간이다. 값을 저장할 때는 이름만 사용하고, 값을 꺼낼 때는 이름 앞에 `$`를 붙인다.

```bash
MYNAME="홍길동"        # 값을 저장할 때는 이름만 사용
echo $MYNAME           # 값을 꺼낼 때는 $ 를 붙임
```

> **초보자가 가장 빈번하게 범하는 오류**
> ```
> MYNAME = "홍길동"       ← 등호 앞뒤에 공백이 있음. 오류 발생
> MYNAME="홍길동"         ← 올바른 표기
> ```
> 공백을 넣으면 셸이 `MYNAME`을 **명령어**로 해석하여 `command not found` 오류를 출력한다.
{: .prompt-danger }

---

## 2.2 환경 변수의 개념

변수에는 두 종류가 있다. **사용자 변수**는 현재 셸에서만 유효하며, 새로 실행한 프로그램(자식 프로세스)에는 전달되지 않는다. 이에 비해 **환경 변수**는 `export` 명령으로 내보낸 변수로, 자식 프로세스까지 값이 상속된다.

| 구분 | 정의 | 자식 프로세스 상속 | 조회 명령 |
|---|---|---|---|
| **사용자 변수** | 현재 셸에서만 유효 | **되지 않음** | `set` |
| **환경 변수** | `export`로 내보낸 변수 | **됨** | `env`, `printenv` |

- `export`는 사용자 변수를 환경 변수로 '내보낸다'는 의미이다.
- `env`(**env**ironment)는 현재 환경 변수 전체를 출력한다.

```bash
MYVAR="hello"          # 사용자 변수 정의
export MYVAR           # 환경 변수로 승격
unset MYVAR            # 변수 해제
```

---

## 2.3 주요 환경 변수

| 변수 | 의미 |
|---|---|
| **`PATH`** | **명령어를 탐색할 디렉터리 목록**(콜론으로 구분) |
| `HOME` | 홈 디렉터리 경로(예: `/home/student`) |
| `USER` | 로그인 사용자명 |
| `SHELL` | 로그인 셸 |
| `PWD` | 현재 작업 디렉터리(**p**resent **w**orking **d**irectory) |
| `LANG` | 언어·지역 설정 |

`echo` 명령으로 각 변수의 값을 즉시 확인할 수 있다.

```bash
echo $HOME
echo $USER
echo $PATH
```

---

## 2.4 `PATH`의 동작 원리

사용자가 `ls`를 입력하면 셸은 `PATH`에 나열된 디렉터리를 **앞에서부터 순서대로** 탐색하여 해당 이름의 실행 파일을 찾는다.

```
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/snap/bin
```

`PATH`에 포함되지 않은 디렉터리의 프로그램은 경로를 직접 지정해야 실행된다. 스크립트를 실행할 때 `./script.sh`와 같이 `./`(현재 디렉터리)를 붙이는 이유가 여기에 있다.

> **`PATH`에 `.`을 포함해서는 안 되는 이유**
> `.`은 현재 디렉터리를 의미한다. 만약 `PATH`의 앞부분에 `.`이 포함되어 있으면, 임의의 디렉터리에서 `ls`를 입력했을 때 그 디렉터리에 있는 동명의 파일이 먼저 실행된다.
>
> 공격자가 `/tmp` 등에 `ls`라는 이름의 악성 프로그램을 배치해 두고 사용자가 그 디렉터리에서 `ls`를 입력하기를 기다리는 공격이 실제로 존재한다. 따라서 `PATH`에 `.`을 포함하는 설정은 금지된다.
{: .prompt-danger }

---

## 2.5 별칭 — `alias`

**별칭(alias)** 은 긴 명령을 짧은 이름으로 대신 부를 수 있게 하는 기능이다. 자주 사용하는 명령에 옵션을 붙여 두면 입력을 크게 줄일 수 있다.

```bash
alias                     # 정의된 별칭 목록 조회
alias ll='ls -alF'        # 별칭 정의
unalias ll                # 별칭 해제(un + alias)
```

> **별칭의 적용 범위**
> 별칭은 정의한 셸에서만 유효하며, 터미널을 종료하면 소멸한다. 영구히 사용하려면 개인 설정 파일인 **`~/.bashrc`** 에 기재하여야 한다.
{: .prompt-warning }

---

## 2.6 설정을 영구 적용하는 방법

터미널을 종료하면 그 세션에서 정의한 변수와 별칭은 모두 사라진다. 이를 영구히 유지하려면 셸이 시작될 때마다 자동으로 읽는 **개인 설정 파일 `~/.bashrc`** 에 기록하여야 한다.

| 파일 | 성격 | 주 용도 |
|---|---|---|
| **`~/.bashrc`** | **개인·대화형** | **별칭, 프롬프트, 셸 옵션** |
| `~/.profile` | 개인·로그인 | 개인 환경 변수 |
| `/etc/bash.bashrc` | 전역·대화형 | 시스템 공통 설정 |

파일을 수정한 뒤 즉시 반영하려면 `source ~/.bashrc`(또는 `. ~/.bashrc`)를 실행한다. `source`는 파일에 적힌 내용을 현재 셸에서 그대로 다시 실행한다는 의미이다.

---

> ### 따라 하기 4-2. 환경 변수와 별칭
>
> **목적** 사용자 변수와 환경 변수의 상속 차이를 실험으로 확인하고, 별칭을 영구 적용한다.
{: .prompt-tip }

**1단계.** 사용자 변수를 정의하고 조회한다.

```bash
cd ~/lab04
```

```bash
MYVAR="사용자변수"
```

```bash
echo $MYVAR
```

**2단계.** 잘못된 정의 방식을 확인한다.

```bash
BADVAR = "공백있음"
```

> `command not found` 오류가 발생한다. 셸이 `BADVAR`를 명령어로 해석한 것이다.

**3단계.** 자식 셸로 상속되는지 확인한다.

```bash
bash -c 'echo "자식 셸에서 본 MYVAR = [$MYVAR]"'
```

> 값이 비어 있다. 사용자 변수는 자식 프로세스로 상속되지 않는다.

**4단계.** 환경 변수로 승격한 뒤 다시 확인한다.

```bash
export MYVAR
```

```bash
bash -c 'echo "자식 셸에서 본 MYVAR = [$MYVAR]"'
```

> 값이 전달된다. `export`가 그 경계를 결정한다.

**5단계.** 주요 환경 변수를 조회한다.

```bash
echo $HOME
```

```bash
echo $PATH | tr ':' '\n'
```

> `tr ':' '\n'`은 콜론을 줄바꿈으로 치환하여 `PATH`의 각 항목을 한 줄씩 출력한다. 목록에 `.`이 포함되어 있지 않은지 확인한다.

**6단계.** 별칭을 정의하고 사용한다.

```bash
alias ll='ls -alF'
```

```bash
ll ~/lab04
```

**7단계.** 별칭을 `~/.bashrc`에 등록하여 영구 적용한다.

```bash
cp ~/.bashrc ~/.bashrc.bak
```

> **설정 파일을 수정하기 전에 백업본을 만드는 것은 시스템 관리의 기본 수칙이다.** `cp`는 **c**o**p**y의 약어이다.

```bash
cat >> ~/.bashrc << 'EOF'

# ===== 리눅스 기초 4주차 실습 설정 =====
alias ll='ls -alF'
alias lt='ls -lhtr'
alias ..='cd ..'
EOF
```

> `>>`는 파일 끝에 이어 붙이는 리다이렉션이며(제3절에서 상세히 다룬다), 종료 표시를 `'EOF'`처럼 작은따옴표로 감싸면 내부의 `$` 등이 확장되지 않고 그대로 기록된다.

```bash
source ~/.bashrc
```

```bash
alias | tail -3
```

> **확인 사항** `export` 전후로 자식 셸에서의 값이 달라지는 것을 확인하였고, 별칭을 `~/.bashrc`에 등록하여 새 터미널에서도 사용할 수 있게 되었다면 성공이다.
{: .prompt-tip }

# 제3절. 입출력 리다이렉션과 파이프

---

## 3.1 표준 입출력의 개념

리눅스의 모든 프로세스는 세 개의 기본 통로를 갖는다.

| 명칭 | 파일 디스크립터 | 기본 연결 대상 |
|---|---|---|
| 표준 입력(stdin) | **0** | 키보드 |
| 표준 출력(stdout) | **1** | 화면 |
| 표준 오류(stderr) | **2** | 화면 |

프로그램은 정상적인 결과를 표준 출력으로, 오류 메시지를 표준 오류로 내보낸다. 두 경로가 분리되어 있기 때문에 **정상 결과만 저장하고 오류는 별도로 처리하는 것이 가능하다.**

---

## 3.2 리다이렉션

**리다이렉션(redirection)** 은 입출력의 방향을 바꾸는 기능이다. 명령의 출력을 화면 대신 파일로 보내거나, 파일을 명령의 입력으로 사용할 수 있다.

| 표기 | 동작 |
|---|---|
| `명령 > 파일` | 표준 출력을 파일로 **덮어쓰기** |
| `명령 >> 파일` | 표준 출력을 파일에 **이어 붙이기** |
| `명령 < 파일` | 파일을 표준 입력으로 사용 |
| `명령 2> 파일` | **표준 오류만** 파일로 |
| `명령 > 파일 2>&1` | 표준 출력과 표준 오류를 **모두** 같은 파일로 |
| `명령 2>/dev/null` | 오류 메시지를 폐기 |

`/dev/null`은 기록된 모든 내용을 폐기하는 특수 장치이다. 불필요한 오류 메시지를 제거할 때 사용한다.

> **`>` 사용 시 유의 사항**
> `>`는 명령을 실행하기 **전에** 파일을 먼저 비운다. 따라서 다음과 같은 명령은 파일의 내용을 완전히 소실시킨다.
> ```
> cat important.txt > important.txt
> ```
> 내용을 이어 붙이려는 경우에는 반드시 `>>`를 사용한다.
{: .prompt-danger }

---

## 3.3 파이프와 필터

**파이프(`|`)** 는 앞 명령의 표준 출력을 뒤 명령의 표준 입력으로 연결한다. 단순한 명령들을 조합하여 복잡한 처리를 수행할 수 있게 하는 유닉스 철학의 핵심 요소이다.

```bash
ps aux | grep bash
cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn
```

파이프와 함께 자주 사용하는 명령을 **필터(filter)** 라 한다.

| 필터 명령 | 기능 |
|---|---|
| `sort` | 정렬(`-n` 숫자, `-r` 역순) |
| `uniq` | 인접한 중복 제거(`-c` 개수 표시. **uniq**ue) |
| `wc` | 행·단어·문자 수 계산(**w**ord **c**ount) |
| `head` / `tail` | 앞 / 뒤 일부 추출 |
| `cut` | 필드 추출(`-d` 구분자, `-f` 필드 번호) |
| `grep` | 특정 문자열이 포함된 행 추출 |
| `tr` | 문자 치환·삭제(**tr**anslate) |
| **`tee`** | **화면 출력과 파일 저장을 동시에 수행** |

`tee`는 배관의 T자 이음쇠에서 유래한 명칭으로, 데이터의 흐름을 두 방향으로 나눈다.

```bash
df -h | tee report.txt | grep "^/dev"
```

> **[그림 4-1] 필요**
> 파이프의 데이터 흐름 개념도. `cut → sort → uniq → sort`가 왼쪽에서 오른쪽으로 연결되고, 각 단계의 중간 출력이 다음 명령의 입력으로 전달되는 모습을 화살표로 나타낸 도식.
{: .prompt-tip }

---

## 3.4 인용부호와 명령 치환

| 부호 | 명칭 | 동작 |
|---|---|---|
| `'...'` | 작은따옴표 | **모든 특수 의미를 제거**하고 문자 그대로 처리 |
| `"..."` | 큰따옴표 | `$`만 해석하고 나머지는 그대로 |
| `$(...)` | 명령 치환 | 내부 명령을 실행하고 그 **출력으로 치환** |

```bash
NAME="Linux"
echo '$NAME'                 # 출력: $NAME
echo "$NAME"                 # 출력: Linux
echo "오늘은 $(date +%F)"     # 출력: 오늘은 2026-09-22
```

---

> ### 따라 하기 4-3. 리다이렉션과 파이프
>
> **목적** 표준 출력과 표준 오류를 분리하여 처리하고, 파이프로 명령을 연결한다.
{: .prompt-tip }

**1단계.** 표준 출력을 파일로 저장한다.

```bash
cd ~/lab04
```

```bash
ls -l /etc > etc_list.txt
```

```bash
wc -l etc_list.txt
```

> `wc -l`은 파일의 행 수를 출력한다.

**2단계.** 파일에 이어 붙인다.

```bash
date >> etc_list.txt
```

```bash
tail -3 etc_list.txt
```

**3단계.** 표준 출력과 표준 오류가 분리되어 있음을 확인한다.

```bash
ls /etc /없는디렉터리 > out.txt
```

> **오류 메시지만 화면에 남는다.** `>`는 표준 출력(1번)만 처리하기 때문이다.

```bash
cat out.txt
```

> 오류 메시지는 파일에 포함되어 있지 않다.

**4단계.** 오류를 별도 파일로 저장하거나 폐기한다.

```bash
ls /etc /없는디렉터리 > out.txt 2> err.txt
```

```bash
cat err.txt
```

```bash
ls /없는디렉터리 2>/dev/null
```

> 마지막 명령은 아무것도 출력하지 않는다. 오류가 `/dev/null`로 폐기되었기 때문이다.

**5단계.** 파이프를 단계적으로 확장하며 결과를 관찰한다.

```bash
cut -d: -f7 /etc/passwd | head -5
```

```bash
cut -d: -f7 /etc/passwd | sort | uniq -c
```

```bash
cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn
```

> 한 단계씩 추가하면서 결과의 변화를 관찰하는 것이 파이프를 이해하는 가장 효과적인 방법이다. 최종 결과는 "로그인 셸의 종류별 계정 수를 많은 순으로 정렬한 것"이다.

**6단계.** `tee`로 화면과 파일에 동시에 출력한다.

```bash
df -h | tee disk.txt | grep "^/dev"
```

```bash
cat disk.txt
```

**7단계.** 인용부호와 명령 치환의 차이를 확인한다.

```bash
TODAY=$(date +%Y-%m-%d)
```

```bash
echo "오늘은 $TODAY 입니다"
```

```bash
echo '오늘은 $TODAY 입니다'
```

> 큰따옴표는 변수를 값으로 치환하지만, 작은따옴표는 문자 그대로 출력한다.

> **확인 사항** 표준 출력과 표준 오류를 각각 다른 파일로 분리할 수 있고, 파이프로 세 개 이상의 명령을 연결할 수 있다면 성공이다.
{: .prompt-tip }

# 제4절. 텍스트 편집기(nano·vi)

---

## 4.1 편집기의 종류

리눅스에서 설정 파일을 수정하려면 명령행 텍스트 편집기를 사용한다. Ubuntu Desktop에는 그래픽 편집기(gedit 계열)도 있으나, 서버 관리와 원격 접속 환경에서는 명령행 편집기를 다룰 수 있어야 한다.

| 편집기 | 난이도 | 특징 |
|---|---|---|
| **nano** | 낮음 | 화면 하단에 단축키가 표시되어 초보자에게 적합 |
| **vi / vim** | 높음 | **거의 모든 유닉스 계열에 기본 탑재.** 모드 기반 |

본 강의는 초보자에게 적합한 **nano를 우선**으로 익히고, `vi`는 최소한의 모드 전환과 저장·종료만 다룬다.

> **`vi`도 최소한은 익혀야 하는 이유**
> 서버 복구 모드나 최소 설치 환경에서는 `nano`가 설치되어 있지 않을 수 있으나, `vi`는 거의 항상 존재한다. 따라서 최소한의 조작(열기 → 수정 → 저장 → 종료)은 반드시 익혀 두어야 한다.
{: .prompt-info }

---

## 4.2 nano — 초보자용 편집기

```bash
nano 파일명
```

`nano`는 실행 즉시 문자를 입력할 수 있어 직관적이다. 화면 하단에 단축키가 표시되며, `^` 기호는 `Ctrl` 키를 의미한다.

| 단축키 | 동작 |
|---|---|
| **`Ctrl + O`** | 저장(**O**ut. 파일명 확인 후 `Enter`) |
| **`Ctrl + X`** | 종료(e**X**it) |
| `Ctrl + W` | 검색(**W**here is) |
| `Ctrl + \` | 검색 후 치환 |
| `Ctrl + K` | 현재 행 잘라내기 |
| `Ctrl + U` | 붙여넣기 |
| `Ctrl + G` | 도움말 |

> **[그림 4-2] 필요**
> nano 편집기 실행 화면. 본문 영역에 여러 행이 입력되어 있고, 화면 하단에 `^O 저장`, `^X 종료` 등 단축키 안내 줄이 두 줄로 표시된 스크린샷.
{: .prompt-tip }

---

## 4.3 vi의 모드 전환

`vi`가 어렵게 느껴지는 이유는 **모드(mode)** 개념 때문이다. vi에는 세 가지 상태가 존재하며, 같은 키가 상태에 따라 다르게 동작한다.

```
                     i, a, o 를 누르면
   ┌──────────────┐ ────────────────→ ┌──────────────┐
   │  명령 모드    │                    │  입력 모드    │
   │  (Command)   │ ←──────────────── │   (Insert)   │
   └──────┬───────┘    Esc 를 누르면    └──────────────┘
          │
          │  :  를 누르면
          ↓
   ┌──────────────┐
   │  실행 모드    │   :w  :q  :wq  등
   │    (ex)      │
   └──────────────┘
```

> **vi를 사용할 때 반드시 기억할 사항**
> vi를 실행하면 처음에는 **명령 모드**이다. 이 상태에서 입력한 문자는 텍스트가 아니라 명령으로 해석되므로, 그대로 타자를 치면 예상하지 못한 동작이 발생한다.
>
> **문자를 입력하려면 `i`를 눌러 입력 모드로 전환하여야 하며, 상태를 알 수 없을 때는 `Esc`를 눌러 명령 모드로 복귀한다.**
{: .prompt-danger }

**입력 모드 진입 키**

| 키 | 동작 |
|---|---|
| **`i`** | 커서 앞부터 입력(**i**nsert) |
| `a` | 커서 뒤부터 입력(**a**ppend) |
| `o` | 아래에 새 행을 만들고 입력(**o**pen) |

**실행 모드 명령(저장·종료)**

| 명령 | 동작 |
|---|---|
| `:w` | 저장(**w**rite) |
| `:q` | 종료(**q**uit) |
| **`:wq`** | **저장 후 종료** |
| **`:q!`** | **저장하지 않고 강제 종료** |

> **자주 출제되는 개념**
> `:wq`(저장 후 종료)와 `:q!`(저장하지 않고 종료)의 구분은 반복 출제된다. 상태를 알 수 없어 편집을 되돌리고 싶을 때는 `Esc`를 누른 뒤 `:q!`를 입력한다.
{: .prompt-warning }

---

> ### 따라 하기 4-4. nano로 파일 작성
>
> **목적** nano의 기본 조작으로 스크립트를 작성하고 실행한다.

**1단계.** nano로 새 파일을 연다.

```bash
nano ~/lab04/sysinfo.sh
```

**2단계.** 다음 내용을 입력한다.

#!/bin/bash
echo "=============================="

echo "=============================="

**4단계.** 실행 권한을 부여하고 실행한다.

```bash
chmod +x ~/lab04/sysinfo.sh
```

```bash
~/lab04/sysinfo.sh
```

> 첫 행의 `#!/bin/bash`를 **셔뱅(shebang)** 이라 하며, 이 파일을 어떤 인터프리터로 실행할지 지정한다. `chmod +x`는 파일에 실행 권한을 부여한다(**ch**ange **mod**e).

**5단계.** nano의 검색·치환 기능을 사용한다.

```bash
nano ~/lab04/sysinfo.sh
```

> `Ctrl + W`로 `커널`을 검색하고, `Ctrl + \`로 `보고`를 `리포트`로 치환한 뒤 저장·종료한다.

> **확인 사항** 스크립트가 실행되어 시스템 정보를 출력하였다면 성공이다.
{: .prompt-tip }

> ### 따라 하기 4-5. vi 최소 조작
>
> **목적** vi의 모드를 전환하며 입력·저장·종료를 수행한다.
{: .prompt-tip }

**1단계.** vi로 새 파일을 연다.

```bash
vi ~/lab04/practice.txt
```

**2단계.** `i`를 눌러 입력 모드로 전환한다.

> 화면 하단에 `-- INSERT --`가 표시되면 정상이다. 다음 세 행을 입력한다.

```
Linux is a free operating system.
Linux is powerful.
Linux is everywhere.
```

**3단계.** `Esc`를 눌러 명령 모드로 복귀한다.

> 하단의 `-- INSERT --` 표시가 사라진다.

**4단계.** 저장하고 종료한다.

> `:wq`를 입력하고 `Enter`를 누른다.

**5단계.** 저장 결과를 확인한다.

```bash
cat -n ~/lab04/practice.txt
```

**6단계.** 저장하지 않고 종료하는 절차를 연습한다.

```bash
vi ~/lab04/practice.txt
```

> 문자를 몇 개 입력한 뒤,
> - `Esc`를 눌러 명령 모드로 복귀한다.
> - `:q`를 입력하면 `No write since last change` 경고가 표시된다.
> - **`:q!`** 를 입력하여 변경 사항을 폐기하고 종료한다.

```bash
cat -n ~/lab04/practice.txt
```

> 파일이 원래 상태로 유지되어 있음을 확인한다. `:q!`는 편집 실수를 되돌리는 가장 확실한 방법이다.

> **확인 사항** `i`로 문자를 입력하고, `Esc` → `:wq`로 저장·종료하며, `:q!`로 변경을 폐기하고 종료하였다면 성공이다.
{: .prompt-tip }

## 단계 2. 파이프로 정보 추출 방법 확인

스크립트를 작성하기 전에, 필요한 정보를 어떤 명령으로 얻을 수 있는지 개별적으로 확인한다.

```bash
cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn | head -3
```

> 로그인 셸별 계정 수를 집계한다.

```bash
df -h | grep -E "^/dev" | awk '{print $6 " : " $5}'
```

> 마운트 지점별 디스크 사용률을 추출한다. `awk`는 행을 공백 단위로 나누어 특정 필드만 출력하는 필터이다.

```bash
free -h | awk '/^Mem/ {print $3 " / " $2}'
```

> 메모리 사용량을 추출한다.

## 단계 3. nano로 스크립트 작성

```bash
nano ~/lab04/mission/sysreport.sh
```

다음 내용을 입력하고 `Ctrl + O` → `Enter` → `Ctrl + X`로 저장·종료한다.

```bash
#!/bin/bash
# 시스템 상태 종합 보고 스크립트
# 작성: 리눅스 기초 4주차 종합 실습

OUT="$HOME/lab04/mission/report_$(date +%Y%m%d).txt"

{
  echo "=========================================="
  echo "  시스템 상태 보고서"
  echo "  생성 시각: $(date '+%Y-%m-%d %H:%M:%S')"
  echo "  생성 계정: $(whoami)@$(hostname)"
  echo "=========================================="
  echo

  echo "[1] 로그인 셸별 계정 수"
  cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn | sed 's/^/  /'
  echo

  echo "[2] 디스크 사용률"
  df -h | grep -E "^/dev" | awk '{print "  " $6 " : " $5 " 사용 (" $3 "/" $2 ")"}'
  echo

  echo "[3] 메모리 사용량"
  free -h | awk '/^Mem/ {print "  전체 " $2 " 중 " $3 " 사용"}'
} > "$OUT" 2>&1

echo "보고서를 생성하였습니다: $OUT"
cat "$OUT"
```

> `{ ... } > "$OUT"` 구문은 중괄호 내부의 모든 출력을 한 번에 파일로 보낸다. 각 `echo`마다 `>>`를 붙이는 방식보다 간결하며 오류 가능성이 낮다.

# 제6절. 자주 발생하는 오류와 대응 방법

---

| 화면에 출력된 메시지 / 증상 | 원인 | 대응 방법 |
|---|---|---|
| `MYVAR: command not found` | 등호 앞뒤에 공백 | `MYVAR="값"`과 같이 공백 없이 작성한다. |
| 별칭이 적용되지 않음 | 새 셸에서는 소멸 | `~/.bashrc`에 기재하고 `source ~/.bashrc`를 실행한다. |
| vi에서 문자가 입력되지 않음 | 명령 모드 상태 | **`i`** 를 눌러 입력 모드로 전환한다. |
| vi에서 종료할 수 없음 | 모드를 알 수 없음 | **`Esc`** 를 누른 뒤 **`:q!`** 를 입력한다. |
| `./script.sh: not found` | 셔뱅이 없거나 잘못됨 | 첫 행에 `#!/bin/bash`를 기재한다. |
| 스크립트가 실행되지 않음 | 실행 권한 없음 | `chmod +x 파일`을 실행한다. |
| `>` 사용 후 파일이 비워짐 | `>`는 실행 전 파일을 비움 | `>>`를 사용하거나 백업을 선행한다. |
| `PATH`에 추가했으나 적용 안 됨 | 설정을 반영하지 않음 | `source ~/.bashrc`를 실행한다. |

# 제7절. 요약

## 7.1 핵심 개념 정리

| 구분 | 요점 |
|---|---|
| 셸의 역할 | 명령을 해석할 뿐 아니라 와일드카드·변수·명령 치환을 확장하고 입출력 흐름을 제어한다. Ubuntu의 기본 대화형 셸은 bash이다. |
| 환경 변수 | 사용자 변수는 현재 셸에만, 환경 변수는 자식 프로세스까지 전달된다. `export`가 그 경계를 결정하며, `echo $변수`로 값을 조회한다. |
| `PATH` | 명령어를 탐색할 디렉터리 목록이며, `.`을 포함해서는 안 된다. |
| 리다이렉션 | `>`는 덮어쓰기, `>>`는 이어쓰기, `<`는 입력, `2>`는 오류만 처리한다. |
| 파이프와 필터 | `|`로 명령을 연결하고 `sort`·`uniq`·`cut`·`grep`·`awk`·`tee`를 조합하면 별도 프로그램 없이 자료를 분석할 수 있다. |
| 별칭 | `alias`로 정의하며, 영구 적용하려면 `~/.bashrc`에 기재한다. |
| 편집기 | 초보자는 `nano`(`Ctrl+O` 저장, `Ctrl+X` 종료)를 우선 사용하고, `vi`는 `i`(입력)·`Esc`(명령)·`:wq`(저장 종료)·`:q!`(폐기 종료)만 익힌다. |

## 7.2 본 강의에서 학습한 명령어와 기호

| 명령어 / 기호 | 기능 |
|---|---|
| `echo $변수` | 변수 값 조회 |
| `export` | 환경 변수 승격 |
| `alias` / `unalias` | 별칭 정의 / 해제 |
| `source` | 설정 파일 즉시 반영 |
| `>` / `>>` / `<` | 덮어쓰기 / 이어쓰기 / 입력 |
| `2>` / `2>/dev/null` | 오류만 저장 / 오류 폐기 |
| `\|` | 파이프 |
| `tee` | 화면 출력 + 파일 저장 |
| `sort` / `uniq` / `cut` / `grep` / `tr` / `awk` | 필터 명령 |
| `nano` | 초보자용 편집기 |
| `vi` | 표준 편집기 |
