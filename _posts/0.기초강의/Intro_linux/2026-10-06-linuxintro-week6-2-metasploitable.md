# 제1절. Metasploitable 2의 이해와 안전 수칙

---

## 1.1 Metasploitable 2란

**Metasploitable 2**는 보안 학습을 위하여 **의도적으로 취약하게 구성한 리눅스 가상 머신**이다. 보안 도구 개발사가 교육 목적으로 무상 배포한다.

| 항목 | 내용 |
|---|---|
| 기반 운영체제 | Ubuntu 8.04(구형, 32비트) |
| 배포 형식 | 가상 디스크 이미지(`.vmdk`)를 압축한 파일 |
| 기본 계정 | `msfadmin` / `msfadmin` |
| 용도 | 취약점 진단 실습의 **표적** 시스템 |

이 시스템에는 오래된 서비스, 암호화되지 않은 통신, 추측하기 쉬운 비밀번호, 과도한 파일 권한 등이 **의도적으로** 포함되어 있다. 지금까지 배운 안전한 설정과 정반대의 상태이다.

> **본 과정에서는 이 시스템을 공격하지 않는다.** 1주차부터 5주차까지 학습한 조회·점검 명령만을 사용하여 "왜 이 시스템이 위험한가"를 관찰하는 것이 목적이다.
{: .prompt-tip }

## 1.2 반드시 준수하여야 할 안전 수칙

Metasploitable 2는 보호 장치가 제거된 시스템이다. 다음 수칙을 반드시 준수하여야 한다.

| 번호 | 수칙 | 근거 |
|---|---|---|
| **1** | **네트워크는 호스트 전용 어댑터만 사용한다.** | 인터넷이나 물리 LAN에 연결되면 외부에서 침해될 수 있다. |
| **2** | **NAT 어댑터를 설정하지 않는다.** | 인터넷에 노출되는 즉시 위험하다. 갱신이 필요 없으므로 인터넷 연결 자체가 불필요하다. |
| **3** | **브리지 어댑터를 절대 사용하지 않는다.** | 공유기에 연결된 다른 기기에서 접근할 수 있게 된다. |
| **4** | 이 시스템에 개인 자료를 저장하지 않는다. | 보호되지 않는 시스템이다. |
| **5** | 본인이 소유하거나 허가받은 시스템에만 점검을 수행한다. | 타인의 시스템을 무단으로 점검하는 행위는 법적 책임을 수반한다. |

> **가장 중요한 원칙**
> Metasploitable 2는 **격리된 호스트 전용 네트워크 안에서만** 사용한다. 이 원칙 하나만 지켜도 위험은 실습 환경 내부로 한정된다.
{: .prompt-danger }

# 제2절. 가상 머신 등록

---

Metasploitable 2도 Kali와 마찬가지로 직접 설치하지 않고, 배포되는 가상 디스크 이미지를 사용한다.

> ### 따라 하기 2-1. Metasploitable 2 내려받기와 등록
>
> **목적** 취약 표적 시스템을 VirtualBox에 등록한다.
{: .prompt-tip }

**1단계.** [SourceForge의 Metasploitable 배포 페이지](https://sourceforge.net/projects/metasploitable/)에서 압축 파일을 내려받는다. 파일 이름은 `metasploitable-linux-2.0.0.zip` 형태이다.

**2단계.** 압축을 해제한다. `.vmdk` 확장자를 가진 가상 디스크 파일이 생성된다.

**3단계.** VirtualBox 관리자에서 **[새로 만들기(New)]** 를 선택하고 다음과 같이 설정한다. 이번에는 이미 만들어진 디스크를 사용하므로, 디스크 생성 단계에서 **기존 디스크**를 지정한다.

| 항목 | 설정값 |
|---|---|
| 이름(Name) | **`meta2-y1`** |
| 종류(Type) | Linux |
| 버전(Version) | Ubuntu (32-bit) |
| 메모리(RAM) | `512` MB (구형 시스템이므로 충분하다) |
| 하드 디스크 | **기존 가상 하드 디스크 파일 사용** → 앞서 해제한 `.vmdk` 지정 |

**4단계.** 가상 머신이 생성된다. 아직 실행하지 않는다. 다음 절에서 네트워크를 먼저 구성한다.

> **[그림 6-2] 필요**
> VirtualBox 관리자에 ubuntu-y1, kali-y1, meta2-y1 세 대의 가상 머신이 모두 등록되어 있는 목록 화면 스크린샷.
{: .prompt-tip }

# 제3절. 세 대를 하나의 네트워크로 연결

---

세 대의 가상 머신이 서로 통신하려면 같은 네트워크에 속해야 한다. 이를 위하여 **호스트 전용 네트워크(Host-Only Network)** 를 사용한다.

## 3.1 호스트 전용 네트워크란

호스트 전용 네트워크는 **호스트(윈도우 PC)와 그 안의 가상 머신들만이 참여하는 격리된 내부 네트워크**이다. 인터넷이나 외부 기기와는 연결되지 않으므로, 취약한 Metasploitable 2를 두더라도 위험이 외부로 번지지 않는다.

```
                  ┌──────────────────────────┐
                  │   윈도우 호스트            │
                  └────────────┬─────────────┘
                               │
     ┌─────────────────────────┴─────────────────────────┐
     │        호스트 전용 네트워크 (격리된 내부망)          │
     └──┬──────────────────┬──────────────────┬──────────┘
        │                  │                  │
 ┌──────┴──────┐   ┌───────┴───────┐   ┌──────┴────────────┐
 │  ubuntu-y1  │   │   kali-y1     │   │   meta2-y1        │
 │  (Ubuntu)   │   │   (Kali)      │   │ (Metasploitable2) │
 └─────────────┘   └───────────────┘   └───────────────────┘
```

> **[그림 6-3] 필요**
> 윈도우 호스트 아래에 호스트 전용 네트워크가 있고, 그 네트워크에 ubuntu-y1·kali-y1·meta2-y1 세 대가 연결된 구조도. 이 네트워크는 인터넷과 분리되어 있음을 표시.
{: .prompt-tip }

## 3.2 호스트 전용 네트워크 생성

> ### 따라 하기 3-1. 호스트 전용 네트워크 준비
{: .prompt-tip }

**1단계.** VirtualBox 관리자의 상단 메뉴에서 **[도구] → [네트워크(Network)]** 를 선택한다.

**2단계.** **[호스트 전용 네트워크(Host-only Networks)]** 탭에서 **[만들기(Create)]** 를 누른다. `VirtualBox Host-Only Ethernet Adapter`가 생성된다.

**3단계.** 생성된 어댑터의 **DHCP 서버**가 활성화되어 있는지 확인한다. 활성화되어 있으면 각 가상 머신이 IP 주소를 자동으로 받는다.

## 3.3 각 가상 머신에 어댑터 연결

세 대 모두 호스트 전용 어댑터를 연결한다. 각 가상 머신을 선택하고 **[설정] → [네트워크]** 에서 아래와 같이 구성한다.

| 가상 머신 | 어댑터 1 | 어댑터 2 |
|---|---|---|
| `ubuntu-y1` | NAT (인터넷용, 기존 유지) | **호스트 전용 어댑터** 추가 |
| `kali-y1` | NAT (인터넷용, 기존 유지) | **호스트 전용 어댑터** 추가 |
| `meta2-y1` | **연결하지 않음** | **호스트 전용 어댑터만** |

> **`meta2-y1`에만 NAT가 없는 것은 의도된 구성이다.** 취약 시스템이 인터넷에 노출되지 않도록, Metasploitable 2에는 호스트 전용 어댑터 하나만 연결한다. 설정 누락이 아니다.
{: .prompt-danger }

**설정 방법.** 각 가상 머신의 **[설정] → [네트워크] → [어댑터 2]** 에서 **[네트워크 어댑터 사용하기]** 를 체크하고, 연결 방식을 **[호스트 전용 어댑터]** 로 지정한다.

# 제4절. 종합 실습 — 3대 통신 확인과 취약 시스템 관찰

---

이번 종합 실습은 본 과정 전체의 마무리이다. 세 대의 가상 머신을 모두 켜고, 서로 통신이 되는지 확인한 뒤, 학습한 명령으로 취약 시스템을 관찰한다.

## 4.1 세 대의 가상 머신 시작과 IP 확인

**1단계.** VirtualBox 관리자에서 `ubuntu-y1`, `kali-y1`, `meta2-y1` 세 대를 모두 시작한다.

**2단계.** 각 가상 머신에 로그인하고 IP 주소를 확인한다. `meta2-y1`은 `msfadmin` / `msfadmin`으로 로그인한다.

`ubuntu-y1`(Ubuntu)과 `kali-y1`(Kali)에서는 다음 명령을 사용한다.

```bash
ip addr
```

> `ip addr`은 네트워크 인터페이스와 IP 주소를 출력한다. 호스트 전용 어댑터에 해당하는 인터페이스에서 `192.168.56.x` 형태의 주소를 확인한다.

`meta2-y1`(Metasploitable 2)은 구형 시스템이므로 다음의 옛 명령을 사용한다.

```bash
ifconfig
```

> `ifconfig`는 **i**nter**f**ace **config**uration의 약어로, `ip addr`의 이전 세대 명령이다. `eth0` 항목의 `inet addr:192.168.56.x`에서 IP 주소를 확인한다.

세 대의 IP 주소를 각각 기록한다. 예를 들어 다음과 같이 확인되었다고 하자(실제 값은 다를 수 있다).

| 가상 머신 | 확인된 IP 주소(예시) |
|---|---|
| `ubuntu-y1` | 192.168.56.101 |
| `kali-y1` | 192.168.56.102 |
| `meta2-y1` | 192.168.56.103 |

> **[그림 6-4] 필요**
> Metasploitable 2 콘솔에서 ifconfig를 실행한 화면. eth0의 inet addr(192.168.56.x)에 표시를 붙인 스크린샷.
{: .prompt-tip }

## 4.2 통신 확인

**3단계.** `ubuntu-y1`의 터미널에서 나머지 두 대로 `ping`을 보낸다. (아래 IP는 앞서 기록한 실제 값으로 바꾸어 입력한다.)

```bash
ping -c 3 192.168.56.102
ping -c 3 192.168.56.103
```

> `ping`은 상대 시스템에 신호를 보내고 응답을 확인하는 명령이며, `-c 3`은 **c**ount(횟수) 3회를 의미한다. `3 packets transmitted, 3 received`와 같이 응답이 오면 통신이 정상이다.

**4단계.** 반대로 `kali-y1`에서 `ubuntu-y1`과 `meta2-y1`로도 `ping`이 되는지 확인한다.

## 4.3 취약 시스템 관찰

세 대가 통신되는 것을 확인하였다면, 학습한 조회 명령으로 Metasploitable 2가 왜 위험한지 관찰한다. `meta2-y1` 콘솔에서 수행한다.

**5단계.** 열려 있는 서비스(포트)를 확인한다.

```bash
netstat -tlnp
```

> `netstat`은 네트워크 연결 상태를 출력하는 명령이며, `-tlnp`는 **t**cp, **l**isten(대기 중), **n**umeric(숫자 표기), **p**rogram(프로그램 이름)을 의미한다. 지나치게 많은 서비스가 외부의 연결을 기다리고 있음을 확인한다. 서비스가 많을수록 공격 대상이 되는 지점이 많아진다.

**6단계.** 계정 목록을 확인한다.

```bash
cat /etc/passwd
```

> 1주차부터 학습한 대로 `/etc/passwd`는 계정 정보를 담은 파일이다. 불필요한 서비스 계정이 다수 존재함을 확인한다.

> **관찰의 목적**
> Metasploitable 2에서 관찰한 "많은 열린 포트", "불필요한 계정"은 3주차에서 학습한 **최소 권한 원칙**과 정반대의 상태이다. 안전한 시스템(Ubuntu)과 취약한 시스템(Metasploitable 2)을 비교함으로써, 지금까지 배운 계정 관리와 권한 설정이 왜 중요한지를 확인할 수 있다.
{: .prompt-tip }

## 4.4 완료 기준 — 실습 환경 최종 점검

```
 [ ] VirtualBox 관리자에 ubuntu-y1, kali-y1, meta2-y1 세 대가 등록되어 있다.
 [ ] 세 대 모두 호스트 전용 어댑터로 연결되어 있다.
 [ ] meta2-y1 에는 NAT 어댑터가 없다(호스트 전용만).
 [ ] ubuntu-y1 에서 kali-y1, meta2-y1 로 ping 이 성공한다.
 [ ] netstat, cat /etc/passwd 로 취약 시스템의 상태를 관찰하였다.
```

> **[그림 6-5] 필요**
> ubuntu-y1 터미널에서 kali-y1과 meta2-y1로 각각 ping이 성공하여 응답이 돌아오는 화면 스크린샷.
{: .prompt-tip }

이로써 세 대의 가상 머신으로 구성된 보안 실습 환경이 완성되었다.

# 제5절. 자주 발생하는 오류와 대응 방법

---

| 증상 | 원인 | 대응 방법 |
|---|---|---|
| Metasploitable 2가 부팅되지 않음 | `.vmdk`를 잘못 지정 | 새 가상 머신 생성 시 "기존 가상 하드 디스크 파일 사용"에서 `.vmdk`를 지정하였는지 확인한다. |
| `ping`이 응답하지 않음 | 호스트 전용 어댑터 미연결 | 세 대 모두 [설정] → [네트워크]에서 호스트 전용 어댑터가 연결되었는지 확인한다. |
| IP 주소가 표시되지 않음 | DHCP 서버 비활성화 | [도구] → [네트워크]에서 호스트 전용 어댑터의 DHCP 서버를 활성화한다. |
| `meta2-y1`이 인터넷에 연결됨 | NAT 어댑터가 설정됨 | 즉시 NAT 어댑터를 제거한다. 호스트 전용만 남긴다. |
| `ifconfig`가 없다고 표시됨(Ubuntu/Kali) | 최신 시스템은 `ip` 명령 사용 | Ubuntu·Kali에서는 `ip addr`를 사용한다. `ifconfig`는 Metasploitable 2에서만 사용한다. |
| `ping`이 무한히 계속됨 | 횟수 지정 누락 | `-c 3` 옵션을 붙이거나 `Ctrl` + `C`로 중단한다. |

# 제6절. 요약 및 과정 마무리

---

## 6.1 요약

| 구분 | 요점 |
|---|---|
| Metasploitable 2 | 의도적으로 취약하게 만든 실습 표적이다. 기본 계정은 `msfadmin`이다. |
| 안전 수칙 | 호스트 전용 네트워크에서만 사용하며, NAT·브리지를 연결하지 않는다. |
| 네트워크 연결 | 세 대를 호스트 전용 네트워크로 연결하여 격리된 내부망을 구성한다. |
| 통신 확인 | `ip addr`(Ubuntu·Kali)와 `ifconfig`(Metasploitable 2)로 IP를 확인하고 `ping`으로 통신을 점검한다. |
| 취약 관찰 | `netstat`, `cat /etc/passwd`로 취약 시스템의 위험 요소를 확인한다. |

## 6.2 과정을 마치며

여섯 주에 걸쳐 리눅스의 기초를 학습하였다. 리눅스의 개념과 구조에서 출발하여(1주차), 터미널과 파일 시스템을 다루고(2주차), **사용자 계정과 권한을 설정하며**(3주차), 셸과 프로세스를 제어하고(4주차), 네트워크를 이해한 뒤(5주차), 마지막으로 세 대의 가상 머신으로 보안 실습 환경을 완성하였다(6주차).

특히 3주차의 **계정 관리와 접근 권한**은 리눅스 운영의 핵심이자 보안의 출발점이다. 이번 시간에 관찰한 취약 시스템의 위험 요소 대부분이 계정과 권한의 잘못된 설정에서 비롯된 것임을 확인하였다. 안전한 시스템을 만드는 능력은 이 원칙을 이해하는 데에서 시작된다.

이제 세 대의 가상 머신이 준비되었다. 이 환경은 이후의 보안 관련 후속 과정에서 그대로 사용된다.
