> **학습 목표**
> 1. GNOME 데스크톱 환경에서 터미널을 여는 여러 방법을 설명하고 실행할 수 있다.
> 2. 프롬프트에 담긴 사용자·호스트·현재 위치·권한 정보를 해석할 수 있다.
> 3. 명령어가 명령·옵션·인자의 세 요소로 구성됨을 이해하고 구분할 수 있다.
> 4. 자동 완성, 명령 이력, 매뉴얼 등 명령행의 기본 조작 방법을 활용할 수 있다.
> 5. 전원 인가부터 그래픽 로그인 화면까지의 부팅 과정을 단계별로 설명할 수 있다.
> 6. 시스템을 안전하게 종료하고 재부팅하는 명령을 사용할 수 있다.
{: .prompt-info }

본 강의는 리눅스를 처음 접하는 학습자를 대상으로 한다. 사전 지식은 요구하지 않으며, 모든 명령어는 그 의미와 유래를 함께 제시한다.

실습 환경은 그래픽 사용자 인터페이스(GUI)를 갖춘 **Ubuntu Desktop 24.04 LTS**가 설치된 상태를 전제로 한다. 데스크톱 환경에서는 마우스로 프로그램을 실행하고 창을 조작하는 방식이 익숙하지만, 리눅스의 진정한 힘은 문자로 명령을 입력하는 **터미널**에서 발휘된다. 본 강의에서는 데스크톱 화면에서 터미널을 열고, 명령행 인터페이스의 기본 조작을 익히는 데 집중한다.

실습 계정은 `student`, 호스트 이름은 `ubuntu-y1`으로 구성되어 있으며, 본 강의의 모든 예시는 이 환경을 기준으로 작성되었다.

# 제1절. 터미널을 여는 방법

---

## 1.1 그래픽 데스크톱과 터미널

Ubuntu Desktop을 실행하면 바탕화면, 상단 표시줄, 아이콘 등으로 구성된 그래픽 환경이 나타난다. 이 그래픽 환경을 제공하는 소프트웨어를 **데스크톱 환경(Desktop Environment)** 이라 하며, 우분투는 **GNOME(그놈)** 이라는 데스크톱 환경을 기본으로 채택하고 있다.

그래픽 환경에서 마우스로 대부분의 작업을 처리할 수 있으나, 리눅스를 학습하고 관리하기 위해서는 문자로 명령을 입력하는 **명령행 인터페이스(Command Line Interface, CLI)** 를 반드시 익혀야 한다. 이 명령행 인터페이스를 사용할 수 있게 해 주는 프로그램이 **터미널(Terminal)** 이다.

| 구분 | 그래픽 방식(GUI) | 명령행 방식(CLI) |
|---|---|---|
| 조작 수단 | 마우스 클릭 | 키보드 문자 입력 |
| 대표 프로그램 | 파일 관리자(Files) | 터미널(Terminal) |
| 반복 작업 | 매번 손으로 반복 | 명령을 저장해 자동 반복 |
| 대량 처리 | 파일을 하나씩 처리 | 하나의 명령으로 수천 개 처리 |

터미널 창 안에서 사용자가 입력한 문자를 해석하여 실제 프로그램을 실행하는 것은 **셸(Shell)** 이라는 소프트웨어이다. 우분투의 기본 셸은 **bash(배시)** 이며, 터미널은 이 셸과 사용자를 이어 주는 창구에 해당한다.

> **용어 정리 — 터미널과 셸**
> 터미널은 문자를 입력하고 출력을 보여 주는 '창'이고, 셸은 그 창 안에서 명령을 해석하는 '해석기'이다. 창(터미널)과 해석기(셸)는 서로 다른 개념이나, 일상적으로는 둘을 묶어 "터미널을 연다"라고 표현한다.
{: .prompt-info }

---

## 1.2 터미널을 여는 세 가지 방법

GNOME 데스크톱에서 터미널을 여는 방법은 여러 가지이다. 상황에 맞는 방법을 익혀 두면 편리하다.

| 방법 | 조작 | 특징 |
|---|---|---|
| 단축키 | `Ctrl + Alt + T` | 가장 빠르다. 어느 화면에서나 즉시 열린다. |
| 앱 목록 | 좌측 하단 격자 아이콘 → `Terminal` 검색 | 프로그램 이름으로 찾아 실행한다. |
| 파일 관리자 | 폴더에서 마우스 오른쪽 버튼 → 터미널 열기 | 특정 폴더 위치에서 바로 시작한다. |

> **[그림 2-1] 필요**
> GNOME 데스크톱 화면에서 `Ctrl + Alt + T`로 터미널 창이 열린 모습. 상단 제목표시줄과 프롬프트 `student@ubuntu-y1:~$`가 보이는 스크린샷.
{: .prompt-tip }

---

> ### 따라 하기 1-1. 터미널 열기
>
> **목적** GNOME 데스크톱에서 여러 방법으로 터미널을 열어 본다.
{: .prompt-tip }

**1단계.** 단축키로 터미널을 연다.

키보드에서 `Ctrl`, `Alt`, `T` 세 키를 동시에 누른다. 검은 바탕(또는 설정에 따른 색)의 터미널 창이 나타나며, 다음과 같은 프롬프트가 표시된다.

```
student@ubuntu-y1:~$
```

**2단계.** 앱 목록에서 터미널을 찾는다.

화면 좌측 하단의 격자 모양 아이콘(앱 표시)을 누르고, 검색란에 `terminal`을 입력한다. `Terminal` 아이콘이 나타나면 눌러 실행한다.

**3단계.** 터미널이 정상 동작하는지 확인한다.

터미널 창에 다음을 입력하고 `Enter` 키를 누른다.

```bash
echo "터미널이 열렸습니다"
```

> `echo`는 뒤에 오는 문자열을 화면에 그대로 출력하는 명령이다. 입력한 문장이 아래 줄에 그대로 표시되면 터미널이 정상적으로 동작하는 것이다.

> **확인 사항** 두 가지 이상의 방법으로 터미널을 열었고, `echo` 명령의 출력이 화면에 표시되었다면 성공이다.
{: .prompt-tip }

# 제2절. 프롬프트의 해석

---

## 2.1 프롬프트가 담고 있는 정보

터미널을 열면 커서 앞에 다음과 같은 문자열이 표시된다. 이를 **프롬프트(prompt)** 라 한다. 프롬프트는 시스템이 사용자의 명령을 받을 준비가 되었음을 알리는 표시이다.

```
student@ubuntu-y1:~$
```

프롬프트는 짧지만 네 가지 정보를 담고 있다.

```
 student  @  ubuntu-y1  :  ~  $
    │      │      │       │  │  │
    │      │      │       │  │  └─ 권한 구분 기호
    │      │      │       │  └──── 현재 작업 디렉터리
    │      │      │       └─────── 구분자
    │      │      └─────────────── 호스트(컴퓨터) 이름
    │      └────────────────────── "~에 소속된"의 의미
    └───────────────────────────── 로그인한 사용자 이름
```

| 구성 요소 | 의미 |
|---|---|
| 사용자 이름 | 현재 로그인한 계정(`student`) |
| `@` | "~에 소속된"을 뜻하는 구분자 |
| 호스트 이름 | 이 컴퓨터에 부여된 이름(`ubuntu-y1`) |
| 현재 디렉터리 | `~`는 해당 사용자의 홈 디렉터리를 나타내는 약칭이다. |
| **`$` 또는 `#`** | **`$`는 일반 사용자, `#`는 관리자(root)를 의미한다.** |

> **가장 중요한 확인 습관**
> 프롬프트 마지막 한 글자를 항상 확인하는 습관을 들여야 한다. `$`는 일반 사용자이므로 실수하더라도 피해가 자신의 파일에 한정되지만, `#`는 관리자이므로 잘못된 명령 하나가 시스템 전체를 손상시킬 수 있다.
{: .prompt-warning }

---

> ### 따라 하기 1-2. 프롬프트 해석과 사용자 확인
>
> **목적** 프롬프트가 표시하는 정보를 명령어로 각각 확인하고, 관리자 전환 시 프롬프트가 변화하는 것을 관찰한다.
{: .prompt-tip }

**1단계.** 현재 로그인한 사용자를 확인한다.

```bash
whoami
```

> `whoami`는 "who am i(나는 누구인가)"를 붙여 쓴 명령이다. 프롬프트의 `@` 앞부분(`student`)과 일치하는지 확인한다.

**2단계.** 컴퓨터 이름을 확인한다.

```bash
hostname
```

> 프롬프트의 `@` 뒷부분(`ubuntu-y1`)과 일치하는지 확인한다.

**3단계.** 현재 작업 디렉터리를 확인한다.

```bash
pwd
```

> `pwd`는 **p**rint **w**orking **d**irectory(현재 작업 디렉터리를 출력하라)의 약어이다. `/home/student`와 같이 출력되며, 프롬프트의 `~`가 바로 이 경로의 축약 표기임을 알 수 있다.

**4단계.** 관리자로 전환하여 프롬프트의 변화를 관찰한다.

```bash
sudo -i
```

> `sudo`는 **s**uper**u**ser **do**(관리자 권한으로 실행하라)의 약어이다. 비밀번호를 요구하면 **자신의 비밀번호**를 입력한다. 입력 중 화면에 아무 문자도 표시되지 않는 것은 정상 동작이다.

```bash
whoami
```

> `root`가 출력되고, 프롬프트 기호가 `$`에서 `#`로 변경된 것을 확인한다.

**5단계.** 원래 계정으로 복귀한다.

```bash
exit
```

> 프롬프트가 다시 `$`로 돌아왔는지 확인한다.

> **확인 사항** `whoami`의 출력이 '자신의 계정 → root → 자신의 계정' 순으로 변하고, 프롬프트 기호가 `$ → # → $`로 변화하였다면 성공이다.
{: .prompt-tip }

> **참고 — 우분투에서 관리자 전환**
> 우분투는 보안 정책상 root 계정에 비밀번호를 설정하지 않고 잠가 둔다. 따라서 모든 관리 작업은 `sudo`를 통해 수행한다. 이렇게 하면 누가 언제 어떤 관리 명령을 실행했는지 기록이 남아 감사(audit)가 가능해진다.
{: .prompt-info }

# 제3절. 명령어의 구조와 도움말

---

## 3.1 명령어의 구조

리눅스 명령어는 다음과 같은 일정한 형식을 따른다.

```
 명령어   [옵션]      [인자]
   ls      -l  -h      /etc
    │       │            │
    │       │            └── 인자(argument): 명령이 작용할 대상
    │       └─────────────── 옵션(option): 동작 방식을 조정하는 값
    └─────────────────────── 명령(command): 실행할 프로그램
```

| 구성 요소 | 역할 |
|---|---|
| 명령(command) | 실행할 프로그램의 이름 |
| 옵션(option) | 명령의 동작 방식을 조정하는 값 |
| 인자(argument) | 명령이 작용할 대상(파일·디렉터리 등) |

옵션의 표기 방식은 두 가지가 있다.

| 형식 | 표기 | 예시 |
|---|---|---|
| 짧은 옵션 | 하이픈 1개 + 알파벳 1글자 | `ls -l`, `ls -a` |
| 긴 옵션 | 하이픈 2개 + 단어 | `ls --all`, `du --max-depth=1` |

짧은 옵션은 하나로 묶어 쓸 수 있다. `ls -l -a -h`와 `ls -lah`는 동일한 명령이다.

> **유의 사항**
> 리눅스는 대소문자를 엄격히 구분한다. 명령어 `ls`는 동작하지만 `LS`는 동작하지 않으며, 파일 `Data.txt`와 `data.txt`는 서로 다른 파일이다. 초심자가 가장 빈번하게 겪는 오류의 원인이므로 반드시 유의해야 한다.
{: .prompt-warning }

---

## 3.2 도움말 조회 방법

명령어의 옵션을 모두 암기할 필요는 없다. 리눅스는 체계적인 도움말 체계를 갖추고 있다.

| 명령 | 약어 풀이 | 설명 |
|---|---|---|
| `man 명령어` | **man**ual | 매뉴얼 페이지 표시. 가장 상세한 공식 문서 |
| `명령어 --help` | — | 간략한 사용법 요약 |
| `whatis 명령어` | what is | 한 줄 설명 |
| `type 명령어` | — | 내부 명령인지 외부 명령인지 판별 |

`man` 화면은 `less`라는 페이지 표시 프로그램으로 출력되며, 다음 키로 조작한다.

| 키 | 동작 |
|---|---|
| `Space` | 다음 화면 |
| `b` | 이전 화면(**b**ack) |
| `/문자열` | 아래 방향 검색 |
| `n` | 다음 검색 결과(**n**ext) |
| `g` / `G` | 문서 처음 / 끝 |
| **`q`** | **종료(**q**uit)** |

> **초심자가 자주 겪는 상황**
> `man`이나 `less` 화면에서 빠져나오지 못해 당황하는 경우가 많다. **`q`** 를 누르면 종료된다.
{: .prompt-tip }

---

> ### 따라 하기 1-3. 명령어 구조와 도움말 익히기
>
> **목적** 명령어의 옵션과 인자를 직접 조합해 보고, 매뉴얼을 조회한다.
{: .prompt-tip }

**1단계.** 옵션 없이 명령을 실행한다.

```bash
ls
```

> 현재 디렉터리의 파일 목록이 이름만 간단히 출력된다.

**2단계.** 옵션을 추가하여 동작을 바꾼다.

```bash
ls -l
```

> `-l`(**l**ong) 옵션을 붙이면 권한·소유자·크기·시각이 함께 출력된다. 같은 명령이라도 옵션에 따라 결과가 달라짐을 확인한다.

**3단계.** 옵션과 인자를 함께 지정한다.

```bash
ls -l /etc
```

> `/etc`가 인자이다. 현재 위치가 아니라 지정한 `/etc` 디렉터리의 내용을 상세히 출력한다.

**4단계.** 매뉴얼을 조회한다.

```bash
man ls
```

> 화면 내에서 `/-a`를 입력한 뒤 `Enter`를 눌러 `-a` 옵션 설명을 검색한다. `q`를 눌러 종료한다.

**5단계.** 간략한 사용법을 확인한다.

```bash
ls --help
```

> `--help`는 매뉴얼보다 짧은 사용법 요약을 화면에 곧바로 출력한다. `man`처럼 별도 종료 키가 필요하지 않다.

**6단계.** 명령의 한 줄 설명과 종류를 확인한다.

```bash
whatis pwd
```

```bash
type pwd
```

> `pwd`는 `pwd is a shell builtin`으로 출력된다. 셸에 내장된 명령이라는 의미이다.

> **확인 사항** 같은 `ls` 명령이 옵션에 따라 다르게 동작함을 확인하였고, `man ls`에서 검색과 종료를 수행하였다면 성공이다.
{: .prompt-tip }

# 제4절. 명령행의 기본 조작

---

## 4.1 자동 완성과 명령 이력

효율적인 작업을 위해 다음 조작을 반드시 익혀 두어야 한다.

| 키 | 동작 | 활용 상황 |
|---|---|---|
| **`Tab`** | 이름 자동 완성 | **오타를 줄이는 가장 효과적인 수단이다.** |
| `↑` `↓` | 이전 명령 불러오기 | 동일한 명령을 반복할 때 |
| `Ctrl + R` | 이전 명령 검색(**R**everse) | 오래전에 사용한 명령을 찾을 때 |
| `Ctrl + A` / `Ctrl + E` | 행의 처음 / 끝으로 이동 | 긴 명령을 수정할 때 |
| `Ctrl + U` / `Ctrl + K` | 커서 앞 / 뒤 삭제 | 입력을 취소할 때 |
| **`Ctrl + C`** | **실행 중단(**C**ancel)** | **화면이 멈춘 것처럼 보일 때** |
| `Ctrl + L` | 화면 지우기(c**l**ear) | 화면이 복잡할 때 |

`history`는 지금까지 입력한 명령의 목록을 보여 주는 명령이다. `hist**ory**`의 앞부분만 입력하고 `Tab`을 누르면 자동으로 완성된다.

---

> ### 따라 하기 1-4. 자동 완성과 이력 활용
>
> **목적** 자동 완성 기능과 명령 이력을 체험한다.
{: .prompt-tip }

**1단계.** 자동 완성 기능을 사용한다.

터미널에 `hist`까지만 입력하고 `Tab` 키를 누른다.

```bash
hist
```

> `history`로 자동 완성되는 것을 확인한다. 이어서 `Enter`를 눌러 실행하면 지금까지 입력한 명령 목록이 출력된다.

**2단계.** 후보가 여러 개일 때의 동작을 확인한다.

`ls`까지 입력하고 `Tab` 키를 **두 번** 누른다.

```bash
ls
```

> `ls`, `lsblk`, `lscpu` 등 `ls`로 시작하는 명령 목록이 표시된다. 후보가 하나로 좁혀지지 않을 때는 이렇게 목록을 보여 준다.

**3단계.** 이전 명령을 불러온다.

키보드의 `↑`(위 화살표) 키를 여러 번 눌러 앞서 입력한 명령들이 차례로 나타나는 것을 확인한다. 원하는 명령이 나타나면 `Enter`로 다시 실행할 수 있다.

**4단계.** 화면을 정리한다.

```bash
clear
```

> 또는 `Ctrl + L`을 눌러도 동일하게 화면이 깨끗해진다. `clear`는 화면을 지우는 명령이다.

> **확인 사항** `Tab` 자동 완성으로 `history`를 완성해 보았고, `↑` 키로 이전 명령을 불러왔다면 성공이다.

# 제5절. 부팅 과정과 안전한 종료

---

## 5.1 부팅의 정의와 단계

**부팅(Booting)** 이란 컴퓨터의 전원을 인가한 시점부터 운영체제가 완전히 동작하여 로그인 화면이 출력될 때까지의 과정을 말한다. Ubuntu Desktop에서는 이 과정이 끝나면 문자 프롬프트가 아니라 **그래픽 로그인 화면**이 나타난다. 부팅은 다음 다섯 단계로 이루어진다.

![](/assets/img/posts/2026-09-08-linuxintro-week2-1-terminal-cli-1787465061653.png)



각 단계의 세부 동작은 다음과 같다.

| 단계 | 수행 내용 |
|---|---|
| **BIOS/UEFI** | ROM에 저장된 펌웨어. 전원을 켜면 가장 먼저 동작하여 메모리·키보드 등 하드웨어 상태를 점검한다. |
| **GRUB** | **GR**and **U**nified **B**ootloader. 커널 이미지를 메모리에 적재하고 제어권을 커널에 넘긴다. 여러 운영체제가 설치된 경우 선택 메뉴를 제공한다. |
| **커널(Kernel)** | CPU 레지스터 초기화, 메모리 관리 체계 구성, 장치 인식, 루트 파일 시스템 연결, 최초 프로세스 생성 |
| **systemd** | PID 1번 프로세스. 필요한 서비스를 병렬로 기동하고, 데스크톱에서는 그래픽 로그인 화면을 담당하는 서비스를 실행한다. |

> **용어 정리 — 데몬(Daemon)**
> 사용자와 직접 상호작용하지 않고 배경에서 지속적으로 실행되며 서비스를 제공하는 프로세스를 말한다. 명칭이 대부분 `d`로 끝나는 특징이 있다. 예를 들어 `systemd`는 시스템 관리를, 그래픽 로그인을 담당하는 `gdm`(GNOME Display Manager)은 로그인 화면 표시를 담당한다.
{: .prompt-info }

---

## 5.2 그래픽 로그인과 세션

부팅이 끝나면 사용자 이름과 비밀번호를 입력하는 그래픽 로그인 화면이 나타난다. 여기서 `student` 계정으로 로그인하면 GNOME 데스크톱 **세션(session)** 이 시작된다. 세션이란 로그인한 시점부터 로그아웃할 때까지 이어지는 하나의 작업 단위를 말한다.

> **[그림 2-2] 필요**
> Ubuntu Desktop의 그래픽 로그인 화면. 사용자 목록에 `student`가 표시되고 비밀번호 입력란이 보이는 스크린샷.
{: .prompt-tip }

Ubuntu Desktop은 그래픽 환경을 기본으로 제공하므로, systemd가 목표로 삼는 기본 상태는 그래픽 화면을 포함하는 `graphical.target`이다. 시스템이 텍스트 화면만 사용할지 그래픽 화면까지 사용할지를 정하는 이 목표 상태를 **타깃(Target)** 이라 한다.

| 타깃 | 설명 |
|---|---|
| `multi-user.target` | 텍스트 모드. 그래픽 화면 없이 여러 사용자가 접속 가능 |
| **`graphical.target`** | **텍스트 모드 + 그래픽 화면. Ubuntu Desktop 기본값** |

---

## 5.3 시스템 종료와 재부팅

데스크톱에서는 우측 상단 메뉴에서 마우스로 전원을 끌 수도 있으나, 터미널에서 명령으로 종료하는 방법도 반드시 익혀야 한다.

| 명령 | 약어 풀이 | 설명 |
|---|---|---|
| `sudo shutdown -h now` | **h**alt | 즉시 종료 |
| `sudo shutdown -r +10 "점검"` | **r**eboot | 10분 뒤 재부팅 및 접속자 통보 |
| `sudo shutdown -c` | **c**ancel | 예약된 종료 취소 |
| `sudo poweroff` | — | 즉시 전원 차단 |
| `sudo reboot` | — | 즉시 재부팅 |

> **유의 사항**
> 전원 버튼을 눌러 강제로 종료하면 메모리 버퍼에 남아 있던 데이터가 유실되고 파일 시스템이 손상될 수 있다. 반드시 위 명령 또는 데스크톱 메뉴의 정상 종료 기능을 사용하여야 한다.
{: .prompt-warning }

---

> ### 따라 하기 1-5. 예약 종료와 안전한 재부팅
>
> **목적** 예약 종료를 설정하고 취소하는 절차를 실습한 뒤, 가동 시간을 확인한다.
{: .prompt-tip }

**1단계.** 현재 가동 시간을 확인한다.

```bash
uptime
```

> `uptime`은 **up + time**으로, 시스템이 켜진 뒤 얼마나 동작하였는지를 출력한다.

**2단계.** 5분 뒤 재부팅을 예약한다.

```bash
sudo shutdown -r +5 "실습용 재부팅 예약"
```

> 접속 중인 사용자 전원에게 메시지가 전달된다. `-r`은 재부팅(**r**eboot)을, `+5`는 5분 뒤를 의미한다.

**3단계.** 예약을 취소한다.

```bash
sudo shutdown -c
```

> **반드시 취소하여야 한다.** 취소하지 않으면 5분 뒤 실제로 재부팅된다. `-c`는 취소(**c**ancel)를 의미한다.

> **확인 사항** 예약 종료가 정상적으로 취소되어 시스템이 계속 동작하고 있다면 성공이다. 실제 재부팅이 필요하면 `sudo reboot`을 사용한다.
{: .prompt-tip }

# 제6절. 종합 실습 — 나의 작업 환경 조사

## 단계 1. 작업 공간 준비

```bash
mkdir -p ~/lab02
```

> `mkdir`은 **m**a**k**e **dir**ectory(디렉터리를 생성하라)의 약어이며, `-p`는 **p**arents(상위 디렉터리까지 함께 생성)를 의미한다.

```bash
cd ~/lab02
```

> `cd`는 **c**hange **d**irectory(디렉터리를 변경하라)의 약어이다.

```bash
pwd
```

## 단계 2. 계정과 컴퓨터 정보 기록

```bash

```

> `>` 기호는 명령의 출력을 화면이 아닌 파일로 보내는 **리다이렉션(redirection)** 이다. 기존 내용이 있으면 삭제되고 새로 작성된다.

```bash
whoami >> env.txt
```

> `>>`는 기존 내용 뒤에 이어서 기록한다. `>`와 `>>`의 차이에 유의한다.

```bash
hostname >> env.txt
```

---

## 단계 3. 가동 시간과 커널 정보 기록

```bash
uptime >> env.txt
```

```bash
uname -a >> env.txt
```

> `uname`은 **u**nix **name**의 약어이고, `-a`는 **a**ll(전부)의 약어이다. 커널 이름·호스트 이름·커널 버전 등이 한 줄로 출력된다.

## 단계 4. 결과 확인

```bash
cat env.txt
```

> `cat`은 con**cat**enate(연결하다)의 약어로, 파일 내용을 화면에 출력한다.

```bash
wc -l env.txt
```

> `wc`는 **w**ord **c**ount의 약어이고 `-l`은 **l**ines(행 수)이다. 기록된 행 수를 확인한다.

> **종합 실습 완료 기준**
> `env.txt` 파일 하나에 로그인 계정, 컴퓨터 이름, 가동 시간, 커널 정보가 순서대로 기록되어 있으면 성공이다. 본 실습에서 사용한 명령은 `mkdir`, `cd`, `pwd`, `echo`, `whoami`, `hostname`, `uptime`, `uname`, `cat`, `wc`의 10개이다.

# 제7절. 자주 발생하는 오류와 대응 방법

---

| 화면에 출력된 메시지 | 원인 | 대응 방법 |
|---|---|---|
| `command not found` | 명령어 오타 또는 미설치 | 철자와 대소문자를 확인한다. `Tab` 자동 완성을 활용한다. |
| `Permission denied` | 권한 부족 | 명령 앞에 `sudo`를 붙인다. 상세한 원리는 이후 계정·권한 강의에서 다룬다. |
| 화면이 정지한 것처럼 보임 | 명령이 실행 중 | **`Ctrl + C`** 를 눌러 중단한다. |
| `:` 기호만 표시되고 진행되지 않음 | 페이지 표시 상태(`less`) | **`q`** 를 눌러 종료한다. |
| `sudo` 실행 시 비밀번호가 화면에 보이지 않음 | **정상 동작이다** | 보안을 위해 입력 내용을 표시하지 않는 것이므로 그대로 입력하고 `Enter`를 누른다. |
| 대문자로 입력한 명령이 동작하지 않음 | 리눅스는 대소문자를 구분함 | `LS`가 아니라 `ls`로 입력한다. |
