# 제1절. 가상 머신의 이해

---

## 1.1 실습 환경을 분리하는 이유

리눅스를 학습하는 과정에서는 시스템 설정을 변경하고, 계정을 생성·삭제하며, 파일 권한을 조작하는 작업을 반복적으로 수행한다. 이러한 작업을 평소 사용하는 개인용 컴퓨터에서 직접 수행할 경우 다음 두 가지 문제가 발생한다.

| 문제 | 내용 |
|---|---|
| **복구의 어려움** | 설정을 잘못 변경하면 운영체제가 정상적으로 동작하지 않을 수 있으며, 개인 자료가 손실될 위험이 있다. |
| **환경의 불일치** | 학습자마다 운영체제와 버전이 상이하여 교재의 화면 및 명령 결과와 일치하지 않는다. |

이러한 문제를 해결하기 위하여, 실제 컴퓨터 내부에 독립된 가상의 컴퓨터를 생성하고 그 안에서만 실습을 수행하는 방식을 채택한다. 이때 생성되는 가상의 컴퓨터를 **가상 머신(Virtual Machine, VM)** 이라 한다.

## 1.2 가상 머신의 구성 요소

| 용어 | 정의 | 본 과정에서의 대상 |
|---|---|---|
| **호스트(Host)** | 실제 물리 컴퓨터 | 학습자의 **윈도우 PC** |
| **게스트(Guest)** | 호스트 내부에 생성한 가상 컴퓨터 | **Ubuntu 24.04 데스크톱** |
| **하이퍼바이저(Hypervisor)** | 가상 머신을 생성하고 구동하는 소프트웨어 | **VirtualBox**(무료) |

```
 ┌─────────────────────────────────────────────────────┐
 │  호스트 : 물리 컴퓨터 (윈도우 PC)                      │
 │                                                     │
 │   ┌───────────────────────────────────────────┐     │
 │   │  하이퍼바이저 : VirtualBox                  │     │
 │   │                                           │     │
 │   │   ┌─────────────────┐                     │     │
 │   │   │  게스트          │                     │     │
 │   │   │  Ubuntu 24.04   │  (6주차에 Kali,     │     │
 │   │   │  데스크톱         │   Metasploitable2   │     │
 │   │   │  이름: ubuntu-y1 │   두 대를 추가한다) │     │
 │   │   └─────────────────┘                     │     │
 │   └───────────────────────────────────────────┘     │
 └─────────────────────────────────────────────────────┘
```

![](/assets/img/posts/2026-09-01-linuxintro-week1-2-lab-setup-ubuntu-1787460814471.png)

## 1.3 가상 머신의 이점

| 이점 | 설명 |
|---|---|
| **격리(Isolation)** | 게스트 내부에서 어떤 문제가 발생하더라도 호스트에는 영향을 미치지 않는다. |
| **환경의 동일성** | 모든 학습자가 동일한 운영체제와 버전을 사용하므로 교재의 내용과 실행 결과가 일치한다. |
| **스냅샷(Snapshot)** | 특정 시점의 상태를 그대로 저장해 두었다가, 문제가 발생하면 해당 시점으로 즉시 복원할 수 있다. |

> **가상 머신 이름에 관한 안내**
> 본 과정은 1학년 대상 과목이므로, 생성하는 모든 가상 머신의 이름 끝에 1학년을 뜻하는 표시 `-y1`(year 1)을 붙인다. 이번 시간에 만드는 Ubuntu 가상 머신의 이름은 `ubuntu-y1`이며, 이 이름은 시스템의 호스트 이름과 프롬프트에도 동일하게 나타난다.
{: .prompt-tip }

# 제2절. VirtualBox 설치

---

VirtualBox는 가상 머신을 생성하고 구동하는 무료 하이퍼바이저이다.

## 2.1 준비물 점검

작업을 시작하기 전에 다음 항목을 확인한다. 데스크톱 판은 그래픽 화면을 포함하므로 서버 판보다 더 많은 자원을 필요로 한다.

| 항목 | 요구 사항 | 비고 |
|---|---|---|
| 운영체제 | 윈도우 10 또는 11 | 호스트 |
| 메모리(RAM) | **8GB 이상** | 가상 머신에 4GB를 할당하려면 호스트에 8GB 이상이 필요하다 |
| 여유 디스크 공간 | **40GB 이상** | 6주차에 가상 머신 2대를 추가하므로 여유를 둔다 |
| 인터넷 연결 | 필수 | 설치 파일의 용량이 수 GB에 이른다 |

> ### 따라 하기 2-1. VirtualBox 내려받기와 설치
>
> **목적** 가상 머신을 구동할 하이퍼바이저를 설치한다.
{: .prompt-tip }

**1단계.** 웹 브라우저에서 [VirtualBox 공식 사이트](https://www.virtualbox.org/)에 접속하여 **[Download VirtualBox]** 를 선택한다.

**2단계.** **Windows hosts** 항목의 설치 파일(`.exe`)을 내려받는다.

**3단계.** 내려받은 파일을 실행하고 모든 항목을 기본값으로 두어 설치를 진행한다. 설치 도중 "네트워크 연결이 일시적으로 중단된다"는 안내가 표시되면 **Yes**를 선택하여 계속 진행한다. 가상 네트워크 드라이버를 설치하는 과정이다.

**4단계.** 설치가 완료되면 **VirtualBox 관리자(Manager)** 창이 실행된다. 이후 모든 가상 머신은 이 화면에서 관리한다.

> **확인 사항** VirtualBox 관리자 창이 정상적으로 실행되면 성공이다.
{: .prompt-tip }

> **가상화 기능이 비활성화된 경우**
> 일부 시스템은 CPU의 가상화 기능이 꺼져 있어 64비트 가상 머신을 실행하지 못한다. 이 경우 시스템 부팅 시 **BIOS 또는 UEFI 설정 화면**에 진입하여 **VT-x**(인텔) 또는 **SVM**(AMD) 항목을 **Enable**로 변경하여야 한다. 대부분의 시스템에서는 기본적으로 활성화되어 있다.
{: .prompt-warning }

# 제3절. Ubuntu Desktop 가상 머신 생성

---

## 3.1 설치 이미지(ISO) 내려받기

> ### 따라 하기 3-1. Ubuntu Desktop ISO 내려받기
>
> **목적** 설치에 사용할 운영체제 이미지 파일을 준비한다.
{: .prompt-tip }

**1단계.** [Ubuntu Desktop 다운로드 페이지](https://ubuntu.com/download/desktop)에 접속한다.

**2단계.** **Ubuntu 24.04 LTS** 항목의 ISO 파일을 내려받는다. 파일 이름은 `ubuntu-24.04.x-desktop-amd64.iso` 형태이며, 용량은 약 6GB이다.

> **서버 판이 아니라 데스크톱 판을 내려받는다.** 페이지 상단의 [Desktop]과 [Server] 구분을 반드시 확인한다. 데스크톱 판은 그래픽 화면을 포함한다.
{: .prompt-warning }

## 3.2 가상 머신 생성

> ### 따라 하기 3-2. 가상 머신 생성
>
> **목적** Ubuntu를 설치할 빈 가상 머신을 만든다.
{: .prompt-tip }

**1단계.** VirtualBox 관리자에서 **[새로 만들기(New)]** 를 선택한다.

**2단계.** 다음과 같이 설정한다. 이름에는 1학년을 뜻하는 `-y1`을 포함한다.

![](/assets/img/posts/2026-09-01-linuxintro-week1-2-lab-setup-ubuntu-1787461003201.png)

| 항목             | 설정값                  | 비고                      |
| -------------- | -------------------- | ----------------------- |
| 이름(Name)       | **`ubuntu-y1`**      | 프롬프트에 표시될 호스트 이름과 일치시킨다 |
| ISO 이미지        | 앞서 내려받은 `.iso` 파일 지정 |                         |
| 종류(Type)       | Linux                |                         |
| 버전(Version)    | Ubuntu (64-bit)      |                         |
| **자동 설치 건너뛰기** | **체크함**              | 설치 과정을 직접 진행하기 위함이다     |

![](/assets/img/posts/2026-09-01-linuxintro-week1-2-lab-setup-ubuntu-1787461044225.png)

**3단계.** 하드웨어 자원을 설정한다. 데스크톱 판은 그래픽 화면을 구동하므로 서버 판보다 넉넉히 할당한다.

| 항목       | 설정값           | 비고                     |
| -------- | ------------- | ---------------------- |
| 메모리(RAM) | **`4096` MB** | 최소 2048 MB, 권장 4096 MB |
| 프로세서     | **`2` CPU**   |                        |
![](/assets/img/posts/2026-09-01-linuxintro-week1-2-lab-setup-ubuntu-1787461080313.png)


**4단계.** 가상 디스크를 생성한다.

| 항목 | 설정값 |
|---|---|
| 디스크 크기 | **`25` GB** (동적 할당) |
![](/assets/img/posts/2026-09-01-linuxintro-week1-2-lab-setup-ubuntu-1787461092577.png)

**5단계.** **[만들기(Create)]** 를 선택하여 가상 머신을 생성한다.

**6단계.** (권장) 생성된 가상 머신을 선택하고 **[설정] → [디스플레이]** 로 이동하여 **비디오 메모리를 128 MB**로 상향한다. 그래픽 화면이 원활하게 동작한다.

> **[그림 1-3] 필요**
> VirtualBox 관리자에서 새 가상 머신을 만드는 마법사 화면. 이름 칸에 `ubuntu-y1`이 입력되어 있고 ISO 이미지가 지정된 상태의 스크린샷.
{: .prompt-tip }

# 제4절. Ubuntu Desktop 설치

---

가상 머신을 시작하면 설치 마법사가 그래픽 화면으로 실행된다. 화면의 안내에 따라 마우스로 진행한다.

> ### 따라 하기 4-1. 설치 마법사 진행
>
> **목적** 가상 머신에 Ubuntu 데스크톱을 설치한다.
{: .prompt-tip }

**1단계.** VirtualBox 관리자에서 `ubuntu-y1`을 선택하고 **[시작(Start)]** 을 누른다. (관리자 ID 입력에 대해서는 개인적 설정에 따라 다르다.)

**2단계.** 잠시 후 설치 화면이 나타난다. 주요 단계와 선택값은 다음과 같다.

| 설치 단계 | 선택값 | 근거 |
|---|---|---|
| 언어 | English 또는 한국어 | 오류 메시지 검색이 용이하도록 English를 권장한다 |
| 설치 방식 | **Install Ubuntu** | (Try Ubuntu가 아니라 설치를 선택) |
| 키보드 배열 | Korean 또는 기본값 | |
| 설치 유형 | **Interactive installation** | 직접 선택하며 진행한다 |
| 애플리케이션 | **Default selection**(기본) | |
| 추가 소프트웨어 | 기본값 유지 | |
| 디스크 설정 | **Erase disk and install Ubuntu** | 가상 디스크 전체를 사용한다. 실제 PC 디스크가 아니라 25GB 가상 디스크이므로 안전하다 |

> **"디스크를 지운다(Erase disk)"는 선택에 관한 안내**
> 이 선택은 **가상 머신의 25GB 가상 디스크**만을 대상으로 한다. 호스트인 윈도우 PC의 실제 디스크와 개인 자료에는 아무런 영향을 주지 않는다. 안심하고 선택한다.
{: .prompt-warning }

**3단계.** 계정 정보를 입력한다. 이 값들은 이후 모든 실습에서 사용하므로 정확히 입력한다.

| 항목                    | 입력값             | 비고                   |
| --------------------- | --------------- | -------------------- |
| 이름(Your name)         | `student`       |                      |
| 컴퓨터 이름(Computer name) | **`ubuntu-y1`** | 프롬프트에 표시되는 호스트 이름이다  |
| 사용자 이름(username)      | **`student`**   | 로그인 계정이다             |
| 비밀번호                  | 기억 가능한 값        | 실습용으로 `Linux#2026` 등 |

> **[그림 1-4] 필요**
> Ubuntu 설치 마법사의 계정 설정 화면. 이름 `student`, 컴퓨터 이름 `ubuntu-y1`, 사용자 이름 `student`가 입력된 스크린샷.
{: .prompt-tip }

**4단계.** 설치가 진행된다. 수 분에서 십수 분이 소요된다. 완료되면 **[Restart Now]** 를 선택한다.

**5단계.** 재시작 시 "설치 미디어를 제거하라(Please remove the installation medium)"는 안내가 표시되면, VirtualBox 메뉴의 **[장치] → [광학 드라이브] → [가상 드라이브에서 디스크 꺼내기]** 를 선택한 뒤 `Enter`를 누른다.

## 4.2 첫 로그인과 터미널 열기

**6단계.** 재부팅 후 로그인 화면에서 `student` 계정을 선택하고 비밀번호를 입력하여 로그인한다. GNOME 데스크톱 화면이 나타난다.

**7단계.** **터미널(Terminal)** 을 연다. 명령어는 이 터미널에 입력한다.

| 방법 | 조작 |
|---|---|
| 단축키 | `Ctrl` + `Alt` + `T` |
| 앱 목록 | 좌측 하단 **[Show Applications]** → `terminal` 검색 → 실행 |

터미널을 열면 다음과 같은 프롬프트가 표시된다.

```
student@ubuntu-y1:~$
```

> **[그림 1-5] 필요**
> GNOME 데스크톱에서 터미널 창이 열린 화면. 프롬프트 `student@ubuntu-y1:~$`가 보이는 스크린샷.
{: .prompt-tip }

> **프롬프트의 구성**
> `student`는 로그인한 사용자, `ubuntu-y1`은 컴퓨터의 호스트 이름, `~`는 현재 위치(사용자의 홈 디렉터리), `$`는 명령 입력을 기다린다는 표시이다. 명령어는 `$` 뒤에 입력한다.
{: .prompt-tip }

# 제5절. 스냅샷 생성

---

설치가 완료된 직후의 상태를 스냅샷으로 저장해 두어야 한다. 이후 실습 과정에서 시스템 설정을 손상시키더라도 재설치 없이 이 시점으로 복원할 수 있다.

> ### 따라 하기 5-1. 설치 직후 스냅샷 생성
>
> **목적** 깨끗한 설치 상태를 복원 지점으로 저장한다.
{: .prompt-tip }

**1단계.** 터미널에서 가상 머신을 안전하게 종료한다.

```bash
sudo poweroff
```

> `sudo`는 **s**uper**u**ser **do**의 약어로, 관리자 권한으로 명령을 실행한다. 비밀번호를 물으면 로그인 비밀번호를 입력한다. `poweroff`는 시스템을 안전하게 종료하는 명령이다.

**2단계.** VirtualBox 관리자에서 `ubuntu-y1`을 선택한다.

**3단계.** 오른쪽 상단 메뉴에서 **[스냅샷(Snapshots)] → [찍기(Take)]** 를 선택한다.

**4단계.** 이름을 `설치 직후`로 지정하고 확인한다.

> **확인 사항** 스냅샷 목록에 `설치 직후` 항목이 나타나면 성공이다. 이후 실습 중 시스템이 손상되면 이 스냅샷을 선택하고 **[복원(Restore)]** 하여 되돌릴 수 있다.
{: .prompt-tip }

# 제6절. 종합 실습 — 설치 점검과 세 계층 확인

---

지금까지 구축한 환경이 정상적인지 점검하고, 1주차-1에서 학습한 **커널·셸·응용 프로그램의 세 계층**을 실제 명령어로 확인한다. 가상 머신을 다시 시작하고 로그인한 뒤, 터미널을 열어 아래 단계를 순서대로 수행한다.

## 6.1 설치 결과 점검

**1단계.** 현재 로그인한 사용자를 확인한다.

```bash
whoami
```

> `whoami`는 "who am i(나는 누구인가)"에서 유래한 명령으로, 현재 사용자 이름을 출력한다. `student`가 출력되어야 한다.

**2단계.** 컴퓨터의 호스트 이름을 확인한다.

```bash
hostname
```

> `ubuntu-y1`이 출력되어야 한다. 프롬프트에 표시된 이름과 동일하다.

**3단계.** 배포판과 버전을 확인한다.

```bash
cat /etc/os-release
```

> `cat`은 con**cat**enate(연결하다)의 약어로, 파일 내용을 화면에 출력한다. 출력 중 `VERSION="24.04.x LTS (Noble Numbat)"` 항목을 확인한다.

## 6.2 세 계층 확인

**4단계.** **커널**의 버전을 확인한다.

```bash
uname -r
```

> `uname`은 **u**nix **name**의 약어이며, `-r`은 **r**elease(배포 번호)를 의미한다. `6.8.0-xx-generic`과 같은 형태로 출력되며, 이것이 현재 동작 중인 커널이다.

**5단계.** **셸**의 종류를 확인한다.

```bash
echo $SHELL
```

> `echo`는 문자열을 화면에 출력하는 명령이고, `$SHELL`은 로그인 셸의 경로를 담고 있는 변수이다. `/bin/bash`가 출력된다.

**6단계.** **응용 프로그램**의 실체를 확인한다.

```bash
which ls
```

> `which`는 해당 명령어의 실행 파일이 어디에 있는지 알려 준다. `/usr/bin/ls`가 출력되며, 이는 `ls`가 디스크에 존재하는 하나의 프로그램임을 의미한다.

## 6.3 완료 기준

다음 항목을 모두 확인하였다면 실습 환경 구축이 완료된 것이다.

```
 [ ] VirtualBox 관리자에 ubuntu-y1 가상 머신이 등록되어 있다.
 [ ] student 계정으로 로그인되며, 프롬프트가 student@ubuntu-y1:~$ 형태이다.
 [ ] cat /etc/os-release 결과에 24.04 LTS가 포함된다.
 [ ] uname -r 로 커널 버전이, echo $SHELL 로 /bin/bash 가 확인된다.
 [ ] 설치 직후 스냅샷이 생성되어 있다.
```

> 이로써 1주차-1에서 개념으로만 학습한 커널·셸·응용 프로그램의 세 계층을 실제 시스템에서 확인하였다. 커널은 `uname`으로, 셸은 `$SHELL` 변수로, 응용 프로그램은 `which`로 그 실체를 드러낸다.
{: .prompt-tip }

# 제7절. 자주 발생하는 오류와 대응 방법

---

| 증상                      | 원인               | 대응 방법                                                              |
| ----------------------- | ---------------- | ------------------------------------------------------------------ |
| 64비트 버전이 목록에 없음         | CPU 가상화 기능 비활성화  | BIOS/UEFI에서 VT-x 또는 SVM을 활성화한다.                                    |
| 가상 머신이 시작되지 않음          | 다른 가상화 소프트웨어와 충돌 | 윈도우 기능에서 Hyper-V를 비활성화한다.                                          |
| 설치 화면이 반복해서 나타남         | ISO가 제거되지 않음     | 저장소 설정에서 광학 드라이브를 비운다.                                             |
| 화면이 지나치게 작거나 크기 조정이 안 됨 | 게스트 확장 미설치       | VirtualBox 메뉴 **[장치] → [게스트 확장 CD 삽입]** 을 실행한 뒤 안내에 따라 설치하고 재부팅한다. |
| 마우스 커서가 가상 머신에 갇힘       | 마우스 통합 미설정       | 오른쪽 `Ctrl` 키를 누르면 호스트로 복귀한다.                                       |
| 설치 속도가 매우 느림            | 메모리 또는 CPU 할당 부족 | 설정에서 메모리를 4096 MB, 프로세서를 2개 이상으로 조정한다.                             |
| 비밀번호 입력 시 화면에 표시되지 않음   | **정상 동작**        | 보안상 입력 내용을 표시하지 않는다. 그대로 입력하고 `Enter`를 누른다.                        |

# 제8절. 요약 및 다음 강의

---

## 8.1 요약

| 구분 | 요점 |
|---|---|
| 가상 머신 | 호스트(윈도우 PC) 안에 하이퍼바이저(VirtualBox)로 생성한 가상 컴퓨터이다. |
| VirtualBox | 무료 하이퍼바이저이며, 기본값으로 설치한다. |
| Ubuntu Desktop | 본 과정의 실습 환경이다. 사용자 `student`, 호스트 이름 `ubuntu-y1`으로 설치한다. |
| 스냅샷 | 설치 직후 반드시 생성한다. 문제 발생 시 즉시 복원할 수 있다. |
| 세 계층 확인 | 커널은 `uname -r`, 셸은 `echo $SHELL`, 응용 프로그램은 `which`로 확인한다. |

## 8.2 학습한 명령어

| 명령어 | 약어 풀이 | 기능 |
|---|---|---|
| `whoami` | who am i | 현재 사용자 이름 출력 |
| `hostname` | host name | 컴퓨터 이름 출력 |
| `cat` | concatenate | 파일 내용 출력 |
| `uname -r` | unix name, release | 커널 버전 확인 |
| `echo` | echo | 문자열 출력 |
| `which` | which | 명령어의 실행 파일 위치 확인 |
| `sudo` | superuser do | 관리자 권한으로 명령 실행 |
| `poweroff` | power off | 시스템 안전 종료 |

## 8.3 다음 강의 예고

실습 환경이 완성되었다. 다음 주차 **2주차**에서는 이 환경에서 터미널을 본격적으로 사용한다. 명령행의 구조를 이해하고, 리눅스의 디렉터리 구조와 파일을 탐색하는 기본 명령어를 익힌다.
