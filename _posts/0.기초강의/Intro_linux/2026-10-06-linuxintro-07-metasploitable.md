# 제1절. Metasploitable 2의 이해와 안전 수칙

---

## 1.1 Metasploitable 2란

**Metasploitable 2**는 보안 학습을 위하여 **의도적으로 취약하게 구성한 리눅스 가상 머신 이미지**이다. 보안 도구 개발사가 교육 및 도구 검증 목적으로 무상 배포하고 있다.

| 항목 | 내용 |
|---|---|
| 기반 운영체제 | Ubuntu 8.04(32비트) |
| 배포 형식 | 가상 디스크 이미지(`.vmdk`)를 압축한 파일 |
| 기본 계정 | `msfadmin` / `msfadmin` |
| 용도 | 취약점 진단 실습, 보안 도구 검증, 보안 교육 |

이 시스템에는 다음과 같은 취약 요소가 **의도적으로** 포함되어 있다.

| 유형 | 구체적 내용 |
|---|---|
| 오래된 서비스 | 지원이 종료된 버전의 FTP·웹·데이터베이스 서비스가 다수 동작한다. |
| 평문 프로토콜 | Telnet, FTP 등 암호화되지 않은 서비스가 활성화되어 있다. |
| 취약한 계정 정책 | 추측하기 쉬운 비밀번호를 사용하는 계정이 다수 존재한다. |
| 과도한 권한 | 불필요한 SetUID 파일과 느슨한 파일 권한이 설정되어 있다. |
| 불필요한 서비스 개방 | 사용하지 않는 다수의 포트가 개방되어 있다. |

**본 과정에서는 이 시스템을 공격하지 않는다.** 제1강부터 제6강까지 학습한 조회·점검 명령만을 사용하여 "왜 이 시스템이 위험한가"를 확인하는 데 목적을 둔다.

---

## 1.2 반드시 준수하여야 할 안전 수칙

Metasploitable 2는 **보호 장치가 제거된 시스템**이다. 다음 수칙을 반드시 준수하여야 한다.

| 번호 | 수칙 | 근거 |
|---|---|---|
| **1** | **네트워크 연결 방식은 호스트 전용 어댑터만 사용한다.** | 물리 LAN이나 인터넷에 연결되면 외부에서 침해될 수 있다. |
| **2** | **NAT 어댑터를 설정하지 않는다.** | 인터넷에 노출되는 즉시 위험하며, 갱신이 불필요하므로 인터넷 연결 자체가 필요 없다. |
| **3** | **브리지 어댑터를 절대 사용하지 않는다.** | 공유기에 연결된 다른 기기에서 접근할 수 있게 된다. |
| **4** | 실습이 끝나면 가상 머신을 종료한다. | 불필요하게 구동 상태를 유지하지 않는다. |
| **5** | 이 시스템에 개인 자료를 저장하지 않는다. | 보호되지 않는 시스템이다. |
| **6** | 본인이 소유하거나 명시적으로 허가받은 시스템에만 점검을 수행한다. | 타인의 시스템을 무단으로 점검하는 행위는 법적 책임을 수반한다. |

> **가장 중요한 원칙**
> Metasploitable 2는 **격리된 호스트 전용 네트워크 안에서만** 사용한다. 이 원칙 하나만 지켜도 위험은 실습 환경 내부로 한정된다.
>
> 제0강에서 구성한 호스트 전용 어댑터가 바로 이 목적에 부합한다. 물리 LAN과 분리되어 있으므로 외부에서 접근할 수 없다.
{: .prompt-danger }

## 1.3 실습 환경의 최종 구성

Metasploitable 2를 추가하면 실습 환경은 다음과 같이 구성된다.

```
                  ┌──────────────────────────┐
                  │   윈도우 호스트            │
                  │   192.168.56.1           │
                  └────────────┬─────────────┘
                               │
     ┌─────────────────────────┴─────────────────────────┐
     │       호스트 전용 네트워크  192.168.56.0/24         │
     └──┬──────────────────┬──────────────────┬──────────┘
        │                  │                  │
 ┌──────┴──────┐   ┌───────┴───────┐   ┌──────┴────────────┐
 │ Ubuntu 24.04│   │ Kali Linux    │   │ Metasploitable 2  │
 │ 192.168.56  │   │ 192.168.56    │   │ 192.168.56.50     │
 │        .30  │   │        .10    │   │                   │
 │ NAT + 호스트 │   │ NAT + 호스트   │   │ 호스트 전용만!     │
 │ 전용         │   │ 전용(선택)     │   │ (인터넷 연결 금지)  │
 └─────────────┘   └───────────────┘   └───────────────────┘
        │                  │
        └────── NAT ───────┘
                ↓
            [ 인터넷 ]
```

**Metasploitable 2에만 NAT 어댑터가 없다는 점**에 유의한다. 이는 설정 누락이 아니라 의도된 구성이다.

| 시스템 | 주소 | 어댑터 1 | 어댑터 2 |
|---|---|---|---|
| Ubuntu Server 24.04 | `192.168.56.30` | NAT | 호스트 전용 |
| Kali Linux(선택) | `192.168.56.10` | NAT | 호스트 전용 |
| **Metasploitable 2** | **`192.168.56.50`** | **설정하지 않음** | **호스트 전용** |

# 제2절. 내려받기와 가상 머신 등록

---

## 2.1 이미지 내려받기

**1단계.** 배포처에서 Metasploitable 2 이미지를 내려받는다.

- 배포 페이지: [SourceForge — Metasploitable](https://sourceforge.net/projects/metasploitable/)

**2단계.** 압축 파일(통상 `metasploitable-linux-2.0.0.zip` 형태)을 내려받는다.

> 파일명과 용량은 배포 시점에 따라 다를 수 있다. 압축 해제 후 **`.vmdk` 확장자를 가진 가상 디스크 파일**이 존재하는지를 기준으로 판단한다.

**3단계.** 압축을 해제한다. 다음과 같은 파일이 생성된다.

| 파일 | 성격 |
|---|---|
| `Metasploitable.vmdk` | **가상 디스크 이미지(실제로 사용하는 파일)** |
| `Metasploitable.vmx` 등 | VMware용 설정 파일(VirtualBox에서는 사용하지 않음) |

**4단계.** 압축을 해제한 위치를 기록해 둔다. 다음 절에서 지정하여야 한다.

---

## 2.2 가상 머신 생성

Metasploitable 2는 운영체제를 설치하는 방식이 아니라, **이미 만들어진 가상 디스크를 연결하는 방식**으로 등록한다.

**1단계.** VirtualBox 관리자에서 **[새로 만들기(New)]** 를 선택한다.

**2단계.** 다음과 같이 설정한다.

| 항목 | 설정값 | 비고 |
|---|---|---|
| 이름 | `metasploitable2` | |
| 종류(Type) | Linux | |
| **버전(Version)** | **Ubuntu (32-bit)** | **32비트를 선택하여야 한다** |
| 메모리(RAM) | `512` MB | 구형 시스템이므로 충분하다 |
| 프로세서 | `1` CPU | |
| **하드 디스크** | **기존 가상 하드 디스크 파일 사용** | **새로 만들지 않는다** |

**3단계.** 하드 디스크 항목에서 **[기존 가상 하드 디스크 파일 사용]** 을 선택하고, 폴더 아이콘을 눌러 앞서 압축을 해제한 **`Metasploitable.vmdk`** 파일을 지정한다.

**4단계.** **[만들기(Create)]** 를 눌러 가상 머신을 생성한다.

> **32비트 항목이 표시되지 않는 경우**
> 버전 목록에 32비트 항목이 나타나지 않는다면, 호스트의 CPU 가상화 기능이 비활성화되어 있을 가능성이 있다. BIOS 또는 UEFI 설정에서 **VT-x** 또는 **SVM**을 활성화한다. 이 내용은 0-2 제1절에서 다루었다.
{: .prompt-warning }

---

## 2.3 네트워크 어댑터 설정

**이 단계가 본 부록에서 가장 중요한 설정이다.**

**1단계.** 생성한 가상 머신을 선택하고 **[설정] → [네트워크]** 로 이동한다.

**2단계.** **어댑터 1** 탭을 다음과 같이 설정한다.

| 항목 | 설정값 |
|---|---|
| 네트워크 어댑터 사용하기 | 체크 |
| 연결 방식 | **호스트 전용 어댑터** |
| 이름 | `VirtualBox Host-Only Ethernet Adapter` |

**3단계.** **어댑터 2** 이하는 **모두 사용하지 않음** 상태로 둔다.

> **Ubuntu·Kali와 구성이 다른 이유**
> Ubuntu와 Kali는 어댑터 1을 NAT로 설정하여 인터넷에 연결하였다. 패키지를 설치하고 갱신해야 하기 때문이다.
>
> 그러나 Metasploitable 2는 **갱신할 필요가 없고, 갱신해서도 안 되는 시스템**이다. 취약한 상태를 유지하는 것이 목적이기 때문이다. 따라서 인터넷 연결이 불필요하며, 연결할 경우 외부로부터 침해될 위험만 발생한다.
>
> **어댑터 1을 호스트 전용으로 설정하고, NAT는 사용하지 않는다.**
{: .prompt-danger }

## 2.4 첫 구동과 로그인

**1단계.** **[시작(Start)]** 을 눌러 가상 머신을 구동한다.

**2단계.** 부팅이 완료되면 로그인 프롬프트가 표시된다. 다음 계정으로 로그인한다.

| 항목 | 값 |
|---|---|
| 사용자 이름 | `msfadmin` |
| 비밀번호 | `msfadmin` |

> 비밀번호 입력 시 화면에 문자가 표시되지 않는 것은 정상 동작이다. 제1강 따라 하기 1-3에서 확인한 내용과 동일하다.

**3단계.** 로그인 후 프롬프트를 확인한다.

```
msfadmin@metasploitable:~$
```

> 제1강 2.1절에서 학습한 형식과 동일하다. `사용자명@호스트명:현재위치$` 구조이며, 마지막 기호가 `$`이므로 일반 사용자로 로그인한 상태이다.

**4단계.** 스냅샷을 생성한다.

가상 머신을 종료한 뒤 VirtualBox 관리자에서 **[스냅샷] → [찍기]** 를 선택하고 이름을 `초기 상태`로 지정한다.

```bash
sudo poweroff
```

# 제3절. 네트워크 설정과 접속

---

## 3.1 구형 리눅스의 네트워크 설정 방식

Metasploitable 2는 Ubuntu 8.04를 기반으로 하므로, **netplan이 존재하지 않는다.** 대신 데비안 계열의 전통적 방식인 **`/etc/network/interfaces`** 파일을 사용한다.

| 구분 | Ubuntu 24.04 | **Metasploitable 2(Ubuntu 8.04)** |
|---|---|---|
| 설정 도구 | netplan | **ifupdown** |
| 설정 파일 | `/etc/netplan/*.yaml` | **`/etc/network/interfaces`** |
| 파일 형식 | YAML | **키워드 나열 방식** |
| 적용 명령 | `netplan apply` | **`ifdown` / `ifup`** |

> **두 방식을 비교하는 것이 본 절의 학습 목적이다**
> 제6강 2.1절에서 구형 명령(`ifconfig`, `netstat`)과 신형 명령(`ip`, `ss`)의 대응 관계를 학습하였다. 설정 파일 역시 동일하게 세대 차이가 존재한다.
>
> 실무에서는 노후한 시스템을 인수하여 관리하게 되는 경우가 적지 않으므로, 구형 방식도 읽을 수 있어야 한다.
{: .prompt-tip }

---

## 3.2 현재 주소 확인

가상 머신을 다시 구동하고 로그인한 뒤 다음을 수행한다.

**1단계.** 인터페이스와 주소를 확인한다.

```bash
ifconfig
```

> Metasploitable 2에는 신형 `ip` 명령이 없거나 기능이 제한적이므로 구형 `ifconfig`를 사용한다. `eth0` 항목의 `inet addr` 값이 현재 주소이다.
>
> 호스트 전용 네트워크의 DHCP 서버가 동작 중이라면 `192.168.56.101` 이상의 주소를 자동으로 받았을 수 있다.

**2단계.** 라우팅 정보를 확인한다.

```bash
route -n
```

> 제6강에서 학습한 `ip route`에 대응하는 구형 명령이다.

---

## 3.3 고정 IP 설정

**1단계.** 설정 파일을 백업한다.

```bash
sudo cp /etc/network/interfaces /etc/network/interfaces.bak
```

> 비밀번호를 요구하면 `msfadmin`을 입력한다.

**2단계.** 설정 파일을 편집한다.

```bash
sudo nano /etc/network/interfaces
```

> `nano`는 제4강 4.2절에서 학습한 편집기이다. Metasploitable 2에도 설치되어 있다.

**3단계.** 파일 내용을 다음과 같이 수정한다.

```
auto lo
iface lo inet loopback

auto eth0
iface eth0 inet static
address 192.168.56.50
netmask 255.255.255.0
```

> 각 항목의 의미는 다음과 같다.
>
> | 항목 | 의미 |
> |---|---|
> | `auto eth0` | 부팅 시 자동으로 활성화한다. |
> | `iface eth0 inet static` | 주소를 **고정**으로 지정한다(`dhcp`가 아님). |
> | `address` | 지정할 IP 주소 |
> | `netmask` | 서브넷 마스크(`/24`에 해당) |
>
> **게이트웨이(`gateway`) 항목은 지정하지 않는다.** 이 시스템은 인터넷에 연결하지 않기 때문이다.

**4단계.** `Ctrl + O` → `Enter`로 저장하고 `Ctrl + X`로 종료한다.

**5단계.** 설정을 적용한다.

```bash
sudo /etc/init.d/networking restart
```

> 오류가 발생하면 다음 방법을 사용한다.

```bash
sudo ifdown eth0 && sudo ifup eth0
```

**6단계.** 적용 결과를 확인한다.

```bash
ifconfig eth0
```

> `inet addr:192.168.56.50`이 표시되면 성공이다.

## 3.4 접속 확인

**1단계.** Metasploitable 2에서 윈도우 호스트로의 통신을 확인한다.

```bash
ping -c 3 192.168.56.1
```

**2단계.** Ubuntu에서 Metasploitable 2로의 통신을 확인한다.

Ubuntu Server(`192.168.56.30`)에 접속하여 다음을 실행한다.

```bash
ping -c 3 192.168.56.50
```

**3단계.** 인터넷에 연결되지 **않는지** 확인한다.

Metasploitable 2에서 다음을 실행한다.

```bash
ping -c 3 8.8.8.8
```

> **응답이 오지 않아야 정상이다.** `Network is unreachable` 또는 응답 없음이 표시되면 의도한 대로 격리된 것이다.
>
> 만약 응답이 온다면 NAT 어댑터가 설정되어 있는 것이므로, 즉시 가상 머신을 종료하고 제2절 2.3을 다시 확인한다.

**4단계.** 윈도우 호스트에서 SSH로 접속한다.

윈도우 터미널에서 다음을 실행한다.

```
ssh msfadmin@192.168.56.50
```

> 최신 SSH 클라이언트는 구형 암호 알고리즘을 기본적으로 거부하므로 접속이 실패할 수 있다. 그 경우 다음과 같이 알고리즘을 명시적으로 허용한다.
>
> ```
> ssh -o KexAlgorithms=+diffie-hellman-group1-sha1 -o HostKeyAlgorithms=+ssh-rsa msfadmin@192.168.56.50
> ```
>
> **이 명령이 필요하다는 사실 자체가 학습 내용이다.** 이 시스템이 사용하는 암호 알고리즘이 현재 기준으로는 안전하지 않다고 판단되어 클라이언트가 거부한 것이다.

> **확인 사항** `192.168.56.50` 주소가 적용되고, 호스트 및 Ubuntu와는 통신되나 인터넷에는 연결되지 않으면 성공이다.

# 제4절. 학습 내용을 적용한 시스템 점검

---

본 절에서는 제1강부터 제6강까지 학습한 명령만을 사용하여 Metasploitable 2의 보안 상태를 점검한다. **동일한 명령을 Ubuntu Server에서도 실행하여 결과를 비교**하는 방식으로 진행한다.

---

> ### 따라 하기 7-1. 계정 상태 점검 (제3강 적용)
>
> **목적** 계정 파일을 조회하여 취약한 계정 구성을 식별한다.
{: .prompt-tip }

**1단계.** UID 0 계정을 확인한다.

```bash
awk -F: '$3 == 0 {print $1}' /etc/passwd
```

> 제3강 따라 하기 3-1에서 학습한 점검 항목이다. `root` 외의 계정이 표시된다면 즉시 확인이 필요하다.

**2단계.** 로그인 가능한 일반 계정을 조회한다.

```bash
awk -F: '$3 >= 1000 && $7 !~ /nologin|false/ {print $1, $3, $7}' /etc/passwd
```

> Ubuntu Server에서 동일한 명령을 실행한 결과와 비교한다. **Metasploitable 2에는 로그인 가능한 계정이 훨씬 많다.**

**3단계.** 전체 계정 수를 비교한다.

```bash
wc -l /etc/passwd
```

**4단계.** 비밀번호가 설정되지 않은 계정을 확인한다.

```bash
sudo awk -F: '($2 == "") {print "비밀번호 없음: " $1}' /etc/shadow
```

**5단계.** `/etc/shadow`의 권한을 확인한다.

```bash
ls -l /etc/passwd /etc/shadow
```

> 제3강 2.2절에서 학습한 대로 `/etc/shadow`는 root만 읽을 수 있어야 한다. 두 시스템의 권한을 비교한다.

> **점검 결과 정리**
>
> | 점검 항목 | Ubuntu 24.04 | Metasploitable 2 |
> |---|---|---|
> | UID 0 계정 수 | | |
> | 로그인 가능 계정 수 | | |
> | 비밀번호 없는 계정 | | |
>
> 위 표를 직접 채워 두 시스템을 비교한다.
{: .prompt-tip }

---

> ### 따라 하기 7-2. 파일 권한 점검 (제3강 적용)
>
> **목적** 과도한 권한이 부여된 파일을 탐지한다.
{: .prompt-tip }

**1단계.** SetUID가 설정된 파일을 조회한다.

```bash
sudo find / -perm -4000 -type f 2>/dev/null
```

> 제3강 6.2절에서 학습한 점검 명령이다. Ubuntu Server에서 동일하게 실행하여 **목록의 길이를 비교**한다.

**2단계.** 개수를 비교한다.

```bash
sudo find / -perm -4000 -type f 2>/dev/null | wc -l
```

> **Metasploitable 2 쪽이 현저히 많다.** 제3강에서 학습한 대로 SetUID 파일이 많을수록 권한 상승 경로가 늘어난다.

**3단계.** 누구나 쓸 수 있는 파일을 조회한다.

```bash
sudo find /etc -type f -perm -0002 2>/dev/null
```

> `/etc`의 설정 파일에 기타 사용자 쓰기 권한이 부여되어 있다면 심각한 문제이다. 임의의 사용자가 시스템 설정을 변경할 수 있기 때문이다.

**4단계.** 스티키 비트가 없는 공유 디렉터리를 확인한다.

```bash
ls -ld /tmp
```

> 제3강 6.1절에서 학습한 대로 `/tmp`에는 스티키 비트(`t`)가 설정되어 있어야 한다. `drwxrwxrwt`와 같이 마지막 문자가 `t`인지 확인한다.

> ### 따라 하기 7-3. 개방 포트와 서비스 점검 (제5강·제6강 적용)
>
> **목적** 불필요하게 개방된 서비스를 식별한다.
{: .prompt-tip }

**1단계.** 개방된 포트를 조회한다.

```bash
netstat -tuln
```

> Metasploitable 2에는 신형 `ss` 명령이 없으므로 구형 `netstat`을 사용한다. 제6강 2.1절의 대응표를 참고한다.

**2단계.** 개수를 확인한다.

```bash
netstat -tuln | grep LISTEN | wc -l
```

**3단계.** Ubuntu Server에서 동일한 점검을 수행한다.

```bash
ss -tuln | grep LISTEN | wc -l
```

> **두 시스템의 개방 포트 수 차이를 확인한다.** Ubuntu Server는 SSH 정도만 개방되어 있으나, Metasploitable 2는 수십 개의 포트가 개방되어 있다.

**4단계.** 어떤 서비스가 개방되어 있는지 확인한다.

```bash
netstat -tulnp 2>/dev/null | grep LISTEN | head -20
```

**5단계.** 개방된 포트 번호에 해당하는 서비스를 확인한다.

```bash
grep -E "^(ftp|telnet|smtp|http|microsoft-ds|mysql|postgresql)\s" /etc/services
```

> 제6강 1.2절에서 학습한 포트 번호와 대조한다. **평문으로 통신하는 Telnet(23번)과 FTP(21번)가 개방되어 있다는 점**에 주목한다.

**6단계.** 실행 중인 프로세스를 확인한다.

```bash
ps aux | head -20
```

```bash
ps aux | wc -l
```

> 제5강 1.4절에서 학습한 명령이다. 불필요한 데몬이 다수 동작하고 있음을 확인한다.

> **공격 표면(Attack Surface)의 개념**
> 개방된 포트 하나하나가 외부에서 접근할 수 있는 통로이다. 통로가 많을수록 그중 하나에 취약점이 존재할 가능성이 높아진다.
>
> 이것이 서버 구축 시 **"사용하지 않는 서비스는 중지하고, 필요한 포트만 개방한다"** 는 원칙을 적용하는 이유이다. 제5강의 `systemctl disable`과 제6강의 `ufw` 설정이 이 원칙을 구현하는 수단이다.
{: .prompt-warning }

# 제5절. 자주 발생하는 오류와 대응 방법

---

| 증상 | 원인 | 대응 방법 |
|---|---|---|
| 버전 목록에 32비트가 없음 | CPU 가상화 기능 비활성화 | BIOS/UEFI에서 VT-x 또는 SVM을 활성화한다. |
| 부팅 중 정지 | 디스크 파일 경로 오류 | `[설정] → [저장소]`에서 `.vmdk` 연결을 확인한다. |
| 로그인이 되지 않음 | 계정 정보 오입력 | `msfadmin` / `msfadmin`을 정확히 입력한다. 대소문자를 구분한다. |
| 주소가 적용되지 않음 | 설정 파일 오타 | `/etc/network/interfaces`의 항목명과 들여쓰기를 확인한다. |
| `networking restart` 실패 | 구형 스크립트의 제약 | `sudo ifdown eth0 && sudo ifup eth0`을 사용한다. |
| **인터넷에 연결됨** | **NAT 어댑터가 설정되어 있음** | **즉시 종료하고 어댑터 설정을 호스트 전용으로 변경한다.** |
| 호스트에서 SSH 접속 실패 | 구형 암호 알고리즘 거부 | `-o KexAlgorithms=+...` 옵션을 추가한다. |
| Ubuntu에서 `ping` 실패 | 서로 다른 호스트 전용 어댑터 선택 | 세 가상 머신이 동일한 어댑터를 사용하는지 확인한다. |
| 시스템이 손상됨 | 실습 중 설정 변경 | `초기 상태` 스냅샷으로 복원한다. |

|---|---|
| Metasploitable 2 | 보안 학습용으로 의도적으로 취약하게 구성한 Ubuntu 8.04 기반 가상 머신이다. 기본 계정은 `msfadmin`/`msfadmin`이다. |
| **격리 원칙** | **호스트 전용 어댑터만 사용하며, NAT와 브리지는 설정하지 않는다.** 인터넷 연결이 되지 않는 것이 정상이다. |
| 등록 방식 | 운영체제를 설치하지 않고 기존 `.vmdk` 디스크를 연결하여 등록한다. 버전은 **Ubuntu 32비트**를 선택한다. |
| 네트워크 설정 | netplan이 없으므로 `/etc/network/interfaces`를 편집하고 `ifdown`/`ifup`으로 적용한다. |
| 점검 방법 | 제1강~제6강에서 학습한 조회 명령만으로 계정·권한·포트·프로세스를 점검할 수 있다. |
| 결론 | 두 시스템의 차이는 기능이 아니라 **설정**에서 비롯된다. 보안은 기본 관리의 결과이다. |

## 7.2 구형 방식과 신형 방식의 대응

본 부록에서 확인한 세대별 차이를 정리하면 다음과 같다.

| 기능 | 구형(Metasploitable 2) | 신형(Ubuntu 24.04) |
|---|---|---|
| 주소 조회 | `ifconfig` | `ip addr` |
| 경로 조회 | `route -n` | `ip route` |
| 포트 조회 | `netstat -tuln` | `ss -tuln` |
| 네트워크 설정 | `/etc/network/interfaces` | `/etc/netplan/*.yaml` |
| 설정 적용 | `ifdown` / `ifup` | `netplan apply` |
| 서비스 관리 | `/etc/init.d/서비스` | `systemctl` |

## 7.3 다음 학습 방향

본 부록으로 리눅스 기초 과정의 모든 내용을 마쳤다.

여기서 구축한 세 대의 시스템(Ubuntu Server, Kali Linux, Metasploitable 2)은 후속 보안 과정의 실습 환경으로 그대로 사용된다. 후속 과정에서는 본 부록에서 **조회하는 데 그쳤던 취약점들을 실제로 진단하고 대응하는 방법**을 학습한다.

| 후속 학습 주제 | 본 과정과의 연결 |
|---|---|
| 서비스별 취약점 진단 | 제5강 서비스 관리, 본 부록 포트 점검 |
| 계정 및 권한 강화 | **제3강 계정 관리와 접근 권한** |
| 로그 분석과 침해 대응 | 제2강 `grep`·`tail`, 제5강 `journalctl` |
| 네트워크 접근 통제 | 제6강 `ufw`, 포트와 서비스 |

> **마무리**
> 리눅스 기초 과정에서 학습한 명령은 그 자체로는 단순한 조회 도구이다. 그러나 **무엇을 확인해야 하는지 알고 있을 때** 비로소 점검 도구가 된다.
>
> 본 부록에서 수행한 작업이 바로 그 사례이다. `find`, `awk`, `netstat`은 특별한 보안 도구가 아니지만, 이를 통해 시스템의 위험 요소를 식별할 수 있었다.
