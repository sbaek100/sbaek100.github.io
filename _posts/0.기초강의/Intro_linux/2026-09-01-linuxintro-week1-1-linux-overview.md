# 제1절. 운영체제와 리눅스의 이해

---

## 1.1 운영체제의 개념

컴퓨터는 중앙처리장치(CPU), 주기억장치(메모리), 보조기억장치(디스크), 입출력 장치로 구성된다. 이러한 하드웨어는 그 자체로는 아무런 작업도 수행하지 못하며, 이를 제어하고 자원을 배분하는 소프트웨어가 필요하다. 이 소프트웨어를 **운영체제(Operating System, OS)** 라 한다.

운영체제가 수행하는 주요 기능은 다음과 같다.

| 기능 | 설명 |
|---|---|
| 프로세스 관리 | 어떤 프로그램에 CPU를 얼마나 할당할 것인지 결정한다. |
| 메모리 관리 | 각 프로그램이 사용할 메모리 영역을 배정하고 보호한다. |
| 파일 시스템 관리 | 데이터를 파일 단위로 저장하고 검색할 수 있도록 한다. |
| 장치 관리 | 키보드·디스크·네트워크 카드 등을 프로그램이 사용할 수 있게 한다. |
| 사용자 인터페이스 제공 | 사용자가 명령을 내리고 결과를 확인할 수 있는 창구를 제공한다. |

윈도우(Windows), macOS, 리눅스(Linux)는 모두 이러한 기능을 수행하는 운영체제이다.

## 1.2 리눅스의 위치와 활용 범위

리눅스는 일반 사용자에게 다소 생소하게 느껴질 수 있으나, 실제로는 매우 광범위하게 사용되고 있다.

| 분야        | 구체적 사례                             |
| --------- | ---------------------------------- |
| 모바일       | 안드로이드 운영체제는 리눅스 커널을 기반으로 한다.       |
| 인터넷 서비스   | 대규모 웹 서비스의 서버 대부분이 리눅스로 운영된다.      |
| 네트워크 장비   | 가정용 공유기, 기업용 라우터의 내부 운영체제          |
| 임베디드 시스템  | 스마트 TV, 차량 인포테인먼트, 산업 제어 장치        |
| 고성능 컴퓨팅   | 세계 슈퍼컴퓨터 상위 500대 전부가 리눅스를 채택하고 있다. |
| 클라우드·컨테이너 | 클라우드 인스턴스와 컨테이너 기술의 기반 환경          |

따라서 정보기술 분야의 실무에서 리눅스는 선택 사항이 아니라 기본 소양에 해당한다.

## 1.3 윈도우와 리눅스의 비교

학습자 대부분이 윈도우에 익숙하므로, 두 운영체제의 차이를 먼저 정리한다.

| 비교 항목 | 윈도우 | 리눅스 |
|---|---|---|
| 라이선스 | 상용(유료) | 대부분 무료·오픈소스 |
| 소스 코드 | 비공개 | 공개 |
| 주된 조작 방식 | 그래픽 사용자 인터페이스(GUI) | 그래픽 인터페이스와 **명령행 인터페이스(CLI)** 를 모두 사용 |
| 저장 장치 표현 | `C:`, `D:` 등 드라이브 문자로 분리 | **`/`(루트)를 정점으로 하는 단일 트리** |
| 파일명 대소문자 | 구분하지 않음 | **구분함** |
| 관리자 계정 | Administrator | **root** |

> **유의 사항**
> 리눅스는 대소문자를 엄격히 구분한다. `Data.txt`와 `data.txt`는 서로 다른 파일이며, 명령어 역시 `ls`는 동작하지만 `LS`는 동작하지 않는다. 초심자가 가장 빈번하게 겪는 오류의 원인이므로 반드시 유의해야 한다.
{: .prompt-warning }

본 과정에서는 리눅스 배포판 가운데 **Ubuntu(우분투)** 의 **데스크톱(Desktop) 판**을 사용한다. 데스크톱 판은 윈도우와 유사한 그래픽 화면을 제공하므로, 처음 접하는 학습자가 마우스로 창을 조작하면서 동시에 명령행을 익히기에 적합하다.

# 제2절. 리눅스의 계층 구조

---

## 2.1 세 개의 계층

리눅스 시스템은 하드웨어를 중심으로 세 개의 계층이 겹겹이 감싸는 구조를 이룬다.

```
 ┌─────────────────────────────────────────────┐
 │  응용 프로그램                                │
 │  (웹 브라우저, 편집기, 터미널 등)               │
 ├─────────────────────────────────────────────┤
 │  셸(Shell)                                   │
 │  사용자의 명령을 해석하여 커널에 전달           │
 ├─────────────────────────────────────────────┤
 │  커널(Kernel)                                │
 │  프로세스·메모리·파일 시스템·장치 관리          │
 ├─────────────────────────────────────────────┤
 │  하드웨어 (CPU, 메모리, 디스크, 네트워크 카드)   │
 └─────────────────────────────────────────────┘
```

![](/assets/img/posts/2026-09-01-linuxintro-week1-1-linux-overview-1787460298788.png) 

각 계층의 역할은 다음과 같다.

| 계층 | 역할 | 비유 |
|---|---|---|
| **커널(Kernel)** | 하드웨어를 직접 제어하는 핵심부. 엄밀한 의미의 '리눅스'는 이 커널을 가리킨다. | 자동차의 엔진 |
| **셸(Shell)** | 사용자가 입력한 문자열을 해석하여 커널에 전달하는 명령 해석기 | 운전대와 페달 |
| **응용 프로그램** | 사용자가 실제로 이용하는 프로그램 | 오디오·공조 장치 |

셸(Shell)이라는 명칭은 '껍데기'를 뜻하며, 커널(Kernel, 알맹이)을 감싸고 있다는 데에서 유래하였다. 사용자는 커널에 직접 접근하지 못하고 반드시 셸을 거쳐야 하는데, 이러한 구조가 리눅스 보안의 출발점이 된다.

## 2.2 이 개념을 왜 먼저 배우는가

다음 시간에 실습 환경을 구축한 뒤, 가장 먼저 수행하는 작업이 바로 이 세 계층을 명령어로 확인하는 것이다. 예컨대 커널의 버전은 `uname -r`, 현재 사용 중인 셸은 `echo $SHELL`, 특정 응용 프로그램의 위치는 `which` 명령으로 확인한다. 지금은 각 계층의 이름과 역할만 기억해 두면 충분하다.

# 제3절. 리눅스의 역사와 라이선스

---

## 3.1 발전 과정

리눅스의 역사는 사실 딱딱한 연표보다 훨씬 흥미진진하다. 고장 난 프린터에 대한 분노에서 시작된 운동이 있었고, "그냥 취미로 만든 것"이라던 한 학생의 겸손한 예고가 완전히 빗나간 일도 있었다. 연표를 먼저 살펴본 뒤, 그 뒤에 숨은 이야기를 따라가 보자.


| 연도   | 사건                                    |
| ---- | ------------------------------------- |
| 1969 | 벨 연구소에서 **유닉스(UNIX)** 개발              |
| 1973 | 유닉스를 C 언어로 재작성하여 이식성 확보               |
| 1983 | 리처드 스톨만이 **GNU 프로젝트** 시작              |
| 1991 | 리누스 토르발스가 **리눅스 커널** 최초 공개            |
| 1992 | 리눅스 커널을 GPL로 배포하여 GNU 유틸리티와 결합        |
| 2004 | **우분투(Ubuntu)** 최초 배포                 |
| 2024 | **Ubuntu 24.04 LTS(Noble Numbat)** 배포 |

![ 리처드 스톨먼 ](/assets/img/posts/2026-09-01-linuxintro-week1-1-linux-overview-1787460476328.png)
[리쳐드 스톨먼 Wiki 자료](https://ko.wikipedia.org/wiki/%EB%A6%AC%EC%B2%98%EB%93%9C_%EC%8A%A4%ED%86%A8%EB%A8%BC)

> **일화 1. 프린터 때문에 시작된 자유 소프트웨어 운동**
> 1980년, MIT 인공지능 연구소는 새로 들여온 제록스(Xerox) 레이저 프린터 때문에 골머리를 앓고 있었다. 종이가 자주 걸렸는데, 프린터가 이를 알려주지 않아 사람들이 몇 시간씩 결과물을 기다리다 허탕을 치기 일쑤였다. 스톨만은 예전 프린터에서 했던 것처럼 소스 코드를 고쳐 알림 기능을 추가하려 했지만, 제록스는 소스 코드도 실행 파일도 내주지 않았다. 이 경험이 그를 "소프트웨어는 사용자가 자유롭게 고칠 수 있어야 한다"는 신념으로 이끌었고, 1983년 **GNU 프로젝트**로 이어졌다. GNU는 "GNU's Not Unix"의 약자로, 유닉스와 호환되면서도 완전히 자유로운 운영체제를 처음부터 새로 만들겠다는 선언이었다.
{: .prompt-tip }

[스톨만이 직접 쓴 "The GNU Project" — 프린터 일화 원문](https://www.gnu.org/gnu/thegnuproject.html)

> **일화 2. "그냥 취미로 만든 겁니다" — 세상에서 가장 겸손했던 예고**
> 1991년 8월 25일, 헬싱키 대학의 21세 학생 리누스 토르발스는 인터넷 뉴스그룹(comp.os.minix)에 짧은 글을 올렸다. "저는 (386, 486급의) AT 호환기기를 위한 취미용 운영체제를 만들고 있습니다. 4월부터 준비해왔고, 이제 슬슬 완성되어 가고 있어요. GNU처럼 크고 전문적이지는 않을 겁니다." 이 문장은 컴퓨터 역사상 가장 유명한 과소평가(understatement) 중 하나로 꼽힌다. 30여 년 뒤 이 '취미 프로젝트'는 안드로이드폰, 슈퍼컴퓨터, 클라우드 서버를 움직이는 커널이 되었다.
{: .prompt-tip }

![리누스토발즈](/assets/img/posts/2026-09-01-linuxintro-week1-1-linux-overview-1787473197856.png)
[리누스가 남긴 1991년 원본 게시글 모음 — comp.os.minix 아카이브](https://www.cs.cmu.edu/~awb/linux.history.html) · [영상: TED, 「Linus Torvalds: The mind behind Linux」](https://www.ted.com/talks/linus_torvalds_the_mind_behind_linux)

> **일화 3. 원래 이름은 "Freax"였다**
> 토르발스는 처음에 자신의 커널에 "Freax"(free + freak + x, 유닉스 계열 명칭 관행)라는 이름을 붙이려 했다. 정작 "Linux"라는 이름은 그가 커널 소스를 업로드할 FTP 서버를 관리하던 헬싱키 공대의 아리 렘케(Ari Lemmke)가, 토르발스의 뜻과 무관하게 서버 디렉터리 이름을 "linux"로 정해버리면서 굳어졌다. 본인이 이름 짓기를 망설이던 사이 관리자가 대신 정해준 이름이, 오늘날 전 세계가 부르는 이름이 된 셈이다.
{: .prompt-tip }

[리눅스 초기 역사 정리 — Wikipedia "History of Linux"](https://en.wikipedia.org/wiki/History_of_Linux)

> **일화 4. "리눅스는 한물간 설계다" — 타넨바움과의 설전**
> 1992년, 교육용 유닉스 계열 운영체제 미닉스(Minix)를 만든 네덜란드 교수 앤드루 타넨바움은 뉴스그룹에 "Linux is obsolete"(리눅스는 한물갔다)라는 제목의 글을 올려, 리눅스가 채택한 '모놀리식 커널' 구조(모놀리식 커널(Monolithic Kernel)은 운영체제의 핵심 기능을 하나의 거대한 공간(커널 영역)에 모아서 동작시키는 구조)를 1970년대식 낡은 설계라고 비판했다. 갓 스무 살을 넘긴 토르발스는 물러서지 않고 정면으로 반박했고, 이 논쟁은 소프트웨어 공학계에서 두고두고 회자되는 유명한 온라인 설전으로 남았다. 결과적으로 모놀리식 구조를 택한 리눅스는 이후 30여 년간 성능과 확장성을 모두 증명하며 이 논쟁에 스스로 답을 내놓았다.
{: .prompt-tip }

[Tanenbaum–Torvalds Debate 전문 정리](https://en.wikipedia.org/wiki/Tanenbaum%E2%80%93Torvalds_debate) · [O'Reilly 『Open Sources』 부록 A — 원문 이메일 전재](https://www.oreilly.com/openbook/opensources/book/appa.html)

> **일화 5. 펭귄 마스코트 턱스(Tux)의 탄생**
> 리눅스의 상징인 펭귄 캐릭터 '턱스(Tux)'는 토르발스가 호주 캔버라의 한 동물원에서 펭귄에게 물린(정확히는 다가갔다가 쫓긴) 뒤 펭귄에 애착을 갖게 되었다는 일화에서 비롯되었다는 설이 널리 알려져 있다. 이후 1996년 커널 개발자들의 투표를 거쳐 통통한 펭귄이 공식 마스코트로 확정되었다.
{: .prompt-tip }

![|423x433](/assets/img/posts/2026-09-01-linuxintro-week1-1-linux-overview-1787473352222.png)
[턱스(Tux) 마스코트 관련 정보 — Wikipedia](https://en.wikipedia.org/wiki/Tux_(mascot))

여기서 반드시 구분해야 할 개념이 있다. **유닉스는 상용 운영체제의 계보이고, 리눅스는 유닉스의 설계 철학과 인터페이스를 따르되 코드는 새로 작성한 독립적 구현**이다. 즉 리눅스는 유닉스의 후손이 아니라, 유닉스의 규격을 공유하는 별개의 운영체제이다.

또한 엄밀히 말하면 리눅스는 커널의 이름이며, 여기에 GNU 프로젝트가 제작한 유틸리티가 결합되어야 완전한 운영체제가 된다. 이 때문에 GNU 진영에서는 **GNU/Linux**라는 명칭을 권장한다. 실제로 스톨만이 만든 GNU 진영은 1990년대 초 자체 커널(GNU Hurd)을 개발하고 있었으나 완성이 계속 지연되었고, 그 공백을 토르발스의 리눅스 커널이 메우면서 'GNU 유틸리티 + 리눅스 커널'이라는 조합이 사실상 굳어졌다. 만약 Hurd가 예정대로 완성되었다면, 오늘날 우리가 쓰는 것은 전혀 다른 이름의 운영체제였을지도 모른다.

## 3.2 자유 소프트웨어와 GPL

자유 소프트웨어 재단은 사용자가 누려야 할 네 가지 자유를 정의하였다.

| 구분 | 내용 |
|---|---|
| 자유 0 | 목적을 불문하고 프로그램을 **실행**할 자유 |
| 자유 1 | 프로그램의 동작을 **연구하고 수정**할 자유 |
| 자유 2 | 복제본을 **재배포**할 자유 |
| 자유 3 | 수정한 판본을 **배포**할 자유 |

리눅스 커널이 채택한 **GPL(GNU General Public License)** 의 핵심은 **카피레프트(copyleft)** 이다. GPL 소프트웨어를 수정하여 배포하는 경우, 그 파생물 역시 GPL로 공개하여야 한다. 이 조항이 리눅스 생태계가 특정 기업에 독점되지 않고 발전할 수 있었던 제도적 기반이 되었다.

| 라이선스 | 카피레프트 강도 | 특징 |
|---|---|---|
| GPL | 강함 | 파생물도 반드시 동일 조건으로 공개 |
| LGPL | 약함 | 라이브러리 링크 시 독점 배포 허용 |
| BSD / MIT | 없음 | 저작권 표시만 유지하면 독점 소프트웨어에 포함 가능 |
| Apache 2.0 | 없음 | 특허 관련 조항을 명시 |

> **자주 출제되는 개념**
> GPL로 배포된 프로그램을 수정하여 **판매하는 것은 가능하다.** 다만 판매 시 소스 코드를 함께 제공하고 동일한 GPL 조건으로 배포해야 한다. GPL은 '무상'이 아니라 '자유'를 규정하는 라이선스이다.

# 제4절. 배포판의 이해

---

## 4.1 배포판이란

커널만으로는 시스템을 운영할 수 없으므로, 커널·유틸리티·패키지 관리자·설치 프로그램을 하나로 묶어 배포한다. 이를 **배포판(Distribution)** 이라 한다. 배포판의 계열은 **패키지 관리 방식**을 기준으로 구분한다.

| 계열 | 대표 배포판 | 패키지 형식 | 저수준 도구 | 고수준 도구 |
|---|---|---|---|---|
| **데비안 계열** | Debian, **Ubuntu**, Linux Mint, **Kali Linux** | `.deb` | `dpkg` | `apt` |
| **레드햇 계열** | RHEL, Rocky, Fedora | `.rpm` | `rpm` | `dnf`(구 `yum`) |
| 슬랙웨어 계열 | Slackware | `.tgz` | `pkgtool` | `slackpkg` |
| 기타 | Arch, openSUSE, Gentoo | 각기 다름 | `pacman`, `zypper` | — |

본 과정에서 사용하는 **Ubuntu**와, 마지막 주차에서 다루는 보안 점검용 배포판 **Kali Linux**는 모두 데비안 계열이다. 따라서 두 배포판은 동일한 패키지 관리 도구 `apt`를 사용하며, 명령어 체계가 대부분 같다.

## 4.2 버전 표기와 LTS

우분투의 버전 표기는 **배포 연도.월** 형식을 따른다. `24.04`는 2024년 4월에 배포되었음을 의미하며, 짝수 해 4월 판본은 **LTS(Long Term Support, 장기 지원)** 로 지정되어 5년간 표준 보안 갱신을 제공한다. 학습 도중 지원이 종료되어 환경을 다시 구축하는 상황을 피하기 위하여, 본 과정에서는 **Ubuntu 24.04 LTS** 판본을 사용한다.

## 4.3 데스크톱 판과 서버 판

Ubuntu는 용도에 따라 두 종류의 판본을 제공한다.

| 판본 | 특징 | 용도 |
|---|---|---|
| **데스크톱(Desktop) 판** | 그래픽 화면(GNOME)을 기본으로 제공한다. 마우스로 창을 조작할 수 있다. | 개인용 컴퓨터, 학습 환경 |
| 서버(Server) 판 | 그래픽 화면 없이 명령행만으로 동작한다. | 웹 서버, 데이터베이스 서버 등 |

본 과정은 리눅스를 처음 접하는 학습자를 대상으로 하므로, 익숙한 그래픽 화면과 명령행을 함께 사용할 수 있는 **데스크톱 판**을 선택한다. 실무 서버는 대부분 서버 판으로 운영되나, 명령어 자체는 두 판본이 동일하므로 데스크톱 판에서 학습한 내용을 서버 환경에 그대로 적용할 수 있다.
