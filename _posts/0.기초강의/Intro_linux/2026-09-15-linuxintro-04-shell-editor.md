# 제1절. 셸의 이해

---

## 1.1 셸의 역할

**셸(Shell)** 은 사용자가 입력한 문자열을 해석하여 커널에 전달하는 **명령 해석기(command interpreter)** 이다. 명칭은 '껍데기'를 뜻하며, 커널(Kernel, 알맹이)을 감싸고 있다는 점에서 유래하였다.

```
 사용자 입력  →  [ 셸 ]  →  커널  →  하드웨어
                   │
                   ├─ ① 명령·옵션·인자 분리
                   ├─ ② 확장 처리(와일드카드, 변수, 명령 치환)
                   ├─ ③ 입출력 방향 설정(리다이렉션·파이프)
                   ├─ ④ 프로그램 실행
                   └─ ⑤ 결과를 화면에 전달
```

셸의 역할은 단순한 전달에 그치지 않는다. 명령을 실행하기 **전에** 여러 가지 변환 작업을 수행한다.

| 셸이 수행하는 확장 | 예시 | 결과 |
|---|---|---|
| 와일드카드 확장 | `rm *.txt` | 실제 파일 목록으로 치환하여 `rm`에 전달 |
| 변수 치환 | `echo $HOME` | `echo /home/student` |
| 명령 치환 | `echo $(date)` | `date`를 실행하여 그 출력으로 치환 |
| 리다이렉션 설정 | `ls > list.txt` | 출력 방향을 파일로 변경 |
| 파이프 연결 | `ls \| grep txt` | 앞 명령의 출력을 뒤 명령의 입력으로 연결 |

> **셸의 확장 처리를 이해하면 설명되는 현상**
> `rm *.txt`에서 `*.txt`를 해석하는 주체는 `rm`이 아니라 **셸**이다. `rm`은 이미 확장이 완료된 파일명 목록만 전달받는다.
>
> 그러므로 조건에 맞는 파일이 하나도 없으면 셸이 확장하지 못하고 `*.txt`를 문자 그대로 전달하며, 그 결과 `rm: cannot remove '*.txt'`라는 오류가 발생한다.
{: .prompt-tip }

## 1.2 셸의 종류

| 셸 | 경로 | 특징 |
|---|---|---|
| sh (Bourne Shell) | `/bin/sh` | 최초의 표준 셸 |
| **bash** (Bourne Again Shell) | `/bin/bash` | **대부분의 배포판 기본 대화형 셸** |
| dash | `/bin/dash` | 경량·고속. 우분투의 시스템 스크립트 실행용 |
| csh / tcsh | `/bin/tcsh` | C 언어 유사 문법, 히스토리 기능 도입 |
| ksh (Korn Shell) | `/bin/ksh` | sh 호환성과 csh의 기능을 결합 |
| zsh (Z Shell) | `/bin/zsh` | 강력한 자동 완성. macOS 기본 셸 |

> **우분투의 `/bin/sh`**
> 우분투에서 `/bin/sh`는 bash가 아니라 **dash**로 연결되어 있다. 부팅 스크립트를 신속하게 실행하기 위한 선택이다.
>
> 이로 인해 `#!/bin/sh`로 시작하는 스크립트에서 bash 전용 문법을 사용하면 오류가 발생한다. bash의 기능이 필요하다면 반드시 **`#!/bin/bash`** 를 명시하여야 한다.
{: .prompt-warning }

## 1.3 로그인 셸의 확인

| 명령 | 조회 대상 |
|---|---|
| `echo $SHELL` | **로그인 셸**(`/etc/passwd`에 기록된 값) |
| `ps -p $$` | **현재 실행 중인** 셸 |
| `cat /etc/shells` | 로그인 셸로 허용된 경로 목록 |
| `chsh -s /bin/bash` | 로그인 셸 변경(**ch**ange **sh**ell) |

> **자주 출제되는 개념**
> `chsh`가 참조하는 파일은 **`/etc/shells`** 이다. 이 목록에 없는 경로는 로그인 셸로 지정할 수 없다.
>
> 또한 `$SHELL`은 로그인 셸을 담고 있을 뿐 현재 실행 중인 셸을 보장하지 않는다는 점도 자주 출제된다.
{: .prompt-warning }

> ### 따라 하기 4-1. 셸 확인과 전환
>
> **목적** 로그인 셸과 현재 셸을 구분하고, 셸을 중첩 실행하며 계층 구조를 관찰한다.
{: .prompt-tip }

**1단계.** 실습 디렉터리를 생성한다.

```bash
mkdir -p ~/lab04 && cd ~/lab04
```

**2단계.** 로그인 셸과 현재 셸을 비교한다.

```bash
echo $SHELL
```

```bash
ps -p $$
```

> `$$`는 현재 셸의 프로세스 번호를 담은 특수 변수이다.

**3단계.** 허용된 로그인 셸 목록을 확인한다.

```bash
cat /etc/shells
```

**4단계.** `/bin/sh`의 실체를 확인한다.

```bash
ls -l /bin/sh
```

> `/bin/sh -> dash`로 출력된다. 우분투가 부팅 성능을 위해 채택한 구성이다.

**5단계.** 다른 셸을 실행하여 차이를 확인한다.

```bash
echo $BASH_VERSION
```

> bash의 버전이 출력된다.

```bash
dash
```

```bash
echo $BASH_VERSION
```

> **아무것도 출력되지 않는다.** dash에는 해당 변수가 존재하지 않기 때문이다.

```bash
exit
```

```bash
echo $BASH_VERSION
```

> bash로 복귀하여 다시 출력된다.

**6단계.** 셸의 중첩 깊이를 확인한다.

```bash
echo $SHLVL
```

```bash
bash
```

```bash
echo $SHLVL
```

> 값이 1 증가한다. `SHLVL`은 **SH**ell **L**e**V**e**L**의 약어로 셸의 중첩 깊이를 의미한다.

```bash
exit
```

> **확인 사항** `$SHELL`과 `ps -p $$`의 차이를 설명할 수 있고, 셸 중첩 시 `SHLVL`이 증가하는 것을 확인하였다면 성공이다.
{: .prompt-tip }

# 제2절. 변수와 초기화 파일

---

## 2.1 변수의 정의와 사용

변수는 값을 담아 두는 저장 공간이다.

```bash
MYNAME="홍길동"        # 값을 저장할 때는 이름만 사용
echo $MYNAME           # 값을 꺼낼 때는 $ 를 붙임
```

> **초보자가 가장 빈번하게 범하는 오류**
> ```
> MYNAME = "홍길동"       ← 등호 앞뒤에 공백이 있음. 오류 발생
> MYNAME="홍길동"         ← 올바른 표기
> ```
> 공백을 넣으면 셸이 `MYNAME`을 **명령어**로 해석하여 `command not found` 오류를 출력한다.
{: .prompt-danger }

---

## 2.2 사용자 변수와 환경 변수

| 구분 | 정의 | 자식 프로세스 상속 | 조회 명령 |
|---|---|---|---|
| **사용자 변수** | 현재 셸에서만 유효 | **되지 않음** | `set` |
| **환경 변수** | `export`로 내보낸 변수 | **됨** | `env`, `printenv` |

```bash
MYVAR="hello"          # 사용자 변수 정의
export MYVAR           # 환경 변수로 승격
export PATH=$PATH:/opt/bin
unset MYVAR            # 변수 해제
```

---

## 2.3 주요 환경 변수

| 변수 | 의미 |
|---|---|
| **`PATH`** | **명령어를 탐색할 디렉터리 목록**(콜론으로 구분) |
| `HOME` | 홈 디렉터리 경로 |
| `USER`, `LOGNAME` | 로그인 사용자명 |
| `SHELL` | 로그인 셸 |
| `PWD`, `OLDPWD` | 현재 / 직전 작업 디렉터리 |
| **`PS1`** | 기본 프롬프트 문자열 |
| `PS2` | 명령이 다음 행으로 이어질 때의 프롬프트 |
| `LANG` | 언어·지역 설정 |
| `TERM` | 터미널 종류 |
| `HISTSIZE` | 메모리에 보관할 명령 이력 개수 |

## 2.4 `PATH`의 동작 원리와 보안

사용자가 `ls`를 입력하면 셸은 `PATH`에 나열된 디렉터리를 **앞에서부터 순서대로** 탐색하여 해당 이름의 실행 파일을 찾는다.

```bash
echo $PATH
```

```
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin:/usr/games:/usr/local/games:/snap/bin
```

이 기본값은 `/etc/environment`에 정의되어 있다. 여기에 더하여 `~/bin` 또는 `~/.local/bin` 디렉터리가 존재하면 `~/.profile`이 로그인 시 앞쪽에 추가하므로, 사용자마다 실제 값은 다를 수 있다.

`PATH`에 포함되지 않은 디렉터리의 프로그램은 경로를 직접 지정해야 실행된다. 스크립트를 실행할 때 `./script.sh`와 같이 `./`를 붙이는 이유가 여기에 있다.

> **`PATH`에 `.`을 포함해서는 안 되는 이유**
> `.`은 현재 디렉터리를 의미한다. 만약 `PATH`의 앞부분에 `.`이 포함되어 있으면, 임의의 디렉터리에서 `ls`를 입력했을 때 그 디렉터리에 있는 동명의 파일이 먼저 실행된다.
>
> 공격자가 `/tmp` 등에 `ls`라는 이름의 악성 프로그램을 배치해 두고 관리자가 해당 디렉터리에서 `ls`를 입력하기를 기다리는 공격이 실제로 존재한다. 따라서 `PATH`에 `.`을 포함하는 설정은 금지된다.
{: .prompt-danger }

## 2.5 프롬프트 설정 — `PS1`

| 기호 | 의미 | 기호 | 의미 |
|---|---|---|---|
| `\u` | 사용자명 | `\h` | 호스트명(짧게) |
| `\w` | 현재 디렉터리(전체 경로) | `\W` | 현재 디렉터리(마지막 요소) |
| `\$` | root면 `#`, 아니면 `$` | `\t` | 24시간 시각 |
| `\n` | 줄바꿈 | `\d` | 날짜 |

```bash
PS1='[\t] \u@\h:\w\$ '
```

## 2.6 셸 초기화 파일

터미널을 종료하면 설정한 변수와 별칭이 모두 소멸한다. 이를 영구히 유지하려면 **초기화 파일**에 기재하여야 한다.

셸이 시작될 때 읽는 파일은 **로그인 셸 여부**에 따라 달라진다.

| 구분 | 정의 | 예시 |
|---|---|---|
| **로그인 셸** | 인증 절차를 거쳐 시작된 셸 | 콘솔 로그인, SSH 접속, `su -` |
| **비로그인 셸** | 이미 인증된 상태에서 새로 연 셸 | 터미널 창 추가, `bash` 입력 |

**로그인 셸의 실행 순서**

```
 ① /etc/profile              시스템 전역 설정
      └ /etc/profile.d/*.sh   패키지별 설정 조각
 ② ~/.bash_profile → 없으면 ~/.bash_login → 없으면 ~/.profile
      └ 우분투의 ~/.profile 은 내부에서 ~/.bashrc 를 호출한다
 ③ (로그아웃 시) ~/.bash_logout
```

**비로그인 대화형 셸의 실행 순서**

```
 ① /etc/bash.bashrc          시스템 전역(데비안 계열)
 ② ~/.bashrc                 사용자 개인 설정
```

| 파일 | 성격 | 주 용도 |
|---|---|---|
| `/etc/profile` | 전역·로그인 | 시스템 공통 환경 변수 |
| `/etc/bash.bashrc` | 전역·대화형 | 시스템 공통 별칭·프롬프트 |
| `~/.profile` | 개인·로그인 | 개인 환경 변수 |
| **`~/.bashrc`** | **개인·대화형** | **별칭, 프롬프트, 셸 옵션** |
| `~/.bash_logout` | 개인·로그아웃 | 종료 시 정리 작업 |

> **실무상의 원칙**
> 별칭과 프롬프트는 `~/.bashrc`에, 환경 변수는 `~/.profile`에 기재한다. 우분투의 `~/.profile`이 `~/.bashrc`를 호출하므로 로그인 셸에서도 별칭이 적용된다.
>
> 수정 후 즉시 반영하려면 `source ~/.bashrc` 또는 `. ~/.bashrc`를 실행한다.
{: .prompt-tip }

## 2.7 별칭 — `alias`

```bash
alias                     # 정의된 별칭 목록 조회
alias ll='ls -alF'        # 별칭 정의
unalias ll                # 별칭 해제
\ls                       # 별칭을 무시하고 원본 명령 실행
```

> **별칭의 적용 범위**
> 별칭은 **대화형 셸에서만** 적용되며 셸 스크립트에서는 동작하지 않는다. 또한 정의한 셸에서만 유효하므로, 영구히 사용하려면 `~/.bashrc`에 기재하여야 한다.
{: .prompt-warning }

> ### 따라 하기 4-2. 변수와 초기화 파일
>
> **목적** 사용자 변수와 환경 변수의 상속 차이를 실험으로 확인하고, 개인 설정을 영구 적용한다.
{: .prompt-tip }

**1단계.** 사용자 변수를 정의한다.

```bash
MYVAR="사용자변수"
```

```bash
echo $MYVAR
```

**2단계.** 잘못된 정의 방식을 확인한다.

```bash
BADVAR = "공백있음"
```

> `command not found` 오류가 발생한다. 셸이 `BADVAR`를 명령어로 해석한 것이다.

**3단계.** 자식 셸로 상속되는지 확인한다.

```bash
bash -c 'echo "자식 셸에서 본 MYVAR = [$MYVAR]"'
```

> 값이 비어 있다. 사용자 변수는 자식 프로세스로 상속되지 않는다.

**4단계.** 환경 변수로 승격한 뒤 다시 확인한다.

```bash
export MYVAR
```

```bash
bash -c 'echo "자식 셸에서 본 MYVAR = [$MYVAR]"'
```

> 값이 전달된다. `export`가 그 경계를 결정한다.

```bash
env | grep MYVAR
```

**5단계.** `PATH`를 확인한다.

```bash
echo $PATH | tr ':' '\n'
```

> `tr ':' '\n'`은 콜론을 줄바꿈으로 치환하여 각 항목을 한 줄씩 출력한다. 목록에 `.`이 포함되어 있지 않은지 확인한다.

**6단계.** 개인 명령어 디렉터리를 `PATH`에 추가한다.

```bash
mkdir -p ~/bin
```

```bash
printf '#!/bin/bash\necho "개인 명령어가 실행되었습니다"\n' > ~/bin/mycmd
```

```bash
chmod +x ~/bin/mycmd
```

```bash
mycmd
```

> `command not found`가 발생한다. `PATH`에 `~/bin`이 없기 때문이다.

```bash
~/bin/mycmd
```

> 경로를 직접 지정하면 실행된다.

```bash
export PATH="$HOME/bin:$PATH"
```

```bash
mycmd
```

```bash
which mycmd
```

> 이제 경로 없이 실행된다.

**7단계.** 별칭을 정의하고 영구 적용한다.

```bash
cp ~/.bashrc ~/.bashrc.bak
```

> **설정 파일을 수정하기 전에 백업본을 만드는 것은 시스템 관리의 기본 수칙이다.**

```bash
alias ll='ls -alF'
```

```bash
ll ~/lab04
```

```bash
bash -c 'll'
```

> 자식 셸에서는 동작하지 않는다.

```bash
cat >> ~/.bashrc << 'EOF'

# ===== 리눅스 기초 4강 실습 설정 =====
alias ll='ls -alF'
alias lt='ls -lhtr'
alias ..='cd ..'
EOF
```

> 종료 표시를 `'EOF'`처럼 작은따옴표로 감싸면 내부의 `$` 등이 확장되지 않고 그대로 기록된다.

```bash
source ~/.bashrc
```

```bash
alias | tail -3
```

**8단계.** 초기화 파일의 실행 순서를 실험으로 확인한다.

```bash
echo 'echo "[bashrc 실행됨]"' >> ~/.bashrc
```

```bash
echo 'echo "[profile 실행됨]"' >> ~/.profile
```

```bash
bash
```

> `[bashrc 실행됨]`만 출력된다(비로그인 셸). `~/.profile`은 읽지 않기 때문이다.

```bash
exit
```

```bash
bash -l
```

> 이번에는 **두 행이 모두** 출력된다(로그인 셸). 다만 출력 순서에 주의한다.
>
> ```
> [bashrc 실행됨]
> [profile 실행됨]
> ```
>
> 로그인 셸이 읽는 파일은 `~/.profile`이지만, 우분투의 `~/.profile`은 **파일 앞부분에서 `~/.bashrc`를 먼저 호출**하도록 작성되어 있다. 앞서 추가한 두 행은 각 파일의 **끝**에 붙었으므로, `~/.profile`의 앞부분에서 호출된 `~/.bashrc`의 내용이 먼저 실행되고, 이어서 `~/.profile`의 마지막 행이 실행된다.
>
> 다음 명령으로 그 호출 지점을 직접 확인할 수 있다.

```bash
head -20 ~/.profile
```

> 12~17행에 `if [ -f "$HOME/.bashrc" ]; then . "$HOME/.bashrc"; fi` 구문이 있다. **"로그인 셸에서도 별칭이 적용되는 이유"** 가 바로 이 호출이다.

```bash
exit
```

**9단계.** 실험용 행을 제거한다.

```bash
sed -i '/실행됨/d' ~/.bashrc ~/.profile
```

```bash
tail -6 ~/.bashrc
```

> **확인 사항** `export` 전후로 자식 셸에서의 값이 달라지는 것을 확인하였고, 로그인 셸과 비로그인 셸의 초기화 파일 실행 순서를 설명할 수 있다면 성공이다.
{: .prompt-tip }

# 제3절. 입출력 제어와 파이프

---

## 3.1 표준 입출력의 개념

리눅스의 모든 프로세스는 세 개의 기본 통로를 갖는다.

| 명칭 | 파일 디스크립터 | 기본 연결 대상 |
|---|---|---|
| 표준 입력(stdin) | **0** | 키보드 |
| 표준 출력(stdout) | **1** | 화면 |
| 표준 오류(stderr) | **2** | 화면 |

프로그램은 정상적인 결과를 표준 출력으로, 오류 메시지를 표준 오류로 내보낸다. 두 경로가 분리되어 있기 때문에 **정상 결과만 저장하고 오류는 별도로 처리하는 것이 가능하다.**

---

## 3.2 리다이렉션

| 표기 | 동작 |
|---|---|
| `명령 > 파일` | 표준 출력을 파일로 **덮어쓰기** |
| `명령 >> 파일` | 표준 출력을 파일에 **이어 붙이기** |
| `명령 < 파일` | 파일을 표준 입력으로 사용 |
| `명령 2> 파일` | **표준 오류만** 파일로 |
| `명령 > 파일 2>&1` | 표준 출력과 표준 오류를 **모두** 같은 파일로 |
| `명령 &> 파일` | 위와 동일(bash 축약 표기) |
| `명령 2>/dev/null` | 오류 메시지를 폐기 |
| `명령 << EOF` | 여기 문서(here document) |

`/dev/null`은 기록된 모든 내용을 폐기하는 특수 장치이다. 불필요한 오류 메시지를 제거할 때 사용한다.

> **리다이렉션 처리 순서**
> `> 파일 2>&1`과 `2>&1 > 파일`은 결과가 다르다. 리다이렉션은 **왼쪽에서 오른쪽 순서로** 처리되므로, 후자는 표준 오류가 아직 화면을 가리키던 시점에 복제되어 오류가 화면에 남는다. 반드시 `2>&1`을 마지막에 배치하여야 한다.
{: .prompt-warning }

> **`>` 사용 시 유의 사항**
> `>`는 명령을 실행하기 **전에** 파일을 먼저 비운다. 따라서 다음과 같은 명령은 파일의 내용을 완전히 소실시킨다.
> ```
> cat important.txt > important.txt
> ```
{: .prompt-danger }

---

## 3.3 파이프와 필터

파이프(`|`)는 앞 명령의 표준 출력을 뒤 명령의 표준 입력으로 연결한다. 단순한 명령들을 조합하여 복잡한 처리를 수행할 수 있게 하는 유닉스 철학의 핵심 요소이다.

```bash
ps aux | grep nginx | grep -v grep
cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn
```

파이프와 함께 자주 사용하는 명령을 **필터(filter)** 라 한다.

| 필터 명령 | 기능 |
|---|---|
| `sort` | 정렬(`-n` 숫자, `-r` 역순) |
| `uniq` | 인접한 중복 제거(`-c` 개수 표시) |
| `wc` | 행·단어·문자 수 계산 |
| `head` / `tail` | 앞 / 뒤 일부 추출 |
| `cut` | 필드 추출(`-d` 구분자, `-f` 필드 번호) |
| `tr` | 문자 치환·삭제 |
| `sed` | 스트림 편집(치환·삭제) |
| `awk` | 필드 단위 처리·계산 |
| **`tee`** | **화면 출력과 파일 저장을 동시에 수행** |

`tee`는 배관의 T자 이음쇠에서 유래한 명칭으로, 데이터의 흐름을 두 방향으로 나눈다.

```bash
df -h | tee report.txt | grep "^/dev"
```

---

## 3.4 인용부호와 명령 치환

| 부호 | 명칭 | 동작 |
|---|---|---|
| `'...'` | 작은따옴표 | **모든 특수 의미를 제거**하고 문자 그대로 처리 |
| `"..."` | 큰따옴표 | `$`, `` ` ``, `\`만 해석하고 나머지는 그대로 |
| `$(...)` | 명령 치환 | 내부 명령을 실행하고 그 **출력으로 치환** |

```bash
NAME="Linux"
echo '$NAME'                 # 출력: $NAME
echo "$NAME"                 # 출력: Linux
echo "오늘은 $(date +%F)"     # 출력: 오늘은 2026-09-15
```

---

## 3.5 조건부 실행

| 기호 | 동작 |
|---|---|
| `;` | 앞 명령의 성공 여부와 무관하게 순차 실행 |
| `&&` | 앞 명령이 **성공했을 때만** 실행 |
| `\|\|` | 앞 명령이 **실패했을 때만** 실행 |

```bash
mkdir test && cd test              # 생성 성공 시에만 이동
ls file.txt || echo "파일 없음"     # 실패 시에만 메시지 출력
```

> ### 따라 하기 4-3. 리다이렉션과 파이프
>
> **목적** 표준 출력과 표준 오류를 분리하여 처리하고, 파이프로 명령을 연결한다.
{: .prompt-tip }

**1단계.** 표준 출력을 파일로 저장한다.

```bash
cd ~/lab04
```

```bash
ls -l /etc > etc_list.txt
```

```bash
wc -l etc_list.txt
```

```bash
date >> etc_list.txt
```

```bash
tail -3 etc_list.txt
```

**2단계.** 표준 출력과 표준 오류가 분리되어 있음을 확인한다.

```bash
ls /etc /없는디렉터리
```

> 결과와 오류가 모두 화면에 출력된다.

```bash
ls /etc /없는디렉터리 > out.txt
```

> **오류 메시지만 화면에 남는다.** `>`는 표준 출력(1번)만 처리하기 때문이다.

```bash
cat out.txt
```

> 오류 메시지는 파일에 포함되어 있지 않다.

**3단계.** 오류를 별도 파일로 저장한다.

```bash
ls /etc /없는디렉터리 > out.txt 2> err.txt
```

```bash
cat err.txt
```

**4단계.** 표준 출력과 표준 오류를 함께 저장한다.

```bash

```

```bash
tail -3 all.txt
```

**5단계.** 오류를 폐기한다.

```bash
ls /없는디렉터리 2>/dev/null
```

> 아무것도 출력되지 않는다.

**6단계.** 여기 문서로 여러 행의 파일을 생성한다.

```bash
cat > memo.txt << EOF
리눅스 기초 4강
셸과 편집기
여기 문서 실습
EOF
```

```bash
cat memo.txt
```

**7단계.** 파이프를 단계적으로 확장하며 결과를 관찰한다.

```bash

```

```bash
cut -d: -f7 /etc/passwd | sort | head -5
```

```bash
cut -d: -f7 /etc/passwd | sort | uniq -c
```

```bash
cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn
```

> 한 단계씩 추가하면서 결과의 변화를 관찰하는 것이 파이프를 이해하는 가장 효과적인 방법이다.
>
> 최종 결과는 "로그인 셸의 종류별 계정 수를 많은 순으로 정렬한 것"이며, `nologin` 계정이 압도적으로 많음을 확인할 수 있다.

**8단계.** `tee`로 화면과 파일에 동시에 출력한다.

```bash
df -h | tee disk.txt | grep "^/dev"
```

```bash
cat disk.txt
```

**9단계.** 인용부호와 명령 치환의 차이를 확인한다.

```bash
TODAY=$(date +%Y-%m-%d)
```

```bash
echo "오늘은 $TODAY 입니다"
```

```bash
echo '오늘은 $TODAY 입니다'
```

**10단계.** 조건부 실행을 확인한다.

```bash
ls memo.txt && echo "파일이 존재합니다"
```

```bash
ls 없는파일.txt || echo "파일이 존재하지 않습니다"
```

> **확인 사항** 표준 출력과 표준 오류를 각각 다른 파일로 분리할 수 있고, 파이프로 세 개 이상의 명령을 연결할 수 있다면 성공이다.

# 제4절. 텍스트 편집기

---

## 4.1 편집기의 종류

| 편집기 | 난이도 | 특징 |
|---|---|---|
| **nano** | 낮음 | 화면 하단에 단축키가 표시되어 초보자에게 적합 |
| **vi / vim** | 높음 | **거의 모든 유닉스 계열에 기본 탑재.** 모드 기반 |
| emacs | 높음 | 확장성이 매우 높은 통합 환경 |
| gedit / kate | 낮음 | 그래픽 환경 편집기 |

> **`vi`를 학습하여야 하는 이유**
> 서버 복구 모드나 최소 설치 환경에서는 `nano`가 설치되어 있지 않을 수 있으나, `vi`는 거의 항상 존재한다. 따라서 최소한의 조작(열기 → 수정 → 저장 → 종료)은 반드시 익혀 두어야 한다.
{: .prompt-info }

---

## 4.2 nano

```bash
nano 파일명
```

화면 하단에 단축키가 표시되며, `^` 기호는 `Ctrl` 키를 의미한다.

| 단축키 | 동작 |
|---|---|
| **`Ctrl + O`** | 저장(**O**ut. 파일명 확인 후 `Enter`) |
| **`Ctrl + X`** | 종료(e**X**it) |
| `Ctrl + W` | 검색(**W**here is) |
| `Ctrl + \` | 검색 후 치환 |
| `Ctrl + K` | 현재 행 잘라내기 |
| `Ctrl + U` | 붙여넣기 |
| `Ctrl + G` | 도움말 |

nano는 실행 즉시 문자를 입력할 수 있어 직관적이다.

---

## 4.3 vi의 세 가지 모드

`vi`가 어렵게 느껴지는 이유는 **모드(mode)** 개념 때문이다. vi에는 세 가지 상태가 존재하며, 각 상태에서 동일한 키가 서로 다르게 동작한다.

```
                     i, a, o 를 누르면
   ┌──────────────┐ ────────────────→ ┌──────────────┐
   │  명령 모드    │                    │  입력 모드    │
   │  (Command)   │ ←──────────────── │   (Insert)   │
   └──────┬───────┘    Esc 를 누르면    └──────────────┘
          │
          │  :  또는  /  를 누르면
          ↓
   ┌──────────────┐
   │  실행 모드    │   :w  :q  :wq  :%s  등
   │    (ex)      │
   └──────────────┘
```

> **vi를 사용할 때 반드시 기억할 사항**
> vi를 실행하면 처음에는 **명령 모드**이다. 이 상태에서 입력한 문자는 텍스트가 아니라 명령으로 해석되므로, 그대로 타자를 치면 예상하지 못한 동작이 발생한다.
>
> **문자를 입력하려면 `i`를 눌러 입력 모드로 전환하여야 하며, 상태를 알 수 없을 때는 `Esc`를 눌러 명령 모드로 복귀한다.**
{: .prompt-danger }

### 4.3.1 입력 모드 진입

| 키 | 동작 |
|---|---|
| **`i`** | 커서 앞부터 입력(**i**nsert) |
| `a` | 커서 뒤부터 입력(**a**ppend) |
| `o` | 아래에 새 행을 만들고 입력(**o**pen) |
| `I` / `A` / `O` | 행의 처음 / 행의 끝 / 위에 새 행 |

### 4.3.2 명령 모드 — 이동

| 키 | 동작 | 키 | 동작 |
|---|---|---|---|
| `h` `j` `k` `l` | 좌·하·상·우 | `0` | 행의 처음 |
| `$` | 행의 끝 | `w` / `b` | 다음 / 이전 단어 |
| `gg` | 문서 처음 | `G` | 문서 끝 |
| `5G` | 5번째 행으로 | `Ctrl+F` / `Ctrl+B` | 한 화면 아래 / 위 |

### 4.3.3 명령 모드 — 편집

| 키 | 동작 |
|---|---|
| `x` | 커서 위치의 문자 삭제 |
| **`dd`** | 현재 행 삭제(`3dd`는 세 행) |
| **`yy`** | 현재 행 복사(`3yy`는 세 행) |
| **`p`** | 붙여넣기 |
| **`u`** | 실행 취소(**u**ndo) |
| `Ctrl + R` | 다시 실행(redo) |
| `.` | 직전 명령 반복 |

### 4.3.4 실행 모드

| 명령 | 동작 |
|---|---|
| `:w` | 저장(**w**rite) |
| `:q` | 종료(**q**uit) |
| **`:wq`** 또는 `:x` | **저장 후 종료** |
| **`:q!`** | **저장하지 않고 강제 종료** |
| `:set nu` | 행 번호 표시(**nu**mber) |
| `/문자열` | 아래 방향 검색(`n`으로 다음) |
| `:s/옛것/새것/` | 현재 행의 첫 항목 치환 |
| `:s/옛것/새것/g` | 현재 행 전체 치환 |
| **`:%s/옛것/새것/g`** | **문서 전체 치환** |

> **자주 출제되는 개념**
> `:wq`(저장 후 종료)와 `:q!`(저장하지 않고 종료)의 구분, 그리고 `:%s/old/new/g`의 의미(`%`는 문서 전체, `g`는 각 행의 모든 항목)는 반복 출제된다.
{: .prompt-warning }

## 단계 3. vi로 스크립트 작성

```bash

```

`i`를 눌러 입력 모드로 전환한 뒤 다음을 작성하고, `Esc` → `:wq`로 저장한다.

```bash
#!/bin/bash
# 시스템 상태 종합 보고 스크립트
# 작성: 리눅스 기초 4강 종합 실습

OUT="$HOME/lab04/mission/report_$(date +%Y%m%d_%H%M).txt"

{
  echo "=========================================="
  echo "  시스템 상태 보고서"
  echo "  생성 시각: $(date '+%Y-%m-%d %H:%M:%S')"
  echo "  생성 계정: $(whoami)@$(hostname)"
  echo "=========================================="
  echo

  echo "[1] 로그인 가능한 일반 계정"
  awk -F: '$3 >= 1000 && $3 < 65534 && $7 !~ /nologin|false/ {print "  - " $1 " (UID " $3 ")"}' /etc/passwd
  echo

  echo "[2] 로그인 셸별 계정 수"
  cut -d: -f7 /etc/passwd | sort | uniq -c | sort -rn | sed 's/^/  /'
  echo

  echo "[3] 관리자 권한 보유 계정"
  grep "^sudo:" /etc/group | cut -d: -f4 | tr ',' '\n' | sed 's/^/  - /'
  echo

  echo "[4] 디스크 사용률"
  df -h | grep -E "^/dev" | awk '{print "  " $6 " : " $5 " 사용 (" $3 "/" $2 ")"}'
  echo

  echo "[5] 메모리 사용량"
  free -h | awk '/^Mem/ {print "  전체 " $2 " 중 " $3 " 사용"}'
  echo

  echo "[6] 현재 접속자"
  who | awk '{print "  - " $1 " (" $2 ")"}'
  echo

  echo "[7] 현재 umask"
  echo "  - $(umask)"
} > "$OUT" 2>&1

echo "보고서를 생성하였습니다: $OUT"
cat "$OUT"
```

> `{ ... } > "$OUT"` 구문은 중괄호 내부의 모든 출력을 한 번에 파일로 보낸다. 각 `echo`마다 `>>`를 붙이는 방식보다 간결하며 오류 가능성이 낮다.

# 제6절. 자주 발생하는 오류와 대응 방법

---

| 화면에 출력된 메시지 / 증상 | 원인 | 대응 방법 |
|---|---|---|
| `MYVAR: command not found` | 등호 앞뒤에 공백 | `MYVAR="값"`과 같이 공백 없이 작성한다. |
| 별칭이 적용되지 않음 | 새 셸에서는 소멸 | `~/.bashrc`에 기재하고 `source ~/.bashrc`를 실행한다. |
| vi에서 문자가 입력되지 않음 | 명령 모드 상태 | **`i`** 를 눌러 입력 모드로 전환한다. |
| vi에서 종료할 수 없음 | 모드를 알 수 없음 | **`Esc`** 를 누른 뒤 **`:q!`** 를 입력한다. |
| `./script.sh: not found` | 셔뱅이 없거나 잘못됨 | 첫 행에 `#!/bin/bash`를 기재한다. |
| 스크립트가 실행되지 않음 | 실행 권한 없음 | `chmod +x 파일` |
| `>` 사용 후 파일이 비워짐 | `>`는 실행 전 파일을 비움 | `>>`를 사용하거나 백업을 선행한다. |
| `PATH`에 추가했으나 적용 안 됨 | 설정을 반영하지 않음 | `source ~/.bashrc`를 실행한다. |

# 제8절. 요약

---

## 8.1 핵심 개념 정리

| 구분 | 요점 |
|---|---|
| 셸의 역할 | 명령을 해석할 뿐 아니라 와일드카드·변수·명령 치환을 확장하고 입출력 흐름을 제어한다. |
| 셸의 종류 | 우분투의 기본 대화형 셸은 bash이며, `/bin/sh`는 dash로 연결되어 있다. |
| 변수 | 사용자 변수는 현재 셸에만, 환경 변수는 자식 프로세스까지 전달된다. `export`가 그 경계를 결정한다. |
| `PATH` | 명령어를 탐색할 디렉터리 목록이며, `.`을 포함해서는 안 된다. |
| 초기화 파일 | 로그인 셸은 `/etc/profile` → `~/.profile`을 읽으며, 우분투의 `~/.profile`은 **앞부분에서 `~/.bashrc`를 호출**한다. 비로그인 셸은 `/etc/bash.bashrc` → `~/.bashrc`만 읽는다. |
| 표준 입출력 | stdin 0, stdout 1, stderr 2이며, `2>&1`은 리다이렉션 지정 뒤에 배치하여야 한다. |
| 파이프와 필터 | `sort`·`uniq`·`cut`·`grep`·`awk`·`tee`를 조합하면 별도 프로그램 없이 자료를 분석할 수 있다. |
| vi | 명령·입력·실행의 세 모드로 동작한다. 상태를 알 수 없으면 `Esc`, 저장은 `:wq`, 폐기는 `:q!`이다. |

## 8.2 본 강의에서 학습한 명령어와 기호

| 명령어 / 기호 | 기능 |
|---|---|
| `echo $SHELL` | 로그인 셸 확인 |

| `source` | 설정 파일 즉시 반영 |
| `>` / `>>` | 덮어쓰기 / 이어쓰기 |
| `2>` / `2>&1` | 오류만 / 오류도 함께 |
| `2>/dev/null` | 오류 폐기 |
| `\|` | 파이프 |
| `tee` | 화면 출력 + 파일 저장 |
| `sort` / `uniq` / `cut` / `tr` / `sed` / `awk` | 필터 명령 |
| `nano` | 초보자용 편집기 |
| `vi` | 표준 편집기 |
