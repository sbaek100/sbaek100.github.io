# 제1절. 네트워크 어댑터 구성

---

## 1.1 호스트 전용 어댑터의 존재 확인

호스트 전용 어댑터를 사용하려면 VirtualBox에 해당 어댑터가 먼저 생성되어 있어야 한다. VirtualBox 설치 시 자동으로 생성되는 경우가 많으나, 버전에 따라 직접 생성해야 할 수도 있다.

**1단계.** VirtualBox 관리자에서 **[파일] → [도구] → [네트워크 관리자]** 를 실행한다.

> VirtualBox 6.x 버전에서는 **[파일] → [호스트 네트워크 관리자]** 로 표기되어 있다.

**2단계.** **호스트 전용 네트워크** 탭을 선택한다.

**3단계.** 목록에 어댑터가 존재하는지 확인한다.

| 상황 | 조치 |
|---|---|
| `VirtualBox Host-Only Ethernet Adapter` 항목이 있다 | 다음 단계로 진행한다. |
| 목록이 비어 있다 | **[만들기(Create)]** 를 눌러 어댑터를 생성한다. |

**4단계.** 해당 어댑터를 선택하고 설정값을 확인한다.

| 항목 | 확인값 |
|---|---|
| IPv4 주소 | `192.168.56.1` |
| IPv4 넷마스크 | `255.255.255.0` |
| DHCP 서버 | 사용 여부는 무관 |

> **주소 대역에 관한 제약**
> VirtualBox는 호스트 전용 네트워크에 사용할 수 있는 주소 대역을 **`192.168.56.0/21`** 로 제한하고 있다. 이 범위를 벗어난 주소를 지정하면 어댑터가 정상적으로 동작하지 않는다.
>
> 본 과정이 `192.168.56.x`를 사용하는 이유가 여기에 있다. 또한 DHCP 서버가 자동으로 배정하는 범위(통상 `192.168.56.101` 이상)와 겹치지 않도록 `.10`과 `.30`을 선택하였다.
{: .prompt-warning }

---

## 1.2 가상 머신의 어댑터 설정

**가상 머신을 종료한 상태에서** 다음 절차를 수행한다. Kali를 함께 설치한 경우 양쪽 모두 동일하게 적용한다.

**1단계.** VirtualBox 관리자에서 대상 가상 머신을 선택하고 **[설정] → [네트워크]** 로 이동한다.

**2단계.** **어댑터 1** 탭을 다음과 같이 설정한다.

| 항목 | 설정값 |
|---|---|
| 네트워크 어댑터 사용하기 | 체크 |
| 연결 방식 | **NAT** |

> 어댑터 1은 인터넷 연결만 담당한다. NAT는 VirtualBox의 기본값이므로 별도 설정이 필요하지 않은 경우가 많다.

**3단계.** **어댑터 2** 탭을 다음과 같이 설정한다.

| 항목 | 설정값 |
|---|---|
| 네트워크 어댑터 사용하기 | 체크 |
| 연결 방식 | **호스트 전용 어댑터** |
| 이름 | `VirtualBox Host-Only Ethernet Adapter` |

> **두 가상 머신은 동일한 어댑터를 선택하여야 한다**
> Kali를 함께 설치한 경우, 두 가상 머신의 어댑터 2에서 **같은 이름의 호스트 전용 어댑터**를 선택하여야 서로 통신할 수 있다. 목록에 어댑터가 두 개 이상이면 서로 다른 것을 선택하지 않도록 유의한다.
{: .prompt-danger }

**4단계.** 설정을 저장하고 가상 머신을 시작한다.

# 제2절. Ubuntu 고정 IP 설정

---

## 2.1 netplan의 개념

Ubuntu는 **netplan**이라는 도구로 네트워크를 설정한다. 관리자가 YAML 형식의 설정 파일을 작성하면 netplan이 이를 실제 네트워크 설정으로 변환한다. 자세한 내용은 제6강 2.4절에서 다룬다.

| 항목 | 내용 |
|---|---|
| 설정 파일 위치 | `/etc/netplan/` |
| 파일 형식 | YAML(들여쓰기에 **공백만** 사용, 탭 문자 불가) |
| 문법 검사 명령 | `sudo netplan generate` |
| 적용 명령 | `sudo netplan apply` |
| 안전 적용 명령 | `sudo netplan try`(120초 내 확인이 없으면 자동 복원) |

본 과정의 설정 방침은 다음과 같다.

| 어댑터 | 인터페이스 | 주소 지정 방식 |
|---|---|---|
| 어댑터 1(NAT) | 첫 번째 인터페이스 | **DHCP 자동 할당** — 인터넷 연결 |
| 어댑터 2(호스트 전용) | 두 번째 인터페이스 | **고정 `192.168.56.30`** — 실습 통신 |

> **호스트 전용 어댑터에는 게이트웨이를 지정하지 않는다**
> 인터넷으로 나가는 경로는 어댑터 1(NAT)이 담당한다. 어댑터 2에 게이트웨이를 함께 지정하면 경로가 중복되어 인터넷 연결이 불안정해질 수 있으므로, **주소만 지정하고 게이트웨이는 비워 둔다.**
{: .prompt-warning }

---

## 2.2 인터페이스 이름 확인

설정에 앞서 두 개의 네트워크 인터페이스 이름을 확인한다.

```bash
ip -br link
```

> `ip`는 네트워크를 조회·설정하는 명령이고, `-br`은 **br**ief(간략 형식)의 약어이다.
>
> 출력에서 `lo`는 루프백이므로 제외하고, 나머지 두 개가 각각 어댑터 1(NAT)과 어댑터 2(호스트 전용)에 해당한다. `enp0s3`, `enp0s8`과 같은 형태로 표시된다.

```bash
ip -br addr
```

> 이 시점에서 첫 번째 인터페이스는 `10.0.2.x` 형태의 주소를 자동으로 받은 상태이고, 두 번째 인터페이스는 주소가 없는 상태이다. 두 번째 인터페이스에 고정 주소를 부여하는 것이 본 절의 목표이다.

---

## 2.3 고정 IP 설정

인터페이스 이름을 직접 입력하는 대신, 자동으로 찾아 설정하는 방식을 사용한다.

**1단계.** 인터페이스 이름을 변수에 저장한다.

```bash
IF_NAT=$(ls /sys/class/net | grep -v lo | sed -n '1p')
```

```bash
IF_LAB=$(ls /sys/class/net | grep -v lo | sed -n '2p')
```

```bash
echo "NAT용: $IF_NAT / 호스트 전용: $IF_LAB"
```

> `grep -v lo`는 루프백을 제외하고, `sed -n '1p'`는 첫 번째 행만 출력한다. 두 이름이 정상적으로 표시되는지 확인한 뒤 다음 단계로 진행한다.
>
> **두 번째 이름이 비어 있으면** 어댑터 2가 설정되지 않은 것이다. 가상 머신을 종료하고 제1절을 다시 수행한다.

**2단계.** 기존 설정 파일을 확인하고 백업한다.

```bash
ls -l /etc/netplan/
```

```bash
sudo cp -a /etc/netplan /root/netplan.backup
```

> **설정 파일을 변경하기 전에 백업본을 생성하는 것은 시스템 관리의 기본 수칙이다.** 문제가 발생하면 이 백업으로 복원할 수 있다.

**3단계.** 새 설정 파일을 작성한다.

```bash
sudo rm -f /etc/netplan/00-installer-config.yaml /etc/netplan/50-cloud-init.yaml
```

```bash
sudo tee /etc/netplan/99-lab.yaml > /dev/null <<EOF
network:
  version: 2
  ethernets:
    $IF_NAT:
      dhcp4: true
    $IF_LAB:
      dhcp4: false
      addresses: [192.168.56.30/24]
EOF
```

> 설정 파일의 내용은 다음을 의미한다.
>
> | 항목 | 의미 |
> |---|---|
> | `$IF_NAT: dhcp4: true` | 어댑터 1은 인터넷용이므로 주소를 자동으로 받는다. |
> | `$IF_LAB: dhcp4: false` | 어댑터 2는 자동 할당을 사용하지 않는다. |
> | `addresses: [192.168.56.30/24]` | 어댑터 2에 `.30` 주소를 고정으로 지정한다. |
>
> 어댑터 2에는 `routes`(게이트웨이) 항목이 없다. 인터넷 경로는 어댑터 1이 담당하기 때문이다.
>
> `<<EOF ... EOF` 구문은 여러 행의 내용을 한 번에 파일로 기록하는 방법이며, **여기 문서(here document)** 라 한다. 제4강 3.2절에서 다시 다룬다.

**4단계.** 파일 권한을 조정한다.

```bash
sudo chmod 600 /etc/netplan/99-lab.yaml
```

> Ubuntu 24.04는 netplan 설정 파일의 권한이 `600`이 아니면 경고를 출력한다.

**5단계.** 작성한 내용을 확인한다.

```bash
sudo cat /etc/netplan/99-lab.yaml
```

**6단계.** 문법을 검사한다.

```bash
sudo netplan generate
```

> 오류가 없으면 아무 메시지도 출력되지 않는다. 오류가 있으면 해당 위치를 알려 준다. **적용하지 않고 안전하게 검증할 수 있는 명령이다.**

**7단계.** 설정을 적용한다.

```bash
sudo netplan apply
```

**8단계.** 적용 결과를 확인한다.

```bash
ip -br addr
```

```bash
ip addr | grep 192.168.56.30
```

> `192.168.56.30`이 출력되면 고정 IP 주소가 정상적으로 지정된 것이다.

**9단계.** 기본 경로가 NAT 어댑터로 설정되었는지 확인한다.

```bash
ip route | grep default
```

> `default via 10.0.2.2 dev enp0s3`와 같이 출력된다. 인터넷으로 나가는 경로가 **어댑터 1(NAT)** 을 통하고 있음을 의미한다. 이것이 정상 상태이다.

> **확인 사항** `ip -br addr` 결과에서 인터페이스 두 개가 각각 `10.0.2.x`(자동)와 `192.168.56.30`(고정)을 보유하고, 기본 경로가 `10.0.2.2`를 향하고 있으면 성공이다.
{: .prompt-tip }

# 제3절. Kali 고정 IP 설정(선택)

---

> **Kali Linux를 설치하지 않은 경우 본 절을 건너뛰고 제4절로 이동한다.**
{: .prompt-warning }

Kali Linux는 NetworkManager를 사용하므로 `nmcli` 명령으로 설정한다.

**1단계.** 호스트 전용 인터페이스 이름을 확인한다.

```bash
IFACE2=$(ls /sys/class/net | grep -v lo | sed -n '2p')
```

```bash
echo "호스트 전용: $IFACE2"
```

**2단계.** 고정 IP 주소를 지정한 연결을 생성한다.

```bash
sudo nmcli con add type ethernet ifname "$IFACE2" con-name labnet ip4 192.168.56.10/24
```

> `nmcli`는 **N**etwork**M**anager **c**ommand **l**ine **i**nterface의 약어이다. 비밀번호를 요구하면 `kali`를 입력한다.
>
> `con-name labnet`은 이 연결 설정에 부여하는 이름이며, VirtualBox의 설정과는 무관하다.

**3단계.** 생성한 연결을 활성화한다.

```bash
sudo nmcli con up labnet
```

**4단계.** 적용 결과를 확인한다.

```bash
ip addr | grep 192.168.56.10
```

> `192.168.56.10`이 출력되면 성공이다.

# 제4절. 통신 확인과 호스트 접속

---

## 4.1 가상 머신에서의 확인

설정이 완료되면 **인터넷 연결**과 **실습망 통신**을 각각 확인한다. `ping`은 `Ctrl + C`로 중단할 수 있다.

**1단계.** 인터넷 연결을 확인한다.

```bash
ping -c 3 8.8.8.8
```

> `-c 3`은 세 번만 전송하라는 의미이다. 응답이 반환되면 NAT 어댑터가 정상적으로 동작하는 것이며, 이후 패키지 설치가 가능하다.

**2단계.** 이름 해석을 확인한다.

```bash
ping -c 3 archive.ubuntu.com
```

> 도메인 이름으로도 응답이 오면 DNS가 정상적으로 동작하는 것이다. IP 주소로는 되는데 도메인으로만 실패하면 DNS 문제이다. 이 진단 원리는 제6강 2.3절에서 상세히 다룬다.

**3단계.** 패키지 설치가 가능한지 확인한다.

```bash
sudo apt update
```

> 저장소 목록을 정상적으로 갱신하면 인터넷 연결이 완전히 확보된 것이다.

**4단계.** 윈도우 호스트와의 통신을 확인한다.

```bash
ping -c 3 192.168.56.1
```

> `192.168.56.1`은 윈도우 호스트에 부여된 실습망 주소이다. 응답이 오면 호스트 전용 어댑터가 정상적으로 동작하는 것이다.
>
> **응답이 없어도 설정 오류가 아닐 수 있다.** 윈도우 방화벽은 기본적으로 ICMP 에코 요청(`ping`)을 차단하므로, 어댑터가 정상이어도 `100% packet loss`가 표시되는 경우가 많다. 이 항목은 참고 지표로만 사용하고, **호스트 전용 어댑터의 정상 여부는 4.3절의 `ssh student@192.168.56.30` 접속 성공 여부로 최종 판정한다.**

**5단계.** Kali를 설치한 경우 가상 머신 간 통신을 확인한다.

```bash
ping -c 3 192.168.56.10
```

## 4.2 SSH 서비스 상태 확인

윈도우 호스트에서 접속하려면 Ubuntu에 SSH 서버가 동작하고 있어야 한다. 0-2에서 **OpenSSH server 설치** 항목을 선택하였다면 이미 동작 중이다.

```bash
systemctl is-active ssh.socket
```

> `active`가 출력되어야 한다.

```bash
systemctl is-active ssh
```

> **여기서는 `inactive`가 출력되는 것이 정상이다.** Ubuntu 22.10 이후의 OpenSSH는 **소켓 활성화(socket activation)** 방식을 사용한다. 평소에는 `ssh.socket`만 22번 포트를 지키고 있다가, 실제 접속이 들어오는 순간 `ssh.service`가 기동된다.
>
> 따라서 아직 한 번도 접속하지 않은 상태에서는 `ssh.service`가 `inactive`이며, 4.3절에서 윈도우 터미널로 접속한 뒤 다시 실행하면 `active`로 바뀐다. 서비스 전체의 상태는 다음 명령으로 한 번에 확인할 수 있다.

```bash
systemctl status ssh --no-pager | head -5
```

> `Triggers: ● ssh.socket` 또는 `TriggeredBy: ● ssh.socket` 표시가 있으면 소켓 활성화가 구성된 상태이다.

```bash
sudo ss -tlnp | grep :22
```

> 22번 포트에서 대기 중임을 확인한다. 소켓 활성화 방식이므로 포트를 점유한 프로세스는 `sshd`가 아니라 **`systemd`(PID 1)** 로 표시된다.

**만약 설치되어 있지 않다면** 다음 명령으로 설치한다.

```bash
sudo apt install -y openssh-server
```

```bash
sudo systemctl enable --now ssh
```

> `enable --now`는 자동 시작 등록과 즉시 실행을 동시에 수행한다. 제5강 3.2절에서 상세히 다룬다.

## 4.3 윈도우 호스트에서 SSH 접속

**이 절이 호스트 전용 어댑터를 사용하는 가장 큰 이유이다.** 이후 모든 실습을 윈도우의 터미널 프로그램에서 진행할 수 있다.

**1단계.** 윈도우에서 **터미널** 또는 **PowerShell**을 실행한다.

> 윈도우 10 이상에는 OpenSSH 클라이언트가 기본 포함되어 있다. 별도의 프로그램을 설치하지 않아도 된다.

**2단계.** 다음 명령으로 접속한다.

```
ssh student@192.168.56.30
```

**3단계.** 최초 접속 시 호스트 키 지문을 확인하는 메시지가 표시되면 `yes`를 입력한다.

**4단계.** 0-2에서 설정한 비밀번호를 입력한다.

**5단계.** 접속에 성공하면 다음과 같은 프롬프트가 표시된다.

```
student@ubuntu-lab:~$
```

> **이 방식의 이점**
>
> | 항목 | VirtualBox 콘솔 창 | **윈도우 터미널 접속** |
> |---|---|---|
> | 명령 복사·붙여넣기 | 제한적 | **자유롭게 가능** |
> | 지나간 출력 확인 | 어려움 | **스크롤로 확인 가능** |
> | 여러 세션 동시 사용 | 불가 | **탭으로 여러 개 사용** |
> | 화면 크기 조절 | 제한적 | **자유롭게 조절** |
>
> 교재의 명령을 그대로 복사해 붙여 넣을 수 있으므로 오타로 인한 오류가 크게 줄어든다. **제1강부터는 이 방식으로 실습할 것을 권장한다.**
{: .prompt-tip }


>
> `Ubuntu → 192.168.56.1`의 `ping`은 윈도우 방화벽 정책에 따라 실패할 수 있으므로 완료 기준에서 제외하였다. 마지막 항목인 **SSH 접속이 성공하면 호스트 전용 어댑터는 정상**이라고 판정한다.
>
> 이 시점에서 **스냅샷을 한 번 더 생성**해 둘 것을 권장한다. 이름은 `네트워크 설정 완료`로 지정한다.

# 제5절. 자주 발생하는 오류와 대응 방법

---

## 5.1 증상별 점검 항목

| 증상 | 원인 | 대응 방법 |
|---|---|---|
| 인터페이스가 하나만 표시됨 | 어댑터 2 미설정 | 가상 머신을 종료하고 제1절 1.2를 다시 수행한다. |
| `192.168.56.30`이 표시되지 않음 | 설정이 적용되지 않음 | `sudo netplan apply`를 다시 실행하고 오타를 확인한다. |
| 인터넷 연결이 되지 않음 | 어댑터 1 설정 오류 | 어댑터 1의 연결 방식이 **NAT**인지 확인한다. |
| 도메인만 응답하지 않음 | DNS 문제 | `resolvectl status`로 DNS 서버 설정을 확인한다. |
| **호스트에서 SSH 접속이 안 됨** | SSH 서버 미동작 | `systemctl is-active ssh.socket`으로 확인하고, 필요 시 `sudo systemctl enable --now ssh.socket`을 실행한다. |
| `systemctl is-active ssh`가 `inactive` | **정상 동작** | 소켓 활성화 방식이므로 접속 전에는 `inactive`이다. `ssh.socket`이 `active`이면 문제없다. |
| **VM → `ping 192.168.56.1` 실패** | 윈도우 방화벽의 ICMP 차단 | 설정 오류가 아닐 수 있다. `ssh student@192.168.56.30` 접속으로 판정한다. |
| **호스트에서 `ping 192.168.56.30` 실패** | 호스트 전용 어댑터 미생성 | 네트워크 관리자에서 어댑터가 존재하는지, 주소가 `192.168.56.1`인지 확인한다. |
| **접속은 되나 응답이 매우 느림** | 윈도우 방화벽 차단 | 호스트 전용 어댑터의 네트워크 프로필을 **개인 네트워크**로 변경한다. |
| 주소를 지정했으나 적용되지 않음 | 대역 제약 위반 | `192.168.56.0/21` 범위 내의 주소인지 확인한다. |
| `Permission denied` | 관리자 권한 부족 | 명령 앞에 `sudo`를 붙인다. |
| YAML 파싱 오류 | 탭 문자 사용 | **공백**으로 들여쓰기한다. 탭은 허용되지 않는다. |
| `netplan apply` 후 접속 단절 | 설정 오류 | 콘솔에서 `/root/netplan.backup`의 내용을 복원한다. |
| VM 간 `ping` 실패 | 서로 다른 어댑터 선택 | 두 가상 머신이 **동일한 호스트 전용 어댑터**를 선택했는지 확인한다. |

---

## 5.2 단계적 진단 방법

문제가 발생한 경우 다음 순서로 원인 구간을 좁혀 나간다.

```
 ① ping 127.0.0.1          실패 → 시스템 자체의 네트워크 스택 문제
          ↓ 성공
 ② ip -br addr             주소 없음 → netplan 설정 문제
          ↓ 주소 존재
 ③ ping 192.168.56.1       실패 → 호스트 전용 어댑터 설정 문제
          ↓ 성공
 ④ ping 8.8.8.8            실패 → 어댑터 1(NAT) 설정 문제
          ↓ 성공
 ⑤ ping 도메인              실패 → DNS 설정 문제
          ↓ 성공
 ⑥ 호스트에서 SSH 접속       실패 → SSH 서버 또는 방화벽 문제
```

> **복구가 어려운 경우**
> 위 절차로도 해결되지 않으면 **0-2에서 생성한 `설치 직후` 스냅샷으로 복원**한 뒤 제1절부터 다시 진행한다. 재설치보다 훨씬 신속하게 복구할 수 있다.
{: .prompt-warning }
