# 제1절. 가상 머신의 필요성과 구조

---

## 1.1 실습 환경을 분리하여야 하는 이유


![](/assets/img/posts/2026-08-18-linuxintro-00-1-lab-vm-theory-1786089547470.png)

리눅스를 학습하는 과정에서는 시스템 설정을 변경하고, 계정을 생성·삭제하며, 파일 권한을 조작하는 작업을 반복적으로 수행한다. 이러한 작업을 **평소 사용하는 개인용 컴퓨터에서 직접 수행할 경우** 다음 두 가지 문제가 발생한다.

| 문제 | 내용 |
|---|---|
| **복구의 어려움** | 설정을 잘못 변경하면 운영체제가 정상적으로 동작하지 않을 수 있으며, 개인 자료가 손실될 위험이 있다. |
| **환경의 불일치** | 학습자마다 운영체제와 버전이 상이하여 교재의 화면 및 명령 결과와 일치하지 않는다. |

이러한 문제를 해결하기 위하여, **실제 컴퓨터 내부에 독립된 가상의 컴퓨터를 생성하고 그 안에서만 실습을 수행하는** 방식을 채택한다. 이때 생성되는 가상의 컴퓨터를 **가상 머신(Virtual Machine, VM)** 이라 한다.

---

## 1.2 가상 머신의 정의와 구성 요소

**가상 머신**은 소프트웨어로 구현한 컴퓨터이다. 실제 컴퓨터와 마찬가지로 운영체제가 설치되고 부팅되며 네트워크에 연결되지만, 물리적 본체가 존재하지 않는다는 점이 다르다.

![](/assets/img/posts/2026-08-18-linuxintro-00-1-lab-vm-theory-1786089533848.png)

| 용어 | 정의 | 본 과정에서의 대상 |
|---|---|---|
| **호스트(Host)** | 실제 물리 컴퓨터 | 학습자의 **윈도우 PC** |
| **게스트(Guest)** | 호스트 내부에 생성한 가상 컴퓨터 | **Ubuntu Server 24.04** |
| **하이퍼바이저(Hypervisor)** | 가상 머신을 생성하고 구동하는 소프트웨어 | **VirtualBox**(무료) |

```
 ┌─────────────────────────────────────────────────────┐
 │  호스트 : 물리 컴퓨터 (윈도우 PC)                      │
 │                                                     │
 │   ┌───────────────────────────────────────────┐     │
 │   │  하이퍼바이저 : VirtualBox                  │     │
 │   │                                           │     │
 │   │   ┌─────────────────┐  ┌─────────────────┐│     │
 │   │   │  게스트 1        │  │  게스트 2        ││     │
 │   │   │  Ubuntu Server  │  │  Kali Linux     ││     │
 │   │   │  24.04 LTS      │  │  (선택 사항)     ││     │
 │   │   └─────────────────┘  └─────────────────┘│     │
 │   └───────────────────────────────────────────┘     │
 └─────────────────────────────────────────────────────┘
```

---

## 1.3 가상 머신의 이점

| 이점 | 설명 |
|---|---|
| **격리(Isolation)** | 게스트 내부에서 어떤 문제가 발생하더라도 호스트에는 영향을 미치지 않는다. 방음실 내부의 소음이 외부로 전달되지 않는 것과 같다. |
| **환경의 동일성** | 모든 학습자가 동일한 운영체제와 버전을 사용하므로 교재의 내용과 실행 결과가 일치한다. |
| **스냅샷(Snapshot)** | 특정 시점의 상태를 그대로 저장해 두었다가, 문제가 발생하면 해당 시점으로 즉시 복원할 수 있다. |

> **스냅샷의 중요성**
> 스냅샷은 실습 과정에서 가장 유용한 안전장치이다. 시스템 설정을 손상시킨 경우에도 재설치 없이 수 초 내에 복원할 수 있다.
>
> **설치 직후에 반드시 스냅샷을 생성해 둘 것을 권장한다.** 이 지침은 0-2에서 다시 다룬다.
{: .prompt-tip }

| 항목                    | 값                     |
| --------------------- | --------------------- |
| 호스트 이름                | `ubuntu-lab`          |
| 사용자 계정                | `student`             |
| **실습망 IP 주소(Ubuntu)** | **`192.168.56.30`**   |
| 실습망 IP 주소(Kali, 선택)   | `192.168.56.10`       |
| 윈도우 호스트의 실습망 주소       | `192.168.56.1`(자동 부여) |

> **`192.168.56` 대역을 사용하는 이유**

>
> 또한 VirtualBox가 자동으로 배정하는 주소 범위(통상 `192.168.56.101` 이상)와 겹치지 않도록 `.10`과 `.30`을 선택하였다.
{: .prompt-warning }

이 값을 적용하면 제1강에서 학습하는 프롬프트가 다음과 같이 표시된다.

```

```

# 제3절. 네트워크 기초 개념

---

가상 머신이 인터넷에 연결되고, 두 대를 구성한 경우 상호 통신이 가능하려면 네트워크의 최소한의 개념을 이해하여야 한다. 본 절의 내용은 제6강에서 상세히 다루므로, 여기서는 환경 구축에 필요한 범위만 다룬다.

---

## 3.1 IP 주소 — 시스템의 식별 주소

네트워크에서 각 시스템은 **IP 주소**라는 고유한 번호로 서로를 식별한다. 우편물의 수신 주소에 해당하는 개념이다.

```
 192.168.56.1    ← 윈도우 호스트   (자동 부여)
 192.168.56.10   ← Kali Linux     (선택)
 192.168.56.30   ← Ubuntu Server  (필수)
```

`192.168.x.x` 형식의 주소는 **사설(내부) 주소**로, 가정이나 조직의 내부 네트워크에서만 사용되며 인터넷 전체에 공개되지 않는다.

본 과정에서는 각 시스템에 주소를 **고정으로 지정**한다. 주소가 접속할 때마다 변경되면 상대 시스템을 지정하여 접속할 수 없기 때문이다.

---

## 3.2 서브넷 — 동일 네트워크의 조건

두 시스템이 직접 통신하려면 **동일한 네트워크에 속해야 한다.**

`192.168.56.10`과 `192.168.56.30`은 앞의 세 부분(`192.168.56`)이 동일하므로 같은 네트워크에 속하며, 따라서 상호 통신이 가능하다. 윈도우 호스트에 부여되는 `192.168.56.1` 역시 동일한 네트워크에 속하므로, 호스트에서도 두 가상 머신에 접근할 수 있다.

> **비유를 통한 이해**
> 동일한 아파트 단지(`192.168.56`) 내의 1001호(`.10`)와 1003호(`.30`)는 서로 왕래할 수 있다. 반면 다른 단지에 있다면 별도의 경로(게이트웨이)를 거쳐야 한다.
{: .prompt-tip }

---

## 3.3 VirtualBox의 네트워크 연결 방식

가상 머신의 네트워크 설정에서 가장 중요한 항목은 **연결 방식(Attached to)** 이다. VirtualBox는 여러 방식을 제공하며, 각 방식이 허용하는 통신 범위가 서로 다르다.

| 연결 방식 | VM ↔ VM | VM → 인터넷 | 호스트 → VM | 물리 LAN 노출 |
|---|---|---|---|---|
| **NAT** | **불가** | 가능 | 불가 | 없음 |
| NAT 네트워크 | 가능 | 가능 | 불가 | 없음 |
| 브리지 어댑터 | 가능 | 가능 | 가능 | **있음** |
| 내부 네트워크 | 가능 | 불가 | 불가 | 없음 |
| **호스트 전용 어댑터** | **가능** | 불가 | **가능** | 없음 |

> **가장 흔한 오해 — NAT로는 가상 머신끼리 통신할 수 없다**
> **NAT**는 가상 머신마다 **각각 독립된 주소 변환 장치를 하나씩** 부여한다. 따라서 두 가상 머신을 모두 NAT로 설정하면 각자 인터넷에는 접속할 수 있으나, **서로의 존재를 인식하지 못한다.** 두 시스템이 동일한 주소를 부여받는 경우도 있다.
>
> 이러한 이유로 가상 머신 간 통신에는 NAT가 아닌 **다른 연결 방식이 별도로 필요하다.**
{: .prompt-danger }

---

## 3.4 본 과정의 어댑터 구성

위 표를 근거로, 본 과정에서는 각 가상 머신에 **네트워크 어댑터를 두 개** 설정한다.

| 어댑터 | 연결 방식 | 용도 | 비유 |
|---|---|---|---|
| **어댑터 1** | **NAT** | 인터넷 연결(패키지 설치 및 갱신) | 외부로 통하는 현관 |
| **어댑터 2** | **호스트 전용 어댑터** | 실습 통신(VM 간 · 호스트 ↔ VM) | 단지 내부 전용 통로 |

```
                    ┌────────────────────────┐
                    │   윈도우 호스트          │
                    │   192.168.56.1         │
                    └───────────┬────────────┘
                                │  SSH 접속 가능
          ┌─────────────────────┴─────────────────────┐
          │        호스트 전용 네트워크 (어댑터 2)        │
          │            192.168.56.0/24                │
          └─────┬───────────────────────────────┬─────┘
                │                               │
    ┌───────────┴───────────┐       ┌───────────┴───────────┐
    │  Ubuntu Server        │       │  Kali Linux (선택)     │
    │  192.168.56.30        │←─────→│  192.168.56.10        │
    │                       │       │                       │
    │  어댑터 1 : NAT ───────┼──┐ ┌──┼─────── NAT : 어댑터 1  │
    └───────────────────────┘  │ │  └───────────────────────┘
                               │ │
                        ┌──────┴─┴──────┐
                        │    인터넷      │
                        └───────────────┘
```

| 연결 방식 | 본 구성에서의 역할 |
|---|---|
| **NAT**(어댑터 1) | 가상 머신이 호스트를 경유하여 인터넷에 접속할 수 있게 한다. 패키지 설치에 필수적이다. 주소는 자동으로 부여받는다. |
| **호스트 전용 어댑터**(어댑터 2) | 가상 머신 간 통신과 **윈도우 호스트에서 가상 머신으로의 접속**을 담당한다. 물리 LAN과 분리되어 있어 외부에 노출되지 않는다. 주소는 `192.168.56.x`로 고정 지정한다. |

> **어댑터를 두 개 설정하는 이유**
> NAT 어댑터만 설정하면 가상 머신끼리 통신할 수 없고 호스트에서 접속할 수도 없다. 반대로 호스트 전용 어댑터만 설정하면 인터넷에 접속하지 못하여 패키지를 설치할 수 없다.
>
> 따라서 **인터넷 연결용 1개와 실습 통신용 1개**를 함께 구성한다. Ubuntu 한 대만 설치하는 경우에도 어댑터 2를 함께 설정해 두어야 호스트에서 접속할 수 있다.
{: .prompt-warning }

---

## 3.5 호스트 전용 어댑터를 선택한 이유

가상 머신 간 통신만 놓고 보면 **내부 네트워크**와 **호스트 전용 어댑터** 모두 사용할 수 있다. 두 방식의 차이는 **윈도우 호스트에서 가상 머신에 접속할 수 있는가**이다.

| 항목 | 내부 네트워크 | **호스트 전용 어댑터** |
|---|---|---|
| VM 간 통신 | 가능 | 가능 |
| **호스트 → VM 접속** | **불가** | **가능** |
| 작업 방법 | VirtualBox 콘솔 창만 사용 | **윈도우 터미널·SSH 클라이언트 사용 가능** |

VirtualBox 콘솔 창은 복사·붙여넣기와 화면 스크롤이 제한적이어서, 교재의 명령을 그대로 옮겨 입력하기 어렵다. 호스트 전용 어댑터를 사용하면 윈도우의 터미널 프로그램으로 접속하여 **명령을 복사해 붙여 넣고, 지나간 출력을 자유롭게 되돌려 볼 수 있다.**

이는 실습의 효율에 큰 차이를 만들므로 본 과정에서는 호스트 전용 어댑터를 채택한다. 실제 접속 절차는 0-3 제4절에서 다룬다.

---

## 3.6 통신 확인 방법 — `ping`

설정을 완료한 뒤에는 **`ping`** 명령으로 상대 시스템의 응답 여부를 확인한다. `ping`은 대상에 신호를 전송하고 그 응답을 받는 명령이다.

```bash
ping -c 3 192.168.56.30
```

응답이 반환되면 두 시스템이 정상적으로 연결된 것이다. 실제 실행은 0-3에서 수행한다.

본 구성에서는 다음 세 방향의 통신을 각각 확인하게 된다.

| 확인 방향 | 사용하는 어댑터 | 확인 대상 |
|---|---|---|
| 가상 머신 → 인터넷 | 어댑터 1(NAT) | `8.8.8.8` |
| 윈도우 호스트 → 가상 머신 | 어댑터 2(호스트 전용) | `192.168.56.30` |
| 가상 머신 ↔ 가상 머신(선택) | 어댑터 2(호스트 전용) | `192.168.56.10` |

## 4.1 핵심 개념 정리

| 구분 | 요점 |
|---|---|
| 가상 머신 | 물리 컴퓨터(호스트) 내부에 소프트웨어로 구현한 컴퓨터(게스트)이다. |
| 하이퍼바이저 | 가상 머신을 생성·구동하는 소프트웨어이며, 본 과정에서는 VirtualBox를 사용한다. |
| 격리 | 게스트에서 발생한 문제가 호스트에 영향을 미치지 않는다. |
| 스냅샷 | 특정 시점의 상태를 저장하여 즉시 복원할 수 있다. 설치 직후 반드시 생성한다. |
| 구성 | 리눅스 기초 과정은 **Ubuntu Server 24.04 한 대**로 충분하며, Kali는 후속 보안 과정을 위한 선택 사항이다. |
| IP 주소 | 시스템을 식별하는 주소이며, 앞부분이 동일하여야 같은 네트워크로 인정되어 통신이 가능하다. |
| 연결 방식 | **NAT로는 가상 머신끼리 통신할 수 없다.** 가상 머신마다 독립된 주소 변환 장치가 부여되기 때문이다. |
| 어댑터 구성 | 어댑터 1은 **NAT**(인터넷), 어댑터 2는 **호스트 전용 어댑터**(실습 통신)로 설정한다. |
| 호스트 전용 어댑터의 이점 | 가상 머신 간 통신뿐 아니라 **윈도우 호스트에서 가상 머신으로 접속**할 수 있어, 터미널 프로그램으로 실습을 진행할 수 있다. |
| 주소 대역 | VirtualBox의 제약에 따라 `192.168.56.0/21` 범위 내에서 지정한다. |
| 통신 확인 | `ping` 명령으로 상대 시스템의 응답 여부를 점검한다. |

## 4.2 최종 구성도

```
 ┌─────────────────────────────────────────────────────────────┐
 │  호스트 : 윈도우 PC          호스트 전용 주소 192.168.56.1     │
 │                                    │                        │
 │   ┌────────────────────────────────┼───────────────────┐    │
 │   │  VirtualBox                    │                   │    │
 │   │                                │                   │    │
 │   │   ┌────────────────────────────┴──────────────┐    │    │
 │   │   │   호스트 전용 네트워크 192.168.56.0/24      │    │    │
 │   │   └────┬──────────────────────────────┬───────┘    │    │
 │   │        │                              │            │    │
 │   │   Ubuntu Server 24.04          Kali Linux          │    │
 │   │   192.168.56.30      ←──────→  192.168.56.10       │    │
 │   │   (student@ubuntu-lab)         (선택 사항)          │    │
 │   │        │                              │            │    │
 │   └────────┼──────────────────────────────┼────────────┘    │
 │            │        어댑터 1 : NAT         │                 │
 └────────────┼──────────────────────────────┼─────────────────┘
              └───────────────┬──────────────┘
                              ↓
                          [ 인터넷 ]
```

이 환경을 한 번 구축하면, 제1강부터 제6강까지의 모든 실습을 동일한 환경에서 수행할 수 있다.

또한 윈도우 호스트가 `192.168.56.1` 주소로 실습망에 참여하므로, **윈도우의 터미널 프로그램에서 `ssh student@192.168.56.30` 명령으로 가상 머신에 접속하여 실습을 진행할 수 있다.**
