> **학습 목표**
> 1. 2주차에 학습한 명령어를 실제 상황과 유사한 시나리오 속에서 스스로 선택하여 사용할 수 있다.
> 2. 프롬프트·계정·호스트·가동 시간 등 시스템의 기본 정보를 명령어로 조사할 수 있다.
> 3. 절대 경로와 상대 경로를 상황에 맞게 골라 파일 트리를 이동할 수 있다.
> 4. 디렉터리와 파일을 생성하고 와일드카드로 원하는 파일만 골라낼 수 있다.
> 5. 조사한 내용을 리다이렉션으로 하나의 보고서 파일에 정리할 수 있다.
{: .prompt-info }

본 강의는 2주차-1(터미널과 명령행)과 2주차-2(디렉터리 구조와 파일 탐색)에서 학습한 내용만으로 구성된 **종합 실습**이다. 새로운 명령어는 등장하지 않으며, 이미 배운 명령어를 **시나리오 속에서 스스로 선택하여 사용하는 능력**을 기르는 데 목적이 있다.

실습 계정은 `student`, 호스트 이름은 `ubuntu-y1`이며, 실습 디렉터리로 `~/lab02`를 사용한다.

# 제1절. 실습 시나리오와 진행 방법

---

## 1.1 시나리오

> **실습 시나리오 — 실습실 도우미의 첫 임무**
>
> 학습자는 학과 전산 실습실의 **관리 도우미**로 선발되었다. 첫 출근 날, 관리 선생님으로부터 다음 네 가지 임무가 적힌 쪽지를 받았다.
>
> 1. **임무 1.** 배정받은 컴퓨터의 신원(계정·이름·가동 상태)을 조사하라.
> 2. **임무 2.** 이 컴퓨터의 파일 트리 구조를 정찰하라.
> 3. **임무 3.** 앞으로 사용할 작업 공간(디렉터리와 파일)을 구축하라.
> 4. **임무 4.** 조사한 내용을 보고서 파일 한 개로 정리하여 제출하라.
>
> 관리 선생님은 마우스가 아니라 **반드시 터미널 명령으로** 임무를 수행할 것을 요구하였다.
{: .prompt-info }

---

## 1.2 진행 방법

총 **20문제**이며, 임무당 5문제씩 구성되어 있다. 각 문제는 다음 순서로 진행한다.

| 순서 | 내용 |
|---|---|
| ① 상황 | 시나리오 속에서 주어지는 상황 설명 |
| ② 과제 | 수행해야 할 일 |
| ③ 힌트 | 사용할 명령어의 실마리 |
| ④ 풀이 | 정답 명령과 해설, 예상 결과 |

**먼저 힌트까지만 읽고 스스로 명령을 입력해 본 뒤, 풀이를 열어 확인하는 방식을 권장한다.** 스스로 떠올리는 과정이 있어야 명령어가 자기 것이 된다. 다만 막히는 경우에는 풀이의 명령을 그대로 따라 입력해도 충분한 학습 효과가 있다.

> **유의 사항**
> 1. 리눅스는 대소문자를 엄격히 구분한다. 명령이 동작하지 않으면 철자와 대소문자부터 확인한다.
> 2. 긴 이름은 `Tab` 자동 완성을 활용하면 오타를 줄일 수 있다.
> 3. 화면이 멈춘 것처럼 보이면 `Ctrl + C`, `less` 화면(`:` 표시)에서는 `q`로 빠져나온다.
{: .prompt-warning }

# 제2절. 임무 1 — 담당 컴퓨터의 신원 조사

---

> **상황**
> 실습실에는 컴퓨터가 여러 대 있다. 관리 선생님은 "네가 맡은 컴퓨터가 어떤 계정으로 로그인되어 있고, 이름이 무엇이며, 켜진 지 얼마나 되었는지부터 파악하라"고 지시하였다.
{: .prompt-info }

---

> ### 문제 1. 터미널 열기와 동작 확인
>
> **과제** 단축키로 터미널을 열고, 화면에 `임무를 시작합니다`라는 문장을 출력하여 터미널이 정상 동작하는지 확인한다.
>
> **힌트** 터미널 단축키는 세 개의 키를 동시에 누른다. 문자열 출력에는 `echo`를 사용한다.
{: .prompt-tip }

**풀이.** `Ctrl + Alt + T`를 눌러 터미널을 연 뒤, 다음을 입력한다.

```bash
echo "임무를 시작합니다"
```

> `echo`는 뒤에 오는 문자열을 화면에 그대로 출력한다. 아래 줄에 같은 문장이 표시되면 터미널이 정상 동작하는 것이다.

```
student@ubuntu-y1:~$ echo "임무를 시작합니다"
임무를 시작합니다
```

---

> ### 문제 2. 프롬프트 해석
>
> **과제** 현재 프롬프트 `student@ubuntu-y1:~$`가 담고 있는 네 가지 정보를 말로 설명하고, 그중 **사용자 이름**과 **컴퓨터 이름**을 각각 명령어로 확인하여 프롬프트와 일치하는지 검증한다.
>
> **힌트** "나는 누구인가"를 뜻하는 명령과, "호스트 이름"을 뜻하는 명령을 사용한다.
{: .prompt-tip }

**풀이.** 프롬프트의 네 정보는 다음과 같다.

| 부분 | 의미 |
|---|---|
| `student` | 로그인한 사용자 이름 |
| `ubuntu-y1` | 호스트(컴퓨터) 이름 |
| `~` | 현재 위치(사용자의 홈 디렉터리) |
| `$` | 일반 사용자 권한(`#`이면 관리자) |

각각 명령으로 검증한다.

```bash
whoami
```

```bash
hostname
```

> `whoami`는 who am i의 약어로 `student`가, `hostname`은 `ubuntu-y1`이 출력된다. 프롬프트의 `@` 앞뒤와 각각 일치함을 확인한다.

---

> ### 문제 3. 현재 위치와 `~`의 정체 확인
>
> **과제** 프롬프트에 표시된 `~`가 실제로 어떤 경로의 약칭인지 명령어로 확인한다.
>
> **힌트** 현재 작업 디렉터리를 출력하는 세 글자 명령을 사용한다.
{: .prompt-tip }

**풀이.**

```bash
pwd
```

```
/home/student
```

> `pwd`는 **p**rint **w**orking **d**irectory의 약어이다. 출력된 `/home/student`가 바로 프롬프트의 `~`가 가리키는 실제 경로이다. `~`는 로그인한 사용자의 홈 디렉터리를 나타내는 약칭이다.

---

> ### 문제 4. 가동 시간과 커널 정보 조사
>
> **과제** 이 컴퓨터가 켜진 지 얼마나 되었는지, 그리고 커널 정보(운영체제의 핵심 버전)를 각각 확인한다.
>
> **힌트** "켜져 있는 시간"을 뜻하는 명령과, "unix name"의 약어인 명령에 `-a` 옵션을 붙인다.
{: .prompt-tip }

**풀이.**

```bash
uptime
```

> up + time의 조합으로, 현재 시각·가동 시간·접속자 수·시스템 부하가 한 줄로 출력된다.

```bash
uname -a
```

> `uname`은 **u**nix **name**, `-a`는 **a**ll의 약어이다. 커널 이름(`Linux`)·호스트 이름·커널 버전 등이 출력된다.

---

> ### 문제 5. 관리자 권한 확인 후 복귀
>
> **과제** 이 계정이 관리자 권한을 사용할 수 있는지 확인하기 위해 관리자로 전환하여 프롬프트의 변화를 관찰한 뒤, **반드시 원래 계정으로 복귀**한다.
>
> **힌트** superuser do의 약어인 명령에 `-i` 옵션을 붙여 전환하고, 복귀에는 `exit`를 사용한다.
{: .prompt-tip }

**풀이.**

```bash
sudo -i
```

> 비밀번호를 물으면 자신의 비밀번호를 입력한다. **입력 중 화면에 아무것도 표시되지 않는 것은 정상이다.** 전환에 성공하면 프롬프트가 `#`로 바뀐다.

```bash
whoami
```

> `root`가 출력된다.

```bash
exit
```

> 프롬프트가 다시 `$`로 돌아왔는지 확인한다. **관리자 상태로 계속 작업하면 실수 하나가 시스템 전체를 손상시킬 수 있으므로, 확인 즉시 복귀하는 습관을 들인다.**

> **임무 1 완료 기준** 계정 이름(`student`), 컴퓨터 이름(`ubuntu-y1`), 홈 디렉터리 경로(`/home/student`), 가동 시간, 커널 버전을 모두 말할 수 있고, 프롬프트가 `$` 상태로 돌아와 있으면 임무 1 완수이다.
{: .prompt-tip }

# 제3절. 임무 2 — 파일 트리 정찰

---

> **상황**
> 관리 선생님은 "이 컴퓨터의 파일이 어떻게 배치되어 있는지 파악해 두어야 앞으로 어떤 작업이든 할 수 있다"며, 파일 트리의 최상위부터 차례로 정찰할 것을 지시하였다.
{: .prompt-info }

---

> ### 문제 6. 파일 트리의 최상위 정찰
>
> **과제** 파일 트리의 최상위(루트) 디렉터리에 어떤 디렉터리들이 있는지 조회하고, 그중 **사용자 공간**, **설정 파일 보관소**, **명령 프로그램 보관소**에 해당하는 세 곳의 이름을 찾는다.
>
> **힌트** 목록 조회 명령 뒤에 루트를 뜻하는 기호 한 글자를 인자로 준다.
{: .prompt-tip }

**풀이.**

```bash
ls /
```

> `bin  boot  dev  etc  home  ...  usr  var` 등이 출력된다. 과제에서 요구한 세 곳은 다음과 같다.

| 디렉터리 | 용도 |
|---|---|
| `/home` | 일반 사용자의 개인 작업 공간 |
| `/etc` | 시스템 전역 설정 파일 보관소 |
| `/bin` | `ls`, `cp` 등 기본 명령 프로그램 |

> `/`(루트 디렉터리)와 `/root`(관리자의 홈 디렉터리)는 이름이 비슷하지만 전혀 다른 대상임에 유의한다.

---

> ### 문제 7. 절대 경로로 이동하기
>
> **과제** 현재 위치와 무관하게 한 번의 명령으로 설정 파일 보관소(`/etc`)로 이동한 뒤, 실제로 이동되었는지 확인한다.
>
> **힌트** 절대 경로는 맨 앞에 `/`가 붙는다.
{: .prompt-tip }

**풀이.**

```bash
cd /etc
```

```bash
pwd
```

```
/etc
```

> 맨 앞에 `/`가 있으므로 절대 경로이다. 절대 경로는 현재 위치가 어디이든 항상 같은 곳을 가리키므로, "어디서 출발하든 찾아갈 수 있는 완전한 주소"에 해당한다. 프롬프트도 `:/etc$`로 바뀐 것을 확인한다.

---

> ### 문제 8. 상대 경로로 이동하기
>
> **과제** 현재 위치(`/etc`)에서 **상위 디렉터리로 한 단계** 올라간 뒤, 거기서 **상대 경로만으로** `student`의 홈 디렉터리(`/home/student`)까지 내려간다. 절대 경로(`/`로 시작하는 경로)는 사용하지 않는다.
>
> **힌트** 상위 디렉터리는 점 두 개이다. `/etc`의 상위는 루트이므로, 루트에서 `home` → `student` 순으로 내려가면 된다.
{: .prompt-tip }

**풀이.**

```bash
cd ..
```

```bash
pwd
```

> `..`는 상위 디렉터리를 뜻한다. `/etc`의 상위인 `/`가 출력된다.

```bash
cd home/student
```

```bash
pwd
```

```
/home/student
```

> `home/student`는 맨 앞에 `/`가 없으므로 상대 경로이다. 현재 위치인 `/`를 기준으로 `home` → `student` 순서로 내려간 것이다. 같은 목적지라도 현재 위치에 따라 상대 경로 표기는 달라진다.

---

> ### 문제 9. 두 지점 왕복 순찰
>
> **과제** 홈 디렉터리와 `/var/log`(시스템 로그 보관소)를 오가며 순찰하려 한다. 먼저 `/var/log`로 이동한 뒤, **직전 디렉터리로 되돌아가는 기호**를 사용하여 두 위치를 두 차례 왕복한다. 마지막에는 인자 없는 이동 명령으로 홈에 복귀한다.
>
> **힌트** 직전 디렉터리는 하이픈 기호이다.
{: .prompt-tip }

**풀이.**

```bash
cd /var/log
```

```bash
cd -
```

> `cd -`는 직전에 있던 디렉터리로 되돌아가며, 이동한 경로를 화면에 출력해 준다. `/home/student`로 돌아온다.

```bash
cd -
```

> 다시 `/var/log`로 이동한다. 두 지점을 번갈아 오갈 때 매우 편리하다.

```bash
cd
```

```bash
pwd
```

> `cd`를 인자 없이 실행하면 항상 홈 디렉터리로 복귀한다. **경로를 잃고 헤맬 때 쓰는 최후의 수단이므로 반드시 기억한다.**

---

> ### 문제 10. 파일과 디렉터리 구분하기
>
> **과제** `/etc`의 내용을 **상세 정보와 사람이 읽기 쉬운 크기 단위**로 앞 10줄만 조회한 뒤, 출력의 **맨 앞 한 글자**를 근거로 디렉터리와 일반 파일을 구분한다.
>
> **힌트** 상세는 `-l`, 읽기 쉬운 크기는 `-h`이며 두 옵션은 묶어 쓸 수 있다. 앞 10줄 제한은 `| head -10`을 뒤에 붙인다.
{: .prompt-tip }

**풀이.**

```bash
ls -lh /etc | head -10
```

```
drwxr-xr-x  ...  4.0K  ...  apt
-rw-r--r--  ...  3.0K  ...  bash.bashrc
```

> 각 행의 맨 앞 한 글자가 **`d`이면 디렉터리, `-`이면 일반 파일**이다. 위 예시에서 `apt`는 디렉터리, `bash.bashrc`는 일반 파일이다. `-h`(**h**uman-readable) 덕분에 크기가 `4.0K`처럼 읽기 쉬운 단위로 표시된다.

> **임무 2 완료 기준** 절대 경로와 상대 경로를 모두 사용하여 이동하였고, `cd -`와 인자 없는 `cd`의 차이를 설명할 수 있으며, `ls -l` 출력에서 디렉터리와 파일을 구분할 수 있으면 임무 2 완수이다.
{: .prompt-tip }

# 제4절. 임무 3 — 작업 공간 구축

---

> **상황**
> 관리 선생님은 "앞으로 조사 자료를 넣을 작업 공간을 홈 디렉터리 아래에 만들되, 문서와 로그를 구분해서 보관하라"고 지시하였다. 요구된 구조는 다음과 같다.
>
> ```

> **힌트** 디렉터리 생성 명령에 상위 디렉터리까지 함께 만드는 `-p` 옵션을 붙인다. 명령을 두 번 실행하면 된다.

**풀이.**

```bash
mkdir -p ~/lab02/mission/docs
```

```bash
mkdir -p ~/lab02/mission/logs
```

> `mkdir`은 **m**a**k**e **dir**ectory, `-p`는 **p**arents의 약어이다. `-p`가 있으면 `lab02`, `mission`이 아직 없어도 경로상의 모든 디렉터리를 한 번에 생성하며, 이미 있어도 오류를 내지 않는다.

```bash
ls ~/lab02/mission
```

> `docs  logs` 두 디렉터리가 출력되면 성공이다.

> ### 문제 12. 조사 자료 파일 생성
>
> **과제** `docs` 디렉터리로 이동하여 빈 파일 `report1.txt`, `report2.txt`, `report10.txt`, `memo.md` 네 개를 **한 번의 명령으로** 생성한다. 이어서 `logs` 디렉터리에도 `sys1.log`, `sys2.log` 두 개를 생성한다.
>
> **힌트** 빈 파일 생성 명령 뒤에 파일명을 공백으로 나열하면 한 번에 만들어진다. `logs`는 `docs`의 **형제 디렉터리**이므로 `../logs`처럼 상대 경로로 지정할 수 있다.
{: .prompt-tip }

**풀이.**

```bash
cd ~/lab02/mission/docs
```

```bash
touch report1.txt report2.txt report10.txt memo.md
```

> `touch`는 빈 파일을 생성하는 명령이며, 이름을 나열하면 여러 개가 한 번에 만들어진다.

```bash
touch ../logs/sys1.log ../logs/sys2.log
```

> `..`는 상위 디렉터리(`mission`)를 뜻하므로, `../logs`는 현재 위치(`docs`)에서 형제 디렉터리인 `logs`를 가리킨다. 디렉터리를 이동하지 않고도 다른 위치에 파일을 만들 수 있다.

```bash
ls ../logs
```

> `sys1.log  sys2.log`가 출력되면 성공이다.

**풀이.**


> ### 문제 14. `*`와 `?`의 차이 관찰
>
> **과제** `report?.txt`와 `report*.txt`를 각각 조회하고, **`report10.txt`가 어느 쪽에서 빠지는지** 관찰하여 두 기호의 차이를 설명한다.
>
> **힌트** `?`는 정확히 한 글자, `*`는 0개 이상의 글자와 대응한다.
{: .prompt-tip }

**풀이.**

```bash
ls report?.txt
```

```
report1.txt  report2.txt
```

```bash
ls report*.txt
```

```
report1.txt  report10.txt  report2.txt
```

> `?`는 **정확히 한 글자**와 대응하므로 `report` 뒤에 두 글자(`10`)가 오는 `report10.txt`는 `report?.txt`에서 제외된다. 반면 `*`는 글자 수 제한이 없으므로 세 파일 모두와 대응한다. 여러 파일을 다루는 명령을 실행하기 전에 이렇게 `ls`로 대상을 미리 확인하는 습관이 사고를 예방한다.

> ### 문제 16. 보고서 생성과 조사자 정보 기록
>
> **과제** `docs` 디렉터리에서 보고서 파일을 새로 만들며 첫 줄에 `===== 실습실 조사 보고서 =====`를 기록하고, 이어서 조사자 계정 이름과 컴퓨터 이름을 **파일에 추가로** 기록한다.
>
> **힌트** 새로 만들 때는 `>`, 이어서 기록할 때는 `>>`를 사용한다. 두 기호의 차이가 이 문제의 핵심이다.
{: .prompt-tip }

**풀이.**

```bash
cd ~/lab02/mission/docs
```

```bash
echo "===== 실습실 조사 보고서 =====" > report.txt
```

> `>`는 명령의 출력을 화면 대신 파일로 보내는 **리다이렉션**이다. 파일이 없으면 새로 만들고, **있으면 기존 내용을 지우고** 새로 쓴다.

```bash
whoami >> report.txt
```

```bash
hostname >> report.txt
```

> `>>`는 기존 내용 **뒤에 이어서** 기록한다. 여기서 `>`를 쓰면 앞서 기록한 제목이 지워지므로 주의한다.

> **힌트** 빈 줄은 `echo ""`로 만든다. 임무 1에서 사용한 두 명령의 출력을 `>>`로 보낸다.
{: .prompt-tip }

**풀이.**

```bash
echo "" >> report.txt
```

```bash
echo "===== 시스템 정보 =====" >> report.txt
```

```bash
uptime >> report.txt
```

```bash
uname -a >> report.txt
```

> 화면에 출력되던 내용이 그대로 파일에 쌓인다. 명령 실행 후 화면에 아무것도 나타나지 않는 것은 출력이 파일로 방향을 바꾸었기 때문이며, 정상 동작이다.

> ### 문제 18. 파일 트리 정보 기록

> **과제** 구분선 `===== 루트 디렉터리 =====`에 이어 루트 디렉터리의 목록을 기록하고, 구분선 `===== 홈 디렉터리(숨김 포함) =====`에 이어 **숨김 파일까지 포함한** 홈 디렉터리 목록을 기록한다.
>
> **힌트** 숨김 파일은 `-a` 옵션으로 표시한다. 현재 위치는 `docs`이므로 홈은 `~`로 지정한다.

**풀이.**

```bash
echo "" >> report.txt
```

```bash
echo "" >> report.txt
```

```bash
echo "===== 홈 디렉터리(숨김 포함) =====" >> report.txt
```

> ### 문제 19. 작업 공간 목록 기록과 보고서 확인
>
> **과제** 구분선 `===== 작성한 문서 목록 =====`에 이어 `docs` 안의 **txt 파일만** 와일드카드로 골라 기록한다. 완성된 보고서의 전체 내용을 화면에 출력하고, 총 몇 행인지 계산한다.
>
> **힌트** 내용 출력은 `cat`, 행 수 계산은 `wc -l`이다.
{: .prompt-tip }

**풀이.**

```bash
echo "" >> report.txt
```

```bash
echo "===== 작성한 문서 목록 =====" >> report.txt
```

```bash
ls *.txt >> report.txt
```

```bash
cat report.txt
```

```
===== 실습실 조사 보고서 =====
student
ubuntu-y1

===== 시스템 정보 =====
 13:20:15 up  1:42,  1 user,  load average: 0.08, 0.03, 0.01
Linux ubuntu-y1 6.8.0-xx-generic ...

===== 루트 디렉터리 =====
bin  boot  dev  etc  home  ...

===== 홈 디렉터리(숨김 포함) =====
.  ..  .bashrc  .profile  Desktop  Documents  lab02  ...

===== 작성한 문서 목록 =====
report.txt
report1.txt
report10.txt
report2.txt
```

```bash
wc -l report.txt
```

> `cat`은 con**cat**enate의 약어로 파일 내용을 화면에 출력하고, `wc -l`은 행 수를 계산한다. 네 구분선과 각 조사 내용이 순서대로 담겨 있으면 보고서가 완성된 것이다. `ls *.txt` 결과에 보고서 자신(`report.txt`)도 포함되는 점을 관찰한다. 보고서 역시 txt 파일이기 때문이다.

> ### 문제 20. 작업 복기와 안전한 마무리
>
> **과제** ① 지금까지 입력한 명령 전체를 복기하여 화면에 출력한다. ② 10분 뒤 재부팅을 예약하면서 접속자에게 `실습 종료 예정` 메시지를 통보한 뒤, **곧바로 예약을 취소**한다. ③ 화면을 깨끗이 정리하며 임무를 마친다.
>
> **힌트** 명령 이력 조회, `shutdown`의 `-r`(예약 재부팅)과 `-c`(취소), 화면 정리 명령을 차례로 사용한다.
{: .prompt-tip }

**풀이.**

```bash
history
```

> 지금까지 입력한 명령이 번호와 함께 출력된다. 오늘 어떤 명령으로 임무를 수행했는지 복기한다. 목록이 길면 `history | head -10`처럼 제한할 수 있다.

```bash
sudo shutdown -r +10 "실습 종료 예정"
```

> `-r`은 **r**eboot, `+10`은 10분 뒤를 의미하며, 접속 중인 사용자에게 메시지가 통보된다.

```bash
sudo shutdown -c
```

> **반드시 취소하여야 한다.** 취소하지 않으면 10분 뒤 실제로 재부팅된다. `-c`는 **c**ancel의 약어이다.

```bash
clear
```

> 화면이 깨끗해지면 모든 임무가 종료된 것이다. 실제 재부팅이 필요한 경우에만 `sudo reboot`을 사용한다.

> **임무 4 완료 기준** `report.txt` 한 개에 네 항목이 구분선과 함께 순서대로 기록되어 있고, 예약 재부팅이 정상적으로 취소되었으면 전체 임무 완수이다.
{: .prompt-tip }
