# 9-1 VIEW 개념과 실습 — 가상 테이블로 쿼리 재사용하기

> 이번 주차 학습 목표
> - **VIEW(뷰)가 무엇인지** 한 문장으로 설명할 수 있다.
> - VIEW를 **왜** 쓰는지(재사용, 단순화, 보안) 세 가지를 말할 수 있다.
> - `CREATE VIEW`, `DROP VIEW`, `CREATE OR REPLACE VIEW` 를 직접 작성할 수 있다.
> - VIEW를 통해 **민감한 컬럼을 숨기는 보안 기법**을 실습한다.
{: .prompt-tip }

---

## 1. VIEW란 무엇인가?

**VIEW는 "저장된 SELECT 문"이다.**

- 실제 데이터를 가진 진짜 테이블처럼 `SELECT * FROM 뷰이름;` 으로 조회할 수 있다.
- 하지만 내부에는 데이터가 없고, 대신 **SELECT 쿼리 정의**만 저장되어 있다.
- 그래서 **"가상 테이블(Virtual Table)"** 이라고 부른다.

> 💡 비유하자면, VIEW는 **"자주 쓰는 질문을 단축키로 저장해 둔 것"** 과 같다.  
> 복잡한 JOIN 쿼리를 매번 길게 쓰는 대신, 이름 하나로 불러 쓸 수 있게 해준다.
{: .prompt-info }

### 일반 테이블 vs VIEW

| 구분 | 일반 테이블 | VIEW |
|---|---|---|
| 실제 데이터 저장 | O | X (정의만 저장) |
| 디스크 공간 사용 | 많이 | 거의 없음 |
| 수정 방법 | INSERT/UPDATE/DELETE | SELECT 문을 교체 |
| 속도 | 빠름 | 원본 SELECT가 매번 실행 |

---

## 2. VIEW를 왜 쓰는가?

1. **복잡한 쿼리 재사용** — JOIN 3개짜리 긴 쿼리를 이름 하나로 부른다.
2. **단순화** — 초보 사용자에게 어려운 JOIN 구조를 감춘다.
3. **보안** — 원본 테이블의 민감한 컬럼(비밀번호, 주민번호 등)을 가린 VIEW만 열어 준다.

> ⚠️ 3번이 이 과목(데이터베이스보안)에서 가장 중요한 이유다.  
> 나중에 10주차 권한 관리(GRANT)와 합쳐지면 "이 사용자에게는 이 VIEW만 보여줘" 가 가능해진다.
{: .prompt-warning }

## 3. 실습 환경 준비 (Windows 11 + MySQL Workbench)

### 3-1. 준비 확인

- 내 PC에 **MySQL 8.x** 와 **MySQL Workbench** 가 설치되어 있어야 한다.
- Windows 11의 **작업 표시줄 → MySQL Workbench** 를 실행한다.
- 로컬 연결(보통 `Local instance MySQL80`)을 더블클릭해 접속한다.

### 3-2. 실습용 데이터베이스 만들기

Workbench의 **Query 창**에 아래 SQL을 입력하고 `Ctrl + Enter` 로 실행한다.

```sql
DROP DATABASE IF EXISTS view_db;
CREATE DATABASE view_db;
USE view_db;
```

### 3-3. 실습 테이블 생성

학생 정보와 성적 정보를 가진 두 테이블을 만든다.

```sql
CREATE TABLE students (
    id           INT PRIMARY KEY AUTO_INCREMENT,
    student_no   VARCHAR(20) NOT NULL UNIQUE,
    name         VARCHAR(30) NOT NULL,
    phone        VARCHAR(20),
    resident_no  VARCHAR(14)      -- 주민번호 (민감정보!)
);

CREATE TABLE scores (
    id          INT PRIMARY KEY AUTO_INCREMENT,
    student_id  INT NOT NULL,
    subject     VARCHAR(30) NOT NULL,
    score       INT NOT NULL,
    FOREIGN KEY (student_id) REFERENCES students(id)
);
```

## 4. 첫 번째 VIEW 만들기 — 단순 VIEW

### 기본 문법

```sql
CREATE VIEW 뷰이름 AS
SELECT ... FROM ... WHERE ... ;
```

### 실습 1. "학생 연락처" 뷰

전화번호까지만 보여 주고 **주민번호는 숨기는** 뷰를 만든다.

```sql
CREATE VIEW v_student_contact AS
SELECT id, student_no, name, phone
FROM students;
```

조회해 보자.

```sql
SELECT * FROM v_student_contact;
```

**예상 결과:**

| id | student_no | name | phone |
|---|---|---|---|
| 1 | 2026001 | 김민준 | 010-1111-2222 |
| 2 | 2026002 | 이서연 | 010-3333-4444 |
| ... | ... | ... | ... |

> 💡 `resident_no` 컬럼이 **결과에 아예 나타나지 않는다**.  
> 이것이 VIEW를 이용한 가장 기본적인 보안 기법이다.
{: .prompt-info }

---

## 5. 두 번째 VIEW — JOIN을 감추는 VIEW

### 실습 2. "학생별 성적" 뷰

`students`와 `scores`를 JOIN한 결과를 뷰로 저장한다.

```sql
CREATE VIEW v_student_scores AS
SELECT s.student_no,
       s.name,
       sc.subject,
       sc.score
FROM students AS s
INNER JOIN scores AS sc
    ON s.id = sc.student_id;
```

조회해 보자. **JOIN 쿼리를 한 줄도 안 쓰고** 결과를 본다.

```sql
SELECT * FROM v_student_scores;
SELECT * FROM v_student_scores WHERE name = '김민준';
```

> 💡 VIEW의 진짜 힘: **앞으로는 JOIN을 아는 사람만 뷰를 만들고,  
> 사용하는 사람은 `SELECT * FROM v_student_scores` 만 쓰면 된다.**
{: .prompt-info }

## 6. 세 번째 VIEW — 집계함수가 들어간 VIEW

### 실습 3. "학생별 평균 점수" 뷰

```sql
CREATE VIEW v_student_avg AS
SELECT s.student_no,
       s.name,
       ROUND(AVG(sc.score), 1) AS avg_score
FROM students AS s
INNER JOIN scores AS sc
    ON s.id = sc.student_id
GROUP BY s.id, s.student_no, s.name;
```

조회:

```sql
SELECT * FROM v_student_avg ORDER BY avg_score DESC;
```

**예상 결과 (내림차순):**

| student_no | name | avg_score |
|---|---|---|
| 2026003 | 박지호 | 92.5 |
| 2026001 | 김민준 | 88.5 |
| 2026002 | 이서연 | 83.0 |
| ... | ... | ... |

## 7. VIEW 수정하기 — `CREATE OR REPLACE`

기존 뷰를 지우지 않고 새 정의로 덮어쓰려면 다음을 쓴다.

```sql
CREATE OR REPLACE VIEW v_student_contact AS
SELECT student_no, name, phone      -- id 컬럼 제거
FROM students;
```

```sql
SELECT * FROM v_student_contact;
```

이제 `id` 컬럼이 사라진다.

---

## 8. VIEW 삭제하기 — `DROP VIEW`

```sql
DROP VIEW IF EXISTS v_student_contact;
```

> ⚠️ `DROP TABLE`과 헷갈리지 말 것. **VIEW는 데이터가 없으므로** 삭제해도 원본 테이블은 전혀 영향 받지 않는다.
{: .prompt-warning }

---

## 9. VIEW로 INSERT / UPDATE 가능한가?

가능은 하지만 **제한이 많다.**

| VIEW 형태 | INSERT/UPDATE 가능? |
|---|---|
| 단일 테이블의 단순 VIEW | ✅ 가능 |
| JOIN이 들어간 VIEW | ❌ 대부분 불가 |
| GROUP BY, 집계함수가 들어간 VIEW | ❌ 불가 |
| DISTINCT, UNION이 들어간 VIEW | ❌ 불가 |

### 실습 4. 단순 VIEW에 UPDATE 해 보기

```sql
CREATE OR REPLACE VIEW v_student_contact AS
SELECT id, student_no, name, phone
FROM students;

UPDATE v_student_contact
SET phone = '010-0000-0000'
WHERE student_no = '2026001';

SELECT * FROM students WHERE student_no = '2026001';
```

원본 `students` 테이블의 phone이 바뀐 것을 확인할 수 있다.

> ⚠️ VIEW를 통해 수정하면 **원본 테이블이 바뀐다.**  
> "뷰만 바꾸면 원본은 안전하다" 는 오해는 금물.
{: .prompt-warning }

## 10. 보안용 VIEW — 민감 정보 가리기 (이번 주차 핵심)

### 문제 상황

학생 `students` 테이블에는 `resident_no`(주민번호)가 들어 있다.  
조교에게는 **이름과 전화번호까지만** 보여줘야 한다.

### 해법: 최소 정보만 담은 VIEW

```sql
CREATE OR REPLACE VIEW v_student_public AS
SELECT student_no,
       name,
       phone
FROM students;
```

그리고 **조교 계정에게는 원본 `students`는 막고, `v_student_public`만 접근 허용**한다.  
(권한 부분은 **10-2 강의**에서 실습한다.)

### 마스킹된 VIEW (부분 공개)

주민번호 앞 6자리만 보여 주고 뒷자리는 `*` 로 가리는 뷰도 만들 수 있다.

```sql
CREATE OR REPLACE VIEW v_student_masked AS
SELECT student_no,
       name,
       phone,
       CONCAT(SUBSTRING(resident_no, 1, 7), '*******') AS masked_rrn
FROM students;

SELECT * FROM v_student_masked;
```

**예상 결과:**

| student_no | name | phone | masked_rrn |
|---|---|---|---|
| 2026001 | 김민준 | 010-0000-0000 | 080312-******* |
| 2026002 | 이서연 | 010-3333-4444 | 080715-******* |
| ... | ... | ... | ... |

> 💡 실제 금융·의료 시스템에서도 이런 방식의 "마스킹 뷰"를 많이 쓴다.  
> 민감정보는 DB에는 있지만, 보는 사람에게는 일부만 공개된다.
{: .prompt-info }

## 11. 연습 문제

아래 문제를 **직접 SQL로 작성해 실행**해 보자.

### 문제 1
90점 이상을 받은 학생의 `이름, 과목, 점수` 를 보여 주는 뷰 `v_high_score` 를 만드시오.

<details>
<summary>정답 보기</summary>

```sql
CREATE OR REPLACE VIEW v_high_score AS
SELECT s.name, sc.subject, sc.score
FROM students AS s
INNER JOIN scores AS sc ON s.id = sc.student_id
WHERE sc.score >= 90;

SELECT * FROM v_high_score;
```
</details>

### 문제 2
과목별 평균 점수를 보여 주는 뷰 `v_subject_avg` 를 만드시오.

<details>
<summary>정답 보기</summary>

```sql
CREATE OR REPLACE VIEW v_subject_avg AS
SELECT subject, ROUND(AVG(score), 2) AS avg_score
FROM scores
GROUP BY subject;

SELECT * FROM v_subject_avg;
```
</details>

### 문제 3
전화번호를 `010-****-마지막4자리` 형태로 가려서 보여 주는 뷰 `v_student_phone_masked` 를 만드시오.  
(힌트: `REPLACE`, `CONCAT`, `SUBSTRING` 중 하나를 사용)

<details>
<summary>정답 보기</summary>

```sql
CREATE OR REPLACE VIEW v_student_phone_masked AS
SELECT student_no,
       name,
       CONCAT('010-****-', SUBSTRING(phone, -4)) AS phone_masked
FROM students;

SELECT * FROM v_student_phone_masked;
```
</details>

## 12. 정리

- VIEW는 **데이터가 없는 저장된 SELECT 문** 이다.
- 세 가지 목적: **재사용 / 단순화 / 보안**.
- `CREATE VIEW`, `CREATE OR REPLACE VIEW`, `DROP VIEW` 세 문장이 기본이다.
- JOIN/집계 결과도 VIEW로 만들 수 있으나 INSERT/UPDATE는 제한된다.
- 민감 정보를 **마스킹 뷰** 로 가리는 것이 DB 보안의 기본기다.
