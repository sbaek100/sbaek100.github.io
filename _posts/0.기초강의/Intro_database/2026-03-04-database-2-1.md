# 1장. 데이터베이스 시작하기

## 1.1 데이터베이스(DataBase, DB)란

### 1.1.1 데이터베이스의 개념

데이터베이스(DataBase, DB)는 구조화된 데이터의 집합으로, 방대한 정보를 체계적으로 저장·관리하는 데이터 창고임. 현대 IT 시스템에서 모든 서비스의 핵심 기반 인프라로 작동함.

![](/assets/img/posts/2026-03-04-database-2-1772604639407.png)

과거에는 파일 시스템(File System)에 데이터를 저장했으나, 데이터 중복, 일관성 결여, 동시 접근 문제 등으로 인해 DB 방식으로 전환됨.

> **데이터베이스가 사용되는 분야 (Fact)**
> 
> - **전자상거래**: 상품 정보, 주문 내역, 회원 데이터 관리
> - **금융**: 계좌 정보, 거래 내역, 잔액 실시간 처리
> - **의료**: 환자 기록, 처방 이력, 검사 결과 저장
> - **SNS**: 게시글, 팔로워 관계, 메시지 데이터 처리
> - **공공기관**: 인구 통계, 세금, 행정 데이터 관리

---

### 1.1.2 DBMS(DataBase Management System)

DBMS는 데이터베이스를 생성·관리·운영하기 위한 소프트웨어 시스템임. DB가 '데이터 창고'라면, DBMS는 그 창고를 관리하는 '창고 관리 시스템'에 해당함.

![](/assets/img/posts/2026-03-04-database-2-1772604674659.png)


| 기능         | 설명                        | 예시                 |
| ---------- | ------------------------- | ------------------ |
| **효율적 데이터 관리** | 대량 데이터를 체계적으로 저장·조회       | 수억 건의 거래 데이터 빠른 검색 |
| **데이터 무결성 유지** | 제약 조건으로 정확성·일관성 보장        | 중복 이메일 등록 방지       |
| **동시성 제어**     | 다수 사용자 동시 접근 충돌 방지        | 항공권 좌석 이중 예약 방지    |
| **보안**         | 권한 기반 데이터 접근 통제           | 직원별 열람 가능 데이터 제한   |
| **백업 및 복구**    | 장애 발생 시 데이터 복원 보장         | 트랜잭션 로그 기반 복구      |
| **데이터 추상화**    | 복잡한 저장 구조 숨기고 쉬운 인터페이스 제공 | SQL만으로 데이터 조작 가능   |

#### 주요 DBMS 종류 비교

|DBMS|특징|주요 사용처|
|---|---|---|
|MySQL|무료 오픈소스, 표준 SQL 지원, 대규모 커뮤니티|웹 서비스, 스타트업, 교육|
|PostgreSQL|고급 기능, JSON 지원, 확장성 우수|데이터 분석, 복잡한 쿼리|
|Oracle|엔터프라이즈급, 고가용성, 상용 라이선스|금융, 대기업 핵심 시스템|
|MS SQL Server|윈도우 통합, .NET 친화적|윈도우 기반 기업 환경|
|SQLite|파일 기반, 경량, 설치 불필요|모바일 앱, 임베디드 시스템|

본 강의에서는[ **MySQL**](https://www.mysql.com/)을 사용함. MySQL 선택 이유:

![](/assets/img/posts/2026-03-04-database-2-1772604767698.png)


- 무료 오픈소스(Community Edition) 제공
- 전 세계적으로 가장 광범위하게 사용되는 검증된 DBMS
- 표준 SQL 지원으로 타 DBMS로 이식성 높음
- 풍부한 공식 문서 및 학습 리소스 제공

### 1.1.3 SQL(Structured Query Language)

SQL은 관계형 데이터베이스를 조작하기 위한 표준화된 질의 언어(Query Language)임. 국제 표준화 기구(ISO)에서 표준으로 지정하였으며, 대부분의 DBMS가 이를 지원함.

![](/assets/img/posts/2026-03-04-database-2-1772604820924.png)


|SQL 분류|명령어|설명|
|---|---|---|
|DDL (데이터 정의어)|CREATE, ALTER, DROP|테이블·DB 구조 생성·변경·삭제|
|DML (데이터 조작어)|SELECT, INSERT, UPDATE, DELETE|데이터 조회·삽입·수정·삭제|
|DCL (데이터 제어어)|GRANT, REVOKE|사용자 접근 권한 제어|
|TCL (트랜잭션 제어어)|COMMIT, ROLLBACK|트랜잭션 확정·취소|

> 💡SQL은 프로그래밍 언어가 아니라 선언형(Declarative) 언어임. '어떻게'가 아닌 '무엇을' 원하는지 기술하면 DBMS가 최적 실행 방법을 결정함.

## 1.2 데이터 저장 형식

### 1.2.1 데이터베이스 파일 구성

DBMS가 데이터를 관리할 때 내부적으로 여러 종류의 파일을 사용함.

| 파일 종류                    | 설명 및 역할                                                 |
| ------------------------ | ------------------------------------------------------- |
| **데이터 파일 (Data File)**       | 실제 데이터(테이블, 인덱스 등)를 저장하는 핵심 파일. MySQL의 경우 `.ibd` 확장자 사용 |
| **로그 파일 (Log File)**         | 모든 데이터 변경 이력(생성·수정·삭제)을 순서대로 기록. 장애 복구 시 이 파일 기반으로 복원   |
| **인덱스 파일 (Index File)**      | 검색 속도 향상을 위한 색인 정보 저장. 책의 찾아보기와 동일한 개념                  |
| **설정 파일 (Config File)**      | DBMS 동작 방식, 포트 번호, 메모리 설정 등 운영 환경 정의                    |
| **메타데이터 파일 (Metadata File)** | 테이블 구조(칼럼명, 데이터 타입, 관계 등) 정보 저장. '데이터에 대한 데이터'          |

---

### 1.2.2 테이블(Table) 구조

테이블은 관계형 데이터베이스에서 데이터를 저장하는 가장 기본적인 단위임. 열(Column)과 행(Row)으로 구성된 2차원 구조를 가짐.

![](/assets/img/posts/2026-03-04-database-2-1772604881674.png)


|용어|의미|예시 (학생 테이블)|
|---|---|---|
|테이블 (Table)|데이터를 저장하는 2차원 구조 단위|students (학생 테이블)|
|칼럼 / 열 (Column)|데이터의 속성·항목을 나타내는 수직 구조|id, name, grade, score|
|행 / 튜플 (Row/Tuple)|하나의 레코드, 실제 데이터 1건|1, 홍길동, 3, 92|
|기본키 (Primary Key, PK)|각 행을 유일하게 식별하는 칼럼|id (중복 불가, NULL 불가)|
|자료형 (Data Type)|칼럼에 저장 가능한 데이터 유형|INT, VARCHAR, DATETIME|

> 💡**기본키(Primary Key)는 테이블 내에서 반드시 유일(Unique)해야 하며, NULL 값을 가질 수 없음. 이 두 조건은 DBMS가 자동으로 강제함.**

#### 주요 MySQL 자료형(Data Type)

|분류|자료형|설명 및 사용 예|
|---|---|---|
|정수형|INT|정수 값 저장. 예: 나이, 수량, ID (-2억 ~ 2억)|
|실수형|FLOAT / DOUBLE|부동소수점 수. 예: 온도, 좌표 (근사값)|
|고정소수형|DECIMAL(p, s)|정확한 소수점 수. 예: 금액, 환율 (오차 없음)|
|고정 문자열|CHAR(n)|항상 n 바이트 할당. 예: 우편번호, 전화번호|
|가변 문자열|VARCHAR(n)|실제 길이만큼만 저장. 예: 이름, 이메일 (최대 n)|
|날짜·시간|DATE / DATETIME|날짜 또는 날짜+시간 저장. 예: 생일, 주문일시|
|불리언|TINYINT(1)|0 또는 1. MySQL에는 BOOLEAN 없음 (별칭만 존재)|
|대용량 텍스트|TEXT|긴 문자열. 예: 게시글 내용, 설명|

## 1.3 MySQL 실습 환경 설정

### 1.3.1 실습 환경 구성 개요

MySQL 실습은 **MySQL 서버(Server)**와 **MySQL 워크벤치(Workbench)** 두 가지 프로그램으로 구성됨.

![](/assets/img/posts/2026-03-04-database-2-1772604936869.png)



| 구성 요소                  | 역할                                                                  |
| ---------------------- | ------------------------------------------------------------------- |
| MySQL 서버 (Server)      | 실제 DB 엔진. 데이터를 저장·처리·관리하는 백엔드 프로세스. 포트 3306에서 연결 대기(Port 번호는 변경 가능) |
| MySQL 워크벤치 (Workbench) | GUI 기반 클라이언트 도구. SQL 작성·실행·결과 확인이 가능한 프론트엔드 인터페이스                   |

### 1.3.2 윈도우(Windows) MySQL 설치 방법

윈도우에서는 MySQL Installer를 사용해 서버와 워크벤치를 한 번에 설치할 수 있음.

> **설치 전 확인 사항 (Fact)**
> 
> - 설치 버전: MySQL **8.0.45** (본 강의 기준) 
>   https://dev.mysql.com/downloads/installer/
> - 설치 파일: `mysql-installer-community-8.0.45.msi` (약 450MB)
> - 운영체제: Windows 10 / 11 (64-bit)
>   ![](/assets/img/posts/2026-03-04-database-2-1772605456981.png)
> 
> - 필요 권한: 관리자(Administrator) 권한 필요
> - 포트: 기본 3306 (방화벽 허용 필요)

#### 【단계 1】 설치 파일 다운로드

1. 웹 브라우저에서 MySQL 공식 다운로드 페이지 접속
2. URL: `https://dev.mysql.com/downloads/windows/installer/8.0.html`
3. **[Archives]** 탭 클릭
4. Product Version: `8.0.39` 선택
5. Operating System: `Microsoft Windows` 선택
6. 용량이 큰 파일(약 450MB) 다운로드 선택 → **[No thanks, just start my download]** 클릭

![](/assets/img/posts/2026-03-04-database-2-1772605500401.png)

#### 【단계 2】 설치 유형 선택

1. 다운로드된 `.msi` 파일 실행 (관리자 권한으로 실행 권장)
2. Setup Type 선택 화면에서 **[Full]** 또는 **[Custom]** 선택

![](/assets/img/posts/2026-03-04-database-2-1772605646729.png)


|Setup Type|포함 항목|
|---|---|
|Developer Default (권장)|MySQL Server + Workbench + Shell + Router 등 개발 도구 전체 설치|
|Server only|MySQL Server만 설치 (워크벤치 별도 설치 필요)|
|Client only|클라이언트 도구만 설치 (서버 없음)|
|Custom|사용자가 직접 설치 항목 선택|

![](/assets/img/posts/2026-03-04-database-2-1772605700176.png)

![](/assets/img/posts/2026-03-04-database-2-1772605715583.png)

> 설치는 생각보다 오래 걸려요. 인내심을 갖고 기다려 주세요!!
{: .prompt-danger }
#### 【단계 3】 설치 진행

1. **[Execute]** 버튼 클릭 → 자동으로 의존성 패키지 설치 시작
2. Visual C++ Redistributable 등 필수 라이브러리 자동 설치됨
3. 모든 항목에 녹색 체크 표시 확인 후 **[Next]** 클릭

#### 【단계 4】 MySQL 서버 설정 (Configuration)

1. Config Type: **[Development Computer]** 선택 (개인 PC 실습 환경)
2. Port: `3306` 유지 (기본값)
3. Authentication Method: **[Use Strong Password Encryption]** 선택
4. Root Password 설정 ← **반드시 기억해야 함**
5. Windows Service Name: `MySQL80` 유지
6. **[Execute]** 클릭 → 서비스 등록 및 초기화 완료

> ⚠️ **중요: Root 비밀번호 관리**
> 
> - `root` 계정은 MySQL의 최고 관리자 계정임
> - 설정한 비밀번호를 잊으면 복구 절차가 복잡하므로 반드시 기록해 둘 것
> - 실습 환경에서는 간단한 비밀번호 사용 가능 (예: `1234` 또는 `mysql`)
> - 운영 환경에서는 반드시 복잡한 비밀번호 사용 필수

![](/assets/img/posts/2026-03-04-database-2-1772607213690.png)

![](/assets/img/posts/2026-03-04-database-2-1772607391751.png)


#### 【단계 5】 설치 완료 및 연결 테스트

1. MySQL Workbench 실행
2. **[MySQL Connections]** 항목의 **[Local instance MySQL80]** 클릭(설정에 따라 다름)
3. 설치 시 설정한 root 비밀번호 입력
4. 연결 성공 시 쿼리 편집기 화면 표시됨

### 1.3.3 MySQL Workbench 화면 구성

# 2장. 데이터 생성·조회·수정·삭제하기

## 2.1 데이터 CRUD란

**CRUD는 데이터베이스에서 수행하는 4가지 기본 데이터 조작 작업의 약자임. 모든 데이터 처리 시스템의 핵심 기능 집합임.**

![](/assets/img/posts/2026-03-04-database-2-1772605083578.png)



|CRUD|SQL 명령어|설명|
|---|---|---|
|Create (생성)|INSERT INTO|테이블에 새 데이터(행) 삽입|
|Read (조회)|SELECT|테이블에서 데이터 검색 및 출력|
|Update (수정)|UPDATE ... SET|기존 데이터 값 변경|
|Delete (삭제)|DELETE FROM|테이블에서 데이터(행) 제거|

> 💡 CRUD는 단순히 SQL 명령어의 분류가 아니라, 모든 데이터 처리 로직의 기본 틀임. REST API 설계(GET/POST/PUT/DELETE)와도 직접 대응됨.

---

## 2.2 데이터베이스 만들기

### 2.2.1 쿼리(Query) 개념

쿼리(Query)는 '문의하다', '질문하다'는 뜻으로, 데이터베이스에 특정 작업을 요청하는 SQL 명령문임. 하나의 쿼리는 반드시 세미콜론(`;`)으로 종료함.

---

### 2.2.2 데이터베이스 관리 명령어

|명령어|기능 및 예시|
|---|---|
|`SHOW DATABASES;`|현재 서버에 존재하는 모든 데이터베이스 목록 조회|
|`CREATE DATABASE db명;`|새 데이터베이스 생성. 예: `CREATE DATABASE shop;`|
|`USE db명;`|사용할 데이터베이스 선택·진입. 예: `USE shop;`|
|`DROP DATABASE db명;`|데이터베이스 완전 삭제 (복구 불가). 예: `DROP DATABASE shop;`|

```sql
-- 데이터베이스 목록 조회
SHOW DATABASES;

-- 새 데이터베이스 생성
CREATE DATABASE burger_db;

-- 해당 데이터베이스로 진입  ← 반드시 이 단계 실행 후 테이블 생성으로 넘어가야 함
USE burger_db;

-- 현재 선택된 DB 확인
SELECT DATABASE();
-- 출력: burger_db

-- 데이터베이스 삭제 (주의: 되돌릴 수 없음)
-- DROP DATABASE burger_db;
```

> ⚠️ **`USE` 없이 `CREATE TABLE`을 실행하면 "No database selected" 오류가 발생함.**  
> 테이블을 생성하기 전에 반드시 `USE 데이터베이스명;`으로 작업 대상 DB를 먼저 선택해야 함.

### 2.2.3 주석(Comment) 작성법

주석은 쿼리에 대한 설명을 기록하는 메모로, SQL 실행에 영향을 미치지 않음.

|주석 종류|작성 형식 및 설명|
|---|---|
|한 줄 주석|`-- 내용` (연속된 하이픈 두 개로 시작, 해당 줄 전체 주석 처리)|

```sql
*/
```

## 2.3 테이블 생성 및 데이터 삽입·조회

### 2.3.1 테이블 생성: CREATE TABLE

`burger_db`에 진입한 상태에서 `CREATE TABLE` 문으로 테이블을 정의함. 각 칼럼의 이름, 자료형, 제약 조건을 함께 지정함.

```sql
-- [사전 확인] 현재 선택된 DB가 burger_db인지 확인
SELECT DATABASE();  -- 출력: burger_db

-- burgers 테이블 생성
CREATE TABLE burgers (
    id      INT           NOT NULL AUTO_INCREMENT,  -- 자동 증가 정수 (기본키)
    name    VARCHAR(50)   NOT NULL,                 -- 버거 이름 (최대 50자)
    price   INT           NOT NULL,                 -- 가격 (원 단위)
    gram    INT,                                    -- 무게 (g), NULL 허용
    kcal    INT,                                    -- 열량 (kcal), NULL 허용
    protein DECIMAL(4,1),                           -- 단백질 (g, 소수점 1자리)
    PRIMARY KEY (id)
);
```

> **CREATE TABLE 주요 제약 조건 (Constraint)**
> 
> - `NOT NULL`: 해당 칼럼에 NULL 값 입력 불가 (필수 입력 항목)
> - `AUTO_INCREMENT`: 새 행 삽입 시 자동으로 1씩 증가하는 고유 번호 부여
> - `PRIMARY KEY`: 기본키 지정. 자동으로 NOT NULL + UNIQUE 속성 적용됨
> - `UNIQUE`: 중복 값 불가 (기본키와 달리 NULL은 허용)
> - `DEFAULT 값`: 입력 생략 시 자동으로 지정된 기본값 사용
> - `FOREIGN KEY`: 다른 테이블의 기본키를 참조하는 외래키 (참조 무결성 보장)

### 2.3.3 데이터 삽입: INSERT INTO

`INSERT INTO` 문으로 테이블에 새 행(row)을 추가함. 칼럼 순서와 값 순서를 반드시 일치시켜야 함.

> ⚠️ **아래 예제는 실습용 가상 데이터임. 실제 특정 브랜드의 영양 정보와 다를 수 있음.**

```sql
-- INSERT INTO 기본 구문
INSERT INTO 테이블명 (칼럼1, 칼럼2, ...) VALUES (값1, 값2, ...);

-- 단일 행 삽입 (id는 AUTO_INCREMENT이므로 생략 → 자동으로 1 할당)
INSERT INTO burgers (name, price, gram, kcal, protein)
VALUES ('클래식버거', 5500, 200, 520, 25.0);

-- 여러 행 동시 삽입 (id: 2, 3, 4 순서로 자동 할당)
INSERT INTO burgers (name, price, gram, kcal, protein) VALUES
    ('불고기버거', 3400, 145, 365, 14.2),  -- id = 2
    ('새우버거',   4000, 163, 418, 16.0),  -- id = 3
    ('치즈버거',   3000, 120, 360, 18.5);  -- id = 4

-- 삽입 결과 확인
SELECT * FROM burgers;
```

**삽입 후 예상 결과:**

![](/assets/img/posts/2026-03-04-database-1-1-1772849467491.png)

> 💡 **[Fact]** `AUTO_INCREMENT`로 지정된 `id` 칼럼은 INSERT 시 생략하면 자동으로 1씩 증가하는 값이 삽입됨. 이후 UPDATE/DELETE 예제에서 이 id 값을 기준으로 조건을 지정하므로 데이터를 정확히 삽입했는지 `SELECT *`로 반드시 확인할 것.

### 2.3.4 데이터 조회: SELECT

`SELECT` 문은 SQL에서 가장 자주 사용되는 명령어로, 테이블에서 원하는 데이터를 검색하여 반환함.

```sql
-- SELECT 기본 구문
SELECT 칼럼1, 칼럼2 FROM 테이블명 [WHERE 조건];

-- 모든 칼럼 조회 (* 는 모든 칼럼 의미)
SELECT * FROM burgers;

-- 특정 칼럼만 조회
SELECT name, price FROM burgers;

-- 조건 있는 조회 (price가 4000원 이상인 버거)
SELECT * FROM burgers WHERE price >= 4000;

-- id로 특정 행 조회 (클래식버거)
SELECT * FROM burgers WHERE id = 1;
```

> **SELECT 문 주요 절(Clause) 정리**
> 
> - `SELECT 칼럼명` : 조회할 칼럼 지정 (`*` 는 전체 칼럼)
> - `FROM 테이블명` : 데이터를 가져올 테이블 지정
> - `WHERE 조건` : 특정 조건을 만족하는 행만 필터링
> - `ORDER BY 칼럼` : 결과를 특정 칼럼 기준으로 정렬 (`ASC` 오름차순, `DESC` 내림차순)
> - `LIMIT n` : 최대 n개의 행만 반환
> - `AS 별칭` : 칼럼이나 테이블에 임시 별칭 부여

## 2.4 데이터 수정 및 삭제

### 2.4.1 데이터 수정: UPDATE

`UPDATE` 문으로 테이블의 기존 데이터를 변경함. **WHERE 절 없이 실행하면 전체 행이 수정**되므로 반드시 조건을 명시해야 함.

```sql
-- UPDATE 기본 구문
UPDATE 테이블명 SET 칼럼명 = 새값 [WHERE 조건];

-- id=1인 '클래식버거'의 가격을 5800원으로 변경
UPDATE burgers SET price = 5800 WHERE id = 1;

-- 여러 칼럼 동시 수정: id=1의 가격과 열량을 함께 변경
UPDATE burgers SET price = 5800, kcal = 530 WHERE id = 1;

-- 수정 결과 확인
SELECT * FROM burgers WHERE id = 1;
-- 출력: 1 | 클래식버거 | 5800 | 200 | 530 | 25.0

-- ⚠️ 위험: WHERE 절 없이 실행하면 모든 행의 price가 5800으로 변경됨
-- UPDATE burgers SET price = 5800;  ← 절대 주의!
```

![](/assets/img/posts/2026-03-04-database-1-1-1772849514715.png)

> ⚠️ **MySQL 안전 모드(Safe Update Mode) 안내**
> 
> - MySQL Workbench는 기본적으로 Safe Update Mode가 활성화되어 있음
> - WHERE 절에 기본키(PK) 조건 없이 UPDATE/DELETE 실행 시 오류 발생
> - 전체 데이터 수정이 필요한 경우: `SET SQL_SAFE_UPDATES = 0;` 으로 임시 해제 가능
> - 작업 후 `SET SQL_SAFE_UPDATES = 1;` 로 다시 활성화 권장
> - **[Opinion]** 실무에서는 Safe Update Mode를 항상 켜두는 것을 강력 권장함

---

### 2.4.2 데이터 삭제: DELETE

`DELETE` 문으로 테이블에서 특정 행을 삭제함. **WHERE 절 없이 실행하면 테이블의 모든 데이터가 삭제**되므로 극히 주의해야 함.

```sql
-- DELETE 기본 구문
DELETE FROM 테이블명 [WHERE 조건];

-- 삭제 전 현재 상태 확인
SELECT * FROM burgers;
-- id=3이 '새우버거'임을 확인

-- id=3인 '새우버거' 삭제
DELETE FROM burgers WHERE id = 3;

-- 삭제 결과 확인
SELECT * FROM burgers;
-- 출력: id 1(클래식버거), 2(불고기버거), 4(치즈버거) — id=3 행이 사라진 것을 확인

-- ⚠️ 테이블의 모든 데이터 삭제 (구조는 유지됨)
-- DELETE FROM burgers;

-- TRUNCATE: DELETE보다 빠르게 전체 데이터 삭제 (로그 미기록)
-- TRUNCATE TABLE burgers;
```

![](/assets/img/posts/2026-03-04-database-1-1-1772849559156.png)

> 💡 DELETE 후 id=3은 재사용되지 않음. 다음 INSERT 시 id는 다음 번호부터 시작함. AUTO_INCREMENT는 한 번 사용된 번호를 재사용하지 않는 것이 기본 동작임.

---

### 2.4.3 테이블 삭제: DROP TABLE

`DROP TABLE` 문은 테이블의 데이터뿐만 아니라 테이블 구조 자체를 완전히 삭제함. 실행 후 **되돌릴 수 없음**.

```sql
-- 테이블 완전 삭제 (구조 포함, 복구 불가)
DROP TABLE burgers;

-- 존재할 경우에만 삭제 (오류 방지)
DROP TABLE IF EXISTS burgers;
```

|명령어|삭제 대상|테이블 구조 유지|
|---|---|---|
|DELETE FROM|조건에 맞는 행(데이터)|유지됨|
|TRUNCATE TABLE|모든 행(데이터 전체)|유지됨|
|DROP TABLE|테이블 전체 (구조 포함)|삭제됨|

> 💡 **[Opinion]** DROP은 테이블 구조 자체를 제거하므로 운영 DB에서는 반드시 백업 후 실행해야 함. 실습 환경에서도 의도치 않은 DROP을 방지하기 위해 습관적으로 `IF EXISTS`를 붙이는 것을 권장함.
