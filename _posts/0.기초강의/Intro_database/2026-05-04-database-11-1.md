# 11-1 백업 — `mysqldump` 완전 실습

> 이번 시간 학습 목표
> - **왜 백업이 필요한지** 를 사례로 이해한다.
> - **논리 백업** 과 **물리 백업** 의 차이를 설명할 수 있다.
> - Windows 11에서 `mysqldump` 로 DB를 백업할 수 있다.
> - Python 스크립트로 백업을 자동 실행할 수 있다.
{: .prompt-tip }

---

## 1. 왜 백업이 필요한가?

다음 시나리오 중 **하나라도 일어날 수 있다.**

1. 실수로 `DELETE FROM users;` 를 WHERE 없이 실행해 버림
2. 디스크가 갑자기 고장 나서 MySQL이 켜지지 않음
3. 10-3에서 본 SQL Injection으로 데이터가 삭제됨
4. 랜섬웨어가 PC의 파일을 암호화함
5. 보안 설정 실수로 서비스 전체 DB가 외부에 공개됨

> 💡 백업은 "만약의 상황" 을 위한 것이 아니라, **"언젠가 반드시 일어날 상황"** 을 위한 것이다.  
> 실무에서는 **"백업이 없는 DB는 곧 사라질 DB"** 라고 말한다.
{: .prompt-info }

---

## 2. 백업의 종류

### 2-1. 논리 백업 vs 물리 백업

| 구분 | 논리 백업 (Logical) | 물리 백업 (Physical) |
|---|---|---|
| 저장 내용 | **SQL 문장**(CREATE/INSERT) 의 모음 | DB의 **파일 자체**를 복사 |
| 도구 | `mysqldump` | 파일 복사, `xtrabackup` |
| 파일 형식 | `.sql` 텍스트 | 바이너리 |
| 속도 | 상대적으로 느림 | 빠름 |
| 복구 유연성 | 높음 (다른 버전에도 복구 가능) | 낮음 |
| 이번 수업 | ✅ 이걸 배운다 | 참고 (실무용) |

### 2-2. 전체 / 부분 / 증분

- **전체 백업(Full)** — 매번 전체를 통째로 백업
- **부분 백업(Differential)** — 마지막 전체 백업 이후 바뀐 것만
- **증분 백업(Incremental)** — 마지막 백업(어떤 종류든) 이후 바뀐 것만

수업에서는 **전체 백업** 을 다룬다.

---

## 3. `mysqldump` 란?

- MySQL을 설치하면 기본으로 딸려오는 **명령줄 도구**.
- DB 구조(`CREATE TABLE`) 와 데이터(`INSERT`)를 모두 포함한 **텍스트 SQL 파일** 을 만들어 준다.

### 3-1. Windows 11에서 경로 확인

MySQL 8.x를 기본 설치했다면 대체로:

```
C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe
```

이 경로가 **PATH** 에 잡혀 있어야 `mysqldump` 명령이 어디서든 실행된다.

### 3-2. PATH 확인 및 등록

**시작 → cmd** 후:

```bash
mysqldump --version
```

결과가 정상 출력되면 OK. 만약 `'mysqldump'은(는) 내부 또는 외부 명령...` 라고 나오면:

1. **시작 → "환경 변수 편집" 검색**
2. **사용자 환경 변수 → Path → 편집 → 새로 만들기**
3. `C:\Program Files\MySQL\MySQL Server 8.0\bin` 추가 → 확인
4. cmd를 **완전히 닫았다가 다시 연 뒤** 위 명령을 다시 실행

## 4. 첫 번째 백업 — 전체 백업

### 4-1. 백업 저장 폴더 만들기

Windows 11 탐색기에서 다음 폴더를 만든다.

```
C:\db_backup\
```

### 4-2. 특정 DB 한 개 백업

9-1에서 만든 `view_db` 를 통째로 백업한다.  
**cmd** 에서:

```bash
mysqldump -u root -p view_db > C:\db_backup\view_db.sql
```

비밀번호를 묻는 창이 뜨면 입력한다. 몇 초 뒤 종료되면:

```bash
dir C:\db_backup
```

`view_db.sql` 파일이 있으면 성공.

### 4-3. 백업 파일 열어 보기

메모장 또는 VS Code로 `view_db.sql` 을 연다. 대략 아래 같은 구조다.

```sql
-- MySQL dump 10.13  Distrib 8.0.xx, for Win64
-- Host: localhost    Database: view_db
-- ------------------------------------------------------
-- Server version 8.0.xx

...

DROP TABLE IF EXISTS `students`;
CREATE TABLE `students` (
  `id` int NOT NULL AUTO_INCREMENT,
  ...
) ENGINE=InnoDB ...;

INSERT INTO `students` VALUES (1,'2026001','김민준',...);
INSERT INTO `students` VALUES (2,'2026002','이서연',...);
...
```

> 💡 이 파일은 **완전히 사람이 읽을 수 있는 SQL** 이다.  
> 나중에 이 파일을 `mysql < view_db.sql` 로 실행하면 DB가 그대로 재생성된다.
{: .prompt-info }

## 5. 백업 옵션 — 자주 쓰는 것 정리

### 5-1. 여러 DB 한 번에 백업

```bash
mysqldump -u root -p --databases view_db injection_lab > C:\db_backup\multi.sql
```

### 5-2. 모든 DB 백업

```bash
mysqldump -u root -p --all-databases > C:\db_backup\all.sql
```

### 5-3. 특정 테이블만 백업

```bash
mysqldump -u root -p view_db students scores > C:\db_backup\view_db_some_tables.sql
```

### 5-4. 데이터 없이 구조(스키마)만 백업

```bash
mysqldump -u root -p --no-data view_db > C:\db_backup\view_db_schema.sql
```

### 5-5. 구조 없이 데이터만 백업

```bash
mysqldump -u root -p --no-create-info view_db > C:\db_backup\view_db_data.sql
```

### 5-6. 주요 옵션 표

| 옵션 | 의미 |
|---|---|
| `-u 사용자` | 접속 사용자 |
| `-p` | 비밀번호 입력 프롬프트 표시 |
| `--databases` | 여러 DB 지정 (CREATE DATABASE 구문 포함) |
| `--all-databases` | 전체 DB 백업 |
| `--no-data` | 스키마만 |
| `--no-create-info` | 데이터만 |
| `--routines` | 저장 프로시저/함수 포함 |
| `--events` | 이벤트 포함 |
| `--single-transaction` | InnoDB에서 **락 없이 일관된 백업** (추천) |

## 6. 파일명에 날짜 넣기 (수동)

백업 파일은 **언제 찍은 것인지** 가 핵심이다.

```bash
mysqldump -u root -p view_db > C:\db_backup\view_db_2026-05-04.sql
```

> ⚠️ 같은 이름으로 덮어쓰면 **지난번 백업이 날아간다.**  
> 반드시 날짜/시각을 파일명에 포함하자.
{: .prompt-warning }

## 7. 스케줄링 — 매일 자동으로 백업

Windows 11에는 **작업 스케줄러** 가 내장되어 있다. 수업 시간에는 원리만 소개하고,  
다음 시간(11-2) 에서 **Python 스크립트로** 편하게 자동화한다.

### 작업 스케줄러 간단 소개

1. **시작 → "작업 스케줄러" 실행**
2. **기본 작업 만들기**
3. 이름: `MySQL Daily Backup`
4. 트리거: **매일 새벽 2시**
5. 동작: **프로그램 시작** → 다음 시간에 만드는 `backup.py` 선택

## 8. Python으로 `mysqldump` 호출하기

Python의 `subprocess` 모듈을 쓰면 명령어를 코드에서 실행할 수 있다.

### 8-1. 기본 호출 스크립트

`C:\db_practice\week11\backup_basic.py`:

```python
# backup_basic.py
import subprocess
from datetime import datetime
from pathlib import Path

BACKUP_DIR = Path(r"C:\db_backup")
BACKUP_DIR.mkdir(parents=True, exist_ok=True)

# 1) 파일명에 타임스탬프 포함
timestamp = datetime.now().strftime("%Y%m%d_%H%M%S")
target_db = "view_db"
out_file  = BACKUP_DIR / f"{target_db}_{timestamp}.sql"

# 2) mysqldump 실행
#    - 비밀번호는 -p뒤에 붙여 쓰면 바로 주입되지만,
#      실무에서는 my.cnf에 저장하거나 환경변수를 쓴다.
cmd = [
    "mysqldump",
    "-u", "root",
    "-p본인_비밀번호",           # 비번 바로 주입 (쉼표/공백 없이 -p에 붙임)
    "--single-transaction",
    target_db
]

with out_file.open("w", encoding="utf-8") as f:
    result = subprocess.run(cmd, stdout=f, stderr=subprocess.PIPE, text=True)

if result.returncode == 0:
    print(f"[OK] 백업 성공 → {out_file}")
else:
    print("[FAIL] 백업 실패")
    print(result.stderr)
```

### 8-2. 실행

```bash
cd C:\db_practice\week11
python backup_basic.py
```

`C:\db_backup\` 폴더에 `view_db_20260504_140000.sql` 같은 파일이 생기면 성공.

### 8-3. 보안 팁

> ⚠️ Python 파일에 비밀번호를 그대로 적어 두는 건 **실무에서 금기** 다.  
> 다음 시간(11-2)에서는 환경변수/`my.cnf` 를 이용해 비밀번호를 코드 밖으로 빼는 방법을 배운다.
{: .prompt-warning }

## 9. 실습 과제

### 과제 1
`view_db` 의 **스키마만**, `injection_lab` 의 **데이터만** 각각 별도의 `.sql` 로 백업하는 명령을 작성하시오.

**정답**

```bash
mysqldump -u root -p --no-data view_db > C:\db_backup\view_db_schema.sql
mysqldump -u root -p --no-create-info injection_lab > C:\db_backup\injection_lab_data.sql
```

### 과제 2
`backup_basic.py` 를 수정하여 **여러 DB(`view_db`, `injection_lab`)를 각각 별도의 파일로** 백업하도록 바꾸시오.

**정답 예시**

```python
for db in ["view_db", "injection_lab"]:
    out_file = BACKUP_DIR / f"{db}_{timestamp}.sql"
    cmd = ["mysqldump", "-u", "root", "-p본인_비밀번호",
           "--single-transaction", db]
    with out_file.open("w", encoding="utf-8") as f:
        subprocess.run(cmd, stdout=f, check=True)
    print(f"[OK] {db} 백업 완료")
```

### 과제 3
`mysqldump` 가 만든 `.sql` 파일을 메모장으로 열어, `CREATE TABLE` 과 `INSERT` 가 모두 들어 있는지 스크린샷으로 기록하시오.

## 10. 정리

- 백업은 **선택**이 아니라 **기본 습관** 이다.
- 수업에서 다루는 **논리 백업** 은 `mysqldump` 로 한다.
- 파일명에 **날짜·시각** 을 꼭 넣는다.
- Python의 `subprocess` 로 mysqldump를 호출하면 자동화의 시작이다.

다음 시간([11-2](/posts/database-11-2))에는  
1) 이 파일로 **복구(Restore)** 하는 법  
2) 비밀번호를 숨기고  
3) 오래된 백업을 자동 정리하는  
"현실적인 백업 자동화 스크립트" 를 완성한다.
