# 10-1 DB를 처음부터 만들며 배우는 SQL 명령어 분류

> 이번 시간 학습 목표
> - 빈 MySQL 환경에서 실습용 데이터베이스를 직접 만든다.
> - `CREATE`, `ALTER`, `INSERT`, `UPDATE`, `DELETE`, `COMMIT`, `ROLLBACK`, `GRANT`를 순서대로 실행한다.
> - SQL 명령어를 **DDL / DML / DCL / TCL**로 분류하고, 각 용어의 의미를 설명할 수 있다.
> - `WHERE` 없는 변경 명령과 과도한 권한 부여가 왜 위험한지 이해한다.

## 1. 실습 전에 알아야 할 기본 용어

처음 데이터베이스를 배우면 SQL 문법보다 용어가 먼저 헷갈린다. 이번 실습에서 계속 사용할 용어를 먼저 정리한다.

| 용어 | 의미 |
|---|---|
| **DBMS** | Database Management System. 데이터베이스를 만들고 관리하는 소프트웨어. MySQL이 대표적인 DBMS이다. |
| **데이터베이스(Database)** | 관련 있는 테이블을 모아 둔 논리적 공간. MySQL에서는 `CREATE DATABASE`로 만든다. |
| **테이블(Table)** | 데이터를 행과 열 형태로 저장하는 구조. 엑셀의 시트와 비슷하게 생각할 수 있다. |
| **행(Row, Record)** | 테이블에 저장된 데이터 한 건. 예: 학생 1명의 정보. |
| **열(Column, Field)** | 데이터의 속성. 예: 이름, 학번, 학년, 전화번호. |
| **스키마(Schema)** | 테이블 이름, 열 이름, 자료형, 제약 조건 같은 데이터 구조의 설계 정보. MySQL에서는 데이터베이스와 비슷한 의미로도 자주 쓰인다. |
| **자료형(Data Type)** | 열에 저장할 수 있는 값의 종류. 예: `INT`, `VARCHAR(30)`, `DATE`. |
| **제약 조건(Constraint)** | 잘못된 데이터가 들어가지 않도록 거는 규칙. 예: `PRIMARY KEY`, `NOT NULL`, `UNIQUE`. |
| **기본 키(Primary Key)** | 한 행을 유일하게 구분하는 열. 중복될 수 없고 비어 있을 수 없다. |
| **SQL** | Structured Query Language. 관계형 데이터베이스에 명령을 내리는 표준 언어. |

## 2. SQL 명령어 네 가지 분류

SQL은 모두 같은 문장처럼 보이지만 역할이 다르다. 실무와 시험에서는 이 역할을 구분하는 것이 중요하다.

| 분류 | 전체 이름 | 뜻 | 대표 명령어 |
|---|---|---|---|
| **DDL** | Data Definition Language | 데이터 구조를 정의하는 명령어 | `CREATE`, `ALTER`, `DROP`, `TRUNCATE` |
| **DML** | Data Manipulation Language | 테이블 안의 데이터를 조회, 입력, 수정, 삭제하는 명령어 | `SELECT`, `INSERT`, `UPDATE`, `DELETE` |
| **DCL** | Data Control Language | 사용자 권한을 부여하거나 회수하는 명령어 | `GRANT`, `REVOKE` |
| **TCL** | Transaction Control Language | 작업 묶음을 확정하거나 취소하는 명령어 | `COMMIT`, `ROLLBACK`, `SAVEPOINT` |

짧게 외우면 다음과 같다.

- **DDL**: 구조를 만든다.
- **DML**: 데이터를 다룬다.
- **DCL**: 권한을 통제한다.
- **TCL**: 변경 사항을 확정하거나 되돌린다.

> 실습 흐름도 이 순서로 진행한다. 먼저 구조를 만들고(DDL), 데이터를 넣고 바꾸며(DML), 실수했을 때 되돌리는 법을 보고(TCL), 마지막으로 누가 접근할 수 있는지 제한한다(DCL).
{: .prompt-info }

## 4. DDL 실습 1: 데이터베이스 만들기

먼저 실습용 데이터베이스를 완전히 새로 만든다.

```sql
DROP DATABASE IF EXISTS school_sql_lab;
CREATE DATABASE school_sql_lab
    DEFAULT CHARACTER SET utf8mb4
    DEFAULT COLLATE utf8mb4_0900_ai_ci;
USE school_sql_lab;
```

각 문장의 의미는 다음과 같다.

| SQL | 분류 | 의미 |
|---|---|---|
| `DROP DATABASE IF EXISTS school_sql_lab` | DDL | 같은 이름의 DB가 있으면 삭제한다. 반복 실습을 위해 사용한다. |
| `CREATE DATABASE school_sql_lab` | DDL | 새 데이터베이스를 만든다. |
| `USE school_sql_lab` | 기타 | 앞으로 실행할 명령의 기본 DB를 선택한다. |

> `DROP`은 삭제 명령이다. 실습용 DB가 아닌 실제 DB 이름으로 실행하면 데이터가 사라질 수 있다. 수업에서는 반드시 실습용 이름을 확인하고 실행한다.
{: .prompt-warning }

## 5. DDL 실습 2: 테이블 만들기

학생 정보를 저장할 `students` 테이블을 만든다.

```sql
CREATE TABLE students (
    student_id INT PRIMARY KEY AUTO_INCREMENT,
    student_no VARCHAR(10) NOT NULL UNIQUE,
    name VARCHAR(30) NOT NULL,
    grade INT NOT NULL,
    class_name VARCHAR(10) NOT NULL,
    phone VARCHAR(20),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

### 5-1. 문법 해설

| 부분 | 의미 |
|---|---|
| `CREATE TABLE students` | `students`라는 테이블을 만든다. |
| `student_id INT` | 정수형 열을 만든다. |
| `PRIMARY KEY` | 이 열을 행을 구분하는 기본 키로 지정한다. |
| `AUTO_INCREMENT` | 새 행이 들어올 때 숫자를 자동으로 1씩 증가시킨다. |
| `VARCHAR(10)` | 최대 10글자까지 저장할 수 있는 문자열 자료형이다. |
| `NOT NULL` | 값이 비어 있으면 안 된다는 뜻이다. |
| `UNIQUE` | 중복 값을 허용하지 않는다는 뜻이다. |
| `DEFAULT CURRENT_TIMESTAMP` | 값을 넣지 않으면 현재 시각을 자동으로 저장한다. |

테이블 구조를 확인한다.

```sql
DESC students;
```

예상 결과:

```text
+------------+--------------+------+-----+-------------------+-------------------+
| Field      | Type         | Null | Key | Default           | Extra             |
+------------+--------------+------+-----+-------------------+-------------------+
| student_id | int          | NO   | PRI | NULL              | auto_increment    |
| student_no | varchar(10)  | NO   | UNI | NULL              |                   |
| name       | varchar(30)  | NO   |     | NULL              |                   |
| grade      | int          | NO   |     | NULL              |                   |
| class_name | varchar(10)  | NO   |     | NULL              |                   |
| phone      | varchar(20)  | YES  |     | NULL              |                   |
| created_at | datetime     | YES  |     | CURRENT_TIMESTAMP | DEFAULT_GENERATED |
+------------+--------------+------+-----+-------------------+-------------------+
```

`DESC`는 `DESCRIBE`의 줄임말이며, 테이블의 열 이름, 자료형, NULL 허용 여부, 키 정보를 보여 준다.

## 6. DDL 실습 3: 테이블 구조 변경하기

실제 개발에서는 처음 만든 테이블 구조가 그대로 끝나지 않는다. 요구사항이 바뀌면 열을 추가하거나 이름과 자료형을 바꾼다.

### 6-1. 열 추가: `ALTER TABLE ... ADD COLUMN`

```sql
ALTER TABLE students ADD COLUMN email VARCHAR(100);
DESC students;
```

예상 결과에서 마지막에 `email` 열이 추가되어야 한다.

```text
| email | varchar(100) | YES |     | NULL | |
```

`ALTER TABLE`은 이미 존재하는 테이블 구조를 바꾸는 DDL 명령어이다.

### 6-2. 열 이름 변경: `CHANGE COLUMN`

`class_name`을 더 명확한 이름인 `class_room`으로 바꾼다.

```sql
ALTER TABLE students
CHANGE COLUMN class_name class_room VARCHAR(10) NOT NULL;

DESC students;
```

예상 결과:

```text
| class_room | varchar(10) | NO |     | NULL | |
```

기존 `class_name`은 사라지고 `class_room`이 보여야 한다.

`CHANGE COLUMN 기존이름 새이름 자료형` 순서로 작성한다. MySQL에서는 이름만 바꿀 때도 자료형을 함께 써야 한다.

### 6-3. 자료형 변경: `MODIFY COLUMN`

전화번호 길이를 조금 더 넉넉하게 바꾼다.

```sql
ALTER TABLE students
MODIFY COLUMN phone VARCHAR(30);

DESC students;
```

예상 결과:

```text
| phone | varchar(30) | YES |     | NULL | |
```

### 6-4. 임시 테이블 만들고 삭제하기

`DROP TABLE`은 테이블 자체를 삭제한다.

```sql
CREATE TABLE temp_memo (
    id INT PRIMARY KEY AUTO_INCREMENT,
    memo VARCHAR(100)
);

SHOW TABLES;

DROP TABLE temp_memo;

SHOW TABLES;
```

예상 결과:

```text
-- DROP TABLE 실행 전 SHOW TABLES
+--------------------------+
| Tables_in_school_sql_lab |
+--------------------------+
| students                 |
| temp_memo                |
+--------------------------+

-- DROP TABLE 실행 후 SHOW TABLES
+--------------------------+
| Tables_in_school_sql_lab |
+--------------------------+
| students                 |
+--------------------------+
```

> `DROP TABLE`은 테이블 구조와 데이터가 모두 사라진다. `DELETE`처럼 특정 행만 지우는 명령이 아니다.
{: .prompt-warning }

## 7. DML 실습 1: 데이터 입력하기

이제 테이블 안에 학생 데이터를 넣는다.

```sql
INSERT INTO students (student_no, name, grade, class_room, phone, email)
VALUES
('2026001', '김민준', 3, '3-1', '010-1111-2222', 'minjun@example.com'),
('2026002', '이서연', 3, '3-2', '010-2222-3333', 'seoyeon@example.com'),
('2026003', '박지호', 2, '2-1', '010-3333-4444', 'jiho@example.com'),
('2026004', '최하은', 1, '1-1', '010-4444-5555', 'haeun@example.com');
```

`INSERT`는 DML이다. 테이블 구조는 바꾸지 않고, 테이블 안의 행을 추가한다.

입력된 데이터를 확인한다.

```sql
SELECT * FROM students;
```

예상 결과:

```text
+------------+------------+--------+-------+------------+---------------+---------------------+---------------------+
| student_id | student_no | name   | grade | class_room | phone         | created_at          | email               |
+------------+------------+--------+-------+------------+---------------+---------------------+---------------------+
|          1 | 2026001    | 김민준 |     3 | 3-1        | 010-1111-2222 | 2026-.. ..:..:..    | minjun@example.com  |
|          2 | 2026002    | 이서연 |     3 | 3-2        | 010-2222-3333 | 2026-.. ..:..:..    | seoyeon@example.com |
|          3 | 2026003    | 박지호 |     2 | 2-1        | 010-3333-4444 | 2026-.. ..:..:..    | jiho@example.com    |
|          4 | 2026004    | 최하은 |     1 | 1-1        | 010-4444-5555 | 2026-.. ..:..:..    | haeun@example.com   |
+------------+------------+--------+-------+------------+---------------+---------------------+---------------------+
```

`created_at` 값은 실행한 날짜와 시각으로 표시되므로 예시와 달라도 정상이다.

## 8. DML 실습 2: 데이터 조회하기

`SELECT`는 데이터를 조회하는 DML이다. 데이터베이스 실무에서 가장 많이 사용하는 명령어다.

### 8-1. 전체 조회

```sql
SELECT * FROM students;
```

`*`는 모든 열을 의미한다.

### 8-2. 필요한 열만 조회

```sql
SELECT student_no, name, grade, class_room
FROM students;
```

실제 서비스에서는 불필요한 열을 모두 가져오지 않는 것이 좋다. 특히 주민등록번호, 비밀번호 해시, 전화번호 같은 민감 정보는 필요한 경우에만 조회해야 한다.

### 8-3. 조건 조회: `WHERE`

```sql
SELECT student_no, name, class_room
FROM students
WHERE grade = 3;
```

예상 결과:

```text
+------------+--------+------------+
| student_no | name   | class_room |
+------------+--------+------------+
| 2026001    | 김민준 | 3-1        |
| 2026002    | 이서연 | 3-2        |
+------------+--------+------------+
```

`WHERE`는 조건을 지정한다. 조건에 맞는 행만 조회하거나 수정하거나 삭제할 때 사용한다.

### 8-4. 정렬: `ORDER BY`

```sql
SELECT student_no, name, grade, class_room
FROM students
ORDER BY grade DESC, student_no ASC;
```

`DESC`는 내림차순, `ASC`는 오름차순이다.

## 9. DML 실습 3: 데이터 수정하기

`UPDATE`는 기존 행의 값을 수정하는 DML이다.

```sql
UPDATE students
SET phone = '010-9999-0000'
WHERE student_no = '2026002';

SELECT * FROM students WHERE student_no = '2026002';
```

예상 결과:

```text
+------------+------------+--------+-------+------------+---------------+---------------------+---------------------+
| student_id | student_no | name   | grade | class_room | phone         | created_at          | email               |
+------------+------------+--------+-------+------------+---------------+---------------------+---------------------+
|          2 | 2026002    | 이서연 |     3 | 3-2        | 010-9999-0000 | 2026-.. ..:..:..    | seoyeon@example.com |
+------------+------------+--------+-------+------------+---------------+---------------------+---------------------+
```

`WHERE` 없이 `UPDATE`를 실행하면 모든 행이 바뀐다.

```sql
-- 실행하지 말고 읽기만 하자.
-- UPDATE students SET grade = 3;
```

> `UPDATE`와 `DELETE`를 실행하기 전에는 먼저 같은 조건으로 `SELECT`를 해 본다. 바뀌거나 삭제될 행이 맞는지 확인한 뒤 실행하는 습관이 중요하다.
{: .prompt-warning }

## 10. DML 실습 4: 데이터 삭제하기

`DELETE`는 테이블 안의 행을 삭제하는 DML이다.

삭제 전 대상을 먼저 확인한다.

```sql
SELECT *
FROM students
WHERE student_no = '2026004';
```

확인한 뒤 삭제한다.

```sql
DELETE FROM students
WHERE student_no = '2026004';

SELECT * FROM students;
```

예상 결과:

```text
+------------+------------+--------+-------+------------+---------------+---------------------+---------------------+
| student_id | student_no | name   | grade | class_room | phone         | created_at          | email               |
+------------+------------+--------+-------+------------+---------------+---------------------+---------------------+
|          1 | 2026001    | 김민준 |     3 | 3-1        | 010-1111-2222 | 2026-.. ..:..:..    | minjun@example.com  |
|          2 | 2026002    | 이서연 |     3 | 3-2        | 010-9999-0000 | 2026-.. ..:..:..    | seoyeon@example.com |
|          3 | 2026003    | 박지호 |     2 | 2-1        | 010-3333-4444 | 2026-.. ..:..:..    | jiho@example.com    |
+------------+------------+--------+-------+------------+---------------+---------------------+---------------------+
```

`DELETE`는 테이블 구조를 없애지 않는다. 행만 삭제한다.

## 11. DDL과 DML 비교: `TRUNCATE`와 `DELETE`

`DELETE`와 `TRUNCATE`는 모두 데이터를 지우는 것처럼 보이지만 분류와 동작이 다르다.

```sql
CREATE TABLE delete_test (
    id INT PRIMARY KEY AUTO_INCREMENT,
    memo VARCHAR(50)
);

INSERT INTO delete_test (memo)
VALUES ('A'), ('B'), ('C');

SELECT * FROM delete_test;
```

먼저 `DELETE`를 사용한다.

```sql
DELETE FROM delete_test WHERE id = 1;
SELECT * FROM delete_test;
```

이번에는 테이블을 통째로 비운다.

```sql
TRUNCATE TABLE delete_test;
SELECT * FROM delete_test;
```

예상 결과:

```text
-- INSERT 직후
+----+------+
| id | memo |
+----+------+
|  1 | A    |
|  2 | B    |
|  3 | C    |
+----+------+

-- DELETE FROM delete_test WHERE id = 1 실행 후
+----+------+
| id | memo |
+----+------+
|  2 | B    |
|  3 | C    |
+----+------+

-- TRUNCATE TABLE delete_test 실행 후
Empty set
```

| 명령어 | 분류 | 의미 |
|---|---|---|
| `DELETE` | DML | 조건에 맞는 행을 삭제한다. `WHERE`를 사용할 수 있다. |
| `TRUNCATE` | DDL | 테이블을 비우고 저장 공간을 초기화한다. 보통 전체 삭제 용도로 사용한다. |

## 12. TCL 실습: 실수한 변경 되돌리기

### 12-1. 트랜잭션이란?

**트랜잭션(Transaction)**은 하나의 작업처럼 처리되어야 하는 SQL 묶음이다. 예를 들어 계좌 이체는 다음 두 작업이 함께 성공해야 한다.

1. A 계좌에서 10만 원 차감
2. B 계좌에 10만 원 추가

하나만 성공하면 데이터가 틀어진다. 그래서 둘 다 성공하면 `COMMIT`, 문제가 생기면 `ROLLBACK`으로 되돌린다.

| 용어 | 의미 |
|---|---|
| `START TRANSACTION` | 트랜잭션 시작 |
| `COMMIT` | 트랜잭션 안의 변경 사항을 확정 |
| `ROLLBACK` | 마지막 커밋 이후 변경 사항을 취소 |
| `SAVEPOINT` | 트랜잭션 중간에 되돌아갈 지점 표시 |
| `autocommit` | SQL 한 문장마다 자동으로 커밋할지 정하는 설정 |

### 12-2. `ROLLBACK` 실습

```sql
SET autocommit = 0;

START TRANSACTION;

UPDATE students
SET grade = 9
WHERE student_no = '2026001';

SELECT * FROM students WHERE student_no = '2026001';

ROLLBACK;

SELECT * FROM students WHERE student_no = '2026001';
```

예상 결과:

```text
-- ROLLBACK 전 SELECT 결과
| student_no | name   | grade |
| 2026001    | 김민준 | 9     |

-- ROLLBACK 후 SELECT 결과
| student_no | name   | grade |
| 2026001    | 김민준 | 3     |
```

`ROLLBACK` 후에는 `grade = 9` 변경이 사라진다.

### 12-3. `COMMIT` 실습

```sql
START TRANSACTION;

UPDATE students
SET grade = 3
WHERE student_no = '2026003';

COMMIT;

SELECT * FROM students WHERE student_no = '2026003';
```

예상 결과:

```text
| student_no | name   | grade |
| 2026003    | 박지호 | 3     |
```

`COMMIT` 후에는 변경 사항이 확정된다.

실습을 마치면 자동 커밋을 다시 켠다.

```sql
SET autocommit = 1;
```

> DML은 트랜잭션으로 되돌릴 수 있는 경우가 많다. 하지만 DDL은 MySQL에서 암묵적 커밋이 일어나는 명령이 많기 때문에 `CREATE`, `DROP`, `ALTER`를 쉽게 실행하면 안 된다.

## 13. DCL 맛보기: 조회 전용 계정 만들기

DCL은 권한을 제어하는 명령어이다. 자세한 계정 보안은 10-2에서 다루고, 여기서는 SQL 분류를 이해하기 위해 간단히 실행해 본다.

### 13-1. 사용자 계정 만들기

```sql
DROP USER IF EXISTS 'school_viewer'@'localhost';
CREATE USER 'school_viewer'@'localhost' IDENTIFIED BY 'Viewer_pw_1234!';
```

`CREATE USER`는 MySQL 사용자 계정을 만든다.

| 표현 | 의미 |
|---|---|
| `'school_viewer'` | 로그인할 사용자 이름 |
| `'localhost'` | 이 PC에서 접속할 때만 허용한다는 뜻 |
| `IDENTIFIED BY` | 비밀번호 지정 |

### 13-2. 조회 권한만 부여하기

```sql
GRANT SELECT ON school_sql_lab.students
TO 'school_viewer'@'localhost';

SHOW GRANTS FOR 'school_viewer'@'localhost';
```

예상 결과:

```text
+--------------------------------------------------------------------------------+
| Grants for school_viewer@localhost                                             |
+--------------------------------------------------------------------------------+
| GRANT USAGE ON *.* TO `school_viewer`@`localhost`                               |
| GRANT SELECT ON `school_sql_lab`.`students` TO `school_viewer`@`localhost`      |
+--------------------------------------------------------------------------------+
```

`GRANT`는 권한을 부여하는 DCL이다. 위 명령은 `school_viewer`가 `students` 테이블을 조회할 수만 있게 만든다.

### 13-3. 권한 회수하기

```sql
REVOKE SELECT ON school_sql_lab.students
FROM 'school_viewer'@'localhost';

SHOW GRANTS FOR 'school_viewer'@'localhost';
```

예상 결과:

```text
+--------------------------------------------------+
| Grants for school_viewer@localhost               |
+--------------------------------------------------+
| GRANT USAGE ON *.* TO `school_viewer`@`localhost` |
+--------------------------------------------------+
```

`REVOKE`는 부여했던 권한을 회수하는 DCL이다.

실습 계정을 정리한다.

```sql
DROP USER IF EXISTS 'school_viewer'@'localhost';
```

## 14. Python에서 DML 실행해 보기

Workbench에서 SQL을 실행하는 것과 Python 프로그램에서 SQL을 실행하는 것은 원리가 같다. 다만 프로그램에서는 사용자의 입력값을 SQL에 넣는 일이 많기 때문에 안전한 작성법이 중요하다.

아래 파일을 `C:\db_practice\week10\select_students.py`로 저장한다.

```python
import mysql.connector

conn = mysql.connector.connect(
    host="localhost",
    user="root",
    password="본인_root_비밀번호",
    database="school_sql_lab"
)

cursor = conn.cursor(dictionary=True)

grade = int(input("조회할 학년: "))

sql = """
SELECT student_no, name, grade, class_room
FROM students
WHERE grade = %s
ORDER BY student_no
"""

cursor.execute(sql, (grade,))

for row in cursor.fetchall():
    print(row)

cursor.close()
conn.close()
```

실행 예시:

```text
C:\db_practice\week10>python select_students.py
조회할 학년: 3
{'student_no': '2026001', 'name': '김민준', 'grade': 3, 'class_room': '3-1'}
{'student_no': '2026002', 'name': '이서연', 'grade': 3, 'class_room': '3-2'}
{'student_no': '2026003', 'name': '박지호', 'grade': 3, 'class_room': '2-1'}
```

앞에서 `2026003` 학생의 학년을 `COMMIT`했기 때문에 `grade`가 3으로 나온다.

여기서 `%s`는 문자열 포맷팅이 아니라 MySQL Connector의 **파라미터 자리 표시자**이다. 사용자의 입력값을 SQL 구조가 아니라 데이터 값으로 안전하게 전달한다. 이 내용은 10-3 SQL Injection 방어에서 다시 매우 중요하게 다룬다.

## 15. 전체 실습 요약

이번 시간에 실행한 명령어를 분류하면 다음과 같다.

| 실행한 명령어 | 분류 | 핵심 의미 |
|---|---|---|
| `CREATE DATABASE` | DDL | DB 생성 |
| `CREATE TABLE` | DDL | 테이블 생성 |
| `ALTER TABLE` | DDL | 테이블 구조 변경 |
| `DROP TABLE` | DDL | 테이블 삭제 |
| `TRUNCATE TABLE` | DDL | 테이블 데이터 전체 초기화 |
| `INSERT` | DML | 행 추가 |
| `SELECT` | DML | 행 조회 |
| `UPDATE` | DML | 행 수정 |
| `DELETE` | DML | 행 삭제 |
| `START TRANSACTION` | TCL | 트랜잭션 시작 |
| `COMMIT` | TCL | 변경 확정 |
| `ROLLBACK` | TCL | 변경 취소 |
| `CREATE USER` | 계정 관리 | 사용자 계정 생성 |
| `GRANT` | DCL | 권한 부여 |
| `REVOKE` | DCL | 권한 회수 |

## 16. 연습 문제

### 문제 1

`students` 테이블에 `address VARCHAR(200)` 열을 추가하는 SQL을 작성하시오. 이 명령은 DDL, DML, DCL, TCL 중 무엇인가?

**정답**

```sql
ALTER TABLE students ADD COLUMN address VARCHAR(200);
```

분류: **DDL**. 테이블 구조를 바꾸기 때문이다.

### 문제 2

`student_no`가 `2026003`인 학생의 전화번호를 `010-7777-8888`로 수정하는 SQL을 작성하시오. 실행 전 확인용 `SELECT`도 함께 작성하시오.

**정답**

```sql
SELECT * FROM students WHERE student_no = '2026003';

UPDATE students
SET phone = '010-7777-8888'
WHERE student_no = '2026003';
```

분류: `SELECT`, `UPDATE` 모두 **DML**이다.

### 문제 3

`DELETE`와 `TRUNCATE`의 차이를 한 문장으로 설명하시오.

**정답 예시**

`DELETE`는 조건에 맞는 행을 삭제하는 DML이고, `TRUNCATE`는 테이블을 통째로 비우는 DDL이다.

### 문제 4

`school_viewer` 계정에게 `students` 테이블 조회 권한만 부여하는 SQL을 작성하시오.

**정답**

```sql
GRANT SELECT ON school_sql_lab.students
TO 'school_viewer'@'localhost';
```

분류: **DCL**이다.

## 17. 정리

- SQL 명령어는 역할에 따라 **DDL, DML, DCL, TCL**로 나눈다.
- DDL은 구조를 만들고 바꾸는 명령이다.
- DML은 테이블 안의 데이터를 조회, 입력, 수정, 삭제하는 명령이다.
- TCL은 여러 DML 작업을 하나의 작업처럼 묶고 확정하거나 되돌리는 명령이다.
- DCL은 사용자에게 필요한 권한만 주고 필요 없으면 회수하는 명령이다.
- 다음 10-2에서는 DCL을 본격적으로 사용해 **처음부터 안전한 계정과 권한 구조**를 설계한다.
