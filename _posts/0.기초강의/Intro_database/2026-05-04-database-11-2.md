# 11-2 복구와 Python 자동화

> 이번 시간 학습 목표
> - `mysql` 명령 또는 Workbench로 `.sql` 백업 파일에서 **복구**할 수 있다.
> - **장애 시나리오**(실수 DELETE, DB 삭제)를 직접 복구하는 실습을 해 본다.
> - Python의 `subprocess` 로 **백업 + 복구 + 오래된 파일 정리** 를 자동화한다.
> - 비밀번호를 코드에서 빼는 **안전한 방법**을 이해한다.
{: .prompt-tip }

---

## 1. 복구의 기본 원리

`mysqldump` 가 만든 `.sql` 파일은 **SQL 문장의 모음** 이다.  
복구는 단순하다 — **그 파일의 SQL 문장을 MySQL에 그대로 실행**하면 된다.

```bash
mysql -u root -p 대상DB이름 < 백업파일.sql
```

> 💡 **부등호 `<` 의 방향에 주의**  
> - 백업: `mysqldump ... > file.sql` (오른쪽으로 내보냄)  
> - 복구: `mysql ... < file.sql` (왼쪽으로 들여옴)  
> 방향이 반대다. 한 끗 차이로 백업 파일을 날리지 말자.
{: .prompt-warning }

```bash
mysqldump -u root -p --single-transaction view_db > C:\db_backup\view_db_safety.sql
```

## 3. 장애 시나리오 A — 실수로 `DELETE` 전체 실행

### 3-1. 사고 재현

Workbench에서:

```sql
USE view_db;
DELETE FROM scores;            -- 😱 WHERE 없이 실행
SELECT COUNT(*) FROM scores;   -- 0
```

### 3-2. 복구

**cmd** 에서:

```bash
mysql -u root -p view_db < C:\db_backup\view_db_safety.sql
```

Workbench에서 다시 확인:

```sql
SELECT COUNT(*) FROM scores;   -- 10 복구됨
```

> 💡 이때 DB가 **기존 테이블을 `DROP TABLE IF EXISTS` 로 날린 뒤 다시 만드는 것**이 포인트다.  
> 그래서 `.sql` 파일 맨 위에 `DROP TABLE IF EXISTS ...;` 가 들어 있었던 것.
{: .prompt-info }

## 4. 장애 시나리오 B — DB 자체가 사라짐

### 4-1. 사고 재현

```sql
DROP DATABASE view_db;
SHOW DATABASES;   -- view_db 사라짐
```

### 4-2. 복구 (조금 다르다)

백업 파일이 **`CREATE DATABASE` 구문을 포함하지 않으면** 빈 DB를 먼저 만들고 넣어야 한다.

```bash
mysql -u root -p -e "CREATE DATABASE view_db;"
mysql -u root -p view_db < C:\db_backup\view_db_safety.sql
```

또는 **애초에 `--databases` 옵션으로 백업된 파일**이라면 `CREATE DATABASE`까지 포함되어 있어 그냥 실행하면 된다:

```bash
mysql -u root -p < C:\db_backup\multi.sql
```

확인:

```sql
SHOW DATABASES;
USE view_db;
SELECT COUNT(*) FROM students;
```

## 5. Workbench로 복구하기 (GUI 방식)

## 6. 비밀번호를 코드에서 빼기

11-1 스크립트에 `-p본인_비밀번호` 를 그대로 썼다. 다음 방법으로 더 안전하게 만든다.

### 6-1. 방법 A — `my.cnf` (또는 `my.ini`) 에 저장

Windows 11에서는 사용자 폴더에 다음 파일을 만든다:

```
C:\Users\본인계정\my.cnf
```

내용:

```ini
[client]
user = root
password = 여기에_비밀번호
```

이후 `mysqldump` / `mysql` 명령에 **`--defaults-file`** 을 주면 비밀번호를 코드에 안 써도 된다.

```bash
mysqldump --defaults-file=C:\Users\본인계정\my.cnf view_db > C:\db_backup\view_db.sql
```

> ⚠️ 이 파일은 **비밀번호 평문**이 들어 있다.  
> 파일 속성 → 보안 → **사용자 본인만 읽기 권한**을 주는 것이 원칙이다.
{: .prompt-warning }

### 6-2. 방법 B — 환경변수

cmd에서 **한 세션 동안만** 유지되는 임시 환경변수:

```bash
set MYSQL_PWD=본인_비밀번호
mysqldump -u root view_db > C:\db_backup\view_db.sql
```

Python에서는:

```python
import os
os.environ["MYSQL_PWD"] = "본인_비밀번호"   # 파이썬 실행 시에만 적용
subprocess.run(["mysqldump", "-u", "root", "view_db"], ...)
```

> 💡 `MYSQL_PWD` 환경변수는 MySQL 클라이언트가 자동으로 읽는다.  
> 그래서 명령줄에 `-p...` 를 쓰지 않아도 된다.
{: .prompt-info }

## 7. 완성형 — 백업 + 정리 + 복구 통합 스크립트

`C:\db_practice\week11\dbops.py`:

```python
# dbops.py — 백업 / 복구 / 오래된 파일 정리
import os
import sys
import subprocess
from datetime import datetime, timedelta
from pathlib import Path

# ─── 설정 ─────────────────────────────────────────
BACKUP_DIR    = Path(r"C:\db_backup")
TARGET_DB     = "view_db"
MYSQL_USER    = "root"
KEEP_DAYS     = 7          # 7일 지난 백업은 자동 삭제

# 비밀번호는 환경변수 MYSQL_PWD 로 읽는다.
# (실행 전: set MYSQL_PWD=본인_비밀번호)
if "MYSQL_PWD" not in os.environ:
    print("환경변수 MYSQL_PWD 가 설정되지 않았습니다.")
    print('예:  set MYSQL_PWD=본인_비밀번호')
    sys.exit(1)

BACKUP_DIR.mkdir(parents=True, exist_ok=True)


def backup():
    ts = datetime.now().strftime("%Y%m%d_%H%M%S")
    out_file = BACKUP_DIR / f"{TARGET_DB}_{ts}.sql"

    cmd = ["mysqldump", "-u", MYSQL_USER,
           "--single-transaction", TARGET_DB]
    with out_file.open("w", encoding="utf-8") as f:
        r = subprocess.run(cmd, stdout=f, stderr=subprocess.PIPE, text=True)

    if r.returncode == 0:
        print(f"[OK] 백업: {out_file}")
    else:
        print("[FAIL]", r.stderr)


def restore(sql_path: str):
    path = Path(sql_path)
    if not path.exists():
        print(f"파일이 없습니다: {path}")
        return

    # DB가 없다면 먼저 만든다
    subprocess.run(
        ["mysql", "-u", MYSQL_USER, "-e",
         f"CREATE DATABASE IF NOT EXISTS {TARGET_DB};"],
        check=True,
    )

    with path.open("r", encoding="utf-8") as f:
        r = subprocess.run(
            ["mysql", "-u", MYSQL_USER, TARGET_DB],
            stdin=f, stderr=subprocess.PIPE, text=True
        )
    if r.returncode == 0:
        print(f"[OK] 복구 완료: {path}")
    else:
        print("[FAIL]", r.stderr)


def cleanup():
    """KEEP_DAYS 보다 오래된 백업 삭제"""
    cutoff = datetime.now() - timedelta(days=KEEP_DAYS)
    removed = 0
    for f in BACKUP_DIR.glob(f"{TARGET_DB}_*.sql"):
        mtime = datetime.fromtimestamp(f.stat().st_mtime)
        if mtime < cutoff:
            f.unlink()
            removed += 1
            print(f"  - 삭제: {f.name}")
    print(f"[OK] 오래된 백업 {removed}개 정리")


def usage():
    print("사용법:")
    print("  python dbops.py backup")
    print("  python dbops.py restore <sql파일경로>")
    print("  python dbops.py cleanup")


if __name__ == "__main__":
    if len(sys.argv) < 2:
        usage(); sys.exit(0)

    op = sys.argv[1]
    if op == "backup":
        backup()
    elif op == "restore" and len(sys.argv) >= 3:
        restore(sys.argv[2])
    elif op == "cleanup":
        cleanup()
    else:
        usage()
```

### 실행 예

```bash
set MYSQL_PWD=본인_비밀번호

python dbops.py backup
python dbops.py cleanup
python dbops.py restore C:\db_backup\view_db_20260504_140000.sql
```

## 8. 작업 스케줄러로 자동 실행 (Windows 11)

1. **시작 → "작업 스케줄러"** 실행
2. **기본 작업 만들기** → 이름 `DB Daily Backup`
3. **트리거**: 매일 02:00
4. **동작**: "프로그램 시작" → 다음처럼 입력

| 항목 | 입력 값 |
|---|---|
| 프로그램/스크립트 | `python` |
| 인수 | `C:\db_practice\week11\dbops.py backup` |
| 시작 위치 | `C:\db_practice\week11` |

5. 비밀번호는 작업 스케줄러 환경에서 **시스템 환경변수 `MYSQL_PWD`** 로 등록하거나, `--defaults-file=my.cnf` 로 대체한다.

> 💡 매일 새벽 2시에 자동으로 백업되고, `cleanup` 을 추가 등록하면 **오래된 백업까지 자동 정리** 된다.

## 9. 복구 연습 시나리오

### 시나리오 1 — 실수 UPDATE
```sql
UPDATE students SET name = 'X';   -- WHERE 없음!
```
→ 최신 백업으로 `restore` 실행해 복구.

### 시나리오 2 — SQL Injection 이후
10-3에서 배운 공격으로 데이터가 일부 삭제/변조된 상황 가정.  
→ 백업 복구 후, **공격 경로**(코드의 문자열 연결 부분)를 파라미터 바인딩으로 수정하는 것까지 포함해야 **진짜 복구**다.

### 시나리오 3 — 디스크 고장 (가상)
새 PC에 MySQL을 설치 → `dbops.py restore <최신파일>` 한 줄로 DB 재구축.

## 11. 정리

- 복구는 **`mysql ... < 파일.sql`** 한 줄이 기본이다.
- DB 자체가 삭제되었다면 `CREATE DATABASE` 를 먼저 만들어 준다.
- 비밀번호는 **코드에 직접 쓰지 말고** 환경변수(`MYSQL_PWD`)나 `my.cnf` 로 뺀다.
- Python + `subprocess` + 작업 스케줄러 조합이면 **매일 자동 백업 + 오래된 파일 정리** 가 가능하다.
