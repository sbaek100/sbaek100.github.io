## 문제 1

**문제:** 모든 사진의 파일명과 작성자 이름을 함께 조회하세요.

**힌트:** `photos.user_id = users.id`

**답안:**

```sql
SELECT p.filename, u.display_name
FROM photos AS p
INNER JOIN users AS u
  ON p.user_id = u.id
ORDER BY p.id;
```

**예상 결과:**

| filename | display_name |
|---|---|
| mju_sunset.jpg | 김민준 |
| seoyeon_cafe.jpg | 이서연 |
| mju_cat.jpg | 김민준 |
| jiho_bike.jpg | 박지호 |
| sua_flower.jpg | 최수아 |
| seoyeon_book.jpg | 이서연 |

## 문제 3

**문제:** 모든 사용자와 그 사용자가 올린 사진 파일명을 함께 조회하세요.  
사진이 없는 사용자도 결과에 포함하세요.

**힌트:** 기준 테이블은 `users`

## 문제 4

## 문제 5

**문제:** 모든 사진의 파일명과 좋아요 수를 조회하세요.  
좋아요가 없는 사진도 포함하세요.

**힌트:** `photos`를 기준으로 `photo_likes`를 `LEFT JOIN`

**답안:**

```sql
SELECT p.filename,
       COUNT(pl.id) AS like_count
FROM photos AS p
LEFT JOIN photo_likes AS pl
  ON p.id = pl.photo_id
GROUP BY p.id, p.filename
ORDER BY p.id;
```

**예상 결과:**

| filename | like_count |
|---|---|
| mju_sunset.jpg | 3 |
| seoyeon_cafe.jpg | 2 |
| mju_cat.jpg | 3 |
| jiho_bike.jpg | 2 |
| sua_flower.jpg | 1 |
| seoyeon_book.jpg | 0 |

---

## 문제 6

**문제:** 좋아요가 2개 이상인 사진만 조회하세요.

**힌트:** `HAVING COUNT(pl.id) >= 2`

**답안:**

```sql
SELECT p.filename,
       COUNT(pl.id) AS like_count
FROM photos AS p
LEFT JOIN photo_likes AS pl
  ON p.id = pl.photo_id
GROUP BY p.id, p.filename
HAVING COUNT(pl.id) >= 2
ORDER BY p.id;
```

**예상 결과:**

| filename | like_count |
|---|---|
| mju_sunset.jpg | 3 |
| seoyeon_cafe.jpg | 2 |
| mju_cat.jpg | 3 |
| jiho_bike.jpg | 2 |

## 문제 7

## 문제 8

**문제:** 이서연이 좋아요를 누른 사진의 파일명을 조회하세요.

**힌트:** `users -> photo_likes -> photos`

**답안:**

```sql

INNER JOIN photo_likes AS pl
  ON u.id = pl.user_id

ORDER BY p.id;
```

|---|

## 문제 9

**문제:** 모든 댓글에 대해 댓글 본문, 댓글 작성자, 댓글이 달린 사진 파일명을 함께 조회하세요.

## 문제 11

**문제:** 댓글 본문과 함께 **사진 작성자**와 **댓글 작성자**를 동시에 조회하세요.

**힌트:** `users` 테이블을 두 번 JOIN해야 한다.

**답안:**

```sql
SELECT p.filename,
       owner.display_name   AS photo_owner,
       writer.display_name  AS comment_writer,
       c.content
FROM comments AS c
INNER JOIN photos AS p
  ON c.photo_id = p.id
INNER JOIN users AS owner
  ON p.user_id = owner.id
INNER JOIN users AS writer
  ON c.user_id = writer.id
ORDER BY c.id;
```

**예상 결과 예시:**

| filename | photo_owner | comment_writer | content |
|---|---|---|---|
| mju_sunset.jpg | 김민준 | 이서연 | 노을 색감 좋다! |
| mju_sunset.jpg | 김민준 | 최수아 | 직접 보면 더 예쁠 듯 |
| seoyeon_cafe.jpg | 이서연 | 김민준 | 디저트 맛있어 보여요 |

> 같은 `users` 테이블을 역할별로 2번 JOIN할 때는  
> `owner`, `writer`처럼 별칭을 다르게 주는 것이 중요하다.

## 문제 12

**문제:** `2026-04-03` 이후에 업로드된 사진의 파일명, 작성자 이름, 업로드 시각을 조회하세요.

## 문제 14

**문제:** MySQL에서 `FULL JOIN`을 직접 지원하지 않는다는 점을 떠올리며,  
모든 사용자와 모든 사진을 “한쪽만 있어도 보이게” 합친 결과를 `UNION`으로 흉내 내 보세요.

**힌트:** `LEFT JOIN` 결과 + `RIGHT JOIN` 결과를 합친다.

**답안:**

```sql
SELECT u.display_name, p.filename
FROM users AS u
LEFT JOIN photos AS p
  ON u.id = p.user_id

UNION

SELECT u.display_name, p.filename
FROM users AS u
RIGHT JOIN photos AS p
  ON u.id = p.user_id;
```

**예상 결과 설명:**

- 사진이 있는 사용자와 사진은 정상적으로 연결된다.
- 사진이 없는 `한도윤`도 포함된다.
- 현재 실습 데이터에서는 “사용자 없이 존재하는 사진”은 없으므로, 오른쪽만 있는 행은 추가되지 않는다.

> 이 문제는 “왜 MySQL에서 FULL JOIN을 직접 못 쓰는지”를 다시 떠올리는 복습용이다.  
> 초급 단계에서는 개념 확인 정도로만 이해해도 충분하다.

## 정리

- 7-1에서는 JOIN의 개념과 유형을 배웠다.
- 7-2에서는 Stargram DB를 직접 만들며 JOIN을 따라 했다.

이제 다음 단계에서는:

으로 넘어갈 준비가 된 것이다.
