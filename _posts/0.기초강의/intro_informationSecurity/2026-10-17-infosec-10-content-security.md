# 디지털 콘텐츠 보안 — 저작권 보호와 정보 은닉

---

앞 장까지는 **누가 들어올 수 있는가**(인증)와 **무엇을 할 수 있는가**(인가)를 다루었음. 그런데 정당한 권한으로 들어와 콘텐츠를 정상적으로 내려받은 사람이, 그것을 그대로 복사해 인터넷에 올린다면 접근통제는 아무것도 막지 못함.

**접근통제가 끝나는 지점에서 시작되는 보안**이 이 장의 주제임. 이미 상대의 손에 넘어간 콘텐츠를 어떻게 보호할 것인가의 문제임.

---

## Part 1. 디지털 콘텐츠란 무엇인가

**디지털 콘텐츠(Digital Contents)** 는 텍스트·이미지·오디오·비디오 등 다양한 형태의 정보를 디지털 형태로 제작·저장·배포한 결과물임. 즉 인간이 창작한 콘텐츠를 아날로그가 아닌 **0과 1의 이진수 형태**로 표현하여 손쉽게 복제·전송·재생할 수 있도록 만든 것임.

대표적인 예로는 음악 파일(MP3), 영화 파일(MP4), 전자책(eBook), 게임, 소프트웨어, SNS 게시물 등이 있음.

디지털 콘텐츠는 접근성과 유통 효율성이 높다는 장점을 가지지만, 동시에 복제와 유출이 용이하여 **저작권 침해와 불법 유통의 위험**에 노출되어 있음.

---

## Part 2. 디지털 콘텐츠의 취약한 특성과 보호의 필요성

### 2.1 왜 디지털 콘텐츠는 지키기 어려운가

디지털 콘텐츠는 그 본질이 데이터이므로, 한 번 유출되면 **무한 복제가 가능하며 원본과 복제본의 구별이 어려움**. 또한 인터넷 환경에서는 전 세계적으로 **실시간 유통이 가능**하기 때문에 보안 통제가 어려움.

주요 취약 요인은 다음과 같음.

| 취약 요인 | 내용 |
|---|---|
| **무손실 복제 가능성** | 원본과 동일한 품질의 복제본을 무한히 만들 수 있음 |
| **빠른 확산성** | P2P, 클라우드, 스트리밍 기술을 통해 짧은 시간에 대량 확산이 가능함 |
| **출처 추적의 어려움** | 불법 복제물이 수정·재배포되면 최초 유출 경로를 파악하기 어려움 |
| **사용자 인식 부족** | '공유'와 '복제'의 경계를 인식하지 못해 무심코 저작권을 침해하는 사례가 많음 |

> **아날로그와의 결정적 차이** — 종이책을 복사하면 화질이 떨어지고, 그 복사본을 다시 복사하면 더 나빠짐. 복제할수록 열화되는 성질이 그 자체로 확산을 막는 장벽이었음. 디지털에는 그 장벽이 없음. **1,000번째 복제본도 원본과 완전히 같음.**
{: .prompt-tip }

### 2.2 보호의 필요성

디지털 콘텐츠는 **창작자의 노동과 지식이 결합된 산출물**임. 따라서 이를 보호하는 것은 단순히 법적 의무가 아니라 창작 생태계의 지속성을 보장하기 위한 필수적 행위임.

저작권 보호는 창작자가 정당한 보상을 받고, 이용자는 합법적인 방식으로 콘텐츠를 향유할 수 있도록 하는 **문화적 신뢰 기반**임.

### 2.3 대표적 저작권 침해 사례

#### (가) 사례 1 — 국내 불법 스트리밍 플랫폼 운영자 처벌

누누티비(Noonoo TV) 등 한국 콘텐츠(드라마·영화·웹툰 등)를 불법으로 스트리밍·배포해 온 플랫폼이 적발된 바 있음. 베트남 등 외국에 법인을 설립하고 한국 콘텐츠를 무단 유통한 운영자들이 2024년 말 기소된 사례가 있음. 이어 2025년 5월에는 국내 최대 규모 저작권 침해 웹사이트로 알려진 누누티비 운영자가 **징역 3년형**을 선고받고 벌금·몰수 처분을 받음.

**쟁점**

- 국경을 넘는 콘텐츠 유통 구조(한국 → 해외 서버/법인)로 단속이 더 복잡해짐.
- 영상·드라마 같은 'K-콘텐츠'의 해외 가치 증가로 침해 규모 및 산업적 손실이 커지고 있음.

**시사점**

- 기존의 단순 다운로드 중심 침해에서 **스트리밍 및 클라우드 기반 무단 유통**으로 방식이 변화하고 있음을 보여줌.
- 법 집행이 강화되고 있으며, 국내 정부도 국내외 연계를 통해 단속 역량을 강화하고 있음. 2025년 1월 인터폴(INTERPOL)과 한국은 디지털 저작권 침해에 대한 **글로벌 단속 2단계(I-SOP 프로젝트)** 를 개시함.

#### (나) 사례 2 — AI 시대의 저작권 분쟁: 이미지 생성 및 학습 데이터 문제

2025년 6월, 월트디즈니(The Walt Disney Company)와 유니버설 픽처스(Universal Pictures)가 AI 이미지 생성 회사 **미드저니(Midjourney)** 를 상대로 저작권 침해 소송을 제기함. 해당 회사가 자사 인기 캐릭터(예: 슈퍼맨, 배트맨, 미니언즈 등)를 무단으로 사용한 이미지 생성 서비스를 제공했다고 주장하였음.

또한 중국 항저우 인터넷 법원(Hangzhou Internet Court) 판결에서, 생성형 AI가 이미지 생성 과정에서 타인의 저작물을 학습에 이용한 것이 저작권 침해로 인정된 사례도 있음.

**쟁점**

- AI의 **학습 데이터**에 저작권 있는 작품이 포함되어 있는지가 핵심 쟁점임.
- AI가 생성한 콘텐츠에 인간 창작자가 개입했는지, 저작자 인격권 및 저작권 귀속은 누구에게 있는지 등이 법적 논쟁 대상임.

**시사점**

- 저작권 보호 체계가 기술 변화에 의해 재검토되고 있으며, AI 관련 분쟁이 저작권 보호의 새로운 지평이 되고 있음.

## Part 3. 기술적 보호 수단

디지털 콘텐츠 보호는 **기술적·법적·관리적 접근**이 종합적으로 이루어져야 함. 1장에서 배운 세 가지 보호대책 구분이 여기서도 그대로 적용됨.

먼저 기술적 보호 수단을 다섯 가지로 나누어 살펴봄.

```
   [ 콘텐츠 유통 흐름과 보호 기술의 배치 ]

   제작 ──────> 배포 ──────> 소비 ──────> (유출 발생)
    │            │            │              │
    ▼            ▼            ▼              ▼
  워터마킹      암호화        DRM          핑거프린팅
 (소유권 표시) (전송 보호) (사용 통제)   (유출자 추적)
                              │
                              ▼
                        무결성 검증(해시)
```

### 3.1 디지털 워터마킹(Digital Watermarking)

콘텐츠 내부에 저작권자 식별 정보를 비가시적으로 삽입하여 불법 복제 시에도 **출처를 추적**할 수 있게 하는 기술임. 워터마크는 눈에 보이지 않지만, 디코딩을 통해 원저작자를 식별할 수 있으며 법적 증거로도 활용됨.

**워터마킹**이란 용어는 지폐 제조과정에서 위조지폐를 가려내기 위해, 물에 젖은 상태에서 특정 그림을 인쇄·건조한 뒤 **불빛에 비추면 그림이 보이도록** 하는 기술에서 유래함.

#### (가) 디지털 워터마크의 목적

| 목적 | 내용 |
|---|---|
| 저작권 보호 | 소유권 증명 및 불법 복제 방지 |
| 출처 추적 | 콘텐츠 유통 경로 파악 |
| 인증 | 콘텐츠의 진위 여부 확인 |
| 무결성 검증 | 내용 변조 여부 탐지 |

#### (나) 가시성에 따른 분류

**가시적 워터마크(Visible Watermark)**

- 육안으로 확인 가능한 워터마크임.
- 로고, 텍스트, 패턴 등을 이미지 위에 오버레이함.
- 예시: 방송사 로고, 사진 작가 서명, 주민등록등본의 무궁화 문양
- 장점: 명확한 소유권 표시, 심리적 억제 효과
- 단점: 미관 해치기, 사용자 경험 저하

**비가시적 워터마크(Invisible Watermark)**

- 육안으로 보이지 않지만 특수 도구로 검출 가능함.
- **주파수 영역(DCT, DWT)** 에 정보를 삽입함.
- 예시: 디지털 영화관의 CAM 녹화 방지
- 장점: 원본 품질 유지, 사용자 경험 방해 없음
- 단점: 검출 도구 필요, 구현 복잡도 높음

#### (다) 디지털 워터마크 시스템이 갖추어야 할 네 가지 특성

| 특성 | 요구사항 |
|---|---|
| **비가시성**(Imperceptibility) | 워터마크가 삽입되어도 원본 콘텐츠의 지각 품질이 유지되어야 함. 사용자가 워터마크의 존재를 느끼지 못해야 함 |
| **강인성**(Robustness) | 다양한 공격에 대해 워터마크가 살아남아야 함 |
| **보안성**(Security) | 권한 없는 사람이 워터마크를 제거하거나 위조할 수 없어야 함. 암호학적 키를 사용하여 보안성을 강화함 |
| **용량**(Capacity) | 충분한 양의 정보를 삽입할 수 있어야 함. 저작권 정보, ID, 날짜 등 필요한 데이터를 모두 포함 |

강인성이 견뎌야 하는 공격 유형은 다음과 같음.

- **기하학적 공격**: 회전, 크기 조정, 자르기
- **신호처리 공격**: 압축(JPEG, MP3), 필터링, 노이즈 추가
- **악의적 공격**: 워터마크 제거 시도

> **네 가지 특성은 서로 충돌함.** 더 많은 정보를 넣으면(용량 ↑) 화질 변화가 커지고(비가시성 ↓), 공격에 잘 견디게 만들면(강인성 ↑) 삽입 강도가 커져 역시 비가시성이 떨어짐. 1장에서 배운 **보안과 다른 목표 사이의 트레이드오프**가 여기서도 그대로 나타남. 정답은 최대화가 아니라 **용도에 맞는 균형점**임.
{: .prompt-warning }

#### (라) 강인성에 따른 분류

- **강한(강성) 워터마킹**: 공격을 받아도 쉽게 파괴·손상되지 않음. 저작권 증명용.
- **약한(연성) 워터마킹**: 공격을 받으면 쉽게 파괴·손상됨. 역설적으로 **변조 탐지용**으로 쓰임. 워터마크가 깨졌다는 사실 자체가 "이 파일은 수정되었다"는 증거가 되기 때문임.

#### (마) 포렌식 워터마크

같은 원본 콘텐츠를 구매자마다 **조금씩 다른 워터마크를 넣어** 배포하는 방식임. 나중에 불법 유출본이 발견되면 그 안에 박힌 워터마크를 읽어 **어느 구매자에게서 새어 나갔는지** 유포 경로를 확인할 수 있음. 뒤에서 볼 핑거프린팅과 같은 발상임.

### 3.2 스테가노그래피(Steganography)

스테가노그래피는 '숨겨진 글쓰기(hidden writing)'라는 뜻으로, **정보의 존재 자체를 숨기는 기술**임.

- **암호화**가 「비밀로 기록하는 것(secret writing)」을 의미하는 반면, **스테가노그래피**는 「감추어진 기록(covered writing)」을 의미함.
  - 암호화 → 메시지의 **내용**을 은폐함. 다만 "무언가 숨기고 있다"는 사실은 드러남.
  - 스테가노그래피 → 다른 무언가로 감추어 **메시지 자체(존재)** 를 은폐함.

#### (가) 원리 — LSB(최하위 비트) 삽입

이미지·오디오·비디오 등의 디지털 파일에 메시지를 삽입하되, 파일의 시각적·청각적 품질을 유지하여 변화를 인지하기 어렵게 만듦. 가장 널리 쓰이는 방법이 각 픽셀의 **최하위 비트(LSB, Least Significant Bit)** 를 조작하여 비밀 정보를 저장하는 방식임.

```
   한 바이트(8비트)에서의 자리값

   MSB                                              LSB
  (가장 큰 영향)                              (가장 작은 영향)
    ┌───┬───┬───┬───┬───┬───┬───┬───┐
    │ 1 │ 0 │ 1 │ 1 │ 0 │ 0 │ 1 │ 0 │   = 178
    └───┴───┴───┴───┴───┴───┴───┴───┘
     128  64  32  16   8   4   2   1
      ↑                           ↑
   바꾸면 값이 128 변함      바꾸면 값이 1만 변함
   (눈에 확 띔)              (사람 눈으로 구별 불가)
```

즉 픽셀의 붉은색 값이 178에서 179로 바뀌어도 사람 눈은 그 차이를 알아채지 못함. 이 **1비트씩의 여유 공간**을 모아 비밀 메시지를 담는 것임.

```
   원본 이미지 픽셀들          비밀 메시지          결과(스테고 이미지)
   ┌────────────┐                              ┌───────────┬─┐
   │  00110101  │                              │ 0011010   │1│
   │  10011100  │      1 0 1 1 0 0 1 ...       │ 1001110   │0│
   │  01010011  │  +   ─────────────────  →    │ 0101001   │1│
   │  11001010  │      (각 바이트의 LSB에)      │ 1100101   │1│
   │  00111001  │                              │ 0011100   │0│
   └────────────┘                              └───────────┴─┘
      cover(덮개)                                  stego(결과물)
                                                 육안으로 동일
```

#### (나) 워터마킹과의 차이

스테가노그래피는 **비밀 통신**이 목적이지만, 워터마킹은 **저작권 보호**가 주목적임. 워터마크는 제거하기 어렵도록 설계되며(**강인성**), 스테가노그래피는 **발견되지 않는 것이 중요함(은닉성)**.

또 하나의 차이는 숨기는 정보의 성격임. 스테가노그래피는 은폐 미디어를 단지 **비밀 정보를 숨기는 수단**으로 사용하는 반면, 워터마킹이 추가하는 정보는 **원래의 미디어와 관련 있는 정보(저작권 정보 등)** 임.

#### (다) 보안적 의의와 양면성

- 불법 유출된 콘텐츠에 스테가노그래피로 식별 정보를 숨겨 두면, 외부인이 모르는 상태에서 추적이 가능함.
- 데이터 전송 과정에서 기밀 정보를 노출 없이 전달할 수 있음.
- 워터마킹, DRM과 결합하여 **복합 보호 체계**를 구축할 수 있음.
- 활용 예시: 정부기관이나 기업의 내부 기밀 파일 보호, 저작권 추적을 위한 비가시성 식별자 삽입, 보안 통신 및 디지털 포렌식 영역.

> **양날의 검임.** 같은 기술이 공격에도 쓰임. 실제로 테러 조직이 **dead-drop(비밀 연락 수단)** 으로 악용한 사례가 있고, 악성코드가 정상 이미지 파일 안에 명령을 숨겨 탐지를 우회하는 기법도 존재함. 방어자 입장에서는 "이 파일에 무언가 숨어 있는가"를 찾아내는 **스테그어낼리시스(Steganalysis)** 가 필요해짐.
{: .prompt-warning }

### 3.3 핑거프린팅(Fingerprinting)

디지털 콘텐츠를 **구매할 때 구매자의 정보를 삽입**하여, 불법 배포 발견 시 **최초의 배포자(유출자)를 추적**할 수 있게 하는 기술임.

판매되는 콘텐츠마다 구매자 정보가 들어가므로, 불법 재배포된 콘텐츠에서 핑거프린팅된 정보를 추출하여 **구매자를 식별하고 법적 조치**를 가할 수 있음.

#### 표 — 스테가노그래피 · 워터마크 · 핑거프린트 비교

| 항목 | 스테가노그래피 | 워터마크 | 핑거프린트 |
|---|---|---|---|
| 은닉 정보 | 메시지 | 판매자 정보 | 구매자 추적정보 |
| 관심(목적) | 은닉 메시지 검출 | 저작권 표시 | 구매자 추적 |
| 트래킹 | 불가 | 가능 | 가능 |
| 불법예방 효과 | 하 | 중 | 상 |
| 저작권증명 효과 | 하 | 중 | 상 |
| 공격 강인성 | 상대적 약함 | 상대적 강함 | 상대적 강함 |

> **암기 포인트** — 세 기술의 차이는 **"무엇을 숨기는가"** 로 구분하면 쉬움.
> - 스테가노그래피 → **메시지**를 숨김 (비밀 통신)
> - 워터마크 → **판매자(저작권자) 정보**를 숨김 (내 것임을 증명)
> - 핑거프린트 → **구매자 정보**를 숨김 (누가 유출했는지 추적)
{: .prompt-tip }

### 3.4 디지털 저작권 관리 (DRM, Digital Rights Management)

#### (가) 개요

**DRM**은 콘텐츠의 복제·재생·인쇄 등을 통제하기 위한 **접근 제어 기술**임. DRM은 암호화, 사용자 인증, 라이선스 관리 등의 과정을 통해 **허가된 사용자만 콘텐츠를 사용할 수 있도록** 함.

- DRM은 디지털 콘텐츠 소유자가 자신의 콘텐츠에 대한 접근을, 자신 또는 위임자가 지정하는 **다양한 방식으로 제어**할 수 있게 하는 기술적 방법(또는 방법의 집합)임.
- DRM이 제어하는 콘텐츠 **접근**에는 실행(executing)·보기(viewing)·복제(copying)·출력(printing)·변경(altering) 등이 모두 포함되며, 디지털 콘텐츠에는 오디오·비디오·이미지·텍스트·멀티미디어·컴퓨터 소프트웨어 등이 포함됨.

DRM이 걸 수 있는 제한의 예시는 다음과 같음. 재생 횟수 제한, 시간 제한 재생, 파일 복사 제한, 파일 전송 제한, 파일 녹화 제한 등임.

#### (나) DRM 구성 요소

| 구성 요소 | 역할 |
|---|---|
| 메타데이터(Metadata) | 콘텐츠 생명주기 범위 내에서 관리되어야 할 각종 데이터의 **구조 및 정보** |
| 패키저(Packager) | 보호 대상 콘텐츠를 메타데이터와 함께 **Secure Container 포맷으로 패키징**하는 모듈 |
| 시큐어 컨테이너(Secure Container) | DRM 보호 범위 내에서 유통되는 콘텐츠의 **배포 단위** |
| 식별자(Identifier) | 콘텐츠를 **식별**하기 위한 식별자 |
| DRM 제어기(DRM Controller) | 사용자 PC·디바이스에서 콘텐츠가 **라이선스에 명시된 범위 내에서** 지속 보호되도록 프로세스를 제어 |

#### (다) DRM 모델

DRM 사용자는 **콘텐츠 제공자 · 콘텐츠 배포자 · 콘텐츠 소비자 · 클리어링하우스**로 분류됨. 이들 간의 정보 흐름과 자금 흐름은 다음과 같음.

```
                       ┌──────────────────┐
        로열티 수수료 ↑ │   클리어링하우스    │ ↕ 디지털 권리 / 이용대금 지불
           사용 규칙 ↓ │  (Clearinghouse)  │
                       └──────────────────┘
          ┌───────────────┐                  ┌──────────────┐
          │  콘텐츠 제공자   │   보호된 콘텐츠    │    소비자      │
          │(Content Provider)│ ─ ─ ─ ─ ─ ─ ─ ▶ │ (Consumer)    │
          └───────────────┘                  └──────────────┘
                  │  보호된 콘텐츠      배포비용/이용대금 ▲ │
                  ▼                                   │ ▼
                       ┌──────────────────┐
                       │  배포자(Distributor) │
                       └──────────────────┘
        ── 정보 흐름     - - 자금 흐름
```

| 사용자(역할) | 설명 |
|---|---|
| **콘텐츠 제공자**(Content Provider) | 콘텐츠에 대한 **디지털 권리**를 가지고 권리 보호를 원하는 DRM 사용자. 콘텐츠 사용 규칙을 표현하는 언어를 **권리 표현 언어(REL, Rights Expression Language)** 라 하며, 대표 REL은 **ODRL**(Open Digital Rights Language)과 **MPEG REL**임 |
| **콘텐츠 배포자**(Distributor) | 온라인 쇼핑몰과 같은 **유통 채널** 제공자. 정당한 소비자에게 안전하게 콘텐츠를 전달하고, 클리어링하우스로부터 **합당한 대금(배급 수수료)** 을 분배받음 |
| **콘텐츠 소비자**(Content Consumer) | 클리어링하우스를 통해 콘텐츠에 대한 **권리를 요청**하고 합당한 대금을 지불 |
| **클리어링하우스**(Clearinghouse) | **디지털 허가(라이선스)** 를 소비자에게 발급, 콘텐츠 제공자에게 **로열티**·배포자에게 **배급 수수료**를 지불하는 **재정적 거래**를 취급. 또한 모든 소비자의 **허가된 사용을 기록**할 책임을 짐 |

> **DRM (출처: TTA)**
> 디지털 미디어의 불법·비인가 사용을 제한하기 위해 저작권/판권 소유자가 이용하는 정보 보호 기술의 일종인 **접근제어 기술**. 음원·영화 등 창작 미디어에 일반적으로 적용되며, 디지털 미디어의 생명 주기 동안 **사용 권한 관리·과금·유통 단계**를 관리함. 위반자 단속에 앞서 **사용을 허가하는 라이선스를 획득한 후** 사용이 가능하도록 기술적 통제가 가능한 시스템임. DRM에는 **암호 기술·키 관리 기술·워터마킹** 등 다양한 정보 보호 기술이 활용됨.
{: .prompt-info }

### 3.5 암호화(Encryption)

콘텐츠의 데이터를 암호화하여 비인가 사용자가 내용을 열람하거나 복제하지 못하도록 하는 기술임. 특히 스트리밍 서비스에서는 **전송 구간 암호화**를 통해 실시간 복제 방지를 수행함.

4장에서 배운 암호 기술이 여기서 DRM의 기반 기술로 다시 쓰임. DRM은 암호화 위에 **라이선스와 사용 규칙**을 얹은 체계라고 이해하면 됨.

### 3.6 무결성 검증 기술

콘텐츠의 **해시값**을 저장해 두고, 추후 동일성을 비교함으로써 변조 여부를 판단함. 이 기술은 디지털 포렌식, 저작권 분쟁 증거 확보에도 활용됨.

## Part 4. 법적·관리적 보호 수단

기술만으로는 콘텐츠를 지킬 수 없음. 복제를 아무리 어렵게 만들어도 완전히 막을 수는 없기 때문에, 침해가 발생했을 때 **책임을 물을 수 있는 근거**가 필요함.

| 구분 | 내용 |
|---|---|
| **저작권법** | 창작자의 권리를 보호하며, 무단 복제나 배포 행위에 대해 민형사상 처벌을 가능하게 함 |
| **정보통신망법 및 개인정보보호법** | 데이터의 불법 수집·이용을 방지하고, 개인 정보가 포함된 콘텐츠의 유출을 제재함 |
| **국제 협약** | **베른협약(Berne Convention)**, **WIPO 저작권 조약(WCT)** 등은 국가 간 저작권 보호의 통일적 기준을 제시함 |

국제 협약이 중요한 이유는 Part 2의 사례에서 본 그대로임. 침해 서버가 해외에 있으면 국내법만으로는 손이 닿지 않음. 인터폴과의 공조 수사가 필요해지는 것도 같은 이유임.

## Part 5. AI 시대의 저작권

AI 기술의 급격한 발전은 창작물의 생산 방식을 근본적으로 바꾸고 있음. AI는 기존 데이터(텍스트·이미지·음악 등)를 학습하여 새로운 콘텐츠를 생성하지만, 이 과정에서 **기존 저작물의 이용과 저작권 귀속 문제**가 발생함.

### 5.1 주요 쟁점

| 쟁점 | 내용 |
|---|---|
| **AI 생성물의 저작권 주체** | 인간의 개입이 최소한인 경우, 해당 결과물의 저작권을 AI 개발자나 사용자 중 누구에게 귀속할 것인지 명확하지 않음 |
| **학습 데이터의 저작권 침해** | AI가 저작권이 있는 콘텐츠를 학습 데이터로 사용했다면, 이는 공정 이용인지 위반인지 논란이 있음 |
| **딥페이크 콘텐츠 문제** | AI가 실제 인물의 얼굴이나 음성을 조합하여 허위 콘텐츠를 생성할 경우, 초상권과 명예훼손 문제가 동시에 발생할 수 있음 |

### 5.2 대응 방향

- **기술적 측면**: AI 생성물에 출처와 생성 이력을 명시하는 **메타데이터 기반 추적 기술**을 적용할 필요가 있음.
- **법적 측면**: AI 생성물의 저작권 인정 기준과 책임 주체를 명확히 규정해야 함.
- **윤리적 측면**: 생성형 AI 사용에 대한 사회적 합의와 윤리적 지침이 마련되어야 함.

> 기술적 대응 방향으로 제시된 "메타데이터 기반 추적"은 결국 이 장에서 배운 **워터마킹**의 확장임. AI 생성 이미지에 보이지 않는 표식을 넣어 "이것은 AI가 만들었다"를 증명하려는 시도가 실제로 진행되고 있음. 30년 전 저작권 보호를 위해 만들어진 기술이 지금은 **진짜와 가짜를 구별하기 위해** 쓰이고 있는 셈임.
{: .prompt-info }

## Part 6. 실습 — OpenStego로 정보 은닉 체험하기

지금까지 배운 스테가노그래피와 워터마킹을 **OpenStego**로 직접 확인해 봄.

**OpenStego**는 자바(Java) 기반의 무료 오픈소스 스테가노그래피 도구임. 라이선스는 GNU GPL v2이며, 두 가지 기능을 제공함.

- **Data Hiding**: 덮개 파일(이미지) 안에 임의의 파일을 숨김. LSB 방식을 사용하며 암호로 추가 보호할 수 있음.
- **Watermarking**: 이미지에 보이지 않는 서명(워터마크)을 삽입하고 검증함.

> **실습 윤리**
> 이 실습의 목적은 **정보 은닉의 원리를 이해하고, 방어자 입장에서 그 흔적을 인식**하는 것임. 숨긴 파일을 타인에게 몰래 전달하거나, 조직의 보안 정책을 우회하는 용도로 사용해서는 안 됨. 많은 기업에서 스테가노그래피를 이용한 정보 유출은 **징계 및 법적 처벌 대상**임.
{: .prompt-warning }

### 6.1 준비

#### Step 1. 설치

1. [openstego.com](https://www.openstego.com/)에서 최신 버전을 내려받음. Windows용 설치 파일(`.exe`)과 무설치 압축본(`.zip`)이 함께 제공됨.
2. OpenStego는 자바로 만들어졌으므로 **자바 실행 환경(JRE)** 이 필요함. 최근 배포판에는 런타임이 포함되어 있으나, 실행되지 않으면 자바를 별도로 설치해야 함.
3. 설치 후 `OpenStego`를 실행함.

#### Step 2. 실습 파일 준비

바탕화면에 `stego` 폴더를 만들고 아래 두 파일을 넣음.

| 파일 | 내용 |
|---|---|
| `cover.png` | 덮개로 쓸 이미지. **PNG 또는 BMP**를 권장함 |
| `secret.txt` | 숨길 메시지. 메모장으로 "학번-이름-비밀메시지" 정도를 적어 저장 |

> **덮개 이미지는 반드시 PNG나 BMP를 쓸 것.** JPG는 **손실 압축** 방식이라 저장할 때마다 픽셀 값이 미세하게 바뀜. LSB에 숨겨 둔 비트가 그 과정에서 깨지므로 메시지를 복구할 수 없음. OpenStego의 출력 파일도 PNG로 생성됨.
>
> 지원 형식은 아래 명령으로 직접 확인할 수 있음.
>
> ```powershell
> java -jar openstego.jar readformats
> java -jar openstego.jar writeformats
> ```
{: .prompt-warning }

또한 덮개 이미지는 **숨길 파일보다 충분히 커야 함**. 픽셀 하나당 몇 비트씩만 쓸 수 있기 때문임. 대략적인 계산은 다음과 같음.

```
   숨길 수 있는 최대 용량 ≈ (가로 픽셀 × 세로 픽셀 × 3) / 8  바이트

   예) 1920 × 1080 이미지
       (1920 × 1080 × 3) / 8 = 777,600 바이트 ≈ 약 760 KB
```

### 6.2 실습 A — 데이터 숨기기(Data Hiding)

#### Step 1. 숨기기

1. OpenStego 왼쪽 메뉴에서 **Data Hiding** 선택
2. 상단 탭에서 **Hide data** 선택
3. 항목을 다음과 같이 지정함.

| 항목 | 입력값 |
|---|---|
| Message File | `secret.txt` |
| Cover File | `cover.png` |
| Output Stego File | `stego.png` |
| Encryption Algorithm | `AES128` (선택) |
| Password | 임의의 암호 (선택) |

4. **Hide Data** 버튼 클릭 → 성공 메시지 확인

#### Step 2. 결과 확인 — 눈으로 비교

`cover.png`와 `stego.png`를 나란히 열어 봄. **육안으로는 전혀 구별되지 않음.** 이것이 스테가노그래피의 핵심임.

이어서 두 파일의 **크기와 해시값**을 비교해 봄. PowerShell에서 실행함.

```powershell
Get-ChildItem cover.png, stego.png | Select-Object Name, Length
Get-FileHash cover.png, stego.png -Algorithm SHA256 | Select-Object Hash, Path
```

- 파일 크기는 비슷하지만 **완전히 같지는 않음**.
- **해시값은 전혀 다름.** 내용이 1비트라도 바뀌면 해시가 완전히 달라지기 때문임. 4장에서 배운 **눈사태 효과**가 여기서 확인됨.

#### Step 3. 꺼내기

1. 상단 탭에서 **Extract data** 선택
2. Input Stego File에 `stego.png` 지정
3. Output Folder 지정, 암호를 걸었다면 암호 입력
4. **Extract Data** 클릭 → `secret.txt`가 복원됨

#### Step 4. 명령줄로도 해 보기

GUI와 동일한 작업을 명령줄로 수행할 수 있음. 실무에서는 자동화를 위해 이 방식을 씀.

```powershell
java -jar openstego.jar embed -mf secret.txt -cf cover.png -sf stego.png -p mypassword
```

```powershell
java -jar openstego.jar extract -sf stego.png -xd .\out -p mypassword
```

| 옵션 | 의미 |
|---|---|
| `-mf, --messagefile` | 숨길 원본 파일 |
| `-cf, --coverfile` | 덮개 파일 |
| `-sf, --stegofile` | 결과(스테고) 파일 |
| `-xd, --extractdir` | 추출한 파일을 저장할 폴더 |
| `-p, --password` | 암호 |
| `-A, --cryptalgo` | 암호 알고리즘(AES128 / AES256) |

### 6.3 실습 B — 보이지 않는 워터마크(Watermarking)

#### Step 1. 서명 생성

1. 왼쪽 메뉴에서 **Digital Watermarking (Beta)** 선택
2. **Generate Signature** 탭 선택
3. 임의의 암호를 입력하고 출력 서명 파일 이름을 `mysig.sig`로 지정
4. **Generate Signature** 클릭

#### Step 2. 워터마크 삽입

1. **Embed Watermark** 탭 선택
2. File to be watermarked: `cover.png`
3. Signature File: `mysig.sig`
4. Output File: `marked.png`
5. **Embed Watermark** 클릭

#### Step 3. 워터마크 검증

1. **Verify Watermark** 탭 선택
2. Watermarked File: `marked.png`, Signature File: `mysig.sig`
3. **Verify Watermark** 클릭 → 상관도(correlation) 값과 함께 워터마크 존재 여부가 표시됨

#### Step 4. 강인성 실험 (핵심)

여기가 이 실습에서 가장 중요한 부분임. **워터마크가 공격을 견디는지** 확인함.

`marked.png`를 아래와 같이 변형한 뒤, 각각에 대해 다시 **Verify Watermark**를 수행하고 결과를 표에 기록함.

| 변형 | 방법 | 워터마크 검출 여부 | 상관도 |
|---|---|---|---|
| 원본 그대로 | 변형 없음 | | |
| 크기 축소 | 그림판에서 50% 축소 후 저장 | | |
| 잘라내기 | 가장자리 20% 정도 잘라냄 | | |
| JPG로 저장 | 그림판에서 JPG로 다시 저장 | | |
| 밝기 조정 | 사진 앱에서 밝기 변경 후 저장 | | |

같은 변형을 **실습 A의 `stego.png`** 에도 적용하고 데이터 추출을 시도해 봄.

> **여기서 확인해야 할 것**
> 워터마크는 일부 변형 후에도 살아남는 경우가 있지만, 실습 A의 LSB 데이터는 **작은 변형만으로도 대부분 복구가 불가능해짐**. 이 차이가 곧 **강인성(Robustness)** 의 유무이며, 워터마킹과 스테가노그래피가 서로 다른 목표를 가진 기술이라는 사실을 보여줌.
>
> - 워터마킹 → 공격받아도 **살아남아야** 함 (강인성)
> - 스테가노그래피 → 애초에 **들키지 않아야** 함 (은닉성)
{: .prompt-tip }

### 6.4 문제 해결

| 증상 | 원인 | 조치 |
|---|---|---|
| 프로그램이 실행되지 않음 | 자바 런타임 없음 | JRE 설치 후 재실행, 또는 런타임 포함 배포판 사용 |
| "Message file is too big" 오류 | 덮개 이미지가 너무 작음 | 더 큰 해상도의 이미지를 쓰거나 숨길 파일을 줄임 |
| 추출했는데 내용이 깨짐 | 스테고 파일을 JPG로 재저장함 | PNG 원본으로 다시 시도. LSB는 손실 압축을 견디지 못함 |
| 암호 오류 | 삽입할 때와 다른 암호 입력 | 삽입 시 사용한 암호를 정확히 입력 |
| 워터마크 검증 실패 | 서명 파일이 다르거나 변형이 과함 | 삽입에 쓴 `.sig` 파일을 그대로 사용 |

### 6.5 생각해 볼 점

- 회사에서 직원이 기밀 문서를 휴가 사진 안에 숨겨 개인 메일로 보냈다면, 보안 담당자는 어떻게 탐지할 수 있겠는가.
- 파일 크기·해시값 외에 "무언가 숨겨져 있다"고 의심할 만한 단서로 무엇이 있겠는가.
- 실습 A와 B 중 **저작권 소송의 증거**로 쓸 수 있는 쪽은 어느 것이며, 그 이유는 무엇인가.
- DRM이 걸린 콘텐츠를 정당하게 구매한 사람이 기기를 바꾸었을 때 재생이 안 된다면, 이는 어떤 보안 요구사항과 충돌하는 것인가. (1장의 CIA 중 하나를 떠올려 볼 것)

## 시험에 나오는 핵심 3가지

> **① 세 기술의 구분 — "무엇을 숨기는가"**
> 스테가노그래피는 **메시지**(비밀 통신 목적, 은닉성 중시), 워터마크는 **판매자·저작권자 정보**(저작권 표시, 강인성 중시), 핑거프린트는 **구매자 정보**(유출자 추적)를 숨김.
>
> **② 디지털 워터마크의 네 가지 요구 특성**
> **비가시성 · 강인성 · 보안성 · 용량**. 이 네 가지는 서로 충돌하므로 용도에 맞는 균형점을 찾아야 함.
>
> **③ DRM의 네 주체와 클리어링하우스의 역할**
> 콘텐츠 제공자 · 배포자 · 소비자 · **클리어링하우스**. 클리어링하우스는 **라이선스 발급**과 **로열티·수수료 정산**, **사용 기록 관리**를 담당함. 권리 표현 언어(REL)로는 **ODRL**과 **MPEG REL**이 대표적임.
{: .prompt-tip }

## 용어 정리

| 용어 | 영문(약어) | 정의 |
|---|---|---|
| 디지털 콘텐츠 | Digital Contents | 정보를 디지털 형태로 제작·저장·배포한 결과물 |
| 스테가노그래피 | Steganography | 정보의 존재 자체를 숨기는 기술('감추어진 기록') |
| 최하위 비트 | Least Significant Bit (LSB) | 한 바이트에서 값에 가장 적은 영향을 주는 비트. 스테가노그래피의 주된 삽입 위치 |
| 스테그어낼리시스 | Steganalysis | 파일에 은닉된 정보가 있는지 탐지·분석하는 기술 |
| 디지털 워터마킹 | Digital Watermarking | 콘텐츠에 저작권자 식별 정보를 삽입하는 기술 |
| 가시적 워터마크 | Visible Watermark | 육안으로 확인 가능한 워터마크(방송사 로고 등) |
| 비가시적 워터마크 | Invisible Watermark | 육안으로 보이지 않고 주파수 영역(DCT·DWT)에 삽입되는 워터마크 |
| 강인성 | Robustness | 압축·자르기·노이즈 등 공격 후에도 워터마크가 살아남는 성질 |
| 비가시성 | Imperceptibility | 삽입 후에도 원본의 지각 품질이 유지되는 성질 |
| 핑거프린팅 | Fingerprinting | 구매자 정보를 삽입하여 유출자를 추적하는 기술 |
| 포렌식 워터마크 | Forensic Watermark | 구매자별로 다른 워터마크를 넣어 유포 경로를 확인하는 방식 |
| 디지털 저작권 관리 | Digital Rights Management (DRM) | 허가된 사용자만 콘텐츠를 사용하도록 통제하는 접근제어 기술 |
| 시큐어 컨테이너 | Secure Container | DRM 보호 범위 내에서 유통되는 콘텐츠의 배포 단위 |
| 클리어링하우스 | Clearinghouse | 라이선스 발급과 대금 정산·사용 기록을 담당하는 DRM 주체 |
| 권리 표현 언어 | Rights Expression Language (REL) | 콘텐츠 사용 규칙을 기술하는 언어. ODRL, MPEG REL |
| 베른협약 | Berne Convention | 국가 간 저작권 보호의 통일 기준을 제시한 국제 협약 |
| WIPO 저작권 조약 | WIPO Copyright Treaty (WCT) | 디지털 환경의 저작권 보호를 다루는 국제 조약 |
