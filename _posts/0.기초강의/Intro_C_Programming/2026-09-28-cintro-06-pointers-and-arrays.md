## 제1절. 메모리와 주소

### 1.1 메모리는 번호가 매겨진 칸들입니다

컴퓨터의 메모리는 **번호가 붙은 칸이 줄지어 있는 것**이라고 생각하면 됩니다. 그 번호를 **주소(address)** 라고 합니다.

| 주소 | … | 1000 | 1001 | 1002 | 1003 | 1004 | … |
|---|---|---|---|---|---|---|---|
| 내용 | | (1바이트) | (1바이트) | (1바이트) | (1바이트) | (1바이트) | |

자료형에 따라 몇 칸을 차지하는지가 달라집니다(3강 2절).

| 자료형 | 차지하는 칸 수 |
|---|---|
| `char` | 1 |
| `int` | 4 |
| `double` | 8 |

변수를 선언하면 컴파일러가 **어딘가에 자리를 잡아 주고 그 자리에 이름을 붙여 줍니다.** 우리는 그동안 이름만 사용했지만, 그 뒤에는 언제나 주소가 있었습니다.

### 1.2 주소를 눈으로 보기

`&` 연산자는 **변수의 주소를 돌려줍니다.** `%p`는 주소를 출력하는 서식 지정자입니다.

`addr_demo.c`입니다.

```c
#include <stdio.h>

int main(void)
{
    int a = 10;
    double d = 3.14;
    char c = 'A';
    int arr[4] = {1, 2, 3, 4};

    printf("a  의 주소 = %p\n", (void *) &a);
    printf("d  의 주소 = %p\n", (void *) &d);
    printf("c  의 주소 = %p\n", (void *) &c);
    printf("arr      = %p\n", (void *) arr);
    printf("&arr[0]  = %p   <- arr 과 같다\n", (void *) &arr[0]);
    printf("&arr[1]  = %p   <- 4바이트 뒤\n", (void *) &arr[1]);
    printf("arr + 1  = %p   <- &arr[1] 과 같다\n", (void *) (arr + 1));
    return 0;
}
```

**주소 값은 실행할 때마다 달라지므로** 다음은 어디까지나 예시입니다. 숫자 자체가 아니라 **관계**를 보시기 바랍니다.

```text
a  의 주소 = 000000000061FE0C
d  의 주소 = 000000000061FE00
c  의 주소 = 000000000061FDFF
arr      = 000000000061FDE0
&arr[0]  = 000000000061FDE0   <- arr 과 같다
&arr[1]  = 000000000061FDE4   <- 4바이트 뒤
arr + 1  = 000000000061FDE4   <- &arr[1] 과 같다
```

여기서 **이번 강의 전체의 씨앗**이 되는 사실 세 가지가 이미 보입니다.

1. `arr`과 `&arr[0]`의 값이 **같습니다.** 배열 이름은 곧 **첫 원소의 주소**입니다.
2. `&arr[1]`은 `&arr[0]`보다 **4** 큽니다. `int`가 4바이트이기 때문입니다.
3. `arr + 1`이 `&arr[1]`과 **같습니다.** 포인터에 1을 더하면 주소가 1 늘어나는 것이 아니라 **원소 하나만큼** 움직입니다.

> `%p`로 출력할 때 `(void *)`로 캐스트한 이유는 `%p`가 요구하는 자료형이 `void *`이기 때문입니다. 캐스트하지 않으면 `-Wall`에서 경고가 납니다.

## 제2절. 포인터 — `&`와 `*`

### 2.1 포인터는 주소를 담는 변수입니다

**포인터(pointer)** 란 **주소를 값으로 가지는 변수**입니다. 정수를 담는 변수가 `int`이듯, 주소를 담는 변수가 포인터입니다.

```c
int *ip;      /* ip 는 int 를 가리키는 포인터 */
```

이 선언을 읽는 요령이 있습니다. **`*ip`가 `int`이다** — 즉 `ip` 앞에 `*`를 붙이면 `int`가 나오는 그런 변수라는 뜻입니다. C의 선언은 이렇게 **"사용하는 모습"을 흉내 내어** 적습니다.

포인터에 딸린 연산자는 두 개뿐입니다.

| 연산자 | 이름 | 하는 일 |
|---|---|---|
| `&` | 주소 연산자 | 변수의 **주소**를 돌려준다 |
| `*` | 역참조(간접) 연산자 | 포인터가 **가리키는 곳의 값**을 꺼낸다 |

두 연산자는 **서로 반대**입니다.

### 2.2 직접 해 보기

`ptr_basic.c`입니다.

```c
#include <stdio.h>

int main(void)
{
    int x = 1, y = 2;
    int *ip;            /* ip 는 int 를 가리키는 포인터 */

    ip = &x;            /* ip 가 x 를 가리킨다 */
    printf("x = %d, y = %d\n", x, y);
    printf("*ip = %d           <- ip 가 가리키는 값\n", *ip);

    y = *ip;            /* y 에 x 의 값이 들어간다 */
    printf("y = *ip 후: y = %d\n", y);

    *ip = 0;            /* ip 가 가리키는 곳(=x)에 0 을 넣는다 */
    printf("*ip = 0 후: x = %d\n", x);

    *ip = *ip + 10;     /* x 를 10 증가 */
    printf("*ip = *ip + 10 후: x = %d\n", x);

    (*ip)++;            /* 괄호가 중요하다 */
    printf("(*ip)++ 후: x = %d\n", x);

    printf("sizeof(int) = %zu, sizeof(int *) = %zu\n", sizeof(int), sizeof(int *));
    return 0;
}
```

```text
x = 1, y = 2
*ip = 1           <- ip 가 가리키는 값
y = *ip 후: y = 1
*ip = 0 후: x = 0
*ip = *ip + 10 후: x = 10
(*ip)++ 후: x = 11
sizeof(int) = 4, sizeof(int *) = 8
```

**`ip`를 통해 `x`를 읽고 쓸 수 있다**는 점이 핵심입니다. `*ip = 0;`은 `x = 0;`과 완전히 같은 일을 합니다. `ip`가 `x`를 가리키고 있기 때문입니다.

머릿속에 다음 그림을 그려 두면 헷갈리지 않습니다.

| 변수 | 담고 있는 값 | 뜻 |
|---|---|---|
| `x` | `11` | 보통의 정수 |
| `ip` | `x`의 주소 | **주소**를 담고 있음 |
| `*ip` | `11` | `ip`가 가리키는 곳의 값 = `x` |

### 2.3 `(*ip)++`의 괄호

```c
(*ip)++;      /* ip 가 가리키는 값을 1 증가 */
*ip++;        /* 전혀 다른 뜻! */
```

3강 12절의 우선순위 표를 떠올리십시오. **단항 연산자는 오른쪽에서 왼쪽으로 결합**하므로 `*ip++`는 `*(ip++)`로 해석됩니다. 즉 **가리키는 값이 아니라 포인터 자신이 움직입니다.**

값을 바꾸려면 반드시 **괄호를 씌워야** 합니다.

### 2.4 포인터의 크기와 자료형

위 출력에서 `sizeof(int *)`가 **8**입니다. 64비트 환경에서 주소가 8바이트이기 때문입니다. `double *`이든 `char *`이든 **주소를 담으므로 크기는 모두 같습니다.**

그렇다면 왜 `int *`, `double *`처럼 자료형을 구분할까요? 두 가지 이유입니다.

1. **몇 바이트를 읽을지 알아야 합니다.** `*p`로 값을 꺼낼 때 `int`면 4바이트, `double`이면 8바이트를 읽어야 합니다.
2. **포인터 연산의 보폭이 달라집니다.** `p + 1`이 몇 바이트 움직일지는 가리키는 자료형이 결정합니다(제5절).

> **초기화하지 않은 포인터는 매우 위험합니다.**
> ```c
> int *p;      /* 아무 데나 가리키고 있다 */
> *p = 10;     /* 어디에 쓰는지 알 수 없다 — 프로그램이 죽거나 조용히 망가진다 */
> ```
> 포인터는 **반드시 유효한 주소로 초기화한 뒤** 사용하십시오. 아직 가리킬 곳이 없다면 `NULL`을 넣어 두고(제5.4절), 쓰기 전에 검사하는 것이 원칙입니다.

## 제3절. 포인터와 함수 인자

### 3.1 값에 의한 호출의 한계

2강에서 C의 인자 전달은 **값에 의한 호출뿐**이라고 배웠습니다. 함수는 인자의 **복사본**을 받으므로 원본을 바꿀 수 없습니다. 두 변수의 값을 맞바꾸는 함수를 그대로 만들면 실패합니다.

`swap_demo.c`입니다.

```c
#include <stdio.h>

/* 잘못된 판: 복사본만 바꾸므로 호출한 쪽은 그대로다 */
void swap_wrong(int x, int y)
{
    int temp;

    temp = x;
    x = y;
    y = temp;
}

/* 올바른 판: 주소를 받아 원본을 바꾼다 */
void swap(int *px, int *py)
{
    int temp;

    temp = *px;
    *px = *py;
    *py = temp;
}

int main(void)
{
    int a = 1, b = 2;

    swap_wrong(a, b);
    printf("swap_wrong 후: a = %d, b = %d   <- 바뀌지 않았다\n", a, b);

    swap(&a, &b);
    printf("swap 후      : a = %d, b = %d   <- 바뀌었다\n", a, b);
    return 0;
}
```

```text
swap_wrong 후: a = 1, b = 2   <- 바뀌지 않았다
swap 후      : a = 2, b = 1   <- 바뀌었다
```

### 3.2 무슨 일이 일어났는가

| 호출 | 함수가 받은 것 | 결과 |
|---|---|---|
| `swap_wrong(a, b)` | `a`와 `b`의 **값** 1과 2 | 복사본 `x`, `y`만 맞바뀐다. `a`, `b`는 그대로 |
| `swap(&a, &b)` | `a`와 `b`의 **주소** | `*px`, `*py`로 원본을 직접 고친다 |

**여전히 값에 의한 호출입니다.** `swap`도 주소의 복사본을 받습니다. 다만 그 복사본이 **원본을 가리키는 주소**이므로 원본에 접근할 수 있는 것입니다.

이것이 C에서 함수가 호출한 쪽의 값을 바꾸는 **유일한 방법**입니다.

### 3.3 이제 `scanf`의 `&`가 이해됩니다

4강 부록 A에서 "`scanf`에는 `&`를 붙인다"고만 하고 넘어갔습니다. 이유는 이제 분명합니다.

```c
scanf("%d", &n);
```

`scanf`는 읽은 값을 **`n`에 써 넣어야** 합니다. 그러려면 `n`의 값이 아니라 **주소**를 받아야 합니다. `printf`는 값을 읽기만 하므로 주소가 필요 없고, `scanf`는 값을 써야 하므로 주소가 필요합니다.

같은 이유로 **문자 배열에는 `&`를 붙이지 않습니다.** 배열 이름은 그 자체가 이미 주소이기 때문입니다(제4절).

### 3.4 값과 상태를 함께 돌려주기

함수가 **결과와 성공 여부를 동시에** 알려야 할 때가 많습니다. 입력에서 정수를 읽는 함수가 그렇습니다. 읽은 값을 돌려주면 "입력이 끝났다"를 알릴 방법이 없습니다. `EOF`로 쓰기로 한 −1도 정당한 입력값일 수 있기 때문입니다.

**해결책은 값은 포인터로 돌려주고, 반환값은 상태를 알리는 데 쓰는 것**입니다. `scanf`가 바로 이 방식입니다.

`getint_demo.c`입니다.

```c
#include <stdio.h>
#include <ctype.h>

#define SIZE 5

int getint(int *pn);

/* 입력에서 정수를 읽어 배열에 채운다 */
int main(void)
{
    int n, array[SIZE];

    for (n = 0; n < SIZE && getint(&array[n]) != EOF; n++)
        ;

    printf("읽은 개수 = %d\n", n);
    for (int i = 0; i < n; i++)
        printf("array[%d] = %d\n", i, array[i]);
    return 0;
}

/* getint: 다음 정수를 읽어 *pn 에 넣는다.
   돌려주는 값 — EOF(입력 끝), 0(숫자가 아님), 그 밖(정상) */
int getint(int *pn)
{
    int c, sign;

    while (isspace(c = getchar()))       /* 공백류 건너뛰기 */
        ;
    if (!isdigit(c) && c != EOF && c != '+' && c != '-') {
        ungetc(c, stdin);                /* 숫자가 아니면 되돌린다 */
        return 0;
    }
    sign = (c == '-') ? -1 : 1;
    if (c == '+' || c == '-')
        c = getchar();
    for (*pn = 0; isdigit(c); c = getchar())
        *pn = 10 * *pn + (c - '0');
    *pn *= sign;
    if (c != EOF)
        ungetc(c, stdin);
    return c;
}
```

입력이 다음과 같을 때

```text
10 20 -30 40 50
```

```text
읽은 개수 = 5
array[0] = 10
array[1] = 20
array[2] = -30
array[3] = 40
array[4] = 50
```

읽을 점이 세 가지입니다.

- **`getint(&array[n])`** — 배열 원소 하나의 주소를 넘겼습니다. `array[n]`은 `int`이므로 `&`를 붙이면 `int *`가 됩니다.
- **`*pn`은 보통의 `int` 변수처럼 쓰였습니다.** `*pn = 10 * *pn + (c - '0');` 처럼 읽고 쓰기가 모두 됩니다.
- **`ungetc`** 는 5강에서 우리가 직접 만들었던 `ungetch`의 표준 라이브러리판입니다. 다만 **되돌릴 수 있는 글자가 하나뿐**임이 보장될 뿐이므로, 두 글자를 되돌려야 하면 5강처럼 직접 버퍼를 만들어야 합니다(실습문제 1).

## 제4절. 포인터와 배열

### 4.1 배열 이름은 첫 원소의 주소입니다

C에서 포인터와 배열은 **떼어 놓고 설명할 수 없을 만큼** 밀접합니다. 다음 선언을 봅니다.

```c
int a[5];
int *pa;
```

`a`는 정수 5개가 연속으로 놓인 자리이고, 각각은 `a[0]`부터 `a[4]`입니다. 여기서

```c
pa = &a[0];
```

라고 하면 `pa`는 `a[0]`을 가리킵니다. 그런데 **배열 이름 자체가 첫 원소의 주소**이므로 다음처럼 짧게 쓸 수 있습니다.

```c
pa = a;      /* pa = &a[0] 과 같다 */
```

### 4.2 `a[i]`와 `*(a+i)`는 같습니다

포인터에 정수를 더하면 **그만큼 뒤의 원소를 가리킵니다.** 그래서 다음이 모두 성립합니다.

| 표기 | 같은 뜻 |
|---|---|
| `a[i]` | `*(a + i)` |
| `&a[i]` | `a + i` |
| `pa[i]` | `*(pa + i)` |

**컴파일러는 `a[i]`를 만나면 곧바로 `*(a+i)`로 바꾸어 처리합니다.** 즉 배열 첨자는 포인터 연산의 편한 표기일 뿐입니다.

`array_ptr.c`로 확인합니다.

```c
#include <stdio.h>

int main(void)
{
    int a[5] = {10, 20, 30, 40, 50};
    int *pa;
    int i;

    pa = &a[0];          /* pa = a; 와 같다 */

    printf("a[2]      = %d\n", a[2]);
    printf("*(a + 2)  = %d   <- a[2] 와 같은 뜻\n", *(a + 2));
    printf("pa[2]     = %d   <- 포인터에도 첨자를 쓸 수 있다\n", pa[2]);
    printf("*(pa + 2) = %d\n", *(pa + 2));

    printf("\n포인터를 옮겨 가며 출력:\n");
    for (pa = a; pa < a + 5; pa++)
        printf("  %d", *pa);
    printf("\n");

    printf("\n첨자로 출력:\n");
    for (i = 0; i < 5; i++)
        printf("  %d", a[i]);
    printf("\n");

    pa = a + 3;
    printf("\npa = a + 3 일 때\n");
    printf("  *pa      = %d\n", *pa);
    printf("  pa - a   = %td   <- 몇 번째 원소인지\n", pa - a);
    printf("  pa[-1]   = %d   <- 바로 앞 원소\n", pa[-1]);
    return 0;
}
```

```text
a[2]      = 30
*(a + 2)  = 30   <- a[2] 와 같은 뜻
pa[2]     = 30   <- 포인터에도 첨자를 쓸 수 있다
*(pa + 2) = 30

포인터를 옮겨 가며 출력:
  10  20  30  40  50

첨자로 출력:
  10  20  30  40  50

pa = a + 3 일 때
  *pa      = 40
  pa - a   = 3   <- 몇 번째 원소인지
  pa[-1]   = 30   <- 바로 앞 원소
```

### 4.3 결정적인 차이 하나

배열 이름과 포인터가 아무리 닮았어도 **한 가지 차이**가 있습니다.

> **포인터는 변수이지만, 배열 이름은 변수가 아닙니다.**

| 문장 | 가능한가 |
|---|---|
| `pa = a;` | ✅ 포인터에 주소를 대입 |
| `pa++;` | ✅ 포인터를 옮김 |
| `a = pa;` | ❌ **오류** — 배열 이름에는 대입할 수 없다 |
| `a++;` | ❌ **오류** — 배열 이름은 움직일 수 없다 |

배열 이름은 "그 자리를 가리키는 고정된 이름표"이지 값을 바꿀 수 있는 상자가 아닙니다.

### 4.4 배열을 함수에 넘기면 무슨 일이 벌어지는가

이제 2강과 4강에서 미뤄 둔 물음에 답할 수 있습니다.

**배열을 함수에 넘기면 전달되는 것은 첫 원소의 주소뿐입니다.** 원소 전체가 복사되지 않습니다. 그래서

- 배열이 아무리 커도 **넘기는 비용은 주소 하나**로 같습니다.
- 함수 안에서 원소를 고치면 **원본이 바뀝니다.**
- 함수는 **배열의 크기를 알 수 없습니다.** 그래서 `binsearch(x, v, n)`처럼 크기를 따로 넘겨야 합니다.

함수의 매개변수 자리에서는 다음 두 표기가 **완전히 같습니다.**

```c
int strlen1(const char s[]);     /* 배열처럼 적기 */
int strlen2(const char *s);      /* 포인터로 적기 */
```

K&R은 **뒤쪽을 권합니다.** 그 매개변수가 실제로 포인터라는 사실이 더 분명히 드러나기 때문입니다.

### 4.5 같은 함수를 세 가지로 써 보기

`strlen3.c`는 문자열의 길이를 세는 함수를 세 가지 방식으로 만든 것입니다.

```c
#include <stdio.h>

/* 판 1: 배열 첨자 */
int strlen1(const char s[])
{
    int n;

    for (n = 0; s[n] != '\0'; n++)
        ;
    return n;
}

/* 판 2: 포인터를 옮겨 가며 센다 */
int strlen2(const char *s)
{
    int n;

    for (n = 0; *s != '\0'; s++)
        n++;
    return n;
}

/* 판 3: 포인터 뺄셈 */
int strlen3(const char *s)
{
    const char *p = s;

    while (*p != '\0')
        p++;
    return (int) (p - s);
}

int main(void)
{
    char arr[100] = "hello, world";
    const char *ptr = "hello, world";

    printf("strlen1(문자열 상수) = %d\n", strlen1("hello, world"));
    printf("strlen2(배열)        = %d\n", strlen2(arr));
    printf("strlen3(포인터)      = %d\n", strlen3(ptr));
    return 0;
}
```

```text
strlen1(문자열 상수) = 12
strlen2(배열)        = 12
strlen3(포인터)      = 12
```

세 함수 모두 **문자열 상수·배열·포인터를 가리지 않고** 받을 수 있습니다. 어차피 넘어오는 것은 주소 하나이기 때문입니다.

판 2에서 `s++`를 한 것에 놀랄 필요가 없습니다. `s`는 **함수가 받은 복사본**이므로, 아무리 움직여도 호출한 쪽의 배열이나 포인터에는 아무 영향이 없습니다.

### 4.6 배열의 일부를 넘기기

배열의 중간부터 넘기고 싶으면 그 자리의 주소를 주면 됩니다.

```c
f(&a[2]);      /* 두 가지 표기는 같다 */
f(a + 2);
```

함수 쪽에서는 그것이 큰 배열의 일부인지 아닌지 **알 수도 없고 알 필요도 없습니다.** 받은 주소부터가 자기 배열인 것처럼 다루면 됩니다.

## 제5절. 포인터 연산

### 5.1 허용되는 연산은 정해져 있습니다

포인터로 할 수 있는 일은 다음이 **전부**입니다.

| 할 수 있는 것 | 예 |
|---|---|
| 같은 자료형 포인터끼리 대입 | `p = q;` |
| 포인터 ± 정수 | `p + 3`, `p - 1`, `p++` |
| **같은 배열 안**의 두 포인터 빼기 | `q - p` |
| **같은 배열 안**의 두 포인터 비교 | `p < q`, `p == q` |
| `NULL`(0)과 대입·비교 | `p = NULL;`, `if (p != NULL)` |

반대로 **할 수 없는 것**도 분명합니다. 포인터끼리 더하기, 곱하기·나누기, 실수 더하기, 다른 자료형 포인터를 캐스트 없이 대입하기 — 모두 오류입니다.

### 5.2 1을 더하면 몇 바이트 움직이는가

`ptr_arith.c`로 확인합니다.

```c
#include <stdio.h>

int main(void)
{
    int a[8] = {1, 2, 3, 4, 5, 6, 7, 8};
    int *p, *q;
    double d[4];

    p = &a[1];
    q = &a[5];

    printf("q - p        = %td   <- 사이에 있는 원소 개수\n", q - p);
    printf("*p = %d, *q = %d\n", *p, *q);
    printf("p < q        = %d\n", p < q);
    printf("p == &a[1]   = %d\n", p == &a[1]);

    p += 2;
    printf("p += 2 후 *p = %d\n", *p);
    p--;
    printf("p-- 후   *p = %d\n", *p);

    /* 포인터를 1 늘리면 가리키는 자료형의 크기만큼 주소가 움직인다 */
    printf("\nint  포인터: (a+1) - a 의 주소 차이 = %td 바이트\n",
           (char *) (a + 1) - (char *) a);
    printf("double 포인터: (d+1) - d 의 주소 차이 = %td 바이트\n",
           (char *) (d + 1) - (char *) d);
    return 0;
}
```

```text
q - p        = 4   <- 사이에 있는 원소 개수
*p = 2, *q = 6
p < q        = 1
p == &a[1]   = 1
p += 2 후 *p = 4
p-- 후   *p = 3

int  포인터: (a+1) - a 의 주소 차이 = 4 바이트
double 포인터: (d+1) - d 의 주소 차이 = 8 바이트
```

**`p + 1`은 주소를 1 늘리는 것이 아니라 원소 하나만큼 옮기는 것**입니다. `int`면 4바이트, `double`이면 8바이트가 움직입니다. 그래서 자료형이 다른 포인터를 섞어 쓸 수 없는 것입니다.

**포인터끼리 빼면 "몇 개 떨어져 있는가"** 가 나옵니다. 위에서 `q - p`가 4인 것은 `a[1]`과 `a[5]` 사이에 원소가 4개 있다는 뜻입니다. 이 결과의 자료형은 `ptrdiff_t`이며 `%td`로 출력합니다.

### 5.3 저장 공간을 나누어 주는 프로그램

포인터 연산이 실제로 쓰이는 예로, 큰 배열을 조금씩 잘라서 빌려주는 아주 단순한 **저장소 할당기**를 만들어 봅니다.

`alloc_demo.c`입니다.

```c
#include <stdio.h>

#define ALLOCSIZE 10000     /* 쓸 수 있는 저장 공간의 크기 */

static char allocbuf[ALLOCSIZE];    /* alloc 이 나누어 주는 공간 */
static char *allocp = allocbuf;     /* 다음에 내어 줄 위치 */

/* alloc: n 글자를 담을 수 있는 자리를 내어 준다. 공간이 없으면 NULL */
char *alloc(int n)
{
    if (allocbuf + ALLOCSIZE - allocp >= n) {   /* 자리가 있으면 */
        allocp += n;
        return allocp - n;                      /* 내어 준 자리의 시작 */
    }
    return NULL;                                /* 자리가 없다 */
}

/* afree: p 부터의 공간을 되돌려 준다 */
void afree(char *p)
{
    if (p >= allocbuf && p < allocbuf + ALLOCSIZE)
        allocp = p;
}
```

```text
처음 사용량 = 0
100 요청 후 사용량 = 100, 성공 여부 = 성공
50 요청 후  사용량 = 150
second - first = 100   <- 앞서 내어 준 100칸 뒤에 놓인다
second 반납 후 사용량 = 100
first 반납 후  사용량 = 0
너무 큰 요청(20000) = NULL (실패)
```

이 짧은 코드에 포인터 연산이 모두 들어 있습니다.

| 코드 | 쓰인 연산 |
|---|---|
| `allocbuf + ALLOCSIZE - allocp >= n` | 포인터 + 정수, 포인터 − 포인터, 비교 |
| `allocp += n` | 포인터 이동 |
| `return allocp - n` | 포인터 − 정수 |
| `p >= allocbuf && p < allocbuf + ALLOCSIZE` | 포인터 비교로 **범위 검사** |
| `return NULL` | 실패를 알리는 값 |

- **함수가 포인터를 돌려줍니다.** 반환 자료형이 `char *`인 것에 주목하십시오.
- `static`으로 감춘 덕분에(5강 7.1절) 밖에서는 `allocbuf`의 존재조차 알 수 없습니다. 오직 `alloc`과 `afree`로만 접근합니다.
- 표준 라이브러리의 `malloc`·`free`가 이와 같은 일을 훨씬 정교하게 해 줍니다. 여기서는 원리만 확인합니다.

### 5.4 `NULL` — "아무것도 가리키지 않음"

**주소 0은 어떤 자료에도 쓰이지 않는다고 보장되어 있습니다.** 그래서 0을 "유효한 주소가 아님"이라는 뜻으로 씁니다. `<stdio.h>` 등에 정의된 기호 상수 `NULL`이 그것입니다.

```c
char *p = NULL;

if (p != NULL)
    *p = 'A';        /* 유효할 때만 사용 */
```

> **`NULL` 검사를 생략하지 마십시오.**
> 포인터를 돌려주는 함수는 대개 실패를 `NULL`로 알립니다. 검사 없이 그대로 `*p`를 쓰면 프로그램이 즉시 죽습니다. 잘 죽으면 그나마 다행이고, 조용히 엉뚱한 메모리를 건드리는 편이 훨씬 나쁩니다.
{: .prompt-danger }

### 5.5 배열 범위를 벗어난 포인터

포인터 비교와 연산은 **같은 배열 안**에서만 뜻이 있습니다. 예외가 하나 있는데, **배열의 끝 바로 다음 자리**는 계산에 쓸 수 있습니다(`a + 5`처럼). 다만 그 자리의 **값을 읽거나 쓰는 것은 안 됩니다.**

```c
for (p = a; p < a + 5; p++)     /* 올바름: a + 5 는 비교에만 쓴다 */
    printf("%d ", *p);
```

```c
for (p = a; p <= a + 5; p++)    /* 잘못: 마지막에 배열 밖을 읽는다 */
    printf("%d ", *p);
```

**이것이 2강·5강에서 예고한 버퍼 오버플로와 같은 문제**입니다. 배열 밖을 가리키는 포인터를 만드는 것 자체가 이미 위험 신호이며, 그 값을 읽거나 쓰면 무슨 일이 일어날지 알 수 없습니다.

## 제6절. 문자 포인터와 문자열

### 6.1 문자열 상수는 문자 배열입니다

```c
"I am a string"
```

이런 문자열 상수는 메모리에 **문자들과 끝의 `'\0'`이 놓인 배열**로 저장되고, 프로그램은 **그 첫 글자를 가리키는 포인터**로 접근합니다. `printf("hello\n")`에서 `printf`가 실제로 받는 것도 주소 하나입니다.

### 6.2 `char amessage[]`와 `char *pmessage`

이 둘의 차이는 포인터 학습에서 가장 중요한 갈림길입니다.

```c
char amessage[] = "now is the time";      /* 배열 */
char *pmessage  = "now is the time";      /* 포인터 */
```

| 구분 | `amessage` (배열) | `pmessage` (포인터) |
|---|---|---|
| 무엇인가 | 글자들을 담은 **자기 소유의 저장 공간** | 문자열 상수를 **가리키는 주소 하나** |
| 크기 | 문자열 전체 + `'\0'` = 16바이트 | 주소 크기 = 8바이트 |
| 내용을 바꿀 수 있는가 | ✅ 가능 | ❌ **불가**(문자열 상수는 고칠 수 없다) |
| 다른 곳을 가리키게 할 수 있는가 | ❌ 배열 이름은 변수가 아니다 | ✅ 가능 |

`str_ptr_array.c`입니다.

```c
#include <stdio.h>

int main(void)
{
    char amessage[] = "now is the time";    /* 배열 — 내용을 바꿀 수 있다 */
    const char *pmessage = "now is the time"; /* 포인터 — 문자열 상수를 가리킨다 */

    printf("amessage = %s\n", amessage);
    printf("pmessage = %s\n", pmessage);
    printf("sizeof amessage = %zu   <- 문자열 전체를 담은 배열\n", sizeof amessage);
    printf("sizeof pmessage = %zu   <- 주소 하나의 크기\n", sizeof pmessage);

    amessage[0] = 'N';                /* 배열의 내용은 바꿀 수 있다 */
    printf("amessage[0] 변경 후 = %s\n", amessage);

    pmessage = "later";               /* 포인터가 다른 곳을 가리키게 할 수는 있다 */
    printf("pmessage 재지정 후  = %s\n", pmessage);
    return 0;
}
```

```text
amessage = now is the time
pmessage = now is the time
sizeof amessage = 16   <- 문자열 전체를 담은 배열
sizeof pmessage = 8   <- 주소 하나의 크기
amessage[0] 변경 후 = Now is the time
pmessage 재지정 후  = later
```

> **문자열 상수를 고치면 안 됩니다.**
> ```c
> char *p = "hello";
> p[0] = 'H';          /* 절대 하면 안 된다 */
> ```
> 문자열 상수는 대개 **읽기 전용 메모리**에 놓이므로, 고치려 하면 프로그램이 그 자리에서 죽습니다. 그래서 위 예제에서 `pmessage`를 **`const char *`** 로 선언한 것입니다. `const`를 붙여 두면 실수로 고치는 코드를 **컴파일러가 미리 막아 줍니다**(3강 4.3절).
>
> 내용을 바꿔야 한다면 반드시 **배열로 선언**하십시오.

### 6.3 `strcpy` — 세 가지 표기

문자열을 복사하는 함수를 만들며 포인터 표기에 익숙해져 봅니다. `s = t;`로는 **주소만 복사**될 뿐 글자는 복사되지 않으므로 반복이 필요합니다.

`strcpy_cmp.c`의 일부입니다.

```c
/* 판 1: 배열 첨자 */
void strcpy1(char *s, const char *t)
{
    int i;

    i = 0;
    while ((s[i] = t[i]) != '\0')
        i++;
}

/* 판 2: 포인터 */
void strcpy2(char *s, const char *t)
{
    while ((*s = *t) != '\0') {
        s++;
        t++;
    }
}

/* 판 3: 숙련된 C 프로그래머의 표기 */
void strcpy3(char *s, const char *t)
{
    while ((*s++ = *t++) != '\0')
        ;
}
```

세 판은 **완전히 같은 일**을 합니다. 판 3의 `*s++ = *t++`를 풀어 보면 이렇습니다.

| 순서 | 하는 일 |
|---|---|
| 1 | `*t`의 값을 꺼낸다(아직 `t`는 그대로) |
| 2 | 그 값을 `*s` 자리에 넣는다(아직 `s`는 그대로) |
| 3 | 그다음 `t`와 `s`를 각각 한 칸 옮긴다 |

3강 8절의 **후위 증가**가 "값을 먼저 쓰고 나중에 옮긴다"였음을 떠올리면 정확히 들어맞습니다.

실무의 `strcpy`는 여기서 한 단계 더 줄여 `while (*s++ = *t++);` 로 씁니다. `'\0'`은 값이 0이므로 **조건이 자연히 거짓이 되기** 때문입니다. 처음에는 암호처럼 보이지만 **C 코드에서 매우 자주 만나는 관용구**이므로 눈에 익혀 두어야 합니다.

### 6.4 `strcmp` — 문자열 비교

```c
/* strcmp: s < t 이면 음수, 같으면 0, s > t 이면 양수 */
int strcmp1(const char *s, const char *t)
{
    int i;

    for (i = 0; s[i] == t[i]; i++)
        if (s[i] == '\0')
            return 0;
    return s[i] - t[i];
}

/* strcmp 의 포인터 판 */
int strcmp2(const char *s, const char *t)
{
    for ( ; *s == *t; s++, t++)
        if (*s == '\0')
            return 0;
    return *s - *t;
}
```

```text
strcpy1 -> hello
strcpy2 -> world
strcpy3 -> pointer
strcmp1("abc", "abc") = 0
strcmp1("abc", "abd") = -1
strcmp2("abd", "abc") = 1
strcmp2("ab",  "abc") = -99
```

**처음으로 다른 글자가 나온 자리에서 두 문자를 뺀 값**을 돌려줍니다. `"abc"`와 `"abd"`는 `'c' - 'd'` = **−1**입니다.

마지막 결과가 −99인 것은 `"ab"` 쪽이 `'\0'`(0)이고 `"abc"` 쪽이 `'c'`(99)이기 때문입니다. **문자열 비교의 결과는 "음수·0·양수"라는 사실만 쓰고, 그 크기에 의존하지 마십시오.** 표준 `strcmp`도 −1이나 1을 돌려준다는 보장이 없습니다.

> `strcmp`로 문자열이 같은지 확인할 때는 이렇게 씁니다.
> ```c
> if (strcmp(a, b) == 0)       /* 같다 */
> ```
> **`if (a == b)` 는 주소를 비교**하는 것이므로 전혀 다른 뜻입니다. 초심자가 가장 많이 하는 실수 중 하나입니다.

### 문제 1. `getint` — 부호만 있고 숫자가 없을 때

3.4절의 `getint`는 `+`나 `-` 뒤에 숫자가 없어도 **0을 읽은 것처럼** 처리합니다. 부호까지 입력으로 되돌리도록 고치십시오.

**정답 및 해설**

```c
/* 표준 ungetc 는 한 글자만 되돌릴 수 있으므로,
   5강에서 만든 방식대로 자체 버퍼를 둔다 */
#define BUFSIZE 100

static int buf[BUFSIZE];
static int bufp = 0;

int getch(void)
{
    return (bufp > 0) ? buf[--bufp] : getchar();
}

void ungetch(int c)
{
    if (bufp >= BUFSIZE)
        printf("오류: 되돌릴 수 있는 글자 수를 넘었습니다\n");
    else
        buf[bufp++] = c;
}

/* getint 개선판: 부호 뒤에 숫자가 없으면 부호까지 되돌린다 */
int getint(int *pn)
{
    int c, sign, next;

    while (isspace(c = getch()))
        ;
    if (!isdigit(c) && c != EOF && c != '+' && c != '-') {
        ungetch(c);
        return 0;
    }
    sign = (c == '-') ? -1 : 1;
    if (c == '+' || c == '-') {
        next = getch();
        if (!isdigit(next)) {          /* 부호 뒤가 숫자가 아니면 */
            if (next != EOF)
                ungetch(next);         /* 뒤 글자를 되돌리고 */
            ungetch(c);                /* 부호도 되돌린다 */
            return 0;                  /* 숫자가 아니었다고 알린다 */
        }
        c = next;
    }
    for (*pn = 0; isdigit(c); c = getch())
        *pn = 10 * *pn + (c - '0');
    *pn *= sign;
    if (c != EOF)
        ungetch(c);
    return c;
}
```

- **이 문제의 핵심은 "두 글자를 되돌려야 한다"는 것**입니다. 부호와 그 뒤 글자를 모두 되돌려야 하기 때문입니다.
- 그런데 **표준 `ungetc`는 한 글자만 보장**합니다. 그래서 5강에서 만들었던 **자체 버퍼 방식**으로 되돌아왔습니다. K&R이 표준 함수가 있는데도 `getch`·`ungetch`를 직접 만든 이유가 바로 이것입니다.
- 되돌리는 **순서**에 주의하십시오. 나중에 넣은 것이 먼저 나오므로, `next`를 먼저 넣고 부호를 나중에 넣어야 다음 읽기에서 부호가 먼저 나옵니다.

### 문제 2. `getfloat`

`getint`의 실수 판인 `getfloat`를 작성하십시오. 값은 `double *`로 돌려줍니다.

**정답 및 해설**

```c
/* getfloat: getint 의 실수 판 */
int getfloat(double *pn)
{
    int c, sign;
    double power;

    while (isspace(c = getchar()))
        ;
    if (!isdigit(c) && c != EOF && c != '+' && c != '-' && c != '.') {
        ungetc(c, stdin);
        return 0;
    }
    sign = (c == '-') ? -1 : 1;
    if (c == '+' || c == '-')
        c = getchar();

    for (*pn = 0.0; isdigit(c); c = getchar())      /* 정수부 */
        *pn = 10.0 * *pn + (c - '0');
    if (c == '.')
        c = getchar();
    for (power = 1.0; isdigit(c); c = getchar()) {  /* 소수부 */
        *pn = 10.0 * *pn + (c - '0');
        power *= 10.0;
    }
    *pn *= sign / power;
    if (c != EOF)
        ungetc(c, stdin);
    return c;
}
```

입력이 `3.14 -2.5 0.125` 일 때

```text
읽은 실수 = 3.14
읽은 실수 = -2.5
읽은 실수 = 0.125
```

- **돌려주는 값의 자료형은 여전히 `int`** 입니다. 반환값은 "상태"(EOF·0·그 밖)를 알리는 용도이고, **실수 값 자체는 포인터로 전달**하기 때문입니다. 3.4절에서 설명한 설계 그대로입니다.
- 소수부 처리는 5강 2.1절의 `my_atof`와 같습니다. 자릿수만큼 `power`를 키워 두었다가 마지막에 나눕니다.
- `.5` 처럼 소수점으로 시작하는 입력도 받아들이도록 첫 검사에 `c != '.'`를 넣었습니다.

### 문제 3·4. `strcat`과 `strend`

- `strcat(s, t)` — `t`를 `s`의 끝에 이어 붙인다. **포인터 표기**로 작성하십시오.
- `strend(s, t)` — `t`가 `s`의 **끝부분에 나타나면** 1, 아니면 0을 돌려준다.

**정답 및 해설**

```c
/* strcat 포인터 판 */
void my_strcat(char *s, const char *t)
{
    while (*s)          /* s 의 끝을 찾는다 */
        s++;
    while ((*s++ = *t++) != '\0')
        ;
}

/* strend: t 가 s 의 끝에 나타나면 1, 아니면 0 */
int strend(const char *s, const char *t)
{
    const char *ps, *pt;

    ps = s;
    pt = t;
    while (*ps)
        ps++;
    while (*pt)
        pt++;

    while (ps >= s && pt >= t) {
        if (*ps != *pt)
            return 0;
        if (pt == t)        /* t 를 끝까지 맞추었다 */
            return 1;
        ps--;
        pt--;
    }
    return 0;
}
```

```text
my_strcat  -> hello, world
strend("hello.txt", ".txt") = 1
strend("hello.txt", ".c")   = 0
```

- `while (*s) s++;` 는 `while (*s != '\0') s++;` 의 줄임입니다. `'\0'`이 0이므로 조건이 자연히 거짓이 됩니다.
- `strend`는 **뒤에서부터 맞추어 보는 것**이 요령입니다. 두 포인터를 각각 끝에 놓고 한 칸씩 앞으로 오면서 비교합니다.
- `pt == t`가 되면 `t`의 첫 글자까지 모두 맞은 것이므로 성공입니다. 이 검사를 빠뜨리면 배열 앞을 벗어나게 됩니다(5.5절).

### 문제 5. `strncpy`·`strncmp`

앞의 `n`글자만 다루는 판을 작성하십시오.

**정답 및 해설**

```c
/* strncpy: t 의 앞 n 글자를 s 로 복사한다 */
void my_strncpy(char *s, const char *t, int n)
{
    while (n > 0 && *t) {
        *s++ = *t++;
        n--;
    }
    while (n > 0) {         /* 모자라면 '\0' 으로 채운다 */
        *s++ = '\0';
        n--;
    }
}

/* strncmp: 앞 n 글자만 비교한다 */
int my_strncmp(const char *s, const char *t, int n)
{
    for ( ; n > 0 && *s == *t; s++, t++, n--)
        if (*s == '\0')
            return 0;
    return (n == 0) ? 0 : *s - *t;
}
```

```text
my_strncpy(5) -> progr
my_strncmp("program", "progress", 4) = 0
my_strncmp("program", "progress", 6) = -4
```

- 앞 4글자(`prog`)까지는 같으므로 0, 6글자까지 비교하면 5번째에서 `'a'`와 `'e'`가 달라 **−4**가 나옵니다.
- **`my_strncpy`는 `'\0'`을 붙여 주지 않을 수 있습니다.** `n`글자를 다 채우면 끝 표시가 없는 상태가 되므로, 문자열로 쓰려면 호출한 쪽이 직접 `cut[5] = '\0';` 처럼 붙여야 합니다. 표준 `strncpy`도 같은 성질을 가지며, 이 때문에 **실무에서 사고가 잦은 함수**입니다. 10강에서 안전한 대안을 다룹니다.

### 문제 6·7. 포인터 표기로 다시 쓰기

`atoi`와 `reverse`를 **포인터 표기**로 다시 쓰고, 배열의 합과 최댓값을 포인터로 구하는 함수를 작성하십시오.

**정답 및 해설**

```c
/* atoi 의 포인터 판 */
int atoi_ptr(const char *s)
{
    int n, sign;

    while (isspace((unsigned char) *s))
        s++;
    sign = (*s == '-') ? -1 : 1;
    if (*s == '+' || *s == '-')
        s++;
    for (n = 0; isdigit((unsigned char) *s); s++)
        n = 10 * n + (*s - '0');
    return sign * n;
}

/* reverse 의 포인터 판 */
void reverse_ptr(char *s)
{
    char *end, temp;

    end = s;
    while (*end)
        end++;
    end--;                  /* 마지막 글자 */

    while (s < end) {
        temp = *s;
        *s++ = *end;
        *end-- = temp;
    }
}

/* 배열의 합과 최댓값을 포인터로 구한다 */
void sum_max(const int *p, int n, int *psum, int *pmax)
{
    const int *end = p + n;

    *psum = 0;
    *pmax = *p;
    for ( ; p < end; p++) {
        *psum += *p;
        if (*p > *pmax)
            *pmax = *p;
    }
}
```

```text
atoi_ptr("  -1234abc") = -1234
reverse_ptr -> gnimmargorp
합 = 86, 최댓값 = 42
```

- `reverse_ptr`은 **두 포인터가 양쪽에서 안으로 좁혀 오다가 만나면 멈춥니다.** 조건이 `s < end`이므로 가운데에서 자동으로 끝납니다.
- `*s++ = *end;` 와 `*end-- = temp;` 에서 후위 증감이 "값을 쓴 뒤에 옮긴다"로 정확히 동작합니다.
- `sum_max`는 **결과를 두 개 돌려주어야 하므로 포인터를 두 개 받았습니다.** 3.4절에서 본 방식의 응용입니다.
- 반복의 끝을 `end = p + n`으로 미리 계산해 두면 매번 `p < arr + n`을 계산하지 않아도 됩니다.

### 문제 8. `swap`으로 세 값 정렬하기

`swap(int *, int *)`만 사용하여 세 정수를 오름차순으로 정렬하는 함수를 작성하십시오.

**정답 및 해설**

```c
void sort3(int *a, int *b, int *c)
{
    if (*a > *b)
        swap(a, b);
    if (*b > *c)
        swap(b, c);
    if (*a > *b)      /* 두 번째 비교로 a 가 밀려났을 수 있으므로 다시 */
        swap(a, b);
}
```

- **세 번의 비교가 필요합니다.** 마지막 비교를 빠뜨리면 `3 2 1` 같은 입력에서 정렬이 완성되지 않습니다. 직접 손으로 따라가 확인해 보십시오.
- 인자 이름이 `a`, `b`, `c`이지만 **모두 포인터**이므로 비교할 때 `*a > *b`처럼 별을 붙여야 합니다. `a > b`라고 쓰면 **주소를 비교**하게 되어 전혀 다른 뜻이 됩니다. 컴파일도 통과하므로 특히 조심해야 합니다.
- 이 함수는 4강의 셸 정렬·5강의 퀵 정렬과 같은 원리(비교하고 맞바꾸기)를 가장 작은 규모로 보여 줍니다.

### 문제 9. `alloc`으로 문자열 보관하기

5.3절의 `alloc`을 사용하여 입력받은 문자열을 보관하고 출력하는 프로그램을 작성하십시오. 공간이 모자라면 오류를 알려야 합니다.

**정답 및 해설**

```c
char *save_string(const char *s)
{
    int len = 0;
    char *p, *q;

    while (s[len] != '\0')       /* 필요한 길이를 센다 */
        len++;

    p = alloc(len + 1);          /* '\0' 자리까지 확보 */
    if (p == NULL)               /* 반드시 검사 */
        return NULL;

    q = p;
    while ((*q++ = *s++) != '\0')
        ;
    return p;
}
```

- **`len + 1`을 요청한 것**이 핵심입니다. `'\0'` 자리를 빠뜨리면 문자열이 어디서 끝나는지 알 수 없게 되고, 뒤이어 저장한 다른 문자열까지 이어서 출력됩니다.
- **`alloc`의 결과를 반드시 `NULL`과 비교**해야 합니다(5.4절). 검사하지 않고 `*p`에 쓰면 공간이 없을 때 프로그램이 죽습니다.
- 이 함수는 이름이 다를 뿐 표준 라이브러리의 `strdup`과 같은 일을 합니다.

### 문제 10. 배열 표기 ↔ 포인터 표기

다음 함수를 **포인터 표기만 사용**하여 다시 쓰고, 두 판이 같은 일을 함을 확인하십시오.

```c
/* 배열 표기 */
int count_char(const char s[], char target)
{
    int i, n = 0;

    for (i = 0; s[i] != '\0'; i++)
        if (s[i] == target)
            n++;
    return n;
}
```

**정답 및 해설**

```c
/* 포인터 표기 */
int count_char_ptr(const char *s, char target)
{
    int n = 0;

    for ( ; *s != '\0'; s++)
        if (*s == target)
            n++;
    return n;
}
```

두 판의 대응 관계는 다음과 같습니다.

| 배열 표기 | 포인터 표기 | 설명 |
|---|---|---|
| `s[i]` | `*s` | 현재 글자 |
| `i++` | `s++` | 다음으로 이동 |
| `s[i] != '\0'` | `*s != '\0'` | 끝인지 검사 |
| 첨자 `i`가 필요 | 첨자 불필요 | 포인터 자신이 위치를 기억 |

- 두 판은 **완전히 같은 일**을 합니다. 어느 쪽을 쓸지는 취향과 문맥의 문제입니다.
- 다만 **위치 번호가 필요하면 첨자 표기**가 낫습니다. "몇 번째에서 찾았는지"를 돌려주어야 한다면 `i`가 그대로 답이 되기 때문입니다.
- 포인터 표기는 **문자열을 훑는 코드**에서 특히 간결합니다. `while (*s++)` 같은 관용구가 그 예입니다.

## 정리

| 구분 | 내용 |
|---|---|
| 포인터 | **주소를 담는 변수**. `int *p;`는 "`*p`가 `int`"라고 읽는다 |
| `&`와 `*` | 주소를 얻는다 / 가리키는 값을 꺼낸다. 서로 반대 |
| 함수 인자 | 주소를 넘기면 **원본을 바꿀 수 있다**. `scanf`의 `&`가 그 이유 |
| 값 + 상태 | 결과는 포인터로, 성공 여부는 반환값으로 (`getint`, `scanf`) |
| 배열과 포인터 | `a[i]` ≡ `*(a+i)`, `&a[i]` ≡ `a+i`, **배열 이름 = 첫 원소의 주소** |
| 결정적 차이 | 포인터는 변수, **배열 이름은 변수가 아니다**(`a++` 불가) |
| 배열 전달 | 주소만 전달된다 → 크기를 함께 넘겨야 하고, 함수가 원본을 고칠 수 있다 |
| 포인터 연산 | `p ± 정수`는 **원소 단위**로 움직인다. 뺄셈·비교는 **같은 배열 안에서만** |
| `NULL` | "아무것도 가리키지 않음". 쓰기 전에 **반드시 검사** |
| 문자열 | `char s[]`는 자기 저장 공간(수정 가능), `char *s`는 상수를 가리킴(**수정 불가**) |
| 관용구 | `while ((*s++ = *t++) != '\0')` — 복사·이동·검사를 한 줄에 |

포인터의 기본을 익혔습니다. 그러나 아직 다루지 못한 것이 남아 있습니다. 문자열 여러 개를 한꺼번에 다루려면, 표를 다루려면, 프로그램 실행 시 옵션을 받으려면 어떻게 해야 할까요?

**다음 7강에서는 포인터의 활용(K&R 5.6 ~ 5.12)** 을 다룹니다. **포인터 배열**로 문자열 목록을 정렬하고, **다차원 배열**과 포인터 배열의 차이를 구분하며, **명령행 인자**로 프로그램에 값을 넘기고, **함수를 가리키는 포인터**까지 나아갑니다. 그리고 2강부터 예고해 온 **버퍼 오버플로가 실제로 값을 어떻게 망가뜨리는지** 직접 확인합니다.

## 부록 A. 포인터 표기 읽는 법

| 표기 | 읽는 법 | 뜻 |
|---|---|---|
| `int *p;` | `*p`가 `int`이다 | `p`는 `int`를 가리키는 포인터 |
| `&x` | `x`의 주소 | 주소를 얻는다 |
| `*p` | `p`가 가리키는 값 | 값을 꺼낸다 |
| `*p = 5` | `p`가 가리키는 곳에 5를 넣는다 | 원본을 바꾼다 |
| `p = &x` | `p`가 `x`를 가리키게 한다 | 포인터를 옮긴다 |
| `p + 1` | 다음 원소의 주소 | 자료형 크기만큼 이동 |
| `(*p)++` | 가리키는 **값**을 1 증가 | 괄호 필수 |
| `*p++` | 값을 쓴 뒤 **포인터**를 1 이동 | `*(p++)` |
| `p[i]` | `*(p + i)` | 포인터에도 첨자를 쓸 수 있다 |
| `char *s` | `s`는 문자를 가리키는 포인터 | 문자열의 첫 글자 주소 |
