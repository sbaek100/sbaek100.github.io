## 제1절. 요구사항

**작은 도서관의 장서를 관리하는 프로그램**을 만듭니다.

### 1.1 기능

| 번호 | 기능 | 설명 |
|---|---|---|
| 1 | 목록 | 등록된 책을 모두 보여 준다 |
| 2 | 등록 | 제목·지은이·출판년을 받아 새 책을 넣는다. 번호는 자동 부여 |
| 3 | 검색 | 제목이나 지은이에 검색어가 들어 있는 책을 찾는다 |
| 4 | 대출 | 번호로 찾아 대출 중으로 바꾼다 |
| 5 | 반납 | 번호로 찾아 서가로 되돌린다 |
| 6 | 삭제 | 번호로 찾아 지운다 |
| 7 | 정렬 | 제목의 사전 순으로 정렬한다 |
| 8 | 저장 | CSV 파일로 저장한다 |
| 0 | 종료 | 저장하고 끝낸다 |

### 1.2 제약

| 항목 | 조건 |
|---|---|
| 자료 보관 | `books.csv` 파일. 시작할 때 읽고 끝낼 때 쓴다 |
| 책의 수 | **미리 정하지 않는다.** 필요한 만큼 늘어난다 |
| 제목 | 1~59자, 쉼표 불가 |
| 지은이 | 1~39자, 쉼표 불가 |
| 출판년 | 1450~2100 |
| 번호 | 1 이상, 중복 불가, 자동 부여 |
| 잘못된 입력 | **프로그램이 죽지 않고** 안내한 뒤 계속 진행 |
| 깨진 파일 줄 | 건너뛰고 `stderr`에 알린다 |
| 메모리 | 종료할 때 누수가 없어야 한다 |
| 컴파일 | `-Wall -Wextra` **경고 0개** |

> **"프로그램이 죽지 않는다"** 가 이 과제에서 가장 중요한 요구사항입니다. 10강에서 배운 대로, 바깥에서 들어오는 값은 무엇이든 될 수 있습니다.

## 제2절. 설계 — 자료부터

### 2.1 순서

프로그램을 만들 때는 **기능이 아니라 자료부터** 정합니다.

| 순서 | 질문 | 이 과제의 답 |
|---|---|---|
| 1 | 무엇을 다루는가 | **책 한 권** |
| 2 | 한 권에 무엇이 담기는가 | 번호·제목·지은이·출판년·대출 여부 |
| 3 | 여러 권을 어떻게 담는가 | **늘어나는 배열** |
| 4 | 어떻게 오래 보관하는가 | **CSV 파일** |
| 5 | 무엇을 할 수 있는가 | 넣기·찾기·지우기·정렬·읽기·쓰기 |

**자료 구조가 정해지면 함수는 거의 자동으로 결정됩니다.** 반대로 기능부터 만들면 자료 구조가 뒤엉킵니다.

### 2.2 왜 배열을 늘리는가

세 가지 방법을 견주어 보았습니다.

| 방법 | 장점 | 단점 |
|---|---|---|
| 고정 배열 `struct book v[100]` | 가장 간단 | **100권을 넘으면 못 담는다** |
| **늘어나는 배열**(`realloc`) | 개수 제한 없음, 첨자 접근 가능, 정렬 쉬움 | 늘릴 때 통째로 옮긴다 |
| 연결 리스트 | 넣고 빼기가 빠르다 | **첨자 접근 불가**, `qsort` 못 씀, 포인터 관리 부담 |

요구사항에 **정렬과 목록 출력**이 있으므로 **늘어나는 배열**이 알맞습니다. 8강에서 배운 연결 리스트가 언제나 정답은 아니라는 점을 확인해 두십시오.

### 2.3 왜 CSV인가

| 형식 | 장점 | 단점 |
|---|---|---|
| **CSV**(쉼표로 구분한 글자) | 사람이 읽을 수 있고 엑셀로 열린다 | 쉼표를 값에 못 쓴다 |
| 이진 파일(`fwrite`) | 빠르고 크기가 작다 | 사람이 못 읽고, 컴퓨터가 바뀌면 깨질 수 있다 |

배우는 단계에서는 **눈으로 확인할 수 있는 것**이 훨씬 유용합니다. 그래서 CSV를 쓰고, 대신 **제목과 지은이에 쉼표를 금지**합니다(9강 9절과 같은 방식).

## 제3절. 파일 나누기

### 3.1 책임에 따라 나눕니다

| 파일 | 책임 | 아는 것 / 모르는 것 |
|---|---|---|
| `book.h` / `book.c` | **책 한 권** — 출력, CSV 변환, 값 검사 | 여러 권은 모른다 |
| `store.h` / `store.c` | **여러 권** — 넣기·찾기·지우기·정렬·파일 | 화면과 메뉴는 모른다 |
| `input.h` / `input.c` | **안전한 입력** — 한 줄 읽기, 정수 변환 | 책이 무엇인지 모른다 |
| `main.c` | **메뉴와 흐름** — 사용자와 대화 | 세부 구현은 모른다 |
| `Makefile` | 빌드 | — |

### 3.2 이 나눔의 좋은 점

| 점 | 설명 |
|---|---|
| 각 파일이 짧다 | 100~200줄 안팎이라 한눈에 들어온다 |
| **의존이 한 방향** | `main` → `store` → `book` → `input` |
| 다시 쓸 수 있다 | `input`은 다른 프로그램에서 그대로 쓸 수 있다 |
| 시험하기 쉽다 | `store`만 따로 시험하는 프로그램을 만들 수 있다 |

> **의존이 한 방향인지 반드시 확인하십시오.** `book.c`가 `store.h`를 포함하면 순환이 생깁니다. 순환이 생기면 어느 쪽도 따로 시험할 수 없게 됩니다.

## 제4절. 자료형과 헤더

### 4.1 `book.h`

```c
#ifndef BOOK_H
#define BOOK_H

#include <stddef.h>

#define TITLE_LEN   60      /* '\0' 포함 */
#define AUTHOR_LEN  40

struct book {
    int  id;                        /* 1 이상. 중복되지 않는다 */
    char title[TITLE_LEN];
    char author[AUTHOR_LEN];
    int  year;                      /* 1450 ~ 2100 */
    int  borrowed;                  /* 0 = 서가에 있음, 1 = 대출 중 */
};

/* book_print_header: 목록의 머리글을 출력한다 */
void book_print_header(void);

/* book_print: 책 한 권을 한 줄로 출력한다 */
void book_print(const struct book *b);

/* book_to_csv: 책을 CSV 한 줄로 만든다.
   line 에 담지 못하면 0 을, 성공하면 1 을 돌려준다. */
int book_to_csv(const struct book *b, char *line, size_t linesize);

/* book_from_csv: CSV 한 줄을 읽어 책으로 만든다.
   형식이 맞지 않으면 0 을, 성공하면 1 을 돌려준다. line 은 수정된다. */
int book_from_csv(char *line, struct book *b);

/* book_valid_text: 제목·지은이로 쓸 수 있는 문자열인지 검사한다.
   비어 있거나 쉼표를 포함하면 0 을 돌려준다. */
int book_valid_text(const char *s);

#endif   /* BOOK_H */
```

**설계 판단 세 가지를 짚어 둡니다.**

| 판단 | 이유 |
|---|---|
| 문자열을 **포인터가 아니라 배열**로 | 구조체 하나가 자기 자료를 통째로 갖는다. 대입·정렬·저장이 단순해진다(8강 3절) |
| 크기를 **`#define` 상수**로 | 여러 곳에서 같은 값을 쓴다. 바꿀 때 한 곳만 고친다 |
| `book_from_csv`가 `line`을 **수정** | 항목을 자를 때 쉼표 자리에 `'\0'`을 넣는다. **주석에 밝혀 두었다** |

마지막 항목이 중요합니다. **인자를 고치는 함수는 반드시 그 사실을 헤더에 적어야** 합니다(11강 6.2절).

### 4.2 `book.c` — CSV 변환

**만들기**는 `snprintf` 한 번이면 됩니다.

```c
int book_to_csv(const struct book *b, char *line, size_t linesize)
{
    int n;

    n = snprintf(line, linesize, "%d,%s,%s,%d,%d",
                 b->id, b->title, b->author, b->year, b->borrowed);
    return n > 0 && (size_t) n < linesize;   /* 잘렸으면 실패로 본다 */
}
```

`snprintf`의 반환값은 **잘리지 않았다면 썼을 글자 수**입니다. 그래서 그것이 `linesize`보다 크거나 같으면 잘린 것입니다. 10강 3.3절에서 **판단에 쓰이는 값은 자르지 말고 거부**하기로 했으므로, 여기서는 **실패로 처리**합니다.

**읽기**는 항목을 하나씩 잘라 냅니다.

```c
/* next_field: line 에서 다음 항목을 잘라 내고 그 시작을 돌려준다.
   더 없으면 NULL. 구분자 자리에는 '\0' 을 넣는다. */
static char *next_field(char **pos)
{
    char *start = *pos;
    char *comma;

    if (start == NULL)
        return NULL;
    comma = strchr(start, ',');
    if (comma != NULL) {
        *comma = '\0';
        *pos = comma + 1;
    } else {
        *pos = NULL;                    /* 마지막 항목이었다 */
    }
    return start;
}
```

- `static`이므로 **밖에서 보이지 않습니다**(5강 7.1절). 내부 도구입니다.
- 인자가 **포인터의 포인터(`char **`)** 입니다. 함수가 호출한 쪽의 포인터를 옮겨 주어야 하기 때문입니다(7강 2절).
- `strtok`을 쓰지 않은 이유는, `strtok`이 **연속된 쉼표를 하나로 취급**해 빈 항목을 건너뛰기 때문입니다. CSV에서는 빈 항목도 하나의 항목입니다.

```c
int book_from_csv(char *line, struct book *b)
{
    char *pos = line;
    char *f_id, *f_title, *f_author, *f_year, *f_borrowed;
    long v;

    f_id       = next_field(&pos);
    f_title    = next_field(&pos);
    f_author   = next_field(&pos);
    f_year     = next_field(&pos);
    f_borrowed = next_field(&pos);

    if (f_id == NULL || f_title == NULL || f_author == NULL
        || f_year == NULL || f_borrowed == NULL)
        return 0;                       /* 항목 수가 모자란다 */

    if (!parse_int(f_id, 1, 1000000L, &v))
        return 0;
    b->id = (int) v;

    if (!book_valid_text(f_title) || !book_valid_text(f_author))
        return 0;
    snprintf(b->title, sizeof b->title, "%s", f_title);
    snprintf(b->author, sizeof b->author, "%s", f_author);

    if (!parse_int(f_year, 1450, 2100, &v))
        return 0;
    b->year = (int) v;

    if (!parse_int(f_borrowed, 0, 1, &v))
        return 0;
    b->borrowed = (int) v;

    return 1;
}
```

**모든 항목을 검증합니다.** 파일은 사용자가 편집기로 고칠 수 있으므로 **바깥 입력**입니다(10강 1.3절). `atoi`가 아니라 `parse_int`를 쓴 것도 같은 이유입니다.

## 제5절. 보관함 — 동적 배열

### 5.1 `store.h`

```c
struct store {
    struct book *v;         /* 책 배열. malloc 으로 빌린다 */
    size_t n;               /* 지금 들어 있는 개수 */
    size_t cap;             /* 담을 수 있는 개수 */
};
```

**`n`과 `cap`을 구분하는 것**이 핵심입니다.

| 이름 | 뜻 | 예 |
|---|---|---|
| `n` | 실제로 들어 있는 개수 | 5권 |
| `cap` | 담을 수 있는 개수 | 8칸 |

칸이 다 차면(`n == cap`) 늘립니다.

### 5.2 늘리기

```c
/* grow: 칸을 두 배로 늘린다. 성공하면 1 */
static int grow(struct store *s)
{
    size_t newcap;
    struct book *p;

    newcap = (s->cap == 0) ? FIRST_CAP : s->cap * 2;

    if (newcap > SIZE_MAX / sizeof(struct book))    /* 곱셈이 넘치는가 */
        return 0;

    p = (struct book *) realloc(s->v, newcap * sizeof(struct book));
    if (p == NULL)
        return 0;           /* 실패해도 s->v 는 그대로 살아 있다 */

    s->v = p;
    s->cap = newcap;
    return 1;
}
```

이 짧은 함수에 **세 가지 중요한 판단**이 들어 있습니다.

| 판단 | 이유 |
|---|---|
| **두 배씩** 늘린다 | 한 칸씩 늘리면 옮기는 일이 너무 잦다. 두 배면 전체 비용이 훨씬 작다 |
| **곱셈 넘침을 검사**한다 | 10강 5.2절. 넘치면 아주 작은 크기를 빌려 넘침 사고가 난다 |
| **새 변수 `p`에 받는다** | `s->v = realloc(s->v, ...)`라고 쓰면, 실패했을 때 **기존 자료를 통째로 잃어버린다** |

> **`realloc`의 결과를 원래 포인터에 바로 대입하지 마십시오.**
> 실패하면 `NULL`이 대입되어, 아직 살아 있는 메모리를 가리킬 방법이 사라집니다. **누수이자 자료 손실**입니다. 매우 흔한 실수입니다.
{: .prompt-danger }

### 5.3 넣기와 지우기

```c
int store_add(struct store *s, const struct book *b)
{
    if (s->n == s->cap && !grow(s))
        return 0;
    s->v[s->n] = *b;        /* 구조체는 통째로 대입된다 */
    s->n++;
    return 1;
}
```

`s->v[s->n] = *b;` 한 줄로 구조체 전체가 복사됩니다(8강 2.3절). 항목이 늘어도 이 코드는 바뀌지 않습니다.

```c
int store_remove(struct store *s, int id)
{
    size_t i, j;

    for (i = 0; i < s->n; i++) {
        if (s->v[i].id == id) {
            for (j = i; j + 1 < s->n; j++)
                s->v[j] = s->v[j + 1];      /* 뒤를 한 칸씩 당긴다 */
            s->n--;
            return 1;
        }
    }
    return 0;
}
```

- `j + 1 < s->n`으로 쓴 것에 주의하십시오. `j < s->n - 1`이라고 쓰면 **`n`이 0일 때 `s->n - 1`이 거대한 값**이 됩니다. `size_t`는 부호가 없기 때문입니다(10강 5.3절).
- 지울 때 `cap`은 줄이지 않습니다. 다시 넣을 때 재사용됩니다.

### 5.4 정렬

```c
/* by_title: qsort 에 넘길 비교 함수 */
static int by_title(const void *a, const void *b)
{
    const struct book *x = (const struct book *) a;
    const struct book *y = (const struct book *) b;

    return strcmp(x->title, y->title);
}

void store_sort_by_title(struct store *s)
{
    if (s->n > 1)
        qsort(s->v, s->n, sizeof(struct book), by_title);
}
```

7강 4절에서 배운 **함수를 가리키는 포인터**의 실제 쓰임입니다. `qsort`는 무엇을 정렬하는지 모르는 채로, **비교 방법만 넘겨받아** 정렬합니다.

지은이순·연도순을 추가하려면 비교 함수만 하나 더 만들면 됩니다(실습문제 4).

### 5.5 반납

```c
void store_free(struct store *s)
{
    free(s->v);
    s->v = NULL;            /* 반납 뒤에는 NULL — 재사용 사고를 막는다 */
    s->n = 0;
    s->cap = 0;
}
```

구조체 안에 문자열을 **배열로** 넣었기 때문에(4.1절), 반납할 것은 **배열 하나뿐**입니다. 만약 `char *title`로 만들었다면 책마다 따로 `free` 해야 했을 것입니다. **설계 판단 하나가 반납 코드의 복잡도를 결정합니다.**

## 제6절. 파일 읽고 쓰기

### 6.1 읽기

```c
    fp = fopen(path, "r");
    if (fp == NULL)
        return -1;                      /* 파일이 없는 것은 오류가 아니다 */

    while (fgets(line, sizeof line, fp) != NULL) {
        lineno++;
        len = strlen(line);
        if (len > 0 && line[len - 1] == '\n')
            line[len - 1] = '\0';
        if (line[0] == '\0' || line[0] == '#')
            continue;                   /* 빈 줄과 주석은 건너뛴다 */

        if (!book_from_csv(line, &b)) {
            fprintf(stderr, "%s:%d 형식이 올바르지 않아 건너뜁니다\n", path, lineno);
            continue;
        }
        if (store_find(s, b.id) != NULL) {
            fprintf(stderr, "%s:%d 번호 %d 가 중복되어 건너뜁니다\n", path, lineno, b.id);
            continue;
        }
        if (!store_add(s, &b)) {
            fprintf(stderr, "메모리가 부족합니다\n");
            break;
        }
        count++;
    }
    fclose(fp);
```

| 처리 | 이유 |
|---|---|
| 파일이 없으면 **-1을 돌려주고 계속** | 처음 실행할 때는 파일이 없는 것이 정상이다 |
| 깨진 줄은 **건너뛰고 알린다** | 한 줄 때문에 전체를 못 읽으면 안 된다 |
| **줄 번호를 함께 출력** | 사용자가 어디를 고쳐야 하는지 알 수 있다 |
| 메시지는 **`stderr`로** | 목록 출력과 섞이지 않는다(9강 5절) |
| 번호 **중복 검사** | 요구사항의 제약이다 |

### 6.2 쓰기

```c
    fprintf(fp, "# 번호,제목,지은이,출판년,대출여부\n");
    for (i = 0; i < s->n; i++) {
        if (!book_to_csv(&s->v[i], line, sizeof line)) {
            fprintf(stderr, "번호 %d 은(는) 너무 길어 저장하지 못했습니다\n", s->v[i].id);
            continue;
        }
        fprintf(fp, "%s\n", line);
        count++;
    }

    if (fclose(fp) != 0) {              /* 닫을 때도 오류가 날 수 있다 */
        fprintf(stderr, "%s 을(를) 닫는 중 오류가 발생했습니다\n", path);
        return -1;
    }
```

> **`fclose`의 반환값을 검사한 것에 주목하십시오.**
> 출력은 버퍼에 모였다가 나중에 한꺼번에 기록됩니다(9강 3.4절). 그래서 **디스크가 가득 찼다는 사실이 `fclose` 순간에야 드러날 수 있습니다.** `fprintf`가 모두 성공했다고 저장이 끝난 것은 아닙니다.

첫 줄에 `#`로 시작하는 머리글을 넣어, **사람이 파일을 열었을 때 각 항목이 무엇인지 알 수 있게** 했습니다. 읽을 때는 `#`로 시작하는 줄을 건너뛰므로 문제가 없습니다.

## 제7절. 안전한 입력

10강에서 만든 것을 **재사용 가능한 모듈로** 옮깁니다.

### 7.1 `input.h`

```c
#ifndef INPUT_H
#define INPUT_H

#include <stddef.h>

/* read_line: stdin 에서 한 줄을 읽어 buf 에 담고 끝의 개행을 지운다.
   size 는 buf 의 전체 크기다. 줄이 너무 길어 잘렸으면 *truncated 에 1 을 넣고
   남은 글자를 모두 버린다. 성공하면 1, 파일 끝이면 0 을 돌려준다. */
int read_line(char *buf, size_t size, int *truncated);

/* parse_int: 문자열 s 를 정수로 바꾼다. 숫자 외의 글자가 있거나
   min~max 범위를 벗어나면 0 을, 성공하면 1 을 돌려주고 *out 에 값을 넣는다. */
int parse_int(const char *s, long min, long max, long *out);

/* ask_line: 안내문을 보이고 한 줄을 받는다. 빈 줄이면 0 을 돌려준다. */
int ask_line(const char *prompt, char *buf, size_t size);

/* ask_int: 안내문을 보이고 범위 안의 정수를 받는다. 성공하면 1 */
int ask_int(const char *prompt, long min, long max, long *out);

#endif   /* INPUT_H */
```

이 헤더에는 **책이라는 말이 한 번도 나오지 않습니다.** 그래서 다른 프로그램에 그대로 가져다 쓸 수 있습니다(문제 6).

### 7.2 한 줄 읽기

```c
int read_line(char *buf, size_t size, int *truncated)
{
    size_t len;

    *truncated = 0;
    if (fgets(buf, (int) size, stdin) == NULL)
        return 0;                       /* 파일 끝 또는 오류 */

    len = strlen(buf);
    if (len > 0 && buf[len - 1] == '\n') {
        buf[len - 1] = '\0';            /* 개행을 지운다 */
    } else {
        int c;                          /* 줄이 잘렸다 — 남은 글자를 버린다 */
        *truncated = 1;
        while ((c = getchar()) != '\n' && c != EOF)
            ;
    }
    return 1;
}
```

### 7.3 묻고 받기

그 위에 **묻고 받는** 함수를 얹습니다.

```c
int ask_int(const char *prompt, long min, long max, long *out)
{
    char buf[64];
    int truncated;

    printf("%s", prompt);
    fflush(stdout);
    if (!read_line(buf, sizeof buf, &truncated))
        return 0;
    if (!parse_int(buf, min, max, out)) {
        printf("  %ld ~ %ld 사이의 정수를 입력하십시오.\n", min, max);
        return 0;
    }
    return 1;
}
```

| 요소 | 이유 |
|---|---|
| `fflush(stdout)` | 안내문 끝에 개행이 없어 화면에 안 나올 수 있다(9강 3.4절) |
| **`fgets` 뒤 `parse_int`** | `scanf("%d")`는 잘못된 입력이 남아 무한 반복을 일으킨다(4강 부록 A) |
| 실패해도 **0을 돌려주고 계속** | 프로그램이 죽지 않는다는 요구사항 |

**이 계층 구조가 핵심입니다.** `read_line`은 안전하게 읽기만 하고, `parse_int`는 변환만 하고, `ask_int`는 그 둘을 묶어 대화합니다. 각각을 따로 시험할 수 있습니다.

## 제8절. 메뉴와 명령

### 8.1 명령 하나에 함수 하나

```c
static void cmd_add(struct store *s)
{
    struct book b;
    long v;

    memset(&b, 0, sizeof b);

    if (!ask_line("제목  : ", b.title, sizeof b.title)) {
        printf("제목은 비울 수 없습니다.\n");
        return;
    }
    if (!book_valid_text(b.title)) {
        printf("제목에 쉼표를 쓸 수 없습니다.\n");
        return;
    }
    if (!ask_line("지은이: ", b.author, sizeof b.author)
        || !book_valid_text(b.author)) {
        printf("지은이가 올바르지 않습니다.\n");
        return;
    }
    if (!ask_int("출판년: ", 1450, 2100, &v))
        return;
    b.year = (int) v;

    b.id = store_next_id(s);
    b.borrowed = 0;

    if (!store_add(s, &b)) {
        fprintf(stderr, "메모리가 부족하여 등록하지 못했습니다\n");
        return;
    }
    printf("번호 %d 로 등록했습니다.\n", b.id);
}
```

- `memset`으로 **구조체 전체를 0으로** 만들고 시작합니다. 어느 항목도 쓰레기 값으로 남지 않습니다.
- **잘못되면 곧바로 `return`** 합니다. 중첩된 `if`로 들여쓰기를 깊게 만들지 않는 방식입니다.
- `sizeof b.title`로 크기를 넘깁니다. 상수를 직접 적지 않습니다(10강 4.1절).

### 8.2 대출과 반납은 한 함수로

```c
static void cmd_borrow(struct store *s, int borrow)
{
    struct book *b;
    long v;

    if (!ask_int("번호  : ", 1, 1000000L, &v))
        return;
    b = store_find(s, (int) v);
    if (b == NULL) {
        printf("번호 %ld 인 책이 없습니다.\n", v);
        return;
    }
    if (b->borrowed == borrow) {
        printf("이미 %s 상태입니다.\n", borrow ? "대출 중인" : "서가에 있는");
        return;
    }
    b->borrowed = borrow;
    printf("\"%s\" 을(를) %s 했습니다.\n", b->title, borrow ? "대출" : "반납");
}
```

대출과 반납은 **한 값만 다릅니다.** 인자 하나로 구분하면 코드가 절반이 됩니다. `store_find`가 **포인터를 돌려주므로** 찾은 자리를 바로 고칠 수 있다는 점도 확인해 두십시오(7강 3절).

### 8.3 주 반복

```c
    while (running) {
        menu();
        if (!ask_int("선택: ", 0, 8, &choice))

        switch (choice) {
```

## 제9절. 빌드

11강의 뼈대를 그대로 씁니다.

```makefile
CC      = gcc
```

## 제10절. 시험 계획

**프로그램을 다 만든 뒤에 시험하는 것이 아니라, 시험할 것을 미리 정해 두고 만듭니다.**

### 10.1 정상 동작

| 번호 | 시험 | 기대 결과 |
|---|---|---|
| N1 | 책 3권 등록 후 목록 | 3권이 번호 1·2·3으로 보인다 |
| N2 | 저장 후 프로그램 재실행 | 3권을 그대로 읽어 온다 |
| N3 | 검색어 "C" | 제목·지은이에 C가 든 책만 |
| N4 | 대출 후 목록 | 상태가 "대출 중" |
| N5 | 제목순 정렬 | 사전 순으로 재배열 |

### 10.2 경계 조건

| 번호 | 시험 | 기대 결과 |
|---|---|---|
| B1 | 아무것도 없이 목록 | "등록된 책이 없습니다" |
| B2 | 1권만 두고 정렬 | 그대로. **죽지 않는다** |
| B3 | 마지막 1권 삭제 | 빈 목록이 된다 |
| B4 | 출판년 1450 / 2100 | 받아들인다 |
| B5 | 출판년 1449 / 2101 | 거부한다 |
| B6 | 제목 59자 / 60자 | 59자는 통과, 60자는 잘림 안내 |

### 문제 4. 정렬 기준 추가

지은이순·출판년순 정렬을 추가하십시오.

**정답 및 해설**

```c
static int by_author(const void *a, const void *b)
{
    const struct book *x = (const struct book *) a;
    const struct book *y = (const struct book *) b;

    return strcmp(x->author, y->author);
}

static int by_year(const void *a, const void *b)
{
    const struct book *x = (const struct book *) a;
    const struct book *y = (const struct book *) b;

    if (x->year < y->year)
        return -1;
    if (x->year > y->year)
        return 1;
    return strcmp(x->title, y->title);   /* 같은 해면 제목순 */
}
```

- **`return x->year - y->year;` 라고 쓰지 마십시오.** 두 값이 크게 다르면 뺄셈이 넘칠 수 있습니다(10강 5.1절). 비교 함수는 **부호만** 맞으면 되므로 위처럼 씁니다.
- 같은 해일 때 제목순으로 다시 정렬한 것을 **두 번째 기준**이라 합니다. 이것이 없으면 실행할 때마다 순서가 달라질 수 있습니다. `qsort`는 **안정 정렬이 아니기** 때문입니다.
- 세 정렬 함수가 **거의 같다**는 점에 주목하십시오. 달라지는 것은 비교 방법뿐이며, 그래서 함수 포인터로 넘기는 것입니다.

### 문제 10. 점검 목록으로 자기 감사

10강 제10절의 점검 목록으로 자신의 프로그램을 검사하고, 발견한 문제를 고치십시오.

**정답 및 해설**

이 과제에서 자주 발견되는 것들입니다.

| 자주 나오는 문제 | 고침 |
|---|---|
| `fclose` 반환값 미검사 | 저장 함수에서 검사(6.2절) |
| 파일 끝에서 무한 반복 | `read_line`의 0 반환을 구분해 종료 |
| `store_free` 호출 누락 경로 | 모든 종료 경로에서 호출 |
| 배열 크기를 숫자로 직접 적음 | `sizeof`로 |
| 오류를 `printf`로 출력 | `fprintf(stderr, ...)` |
| `realloc` 결과를 원래 포인터에 대입 | 임시 포인터로 받기 |
