## 제1절. 문장과 블록

### 1.1 식이 문장이 되는 순간

`x = 0`, `i++`, `printf(...)` 는 모두 **식(expression)** 입니다. 여기에 **세미콜론을 붙이면 문장(statement)** 이 됩니다.

```c
x = 0;
i++;
printf("hello\n");
```

C에서 세미콜론은 문장과 문장을 **구분하는 기호가 아니라 문장을 끝내는 종결자**입니다. 그래서 마지막 문장 뒤에도 반드시 붙여야 합니다.

### 1.2 블록

중괄호 `{ }`로 선언과 문장들을 묶은 것을 **복합문(compound statement)** 또는 **블록(block)** 이라 합니다. 문법적으로 **블록 하나는 문장 하나와 똑같이 취급**됩니다.

이 규칙이 중요한 이유는, `if`·`else`·`while`·`for` 뒤에는 **문장 하나만** 올 수 있기 때문입니다. 여러 문장을 넣고 싶으면 중괄호로 묶어 "문장 하나"로 만들어야 합니다.

```c
if (n > 0)
    printf("양수\n");          /* 문장 하나 — 중괄호 불필요 */
```

```c
if (n > 0) {                   /* 여러 문장 — 중괄호로 묶어야 한다 */
    printf("양수\n");
    count++;
}
```

> **블록을 닫는 `}` 뒤에는 세미콜론을 붙이지 않습니다.**
> 함수 정의의 끝, `if`·`while`의 끝 모두 마찬가지입니다. 예외는 6강에서 배울 구조체 선언 정도입니다.
{: .prompt-warning }

## 제2절. `if-else`와 매달린 `else`

### 2.1 기본 형태

```c
if (식)
    문장1
else
    문장2
```

`else` 부분은 생략할 수 있습니다. 동작은 다음과 같습니다.

1. 괄호 안의 식을 계산한다.
2. 값이 **0이 아니면**(참) `문장1`을 실행한다.
3. 값이 **0이면**(거짓) `else`가 있을 경우 `문장2`를 실행한다.

3강에서 확인한 대로 **"참"은 0이 아닌 모든 값**입니다. 그래서 다음 두 줄은 같은 뜻입니다.

```c
if (n != 0)
```

```c
if (n)
```

짧게 쓸 수 있지만 언제나 좋은 것은 아닙니다. `if (n)`은 "n이 0이 아니면"인지 "n이 참이면"인지 문맥에 따라 읽는 사람이 다르게 받아들일 수 있습니다. **뜻이 분명해지는 쪽**을 고르십시오.

### 2.2 매달린 `else` 문제

`else`는 생략할 수 있기 때문에, `if`가 중첩되면 **어느 `if`에 붙는지** 헷갈리는 상황이 생깁니다. `dangling.c`로 확인합니다.

```c
#include <stdio.h>

/* 매달린 else: 들여쓰기와 실제 동작이 다를 수 있다 */
void wrong(int n, int a, int b)
{
    int z = -999;

    if (n > 0)
        if (a > b)
            z = a;
    else                    /* 눈에는 바깥 if 의 else 처럼 보이지만... */
        z = b;              /* 실제로는 안쪽 if 에 붙는다 */

    printf("wrong(n=%d, a=%d, b=%d) -> z = %d\n", n, a, b, z);
}

void right(int n, int a, int b)
{
    int z = -999;

    if (n > 0) {
        if (a > b)
            z = a;
    } else {
        z = b;
    }

    printf("right(n=%d, a=%d, b=%d) -> z = %d\n", n, a, b, z);
}

int main(void)
{
    wrong(-1, 3, 5);
    right(-1, 3, 5);
    return 0;
}
```

```text
wrong(n=-1, a=3, b=5) -> z = -999
right(n=-1, a=3, b=5) -> z = 5
```

`n`이 −1이므로 작성자의 의도는 "`else`로 내려가 `z = b`"였습니다. 그런데 `wrong`에서는 `z`가 초기값 그대로 `-999`입니다.

**규칙은 하나입니다. `else`는 짝이 없는 가장 가까운 `if`에 붙습니다.** 위 코드에서 `else`는 들여쓰기와 무관하게 안쪽 `if (a > b)`에 붙었고, `n > 0`이 거짓이므로 안쪽 `if` 자체가 실행되지 않아 `z`는 그대로 남은 것입니다.

**컴파일러는 이미 경고하고 있습니다.**

```text
warning: suggest explicit braces to avoid ambiguous 'else' [-Wdangling-else]
```

1강부터 `-Wall`을 켜라고 강조한 이유가 여기서 또 확인됩니다.

> **해결책: `if`를 중첩할 때는 반드시 중괄호를 쓰십시오.**
> 들여쓰기는 사람에게만 보이고 컴파일러는 보지 않습니다. 중괄호만이 의도를 컴파일러에게 전달합니다.
{: .prompt-danger }

## 제3절. `else if`와 이진 탐색

### 3.1 여러 갈래 판단

```c
if (조건1)
    문장1
else if (조건2)
    문장2
else if (조건3)
    문장3
else
    문장4
```

조건을 **위에서부터 차례로** 검사하다가 처음으로 참이 되는 것 하나만 실행하고 전체가 끝납니다. 어느 것도 참이 아니면 마지막 `else`가 실행되며, 이 `else`는 생략할 수 있습니다.

마지막 `else`는 **"그 밖의 모든 경우"** 를 맡습니다. 일어나서는 안 되는 상황을 잡아내는 자리로 쓰면 좋습니다.

```c
else
    printf("오류: 예상하지 못한 값 %d\n", code);
```

### 3.2 이진 탐색

세 갈래 판단(작다 / 크다 / 같다)이 필요한 대표적인 예가 **이진 탐색**입니다. 정렬된 배열에서 값을 찾을 때, 가운데 원소와 비교하여 찾는 범위를 절반씩 줄여 나갑니다.

`binsearch.c`입니다.

```c
#include <stdio.h>

/* binsearch: 오름차순 배열 v[0] <= v[1] <= ... <= v[n-1] 에서 x 를 찾는다 */
int binsearch(int x, const int v[], int n)
{
    int low, high, mid;

    low = 0;
    high = n - 1;
    while (low <= high) {
        mid = (low + high) / 2;
        if (x < v[mid])
            high = mid - 1;
        else if (x > v[mid])
            low = mid + 1;
        else                    /* 찾았다 */
            return mid;
    }
    return -1;                  /* 없다 */
}

int main(void)
{
    int v[] = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
    int n = (int) (sizeof v / sizeof v[0]);
    int i;
    int keys[] = {23, 2, 91, 40};

    printf("배열 원소 %d개\n", n);
    for (i = 0; i < 4; ++i)
        printf("binsearch(%2d) = %2d\n", keys[i], binsearch(keys[i], v, n));
    return 0;
}
```

```text
배열 원소 10개
binsearch(23) =  5
binsearch( 2) =  0
binsearch(91) =  9
binsearch(40) = -1
```

이 함수에서 눈여겨볼 점이 네 가지입니다.

| 항목 | 설명 |
|---|---|
| 전제 조건 | 배열이 **정렬되어 있어야** 한다. 주석으로 명시해 두었다 |
| 세 갈래 | 작다 / 크다 / 같다 — `else if`가 가장 자연스러운 구조 |
| 종료 조건 | `low > high`가 되면 범위가 비었으므로 없는 것이다 |
| 실패 표시 | 유효한 첨자가 아닌 **`-1`** 을 돌려준다(2강 `any`와 같은 관례) |

**`sizeof v / sizeof v[0]`** 은 배열의 원소 개수를 구하는 관용구입니다. 전체 바이트 수를 원소 하나의 바이트 수로 나눈 것이며, 배열 크기를 코드에 두 번 적지 않아도 되므로 실수가 줄어듭니다.

> 이 관용구는 **배열 이름이 살아 있는 곳에서만** 통합니다. 배열을 함수에 넘기면 크기 정보가 사라지므로 함수 안에서는 쓸 수 없습니다. 그래서 `binsearch`가 `n`을 따로 받는 것입니다. 이유는 6강 포인터에서 밝혀집니다.
{: .prompt-warning }

## 제4절. `switch`

### 4.1 정수 값이 무엇과 같은지 검사할 때

`switch`는 하나의 정수 식이 **여러 상수 중 어느 것과 같은지** 검사하여 갈라지는 문장입니다.

```c
switch (식) {
case 상수1:
    문장들
    break;
case 상수2:
    문장들
    break;
default:
    문장들
    break;
}
```

- `case` 뒤에는 **상수**만 올 수 있습니다. 변수나 범위(`case 1..5`)는 쓸 수 없습니다.
- 모든 `case`의 값은 서로 달라야 합니다.
- `default`는 어느 것과도 맞지 않을 때 실행되며, 생략할 수 있습니다. 없고 맞는 것도 없으면 아무 일도 일어나지 않습니다.

### 4.2 2강의 문자 세기를 `switch`로

`switch_count.c`입니다. 2강 7.2절의 `ndigit.c`와 하는 일이 완전히 같습니다.

```c
#include <stdio.h>

/* 2강의 ndigit.c 를 switch 로 다시 쓴다 */
int main(void)
{
    int c, i, nwhite, nother;
    int ndigit[10];

    nwhite = nother = 0;
    for (i = 0; i < 10; i++)
        ndigit[i] = 0;

    while ((c = getchar()) != EOF) {
        switch (c) {
        case '0': case '1': case '2': case '3': case '4':
        case '5': case '6': case '7': case '8': case '9':
            ndigit[c - '0']++;
            break;
        case ' ':
        case '\n':
        case '\t':
            nwhite++;
            break;
        default:
            nother++;
            break;
        }
    }

    printf("digits =");
    for (i = 0; i < 10; i++)
        printf(" %d", ndigit[i]);
    printf(", white space = %d, other = %d\n", nwhite, nother);
    return 0;
}
```

```powershell
.\switch_count.exe < digits.txt
```

```text
digits = 4 2 3 2 2 2 2 1 1 0, white space = 8, other = 21
```

2강의 결과와 정확히 같습니다. `case '0':` 부터 `case '9':` 까지를 **줄줄이 붙여 놓은 것**에 주목하십시오. 이것이 다음에 설명할 폴스루를 **의도적으로 활용한** 형태입니다.

### 4.3 폴스루 — `switch`의 가장 위험한 성질

`case`는 **분기점이 아니라 이름표**입니다. 값이 맞는 `case`에서 실행이 **시작될 뿐**, 그 아래 `case`에서 자동으로 멈추지 않습니다. 명시적으로 `break`를 쓰지 않으면 **다음 `case`로 그대로 흘러 내려갑니다.** 이를 **폴스루(fall-through)** 라 합니다.

`fallthrough.c`로 확인합니다.

```c
#include <stdio.h>

/* break 를 빠뜨리면 아래 case 로 흘러 내려간다 */
void grade_wrong(int score)
{
    printf("점수 %3d -> ", score);
    switch (score / 10) {
    case 10:
    case 9:
        printf("A ");
    case 8:
        printf("B ");
    case 7:
        printf("C ");
    default:
        printf("F ");
    }
    printf("\n");
}
```

```text
[break 없는 판]
점수  95 -> A B C F 
점수  85 -> B C F 
[올바른 판]
점수  95 -> A
점수  85 -> B
점수  60 -> F
```

95점이 `A B C F`로 나왔습니다. `case 9:`에서 시작해 **아래로 끝까지 흘러내린** 결과입니다.

여기서도 컴파일러가 미리 경고합니다.

```text
warning: this statement may fall through [-Wimplicit-fallthrough=]
```

> **`switch` 작성 규칙 세 가지**
> 1. 각 `case`의 끝에는 **반드시 `break`**(또는 `return`)를 쓴다.
> 2. 마지막 `case`나 `default`에도 **논리적으로 불필요해 보여도 `break`를 쓴다.** 나중에 `case`를 하나 더 추가할 때 사고를 막아 준다.
> 3. 폴스루를 **의도적으로** 쓸 때는 4.2절처럼 `case`를 줄줄이 붙이거나, 반드시 주석으로 의도를 밝힌다.
{: .prompt-danger }

### 4.4 `switch`와 `else if` 중 무엇을 쓸 것인가

| 상황 | 알맞은 것 |
|---|---|
| 정수·문자가 **특정 값들과 같은지** 비교 | `switch` |
| 범위 비교(`score >= 90`), 실수 비교, 복합 조건 | `else if` |
| 갈래가 많고 값이 흩어져 있음 | `switch`(가독성이 좋고 컴파일러가 최적화하기도 쉽다) |

성적 판정처럼 **범위**를 다룰 때 `switch (score / 10)` 같은 기법을 쓰기도 하지만, 억지로 맞추기보다 `else if`가 자연스러우면 그쪽을 쓰십시오.

## 제5절. `while`·`for`와 중첩 반복

### 5.1 둘은 서로 바꾸어 쓸 수 있습니다

```c
for (식1; 식2; 식3)
    문장
```

는 원칙적으로 다음과 같습니다.

```c
식1;
while (식2) {
    문장
    식3;
}
```

(단 `continue`가 있을 때는 동작이 달라집니다. 제7절에서 설명합니다.)

**세 부분은 각각 생략할 수 있습니다.** 다만 세미콜론은 남겨야 합니다.

```c
for (;;) {      /* 조건이 없으므로 언제나 참 — 무한 반복 */
    ...
}
```

무한 반복은 `break`나 `return`으로 빠져나옵니다.

### 5.2 어느 쪽을 쓸 것인가

초기화와 증감이 **단순하고 반복 제어와 직결**되면 `for`가 낫습니다. 세 요소가 한자리에 모여 있어 반복의 구조가 한눈에 보이기 때문입니다.

```c
for (i = 0; i < n; i++)
```

반대로 초기화가 없거나 증감이 반복 제어와 무관하면 `while`이 자연스럽습니다.

```c
while ((c = getchar()) == ' ' || c == '\n' || c == '\t')
    ;   /* 공백류를 건너뛴다 */
```

> `for`의 초기화·증감 자리에 **반복 제어와 무관한 계산**을 밀어 넣지 마십시오. 문법적으로는 가능하지만 읽기 어려워집니다.
{: .prompt-tip }

### 5.3 앞뒤 공백과 부호를 처리하는 `atoi`

3강에서 만든 `my_atoi`는 숫자만 처리했습니다. 실제 입력에는 앞쪽 공백과 부호가 섞여 있으므로, 이를 **세 단계로 나누어** 처리합니다.

> 공백을 건너뛴다 → 부호를 읽는다 → 숫자를 읽어 변환한다

`atoi2.c`입니다.

```c
#include <stdio.h>
#include <ctype.h>

/* atoi2: 앞쪽 공백과 부호를 처리하는 문자열 -> 정수 변환 */
int atoi2(const char s[])
{
    int i, n, sign;

    for (i = 0; isspace((unsigned char) s[i]); i++)   /* 공백 건너뛰기 */
        ;
    sign = (s[i] == '-') ? -1 : 1;
    if (s[i] == '+' || s[i] == '-')                   /* 부호 건너뛰기 */
        i++;
    for (n = 0; isdigit((unsigned char) s[i]); i++)
        n = 10 * n + (s[i] - '0');
    return sign * n;
}

int main(void)
{
    printf("atoi2(\"  -1234\")  = %d\n", atoi2("  -1234"));
    printf("atoi2(\"+56abc\")   = %d\n", atoi2("+56abc"));
    printf("atoi2(\"\\t 7\")     = %d\n", atoi2("\t 7"));
    printf("atoi2(\"abc\")      = %d\n", atoi2("abc"));
    return 0;
}
```

```text
atoi2("  -1234")  = -1234
atoi2("+56abc")   = 56
atoi2("\t 7")     = 7
atoi2("abc")      = 0
```

**각 단계가 자기 몫만 처리하고 다음 단계에 깨끗한 상태를 넘겨준다**는 점이 이 함수의 핵심입니다. 숫자가 아닌 글자를 만나면 그 자리에서 변환이 끝납니다.

3강 7.3절에서 예고한 대로 `<ctype.h>`의 `isspace`·`isdigit`을 썼습니다. 인자를 `(unsigned char)`로 캐스트한 이유는, 이 함수들이 음수 값을 받으면 안 되기 때문입니다. `char`의 부호가 환경에 따라 다르다는 3강 7.4절의 이야기가 여기에 적용됩니다.

### 5.4 중첩 반복 — 셸 정렬

반복 안에 반복을 넣을 수 있습니다. `for`의 장점이 가장 잘 드러나는 예가 **셸 정렬(shell sort)** 입니다. 멀리 떨어진 원소끼리 먼저 비교·교환하여 큰 흐트러짐을 빠르게 없애고, 간격을 점점 좁혀 마지막에는 이웃끼리 비교하는 방식입니다.

`shellsort.c`입니다.

```c
#include <stdio.h>

/* shellsort: v[0]...v[n-1] 을 오름차순으로 정렬한다 */
void shellsort(int v[], int n)
{
    int gap, i, j, temp;

    for (gap = n / 2; gap > 0; gap /= 2)
        for (i = gap; i < n; i++)
            for (j = i - gap; j >= 0 && v[j] > v[j + gap]; j -= gap) {
                temp = v[j];
                v[j] = v[j + gap];
                v[j + gap] = temp;
            }
}
```

```text
정렬 전: 38 5 91 2 56 12 72 23 16 8
정렬 후: 2 5 8 12 16 23 38 56 72 91
```

| 반복 | 역할 |
|---|---|
| 바깥 (`gap`) | 비교할 간격을 `n/2`에서 시작해 **절반씩 줄인다** |
| 가운데 (`i`) | 간격만큼 떨어진 짝들을 훑는다 |
| 안쪽 (`j`) | 순서가 뒤바뀐 짝을 맞바꾼다 |

바깥 반복의 증감이 `gap++`가 아니라 **`gap /= 2`** 라는 점을 보십시오. `for`는 등차수열에만 쓰는 문장이 아니며, 세 자리에 **어떤 식이든** 넣을 수 있습니다.

### 5.5 콤마 연산자

`for`의 한 자리에 식을 두 개 이상 넣고 싶을 때 **콤마 연산자**를 씁니다. 왼쪽을 먼저 계산하고 오른쪽을 계산하며, 전체 식의 값은 오른쪽 값입니다.

`reverse_comma.c`는 2강 실습문제 10의 `reverse`를 콤마 연산자로 다시 쓴 것입니다.

```c
#include <stdio.h>
#include <string.h>

/* reverse: 콤마 연산자로 두 첨자를 동시에 움직인다 */
void reverse(char s[])
{
    int c, i, j;

    for (i = 0, j = (int) strlen(s) - 1; i < j; i++, j--) {
        c = s[i];
        s[i] = s[j];
        s[j] = c;
    }
}
```

```text
gnimmargorp
edcba
```

`i`는 앞에서, `j`는 뒤에서 동시에 움직입니다. 2강에서는 길이를 따로 구하고 반복 밖에서 처리했지만, 콤마 연산자를 쓰면 **반복 제어가 한자리에 모입니다.**

> 함수 인자를 구분하는 쉼표(`printf("%d %d", a, b)`)나 선언의 쉼표(`int i, j;`)는 **콤마 연산자가 아닙니다.** 평가 순서도 보장되지 않습니다(3강 12.3절).
{: .prompt-warning }

## 제6절. `do-while`

### 6.1 몸통을 먼저 실행하는 반복

`while`과 `for`는 조건을 **먼저** 검사하므로 몸통이 한 번도 실행되지 않을 수 있습니다. `do-while`은 반대로 **몸통을 먼저 실행하고 나중에** 검사하므로 **적어도 한 번은 실행됩니다.**

```c
do
    문장
while (식);
```

마지막 세미콜론에 주의하십시오. 그리고 몸통이 한 문장이어도 **중괄호를 쓰는 편**이 좋습니다. 그러지 않으면 `while`이 새 반복문의 시작처럼 보여 읽는 사람이 오해합니다.

### 6.2 `itoa` — 정수를 문자열로

3강의 `my_atoi`(문자열 → 정수)의 **반대 방향**입니다. 그런데 자릿수를 뽑아내면 **거꾸로 나옵니다.** 12345에서 `% 10`으로 얻는 첫 자리는 5이기 때문입니다. 그래서 거꾸로 만든 뒤 뒤집습니다.

`itoa.c`입니다.

```c
#include <stdio.h>
#include <string.h>

void reverse(char s[])
{
    int c, i, j;

    for (i = 0, j = (int) strlen(s) - 1; i < j; i++, j--) {
        c = s[i];
        s[i] = s[j];
        s[j] = c;
    }
}

/* my_itoa: 정수 n 을 문자열 s 로 바꾼다 (atoi 의 반대) */
void my_itoa(int n, char s[])
{
    int i, sign;

    if ((sign = n) < 0)      /* 부호를 기억해 둔다 */
        n = -n;              /* 양수로 만든다 */
    i = 0;
    do {                     /* 자리를 거꾸로 만들어 낸다 */
        s[i++] = n % 10 + '0';
    } while ((n /= 10) > 0);
    if (sign < 0)
        s[i++] = '-';
    s[i] = '\0';
    reverse(s);
}

int main(void)
{
    char s[32];

    my_itoa(12345, s);  printf("my_itoa(12345) = \"%s\"\n", s);
    my_itoa(-987, s);   printf("my_itoa(-987)  = \"%s\"\n", s);
    my_itoa(0, s);      printf("my_itoa(0)     = \"%s\"   <- do-while 이라 0 도 한 자리가 나온다\n", s);
    return 0;
}
```

```text
my_itoa(12345) = "12345"
my_itoa(-987)  = "-987"
my_itoa(0)     = "0"   <- do-while 이라 0 도 한 자리가 나온다
```

**왜 `do-while`이어야 하는가** — 여기가 이 절의 핵심입니다. `while`로 썼다면 `n`이 0일 때 조건이 처음부터 거짓이어서 **문자를 하나도 만들지 못하고 빈 문자열**이 됩니다. 그러나 0도 `"0"`이라는 한 글자로 표현되어야 하므로, **최소 한 번은 실행되어야** 합니다.

`(sign = n) < 0` 은 2강에서 익힌 "대입도 식이며 값을 가진다"의 응용입니다. `n`을 `sign`에 넣으면서 동시에 음수인지 검사합니다.

> **`do-while`은 자주 쓰이지 않습니다.** 대부분의 반복은 "조건을 먼저 검사"하는 편이 안전하기 때문입니다. 그러나 **"일단 한 번은 해야 하는 일"** — 메뉴 표시, 값 하나 이상 생성, 사용자에게 다시 묻기 — 에는 꼭 맞습니다.
{: .prompt-tip }

## 제7절. `break`와 `continue`

### 7.1 `break` — 즉시 빠져나오기

`break`는 **가장 안쪽의 `for`·`while`·`do`·`switch` 하나**를 즉시 끝냅니다.

문자열 끝의 공백을 잘라 내는 `trim`이 좋은 예입니다. 뒤에서부터 훑다가 **공백이 아닌 글자를 처음 만나는 순간** 멈추면 됩니다.

`trim.c`입니다.

```c
#include <stdio.h>
#include <string.h>

/* trim: 문자열 끝의 공백·탭·개행을 잘라 내고 새 길이를 돌려준다 */
int trim(char s[])
{
    int n;

    for (n = (int) strlen(s) - 1; n >= 0; n--)
        if (s[n] != ' ' && s[n] != '\t' && s[n] != '\n')
            break;
    s[n + 1] = '\0';
    return n + 1;
}
```

```text
[hello   \t\n] -> 길이 5 -> [hello]
[     ] -> 길이 0 -> []
[(빈 문자열)] -> 길이 0 -> []
```

**경계 상황을 반드시 확인하십시오.** 문자열 전체가 공백이면 `n`이 −1까지 내려가 반복이 끝나고, `s[0] = '\0'`이 되어 빈 문자열이 됩니다. 빈 문자열이 입력이어도 `n`이 처음부터 −1이므로 올바르게 동작합니다. 이렇게 **입력이 비었을 때와 전부가 대상일 때**를 점검하는 습관이 중요합니다.

### 7.2 `continue` — 이번 회차만 건너뛰기

`continue`는 반복을 끝내지 않고 **몸통의 나머지를 건너뛰어 다음 회차로** 넘어갑니다. `switch`에는 적용되지 않으며, 반복문에만 쓸 수 있습니다.

| 문장 | 하는 일 |
|---|---|
| `break` | 반복 **전체**를 끝낸다 |
| `continue` | 이번 회차만 건너뛰고 **다음 회차**로 간다 |

`while`·`do`에서는 곧바로 조건 검사로, `for`에서는 **증감식을 먼저 실행한 뒤** 조건 검사로 갑니다. 이 차이 때문에 `for`와 `while`이 완전히 같지는 않다고 5.1절에서 말한 것입니다.

`breakcont.c`입니다.

```c
#include <stdio.h>

int main(void)
{
    int a[] = {3, -1, 7, -5, 0, 12, -8, 4};
    int n = (int) (sizeof a / sizeof a[0]);
    int i, sum;

    /* continue: 음수는 건너뛴다 */
    sum = 0;
    for (i = 0; i < n; i++) {
        if (a[i] < 0)
            continue;
        sum += a[i];
    }
    printf("음수를 뺀 합 = %d\n", sum);

    /* break: 처음 만난 음수에서 멈춘다 */
    for (i = 0; i < n; i++)
        if (a[i] < 0)
            break;
    if (i < n)
        printf("처음 음수는 a[%d] = %d\n", i, a[i]);
    else
        printf("음수가 없습니다\n");
    return 0;
}
```

```text
음수를 뺀 합 = 26
처음 음수는 a[1] = -1
```

두 번째 반복에서 **`i`가 반복이 끝난 뒤에도 값을 유지한다**는 점을 이용했습니다. `i < n`이면 중간에 `break`로 빠져나온 것이고, `i == n`이면 끝까지 돌았다는 뜻입니다. `for`의 반복 변수를 이렇게 활용하는 방식은 매우 흔합니다.

> `continue`는 **"이 경우는 처리 대상이 아니다"** 를 앞에서 걸러 낼 때 유용합니다. 조건을 뒤집어 몸통 전체를 `if`로 감싸면 들여쓰기가 한 단계 깊어지는데, `continue`를 쓰면 그 깊이를 피할 수 있습니다.
{: .prompt-tip }

## 제8절. `goto` — 알되 쓰지 않는다

C에는 원하는 위치로 곧바로 건너뛰는 `goto`가 있습니다. 위치에는 **레이블**을 붙이며, 레이블은 변수 이름과 같은 형태에 콜론을 붙인 것입니다.

`goto`가 그나마 쓸모 있는 경우는 **여러 겹의 반복을 한 번에 빠져나올 때**입니다. `break`는 가장 안쪽 하나만 끝내기 때문입니다.

`twoloop.c`는 같은 일을 두 가지 방법으로 합니다.

```c
    /* 방법 1: goto */
    for (i = 0; i < n; i++)
        for (j = 0; j < m; j++)
            if (a[i] == b[j])
                goto found_label;
    printf("[goto] 공통 원소가 없습니다\n");
    goto next;

found_label:
    printf("[goto] 공통 원소 %d (a[%d], b[%d])\n", a[i], i, j);

next:
    /* 방법 2: 표시 변수 — goto 없이 같은 일을 한다 */
    found = 0;
    for (i = 0; i < n && !found; i++)
        for (j = 0; j < m && !found; j++)
            if (a[i] == b[j])
                found = 1;
    if (found)
        printf("[flag] 공통 원소 %d (a[%d], b[%d])\n", a[i - 1], i - 1, j - 1);
    else
        printf("[flag] 공통 원소가 없습니다\n");
```

```text
[goto] 공통 원소 5 (a[2], b[2])
[flag] 공통 원소 5 (a[2], b[2])
```

두 방법의 결과는 같습니다. 다만 표시 변수를 쓴 쪽은 **반복이 끝난 뒤 첨자가 한 번 더 증가**했기 때문에 `i - 1`, `j - 1`로 되돌려야 합니다. 이런 지점이 `goto` 없이 쓸 때 실수하기 쉬운 곳입니다.

> **결론: `goto`는 존재를 알아 두되 쓰지 마십시오.**
> `goto`로 짠 코드는 언제나 `goto` 없이 다시 쓸 수 있습니다. 대신 표시 변수 하나가 늘거나 검사를 한 번 더 하게 될 뿐입니다. 그 대가는 충분히 지불할 가치가 있습니다. 흐름이 위아래로 튀는 코드는 읽기도 고치기도 어렵기 때문입니다.
> 실무에서 `goto`가 살아남은 자리는 **여러 겹의 반복 탈출**과 **오류 처리 뒷정리(자원 해제)** 정도이며, 이 과정에서는 다루지 않습니다.
{: .prompt-warning }

## 제9절. 자주 나오는 실수

| 증상 | 원인 | 해결 |
|---|---|---|
| `else`가 엉뚱한 `if`에 붙음 | 중첩된 `if`에 중괄호 없음 | 중첩할 때는 반드시 중괄호 |

### 문제 1. 이진 탐색의 비교 줄이기

`binsearch`는 반복 안에서 비교를 **두 번**(`<`, `>`) 합니다. 반복 안의 비교를 **한 번**으로 줄인 판을 작성하십시오.

**정답 및 해설**

```c
#include <stdio.h>

/* binsearch2: 반복 안의 비교를 한 번으로 줄인 판 */
int binsearch2(int x, const int v[], int n)
{
    int low, high, mid;

    low = 0;
    high = n - 1;
    mid = (low + high) / 2;
    while (low <= high && x != v[mid]) {
        if (x < v[mid])
            high = mid - 1;
        else
            low = mid + 1;
        mid = (low + high) / 2;
    }
    return (low <= high) ? mid : -1;
}
```

```text
binsearch2(23) =  5
binsearch2( 2) =  0
binsearch2(91) =  9
binsearch2(40) = -1
```

- "같은가"를 **반복 조건으로 옮긴 것**이 핵심입니다. 몸통 안에는 `<` 비교 하나만 남습니다.
- 대신 `mid` 계산이 반복 앞과 몸통 끝 **두 곳**에 생겼습니다. 이처럼 최적화는 대개 **한쪽을 줄이면 다른 쪽이 늘어나는 거래**입니다.
- 어느 쪽이 실제로 빠른지는 자료의 성질에 달려 있습니다. **측정하지 않은 최적화는 추측일 뿐**이라는 점을 기억하십시오.

### 문제 2. `escape` · `unescape`

문자열 `t`를 `s`로 복사하면서 개행과 탭을 **눈에 보이는 표기**(`\n`, `\t`)로 바꾸는 `escape`와, 그 반대인 `unescape`를 작성하십시오. `switch`를 사용합니다.

**정답 및 해설**

```c
#include <stdio.h>

/* escape: t 를 s 로 복사하면서 보이지 않는 문자를 눈에 보이게 바꾼다 */
void escape(char s[], const char t[])
{
    int i, j;

    for (i = j = 0; t[i] != '\0'; i++) {
        switch (t[i]) {
        case '\n':
            s[j++] = '\\';
            s[j++] = 'n';
            break;
        case '\t':
            s[j++] = '\\';
            s[j++] = 't';
            break;
        case '\\':
            s[j++] = '\\';
            s[j++] = '\\';
            break;
        default:
            s[j++] = t[i];
            break;
        }
    }
    s[j] = '\0';
}

/* unescape: 반대 방향 — \n, \t 표기를 실제 문자로 되돌린다 */
void unescape(char s[], const char t[])
{
    int i, j;

    for (i = j = 0; t[i] != '\0'; i++) {
        if (t[i] != '\\') {
            s[j++] = t[i];
        } else {
            switch (t[i + 1]) {
            case 'n':
                s[j++] = '\n';
                i++;
                break;
            case 't':
                s[j++] = '\t';
                i++;
                break;
            case '\\':
                s[j++] = '\\';
                i++;
                break;
            default:
                s[j++] = '\\';
                break;
            }
        }
    }
    s[j] = '\0';
}
```

```text
escape   : [a\tb\nc]
unescape : [a<탭>b<개행>c]
```

- `escape`는 **한 글자가 두 글자로 늘어나므로** `s`의 크기가 넉넉해야 합니다. 최악의 경우 두 배가 필요합니다.
- `unescape`에서 `\`를 만나면 **다음 글자까지 함께 보고**(`t[i + 1]`) 두 글자를 소비해야 하므로 `i++`를 추가로 합니다. 이렇게 **한 글자 앞을 미리 보는 것**을 선행 검사(lookahead)라 하며, 문자열 해석에서 흔히 쓰입니다.
- 역슬래시 자체(`\\`)를 처리하지 않으면 왕복 변환이 깨집니다. 원본 → `escape` → `unescape` 결과가 원본과 같아야 올바른 구현입니다.

### 문제 3. `expand("a-z")`

`a-z` 같은 축약 표기를 `abc...xyz`로 펼치는 `expand(s1, s2)`를 작성하십시오. `a-b-c`, `a-z0-9`처럼 이어진 경우도 처리하고, **맨 앞이나 맨 뒤의 `-`는 그대로** 두어야 합니다.

**정답 및 해설**

```c
#include <stdio.h>

/* expand: a-z 같은 표기를 abc...xyz 로 펼친다 */
void expand(const char s1[], char s2[])
{
    int i, j;
    char c;

    i = j = 0;
    while (s1[i] != '\0') {
        if (s1[i + 1] == '-' && s1[i + 2] >= s1[i] && s1[i + 2] != '\0') {
            for (c = s1[i]; c <= s1[i + 2]; c++)
                s2[j++] = c;
            i += 3;                 /* a - z 세 글자를 소비 */
        } else {
            s2[j++] = s1[i++];      /* 앞뒤의 - 는 그대로 둔다 */
        }
    }
    s2[j] = '\0';
}
```

```text
a-f    -> abcdef
a-c0-4 -> abc01234
-a-c   -> -abc
x-     -> x-
```

- **세 글자를 한 묶음으로 보는 것**이 요령입니다. `s1[i]`, `s1[i+1]`, `s1[i+2]`가 `문자 - 문자` 꼴이면 펼치고, 아니면 한 글자만 복사합니다.
- `-a-c`에서 맨 앞 `-`는 앞에 시작 문자가 없으므로 그대로 복사되고, 이어지는 `a-c`가 펼쳐집니다.
- `x-`는 `-` 뒤에 끝 문자가 없으므로(`s1[i+2]`가 `'\0'`) 그대로 남습니다. **경계 검사를 조건에 포함**한 결과입니다.
- 3강의 "`'a'`~`'z'`는 연속된 값"이라는 성질을 다시 쓰고 있습니다.

### 문제 4. `itoa`의 최소 필드 폭

`my_itoa`에 세 번째 인자 `w`를 추가하여, 변환 결과가 `w`자보다 짧으면 **앞을 공백으로 채우도록** 하십시오.

**정답 및 해설**

```c
/* itoa_w: 최소 필드 폭 w 를 지켜 변환한다 (모자라면 앞을 공백으로) */
void itoa_w(int n, char s[], int w)
{
    int i, sign;

    if ((sign = n) < 0)
        n = -n;
    i = 0;
    do {
        s[i++] = n % 10 + '0';
    } while ((n /= 10) > 0);
    if (sign < 0)
        s[i++] = '-';
    while (i < w)                 /* 폭이 모자라면 공백으로 채운다 */
        s[i++] = ' ';
    s[i] = '\0';
    reverse(s);
}
```

```text
[      42]
[   -1234]
[1234567]  <- 폭보다 길면 그대로
```

- 문자열을 **거꾸로 만들고 있으므로**, 앞을 채울 공백은 **뒤에 붙여야** 합니다. 뒤집으면 앞으로 갑니다. 이 점만 잡으면 코드는 두 줄이면 됩니다.
- 폭보다 이미 길면 `while` 조건이 처음부터 거짓이므로 아무 일도 하지 않습니다. `printf`의 `%5d`와 같은 동작입니다(3강 5.1절).

### 문제 5. `itob` — 진법 변환

정수 `n`을 `b`진수 문자열로 바꾸는 `itob(n, s, b)`를 작성하십시오. `itob(n, s, 16)`이면 16진수가 되어야 합니다.

**정답 및 해설**

```c
/* itob: 정수 n 을 b 진수 문자열로 바꾼다 (2 <= b <= 36) */
void itob(int n, char s[], int b)
{
    static const char digits[] = "0123456789abcdefghijklmnopqrstuvwxyz";
    unsigned int u;
    int i, neg;

    neg = (n < 0);
    u = neg ? (unsigned int) (-(long long) n) : (unsigned int) n;  /* 최솟값도 안전 */

    i = 0;
    do {
        s[i++] = digits[u % (unsigned int) b];
    } while ((u /= (unsigned int) b) > 0);
    if (neg)
        s[i++] = '-';
    s[i] = '\0';
    reverse(s);
}
```

```text
itob(255, 2)  = 11111111
itob(255, 8)  = 377
itob(255, 16) = ff
itob(-255,16) = -ff
itob(0, 2)    = 0
```

- **자릿값을 문자로 바꾸는 표**(`digits`)를 두면 진법에 상관없이 같은 코드로 처리됩니다. `u % b`가 곧 표의 첨자입니다.
- 10진 변환의 `10`이 `b`로 바뀐 것 외에는 `itoa`와 구조가 같습니다.
- `unsigned`로 계산하는 이유는 문제 6에서 설명하는 최솟값 문제를 피하기 위해서입니다.
- 3강 3.2절에서 본 `0377`·`0xff`가 어떻게 만들어지는지 이 함수로 확인할 수 있습니다.

### 문제 6. `itoa`와 최솟값 문제

`my_itoa`는 `n`이 `int`의 **최솟값**일 때 올바르게 동작하지 않습니다. 왜 그런지 설명하고 고치십시오.

**정답 및 해설**

```text
INT_MIN = -2147483648
itoa_bad(INT_MIN) = -(
itoa_ok (INT_MIN) = -2147483648
```

**원인** — `if ((sign = n) < 0) n = -n;` 에서 **`-n`이 표현될 수 없습니다.** 32비트 `int`의 범위는 −2147483648 ~ +2147483647이므로, 최솟값의 부호를 뒤집은 +2147483648은 이 범위 밖입니다. 부호 있는 정수의 오버플로는 **미정의 동작**이며(3강 2.2절), 위에서는 `-(` 같은 쓰레기 문자열이 나왔습니다.

**해결** — 부호를 뒤집지 않고 **음수 상태에서 자릿수를 뽑습니다.**

```c
/* 고친 판: 부호를 바꾸지 않고 음수 쪽에서 자릿수를 뽑는다 */
void itoa_ok(int n, char s[])
{
    int i, neg;

    neg = (n < 0);
    i = 0;
    do {
        int digit = n % 10;
        if (digit < 0)
            digit = -digit;      /* 음수의 나머지는 음수가 될 수 있다 */
        s[i++] = (char) (digit + '0');
        n /= 10;
    } while (n != 0);
    if (neg)
        s[i++] = '-';
    s[i] = '\0';
    reverse(s);
}
```

- 음수를 10으로 나눈 나머지는 음수이므로(`-7 % 10 == -7`), 자릿수로 쓰기 전에 절댓값을 취합니다.
- 문제 5처럼 **더 넓은 자료형(`long long`)이나 `unsigned`로 옮겨** 계산하는 방법도 있습니다.
- 이 문제는 "가장자리 값에서만 터지는 버그"의 전형입니다. **테스트할 때 최솟값·최댓값·0을 반드시 넣어 보십시오.**

### 문제 7. 성적 통계

표준 입력에서 점수를 계속 읽어 **인원·합계·평균·최고·최저**를 출력하는 프로그램을 작성하십시오. 음수가 나오면 입력을 끝내고, 100을 넘는 값은 경고를 출력한 뒤 **집계에서 제외**합니다.

**정답 및 해설**

```c
#include <stdio.h>

#define MAXSCORE 100

/* 성적 통계: -1 이 나오면 입력을 끝낸다 */
int main(void)
{
    int score, count, sum, max, min;

    count = sum = 0;
    max = -1;
    min = MAXSCORE + 1;

    while (scanf("%d", &score) == 1) {
        if (score < 0)
            break;                       /* 입력 종료 표시 */
        if (score > MAXSCORE) {
            printf("무시: %d (0~100 범위를 벗어남)\n", score);
            continue;                    /* 잘못된 값은 건너뛴다 */
        }
        count++;
        sum += score;
        if (score > max) max = score;
        if (score < min) min = score;
    }

    if (count == 0) {
        printf("유효한 점수가 없습니다.\n");
        return 0;
    }
    printf("인원 %d명, 합계 %d, 평균 %.2f, 최고 %d, 최저 %d\n",
           count, sum, (double) sum / count, max, min);
    return 0;
}
```

```powershell
echo 88 92 105 79 -1 | .\ex7.exe
```

```text
무시: 105 (0~100 범위를 벗어남)
인원 3명, 합계 259, 평균 86.33, 최고 92, 최저 79
```

- **`break`와 `continue`가 각자의 역할로 한 번씩** 쓰였습니다. 종료는 `break`, 무시는 `continue`입니다.
- `max`와 `min`의 초기값에 주의하십시오. `max`는 가능한 값보다 **작게**, `min`은 **크게** 잡아야 첫 비교에서 반드시 갱신됩니다.
- 평균은 **`(double) sum / count`** 로 캐스트해야 합니다(3강 7.5절). 캐스트를 빠뜨리면 86.33이 아니라 86이 됩니다.
- `count == 0` 검사가 없으면 **0으로 나누게 됩니다.** 자료가 하나도 없는 경우를 항상 생각하십시오.

### 문제 8. 메뉴 프로그램

`do-while`과 `switch`로 메뉴를 반복 표시하는 프로그램을 작성하십시오. 숫자가 아닌 값이 입력되어도 **무한 반복에 빠지지 않아야** 합니다.

**정답 및 해설**

```c
#include <stdio.h>

/* 입력 버퍼에 남은 글자를 줄 끝까지 버린다 */
void clear_input(void)
{
    int ch;

    while ((ch = getchar()) != '\n' && ch != EOF)
        ;
}

int main(void)
{
    int choice;
    int count = 0;

    do {
        printf("\n1) 세기  2) 초기화  3) 종료\n");
        printf("선택: ");
        if (scanf("%d", &choice) != 1) {   /* 숫자가 아니면 */
            clear_input();                 /* 남은 글자를 버리고 */
            printf("숫자를 입력하십시오.\n");
            continue;                      /* 다시 묻는다 */
        }
        clear_input();

        switch (choice) {
        case 1:
            printf("현재 값 = %d\n", ++count);
            break;
        case 2:
            count = 0;
            printf("초기화했습니다.\n");
            break;
        case 3:
            printf("종료합니다.\n");
            break;
        default:
            printf("1 ~ 3 중에서 고르십시오.\n");
            break;
        }
    } while (choice != 3);

    return 0;
}
```

```text

선택: 현재 값 = 1

1) 세기  2) 초기화  3) 종료
선택: 현재 값 = 2

1) 세기  2) 초기화  3) 종료
선택: 초기화했습니다.

1) 세기  2) 초기화  3) 종료
선택: 현재 값 = 1

1) 세기  2) 초기화  3) 종료
선택: 숫자를 입력하십시오.

선택: 종료합니다.
```

- **메뉴는 적어도 한 번은 보여야 하므로 `do-while`이 정확히 맞습니다.**
- **이 문제의 진짜 함정은 무한 반복입니다.** `scanf("%d", ...)`는 숫자가 아닌 글자를 만나면 **그 글자를 소비하지 않고** 실패만 돌려줍니다. 그러면 다음 회차에서 같은 글자를 또 만나 영원히 반복됩니다. 그래서 `clear_input()`으로 줄 끝까지 버려야 합니다. 자세한 내용은 부록 A에 있습니다.
- `continue`가 `do-while`에서는 **조건 검사로 바로 간다**는 점에 주의하십시오. 여기서는 `choice`가 아직 갱신되지 않았으므로 이전 값으로 검사됩니다. 첫 회차라면 `choice`가 초기화되지 않아 위험할 수 있으므로, 실무에서는 `int choice = 0;`으로 초기화해 두는 편이 안전합니다.

### 문제 9. 구구단 표

중첩 반복으로 2단부터 9단까지의 구구단을 **가로로 네 단씩** 출력하십시오.

**정답 및 해설**

```c
#include <stdio.h>

int main(void)
{
    int block, dan, i;

    for (block = 0; block < 2; block++) {          /* 2~5단, 6~9단 */
        for (dan = 2 + block * 4; dan < 6 + block * 4; dan++)
            printf("   [%d단]   ", dan);
        printf("\n");

        for (i = 1; i <= 9; i++) {
            for (dan = 2 + block * 4; dan < 6 + block * 4; dan++)
                printf(" %d x %d = %2d ", dan, i, dan * i);
            printf("\n");
        }
        printf("\n");
    }
    return 0;
}
```

```text
   [2단]      [3단]      [4단]      [5단]   
 2 x 1 =  2  3 x 1 =  3  4 x 1 =  4  5 x 1 =  5 
 2 x 2 =  4  3 x 2 =  6  4 x 2 =  8  5 x 2 = 10 
 2 x 3 =  6  3 x 3 =  9  4 x 3 = 12  5 x 3 = 15 
 2 x 4 =  8  3 x 4 = 12  4 x 4 = 16  5 x 4 = 20 
 2 x 5 = 10  3 x 5 = 15  4 x 5 = 20  5 x 5 = 25 
 2 x 6 = 12  3 x 6 = 18  4 x 6 = 24  5 x 6 = 30 
 2 x 7 = 14  3 x 7 = 21  4 x 7 = 28  5 x 7 = 35 
 2 x 8 = 16  3 x 8 = 24  4 x 8 = 32  5 x 8 = 40 
 2 x 9 = 18  3 x 9 = 27  4 x 9 = 36  5 x 9 = 45 

   [6단]      [7단]      [8단]      [9단]   
 6 x 1 =  6  7 x 1 =  7  8 x 1 =  8  9 x 1 =  9 
（이하 생략）
```

- **바깥 반복이 "행", 안쪽 반복이 "열"** 입니다. 가로로 나열하려면 안쪽에서 단을 돌고, 한 줄이 끝난 뒤 `printf("\n")`을 해야 합니다.
- 초보자가 가장 많이 하는 실수는 **단을 바깥, 곱하는 수를 안쪽**에 두는 것입니다. 그러면 세로로만 나옵니다. **출력 모양을 먼저 그려 보고 반복 순서를 정하십시오.**
- `%2d`로 폭을 맞추면 자리가 어긋나지 않습니다(3강 5.1절).

### 문제 10. `goto` 없이 이중 반복 탈출

두 배열에서 **처음으로 일치하는 원소**를 찾는 프로그램을, `goto`를 쓰지 않고 세 가지 방법으로 작성해 비교하십시오.

**정답 및 해설**

**방법 1 — 표시 변수**

```c
found = 0;
for (i = 0; i < n && !found; i++)
    for (j = 0; j < m && !found; j++)
        if (a[i] == b[j])
            found = 1;
```

**방법 2 — 함수로 분리하고 `return`**

```c
/* 찾으면 1, 없으면 0. 위치는 pi, pj 로 돌려준다 */
int find_common(const int a[], int n, const int b[], int m)
{
    int i, j;

    for (i = 0; i < n; i++)
        for (j = 0; j < m; j++)
            if (a[i] == b[j])
                return a[i];    /* 함수 전체를 즉시 끝낸다 */
    return -1;
}
```

**방법 3 — 안쪽만 `break`하고 바깥에서 검사**

```c
for (i = 0; i < n; i++) {
    for (j = 0; j < m; j++)
        if (a[i] == b[j])
            break;
    if (j < m)                  /* 안쪽에서 찾고 나왔다면 */
        break;
}
```

| 방법 | 장점 | 단점 |
|---|---|---|
| 표시 변수 | `goto` 없이 구조 유지 | 조건이 길어지고, 끝난 뒤 첨자를 `i - 1`로 보정해야 함 |
| **함수로 분리** | **가장 깔끔하다. `return`은 몇 겹이든 한 번에 빠져나온다** | 함수를 하나 더 만들어야 함 |
| 안쪽 `break` + 바깥 검사 | 함수 없이 가능 | 검사가 두 번이라 실수하기 쉬움 |

세 방법 모두 같은 결과를 냅니다.

```text
[flag] 공통 원소 5 (a[2], b[2])
[func] find_common = 5
[break] 공통 원소 5 (a[2], b[2])
```

**실무에서는 방법 2를 권합니다.** 깊은 반복을 빠져나와야 한다면, 그 부분이 이미 **독립된 함수가 될 만큼 하나의 일**을 하고 있다는 신호인 경우가 많습니다.

## 정리

| 구분 | 내용 |
|---|---|
| 문장과 블록 | 세미콜론은 **종결자**, 블록은 문장 하나와 같다, `}` 뒤에는 세미콜론 없음 |
| `if-else` | `else`는 **짝 없는 가장 가까운 `if`**에 붙는다 → 중첩할 땐 중괄호 필수 |
| `else if` | 위에서부터 검사, 처음 참인 하나만 실행. 세 갈래 판단의 대표는 **이진 탐색** |
| `switch` | `case`에는 **상수만**, `break` 없으면 **폴스루**, `default`에도 `break` |
| `while` / `for` | 서로 변환 가능(단 `continue` 동작은 다름), `for(;;)`는 무한 반복 |
| 중첩 반복 | 바깥이 행, 안쪽이 열. `for`의 세 자리에는 **어떤 식이든** 올 수 있다 |
| 콤마 연산자 | 두 변수를 동시에 움직일 때. 함수 인자의 쉼표와는 다르다 |
| `do-while` | **적어도 한 번은 실행**. `itoa`·메뉴처럼 "일단 한 번"이 필요할 때 |
| `break` / `continue` | 반복 전체 종료 / 이번 회차만 건너뛰기. `break`는 **가장 안쪽 하나**만 |
| `goto` | 존재는 알되 쓰지 않는다. 대안은 표시 변수 또는 **함수 분리 + `return`** |
| 입력 | `scanf`는 **반환값을 반드시 검사**하고, 실패 시 입력 버퍼를 비운다 |

이제 프로그램의 흐름을 완전히 다룰 수 있게 되었습니다. 그런데 지금까지 만든 프로그램은 모두 **하나의 파일** 안에 들어 있습니다. 프로그램이 커지면 이 방식은 곧 한계에 부딪힙니다.

**다음 5강에서는 함수와 프로그램 구조(K&R 제4장)** 를 다룹니다. 프로그램을 **여러 파일로 나누어 따로 컴파일**하는 방법, 공개할 함수를 헤더 파일에 정리하는 방법, `static`으로 파일 안에서만 쓰이는 함수를 감추는 방법, 자기 자신을 부르는 **재귀 호출**, 그리고 전처리기를 살펴봅니다. 이번 강의에서 만든 `binsearch`·`itoa`·`trim`이 그때 **재사용 가능한 부품**으로 다시 태어납니다.

## 부록 A. `scanf` 최소 사용법

지금까지 우리는 입력을 `getchar`로 한 글자씩 읽거나 파일 리다이렉션(`< in.txt`)으로 넣었습니다. 그러나 **숫자를 입력받는 실습**을 하려면 `scanf`가 필요합니다. 정식 설명은 9강(K&R 7장)에서 하되, 여기서는 **안전하게 쓰기 위한 최소한**만 익힙니다.

### A.1 기본 형태

```c
#include <stdio.h>

int main(void)
{
    int a, b, count;

    printf("정수 두 개를 입력하십시오: ");
    count = scanf("%d %d", &a, &b);      /* 읽는 데 성공한 개수를 돌려준다 */

    if (count != 2) {
        printf("입력이 올바르지 않습니다. (읽은 항목 수 = %d)\n", count);
        return 1;
    }

    printf("%d + %d = %d\n", a, b, a + b);
    printf("%d / %d = %.2f\n", a, b, b != 0 ? (double) a / b : 0.0);
    return 0;
}
```

```text
정수 두 개를 입력하십시오: 10 3
10 + 3 = 13
10 / 3 = 3.33
```

```text
정수 두 개를 입력하십시오: abc
입력이 올바르지 않습니다. (읽은 항목 수 = 0)
```

### A.2 반드시 지킬 세 가지

**① 변수 앞에 `&`를 붙입니다.**

```c
scanf("%d", &n);     /* 올바름 */
scanf("%d", n);      /* 잘못 — 프로그램이 비정상 종료할 수 있다 */
```

`printf`는 값을 보기만 하므로 값을 넘기지만, `scanf`는 **그 변수에 값을 써 넣어야** 하므로 변수의 **주소**를 알려 주어야 합니다. `&`가 바로 "주소"를 뜻하는 연산자이며, 자세한 내용은 **6강 포인터**에서 다룹니다. 지금은 **"`scanf`에는 `&`를 붙인다"** 로 기억해도 충분합니다.

> 예외가 하나 있습니다. **문자 배열(문자열)에는 `&`를 붙이지 않습니다.** 배열 이름 자체가 이미 시작 주소이기 때문입니다(2강 9절).
{: .prompt-warning }

**② 반환값을 검사합니다.**

`scanf`는 **성공적으로 읽어 저장한 항목의 개수**를 돌려줍니다. 검사하지 않으면 값이 들어오지 않은 변수를 그대로 쓰게 되어 쓰레기 값으로 계산합니다.

```c
if (scanf("%d", &n) != 1) {
    printf("숫자를 입력하십시오.\n");
    return 1;
}
```

**③ 실패했으면 입력 버퍼를 비웁니다.**

`scanf("%d", ...)`는 숫자가 아닌 글자를 만나면 **그 글자를 읽지 않고 그대로 남겨 둔 채** 실패를 돌려줍니다. 그래서 반복문 안에서 검사만 하고 다시 시도하면 **같은 글자를 영원히 다시 만나** 무한 반복에 빠집니다.

```c
/* 입력 버퍼에 남은 글자를 줄 끝까지 버린다 */
void clear_input(void)
{
    int ch;

    while ((ch = getchar()) != '\n' && ch != EOF)
        ;
}
```

이 함수는 **2강에서 배운 `getchar`와 `EOF`만으로** 만들어졌습니다. 실습문제 8의 메뉴 프로그램이 무한 반복에 빠지지 않는 이유가 바로 이것입니다.

### A.3 서식 지정자

| 서식 | 읽는 것 | 변수 자료형 |
|---|---|---|
| `%d` | 10진 정수 | `int *` |
| `%ld` | 긴 정수 | `long *` |
| `%f` | 실수 | **`float *`** |
| `%lf` | 실수 | **`double *`** |
| `%c` | 문자 한 개(공백도 읽음) | `char *` |
| `%s` | 공백 전까지의 문자열 | `char[]` |

> **`printf`와 `scanf`의 실수 서식이 다릅니다.**
> `printf`에서는 `float`도 `double`도 `%f`로 출력하지만, `scanf`에서는 **`float`는 `%f`, `double`은 `%lf`** 로 정확히 구분해야 합니다. 잘못 쓰면 엉뚱한 값이 들어갑니다.
{: .prompt-danger }

### A.4 `%c`와 `%s`의 함정

**`%c`는 공백과 개행도 읽습니다.** 숫자를 읽은 뒤 문자를 읽으면 앞서 남은 개행이 먼저 잡힙니다. 앞에 공백을 하나 두면 공백류를 건너뛰라는 뜻이 됩니다.

```c
scanf(" %c", &ch);    /* %c 앞의 공백에 주의 */
```

**`%s`는 위험합니다.** 배열의 크기를 알지 못한 채 공백이 나올 때까지 계속 써 넣으므로, 긴 입력이 들어오면 **배열 밖을 침범합니다.** 이것이 10강에서 다룰 **버퍼 오버플로**이며, 실제 보안 사고의 단골 원인입니다.

```c
char buf[8];
scanf("%s", buf);           /* 위험: 길이 제한이 없다 */
```

```c
char buf[8];
if (fgets(buf, sizeof buf, stdin) != NULL)  /* 안전: 크기를 함께 넘긴다 */
    ...
```

> **원칙: 문자열 입력에는 `scanf("%s")` 대신 `fgets`를 쓰십시오.** 숫자 입력에만 `scanf`를 제한적으로 쓰고, 반환값을 검사하는 습관을 함께 들이면 됩니다.
{: .prompt-danger }
