## 0. 이 과정에서 우리가 만들 것

이 과정은 **프로그래밍을 한 번도 해 본 적이 없는 학습자**를 대상으로 합니다. 수학을 잘해야 하거나 컴퓨터 전공이어야 시작할 수 있는 것은 아닙니다. 필요한 것은 노트북 한 대와, 화면에 뜬 오류 메시지를 무서워하지 않는 마음가짐뿐입니다.

우리가 첫 언어로 배울 C는 1972년에 만들어진, 오래되었지만 지금도 가장 중요한 언어입니다. 여러분이 매일 쓰는 윈도우와 리눅스의 핵심, 스마트폰의 운영체제, 자동차와 세탁기 안에 들어가는 작은 컴퓨터, 그리고 파이썬 같은 최신 언어의 내부까지 — 이 모든 것이 C로 만들어져 있습니다. C를 배운다는 것은 **컴퓨터가 실제로 어떻게 동작하는지를 배우는 일**이며, 그래서 이후에 어떤 언어를 배우더라도 그 밑바탕이 되어 줍니다.

이 과정의 전체 로드맵은 다음과 같습니다. 교재는 C 언어를 만든 사람이 직접 쓴 표준 교재 **K&R**(Brian W. Kernighan · Dennis M. Ritchie, *The C Programming Language*, 2nd Edition, Prentice Hall, 1988)의 구성을 따릅니다.

## 제1절. 프로그램과 컴파일러의 이해

### 1.1 컴퓨터는 사람의 말을 알아듣지 못합니다

우리가 "화면에 Hello를 출력해 줘"라고 적어도 컴퓨터는 그 말을 이해하지 못합니다. CPU가 이해하는 것은 오직 **0과 1로 된 기계어(machine code)** 뿐입니다. 그렇다고 사람이 0과 1을 직접 적을 수는 없으니, 그 사이를 이어 줄 통역사가 필요합니다.

- **소스 코드(source code)** — 사람이 읽고 쓸 수 있는 형태로 적은 명령서입니다. 우리가 앞으로 작성할 `.c` 파일이 여기에 해당합니다.
- **컴파일러(compiler)** — 소스 코드를 기계어로 번역해 주는 프로그램입니다. 우리가 오늘 설치할 **GCC**가 바로 이 컴파일러입니다.
- **실행 파일(executable)** — 번역이 끝나 컴퓨터가 곧바로 실행할 수 있게 된 파일입니다. 윈도우에서는 `.exe` 확장자를 가집니다.

즉, 우리는 다음 순서로 일하게 됩니다.

> **소스 코드 작성 → 컴파일 → 실행 파일 생성 → 실행**

파이썬 같은 언어는 번역과 실행을 동시에 하지만(인터프리터 방식), C는 **먼저 전부 번역해 두고 나중에 실행**합니다. 그래서 훨씬 빠르게 동작하며, 대신 번역 과정에서 문법이 조금이라도 어긋나면 **컴파일 오류**로 즉시 지적을 받습니다. 이 지적은 잔소리가 아니라, 실행하기도 전에 실수를 잡아 주는 고마운 안전장치입니다.

### 1.2 컴파일은 사실 네 단계입니다

우리가 `gcc hello.c -o hello.exe` 명령 하나를 입력하면, 내부적으로는 다음 네 단계가 순서대로 일어납니다. 지금 모두 외울 필요는 없으나, **오류 메시지가 어느 단계에서 나온 것인지 구분**할 수 있으면 문제 해결이 훨씬 쉬워집니다.

| 단계 | 이름 | 하는 일 | 결과물 |
|---|---|---|---|
| 1 | 전처리(Preprocessing) | `#include`, `#define` 같은 `#` 지시문을 처리하여 코드를 합침 | 확장된 소스 |
| 2 | 컴파일(Compilation) | 문법을 검사하고 어셈블리어로 번역 | `.s` (어셈블리) |
| 3 | 어셈블(Assembly) | 어셈블리어를 기계어로 변환 | `.o` (목적 파일) |
| 4 | 링크(Linking) | 목적 파일과 라이브러리(`printf` 등)를 하나로 묶음 | `.exe` (실행 파일) |

여기서 특히 기억할 점이 있습니다. **`printf` 같은 함수는 우리가 만든 것이 아니라 이미 만들어져 라이브러리에 들어 있는 기능**이며, 4단계 링크에서 우리 코드와 합쳐집니다. 그래서 뒤에서 보게 될 `undefined reference` 오류는 "그런 부품을 창고에서 못 찾겠다"는 뜻입니다.

### 1.3 우리가 설치할 두 가지

이제 준비물을 정리합니다. 프로그래밍에는 **글을 쓰는 도구**와 **번역하는 도구**가 각각 필요합니다.

| 구분 | 설치할 것 | 역할 | 비유 |
|---|---|---|---|
| 편집기(Editor) | **Visual Studio Code** | 소스 코드를 작성하고 관리 | 원고를 쓰는 워드프로세서 |
| 컴파일러(Compiler) | **GCC** (MSYS2로 설치) | 소스 코드를 실행 파일로 번역 | 원고를 인쇄해 주는 인쇄소 |

> VS Code는 그 자체로는 C를 번역하지 못합니다. **편집기와 컴파일러는 반드시 둘 다 설치**하여야 하며, 초보자가 겪는 "코드는 썼는데 실행이 안 된다"는 문제의 대부분은 컴파일러를 설치하지 않았거나 경로(PATH)를 등록하지 않았기 때문입니다.
{: .prompt-warning }

## 제2절. Visual Studio Code 설치

본 강의는 **Windows 10/11 환경**을 기준으로 합니다. macOS와 리눅스 사용자는 이 강의 마지막의 **부록 A**를 참고하시기 바랍니다.

### 2.1 설치 파일 내려받기

1. 웹 브라우저에서 **[https://code.visualstudio.com](https://code.visualstudio.com)** 에 접속합니다.
   ![](/assets/img/posts/2026-08-24-cintro-01-vscode-gcc-hello-world-1787319673940.png)
2. 가운데의 **Download for Windows** 버튼을 누릅니다. (`VSCodeUserSetup-x64-*.exe` 파일이 내려받아집니다.)
   ![](/assets/img/posts/2026-08-24-cintro-01-vscode-gcc-hello-world-1787319687230.png)
3. 내려받은 파일을 실행합니다.

### 2.2 설치 진행

설치 마법사에서 다음과 같이 선택합니다.

| 화면 | 선택 |
|---|---|
| 사용권 계약 | **동의합니다** 선택 후 다음 |
| 설치 위치 | 기본값 그대로 다음 |
| 시작 메뉴 폴더 | 기본값 그대로 다음 |
| **추가 작업 선택** | 아래 항목을 **모두 체크** |
| 설치 준비 완료 | 설치 |

**추가 작업 선택** 화면에서 다음 네 항목에 체크하면 이후 작업이 훨씬 편해집니다.

- ☑ 바탕 화면에 바로 가기 만들기
- ☑ 파일 탐색기의 파일 상황에 맞는 메뉴에 **"Code로 열기"** 작업 추가
- ☑ 파일 탐색기의 디렉터리 상황에 맞는 메뉴에 **"Code로 열기"** 작업 추가
- ☑ **PATH에 추가**(다시 시작한 후 사용 가능)

> 마지막 **PATH에 추가** 항목은 반드시 체크합니다. 이 설정이 있어야 터미널에서 `code .` 명령으로 현재 폴더를 VS Code로 열 수 있습니다.
{: .prompt-tip }

### 2.3 명령어로 설치하기 (선택)

Windows 11에서는 다음 한 줄로도 설치할 수 있습니다. **시작 → PowerShell**을 열고 입력합니다.

```powershell
winget install --id Microsoft.VisualStudioCode -e
```

### 2.4 확장(Extension) 설치

VS Code를 실행한 뒤, 왼쪽 세로 막대에서 **네모 블록 네 개 모양 아이콘**(Extensions, 단축키 `Ctrl+Shift+X`)을 누릅니다. 검색창에 아래 이름을 차례로 입력하여 설치합니다.

| 확장 이름 | 제작자 | 필수 여부 | 역할 |
|---|---|---|---|
| **C/C++** | Microsoft | **필수** | 문법 강조, 자동 완성, 디버깅 |
| Korean Language Pack for Visual Studio Code | Microsoft | 선택 | 메뉴를 한국어로 표시 |

> **주의:** 검색 결과에 나오는 *C/C++ Extension Pack*, *Code Runner* 등은 지금 단계에서는 설치하지 않습니다. 우리는 컴파일 과정을 직접 이해하기 위해 **명령어로 먼저 빌드해 볼 것**이며, 도구가 자동으로 처리해 버리면 무엇이 일어나는지 배우기 어렵습니다.

설치가 끝나면 VS Code를 **완전히 종료**합니다. (PATH 설정을 반영하기 위해서입니다.)

## 제3절. C 컴파일러(GCC) 설치

윈도우에는 C 컴파일러가 기본으로 들어 있지 않습니다. 우리는 **MSYS2**라는 도구를 통해 **GCC**를 설치합니다. MSYS2는 윈도우에서 리눅스용 개발 도구들을 쉽게 설치·관리해 주는 꾸러미 관리자로, VS Code 공식 문서가 권장하는 방식이기도 합니다.

### 3.1 MSYS2 내려받기와 설치

1. **[https://www.msys2.org](https://www.msys2.org)** 에 접속합니다.
2. 페이지 중앙의 **msys2-x86_64-YYYYMMDD.exe** 버튼을 눌러 설치 파일을 내려받습니다.
3. 내려받은 파일을 실행합니다.
   ![](/assets/img/posts/2026-08-24-cintro-01-vscode-gcc-hello-world-1787319846261.png)
4. 설치 경로는 **반드시 기본값 `C:\msys64`를 그대로** 사용합니다. (경로를 바꾸면 뒤에서 나오는 설정을 모두 수정하여야 합니다.)
   ![](/assets/img/posts/2026-08-24-cintro-01-vscode-gcc-hello-world-1787319926918.png)

VS Code에서 처음 폴더를 열면 **"이 폴더에 있는 파일의 작성자를 신뢰합니까?"** 라는 창이 뜹니다. 자신이 만든 폴더이므로 **예, 작성자를 신뢰합니다**를 선택합니다.

### 4.2 소스 파일 작성

1. VS Code 왼쪽 탐색기 영역에서 **LAB01** 글자 옆의 **새 파일** 아이콘(문서에 + 표시)을 누릅니다.
2. 파일 이름으로 **`hello.c`** 를 입력하고 `Enter`를 누릅니다. 확장자 `.c`를 빠뜨리면 C 파일로 인식되지 않습니다.
   ![](/assets/img/posts/2026-08-24-cintro-01-vscode-gcc-hello-world-1787320731034.png)
3. 오른쪽 편집 영역에 다음 코드를 **직접 타이핑하여** 입력합니다.

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, World!\n");
    return 0;
}
```

> 복사·붙여넣기 대신 **손으로 직접 입력**하시기 바랍니다. 괄호와 세미콜론을 손끝으로 익히는 것이 첫 주의 가장 중요한 훈련입니다.
{: .prompt-tip }

입력이 끝나면 `Ctrl+S`를 눌러 **저장**합니다. 저장하지 않으면 파일 이름 옆에 흰 점(●)이 남아 있으며, 컴파일러는 저장된 내용만 읽으므로 **"고쳤는데 결과가 그대로"** 인 현상의 원인이 됩니다.

### 4.3 코드 한 줄씩 읽기

이 여섯 줄에는 C 프로그램의 뼈대가 모두 들어 있습니다. 한 줄씩 뜻을 확인합니다.

| 코드 | 읽는 법 | 의미 |
|---|---|---|
| `#include <stdio.h>` | 샵 인클루드 에스티디아이오 점 에이치 | 표준 입출력(**st**andar**d i**nput/**o**utput) 기능을 가져다 쓰겠다는 선언. `printf`를 쓰려면 반드시 필요합니다. |
| `int main(void)` | 인트 메인 보이드 | 프로그램이 **시작되는 지점**. 모든 C 프로그램에는 `main`이 정확히 하나 있어야 합니다. `void`는 "넘겨받는 값이 없음"을 뜻합니다. |
| `{` ... `}` | 중괄호 | `main`이 수행할 명령들의 **범위**를 표시합니다. 반드시 짝을 이룹니다. |
| `printf("Hello, World!\n");` | 프린트에프 | 큰따옴표 안의 글자를 화면에 출력합니다. |
| `\n` | 백슬래시 엔 | **줄 바꿈**을 뜻하는 특수 기호입니다. 실제로 `\`와 `n` 두 글자가 화면에 나오는 것이 아닙니다. |
| `return 0;` | 리턴 영 | 프로그램이 **정상적으로 끝났음**을 운영체제에 알립니다. 0이 정상, 0이 아니면 오류를 뜻합니다. |
| `;` | 세미콜론 | **문장의 끝**을 표시합니다. 한국어의 마침표에 해당하며, 빠뜨리면 컴파일 오류가 납니다. |

> **왜 `\n`이 필요할까요?** `\n`을 빼고 실행해 보면 출력 다음에 프롬프트가 같은 줄에 붙어 나오는 것을 볼 수 있습니다. C의 `printf`는 우리가 줄을 바꾸라고 명시하지 않으면 절대 스스로 줄을 바꾸지 않습니다.
{: .prompt-info }

### 4.4 컴파일하고 실행하기

VS Code 안에서 터미널을 엽니다. 메뉴의 **터미널 → 새 터미널**을 선택하거나 단축키 `` Ctrl+Shift+` `` 를 누릅니다. 화면 아래쪽에 터미널이 열리고, 경로가 `C:\c-study\lab01`로 되어 있는지 확인합니다.

**첫째, 컴파일합니다.**

```powershell
gcc hello.c -o hello.exe
```

- `gcc` — 컴파일러를 실행합니다.
- `hello.c` — 번역할 소스 파일입니다.
- `-o hello.exe` — 번역 결과를 `hello.exe`라는 이름으로 만들라는 뜻입니다(**o**utput).

**아무 메시지도 나오지 않으면 성공입니다.** 프로그래밍 도구는 대체로 "잘했다"는 칭찬을 하지 않고, 문제가 있을 때만 말을 겁니다. 왼쪽 탐색기에 `hello.exe`가 새로 생겼는지 확인합니다.

**둘째, 실행합니다.**

```powershell
.\hello.exe
```

```text
Hello, World!
```

![](/assets/img/posts/2026-08-24-cintro-01-vscode-gcc-hello-world-1787320886104.png)

이 문장이 화면에 나타났다면, 여러분은 방금 **자신이 만든 최초의 프로그램**을 실행한 것입니다.

> **`.\` 은 왜 붙일까요?** PowerShell은 보안상의 이유로 현재 폴더의 실행 파일을 자동으로 찾지 않습니다. `.\`는 "지금 이 폴더에 있는"이라는 뜻입니다. 이것을 빠뜨리면 `hello.exe 용어가 인식되지 않습니다` 오류가 납니다.
{: .prompt-info }

### 4.5 경고를 켜고 컴파일하는 습관

앞으로는 컴파일할 때 **경고 옵션을 항상 붙이시기 바랍니다.**

```powershell
gcc -Wall -Wextra -std=c17 hello.c -o hello.exe
```

![](/assets/img/posts/2026-08-24-cintro-01-vscode-gcc-hello-world-1787320915667.png)

| 옵션 | 뜻 |
|---|---|
| `-Wall` | 일반적인 경고를 모두 표시(**W**arning **all**) |
| `-Wextra` | 추가 경고까지 표시 |
| `-std=c17` | C17 표준 문법을 기준으로 검사 |
| `-g` | 디버깅 정보를 포함(제5절에서 사용) |

**오류(error)**는 번역 자체가 불가능한 상태이고, **경고(warning)**는 번역은 되지만 의심스러운 부분이 있다는 뜻입니다. 초보자에게는 경고가 곧 "여기 버그가 숨어 있다"는 신호인 경우가 많으므로, 경고가 하나도 나오지 않는 코드를 목표로 삼으시기 바랍니다.

### 4.6 한글이 깨져서 나올 때

`printf("안녕하세요\n");` 처럼 한글을 출력하면 글자가 깨질 수 있습니다. 한국어 윈도우의 콘솔은 기본 문자 인코딩(**코드 페이지**)이 `949`(CP949)인데, VS Code가 저장한 소스 파일은 **UTF-8**이기 때문입니다. 같은 글자를 서로 다른 규칙으로 읽으니 깨지는 것입니다.

여기에는 **네 가지 인코딩**이 얽혀 있으며, 이들이 맞아떨어져야 한글이 제대로 보입니다.

| 무엇 | 역할 | 확인 방법 | 기본값 |
|---|---|---|---|
| ① 소스 파일 저장 인코딩 | `.c` 파일이 디스크에 저장되는 방식 | VS Code 오른쪽 아래 상태 표시줄 | UTF-8 |
| ② 실행 파일의 문자 인코딩 | `printf`가 실제로 내보내는 바이트 | `gcc`의 `-fexec-charset` 옵션 | 소스와 동일(UTF-8) |
| ③ 콘솔 코드 페이지 | 화면에 글자를 그릴 때의 규칙 | 터미널에서 `chcp` | 949(CP949) |
| ④ `[Console]::OutputEncoding` | **PowerShell이 프로그램의 출력 바이트를 해석하는 규칙** | `[Console]::OutputEncoding.WebName` | ks_c_5601-1987(CP949) |

해결 방법은 **②를 그대로 두고 ③·④를 UTF-8로 맞추거나(방법 1·2·3), 반대로 ②를 CP949로 바꾸는 것(방법 4)** 입니다.

![](/assets/img/posts/2026-08-24-cintro-01-vscode-gcc-hello-world-1787320947624.png)


**방법 1 — 터미널에서 한 번만 바꾸기 (임시)**

```powershell
chcp 65001
```

```powershell
[Console]::OutputEncoding = [System.Text.Encoding]::UTF8
```

**두 줄을 모두** 실행하여야 합니다. 확인은 다음과 같이 합니다.

```powershell
chcp
```

```powershell
[Console]::OutputEncoding.WebName
```

각각 `현재 코드 페이지: 65001` 과 `utf-8` 이 나오면 성공입니다. 다만 **터미널을 닫으면 원래대로 돌아갑니다.**

> **`chcp 65001`만으로는 해결되지 않습니다 — 반드시 알아 둘 것**
> `chcp`는 위 표의 ③(콘솔 코드 페이지)만 바꿉니다. 그런데 Windows PowerShell 5.1은 **시작 시점의 코드 페이지를 ④에 새겨 두고**, 이후 외부 프로그램이 내보낸 바이트를 그 값으로 해석합니다. 그래서 `chcp`의 결과가 `65001`인데도 출력만 계속 깨지는 현상이 생깁니다.
>
> ```text
> PS C:\c-study\lab01> chcp
> 활성 코드 페이지: 65001
> PS C:\c-study\lab01> .\hello.exe
> ?댐 뀲 ?샣 꽥 ??
> ```
>
> 이때는 `[Console]::OutputEncoding`까지 함께 지정하여야 합니다. **한글이 깨졌는데 `chcp`가 이미 65001이라면 원인은 여기입니다.**
{: .prompt-danger }

**방법 2 — VS Code에 고정하기 (권장)**

터미널을 열 때마다 위 두 가지가 자동으로 적용되도록 설정합니다.

1. `Ctrl+Shift+P`를 누르고 **`Preferences: Open User Settings (JSON)`** 을 선택합니다.
2. 열린 `settings.json`의 바깥 중괄호 `{ }` 안에 다음을 추가하고 저장합니다.

```json
"terminal.integrated.profiles.windows": {
    "PowerShell (UTF-8)": {
        "source": "PowerShell",
        "args": ["-NoExit", "-Command",
            "chcp 65001 > $null; [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; $OutputEncoding = [System.Text.Encoding]::UTF8"
        ]
    }
},
"terminal.integrated.defaultProfile.windows": "PowerShell (UTF-8)"
```

3. 열려 있던 터미널을 **휴지통 아이콘으로 닫고** 새 터미널(`` Ctrl+Shift+` ``)을 엽니다.

`$OutputEncoding`은 반대 방향, 즉 PowerShell이 프로그램에 **입력을 보낼 때** 쓰는 인코딩입니다. 3강에서 키보드 입력을 다루므로 지금 함께 지정해 둡니다.

> **이미 `terminal.integrated.profiles.windows` 항목이 있는 경우**
> 설정을 통째로 붙여 넣으면 기존 프로파일(Command Prompt, Git Bash 등)이 사라집니다. 그럴 때는 **기존 `"PowerShell"` 항목 안에 `"args"` 한 줄만 추가**하면 됩니다.
>
> ```json
> "PowerShell": {
>     "source": "PowerShell",
>     "icon": "terminal-powershell",
>     "args": ["-NoExit", "-Command",
>         "chcp 65001 > $null; [Console]::OutputEncoding = [System.Text.Encoding]::UTF8; $OutputEncoding = [System.Text.Encoding]::UTF8"
>     ]
> },
> ```
{: .prompt-tip }

> **설정을 바꾸었는데도 그대로라면** 터미널을 **새로 열지 않았기 때문**입니다. 설정은 새로 만들어지는 터미널부터 적용됩니다. `terminal.integrated.enablePersistentSessions` 설정이 켜져 있으면 VS Code를 다시 열 때 **이전 터미널이 그대로 복원**되므로, 이 경우에도 복원된 터미널을 닫고 새 터미널을 열어야 합니다.
{: .prompt-warning }

**방법 3 — 윈도우 전체를 UTF-8로 (재부팅 필요)**

**설정 → 시간 및 언어 → 언어 및 지역 → 관리 언어 설정 → 시스템 로캘 변경**에서 **"세계 언어 지원을 위한 베타: 유니코드 UTF-8 사용"** 을 체크하고 재부팅합니다. 콘솔뿐 아니라 시스템 전체의 기본 인코딩이 UTF-8이 됩니다.

> 이 옵션은 UTF-8을 지원하지 않는 옛 프로그램에서 오히려 글자가 깨질 수 있습니다. 실습실 공용 PC에서는 **방법 2**를 사용하시기 바랍니다.
{: .prompt-warning }

**방법 4 — 컴파일할 때 윈도우 한글 코드로 변환**

콘솔을 그대로 두고 실행 파일 쪽을 CP949에 맞추는 방식입니다.

```powershell
gcc -finput-charset=UTF-8 -fexec-charset=CP949 hello.c -o hello.exe
```

**그래도 네모(□)로 보인다면** 인코딩이 아니라 **글꼴** 문제입니다. `settings.json`에 아래를 추가합니다.

```json
"terminal.integrated.fontFamily": "D2Coding, Consolas, monospace"
```

**소스 파일 자체가 CP949로 저장된 경우**에는 VS Code 오른쪽 아래의 인코딩 표시(`CP949`)를 클릭하고 **인코딩하여 저장 → UTF-8**을 선택하여 다시 저장합니다.

![](/assets/img/posts/2026-08-24-cintro-01-vscode-gcc-hello-world-1787320997687.png)

## 제5절. VS Code에서 빌드하고 디버깅하기

매번 터미널에 명령을 입력하는 것도 좋은 훈련이지만, 실제 개발에서는 단축키 하나로 빌드하고 실행합니다. 이제 그 설정을 만듭니다.

### 5.1 빌드 작업 만들기 (`tasks.json`)

1. VS Code에서 `hello.c` 파일이 열린 상태로 둡니다.
2. 메뉴에서 **터미널 → 기본 빌드 작업 구성...** 을 선택합니다.
3. **구성할 작업 선택** 목록이 나타나면 **`C/C++: gcc.exe 활성 파일 빌드`** 를 선택합니다. 항목 아래의 컴파일러 경로가 `C:\msys64\ucrt64\bin\gcc.exe`인지 반드시 확인하십시오.

   | 목록에 함께 보이는 항목 | 선택 여부 |
   |---|---|
   | **C/C++: gcc.exe 활성 파일 빌드** | **이것을 선택** — 우리가 설치한 MSYS2 UCRT64의 GCC |
   | C/C++: cl.exe 활성 파일 빌드 | 선택하지 않음 — Visual Studio(MSVC)용이며 설치되어 있지 않음 |
   | CMake: 구성 / 빌드 / 설치 … | 선택하지 않음 — CMake Tools 확장의 항목으로, 이 과정에서는 사용하지 않음 |

   같은 이름의 `gcc.exe` 항목이 **두 개 보이더라도** 컴파일러 경로가 같다면 어느 것을 선택해도 결과는 동일합니다.
4. `.vscode` 폴더가 만들어지고 `tasks.json`이 열립니다. 자동 생성된 내용에는 **경고 옵션(`-Wall` 등)이 없고 작업 이름도 다르므로**, 아래 내용으로 **모두 바꾼 뒤** `Ctrl+S`로 저장합니다.

```json
{
    "version": "2.0.0",
    "tasks": [
        {
            "type": "shell",
            "label": "C 빌드 (gcc)",
            "command": "gcc",
            "args": [
                "-g",
                "-Wall",
                "-Wextra",
                "-std=c17",
                "${file}",
                "-o",
                "${fileDirname}\\${fileBasenameNoExtension}.exe"
            ],
            "options": {
                "cwd": "${fileDirname}"
            },
            "problemMatcher": [
                "$gcc"
            ],
            "group": {
                "kind": "build",
                "isDefault": true
            }
        }
    ]
}
```

`${file}`은 "지금 편집 중인 파일", `${fileBasenameNoExtension}`은 "확장자를 뗀 파일 이름"을 뜻하는 VS Code의 변수입니다. 덕분에 이 설정 하나로 앞으로 만들 모든 `.c` 파일을 빌드할 수 있습니다.

이제 `hello.c` 창에서 **`Ctrl+Shift+B`** 를 눌러 보십시오. 아래 터미널에 컴파일 명령이 실행되고 `hello.exe`가 만들어집니다.

### 5.2 디버깅 설정 만들기 (`launch.json`)

**디버깅**이란 프로그램을 원하는 줄에서 멈춰 세우고, 그 순간의 변수 값을 들여다보는 기능입니다. 아직 변수를 배우지 않았지만, 2강부터 곧바로 쓸 것이므로 지금 설정해 둡니다.

1. 왼쪽 세로 막대에서 **벌레와 삼각형 모양 아이콘**(실행 및 디버그, `Ctrl+Shift+D`)을 누릅니다.
   ![](/assets/img/posts/2026-08-24-cintro-01-vscode-gcc-hello-world-1787321604775.png)
2. **launch.json 파일 만들기**를 누릅니다.
   ![](/assets/img/posts/2026-08-24-cintro-01-vscode-gcc-hello-world-1787321643834.png)
3. **디버그 구성 선택** 목록이 나타나면 맨 위의 **`C/C++: gcc.exe 활성 파일 빌드 및 디버그`** 를 선택합니다. 항목 아래에 컴파일러 경로가 `C:\msys64\ucrt64\bin\gcc.exe`로 표시되어 있는지 확인하십시오.

   | 목록에 함께 보이는 항목 | 선택 여부 |
   |---|---|
   | **C/C++: gcc.exe 활성 파일 빌드 및 디버그** | **이것을 선택** — 우리가 설치한 MSYS2 UCRT64의 GCC |
   | C/C++: cl.exe 활성 파일 빌드 및 디버그 | 선택하지 않음 — Visual Studio(MSVC)용이며 설치되어 있지 않음 |
   | (gdb) 시작 | 선택하지 않음 — 내용이 비어 있는 템플릿 |
   | (Windows) 시작 | 선택하지 않음 — MSVC 전용 디버거 |

   VS Code 버전에 따라 이 목록 대신 **C++ (GDB/LLDB)** 하나만 표시되기도 합니다. 그 경우에는 그것을 선택하면 됩니다.
4. 열린 파일의 내용을 아래로 **모두 바꾸고** 저장합니다. VS Code가 자동으로 넣어 준 `preLaunchTask` 값은 5.1절에서 우리가 지은 작업 이름과 다르므로, 아래 내용으로 덮어써야 `F5`가 동작합니다.

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "C 디버그 (gdb)",
            "type": "cppdbg",
            "request": "launch",
            "program": "${fileDirname}\\${fileBasenameNoExtension}.exe",
            "args": [],
            "stopAtEntry": false,
            "cwd": "${fileDirname}",
            "environment": [],
            "externalConsole": false,
            "MIMode": "gdb",
            "miDebuggerPath": "C:\\msys64\\ucrt64\\bin\\gdb.exe",
            "setupCommands": [
                {
                    "description": "gdb에 대해 자동 서식 지정 사용",
                    "text": "-enable-pretty-printing",
                    "ignoreFailures": true
                }
            ],
            "preLaunchTask": "C 빌드 (gcc)"
        }
    ]
}
```

> `preLaunchTask`의 값은 5.1절 `tasks.json`의 `label`과 **글자 하나까지 똑같아야** 합니다. 다르면 "작업을 찾을 수 없습니다" 오류가 납니다.
{: .prompt-warning }

### 5.3 중단점을 걸고 실행해 보기

1. `hello.c` 편집 화면에서 `printf` 가 있는 줄의 **행 번호 왼쪽 여백**을 클릭합니다. 빨간 점(●)이 생기며, 이것을 **중단점(breakpoint)** 이라고 합니다.
2. **`F5`** 를 누릅니다.
3. 프로그램이 빌드된 뒤 실행되다가, 빨간 점이 있는 줄에서 **노란 화살표와 함께 멈춥니다.**
4. 위쪽에 나타난 도구 막대의 버튼을 사용합니다.

| 버튼 | 단축키 | 기능 |
|---|---|---|
| 계속 | `F5` | 다음 중단점까지 실행 |
| 한 단계씩 코드 실행 | `F10` | 현재 줄을 실행하고 다음 줄로 |
| 중지 | `Shift+F5` | 디버깅 종료 |

> **`tasks.json`에 작업이 저절로 늘어나는 경우**
> **실행 및 디버그** 패널에서 우리가 만든 `C 디버그 (gdb)` 대신 VS Code가 제안하는 항목을 실행하면, `tasks.json`에 `"디버거에서 생성된 작업입니다"`라는 작업이 추가되고 **기본 빌드 작업(`isDefault`)이 그쪽으로 옮겨갑니다.** 그러면 `Ctrl+Shift+B`가 경고 옵션(`-Wall -Wextra`) 없이 빌드하게 됩니다.
>
> 화면 왼쪽 위 디버그 구성 드롭다운에 **`C 디버그 (gdb)`** 가 선택되어 있는지 확인하고, 작업이 늘어났다면 5.1절의 내용으로 `tasks.json`을 되돌린 뒤 `"isDefault": true`가 우리 작업에 있는지 확인합니다.
{: .prompt-warning }

`F10`을 눌러 `printf` 줄을 넘기면, 아래 **디버그 콘솔** 또는 터미널에 `Hello, World!`가 출력되는 것을 볼 수 있습니다. 코드 한 줄이 실행되는 순간을 눈으로 확인한 것입니다.

## 제6절. 오류 메시지 읽는 법

프로그래밍 학습에서 오류는 실패가 아니라 **가장 자주 만나는 일상**입니다. 중요한 것은 오류를 피하는 것이 아니라 **읽는 법**을 익히는 것입니다.

GCC의 오류 메시지는 항상 다음 형식을 따릅니다.

```text
hello.c:5:30: error: expected ';' before '}' token
   |          ^
```

| 부분 | 뜻 |
|---|---|
| `hello.c` | 문제가 있는 **파일 이름** |
| `5` | **줄 번호** |
| `30` | 그 줄에서 몇 번째 글자인지 |
| `error:` | 오류(번역 불가) — `warning:` 이면 경고 |
| `expected ';' before '}'` | 무엇이 잘못되었는지 |

> **가장 중요한 원칙:** 오류가 수십 줄 쏟아져도 **맨 위의 첫 번째 오류부터** 고칩니다. 앞의 실수 하나가 뒤의 오류 수십 개를 만들어 내는 일이 매우 흔하기 때문입니다. 하나 고치고 다시 컴파일하면 나머지가 한꺼번에 사라지는 경우가 많습니다.
{: .prompt-tip }

### 6.1 초보자가 자주 만나는 오류 여덟 가지

| 메시지 | 원인 | 해결 |
|---|---|---|
| `'gcc'은(는) 내부 또는 외부 명령...` | PATH 미등록 또는 터미널을 새로 열지 않음 | 3.4~3.5절 재확인 후 터미널 재시작 |
| `hello.exe 용어가 인식되지 않습니다` | 실행할 때 `.\` 를 빠뜨림 | `.\hello.exe` 로 실행 |
| `error: expected ';' before ...` | 세미콜론 누락 | 오류 줄의 **바로 윗줄** 끝에 `;` 추가 |
| `warning: missing terminating " character` | 큰따옴표 짝이 안 맞음 | 문자열 양쪽 `"` 확인 |
| `error: expected declaration or statement at end of input` | 중괄호 `}` 누락 | 여는 `{`와 닫는 `}` 개수 확인 |
| `warning: implicit declaration of function 'printf'` | `#include <stdio.h>` 누락 | 첫 줄에 추가 |
| `undefined reference to 'WinMain'` | `main` 철자 오류(`Main`, `mian` 등) | 반드시 소문자 `main` |
| `Permission denied` / `cannot open output file` | 이전에 만든 프로그램이 아직 실행 중 | 실행 중인 창을 닫고 다시 컴파일 |
| 한글이 `?댐 뀲 ?샣…` 처럼 깨짐 | 콘솔 코드 페이지가 949 | `chcp 65001` (4.6절 방법 2로 고정) |
| `chcp`가 65001인데도 한글이 깨짐 | PowerShell이 시작 시점의 인코딩(CP949)으로 출력을 해석 | `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8` |

### 6.2 스스로 오류를 만들어 보기

오류 메시지에 익숙해지는 가장 좋은 방법은 **일부러 틀려 보는 것**입니다. `hello.c`를 다음과 같이 하나씩 고쳐 컴파일해 보고, 어떤 메시지가 나오는지 확인한 뒤 되돌리시기 바랍니다.

1. `printf` 줄 끝의 세미콜론을 지운다.
2. 첫 줄 `#include <stdio.h>` 를 지운다.
3. `main`을 `Main`으로 고친다.
4. 마지막 `}`를 지운다.

각각의 메시지를 위 표에서 찾아 대응시켜 보면, 오류 메시지가 더 이상 낯선 암호가 아니라 **친절한 안내문**으로 보이기 시작합니다.

### 문제 1. 자기소개 출력하기

`intro.c` 파일을 만들어, 아래와 같이 **세 줄**을 출력하는 프로그램을 작성하십시오. 이름과 학과는 자신의 것으로 적습니다.

```text
이름: 홍길동
학과: 정보보안과
목표: C 언어로 나만의 프로그램 만들기
```

**정답 및 해설**

```c
#include <stdio.h>

int main(void)
{
    printf("이름: 홍길동\n");
    printf("학과: 정보보안과\n");
    printf("목표: C 언어로 나만의 프로그램 만들기\n");
    return 0;
}
```

```powershell
gcc -Wall -Wextra -std=c17 intro.c -o intro.exe
```

```powershell
.\intro.exe
```

**해설**

- `printf`는 여러 번 호출할 수 있으며, 호출한 순서대로 출력됩니다.
- 각 문장 끝의 `\n`이 없으면 세 줄이 한 줄로 이어져 나옵니다.
- 아래처럼 한 번의 `printf`로도 같은 결과를 얻을 수 있습니다.

```c
printf("이름: 홍길동\n학과: 정보보안과\n목표: C 언어로 나만의 프로그램 만들기\n");
```

- 한글이 깨진다면 터미널에서 `chcp 65001`을 먼저 실행합니다(4.6절).

### 문제 2. 특수 문자 출력하기

`escape.c` 파일을 만들어, 아래 결과를 **정확히 그대로** 출력하는 프로그램을 작성하십시오. (따옴표와 역슬래시가 실제로 화면에 보여야 합니다.)

```text
그는 "안녕"이라고 말했다.
경로:	C:\c-study\lab01
합계	100	점
```

**정답 및 해설**

```c
#include <stdio.h>

int main(void)
{
    printf("그는 \"안녕\"이라고 말했다.\n");
    printf("경로:\tC:\\c-study\\lab01\n");
    printf("합계\t100\t점\n");
    return 0;
}
```

**해설**

`\` 로 시작하는 조합을 **이스케이프 시퀀스(escape sequence)** 라고 하며, 키보드로 바로 칠 수 없거나 특별한 의미를 가진 글자를 표현할 때 사용합니다.

| 표기 | 의미 |
|---|---|
| `\n` | 줄 바꿈 |
| `\t` | 탭(가로 정렬) |
| `\"` | 큰따옴표 자체 |
| `\\` | 역슬래시 자체 |
| `\a` | 경고음 |

문자열의 시작과 끝을 알리는 것이 `"` 이므로, 문자열 **안에** 큰따옴표를 넣으려면 `\"` 로 적어 "이건 문자열의 끝이 아니라 글자입니다"라고 알려 주어야 합니다. 마찬가지로 역슬래시 한 개를 출력하려면 `\\` 로 두 번 적어야 합니다.

### 문제 3. 고장 난 코드 고치기

아래 코드는 오류가 **네 군데** 있습니다. `broken.c` 파일에 그대로 입력한 뒤, 컴파일 오류 메시지를 보며 하나씩 고쳐 정상 실행되도록 만드십시오.

```c
include <stdio.h>

int Main(void)
{
    printf("컴파일에 성공했습니다!\n")
    return 0;
```

**정답 및 해설**

```c
#include <stdio.h>

int main(void)
{
    printf("컴파일에 성공했습니다!\n");
    return 0;
}
```

**오류 네 가지**

| 번호 | 잘못된 부분 | 나타나는 메시지 | 수정 |
|---|---|---|---|
| 1 | `include` 앞에 `#` 없음 | `error: unknown type name 'include'` | `#include <stdio.h>` |
| 2 | `Main` (대문자 M) | `undefined reference to 'WinMain'` | `main` |
| 3 | `printf(...)` 끝에 `;` 없음 | `error: expected ';' before 'return'` | 줄 끝에 `;` 추가 |
| 4 | 마지막 `}` 없음 | `error: expected declaration or statement at end of input` | 마지막 줄에 `}` 추가 |

**해설**

- 2번 오류가 특히 헷갈립니다. C는 **대문자와 소문자를 완전히 다른 글자로** 취급하므로 `Main`은 `main`이 아닙니다. 시작 지점을 찾지 못한 링커가 윈도우 프로그램의 시작 지점인 `WinMain`이라도 있는지 찾다가 실패하여 저런 메시지를 냅니다.
- 오류를 **한 번에 하나씩** 고치고 매번 다시 컴파일하면, 메시지와 원인이 어떻게 대응되는지 훨씬 명확하게 보입니다.

### 문제 4. 도형 출력하기

`shape.c` 파일을 만들어, 별표(`*`)로 아래 모양을 출력하는 프로그램을 작성하십시오. (반복문은 아직 배우지 않았으므로 `printf`를 여러 번 사용합니다.)

```text
*
**
***
****
*****
```

**정답 및 해설**

```c
#include <stdio.h>

int main(void)
{
    printf("*\n");
    printf("**\n");
    printf("***\n");
    printf("****\n");
    printf("*****\n");
    return 0;
}
```

**해설**

지금은 다섯 줄을 손으로 적었으나, 만약 100줄짜리 삼각형을 그려야 한다면 이 방식은 곧 한계에 부딪힙니다. **6강 반복문**을 배우면 아래처럼 단 세 줄로 같은 일을 할 수 있게 됩니다. 지금은 눈으로만 보아 두시기 바랍니다.

```c
for (int i = 1; i <= 5; i++) {
    for (int j = 0; j < i; j++) printf("*");
    printf("\n");
}
```

### 문제 5. 빌드 단축키로 실행하기

문제 4에서 만든 `shape.c`를 **터미널에 `gcc` 명령을 입력하지 않고** 빌드하여 실행하십시오.

**정답 및 해설**

**절차**

1. VS Code에서 `shape.c` 파일을 열어 활성 상태로 만듭니다.
2. `Ctrl+Shift+B` 를 누릅니다. → 터미널에 `gcc -g -Wall -Wextra -std=c17 ...` 명령이 자동 실행되고 `shape.exe`가 생성됩니다.
3. 터미널에 `.\shape.exe` 를 입력하여 실행합니다.

**확인 사항**

- `tasks.json`의 `${file}`은 **현재 활성화된 편집 창의 파일**을 가리킵니다. 따라서 `hello.c` 창을 보고 있는 상태에서 `Ctrl+Shift+B`를 누르면 `shape.c`가 아니라 `hello.c`가 빌드됩니다. 빌드 전에 **어느 파일이 앞에 있는지** 항상 확인하는 습관이 필요합니다.
- `F5`를 누르면 빌드와 실행이 한 번에 이루어집니다(`preLaunchTask` 설정 덕분입니다).

## 정리

오늘 우리는 다음을 수행하였습니다.

| 구분 | 내용 |
|---|---|
| 개념 | 소스 코드 → 컴파일(전처리·컴파일·어셈블·링크) → 실행 파일 |
| 설치 | Visual Studio Code + C/C++ 확장, MSYS2 + GCC, PATH 등록 |
| 작성 | `#include`, `main`, `printf`, `return`, 세미콜론, `\n` |
| 실행 | `gcc -Wall -Wextra -std=c17 hello.c -o hello.exe` → `.\hello.exe` |
| 도구 | `tasks.json`으로 `Ctrl+Shift+B` 빌드, `launch.json`으로 `F5` 디버깅 |
| 태도 | 오류 메시지는 파일:줄:열 순으로 읽고, **맨 위 오류부터** 고친다 |

가장 어려운 고비를 이미 넘겼습니다. 환경 구축은 한 번만 하면 되고, 앞으로는 코드를 쓰고 실행하는 일에만 집중하게 됩니다.

**다음 2강에서는 C 언어의 뼈대를 한 바퀴 둘러봅니다.** 변수와 산술식으로 계산하는 프로그램을 만들고, `while`·`for`로 반복하며, `getchar`·`putchar`로 바깥에서 들어오는 자료를 처리하고, 배열·함수·문자열까지 나아갑니다. K&R 제1장 전체에 해당하는 분량으로, 이 강의를 마치면 **쓸모 있는 프로그램**을 직접 만들 수 있게 됩니다.

## 부록 A. macOS · 리눅스 사용자를 위한 안내

컴파일러 설치 방법만 다르고, 이후 과정은 동일합니다. 단 실행 파일에 `.exe`를 붙이지 않는 점에 유의합니다.

### A.1 macOS

터미널(응용 프로그램 → 유틸리티 → 터미널)에서 다음을 실행하여 애플의 명령행 개발 도구를 설치합니다.

```bash
xcode-select --install
```

설치 확인과 사용법은 다음과 같습니다.

```bash
clang --version
```

```bash
clang -Wall -Wextra -std=c17 hello.c -o hello
```

```bash
./hello
```

> macOS에서는 `gcc` 명령을 입력하여도 실제로는 `clang` 컴파일러가 동작합니다. 이 과정의 범위에서는 사용법이 사실상 같으므로 그대로 진행하여도 무방합니다. `launch.json`의 `"MIMode"`는 `"lldb"`로, `"miDebuggerPath"` 항목은 삭제합니다.
{: .prompt-info }

### A.2 우분투 리눅스

```bash
sudo apt update && sudo apt install -y build-essential gdb
```

```bash
gcc --version
```

```bash
gcc -Wall -Wextra -std=c17 hello.c -o hello && ./hello
```

`launch.json`에서는 `"program"` 값의 `\\`를 `/`로 바꾸고 확장자 `.exe`를 제거하며, `"miDebuggerPath"`는 `/usr/bin/gdb`로 지정합니다.
