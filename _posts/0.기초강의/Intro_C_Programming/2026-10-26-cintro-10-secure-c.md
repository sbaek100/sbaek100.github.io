## 제1절. C에서 사고가 잦은 이유

### 1.1 C는 검사하지 않습니다

C는 1970년대에 **운영체제를 만들기 위해** 설계된 언어입니다. 그 목적에 맞추어 **"프로그래머가 옳게 쓸 것"을 전제**하고, 실행 중 검사를 거의 하지 않습니다.

| 다른 언어(파이썬·자바 등) | C |
|---|---|
| 배열 범위를 벗어나면 **오류를 알린다** | **검사하지 않는다.** 그냥 옆 메모리를 건드린다 |
| 메모리를 자동으로 회수한다 | **직접 반납**해야 한다 |
| 자료형이 맞지 않으면 막는다 | 캐스트 한 번이면 통과한다 |
| 정수가 넘치면 알려 주거나 자동 확장 | **조용히 넘친다** |

이 설계 덕분에 C는 빠르고 어디에나 이식되지만, **잘못 쓰면 아무도 막아 주지 않습니다.**

### 1.2 미정의 동작

C 표준은 어떤 상황에 대해서는 **"무슨 일이 일어나든 상관하지 않는다"** 고 정해 두었습니다. 이를 **미정의 동작(undefined behavior)** 이라 합니다.

| 미정의 동작의 예 | 배운 곳 |
|---|---|
| 배열 범위 밖 접근 | 2강 7.1절 |
| 부호 있는 정수의 넘침 | 3강 2.2절 |
| 초기화하지 않은 변수 읽기 | 2강 2.5절 |
| `free` 한 메모리 사용 | 8강 6.2절 |
| 문자열 상수 수정 | 6강 6.2절 |
| 평가 순서에 의존하는 식 | 3강 12.3절 |

**미정의 동작의 무서운 점은 "당장은 잘 돌아간다"는 것**입니다. 내 컴퓨터에서는 멀쩡한데 다른 환경에서, 혹은 컴파일 옵션을 바꾸는 순간 무너집니다. 4강 실습문제 6에서 `itoa_bad(INT_MIN)`이 `-(` 라는 쓰레기를 내놓은 것이 그 예였습니다.

### 1.3 신뢰 경계

프로그램을 **"내가 통제하는 안쪽"과 "밖에서 들어오는 바깥쪽"** 으로 나누어 보십시오. 그 사이가 **신뢰 경계(trust boundary)** 입니다.

| 바깥에서 들어오는 것 | 이 과정에서 다룬 예 |
|---|---|
| 사용자 키보드 입력 | `fgets`, `scanf` |
| 명령행 인자 | `argv`(7강) |
| 파일 내용 | `fopen`+`fgets`(9강) |
| 다른 프로그램의 출력 | 파이프 |

**경계를 넘어 들어온 값은 언제나 "적대적일 수 있다"고 가정**해야 합니다. 길이가 얼마든, 형식이 어떻든, 범위를 벗어나든 프로그램이 무너지지 않아야 합니다.

이 한 문장이 이번 강의 전체를 관통합니다.

## 제2절. 버퍼 오버플로 총정리

### 2.1 무엇이 일어나는가

7강에서 직접 확인했습니다. 배열의 크기를 넘겨 쓰면 **바로 옆 메모리를 덮어씁니다.**

```text
name       = AAAAAAAAAAAA
authorized = 1094795585 (0x41414141)
>> 권한 검사를 통과해 버렸습니다!
```

결과는 **얼마나 넘치는가**에 따라 세 단계로 나뉩니다.

| 넘치는 정도 | 결과 | 심각도 |
|---|---|---|
| 옆 변수까지 | 값이 조용히 바뀐다(7강의 `authorized`) | 판단이 뒤집힌다 |
| 스택 프레임의 **돌아갈 주소**까지 | 함수가 엉뚱한 곳으로 복귀한다(5강 11.3절) | **프로그램 흐름을 빼앗긴다** |
| 읽기 쪽에서 넘침 | 옆 메모리의 내용이 **밖으로 새어 나간다** | 비밀번호·키 유출 |

세 번째는 **읽을 때도 사고가 난다**는 점에서 중요합니다. 배열 밖을 읽는 코드는 그 자리에 있던 남의 자료를 그대로 출력해 버립니다.

### 2.2 왜 아직도 이 사고가 나는가

세 가지가 겹칩니다.

1. **C가 검사하지 않는다**(1.1절).
2. **표준 함수 중에 크기를 받지 않는 것들이 있다**(제3절).
3. **입력의 길이는 실행 중에 정해진다.** 그래서 컴파일러가 미리 잡아 주지 못합니다.

7강 7.5절에서 확인한 그대로입니다. 문자열 상수를 복사할 때는 컴파일러가 경고했지만, `argv[1]`을 복사할 때는 아무 경고도 나오지 않았습니다.

### 2.3 운영체제와 컴파일러의 방어

오늘날에는 **넘치더라도 곧바로 장악당하지는 않도록** 여러 장치가 겹겹이 들어가 있습니다.

| 방어 | 하는 일 | 한계 |
|---|---|---|
| **스택 카나리**(stack canary) | 돌아갈 주소 앞에 표식을 두고, 함수가 끝날 때 훼손을 확인 | 옆 변수 오염은 못 막는다 |
| **ASLR** | 실행할 때마다 메모리 주소를 뒤섞는다 | 주소를 알아내면 무력화된다 |
| **DEP/NX** | 자료 영역의 코드를 실행하지 못하게 한다 | 우회 기법이 있다 |
| 컴파일러 경고·위생 검사기 | 개발 중에 미리 잡는다 | 켜야 동작한다(제9절) |

**이 방어들은 모두 "마지막 방어선"입니다.** 7강의 `authorized` 사고는 위 셋을 모두 켜 두어도 그대로 일어납니다. **경계를 지키는 코드를 쓰는 것**이 유일한 근본 대책입니다.

## 제3절. 위험한 함수와 안전한 대체

### 3.1 크기를 받지 않는 함수가 위험합니다

기준은 단순합니다. **"이 함수가 쓸 공간의 크기를 알고 있는가?"**

| 위험한 함수 | 왜 위험한가 | 안전한 대체 |
|---|---|---|
| `gets(s)` | 크기를 아예 받지 않는다. **C11에서 삭제됨** | `fgets(s, sizeof s, stdin)` |
| `strcpy(d, s)` | `s`가 길면 그대로 넘친다 | 길이 검사 후 복사, 또는 `snprintf` |
| `strcat(d, s)` | 남은 자리를 모른다 | 길이 검사 후, 또는 `snprintf` |
| `sprintf(buf, ...)` | 결과 길이를 모른다 | **`snprintf(buf, sizeof buf, ...)`** |
| `scanf("%s", buf)` | 폭 제한이 없다 | `fgets` + `sscanf`, 또는 `%31s` |
| `printf(s)` | 사용자 입력이 서식으로 해석된다 | `printf("%s", s)` |
| `strncpy(d, s, n)` | **끝 표시를 붙이지 않을 수 있다**(4.2절) | `snprintf` |
| `atoi(s)` | 오류를 구분할 수 없다 | `strtol`(제8절) |

### 3.2 세 가지 방식 비교

같은 문제를 세 가지로 풀어 봅니다. `unsafe_vs_safe.c`입니다.

```c
/* 위험한 판 — 크기를 검사하지 않는다 */
static void unsafe_copy(const char *src)
{
    char name[NAMELEN];

    strcpy(name, src);                 /* src 가 길면 배열 밖을 침범한다 */
    printf("  unsafe: %s\n", name);
}

/* 안전한 판 1 — 잘라서 담는다 */
static void safe_truncate(const char *src)
{
    char name[NAMELEN];
    int n;

    n = snprintf(name, sizeof name, "%s", src);
    printf("  잘라 담기: \"%s\"", name);
    if (n >= (int) sizeof name)
        printf("  (원본 %d자 중 %zu자만 저장)", n, sizeof name - 1);
    printf("\n");
}

/* 안전한 판 2 — 너무 길면 거부한다 */
static int safe_reject(const char *src, char *dst, size_t dstsize)
{
    if (strlen(src) >= dstsize)
        return 0;                      /* 담을 수 없다 */
    strcpy(dst, src);                  /* 길이를 확인했으므로 안전 */
    return 1;
}
```

```powershell
.\unsafe_vs_safe.exe programming
```

```text
입력: "programming" (11자)
  잘라 담기: "program"  (원본 11자 중 7자만 저장)
  거부 방식: 너무 길어 저장하지 않음 (최대 7자)
```

```powershell
.\unsafe_vs_safe.exe kim
```

```text
입력: "kim" (3자)
  잘라 담기: "kim"
  거부 방식: 저장 성공 "kim"
```

### 3.3 자를 것인가 거부할 것인가

**정답은 상황에 따라 다릅니다.** 이것이 이 절에서 가장 중요한 판단입니다.

| 방식 | 알맞은 곳 | 위험 |
|---|---|---|
| **자르기** | 화면 표시, 로그 요약 | 잘린 값이 **다른 사람의 것과 같아질 수 있다** |
| **거부하기** | 계정 이름, 파일 경로, 금액 | 사용자가 불편할 수 있다 |

이름을 자르면 `"김철수1"`과 `"김철수2"`가 모두 `"김철수"`가 되어, 권한 검사에서 **다른 사람으로 오인**될 수 있습니다. **판단에 쓰이는 값은 자르지 말고 거부하십시오.**

> `strcpy`가 언제나 나쁜 것은 아닙니다. **길이를 이미 확인했다면 안전합니다.** 위 `safe_reject`가 그 예입니다. 핵심은 함수 이름이 아니라 **"쓰기 전에 크기를 확인했는가"** 입니다.

## 제4절. 문자열을 안전하게 다루기

### 4.1 규칙 네 가지

| 규칙 | 이유 |
|---|---|
| 배열의 크기는 **`sizeof`로 얻는다** | 숫자를 직접 적으면 배열 크기를 바꿀 때 어긋난다 |
| **`'\0'` 자리를 빼고 계산한다** | 8칸이면 담을 수 있는 글자는 **7자** |
| **함수에 크기를 함께 넘긴다** | 배열을 넘기면 크기 정보가 사라진다(6강 4.4절) |
| **잘렸는지 확인한다** | 조용한 절단도 사고가 될 수 있다 |

### 4.2 `strncpy`의 함정

`strncpy`는 이름만 보면 안전해 보이지만 **끝 표시를 붙이지 않을 수 있습니다.** `strncpy_trap.c`로 확인합니다.

```c
    /* strncpy 는 자리가 모자라면 '\0' 을 붙이지 않는다 */
    memset(dst, '#', sizeof dst);          /* 눈에 보이게 채워 둔다 */
    strncpy(dst, src, sizeof dst);
```

```text
strncpy 뒤 배열 내용: programm
-> '\0' 이 없으므로 이 배열을 문자열로 쓰면 안 된다
고친 뒤: "program" (길이 7)
snprintf: "program"
```

8칸이 모두 글자로 채워져 **끝 표시가 없습니다.** 이 상태로 `printf("%s", dst)`를 하면 `'\0'`이 나올 때까지 계속 읽어 **옆 메모리를 그대로 출력**합니다(2.1절의 세 번째 유형).

고치는 방법은 둘입니다.

```c
    strncpy(dst, src, sizeof dst - 1);
    dst[sizeof dst - 1] = '\0';        /* 직접 붙인다 */
```

```c
    snprintf(dst, sizeof dst, "%s", src);   /* 언제나 끝 표시를 붙여 준다 */
```

**`snprintf`를 기본으로 삼으십시오.** 이름이 낯설 뿐, 규칙이 단순하고 실수할 여지가 적습니다.

### 4.3 이어 붙이기

이어 붙일 때는 **이미 들어 있는 길이까지 계산**해야 합니다.

```c
/* 문자열을 안전하게 이어 붙인다. 성공하면 1, 자리가 모자라면 0 */
int safe_append(char *dst, size_t dstsize, const char *src)
{
    size_t dlen = strlen(dst);
    size_t slen = strlen(src);

    if (dlen + slen + 1 > dstsize)      /* '\0' 자리까지 고려 */
        return 0;
    memcpy(dst + dlen, src, slen + 1);  /* 끝 표시까지 함께 복사 */
    return 1;
}
```

```text
시작: "hello"
", world" 붙이기 = 성공 -> "hello, world"
" and more" 붙이기 = 실패 -> "hello, world"
```

**실패했을 때 원본이 그대로 남는다**는 점이 중요합니다. 중간까지 붙이다 마는 것이 가장 나쁩니다.

## 제5절. 정수 문제

### 5.1 세 가지 함정

`int_overflow.c`로 한꺼번에 확인합니다.

```text
INT_MAX          = 2147483647
INT_MAX 를 넘기면 부호 있는 정수는 미정의 동작입니다.
UINT_MAX         = 4294967295
UINT_MAX + 1     = 0   <- unsigned 는 0 으로 돌아간다(규정된 동작)
(short) 70000    = 4464   <- 값이 잘렸다
-1 < 1u          = 0   <- -1 이 큰 양수로 변환된다!
정상 요청 결과   = 성공
과도한 요청 결과 = 실패(검사에 걸림)
```

| 함정 | 무슨 일이 일어나는가 |
|---|---|
| **부호 있는 정수의 넘침** | **미정의 동작**. 컴파일러가 예상 밖의 코드를 낼 수 있다 |
| **좁은 자료형으로 대입** | 위쪽 비트가 잘린다. 70000이 4464가 되었다 |
| **부호 있는 값과 없는 값의 비교** | 부호 있는 쪽이 **큰 양수로 변환**된다. `-1 < 1u`가 **거짓** |

세 번째가 특히 위험합니다. 길이 검사에서 다음과 같은 코드는 **음수 길이를 통과시킵니다.**

```c
if (len < sizeof buf)      /* len 이 int 이고 음수라면? */
    memcpy(buf, src, len); /* 거대한 크기로 해석되어 넘친다 */
```

**컴파일러가 잡아 줍니다.** `-Wall -Wextra`로 컴파일하면 이 줄에 경고가 나옵니다.

```text
warning: comparison of integer expressions of different signedness: 'int' and 'unsigned int' [-Wsign-compare]
```

### 5.2 크기 계산은 넘침을 검사합니다

3강 2.2절에서 예고한 대로, **정수 넘침은 버퍼 오버플로의 출발점**이 됩니다.

```c
p = malloc(count * size);      /* 곱셈이 넘치면 아주 작은 값이 된다 */
```

`count`와 `size`가 크면 곱이 넘쳐 **작은 값**이 되고, `malloc`은 그 작은 공간만 내어 줍니다. 그런데 프로그램은 `count`개를 쓸 수 있다고 믿습니다.

```c
/* 크기 계산이 넘치는지 검사하고 메모리를 빌린다 */
static void *safe_array_alloc(size_t count, size_t size)
{
    if (count != 0 && size > SIZE_MAX / count) {   /* 곱셈이 넘치는가 */
        fprintf(stderr, "요청이 너무 큽니다 (%zu x %zu)\n", count, size);
        return NULL;
    }
    return malloc(count * size);
}
```

**나눗셈으로 미리 확인하는 것**이 요령입니다. 곱한 뒤에 확인하면 이미 늦습니다.

### 5.3 실무 규칙

| 규칙 | 설명 |
|---|---|
| 크기·개수·길이는 **`size_t`** | 표준 함수들과 자료형이 맞고 음수가 없다 |
| 뺄셈에 주의 | `size_t`끼리 빼면 음수가 **거대한 양수**가 된다 |
| 넓은 자료형으로 검사 | `long long`으로 계산해 범위를 확인(실습문제 3) |
| 경고를 끄지 말 것 | `-Wsign-compare`, `-Wconversion` |

## 제6절. 메모리 관리 규칙

### 6.1 네 가지 사고

| 사고 | 무슨 일 | 증상 |
|---|---|---|
| **메모리 누수** | `free`를 빠뜨림 | 오래 돌수록 메모리를 잡아먹는다 |
| **반납 후 사용**(use-after-free) | `free` 뒤에 그 포인터를 씀 | 남에게 넘어간 자리를 건드린다 — **보안 사고** |
| **이중 반납**(double free) | `free`를 두 번 | 메모리 관리 구조가 망가진다 |
| **`NULL` 미검사** | `malloc` 실패를 확인하지 않음 | 즉시 죽는다 |

### 6.2 규칙과 예제

`memory_rules.c`입니다.

```c
/* 잘못된 반납: free 한 뒤에 p->next 를 읽는다 (절대 이렇게 쓰지 말 것)
   for (p = head; p != NULL; p = p->next)
       free(p);                                              */

/* 올바른 반납 */
static void free_list(struct node *head)
{
    struct node *p, *next;

    for (p = head; p != NULL; p = next) {
        next = p->next;            /* 지우기 전에 다음을 기억한다 */
        free(p);
    }
}
```

8강 실습문제 4에서 만든 것과 같습니다. **`free(p)` 뒤에는 `p->next`를 읽을 수 없다**는 것이 요점입니다.

```c
    head = make_list(5);
    if (head == NULL) {            /* NULL 검사 */
        fprintf(stderr, "메모리가 부족합니다\n");
        return 1;
    }
    ...
    free_list(head);
    head = NULL;                   /* 반납 뒤에는 NULL 로 — 재사용 사고를 막는다 */
```

```text
목록: 1 2 3 4 5
반납 후 head == NULL : 1
복사한 문자열 = hello
```

### 6.3 도중에 실패했을 때

여러 번 메모리를 빌리다가 중간에 실패하면, **이미 빌린 것을 정리하고 나가야** 합니다.

```c
        p = (struct node *) malloc(sizeof(struct node));
        if (p == NULL) {           /* 반드시 검사 */
            free_list(head);       /* 여기까지 만든 것은 정리하고 나간다 */
            return NULL;
        }
```

이 처리를 빠뜨리면 **오류가 날 때마다 메모리가 새어 나갑니다.** 공격자가 일부러 실패를 반복시켜 메모리를 고갈시키는 수법이 있습니다.

### 6.4 습관

| 습관 | 이유 |
|---|---|
| `malloc` 결과는 **즉시 검사** | 실패는 반드시 일어난다 |
| `free` 뒤에는 **`NULL` 대입** | 반납 후 사용과 이중 반납을 동시에 막는다 |
| **빌린 곳과 반납하는 곳을 짝지어** 설계 | 누가 반납할 책임인지 주석에 적는다 |
| 크기 계산에 **`sizeof`와 `+1`** | 문자열은 언제나 끝 표시 자리가 필요하다 |

## 제7절. 형식 문자열 취약점

9강 2.6절에서 짧게 다룬 내용을 정리합니다.

```c
printf(line);          /* 위험 */
printf("%s", line);    /* 안전 */
```

`line`이 사용자 입력이고 그 안에 `%d`, `%s`, `%x` 같은 것이 들어 있으면, `printf`는 **있지도 않은 인자를 찾아 메모리를 읽습니다.**

| 입력에 들어 있으면 | 벌어지는 일 |
|---|---|
| `%x %x %x` | 스택의 값들이 그대로 화면에 출력된다 — **정보 노출** |
| `%s` | 엉뚱한 주소를 문자열로 읽으려다 프로그램이 죽는다 |

`fmt_string.c`에서 두 줄을 비교해 보십시오.

```c
    /* printf(line);            <- 위험: line 안의 % 를 서식으로 해석한다 */
    printf("%s\n", line);       /* 안전 */
```

**규칙은 하나입니다. 형식 문자열 자리에는 언제나 프로그래머가 쓴 문자열 상수만 둡니다.** 변수는 인자 자리로 보내십시오. `fprintf`·`sprintf`·`snprintf`도 모두 같습니다.

## 제8절. 입력 검증과 신뢰 경계

### 8.1 검증의 순서

바깥에서 온 값은 **쓰기 전에** 다음을 확인합니다.

| 순서 | 확인할 것 | 예 |
|---|---|---|
| 1 | **길이** | 배열에 담을 수 있는가 |
| 2 | **형식** | 숫자여야 하는데 글자가 섞이지 않았는가 |
| 3 | **범위** | 0~100 사이인가 |
| 4 | **의미** | 존재하는 학번인가, 권한이 있는가 |

### 8.2 `atoi` 대신 `strtol`

9강에서 쓴 `atoi`는 **오류를 구분하지 못합니다.** `"abc"`도 0을 돌려주고 `"0"`도 0을 돌려줍니다. 범위를 넘겨도 알 수 없습니다.

`input_validate.c`입니다.

```c
/* 문자열을 정수로 안전하게 바꾼다. 성공하면 1 */
static int parse_int(const char *s, long min, long max, long *out)
{
    char *end;
    long v;

    errno = 0;
    v = strtol(s, &end, 10);

    if (end == s)                      /* 숫자가 하나도 없었다 */
        return 0;
    while (*end == ' ' || *end == '\t' || *end == '\n')
        end++;                         /* 뒤쪽 공백은 허용 */
    if (*end != '\0')                  /* 숫자 뒤에 다른 글자가 남았다 */
        return 0;
    if (errno == ERANGE || v < min || v > max)   /* 범위를 벗어났다 */
        return 0;

    *out = v;
    return 1;
}
```

| `strtol`이 알려 주는 것 | 어떻게 |
|---|---|
| 숫자가 아예 없었다 | `end == s` |
| 뒤에 이상한 글자가 남았다 | `*end != '\0'` |
| `long`의 범위를 넘었다 | `errno == ERANGE` |
| 우리가 정한 범위를 넘었다 | `v < min \|\| v > max` |

이 네 가지를 모두 확인해야 비로소 **믿을 수 있는 값**이 됩니다.

### 8.3 배열 접근도 검증합니다

`array_bounds.c`는 첨자를 검사하는 접근 함수를 보여 줍니다.

```c
/* 첨자를 검사하고 접근한다 */
static int get_at(const int a[], int n, int i, int *ok)
{
    if (i < 0 || i >= n) {
        *ok = 0;
        return 0;
    }
    *ok = 1;
    return a[i];
}
```

```text
a[-1] : 범위를 벗어난 접근을 막았습니다
a[ 0] = 10
a[ 1] = 20
a[ 2] = 30
a[ 3] = 40
a[ 4] = 50
a[ 5] : 범위를 벗어난 접근을 막았습니다
배열의 원소 수 = 5   <- sizeof 로 구한다
```

**`i < 0` 검사를 빠뜨리지 마십시오.** 사용자 입력에서 온 첨자는 음수일 수 있고, 음수 첨자는 배열 **앞쪽**을 침범합니다.

### 8.4 안전한 입력 함수 한 벌

`safe_menu.c`는 지금까지의 규칙을 모두 적용한 형태입니다.

```c
/* 한 줄을 안전하게 읽는다. 성공하면 1 */
static int read_line(char *buf, size_t size, int *truncated)
{
    size_t len;

    *truncated = 0;
    if (fgets(buf, (int) size, stdin) == NULL)
        return 0;
    len = strlen(buf);
    if (len > 0 && buf[len - 1] == '\n') {
        buf[len - 1] = '\0';
    } else {
        int c;                         /* 줄이 잘렸다 — 남은 글자를 버린다 */
        *truncated = 1;
        while ((c = getchar()) != '\n' && c != EOF)
            ;
    }
    return 1;
}
```

**줄이 잘렸을 때 남은 글자를 버리는 처리**가 중요합니다. 그러지 않으면 다음 입력에 지난 줄의 찌꺼기가 섞여 들어옵니다.

## 제9절. 도구로 잡기

사람이 모든 것을 기억할 수는 없습니다. **도구가 대신 잡아 주게** 만드십시오.

### 9.1 컴파일러 경고

우리가 1강부터 써 온 `-Wall -Wextra`에 몇 가지를 더할 수 있습니다.

```powershell
gcc -Wall -Wextra -Wconversion -Wshadow -std=c17 prog.c -o prog.exe
```

| 옵션 | 잡아 주는 것 |
|---|---|
| `-Wall -Wextra` | 대부분의 흔한 실수 |
| `-Wconversion` | 자료형이 좁아지며 값이 잘리는 곳 |
| `-Wshadow` | 바깥 이름을 가리는 변수(5강 9절) |
| `-Werror` | **경고를 오류로 취급** — 경고를 남기지 못하게 한다 |

이 과정에서 컴파일러가 미리 잡아 준 것들을 떠올려 보십시오.

| 경고 | 나온 곳 |
|---|---|
| `-Wdangling-else` | 4강 2.2절 매달린 `else` |
| `-Wimplicit-fallthrough` | 4강 4.3절 폴스루 |
| `-Wstringop-overflow` | 2강 실습 문자열 넘침 |
| `-Wsign-compare` | 5.1절 부호 혼용 비교 |

### 9.2 위생 검사기

**실행 중에** 메모리 오류를 잡아 주는 도구가 있습니다.

```powershell
gcc -fsanitize=address,undefined -g prog.c -o prog.exe
```

| 검사기 | 잡는 것 |
|---|---|
| **AddressSanitizer**(`address`) | 배열 범위 초과, 반납 후 사용, 이중 반납, 누수 |
| **UndefinedBehaviorSanitizer**(`undefined`) | 정수 넘침, 잘못된 시프트, 널 포인터 역참조 |

프로그램이 **사고가 난 지점과 원인을 알려 주고 멈춥니다.** 속도가 느려지므로 **개발·시험 중에만** 켭니다.

> 사용하는 환경에 따라 이 옵션이 지원되지 않을 수 있습니다. Windows의 MSYS2 환경에서는 지원 여부가 도구 모음 버전에 따라 다르므로, 동작하지 않으면 리눅스 환경에서 시도해 보시기 바랍니다. **2부 과정에서는 리눅스를 주 실습 환경으로 쓰므로 그때 본격적으로 사용합니다.**

### 문제 1. 위험한 프로그램 전면 수정

다음 프로그램의 **모든** 문제를 찾아 고치십시오.

```c
char name[16];
char msg[128];
char *copy;

gets(name);
sprintf(msg, "안녕하세요, %s님", name);
printf(msg);
copy = malloc(strlen(msg));
strcpy(copy, msg);
printf("복사본: %s\n", copy);
```

**정답 및 해설**

**문제는 다섯 가지입니다.**

| 번호 | 문제 | 고침 |
|---|---|---|
| 1 | `gets` — 크기를 받지 않음 | `fgets(name, sizeof name, stdin)` |
| 2 | `sprintf` — 결과 길이를 모름 | `snprintf(msg, sizeof msg, ...)` |
| 3 | `printf(msg)` — 형식 문자열 취약점 | `printf("%s\n", msg)` |
| 4 | `malloc(strlen(msg))` — **`+1` 누락** | `malloc(strlen(msg) + 1)` |
| 5 | `malloc` 결과 미검사, `free` 없음 | `NULL` 검사 후 사용, 끝나면 `free` |

```c
    printf("이름: ");
    if (fgets(name, sizeof name, stdin) == NULL)   /* gets -> fgets */
        return 1;

    len = strlen(name);
    if (len > 0 && name[len - 1] == '\n')
        name[len - 1] = '\0';

    /* sprintf -> snprintf */
    snprintf(msg, sizeof msg, "안녕하세요, %s님", name);

    /* printf(msg) -> printf("%s", msg) */
    printf("%s\n", msg);

    /* malloc: '\0' 자리 포함, NULL 검사, 사용 후 free */
    copy = (char *) malloc(strlen(msg) + 1);
    if (copy == NULL) {
        fprintf(stderr, "메모리 부족\n");
        return 1;
    }
    strcpy(copy, msg);
    printf("복사본: %s\n", copy);
    free(copy);
    copy = NULL;
```

- **`fgets`가 남긴 개행을 지우는 처리**를 잊지 마십시오(9강 7.2절).
- `strcpy(copy, msg)`는 여기서는 **안전합니다.** 바로 앞에서 `strlen(msg) + 1`만큼 확보했기 때문입니다(3.3절).
- 한글은 UTF-8에서 글자당 3바이트이므로 `msg`를 넉넉히 잡았습니다.

### 문제 2. 안전한 문자열 이어 붙이기

`strcat`을 대신할 안전한 함수를 만드십시오. 자리가 모자라면 **원본을 건드리지 않고** 실패를 알려야 합니다.

**정답 및 해설**

```c
int safe_append(char *dst, size_t dstsize, const char *src)
{
    size_t dlen = strlen(dst);
    size_t slen = strlen(src);

    if (dlen + slen + 1 > dstsize)      /* '\0' 자리까지 고려 */
        return 0;
    memcpy(dst + dlen, src, slen + 1);  /* 끝 표시까지 함께 복사 */
    return 1;
}
```

```text
시작: "hello"
", world" 붙이기 = 성공 -> "hello, world"
" and more" 붙이기 = 실패 -> "hello, world"
```

- **검사를 먼저, 복사는 나중에** 합니다. 이 순서 덕분에 실패해도 원본이 온전합니다.
- `dlen + slen + 1`에서 `+1`이 끝 표시 자리입니다.
- `memcpy`에 `slen + 1`을 넘겨 **`'\0'`까지 복사**했습니다. 이 `+1`을 빠뜨리면 끝 표시가 없는 문자열이 됩니다.
- `dlen + slen`이 넘칠 만큼 큰 값이라면 이 검사도 무력해집니다. 실무에서는 각 길이도 함께 제한합니다(5.2절).

### 문제 3. 넘침을 검사하는 사칙연산

두 정수를 더하거나 곱할 때 **넘침을 검사**하는 함수를 만드십시오.

**정답 및 해설**

```c
/* 넘침을 검사하며 더한다. 성공하면 1 */
int add_checked(int a, int b, int *out)
{
    if (b > 0 && a > INT_MAX - b)      /* a + b 가 INT_MAX 를 넘는가 */
        return 0;
    if (b < 0 && a < INT_MIN - b)      /* a + b 가 INT_MIN 보다 작은가 */
        return 0;
    *out = a + b;
    return 1;
}

/* 넘침을 검사하며 곱한다 */
int mul_checked(int a, int b, int *out)
{
    long long r = (long long) a * b;   /* 더 넓은 자료형으로 계산해 확인 */

    if (r > INT_MAX || r < INT_MIN)
        return 0;
    *out = (int) r;
    return 1;
}
```

```text
2 + 3            = 성공 (5)
INT_MAX + 1      = 넘침을 막았습니다
100000 * 100000  = 넘침을 막았습니다
1000 * 1000      = 성공 (1000000)
```

- **더하기 전에 검사해야 합니다.** `if (a + b > INT_MAX)`라고 쓰면 이미 넘친 뒤이며, 그 자체가 미정의 동작입니다.
- 그래서 **이항하여** `a > INT_MAX - b` 형태로 검사합니다.
- 곱하기는 **더 넓은 자료형(`long long`)으로 계산해 확인**하는 방법이 간단합니다. 다만 `long long`끼리의 곱에는 이 방법을 쓸 수 없으므로 그때는 나눗셈으로 검사합니다(5.2절).
- `(long long) a * b`에서 **캐스트를 앞에 붙인 것**이 중요합니다. `(long long)(a * b)`라고 쓰면 이미 `int`로 곱한 뒤라 소용이 없습니다.

### 문제 4. 실패 경로의 메모리 정리

여러 문자열을 복사해 배열에 담는 함수를 만들되, **도중에 실패하면 지금까지 빌린 것을 모두 반납**하도록 하십시오.

**정답 및 해설**

```c
    for (i = 0; i < n; i++) {
        out[i] = (char *) malloc(strlen(src[i]) + 1);
        if (out[i] == NULL) {              /* 도중에 실패하면 */

```

```text
copy[0] = alpha
copy[1] = beta
copy[2] = gamma
```

### 문제 5. `strtol`로 입력 검증

`"42"`, `"42abc"`, `"abc"`, `"999999999999999999999"`, `"200"`(0~150 범위)을 각각 넣어 보고 결과를 표로 정리하십시오.

**정답 및 해설**

8.2절의 `parse_int`를 사용합니다.

| 입력 | `strtol`의 반응 | `parse_int` 결과 |
|---|---|---|
| `"42"` | 정상 변환, `*end == '\0'` | **성공**, 42 |
| `"42abc"` | 42를 읽고 `end`가 `"abc"`를 가리킴 | **실패**(뒤에 글자가 남음) |

- 마지막 항목이 보여 주듯 **"변환에 성공했다"와 "쓸 수 있는 값이다"는 다릅니다.** 범위 검사는 별도로 해야 합니다(8.1절).

### 문제 6. 배열 접근 검사

첨자를 검사하는 접근 함수를 만들고, **음수 첨자도 막히는지** 확인하십시오.

**정답 및 해설**

```c
static int get_at(const int a[], int n, int i, int *ok)
{
    if (i < 0 || i >= n) {
        *ok = 0;
        return 0;
    }
    *ok = 1;
    return a[i];
}
```

```text
a[-1] : 범위를 벗어난 접근을 막았습니다
a[ 0] = 10
...
a[ 5] : 범위를 벗어난 접근을 막았습니다
```

- **`i < 0` 검사가 핵심입니다.** 상한만 검사하는 코드가 매우 흔한데, 사용자 입력에서 온 첨자는 음수일 수 있습니다.
- 첨자를 `size_t`로 받으면 음수가 **거대한 양수**가 되어 상한 검사에 걸립니다. 다만 그 전에 **음수를 `size_t`로 바꾸는 과정 자체가 사고**이므로, `int`로 받아 명시적으로 검사하는 편이 안전합니다.
- 이 방식은 배열을 다루는 코드를 **한 곳으로 모으는** 효과도 있습니다. 검사 규칙을 바꿀 때 그 함수만 고치면 됩니다.

### 문제 7. `strncpy` 함정 확인

`strncpy`로 8칸 배열에 11자를 복사한 뒤 배열 내용을 한 글자씩 출력하여, **끝 표시가 없음**을 눈으로 확인하십시오.

**정답 및 해설**

```c
    memset(dst, '#', sizeof dst);          /* 눈에 보이게 채워 둔다 */
    strncpy(dst, src, sizeof dst);

    printf("strncpy 뒤 배열 내용: ");
    for (i = 0; i < sizeof dst; i++)
        printf("%c", dst[i]);
    printf("\n");
```

```text
strncpy 뒤 배열 내용: programm
-> '\0' 이 없으므로 이 배열을 문자열로 쓰면 안 된다
고친 뒤: "program" (길이 7)
snprintf: "program"
```

- 8칸이 **모두 글자로 채워졌습니다.** `#`이 하나도 남지 않은 것이 그 증거입니다.
- 이 상태에서 `%s`로 출력하면 `'\0'`을 만날 때까지 **옆 메모리를 계속 읽습니다.** 운이 좋으면 쓰레기가 출력되고, 나쁘면 프로그램이 죽거나 **남의 자료가 노출**됩니다.
- 반대로 **원본이 짧으면** `strncpy`는 남은 칸을 모두 `'\0'`으로 채웁니다. 큰 배열에서는 그만큼 시간이 낭비됩니다. 여러모로 `snprintf`가 낫습니다.

### 문제 8. 자를 것인가 거부할 것인가

다음 각 경우에 **자르기와 거부하기 중 무엇이 옳은지** 판단하고 이유를 쓰십시오.

1. 화면에 표시할 게시글 제목(30자 제한)
2. 로그인 계정 이름(16자 제한)

### 문제 9. 경고 옵션으로 결함 찾기

다음 프로그램을 `-Wall -Wextra`로 컴파일하여 경고를 확인하고, 경고가 가리키는 실제 문제를 설명하십시오.

```c
int len = -1;
char buf[8];

if (len < sizeof buf)
    printf("복사해도 됩니다\n");
```

**정답 및 해설**

```text
warning: comparison of integer expressions of different signedness: 'int' and 'unsigned long long' [-Wsign-compare]
```

- `sizeof`의 결과는 **부호 없는 자료형**입니다. 그래서 `len`이 **부호 없는 값으로 변환**되고, `-1`은 아주 큰 양수(`18446744073709551615`)가 됩니다.
- 결과적으로 조건은 **거짓**이 되어, 이 예에서는 우연히 안전합니다. 그러나 부등호가 반대였다면 **음수 길이가 검사를 통과**해 그대로 넘치는 사고가 됩니다.
- 5.1절에서 실행 결과로 확인한 `-1 < 1u` 가 **0(거짓)** 이었던 것과 같은 현상입니다.
- **해결**: 길이를 `size_t`로 다루고, 음수가 될 수 있는 값은 **부호 있는 자료형에서 먼저 검사**한 뒤 변환합니다.

```c
size_t len;      /* 크기는 size_t 로 */
...
if (len < sizeof buf)
```

### 문제 10. 점검 목록으로 자기 코드 감사

**8강 또는 9강에서 자신이 제출했던 프로그램 하나**를 골라 제10절의 점검 목록으로 검사하고, 발견한 문제와 고친 내용을 표로 정리하십시오.

**정답 및 해설**

정답이 정해진 문제가 아니라 **실제로 해 보는 것**이 목적입니다. 흔히 나오는 결과는 다음과 같습니다.

| 자주 발견되는 문제 | 고침 |
|---|---|
| `fgets` 뒤 개행 처리를 안 함 | 길이 확인 후 `'\0'` 대입 |
| `fopen` 결과를 검사하지 않음 | `NULL` 검사와 `stderr` 메시지 추가 |
| `malloc` 후 `free` 누락 | 종료 경로마다 반납 |
| 배열 크기를 숫자로 직접 적음 | `sizeof`로 대체 |
| 오류 메시지를 `printf`로 출력 | `fprintf(stderr, ...)` |
| 경고를 무시하고 넘어감 | `-Wall -Wextra` 경고 0개로 |

> **이 감사를 습관으로 만드십시오.** 코드를 다 짠 뒤 10분간 목록을 훑는 것만으로 대부분의 사고를 막을 수 있습니다. 실무에서는 이 과정을 **코드 리뷰**라고 부릅니다.

## 정리

| 구분 | 핵심 |
|---|---|
| 근본 원인 | C는 **검사하지 않는다**. 미정의 동작은 "지금은 잘 돌아가는" 것이 가장 위험하다 |
| 신뢰 경계 | 바깥에서 온 값은 **적대적일 수 있다고 가정**한다 |
| 버퍼 오버플로 | 옆 값 오염 → 돌아갈 주소 탈취 → 정보 노출. **경계 검사만이 근본 대책** |
| 위험 함수 | `gets`·`strcpy`·`sprintf`·`scanf("%s")`·`printf(s)` |
| 기본 무기 | **`fgets`·`snprintf`·`strtol`**, 그리고 `sizeof` |
| `strncpy` | 이름과 달리 안전하지 않다. **끝 표시를 붙이지 않을 수 있다** |
| 정수 | 부호 있는 넘침은 미정의, 부호 혼용 비교는 검사를 무력화, 곱셈은 **나눗셈으로 미리 검사** |
| 메모리 | `NULL` 검사 → 사용 → `free` → `NULL` 대입. 실패 경로도 정리 |
| 형식 문자열 | 형식 자리에는 **상수만** |
| 판단 | 결정에 쓰이는 값은 **자르지 말고 거부** |
| 도구 | `-Wall -Wextra -Wconversion`, 위생 검사기, 정적 분석 |

C 언어의 문법을 배우는 것과 **믿을 수 있는 C 프로그램을 쓰는 것**은 다른 일입니다. 이번 강의의 규칙들은 외워야 할 목록이라기보다, **"이 값의 크기를 나는 알고 있는가"** 라는 한 가지 질문을 여러 상황에 적용한 것입니다.

**다음 11강에서는 라이브러리 만들기와 빌드 자동화**를 다룹니다. 5강에서 파일을 나누는 법을 배웠으니, 이제 그것을 **다시 쓸 수 있는 부품(라이브러리)** 으로 묶고, `Makefile`로 빌드를 자동화합니다. 남이 만든 라이브러리를 가져다 쓰는 방법도 함께 익힙니다.

## 부록 A. 위험 함수 → 안전한 대체 (한 장 요약)

| 하려는 일 | 쓰지 말 것 | 쓸 것 |
|---|---|---|
| 한 줄 읽기 | `gets(s)` | `fgets(s, sizeof s, stdin)` |
| 문자열 복사 | `strcpy(d, s)` | 길이 검사 후 복사 / `snprintf(d, sizeof d, "%s", s)` |
| 문자열 잇기 | `strcat(d, s)` | 남은 자리 검사 후 / `snprintf` |
| 문자열 만들기 | `sprintf(buf, ...)` | `snprintf(buf, sizeof buf, ...)` |
| 문자열 입력 | `scanf("%s", buf)` | `fgets` + `sscanf`, 또는 `%31s` |
| 문자열 출력 | `printf(s)` | `printf("%s", s)` |
| 숫자 변환 | `atoi(s)` | `strtol` + 네 가지 검사 |
| 부분 복사 | `strncpy` 단독 | `snprintf`, 또는 `strncpy` 후 끝 표시 |
