## 제1절. 프로그램의 구조 다시 읽기

### 1.1 C 프로그램은 함수와 변수로 이루어진다

C 프로그램은 그 규모가 여섯 줄이든 육십만 줄이든 **오직 두 가지**로 이루어집니다.

| 구성 요소 | 하는 일 |
|---|---|
| **함수(function)** | 수행할 동작(문장)을 적어 둔 묶음 |
| **변수(variable)** | 계산 도중에 쓰이는 값을 담아 두는 저장 공간 |

1강의 `hello.c`에는 함수 `main` 하나만 있고 변수는 없었습니다. 이번 강의에서 여기에 변수를 더해 나갑니다.

### 1.2 첫 프로그램 해부

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, World!\n");
    return 0;
}
```

원서는 이 프로그램의 각 줄에 주석을 달아 설명합니다. 같은 방식으로 정리하면 다음과 같습니다.

| 코드 | 의미 |
|---|---|
| `#include <stdio.h>` | 표준 입출력 라이브러리의 정보를 가져온다 |
| `int main(void)` | `main`이라는 이름의 함수를 정의한다. 건네받는 값은 없다(`void`) |
| `{` | `main`이 수행할 문장들의 시작 |
| `    printf("Hello, World!\n");` | 라이브러리 함수 `printf`를 호출하여 문자열을 출력한다 |
| `    return 0;` | 정상 종료임을 운영체제에 알린다 |
| `}` | `main`의 끝 |

여기서 반드시 기억할 점이 네 가지 있습니다.

- **`main`은 특별한 이름입니다.** 함수 이름은 마음대로 지을 수 있으나 `main`만은 예외로, 프로그램은 **언제나 `main`의 첫 문장부터** 실행됩니다. 따라서 모든 C 프로그램에는 `main`이 반드시 하나 있어야 합니다.
- **함수는 다른 함수를 호출합니다.** `main`은 혼자 일하지 않고 다른 함수를 불러 일을 시킵니다. `printf`가 그 예이며, 우리가 만든 것이 아니라 **이미 제공되는 라이브러리 함수**입니다.
- **괄호 안은 인자 목록입니다.** 함수에 건네주는 값들을 **인자(argument)** 라고 하며, `printf("Hello, World!\n")`에서 문자열이 곧 인자입니다.
- **큰따옴표로 묶인 글자들의 나열**을 **문자열 상수(character string constant)** 라고 합니다.

> **`printf`는 C 언어의 일부가 아닙니다.**
> C 언어 자체에는 입출력 기능이 **없습니다.** 화면에 무엇을 찍는 일은 문법이 아니라 별도로 제공되는 **표준 라이브러리**의 함수가 담당합니다. 그래서 `#include <stdio.h>`로 그 정보를 먼저 가져와야 합니다.
> 이는 C가 작고 단순한 언어로 설계되었기 때문입니다. 언어는 계산과 흐름 제어만 맡고 나머지는 라이브러리에 넘깁니다. 덕분에 C는 운영체제부터 세탁기 제어기까지 어디에나 이식될 수 있었습니다.
{: .prompt-info }

### 1.3 확인 실험 — `printf`를 쪼개어 보기

`printf`는 **우리가 시키지 않으면 절대로 줄을 바꾸지 않습니다.** 따라서 출력을 여러 번에 나누어 조립할 수 있습니다. `lab02` 폴더에 `split.c`를 만들어 확인합니다.

```c
#include <stdio.h>

int main(void)
{
    printf("Hello, ");
    printf("World");
    printf("!");
    printf("\n");
    return 0;
}
```

```powershell
gcc -Wall -Wextra -std=c17 split.c -o split.exe
```

```powershell
.\split.exe
```

```text
Hello, World!
```

네 번 호출했으나 결과는 한 줄입니다. **줄이 바뀌는 것은 오직 `\n` 때문**이며 함수 호출이 끝났기 때문이 아닙니다.

### 1.4 이스케이프 시퀀스

`\n`은 `\`와 `n` 두 글자처럼 보이지만 **실제로는 한 글자**입니다. 이처럼 키보드로 직접 칠 수 없거나 특별한 의미를 가진 글자를 표현하는 표기를 **이스케이프 시퀀스(escape sequence)** 라고 합니다.

| 표기 | 뜻 |
|---|---|
| `\n` | 줄 바꿈(newline) |
| `\t` | 탭(tab) |
| `\b` | 백스페이스 |
| `\r` | 캐리지 리턴 |
| `\"` | 큰따옴표 자체 |
| `\\` | 역슬래시 자체 |
| `\a` | 경고음(bell) |

전체 목록과 8진·16진 표기는 **3강**에서 다룹니다.

## 제2절. 변수와 산술식

### 2.1 변수란 이름을 붙인 메모리 상자입니다

컴퓨터의 메모리는 번호가 매겨진 거대한 사물함과 같습니다. 사람이 `0x7ffd3a1c` 같은 번호를 외워 가며 프로그램을 짤 수는 없으므로 사물함에 **이름을 붙여** 사용합니다. 그 이름이 **변수**입니다.

```c
int fahr;
```

이 한 줄을 **선언(declaration)** 이라고 하며 컴파일러에게 두 가지를 알립니다.

1. `fahr`라는 이름의 상자를 마련하라.
2. 그 상자에는 **정수(`int`)** 를 담겠다.

값을 넣는 일은 **대입(assignment)** 입니다.

```c
fahr = 100;
```

여기서 `=`는 수학의 "같다"가 **아니라** "오른쪽 값을 왼쪽 상자에 넣어라"는 명령입니다. 그래서 다음 문장이 성립합니다.

```c
fahr = fahr + 20;
```

수학이라면 성립할 수 없지만, C에서는 "지금 `fahr`에 든 값에 20을 더해 다시 `fahr`에 넣어라"는 자연스러운 명령입니다. **오른쪽을 먼저 계산하고 그 결과를 왼쪽에 넣는다** — 이 순서를 기억하시기 바랍니다.

> **C에서 모든 변수는 사용하기 전에 반드시 선언하여야 합니다.**
> 선언 없이 이름을 쓰면 `error: 'fahr' undeclared` 오류가 납니다. 번거로워 보이지만 이 규칙 덕분에 오타로 생긴 엉뚱한 변수(`fahr`를 `fhar`로 잘못 친 경우)를 컴파일러가 즉시 잡아 줍니다.
{: .prompt-tip }

### 2.2 기본 자료형

| 자료형 | 담는 값 | Windows 64비트에서의 크기 |
|---|---|---|
| `char` | 문자 한 개(사실상 작은 정수) | 1바이트 |
| `short` | 짧은 정수 | 2바이트 |
| `int` | 정수 | 4바이트 |
| `long` | 긴 정수 | 4바이트(Windows) / 8바이트(리눅스) |
| `long long` | 더 긴 정수 | 8바이트 |
| `float` | 실수(단정밀도) | 4바이트 |
| `double` | 실수(배정밀도) | 8바이트 |

**자료형의 크기는 표준이 못 박아 둔 값이 아니라 컴퓨터와 컴파일러에 따라 달라집니다.** `long`이 윈도우에서 4바이트, 리눅스에서 8바이트인 것이 대표적인 예입니다. 그러므로 크기는 짐작하지 말고 `sizeof`로 확인합니다. `sizes.c`를 만들어 자신의 컴퓨터에서 확인해 보십시오.

```c
#include <stdio.h>

int main(void)
{
    printf("char        : %zu 바이트\n", sizeof(char));
    printf("short       : %zu 바이트\n", sizeof(short));
    printf("int         : %zu 바이트\n", sizeof(int));
    printf("long        : %zu 바이트\n", sizeof(long));
    printf("long long   : %zu 바이트\n", sizeof(long long));
    printf("float       : %zu 바이트\n", sizeof(float));
    printf("double      : %zu 바이트\n", sizeof(double));
    return 0;
}
```

```text
char        : 1 바이트
short       : 2 바이트
int         : 4 바이트
long        : 4 바이트
long long   : 8 바이트
float       : 4 바이트
double      : 8 바이트
```

`sizeof`의 결과는 `size_t`라는 부호 없는 정수형이므로 서식 지정자로 `%zu`를 사용합니다. 각 자료형이 담을 수 있는 **값의 범위**는 3강에서 `<limits.h>`로 직접 조사합니다.

### 2.3 변수 이름 규칙

| 규칙 | 예 |
|---|---|
| 영문자·숫자·밑줄(`_`)만 사용 | `fahr`, `max_value`, `count2` |
| 첫 글자는 숫자가 될 수 없음 | `2nd`(X) → `second`(O) |
| 대문자와 소문자는 다른 글자 | `Fahr` ≠ `fahr` |
| 예약어는 사용 불가 | `int`, `for`, `return` … |
| 밑줄로 시작하지 않기 | `_temp`(권장하지 않음) |

관례적으로 **변수는 소문자, 기호 상수는 대문자**로 씁니다.

### 2.5 첫 번째 계산 프로그램 — 화씨를 섭씨로

화씨 0도부터 300도까지 20도 간격으로 섭씨 온도를 함께 출력하는 표를 만듭니다.

> 섭씨 = (5 / 9) × (화씨 − 32)

`temp1.c`입니다.

```c
#include <stdio.h>

/* 화씨-섭씨 대응표를 출력한다 (화씨 0, 20, ..., 300) */
int main(void)
{
    int fahr, celsius;
    int lower, upper, step;

    lower = 0;      /* 표의 시작 온도 */
    upper = 300;    /* 표의 끝 온도   */
    step  = 20;     /* 온도 간격      */

    fahr = lower;
    while (fahr <= upper) {
        celsius = 5 * (fahr - 32) / 9;
        printf("%d\t%d\n", fahr, celsius);
        fahr = fahr + step;
    }

    return 0;
}
```

```text
300     148
```

한 번의 실행으로 16줄이 나왔습니다. **같은 계산을 열여섯 번 되풀이하는 일을 컴퓨터에 넘긴 것**, 이것이 프로그래밍의 본질입니다.

### 2.6 `while` 문의 동작

```c
while (fahr <= upper) {
    ...
}
```

| 단계 | 동작 |
|---|---|
| 1 | 괄호 안의 조건을 검사한다 |
| 2 | 참이면 중괄호 안의 문장들(몸통)을 처음부터 끝까지 실행한다 |
| 3 | 몸통이 끝나면 **다시 1번으로** 돌아간다 |
| 4 | 거짓이면 반복을 끝내고 중괄호 다음 문장으로 넘어간다 |

`fahr`가 320이 되는 순간 `fahr <= 300`이 거짓이 되어 반복이 끝납니다.

**`fahr = fahr + step;`이 몸통 안에 있어야 한다**는 점에 주의하십시오. 빠뜨리면 `fahr`가 영원히 0이므로 같은 줄을 무한히 출력합니다. 이런 상황을 **무한 루프**라 하며 `Ctrl+C`로 중단할 수 있습니다.

몸통이 문장 하나뿐이면 중괄호를 생략할 수 있습니다.

```c
while (i < j)
    i = 2 * i;
```

다만 처음에는 **항상 중괄호를 쓰는 편**을 권합니다. 나중에 문장을 하나 더 넣을 때 중괄호를 잊으면 조용히 잘못 동작하기 때문입니다.

컴파일러는 공백과 줄바꿈을 무시하므로 들여쓰기를 하지 않아도 동작합니다. 그러나 **들여쓰기는 컴파일러가 아니라 사람을 위한 것**이며, 무엇이 반복 안에 있는지 한눈에 보여 줍니다. 한 줄에 한 문장, 몸통은 공백 4칸 들여쓰기를 습관으로 삼으시기 바랍니다. VS Code에서 `Shift+Alt+F`를 누르면 자동 정렬됩니다.

### 2.7 `printf`의 서식 지정자

```c
printf("%d\t%d\n", fahr, celsius);
```

`printf`의 **첫 번째 인자는 언제나 출력 형식을 적은 문자열**이며, `%`로 시작하는 부분이 **서식 지정자**입니다. 뒤에 오는 인자들과 **순서대로 짝**을 이룹니다.

| 서식 문자열 | `"%d\t%d\n"` |
|---|---|
| 첫 번째 `%d` ← | 두 번째 인자 `fahr` |
| 두 번째 `%d` ← | 세 번째 인자 `celsius` |

> **서식 지정자와 인자는 개수와 자료형이 정확히 맞아야 합니다.**
> 어긋나면 컴파일은 통과하더라도 **엉뚱한 값이 출력되거나 프로그램이 비정상 종료**합니다. `-Wall`을 켜 두면 `warning: format '%d' expects argument of type 'int'` 같은 경고로 미리 알려 줍니다.
{: .prompt-danger }

## 제3절. 정수 나눗셈의 함정과 출력 서식

### 3.1 왜 `5 * (fahr - 32) / 9`인가

공식은 `(5 / 9) × (화씨 − 32)`인데 프로그램에서는 **먼저 5를 곱하고 나중에 9로 나누었습니다.** `divtest.c`로 이유를 확인합니다.

```c
#include <stdio.h>

int main(void)
{
    printf("5 / 9   = %d\n", 5 / 9);
    printf("9 / 5   = %d\n", 9 / 5);
    printf("7 / 2   = %d\n", 7 / 2);
    printf("-7 / 2  = %d\n", -7 / 2);
    printf("7 %% 2   = %d\n", 7 % 2);
    return 0;
}
```

```text
5 / 9   = 0
9 / 5   = 1
7 / 2   = 3
-7 / 2  = -3
7 % 2   = 1
```

**핵심은 첫 줄입니다.** `5 / 9`가 `0.555…`가 아니라 **`0`** 입니다.

C에서 `/`의 양쪽이 모두 정수이면 **정수 나눗셈**이 되어 소수 부분을 그냥 **버립니다.** 이를 **절단(truncation)** 이라 하며 반올림이 아닙니다. `7 / 2`는 4가 아니라 **3**입니다.

공식을 그대로 옮겨 `celsius = 5 / 9 * (fahr - 32);` 라고 적었다면 `5 / 9`가 먼저 0이 되어 **모든 섭씨온도가 0**으로 나옵니다. 곱셈을 먼저 하여 분자를 크게 만든 뒤 나누어야 의미 있는 값이 남습니다.

> `%`는 **나머지 연산자**이며 `7 % 2`는 1입니다. `printf` 문자열 안에서 퍼센트 기호 자체를 출력하려면 `%%`라고 두 번 적습니다.
{: .prompt-info }

### 3.2 실수로 계산하기

절단은 피했지만 여전히 정확하지 않습니다. 화씨 0도의 섭씨는 실제로 **−17.8도**인데 표에는 **−17**로 나와 있습니다. `celsius`가 `int`이므로 소수점 이하를 담을 자리가 없기 때문입니다. `temp2.c`로 고칩니다.

```c
#include <stdio.h>

/* 화씨-섭씨 대응표 (실수 계산 버전) */
int main(void)
{
    float fahr, celsius;
    float lower, upper, step;

    lower = 0.0;
    upper = 300.0;
    step  = 20.0;

    fahr = lower;
    while (fahr <= upper) {
        celsius = (5.0 / 9.0) * (fahr - 32.0);
        printf("%3.0f %6.1f\n", fahr, celsius);
        fahr = fahr + step;
    }

    return 0;
}
```

```text
  0  -17.8
 20   -6.7
 40    4.4
 60   15.6
 80   26.7
100   37.8
120   48.9
140   60.0
160   71.1
180   82.2
200   93.3
220  104.4
240  115.6
260  126.7
280  137.8
300  148.9
```

바뀐 점은 세 가지입니다.

1. 자료형을 `int`에서 `float`로 바꾸었다.
2. 상수에 **소수점을 찍었다.** `5.0 / 9.0`은 실수 나눗셈이므로 `0.5555…`가 그대로 남는다. 이제 공식을 원래 순서대로 적어도 된다.
3. 서식 지정자를 `%d`에서 `%f` 계열로 바꾸었다. **실수를 `%d`로 출력하면 완전히 엉뚱한 값**이 나오므로 반드시 함께 바꾸어야 한다.

### 3.3 정수와 실수가 섞이면

`(fahr - 32.0)`에서 `32.0` 대신 `32`라고 적어도 결과는 같습니다. C는 **한쪽이 실수이면 다른 쪽 정수를 실수로 자동 변환**한 뒤 계산하기 때문입니다.

| 식 | 실제 연산 | 결과 |
|---|---|---|
| `5 / 9` | 정수 ÷ 정수 | `0` |
| `5.0 / 9` | 실수 ÷ (변환된 실수) | `0.5555…` |
| `5 / 9.0` | (변환된 실수) ÷ 실수 | `0.5555…` |
| `5.0 / 9.0` | 실수 ÷ 실수 | `0.5555…` |

한쪽만 실수로 적어도 충분하지만, 양쪽에 소수점을 찍는 편이 의도가 분명히 드러납니다. 변환 규칙은 3강에서 정확히 다룹니다.

> **가장 흔한 초심자 버그**
> ```c
> float average;
> average = 7 / 2;      /* 3.0 이 된다. 3.5 가 아니다! */
> ```
> 왼쪽이 실수형이면 오른쪽도 실수로 계산될 것 같지만 그렇지 않습니다. **오른쪽 식이 먼저 정수끼리 계산되어 3이 되고**, 그 3이 3.0으로 변환되어 대입될 뿐입니다. 올바른 코드는 `average = 7.0 / 2;` 입니다.
{: .prompt-danger }

### 3.4 폭과 정밀도

첫 버전의 출력은 자릿수가 제각각이어서 표처럼 보이지 않았습니다. 서식 지정자에 **폭(width)** 을 지정하면 오른쪽 정렬됩니다.

```c
printf("%3d %6d\n", fahr, celsius);
```

`%3d`는 "정수를 최소 세 칸 폭으로"라는 뜻입니다. 값이 짧으면 앞을 공백으로 채우고, 길면 폭을 무시하고 전체를 출력합니다. 즉 폭은 **최소 보장 폭**입니다.

실수에는 소수점 이하 자릿수, 즉 **정밀도(precision)** 를 함께 지정합니다.

| 서식 | 의미 | `-17.777…`의 출력 |
|---|---|---|
| `%d` | 10진 정수 | (실수에 쓰면 **잘못된 값**) |
| `%f` | 실수(기본 소수점 이하 6자리) | `-17.777778` |
| `%.1f` | 소수점 이하 1자리 | `-17.8` |
| `%6.1f` | 최소 6칸, 소수점 이하 1자리 | `  -17.8` |
| `%.0f` | 소수점 이하 없음 | `-18` |
| `%-6.1f` | 6칸 폭, **왼쪽 정렬** | `-17.8  ` |

자주 쓰는 변환 문자는 다음과 같습니다.

| 서식 | 대상 |
|---|---|
| `%d` | 10진 정수 |
| `%f` | 실수 |
| `%c` | 문자 한 개 |
| `%s` | 문자열 |
| `%o` / `%x` | 8진수 / 16진수 |
| `%ld` / `%lld` | `long` / `long long` |
| `%zu` | `size_t` |
| `%%` | 퍼센트 기호 자체 |

> 정밀도를 줄이는 것은 **출력 형식만 바꾸는 것**이며 저장된 값이 반올림되어 바뀌는 것은 아닙니다.
{: .prompt-info }

## 제4절. `for` 문

### 4.1 반복을 한자리에 모으기

`temp3.c`입니다.

```c
#include <stdio.h>

/* 화씨-섭씨 대응표 (for 문 버전) */
int main(void)
{
    int fahr;

    for (fahr = 0; fahr <= 300; fahr = fahr + 20) {
        printf("%3d %6.1f\n", fahr, (5.0 / 9.0) * (fahr - 32));
    }

    return 0;
}
```

출력은 같지만 프로그램이 눈에 띄게 짧아졌습니다. 변수가 `fahr` 하나만 남았고, `lower`·`upper`·`step`은 `for` 문 안의 상수로 흡수되었으며, 섭씨 계산이 별도의 대입문 없이 **`printf`의 인자 자리에서 직접** 이루어졌습니다. 이는 C의 일반 규칙 덕분입니다. **어떤 자료형의 값을 쓸 수 있는 자리에는 그 자료형의 값을 만들어 내는 식(expression)을 그대로 쓸 수 있습니다.**

### 4.2 `for` 문의 세 부분

```c
for (초기화; 조건; 증감)
    반복할 문장
```

| 부분 | 실행 시점 | 예 |
|---|---|---|
| 초기화 | 반복 시작 전 **한 번만** | `fahr = 0` |
| 조건 | 매 반복 **직전**, 거짓이면 종료 | `fahr <= 300` |
| 증감 | 몸통을 한 번 실행한 **직후** | `fahr = fahr + 20` |

> 초기화 → **조건 검사** → (참) 몸통 → 증감 → **조건 검사** → (참) 몸통 → 증감 → … → (거짓) 종료

`while`과 `for`는 서로 바꾸어 쓸 수 있습니다.

**`while`로 쓴 경우**

```c
fahr = 0;                       /* 초기화 */
while (fahr <= 300) {           /* 조건   */
    ...
    fahr = fahr + 20;           /* 증감   */
}
```

**같은 반복을 `for`로 쓴 경우**

```c
for (fahr = 0; fahr <= 300; fahr = fahr + 20) {
    ...
}
```

**어느 쪽을 쓸 것인가**는 무엇이 더 읽기 쉬운가로 정합니다. 반복 횟수가 정해져 있고 초기화·증감이 단순하면 `for`가 세 요소를 한자리에 모아 주므로 유리합니다. 반대로 "조건이 만족될 때까지"처럼 횟수를 미리 알 수 없는 반복은 `while`이 자연스럽습니다. 제6절의 문자 입력 처리가 후자의 대표적인 예입니다.

> **`for` 문 뒤에 세미콜론을 찍지 마십시오.**
> ```c
> for (fahr = 0; fahr <= 300; fahr = fahr + 20);   /* ← 이 세미콜론! */
>     printf("%d\n", fahr);
> ```
> 문법 오류가 아니어서 컴파일은 되지만, 세미콜론 하나가 **아무 일도 하지 않는 빈 문장**이 되어 반복 몸통을 차지합니다. 결국 반복은 아무것도 하지 않고 끝나며 `printf`는 한 번만 실행됩니다.
{: .prompt-danger }

## 제5절. 기호 상수 `#define`

### 5.1 매직 넘버 문제

```c
for (fahr = 0; fahr <= 300; fahr = fahr + 20)
```

여기서 `0`, `300`, `20`은 무엇을 뜻할까요? 방금 작성했으니 알지만 몇 달 뒤에는 짐작하기 어렵습니다. 이렇게 **코드에 그냥 박혀 있는, 의미를 알 수 없는 숫자**를 **매직 넘버(magic number)** 라 하며 좋지 않은 습관으로 봅니다. 해결책은 **이름을 붙여 주는 것**입니다.

### 5.2 `#define`

```c
#define 이름 대체할내용
```

`#define`이 있는 소스는 **컴파일 이전에** 전처리기가 훑으면서 `이름`이 나오는 자리를 모두 `대체할내용`으로 바꿉니다. 1강에서 배운 컴파일 4단계 중 **1단계 전처리**가 하는 일입니다.

최종 버전 `temp4.c`입니다.

```c
#include <stdio.h>

#define LOWER  0     /* 표의 시작 온도 */
#define UPPER  300   /* 표의 끝 온도   */
#define STEP   20    /* 온도 간격      */

/* 화씨-섭씨 대응표 (기호 상수 버전) */
int main(void)
{
    int fahr;

    printf("화씨   섭씨\n");
    printf("-----------\n");

    for (fahr = LOWER; fahr <= UPPER; fahr = fahr + STEP) {
        printf("%3d %6.1f\n", fahr, (5.0 / 9.0) * (fahr - 32));
    }

    return 0;
}
```

이제 표의 범위를 바꾸려면 **맨 위 세 줄만** 고치면 됩니다.

| 주의 | 설명 |
|---|---|
| 끝에 세미콜론을 붙이지 않는다 | `#define UPPER 300;` 은 `300;`이 통째로 치환되어 이상한 오류를 낸다 |
| `=` 를 쓰지 않는다 | `#define UPPER = 300`(X) |
| 대문자로 쓴다 | 변수와 구별하기 위한 오랜 관례 |
| 변수가 아니다 | 선언문에 나타나지 않으며 값을 대입할 수도 없다. 단순한 **글자 치환**이다 |

> **현대 C의 대안 — `const`**
> ```c
> const int UPPER = 300;
> ```
> `const` 변수는 값을 바꿀 수 없는 상수이며, `#define`과 달리 **자료형을 가지므로 컴파일러의 검사를 받습니다.** 두 가지 모두 널리 쓰이므로 함께 알아 두어야 합니다. 자세한 내용은 3강에서 다룹니다.
{: .prompt-tip }

## 제6절. 문자 입출력 — `getchar`·`putchar`·`EOF`

여기서부터가 이번 강의의 핵심입니다. 지금까지의 프로그램은 **미리 정해진 값**만 다루었습니다. 이제 **바깥에서 들어오는 자료**를 처리합니다.

### 6.1 텍스트 스트림

표준 라이브러리가 제공하는 입출력 모형은 대단히 단순합니다. 자료가 키보드에서 오든 파일에서 오든, 프로그램은 그것을 **문자들이 한 줄로 늘어선 흐름**으로 봅니다. 이를 **텍스트 스트림(text stream)** 이라 합니다.

- 텍스트 스트림은 **줄(line)** 들로 나뉩니다.
- 각 줄은 0개 이상의 문자 뒤에 **개행 문자(`\n`)** 가 붙은 형태입니다.
- 자료가 실제로 디스크에 어떻게 저장되어 있는지는 **라이브러리가 알아서 처리**하므로 우리는 신경 쓰지 않아도 됩니다.

### 6.2 두 개의 함수

| 함수 | 하는 일 |
|---|---|
| `getchar()` | 입력에서 **다음 문자 한 개**를 읽어 그 값을 돌려준다 |
| `putchar(c)` | 문자 한 개를 출력한다 |

이 둘만으로도 놀랄 만큼 쓸모 있는 프로그램을 만들 수 있습니다.

### 6.3 첫 번째 프로그램 — 입력을 그대로 복사하기

하려는 일을 우리말로 적으면 다음과 같습니다.

```text
문자 하나를 읽는다
    입력이 끝났다는 표시가 아닌 동안
        방금 읽은 문자를 출력한다
        문자 하나를 읽는다
```

이것을 C로 옮긴 것이 `copy1.c`입니다.

```c
#include <stdio.h>

/* 입력을 출력으로 그대로 복사한다 (1차 버전) */
int main(void)
{
    int c;

    c = getchar();
    while (c != EOF) {
        putchar(c);
        c = getchar();
    }
    return 0;
}
```

`!=`는 **"같지 않다"** 를 뜻하는 관계 연산자입니다.

### 6.5 왜 `char`가 아니라 `int`인가

여기에 이번 강의에서 가장 중요한 개념 하나가 숨어 있습니다.

`getchar`는 더 읽을 것이 없을 때 **어떤 실제 문자와도 겹치지 않는 특별한 값**을 돌려주어야 합니다. 그 값이 **`EOF`(end of file)** 이며 `<stdio.h>`에 정의되어 있습니다. `eofval.c`로 확인해 보십시오.

```c
#include <stdio.h>

int main(void)
{
    printf("EOF = %d\n", EOF);
    printf("sizeof(char) = %zu, sizeof(int) = %zu\n", sizeof(char), sizeof(int));
    return 0;
}
```

```text
EOF = -1
sizeof(char) = 1, sizeof(int) = 4
```

`EOF`는 대개 `-1`입니다. **`char`는 1바이트뿐이므로 모든 문자와 `EOF`를 함께 담기에는 자리가 모자랍니다.** 그래서 `getchar`의 결과를 받는 변수는 반드시 **`int`** 로 선언하여야 합니다.

> `char c;` 로 선언하면 컴파일은 되지만, 어떤 환경에서는 `EOF`와 특정 문자를 구분하지 못해 **입력이 끝나지 않거나 도중에 멈추는** 버그가 생깁니다. `EOF`의 실제 값이 `-1`이라는 사실에 코드가 의존하지 않도록 **반드시 기호 상수 `EOF`로 비교**하십시오.
{: .prompt-danger }

### 6.6 더 간결한 판 — 대입도 값을 가진다

숙련된 C 프로그래머는 같은 프로그램을 이렇게 씁니다. `copy2.c`입니다.

```c
#include <stdio.h>

/* 입력을 출력으로 그대로 복사한다 (2차 버전) */
int main(void)
{
    int c;

    while ((c = getchar()) != EOF)
        putchar(c);
    return 0;
}
```

C에서 **대입(`=`)은 문장이 아니라 식(expression)이며 값을 가집니다.** `c = getchar()`라는 식의 값은 **대입이 끝난 뒤의 `c`의 값**입니다. 따라서 위 코드는 다음을 한 줄에 담은 것입니다.

1. `getchar()`로 문자 하나를 읽어
2. `c`에 넣고
3. 그 값이 `EOF`인지 검사한다

`getchar`가 한 곳에만 등장하므로 프로그램이 짧아지고 실수할 여지도 줄어듭니다. 이 관용구는 C 코드 어디에서나 볼 수 있으므로 눈에 익혀 두어야 합니다.

> **괄호를 빠뜨리면 안 됩니다.**
> `!=`가 `=`보다 **우선순위가 높기** 때문에
> ```c
> while (c = getchar() != EOF)      /* 잘못된 코드 */
> ```
> 는 다음과 같이 해석됩니다.
> ```c
> while (c = (getchar() != EOF))
> ```
> 즉 `c`에는 문자가 아니라 **비교 결과인 0 또는 1**이 들어갑니다. 반드시 `(c = getchar()) != EOF` 처럼 괄호로 묶으십시오.
{: .prompt-danger }

### 6.7 문자 세기

`countchar.c`입니다.

```c
#include <stdio.h>

/* 입력 문자의 개수를 센다 */
int main(void)
{
    long nc;

    nc = 0;
    while (getchar() != EOF)
        ++nc;
    printf("%ld\n", nc);
    return 0;
}
```

```powershell
.\countchar.exe < in.txt
```

```text
28
```

`in.txt`에는 `hello, world`(12자) + 개행, `this is a test`(14자) + 개행이 들어 있으므로 12 + 1 + 14 + 1 = **28**입니다. **개행 문자도 하나의 문자로 세어진다**는 점에 주의하십시오.

여기에 새 연산자 `++`가 나왔습니다. **`++nc`는 `nc = nc + 1`과 같습니다.** 1씩 줄이는 `--`도 있습니다. 전위(`++nc`)와 후위(`nc++`)의 차이는 3강에서 자세히 다룹니다.

문자 수가 매우 많을 수 있으므로 `int`가 아니라 **`long`**을 썼고, 그에 맞추어 서식도 `%ld`로 바꾸었습니다. 더 큰 수를 세려면 `double`을 쓸 수도 있습니다. `countchar2.c`는 `for`로 같은 일을 합니다.

```c
#include <stdio.h>

/* 입력 문자의 개수를 센다 (for 문 + 빈 문장) */
int main(void)
{
    double nc;

    for (nc = 0; getchar() != EOF; ++nc)
        ;
    printf("%.0f\n", nc);
    return 0;
}
```

세는 일이 모두 `for`의 조건과 증감에서 끝나므로 **몸통에 할 일이 없습니다.** 그러나 문법상 몸통이 반드시 있어야 하므로 세미콜론 하나만 둡니다. 이를 **빈 문장(null statement)** 이라 하며, 눈에 잘 띄도록 **별도의 줄에 들여 씁니다.**

> 입력이 아예 비어 있어도 두 프로그램은 **0을 정확히 출력합니다.** `while`과 `for`는 몸통을 실행하기 **전에** 조건을 검사하기 때문입니다. 자료가 하나도 없는 경우에도 올바르게 동작하는 것은 좋은 프로그램의 중요한 성질입니다.
{: .prompt-info }

### 6.8 줄 세기

각 줄이 개행 문자로 끝나므로, **줄을 세는 일은 개행 문자를 세는 일**입니다. `countline.c`입니다.

```c
#include <stdio.h>

/* 입력의 줄 수를 센다 */
int main(void)
{
    int c, nl;

    nl = 0;
    while ((c = getchar()) != EOF)
        if (c == '\n')
            ++nl;
    printf("%d\n", nl);
    return 0;
}
```

```text
2
```

여기에서 두 가지가 새로 나왔습니다.

**(1) `if` 문과 `==`**

`if (조건) 문장` 은 조건이 참일 때만 문장을 실행합니다. **같은지 비교할 때는 `==`를 씁니다.** 대입의 `=`와 혼동하기 쉬우며, `if (c = '\n')` 이라고 잘못 써도 **문법상 옳은 식이므로 오류가 나지 않습니다.** 대신 조건이 언제나 참이 되어 프로그램이 이상하게 동작합니다. C 초심자가 가장 많이 겪는 버그입니다.

**(2) 문자 상수**

`'\n'`처럼 **작은따옴표로 묶은 한 글자**를 **문자 상수(character constant)** 라 하며, 그 값은 문자 집합에서 그 글자에 해당하는 **정수**입니다. `escape_demo.c`로 확인합니다.

```c
#include <stdio.h>

int main(void)
{
    printf("문자 상수 'A' 의 값 = %d\n", 'A');
    printf("문자 상수 '0' 의 값 = %d\n", '0');
    printf("'7' - '0' = %d\n", '7' - '0');
    printf("문자 상수 '\\n' 의 값 = %d\n", '\n');
    return 0;
}
```

```text
문자 상수 'A' 의 값 = 65
문자 상수 '0' 의 값 = 48
'7' - '0' = 7
문자 상수 '\n' 의 값 = 10
```

`'A'`는 ASCII 문자 집합에서 65입니다. 그러나 **코드에 65라고 적지 말고 `'A'`라고 적으십시오.** 뜻이 분명해지고, 문자 집합이 다른 환경에서도 옳게 동작합니다.

> **`'x'` 와 `"x"` 는 완전히 다릅니다.**
> `'x'`는 **정수 하나**(문자 상수)이고, `"x"`는 **문자 두 개짜리 배열**(문자 `x`와 끝 표시 `'\0'`)입니다. 이 구분은 제10절에서 다시 다룹니다.
{: .prompt-warning }

### 6.9 단어 세기 — 상태를 기억하는 프로그램

이제 줄·단어·문자를 한꺼번에 세는 프로그램을 만듭니다. 유닉스의 `wc` 명령을 아주 단순하게 흉내 낸 것입니다. 여기서 **단어**란 공백·탭·개행을 포함하지 않는 문자들의 연속을 뜻합니다.

```c
#include <stdio.h>

#define IN   1   /* 단어 안 */
#define OUT  0   /* 단어 밖 */

/* 입력의 줄·단어·문자 수를 센다 */
int main(void)
{
    int c, nl, nw, nc, state;

    state = OUT;
    nl = nw = nc = 0;
    while ((c = getchar()) != EOF) {
        ++nc;
        if (c == '\n')
            ++nl;
        if (c == ' ' || c == '\n' || c == '\t')
            state = OUT;
        else if (state == OUT) {
            state = IN;
            ++nw;
        }
    }
    printf("%d %d %d\n", nl, nw, nc);
    return 0;
}
```

```powershell
.\wc.exe < in.txt
```

```text
2 6 28
```

줄 2개, 단어 6개(`hello,` `world` `this` `is` `a` `test`), 문자 28개입니다. 다른 입력으로도 확인해 봅니다.

```text
a
bb
ccc dddd
ee
```

```text
4 5 17
```

이 프로그램에는 배울 것이 네 가지 들어 있습니다.

**(1) 상태 변수**

`state`는 **지금 단어 안에 있는지 밖에 있는지**를 기억합니다. 단어의 첫 글자를 만나는 순간(`state`가 `OUT`인데 공백류가 아닌 글자가 나온 순간)에만 단어 수를 1 늘립니다. 이렇게 **직전까지의 상황을 변수에 담아 두고 판단하는 방식**을 상태 기계라 하며, 프로그래밍에서 매우 널리 쓰입니다.

`1`과 `0` 대신 `IN`, `OUT`이라는 이름을 붙인 이유는 5절에서 이야기한 것과 같습니다. 코드가 읽히기 때문입니다.

**(2) 연쇄 대입**

```c
nl = nw = nc = 0;
```

대입은 값을 가지며 **오른쪽에서 왼쪽으로** 묶이므로, 위 문장은 `nl = (nw = (nc = 0));`과 같습니다. 세 변수가 모두 0이 됩니다.

**(3) 논리 연산자**

| 연산자 | 뜻 | 예 |
|---|---|---|
| `\|\|` | 또는(OR) | `c == ' ' \|\| c == '\n'` |
| `&&` | 그리고(AND) | `i < 10 && c != EOF` |
| `!` | 부정(NOT) | `!found` |

`&&`가 `||`보다 우선순위가 높습니다. 그리고 **왼쪽부터 차례로 검사하다가 결과가 확정되는 순간 멈춥니다.** 이를 **단축 평가(short-circuit)** 라 합니다. 위 코드에서 `c`가 공백이면 나머지 두 비교는 아예 수행되지 않습니다. 이 성질은 3강에서 다시 다룹니다.

**(4) `else if`**

```c
if (조건1)
    문장1;
else if (조건2)
    문장2;
else
    문장3;
```

조건을 위에서부터 차례로 검사하다가 **처음으로 참이 되는 것 하나만** 실행하고 전체를 끝냅니다. 마지막 `else`는 생략할 수 있으며, 그러면 아무것도 하지 않습니다.

> **한글 입력에 대한 주의**
> `getchar`는 **문자가 아니라 바이트를 하나씩** 읽습니다. UTF-8에서 한글 한 글자는 **3바이트**이므로, 한글이 들어 있는 파일에 `countchar`를 돌리면 글자 수가 아니라 바이트 수가 나옵니다. 한글을 글자 단위로 다루는 방법은 이 과정의 범위를 넘어서므로, **실습 자료는 영문과 숫자로 만드십시오.**
{: .prompt-warning }

## 제7절. 배열

### 7.1 같은 종류의 변수를 여럿 다루기

입력에 나온 숫자 `0`~`9`가 각각 몇 번 나왔는지, 공백류는 몇 개인지, 나머지 문자는 몇 개인지 세어 봅니다. 숫자만 해도 열 가지이므로 `n0`, `n1`, `n2` … 처럼 변수를 열 개 만드는 것은 현명하지 않습니다. 이럴 때 쓰는 것이 **배열(array)** 입니다.

```c
int ndigit[10];
```

이 선언은 **정수 열 개를 담는 배열**을 만듭니다. 각 칸은 `ndigit[0]`, `ndigit[1]`, …, `ndigit[9]`로 접근하며, 대괄호 안의 값을 **첨자(subscript)** 라고 합니다.

> **C의 배열 첨자는 언제나 0부터 시작합니다.**
> 크기가 10인 배열의 유효한 첨자는 **0부터 9까지**이며 `ndigit[10]`은 존재하지 않습니다. 그런데 C는 이 범위를 검사해 주지 않으므로, 잘못 접근해도 컴파일 오류가 나지 않고 **엉뚱한 메모리를 건드려 프로그램이 이상해집니다.** 배열을 다룰 때는 첨자의 범위를 스스로 지켜야 합니다.
{: .prompt-danger }

### 7.2 숫자 세기 프로그램

`ndigit.c`입니다.

```c
#include <stdio.h>

/* 숫자·공백류·그 밖의 문자를 각각 센다 */
int main(void)
{
    int c, i, nwhite, nother;
    int ndigit[10];

    nwhite = nother = 0;
    for (i = 0; i < 10; ++i)
        ndigit[i] = 0;

    while ((c = getchar()) != EOF) {
        if (c >= '0' && c <= '9')
            ++ndigit[c - '0'];
        else if (c == ' ' || c == '\n' || c == '\t')
            ++nwhite;
        else
            ++nother;
    }

    printf("digits =");
    for (i = 0; i < 10; ++i)
        printf(" %d", ndigit[i]);
    printf(", white space = %d, other = %d\n", nwhite, nother);
    return 0;
}
```

다음 내용을 담은 `digits.txt`로 실행합니다.

```text
2026 sale 30% off, 45 items
phone 010-1234-5678
```

```powershell
.\ndigit.exe < digits.txt
```

```text
digits = 4 2 3 2 2 2 2 1 1 0, white space = 8, other = 21
```

`0`이 4번, `1`이 2번, `2`가 3번… 나왔다는 뜻입니다.

### 7.3 이 프로그램의 핵심 — `c - '0'`

```c
if (c >= '0' && c <= '9')
    ++ndigit[c - '0'];
```

문자 `'5'`가 들어오면 `c`의 값은 53(ASCII)입니다. 이 값을 그대로 첨자로 쓸 수는 없습니다. 그런데 문자 집합에서 **`'0'`부터 `'9'`까지는 연속된 값**이므로 `'5' - '0'`은 정확히 **5**가 됩니다.

| 문자 | 값(ASCII) | `c - '0'` |
|---|---|---|
| `'0'` | 48 | 0 |
| `'1'` | 49 | 1 |
| `'5'` | 53 | 5 |
| `'9'` | 57 | 9 |

즉 `c - '0'`은 **문자로 표현된 숫자를 실제 수로 바꾸는 관용구**이며, C 프로그램에서 대단히 자주 등장합니다. `char`가 사실상 작은 정수이기 때문에 이런 계산이 가능한 것입니다.

첨자에는 **정수를 만들어 내는 식이면 무엇이든** 쓸 수 있습니다. 변수 `i`도, 계산식 `c - '0'`도 모두 유효합니다.

## 제8절. 함수

### 8.1 왜 함수를 만드는가

지금까지는 이미 만들어진 `printf`, `getchar`, `putchar`를 **사용**하기만 했습니다. 이제 직접 만들어 봅니다.

함수는 **어떤 계산에 이름을 붙여 포장하는 장치**입니다. 잘 만들어 두면 그것이 **어떻게** 동작하는지 잊어버려도 **무엇을** 하는지만 알면 쓸 수 있습니다. C에서는 함수를 만들기 쉽고 빠르므로, 단 한 번만 호출하는 짧은 함수를 만드는 일도 흔합니다. 코드가 그만큼 읽기 쉬워지기 때문입니다.

C에는 거듭제곱 연산자가 없으므로, 연습 삼아 정수의 거듭제곱을 구하는 `power` 함수를 만듭니다.

### 8.2 `power` 함수

`power.c`입니다. 프로그램 전체를 한눈에 보기 위해 `main`과 함께 적습니다.

```c
#include <stdio.h>

int power(int base, int n);   /* 함수 원형 선언 */

/* power 함수를 시험한다 */
int main(void)
{
    int i;

    for (i = 0; i < 10; ++i)
        printf("%2d %6d %6d\n", i, power(2, i), power(-3, i));
    return 0;
}

/* power: base 를 n 제곱한다. n >= 0 */
int power(int base, int n)
{
    int i, p;

    p = 1;
    for (i = 1; i <= n; ++i)
        p = p * base;
    return p;
}
```

```text
 0      1      1
 1      2     -3
 2      4      9
 3      8    -27
 4     16     81
 5     32   -243
 6     64    729
 7    128  -2187
 8    256   6561
 9    512 -19683
```

### 8.3 함수 정의의 형식

```text
반환자료형 함수이름(매개변수 선언 목록)
{
    선언
    문장
}
```

| 요소 | `power`의 경우 | 설명 |
|---|---|---|
| 반환 자료형 | `int` | 함수가 돌려주는 값의 자료형 |
| 함수 이름 | `power` | 호출할 때 쓰는 이름 |
| 매개변수 | `int base, int n` | 호출한 쪽에서 건네받는 값들 |
| 몸통 | `{ … }` | 실제로 수행할 일 |
| 반환 | `return p;` | 계산 결과를 호출한 쪽으로 돌려준다 |

**함수 정의의 순서는 상관없습니다.** `main`이 앞에 오든 뒤에 오든 됩니다. 다만 한 함수를 여러 파일에 쪼개어 쓸 수는 없습니다.

### 8.4 매개변수와 인자

`power(2, i)`처럼 호출할 때 건네는 값을 **인자(argument)**, 함수 쪽 괄호 안에 선언된 변수를 **매개변수(parameter)** 라고 합니다.

**매개변수 이름은 그 함수 안에서만 쓰이는 개인 소유물입니다.** `power`의 `base`, `n`, 그리고 지역 변수 `i`, `p`는 다른 함수에서 볼 수 없습니다. 그러므로 `main`의 `i`와 `power`의 `i`는 **이름만 같을 뿐 완전히 다른 변수**입니다. 이 점 덕분에 함수를 만들 때 다른 함수가 어떤 이름을 쓰는지 신경 쓸 필요가 없습니다.

### 8.5 `return` 문

```c
return 식;
```

식의 값을 호출한 쪽으로 돌려주며 함수를 즉시 끝냅니다. 값을 돌려주지 않는 함수도 있으며, 그때는 `return;`만 쓰거나 마지막 `}`에 도달하는 것으로 끝납니다.

`main`도 함수이므로 값을 돌려줄 수 있습니다. 관례적으로 **0은 정상 종료, 0이 아닌 값은 오류**를 뜻하며, 운영체제나 다른 프로그램이 이 값을 확인할 수 있습니다.

### 8.6 함수 원형 선언

```c
int power(int base, int n);
```

`main`보다 앞에 놓인 이 한 줄을 **함수 원형(function prototype)** 이라고 합니다. 컴파일러에게 "`power`는 `int` 두 개를 받아 `int`를 돌려주는 함수다"라고 미리 알려 주는 것입니다.

원형이 있으면 컴파일러가 **호출이 올바른지 검사**해 줍니다. 인자 개수가 다르거나 자료형이 맞지 않으면 즉시 오류로 알려 주므로, 원형은 선택이 아니라 **반드시 써야 할 습관**입니다.

원형에서 매개변수 이름은 생략할 수 있습니다.

```c
int power(int, int);
```

그러나 이름을 적어 두면 그 자체가 설명이 되므로 남겨 두는 편이 좋습니다.

> **정의와 선언**
> - **정의(definition)** — 함수의 몸통까지 적어 실제로 만드는 것
> - **선언(declaration)** — 이런 함수가 있다고 알리기만 하는 것(원형)
>
> 이 구분은 제11절의 변수에서도 똑같이 등장합니다.
{: .prompt-info }

## 제9절. 인자 전달 — 값에 의한 호출

C에서 함수에 인자를 건네는 방식은 **값에 의한 호출(call by value)** 하나뿐입니다. 함수는 인자의 **값을 복사해 받은 임시 변수**를 가지며, 원본은 건드리지 못합니다.

이 성질 덕분에 매개변수를 **함수 안에서 자유롭게 고쳐 쓸 수 있는 지역 변수**처럼 다룰 수 있습니다. `power`를 그렇게 다시 쓴 것이 `power2.c`입니다.

```c
#include <stdio.h>

int power(int base, int n);

int main(void)
{
    int n = 5;

    printf("호출 전  n = %d\n", n);
    printf("2의 %d제곱 = %d\n", n, power(2, n));
    printf("호출 후  n = %d\n", n);
    return 0;
}

/* power: 매개변수 n 을 직접 세어 내려간다 (값에 의한 호출) */
int power(int base, int n)
{
    int p;

    for (p = 1; n > 0; --n)
        p = p * base;
    return p;
}
```

```text
호출 전  n = 5
2의 5제곱 = 32
호출 후  n = 5
```

**`power` 안에서 `n`을 0이 될 때까지 줄였는데도 `main`의 `n`은 그대로 5입니다.** 두 `n`이 서로 다른 변수이기 때문입니다. 덕분에 반복용 변수 `i`가 필요 없어져 함수가 짧아졌습니다.

> 그렇다면 함수가 호출한 쪽의 변수를 **정말로 바꾸어야 할 때**는 어떻게 할까요? 변수의 **주소**를 건네주어야 하며, 이것이 **포인터**입니다. 이 과정의 뒷부분에서 본격적으로 다룹니다.
>
> 한편 **배열은 예외처럼 보입니다.** 배열 이름을 인자로 넘기면 원소 전체가 복사되는 것이 아니라 **배열이 시작하는 위치**가 전달되므로, 함수가 원본 배열의 내용을 바꿀 수 있습니다. 바로 다음 절에서 이 성질을 사용합니다.
{: .prompt-info }

## 제10절. 문자 배열과 문자열

### 10.1 만들 프로그램

C에서 가장 많이 쓰이는 배열은 **문자 배열**입니다. 이를 익히기 위해 **입력에서 가장 긴 줄을 찾아 출력하는 프로그램**을 만듭니다. 하려는 일을 우리말로 적으면 이렇습니다.

```text
읽을 줄이 남아 있는 동안
    지금까지의 최장 줄보다 길면
        그 줄을 보관하고
        길이도 기록한다
마지막에 보관된 줄을 출력한다
```

이 설명 자체가 프로그램을 **세 부분**으로 나누어 줍니다. 줄을 읽는 부분, 줄을 보관하는 부분, 전체를 지휘하는 부분입니다. 그러므로 함수도 그렇게 나눕니다.

| 함수 | 역할 |
|---|---|
| `get_line` | 다음 한 줄을 읽어 배열에 넣고 **그 길이**를 돌려준다 |
| `copy` | 한 문자 배열의 내용을 다른 배열로 복사한다 |
| `main` | 위 둘을 지휘한다 |

> **함수 이름을 `getline`이 아니라 `get_line`으로 지은 이유**
> 리눅스 등의 환경에서는 표준 라이브러리에 이미 `getline`이라는 함수가 있어 이름이 충돌합니다. 원서가 쓰인 시기에는 없던 함수이므로 원서는 `getline`을 씁니다. 이 강의에서는 어느 환경에서나 문제없이 컴파일되도록 `get_line`으로 바꾸었습니다. **라이브러리에 이미 있는 이름을 피하는 것**은 실무에서도 중요한 습관입니다.
{: .prompt-tip }

### 10.2 프로그램

`longest.c`입니다.

```c
#include <stdio.h>

#define MAXLINE 1000   /* 다룰 수 있는 최대 줄 길이 */

int get_line(char line[], int maxline);
void copy(char to[], char from[]);

/* 입력에서 가장 긴 줄을 찾아 출력한다 */
int main(void)
{
    int len;                /* 지금 읽은 줄의 길이 */
    int max;                /* 지금까지 가장 긴 길이 */
    char line[MAXLINE];     /* 지금 읽은 줄 */
    char longest[MAXLINE];  /* 가장 긴 줄을 보관 */

    max = 0;
    while ((len = get_line(line, MAXLINE)) > 0)
        if (len > max) {
            max = len;
            copy(longest, line);
        }
    if (max > 0)
        printf("가장 긴 줄(%d자): %s", max, longest);
    return 0;
}

/* get_line: 한 줄을 s 로 읽어 들이고 그 길이를 돌려준다 */
int get_line(char s[], int lim)
{
    int c, i;

    for (i = 0; i < lim - 1 && (c = getchar()) != EOF && c != '\n'; ++i)
        s[i] = c;
    if (c == '\n') {
        s[i] = c;
        ++i;
    }
    s[i] = '\0';
    return i;
}

/* copy: from 을 to 로 복사한다. to 가 충분히 크다고 가정한다 */
void copy(char to[], char from[])
{
    int i;

    i = 0;
    while ((to[i] = from[i]) != '\0')
        ++i;
}
```

다음 내용의 `lines.txt`로 실행합니다.

```text
a
bb
ccc dddd
ee
```

```powershell
.\longest.exe < lines.txt
```

```text
가장 긴 줄(9자): ccc dddd
```

`ccc dddd`는 8자인데 길이가 9로 나온 이유는 **줄 끝의 개행 문자까지 포함**했기 때문입니다.

### 10.3 문자열의 끝 표시 `'\0'`

C에는 문자열이라는 자료형이 따로 없습니다. **문자열은 문자 배열이며, 끝을 알리기 위해 값이 0인 문자 `'\0'`(널 문자)을 뒤에 붙입니다.** 그래서 `"hello\n"`이라는 문자열 상수는 메모리에 이렇게 저장됩니다.

| `h` | `e` | `l` | `l` | `o` | `\n` | `\0` |
|---|---|---|---|---|---|---|

글자는 6개인데 **저장 공간은 7칸**입니다. 이 약속 덕분에 문자열의 길이를 미리 알지 못해도 **`'\0'`이 나올 때까지 훑으면** 끝을 찾을 수 있습니다.

- `get_line`은 배열을 다 채운 뒤 마지막에 `s[i] = '\0';`으로 끝을 표시합니다.
- `copy`는 `'\0'`을 만날 때까지 복사하며, **`'\0'` 자체도 복사**합니다. 그래야 복사본도 올바른 문자열이 됩니다.
- `printf`의 `%s`는 인자가 이런 형태라고 가정하고 `'\0'`을 만날 때까지 출력합니다.

> 위 출력에서 `printf("...%s", max, longest)` 뒤에 `\n`이 없는데도 줄이 바뀌는 이유는, **보관된 줄 자체가 개행 문자로 끝나기** 때문입니다.
{: .prompt-info }

### 10.4 `get_line` 자세히 읽기

```c
for (i = 0; i < lim - 1 && (c = getchar()) != EOF && c != '\n'; ++i)
    s[i] = c;
```

조건이 세 개나 `&&`로 이어져 있습니다. **왼쪽부터 차례로 검사하며 하나라도 거짓이면 즉시 멈추는** 단축 평가 덕분에 이 순서에는 의미가 있습니다.

| 순서 | 조건 | 왜 이 순서인가 |
|---|---|---|
| 1 | `i < lim - 1` | **배열에 자리가 남았는지 먼저** 확인해야 한다. 자리가 없는데 읽으면 배열 밖을 침범한다 |
| 2 | `(c = getchar()) != EOF` | 자리가 있을 때만 문자를 읽는다 |
| 3 | `c != '\n'` | 읽은 문자가 개행이면 줄이 끝난 것이다 |

`lim - 1`인 이유는 **마지막 한 칸을 `'\0'` 자리로 남겨 두어야** 하기 때문입니다.

또한 함수의 매개변수 `char s[]`에는 **크기를 적지 않았습니다.** 배열의 크기는 호출하는 쪽(`main`의 `MAXLINE`)이 정하며, 함수는 배열이 시작하는 위치만 전달받기 때문입니다. 그래서 `copy`가 `to` 배열의 내용을 실제로 바꿀 수 있는 것입니다(제9절 참고).

### 10.5 `copy` 자세히 읽기

```c
while ((to[i] = from[i]) != '\0')
    ++i;
```

`copy2.c`에서 본 관용구가 다시 등장했습니다. 대입식의 값은 대입된 결과이므로, 이 한 줄은 **복사하고 → 그 값이 `'\0'`인지 검사한다**를 동시에 합니다.

### 10.6 설계에 관한 이야기

이 짧은 프로그램에도 판단이 필요한 지점이 있습니다. **입력에 `MAXLINE`보다 긴 줄이 들어오면 어떻게 할 것인가?**

`get_line`은 배열이 가득 차면 개행을 만나지 않아도 읽기를 멈추므로 **안전하게** 동작합니다. 다만 그 줄이 잘렸다는 사실을 `main`이 알아야 제대로 대응할 수 있습니다. 이런 판단은 실습문제에서 직접 다루어 봅니다.

한편 `get_line`은 넘침을 검사하지만 `copy`는 검사하지 않습니다. `copy`를 쓰는 쪽은 배열의 크기를 이미 알고 있기 때문입니다. **누가 무엇을 책임질 것인지 정하는 일**이 곧 설계입니다.

> **배열 밖에 쓰면 무슨 일이 벌어지는가 — 이 과정에서 가장 중요한 경고**
> 7.1절에서 C는 배열 첨자의 범위를 검사하지 않는다고 하였습니다. 그러므로 `get_line`에서 `i < lim - 1` 검사를 빼더라도 **컴파일도 되고 실행도 됩니다.** 다만 배열이 끝나는 지점을 넘어 **옆에 있던 다른 변수의 메모리를 덮어씁니다.**
>
> 그 결과는 대개 즉시 드러나지 않습니다. 엉뚱한 변수의 값이 조용히 바뀌어 한참 뒤에 이상하게 동작하거나, 프로그램이 갑자기 죽습니다. 이것이 **버퍼 오버플로(buffer overflow)** 이며, 오늘날에도 보안 사고의 가장 흔한 원인 가운데 하나입니다.
>
> 그래서 `get_line`의 `lim - 1`은 단순한 예의가 아니라 **프로그램이 지켜야 할 안전선**입니다. 배열을 다루는 코드에서 **"몇 칸까지 쓸 수 있는가"를 언제나 함께 넘기고 검사하는 습관**을 지금부터 들이시기 바랍니다. 실제로 어떤 일이 벌어지는지는 **7강**에서 눈으로 확인하고, 막는 방법은 **10강**에서 다룹니다.
{: .prompt-danger }

## 제11절. 외부 변수와 유효 범위

### 11.1 지역 변수

`main`의 `line`, `longest`, `max`는 **`main`의 개인 소유**입니다. 다른 함수는 그 이름으로 접근할 수 없습니다. 이렇게 함수 안에서 선언된 변수를 **지역 변수(local variable)** 또는 **자동 변수(automatic variable)** 라 합니다.

- **함수가 호출될 때 생겨나고, 함수가 끝나면 사라집니다.**
- 따라서 호출과 호출 사이에 값이 남아 있지 않습니다.
- 값을 넣지 않고 사용하면 **쓰레기 값**이 들어 있습니다.

### 11.2 외부 변수

모든 함수 바깥에 선언하면 **어느 함수에서나 이름으로 접근할 수 있는 변수**가 됩니다. 이를 **외부 변수(external variable)** 라 하며, 프로그램이 시작될 때 만들어져 끝날 때까지 남아 있습니다. `longest.c`를 외부 변수로 다시 쓴 것이 `longest_ext.c`입니다.

```c
#include <stdio.h>

#define MAXLINE 1000

int max;                 /* 외부 변수: 지금까지 가장 긴 길이 */
char line[MAXLINE];      /* 외부 변수: 지금 읽은 줄 */
char longest[MAXLINE];   /* 외부 변수: 가장 긴 줄 */

int get_line(void);
void copy(void);

/* 가장 긴 줄 찾기 — 외부 변수 사용판 */
int main(void)
{
    int len;

    max = 0;
    while ((len = get_line()) > 0)
        if (len > max) {
            max = len;
            copy();
        }
    if (max > 0)
        printf("가장 긴 줄(%d자): %s", max, longest);
    return 0;
}

int get_line(void)
{
    int c, i;

    for (i = 0; i < MAXLINE - 1 && (c = getchar()) != EOF && c != '\n'; ++i)
        line[i] = c;
    if (c == '\n') {
        line[i] = c;
        ++i;
    }
    line[i] = '\0';
    return i;
}

void copy(void)
{
    int i;

    i = 0;
    while ((longest[i] = line[i]) != '\0')
        ++i;
}
```

```text
가장 긴 줄(9자): ccc dddd
```

결과는 같습니다. 함수들이 인자를 주고받지 않고 **공용 변수를 직접 읽고 씁니다.**

### 11.3 정의와 선언, 그리고 `extern`

외부 변수는 모든 함수 바깥에서 **정확히 한 번 정의**되어야 하며, 그때 저장 공간이 마련됩니다. 그 변수를 쓰려는 함수가 다른 파일에 있다면, 그 파일에서 `extern`으로 **선언**하여 "이런 변수가 어딘가에 있다"고 알려야 합니다.

```c
extern int max;
extern char longest[];
```

같은 파일 안에서 정의가 사용보다 **앞에** 있으면 `extern` 선언은 필요 없습니다. 실무에서는 외부 변수의 정의를 소스 파일 맨 앞에 모아 두고 `extern`을 생략하며, 여러 파일에서 공유할 때는 `extern` 선언들을 **헤더 파일(`.h`)** 에 모아 각 소스에서 `#include`합니다. `<stdio.h>`가 바로 그런 헤더입니다.

### 11.4 외부 변수를 남용하지 마십시오

외부 변수는 편리해 보입니다. 인자 목록이 짧아지고 어디서나 값을 볼 수 있기 때문입니다. 그러나 바로 그 점이 위험합니다.

> **두 번째 판(`longest_ext.c`)은 첫 번째 판보다 나쁜 프로그램입니다.**
> 1. 어떤 함수가 어떤 변수를 바꾸는지 **겉으로 드러나지 않습니다.** 프로그램이 커지면 값이 언제 어디서 바뀌었는지 추적하기가 매우 어려워집니다.
> 2. `get_line`과 `copy`가 **특정 변수 이름에 묶여 버려** 다른 곳에서 재사용할 수 없습니다. 첫 번째 판의 `copy(to, from)`은 어떤 배열에도 쓸 수 있지만, 두 번째 판의 `copy()`는 오직 `line`과 `longest`만 다룹니다.
>
> **원칙:** 값은 되도록 **인자로 주고받고**, 외부 변수는 여러 함수가 정말로 공유해야 하는 것에만 제한적으로 사용하십시오.
{: .prompt-warning }

### 문제 1. 표에 제목 붙이기

`temp4.c`를 복사하여 `ex1.c`를 만들고, 제목과 구분선이 붙은 표를 출력하도록 고치십시오. 제목은 **한 번만** 출력되어야 합니다.

**정답 및 해설**

```c
#include <stdio.h>

#define LOWER  0
#define UPPER  300
#define STEP   20

int main(void)
{
    int fahr;

    printf("  화씨   섭씨\n");
    printf("------ ------\n");

    for (fahr = LOWER; fahr <= UPPER; fahr = fahr + STEP) {
        printf("%6d %6.1f\n", fahr, (5.0 / 9.0) * (fahr - 32));
    }

    return 0;
}
```

- 제목 `printf`는 **반복문 바깥, 반복 시작 전**에 두어야 합니다. 안에 두면 16번 반복 출력됩니다.
- 본문 서식이 `%6d %6.1f`이므로 제목의 폭도 그에 맞추어야 정렬이 어긋나지 않습니다. 한글은 터미널에서 두 칸을 차지하므로 폭 계산이 어긋날 수 있습니다. 정렬이 흐트러지면 제목을 영문(`Fahr`, `Celsius`)으로 바꾸어도 됩니다.

### 문제 2. 섭씨 → 화씨 표 만들기

### 문제 3. 역순으로 출력하기

화씨 **300도부터 0도까지 20도씩 줄어드는** 순서로 표를 출력하는 `ex3.c`를 작성하십시오.

**정답 및 해설**

```c
#include <stdio.h>

#define LOWER  0
#define UPPER  300
#define STEP   20

int main(void)
{
    int fahr;

    for (fahr = UPPER; fahr >= LOWER; fahr = fahr - STEP) {
        printf("%3d %6.1f\n", fahr, (5.0 / 9.0) * (fahr - 32));
    }

    return 0;
}
```

`for` 문의 **세 부분을 모두** 바꾸어야 합니다.

| 부분 | 정방향 | 역방향 |
|---|---|---|
| 초기화 | `fahr = LOWER` | `fahr = UPPER` |
| 조건 | `fahr <= UPPER` | `fahr >= LOWER` |
| 증감 | `fahr = fahr + STEP` | `fahr = fahr - STEP` |

특히 **부등호 방향**을 바꾸지 않으면 `300 <= 0`이 처음부터 거짓이 되어 **아무것도 출력되지 않습니다.** 반복문이 한 줄도 출력하지 않으면 대개 조건을 의심해야 합니다.

### 문제 4. `EOF`의 값 확인하기

`ex4.c`를 작성하여 `EOF`의 값을 출력하고, 이어서 `getchar() != EOF` 라는 식의 값이 실제로 0 또는 1임을 확인하십시오.

**정답 및 해설**

```c
#include <stdio.h>

int main(void)
{
    int c;

    printf("EOF = %d\n", EOF);

    while ((c = getchar()) != EOF)
        printf("문자 '%c'(%d) 을 읽음. (getchar() != EOF) 의 값 = %d\n",
               c, c, c != EOF);

    printf("입력 종료. (c != EOF) 의 값 = %d\n", c != EOF);
    return 0;
}
```

- `EOF`는 대부분의 환경에서 **−1**입니다. 그러나 표준이 −1로 못 박은 것은 아니므로 **코드에는 반드시 `EOF`라고 적어야** 합니다.
- 관계 연산의 결과는 **참이면 1, 거짓이면 0**입니다. 이 값은 그대로 `printf`로 출력할 수 있습니다.
- 실행할 때는 `.\ex4.exe < in.txt` 처럼 파일을 넣거나, 키보드로 몇 글자 친 뒤 줄 맨 앞에서 `Ctrl+Z` → `Enter` 를 누릅니다.

### 문제 5. 공백·탭·개행 세기

입력에 들어 있는 공백, 탭, 개행의 개수를 각각 세는 `ex5.c`를 작성하십시오.

**정답 및 해설**

```c
#include <stdio.h>

/* 공백·탭·개행의 개수를 각각 센다 */
int main(void)
{
    int c, blanks, tabs, newlines;

    blanks = tabs = newlines = 0;
    while ((c = getchar()) != EOF) {
        if (c == ' ')
            ++blanks;
        else if (c == '\t')
            ++tabs;
        else if (c == '\n')
            ++newlines;
    }
    printf("공백 %d개, 탭 %d개, 개행 %d개\n", blanks, tabs, newlines);
    return 0;
}
```

다음 세 줄짜리 입력(둘째 줄에 탭 한 개 포함)으로 실행한 결과입니다.

```text
hello, world
this is  a	test
C programming language
```

```text
공백 6개, 탭 1개, 개행 3개
```

- 세 조건은 **서로 배타적**이므로 `else if`로 잇는 것이 옳습니다. `if`를 세 번 나열해도 결과는 같지만, 하나가 참이면 나머지는 검사할 필요가 없습니다.
- 마지막 줄에도 개행이 있어야 3개로 셉니다. 텍스트 파일은 마지막 줄도 개행으로 끝내는 것이 관례입니다.

### 문제 6. 연속된 공백을 하나로 줄이기

입력을 출력으로 복사하되, **연속된 공백을 공백 하나로 줄이는** `ex6.c`를 작성하십시오.

**정답 및 해설**

```c
#include <stdio.h>

/* 연속된 공백을 하나로 줄여 출력한다 */
int main(void)
{
    int c, prev;

    prev = 0;
    while ((c = getchar()) != EOF) {
        if (c == ' ' && prev == ' ')
            continue;          /* 앞 글자도 공백이면 건너뛴다 */
        putchar(c);
        prev = c;
    }
    return 0;
}
```

```text
hello, world
this is a	test
C programming language
```

- **직전 문자를 기억하는 변수**가 필요합니다. 6.9절의 상태 변수와 같은 발상입니다.
- `continue`는 반복 몸통의 나머지를 건너뛰고 **다음 반복으로 넘어가라**는 뜻입니다. 이 문장을 쓰지 않으려면 다음처럼 조건을 뒤집어도 됩니다.

```c
if (!(c == ' ' && prev == ' ')) {
    putchar(c);
    prev = c;
}
```

- `prev`의 초기값을 0으로 둔 이유는 **맨 첫 글자가 공백이어도 그것은 출력되어야** 하기 때문입니다.

### 문제 7. 한 줄에 한 단어씩 출력하기

입력의 단어를 **한 줄에 하나씩** 출력하는 `ex7.c`를 작성하십시오.

**정답 및 해설**

```c
#include <stdio.h>

#define IN   1
#define OUT  0

/* 한 줄에 한 단어씩 출력한다 */
int main(void)
{
    int c, state;

    state = OUT;
    while ((c = getchar()) != EOF) {
        if (c == ' ' || c == '\t' || c == '\n') {
            if (state == IN) {
                putchar('\n');
                state = OUT;
            }
        } else {
            state = IN;
            putchar(c);
        }
    }
    if (state == IN)
        putchar('\n');
    return 0;
}
```

```text
hello,
world
this
is
a
test
C
programming
language
```

- 6.9절의 단어 세기와 **완전히 같은 구조**입니다. 단어 수를 세는 대신 개행을 출력할 뿐입니다.
- **공백류가 연속되어도 빈 줄이 생기지 않는** 이유는 `state == IN`일 때만 개행을 출력하기 때문입니다.
- 반복이 끝난 뒤의 `if (state == IN)`은 **파일이 개행 없이 끝나는 경우**를 위한 마무리입니다. 이런 경계 상황을 놓치지 않는 것이 중요합니다.

### 문제 8. 단어 길이 히스토그램

입력에 나온 단어들의 **길이 분포**를 가로 막대 그래프로 출력하는 `ex8.c`를 작성하십시오.

**정답 및 해설**

```c
#include <stdio.h>

#define MAXWORD 15   /* 셀 수 있는 최대 단어 길이 */

/* 단어 길이의 분포를 가로 막대 그래프로 출력한다 */
int main(void)
{
    int c, i, j, len, over;
    int count[MAXWORD + 1];

    over = 0;
    len = 0;
    for (i = 0; i <= MAXWORD; ++i)
        count[i] = 0;

    while ((c = getchar()) != EOF) {
        if (c == ' ' || c == '\t' || c == '\n') {
            if (len > 0) {
                if (len <= MAXWORD)
                    ++count[len];
                else
                    ++over;
            }
            len = 0;
        } else {
            ++len;
        }
    }
    if (len > 0) {                 /* 마지막 단어 처리 */
        if (len <= MAXWORD)
            ++count[len];
        else
            ++over;
    }

    printf("길이  빈도\n");
    for (i = 1; i <= MAXWORD; ++i) {
        printf("%4d  ", i);
        for (j = 0; j < count[i]; ++j)
            putchar('#');
        printf(" %d\n", count[i]);
    }
    if (over > 0)
        printf("%d자 초과: %d개\n", MAXWORD, over);
    return 0;
}
```

```text
길이  빈도
   1  ## 2
   2  # 1
   3   0
   4  ## 2
   5  # 1
   6  # 1
   7   0
   8  # 1
   9   0
  10   0
  11  # 1
  12   0
  13   0
  14   0
  15   0
```

- 배열 크기를 `MAXWORD + 1`로 잡은 이유는 **길이를 첨자로 그대로 쓰기 위해서**입니다. 길이 15인 단어를 `count[15]`에 세려면 첨자 15가 유효해야 하므로 크기는 16이어야 합니다. `count[0]`은 쓰지 않습니다.
- `MAXWORD`를 넘는 단어를 `over`로 따로 세는 것은 **배열 범위를 벗어나지 않기 위한 안전장치**입니다. 이 처리를 빠뜨리면 긴 단어 하나에 프로그램 전체가 망가질 수 있습니다.
- 막대를 세로로 그리려면 먼저 최대 빈도를 구한 뒤 위에서 아래로 한 줄씩 그려야 합니다. 훨씬 까다로우므로 여유가 있으면 도전해 보십시오.

### 문제 9. 80자보다 긴 줄만 출력하기

입력에서 **길이가 80자를 넘는 줄만** 출력하는 `ex9.c`를 작성하십시오. `get_line` 함수를 사용합니다.

**정답 및 해설**

```c
#include <stdio.h>

#define MAXLINE 1000
#define LIMIT     80   /* 이 길이를 넘는 줄만 출력한다 */

int get_line(char s[], int lim);

/* 80자보다 긴 줄만 출력한다 */
int main(void)
{
    int len;
    char line[MAXLINE];

    while ((len = get_line(line, MAXLINE)) > 0)
        if (len > LIMIT)
            printf("%3d: %s", len, line);
    return 0;
}

int get_line(char s[], int lim)
{
    int c, i;

    for (i = 0; i < lim - 1 && (c = getchar()) != EOF && c != '\n'; ++i)
        s[i] = c;
    if (c == '\n') {
        s[i] = c;
        ++i;
    }
    s[i] = '\0';
    return i;
}
```

`x`가 95개인 줄과 `y`가 81개인 줄이 섞인 파일로 실행한 결과입니다.

```text
 96: xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
 82: yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy
```

- 95자짜리 줄의 길이가 **96**으로 나온 것은 `get_line`이 세는 길이에 **개행 문자가 포함**되기 때문입니다. 순수한 글자 수로 비교하려면 `len - 1 > LIMIT`로 하거나, 개행을 제외하고 세도록 `get_line`을 고쳐야 합니다. **무엇을 길이로 볼 것인지 정하는 것도 설계**입니다.
- `printf`에 `\n`이 없는 이유는 `line`이 이미 개행으로 끝나기 때문입니다.

### 문제 10. 줄 뒤집기

입력의 각 줄을 **거꾸로 뒤집어** 출력하는 `ex10.c`를 작성하십시오. 뒤집는 일은 `reverse`라는 함수로 분리합니다.

**정답 및 해설**

```c
#include <stdio.h>

#define MAXLINE 1000

int get_line(char s[], int lim);
void reverse(char s[]);

/* 각 줄을 거꾸로 뒤집어 출력한다 */
int main(void)
{
    char line[MAXLINE];

    while (get_line(line, MAXLINE) > 0) {
        reverse(line);
        printf("%s\n", line);
    }
    return 0;
}

int get_line(char s[], int lim)
{
    int c, i;

    for (i = 0; i < lim - 1 && (c = getchar()) != EOF && c != '\n'; ++i)
        s[i] = c;
    if (c == '\n') {
        s[i] = c;
        ++i;
    }
    s[i] = '\0';
    return i;
}

/* reverse: 문자열 s 를 제자리에서 뒤집는다 (끝의 개행은 제외) */
void reverse(char s[])
{
    int i, j, temp;

    j = 0;
    while (s[j] != '\0')
        ++j;
    --j;
    if (j >= 0 && s[j] == '\n')    /* 개행은 뒤집기 대상에서 제외 */
        --j;

    for (i = 0; i < j; ++i, --j) {
        temp = s[i];
        s[i] = s[j];
        s[j] = temp;
    }

    /* 남아 있는 개행을 지운다 (출력에서 직접 붙이므로) */
    j = 0;
    while (s[j] != '\0')
        ++j;
    if (j > 0 && s[j - 1] == '\n')
        s[j - 1] = '\0';
}
```

```text
dlrow ,olleh
tset	a  si siht
egaugnal gnimmargorp C
```

- 뒤집기의 핵심은 **양쪽 끝에서 안쪽으로 좁혀 오며 두 글자를 맞바꾸는 것**입니다. 세 번째 변수 `temp`가 반드시 필요합니다. `s[i] = s[j]; s[j] = s[i];` 라고 쓰면 첫 대입에서 원래 값이 사라져 두 칸이 같은 값이 됩니다.
- 반복 조건이 `i < j`이므로 가운데에서 자동으로 멈춥니다. 글자 수가 홀수이면 가운데 글자는 제자리에 남습니다.
- **줄 끝의 개행을 어떻게 다룰지**가 이 문제의 진짜 난관입니다. 그대로 뒤집으면 개행이 줄 맨 앞으로 가서 출력이 어그러집니다. 여기서는 뒤집기 대상에서 제외한 뒤 지우고, 출력할 때 `printf`가 붙이도록 했습니다.
- `for (i = 0; i < j; ++i, --j)` 에서 쉼표는 **두 개의 식을 한 자리에 쓰는 콤마 연산자**입니다.

## 정리

| 구분 | 내용 |
|---|---|
| 프로그램 구조 | C 프로그램은 **함수와 변수**로 이루어지며 실행은 언제나 `main`에서 시작 |
| 변수 | 사용 전에 **선언**하고 사용 전에 **초기화**한다 |
| 산술 | **정수 ÷ 정수 = 정수**(절단). 실수 결과가 필요하면 한쪽 이상을 실수로 |
| 출력 | `%d` `%f` `%c` `%s`, 폭과 정밀도는 `%6.1f`, 왼쪽 정렬은 `%-6d` |

| 함수 | 정의·원형 선언·호출, **값에 의한 호출**, 지역 변수는 함수의 개인 소유 |
