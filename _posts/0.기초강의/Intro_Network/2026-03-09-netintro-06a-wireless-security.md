지금까지는 케이블로 연결된 유선 네트워크를 다루었습니다. 이 장에서는 **전파라는 개방된 매체**를 사용하는 무선 네트워크를 살펴봅니다. 무선은 물리적 접속 없이도 누구나 신호에 접근할 수 있어 유선과는 다른 차원의 보안 위협이 존재합니다. 이 편에서는 무선 기반 기술과 위협 요소, 블루투스, 그리고 무선 LAN의 암호화·인증 기술을 다룹니다.

## 1. 무선통신 기반 기술

### (1) 무선 네트워크의 분류

무선 네트워크는 전파가 도달하는 범위(커버리지)에 따라 나뉩니다.

| 구분 | 대표 기술 | 설명 |
|---|---|---|
| WPAN | 블루투스, 지그비(ZigBee) | 수 미터 이내의 근거리 개인 영역 무선망 |
| WLAN | Wi-Fi(IEEE 802.11) | 건물·캠퍼스 범위의 무선 LAN 환경 |
| WMAN | WiMAX | 도시권 범위의 무선 통신망 |

_표 6-1. 무선 네트워크의 분류_

_그림 6-1. 무선 네트워크의 범위별 분류_

### (2) 무선 네트워크 보안 위협의 4대 요소

무선이 유선보다 취약한 이유는 네 가지로 정리됩니다.

| 요소 | 설명 |
|---|---|
| 채널(Channel) | 무선 전파의 개방성으로 도청·재밍(Jamming)에 취약 |
| 이동성(Mobility) | 사용자가 고정되지 않아 물리적 보안 경계 설정이 어려움 |
| 자원(Resources) | 단말의 배터리·컴퓨팅 한계로 고강도 암호화 연산에 제약 |
| 접근성(Accessibility) | 공격자가 건물 외부에서도 무선 신호에 접근 가능 |

_표 6-2. 무선 네트워크 보안 위협의 4대 요소_

### (3) 무선 전파의 물리적 특성

전파는 눈에 보이지 않지만 물리 법칙을 따릅니다. **감쇠(Attenuation)** 는 거리·장애물로 신호가 약해지는 현상, **간섭(Interference)** 은 같은 주파수 대역의 다른 장비가 신호를 왜곡하는 현상(전자레인지·블루투스가 2.4GHz Wi-Fi를 방해), **다중경로 페이딩(Multipath Fading)** 은 전파가 반사·굴절되어 서로 다른 시간에 도착해 겹치는(왜곡) 현상입니다.

### (4) 무선랜 매체 접근 제어 — CSMA/CA

유선 이더넷은 충돌을 감지(CD)한 뒤 재전송하는 CSMA/CD를 씁니다. 그러나 무선은 송신과 수신을 동시에 할 수 없는 반이중 통신이라 전송 중 충돌을 직접 감지할 수 없습니다. 그래서 무선 LAN은 전송 전에 매체가 비어 있는지 확인하고 임의의 시간을 기다려 충돌을 **사전에 회피(CA)** 하는 CSMA/CA를 씁니다.

> **참고 — 숨겨진 단말 문제** 같은 AP에 접속한 두 단말이 서로의 전파 범위 밖에 있으면, 상대의 전송을 듣지 못해 충돌이 생길 수 있습니다(숨겨진 단말 문제). 이를 보완하기 위해 전송 전에 RTS/CTS 제어 프레임으로 매체 사용을 예약하는 방법을 함께 씁니다.
{: .prompt-info }

### (5) IEEE 802.11 표준의 진화

| 표준 | 특징 |
|---|---|
| 802.11a/b/g | 초기 무선 표준. 2.4GHz/5GHz 대역 확립, 속도 향상 |
| 802.11n (Wi-Fi 4) | MIMO(다중 안테나)로 대역폭·신뢰성 향상 |
| 802.11i | WEP 취약성 해결을 위해 WPA2 암호화를 정의한 핵심 보안 표준 |
| 802.11ac/ax/be (Wi-Fi 5/6/7) | 기가비트급 속도, 고밀도 지원(OFDMA), 다중 접속 효율 극대화 |

### (6) 무선랜 핵심 구성요소

**AP(Access Point)** 는 유선망과 무선망을 연결하는 브릿지 역할의 중앙 장비로, 모든 무선 트래픽이 AP를 지나므로 AP 보안이 출발점입니다. **무선 브릿지**는 떨어진 유선 세그먼트 간을 무선으로 연결합니다. **SSID(Service Set Identifier)** 는 무선 네트워크를 구분하는 이름표로, AP가 주기적으로 내보내는 비콘(Beacon) 프레임에 실려 단말 목록에 나타납니다. 어디까지나 이름일 뿐 인증 수단이 아니므로, SSID를 숨기는 것만으로는 보안이 되지 않습니다.

## 2. 블루투스

블루투스(Bluetooth)는 2.4GHz 대역의 근거리 무선 통신(WPAN) 기술입니다. 1개의 마스터와 최대 7개의 슬레이브로 구성된 **피코넷(Piconet)** 이 기본 단위이며, 여러 피코넷이 연결되어 더 큰 **스캐터넷(Scatternet)** 을 이룹니다.

![그림 6-3. 피코넷과 스캐터넷의 구조](/assets/img/posts/2026-03-09-netintro-c6-03.png)
_그림 6-3. 피코넷과 스캐터넷의 구조_

블루투스 공격은 장비 검색·페어링 기능을 악용하는 경우가 많아, 이름이 비슷해 목적을 기준으로 구분해 두어야 합니다.

| 공격 기법 | 설명 |
|---|---|
| 블루프린팅(Blueprinting) | 원격으로 장비 정보를 수집하는 취약점 사전 조사 |
| 블루스나핑(Bluesnarfing) | 주소록·파일 등 인가되지 않은 데이터에 몰래 접근해 훔침 |
| 블루버깅(Bluebugging) | 링크 키를 탈취해 대상 휴대폰을 원격 제어 |
| 블루재킹(Bluejacking) | 원치 않는 스팸 메시지·명함을 무작위 전송 |

_표 6-4. 블루투스의 주요 공격 기법_

> **보안 유의 — 블루투스 기본 수칙** 사용하지 않을 때는 블루투스를 끄고, 장비를 상시 ‘검색 가능’ 상태로 두지 않으며, 공공장소에서 출처를 알 수 없는 페어링 요청을 수락하지 않는 것이 기본 방어입니다.
{: .prompt-warning }

## 3. 무선 LAN 보안 기술 및 프로토콜

### (1) 무선 LAN 취약점

무선 LAN 취약점은 관리·물리적 요인(무분별한 개인 AP 설치, 전파 도달 범위 통제 실패)과 기술적 요인(도청, 인증 해제 프레임을 악용한 무선 DoS, 비인가 AP, SSID·MAC 노출)으로 나뉩니다. 대부분 전파가 공간에 개방되어 있고 무선 관리 프레임이 암호화·인증 없이 오간다는 데서 비롯됩니다.

| 취약점/공격 | 공격 방식 | 위협 | 주요 대응책 |
|---|---|---|---|
| 무선 도청(스니핑) | 개방 전파를 수동 수집해 평문·인증 정보 가로챔 | 기밀성 | WPA2/WPA3, 개방망은 OWE·VPN |
| 인증 해제 공격(Deauth) | 위조 인증 해제 프레임을 대량 전송해 단말을 떨어뜨림 | 가용성(무선 DoS) | 보호 관리 프레임(802.11w, PMF), WIPS |
| 비인가 AP(Rogue AP) | 승인 없이 내부망에 연결된 AP로 보안 경계 우회 | 접근 통제 무력화 | WIPS, 포트 보안·NAC |
| 이블 트윈(Evil Twin) | 정상과 같은 SSID의 가짜 AP로 유인 | 무결성·기밀성(MITM) | 서버 인증서 검증(EAP-TLS), WIPS |
| SSID 노출 | 비콘에 SSID가 평문으로 실림 | 정찰 정보 제공 | 은닉은 보조 수단, 강한 인증·암호화 |
| MAC 노출·스푸핑 | MAC 평문 노출·위조로 필터링 우회 | 접근 통제 무력화 | 802.1X 병행, MAC 무작위화 |
| WPS 취약점 | 8자리 PIN 무차별 대입으로 PSK 획득 | 인증 정보 노출 | WPS 비활성화 |
| 재밍(Jamming) | 같은 대역에 강한 잡음을 쏘아 마비 | 가용성(무선 DoS) | 스펙트럼 모니터링, 채널 변경 |
| 워 드라이빙 | 이동하며 취약 AP를 탐색·지도화 | 공격 대상 식별 | 전파 출력 조정, 강한 암호화 |

_표 6-5. 무선 LAN의 주요 기술적 취약점과 대응_

### (2) 무선 암호화의 발전 — WEP → WPA → WPA2 → WPA3

무선은 통신 범위 안의 누구나 신호를 수신할 수 있다는 전제에서 출발해야 하므로 반드시 암호화가 필요합니다. 802.11 암호화 표준은 WEP의 실패를 교훈 삼아 **TKIP(WPA) → CCMP(WPA2) → SAE(WPA3) → OWE(개방형용)** 순서로 발전했습니다. 이 과정은 ① 키를 ‘고정 키’에서 ‘세션·패킷마다 달라지는 동적 키’로, ② 알고리즘을 취약한 RC4[^rc4]에서 표준 AES[^aes]로, ③ 인증 절차를 오프라인 대입 공격을 원천 차단하도록 재설계한 것으로 요약됩니다.

![그림 6-4. 무선 암호화 표준의 발전](/assets/img/posts/2026-03-09-netintro-c6-04.png)
_그림 6-4. 무선 암호화 표준의 발전_

**WEP(Wired Equivalent Privacy)** 는 1997년 최초의 802.11과 함께 등장해 ‘유선만큼의 프라이버시’를 흉내 내려 했으나 설계 결함으로 사실상 실패한 표준입니다. RC4 스트림 암호로 프레임을 암호화하고 무결성 검증은 암호학적 해시가 아닌 단순 체크섬 CRC-32에 의존했는데, CRC-32는 선형 연산이라 특정 비트를 조작해도 검증값을 맞출 수 있어(비트 플리핑) 위·변조를 막지 못했습니다.

![그림 6-5. WEP의 구조와 취약점](/assets/img/posts/2026-03-09-netintro-c6-05.png)
_그림 6-5. WEP의 구조와 취약점_

결정적 결함은 **짧은 IV(초기화 벡터[^iv])의 재사용**이었습니다. RC4는 매 프레임마다 ‘고정 키 + IV’를 합쳐 새 키스트림을 만드는데, IV가 24비트뿐(약 1,677만 개)이라 트래픽이 많은 AP에서는 수천~수만 프레임만 오가도 같은 IV가 반복됩니다. 게다가 IV는 암호화되지 않고 헤더에 평문으로 실려, 공격자는 같은 IV로 암호화된 프레임을 모아 키스트림을 역산할 수 있습니다. FMS·KoreK·PTW 공격 등은 자동화 도구만으로 수 분~수십 분 안에 WEP 키 전체를 복구합니다. 결국 WEP는 지금 대부분의 장비에서 선택 자체가 막혀 있습니다.

**TKIP(WPA)** 는 WEP 실패 후, 이미 깔린 RC4 하드웨어를 교체하지 않고 펌웨어 업그레이드만으로 보안을 끌어올리려는 과도기 대책이었습니다. 임시 키에 송신자 MAC과 패킷 시퀀스 번호를 결합해 **프레임마다 다른 RC4 키를 만들고(Per-packet Key Mixing)**, CRC-32보다 강화된 무결성 코드 MIC(Michael)를 도입했습니다. 그러나 여전히 취약한 RC4 위에 서 있어 한계가 뚜렷했고(Beck-Tews 공격 등), 결국 폐기(Deprecated)되었습니다.

![그림 6-6. TKIP 알고리즘](/assets/img/posts/2026-03-09-netintro-c6-06.png)
_그림 6-6. TKIP 알고리즘_

**CCMP(WPA2)** 는 RC4를 완전히 걷어내고 **AES 블록 암호**로 넘어간 규격입니다. AES를 스트림 암호처럼 쓰는 CTR 모드로 기밀성을, CBC-MAC로 무결성·인증을 제공하며, 프레임마다 48비트 패킷 번호(PN)를 논스[^nonce]로 써서 WEP·TKIP를 괴롭힌 ‘짧은 IV 재사용’ 문제를 구조적으로 없앴습니다. 하나의 128비트 AES 키로 기밀성과 무결성을 동시에 만족하는 이런 방식을 AEAD(인증된 암호화)라 하며, CCMP 자체의 암호학적 결함은 아직 보고된 바 없습니다.

> **참고 — 4-Way Handshake란** WPA2에서 비밀번호(또는 802.1X 인증 결과)로부터 유도한 장기 키를 PMK라 합니다. 단말과 AP는 이 PMK를 그대로 쓰지 않고, 네 번의 메시지를 주고받아 세션마다 다른 PTK(실제 데이터 암호화 세션 키)를 안전하게 도출합니다. ① AP가 난수 ANonce를 보내고, ② 단말이 SNonce와 무결성값(MIC)을 보내며, ③ AP가 PTK를 계산하고 그룹 키(GTK)를 실어 ‘설치하라’고 지시하고, ④ 단말이 확인(ACK)합니다. 비밀번호 자체는 전파에 실리지 않지만, 이 과정을 캡처해 두면 오프라인에서 비밀번호를 대입해 볼 수 있으므로(WPA2-PSK 한정) 길고 복잡한 비밀번호가 중요합니다.

> **보안 유의 — KRACK 공격** KRACK(Key Reinstallation Attack, 2017)은 4-Way Handshake의 세 번째 메시지가 무선 구간에서 유실될 수 있어 AP가 재전송하도록 설계된 점을 악용합니다. 공격자가 이 메시지의 재전송을 유도하면 단말이 이미 설치한 PTK를 다시 ‘재설치’하는데, 이때 논스(PN)와 재전송 카운터가 초기값(0)으로 되돌아갑니다. CCMP의 안전성은 ‘같은 키로 같은 논스를 두 번 쓰지 않는다’는 전제에 있는데, 이 전제가 깨지며 동일한 키스트림이 재사용되어 공격자가 키스트림 역산·패킷 위조를 시도할 수 있습니다. 4-Way Handshake(802.11i) 자체의 설계 결함이라 사실상 모든 WPA2 구현이 영향을 받았고, WPA3는 SAE와 PMF 의무화로 이를 구조적으로 차단합니다.
{: .prompt-warning }

**SAE(WPA3)** 는 WPA2-PSK의 구조적 약점 — 4-Way Handshake를 한 번만 캡처해 두면 오프라인에서 무제한 사전 대입이 가능한 점 — 을 없애기 위해 도입되었습니다. SAE는 Dragonfly 키 교환에 기반한 **PAKE**[^pake] 방식으로, 비밀번호를 타원곡선 위의 점으로 변환한 뒤 단말·AP가 임시 값을 주고받아 공유 비밀을 계산합니다. 이 과정을 도청해도 비밀번호를 역산할 단서가 없고, 추측하려면 매번 AP와 실제 통신을 주고받아야(온라인) 해서 시도 횟수가 제한·탐지됩니다. 또한 세션마다 임시(Ephemeral) ECDHE[^ecdhe] 키를 새로 만들어 **순방향 비밀성**을 제공합니다 — 나중에 비밀번호가 유출되어도 예전에 저장해 둔 암호문을 거슬러 해독할 수 없습니다(WPA2에서는 비밀번호 하나로 과거 트래픽까지 모두 복호화 가능했던 것과 대비).

**OWE(Enhanced Open)** 는 카페·공항의 개방형 Wi-Fi가 인증·암호화가 전혀 없어 같은 AP 이용자끼리 스니핑이 쉬운 문제를 보완합니다. 비밀번호 없이도 단말과 AP가 디피-헬먼 키 교환을 수행해 접속마다 다른 키를 만들어, ‘누가 접속했는가’ 인증은 없지만 이용자 간 상호 도청은 차단합니다.

| 구분 | 암호 알고리즘 | 키 관리 방식 | 주요 취약점·특징 |
|---|---|---|---|
| WEP | RC4 | 고정 키 + 24비트 IV(재사용) | CRC-32 무결성, IV 재사용으로 키 복구 — 사용 금지 |
| WPA(TKIP) | RC4 | Per-packet Key Mixing | MIC(Michael) 무결성, 과도기 — 폐기 |
| WPA2(CCMP) | AES(CTR+CBC-MAC) | 48비트 PN 기반 Nonce | 안정적 표준(단, KRACK은 핸드셰이크 결함) |
| WPA3(SAE) | AES(CCMP-128/GCMP-256) | Dragonfly PAKE + 세션별 ECDHE | 오프라인 대입 차단, 순방향 비밀성 — 최고 보안 |

_표 6-6. 무선 LAN 암호화 방식의 종합 비교_

한편 같은 CCMP·SAE를 쓰더라도 키를 어떻게 확립하느냐에 따라 개인용(PSK)과 기업용(Enterprise)으로 나뉩니다. 가정은 미리 공유한 비밀번호 하나로, 기업은 IEEE 802.1X와 사용자별 계정으로 중앙 인증합니다.

| 구분 | 개인용(WPA-PSK) | 기업용(Enterprise) |
|---|---|---|
| 인증 방식 | 미리 공유한 키(PSK) | 802.1X + 중앙 인증 서버(RADIUS[^radius]) |
| 사용자 구분 | 모두 같은 키 공유 | 사용자별 계정·인증서로 개별 인증 |
| 보안 수준 | 낮음(공유·유출 시 전체 위험) | 높음(개별 인증·감사, 퇴사자만 선택 차단) |

### (3) 무선 LAN 인증 — 802.1X와 EAP

SSID 은닉과 MAC 필터링은 가장 기초적인 접근 제어이지만 쉽게 우회되므로, 기업 환경에서는 **802.1X** 기반 중앙 인증을 씁니다. **EAP(Extensible Authentication Protocol)** 는 인증서·ID/패스워드·일회용 암호 등 다양한 방식을 담을 수 있는 확장형 인증 프레임워크이고, 802.1X는 이 EAP로 ‘포트 기반 접근 제어’를 구현한 표준입니다.

| 구성요소 | 역할 |
|---|---|
| 서플리컨트(Supplicant) | 인증을 요청하는 클라이언트 단말 |
| 인증자(Authenticator) | 인증 요청을 서버에 전달하고 포트를 차단·개방하는 AP·스위치 |
| 인증 서버 | 실제 인증을 수행하는 RADIUS 서버 |

_표 6-8. 802.1X 인증 시스템의 구성요소_

인증자는 인증 전에는 포트를 ‘비인가 상태’로 두어 인증용 EAPOL 프레임만 통과시키고, 인증에 성공하면 포트를 ‘인가 상태’로 전환해 일반 트래픽을 허용합니다. 이처럼 ‘포트 자체를 열고 닫는’ 방식이라 인증되지 않은 단말은 패킷 한 조각도 내부로 들여보낼 수 없습니다.

![그림 6-8. 802.1X 인증 시스템의 구조](/assets/img/posts/2026-03-09-netintro-c6-10.png)
_그림 6-8. 802.1X 인증 시스템의 구조_

| EAP 유형 | 인증서 요구 | 특징 |
|---|---|---|
| EAP-TLS | 서버·클라이언트 양쪽 | 상호 인증서 기반 가장 강력. 단말마다 인증서 배포 부담 |
| EAP-TTLS | 서버에만 | TLS 터널 안에서 PAP·CHAP·MSCHAPv2 등 레거시 방식까지 수행 |
| PEAP | 서버에만 | TLS 터널 안에서 또 다른 EAP(주로 MSCHAPv2) 수행. Windows 기본 내장, 실무에서 가장 널리 쓰임 |

_표 6-9. 주요 EAP 유형의 비교_

EAP-TLS는 양쪽 모두 인증서로 상호 인증해 패스워드 공격이 원천 불가능하지만 PKI 운영 부담이 큽니다. EAP-TTLS·PEAP는 서버 인증서 하나로 터널을 만든 뒤 기존 ID/패스워드로 내부 인증해 도입이 쉽지만, 단말이 서버 인증서를 제대로 검증하지 않으면 가짜 AP·가짜 서버로 중간자 공격을 당해 터널 안의 ID/패스워드가 새어 나갈 수 있으므로, 반드시 신뢰할 서버 인증서를 지정해 검증해야 합니다.

### (4) 무선 보안 시스템

**WIPS(Wireless Intrusion Prevention System)** 는 무선 공간의 전파를 실시간 모니터링해 비인가 AP·Ad-Hoc 연결·무선 해킹을 탐지하고, 무선 연결 차단 패킷으로 방어하는 시스템입니다. **MAC 무작위화**는 스마트폰이 AP를 탐색할 때 실제 MAC 대신 임의의 가상 MAC을 사용해, MAC 수집을 통한 위치 추적을 막는 최신 프라이버시 보호 기술입니다.

여기까지 무선 기반 기술, 블루투스, 무선 LAN의 암호화·인증을 살펴보았습니다. 다음 편에서는 유·무선이 만나는 **WAP·WTLS·WAP2**, 디바이스 인증과 RFID, 그리고 iOS·안드로이드와 BYOD 같은 모바일 보안·통제 기술을 다룹니다.

[^rc4]: RC4. 1987년 개발된 스트림 암호. 빠르지만 여러 취약점이 발견되어 현재는 안전하지 않은 것으로 간주된다.
[^aes]: AES(Advanced Encryption Standard). 미국 표준으로 채택된 블록 암호로, 오늘날 가장 널리 쓰이는 안전한 대칭키 암호.
[^iv]: IV(Initialization Vector, 초기화 벡터). 같은 키로 암호화해도 매번 다른 결과가 나오도록 섞어 주는 값. 짧거나 반복되면 암호가 뚫린다.
[^nonce]: 논스(Nonce). ‘한 번만 쓰는 값(number used once)’. 재사용하면 안 되는 일회성 숫자.
[^pake]: PAKE(Password-Authenticated Key Exchange). 비밀번호를 노출하지 않고 그 비밀번호를 아는지 확인하며 세션 키를 만드는 방식.
[^ecdhe]: ECDHE(Elliptic Curve Diffie-Hellman Ephemeral). 타원곡선 기반의 임시 키 교환. 세션마다 새 키를 만들어 순방향 비밀성을 제공.
[^radius]: RADIUS. 사용자 계정을 중앙에서 인증·인가·과금(AAA)하는 서버 프로토콜. 기업 무선·원격 접속 인증에 널리 쓰인다.
