> **학습목표**
> 1. 랜카드·허브·브리지·스위치·라우터·게이트웨이의 역할과 동작 계층을 설명할 수 있다.
> 2. 충돌 도메인과 브로드캐스트 도메인의 개념을 이해하고, 장비별로 어떻게 나뉘는지 설명할 수 있다.
> 3. L2·L3·L4·L7 스위치의 차이와 스위칭 방식(Store-and-Forward 등)을 구분할 수 있다.
> 4. 브리지·스위치의 5대 기능과 SPAN·TAP 등 모니터링 장비를 설명할 수 있다.
> 5. 각 장비를 OSI 계층별로 분류하고 서로의 차이점을 비교할 수 있다.
{: .prompt-info }

앞선 장에서 프로토콜과 주소 체계, 라우팅 원리를 배웠다면, 4장에서는 그 통신을 실제로 담당하는 물리적 장비들을 살펴봅니다. 각 장비가 OSI의 어느 계층에서 동작하는지, 그리고 ‘충돌 도메인’과 ‘브로드캐스트 도메인’을 어떻게 나누는지를 기준으로 이해하면 장비 간 차이가 선명하게 보입니다.

먼저 두 도메인을 알아 둡니다. **충돌 도메인(Collision Domain)** 은 한 장비가 신호를 보낼 때 서로 충돌할 수 있는 범위로, 좁을수록 좋습니다. **브로드캐스트 도메인(Broadcast Domain)** 은 하나의 브로드캐스트가 도달하는 범위로, 너무 넓으면 불필요한 트래픽이 많아집니다. 허브(전체가 하나의 충돌 도메인) → 스위치(포트별 충돌 도메인 분리) → 라우터(브로드캐스트 도메인까지 분리)로 갈수록 도메인이 잘게 나뉩니다.

## 1. 랜카드 (NIC)

**랜카드(NIC, Network Interface Card)** 는 컴퓨터를 네트워크에 연결해 주는 가장 기본적인 장치로, OSI 1~2계층에 걸쳐 동작합니다. 컴퓨터 내부의 병렬 데이터를 전송 매체에 맞는 직렬 신호로(또는 그 반대로) 변환하고, 상위에서 내려온 데이터를 프레임으로 만들며, 제조 시 새겨진 고유의 MAC 주소로 자신에게 온 프레임만 걸러 받습니다. 또한 매체 접근 제어(유선 CSMA/CD, 무선 CSMA/CA)를 수행해 언제 신호를 보낼지 조율합니다.

> **보안 유의 — 프로미스큐어스 모드** 랜카드는 원래 자신의 MAC으로 온 프레임만 받아들이지만, 프로미스큐어스(Promiscuous, 무차별) 모드로 바꾸면 지나가는 모든 프레임을 수신합니다. 패킷 분석 도구(Wireshark)가 이 모드를 이용하며, 공격자의 스니핑도 같은 원리로 동작합니다.
{: .prompt-warning }

## 2. 허브 (Hub)

허브는 여러 장비를 하나로 모아 연결하는 **1계층(물리)** 장비로, 특정 포트로 들어온 신호를 해석하지 않고 단순히 증폭·재생해 자신을 제외한 모든 포트로 그대로 내보냅니다. 신호의 ‘내용’은 전혀 보지 않고 ‘전기 신호’만 다룹니다. 참고로 **리피터(Repeater)** 는 거리가 길어져 약해진 신호를 증폭·재생하는 1계층 장비로, 허브는 곧 여러 포트를 가진 리피터(다중 포트 리피터)입니다.

허브에 연결된 모든 장비는 **하나의 충돌 도메인**을 공유하므로 장비가 많아질수록 충돌이 잦아지고 대역폭도 나누어 쓰므로 성능이 떨어집니다. 또 들어온 신호를 전 포트로 뿌리기 때문에 다른 장비의 통신을 엿볼 수 있어 보안에도 취약합니다. 허브 전체가 하나의 충돌 도메인이자 하나의 브로드캐스트 도메인이며, 반이중으로 동작합니다. 이런 한계 때문에 오늘날은 스위치로 대체되었습니다.

## 3. 브리지 (Bridge)

브리지는 둘 이상의 네트워크 세그먼트를 연결하는 **2계층(데이터 링크)** 장비입니다. 허브가 신호만 다루는 것과 달리, 브리지는 프레임의 MAC 주소를 읽어 전달할지 막을지 판단합니다. MAC 주소 테이블을 스스로 학습해, 프레임이 들어오면 출발지 MAC과 들어온 포트를 기록해 두었다가, 목적지 MAC이 같은 세그먼트에 있으면 막고(필터링) 다른 세그먼트에 있으면 전달합니다(포워딩). 이렇게 세그먼트를 나누어 **충돌 도메인을 분리**하지만, 브로드캐스트 프레임은 그대로 통과시키므로 브리지로 연결된 전체는 여전히 하나의 브로드캐스트 도메인입니다. 오늘날의 스위치는 이 브리지를 하드웨어로 고속화한 발전형입니다.

## 4. 스위치 (Switch)

스위치는 브리지를 하드웨어(ASIC)로 구현해 고속화한 **2계층** 장비로, MAC 주소를 기반으로 프레임을 목적지 포트로만 정확히 보냅니다. 각 포트가 독립된 충돌 도메인을 가져 포트마다 전용 대역폭을 쓰고 전이중 통신이 가능하지만, 브로드캐스트는 모든 포트로 전달하므로 브로드캐스트 도메인은 기본적으로 하나이며 이를 나누려면 VLAN(5장)을 씁니다.

### (1) 계층에 따른 분류

- **L2 스위치**: 2계층 MAC 주소를 기준으로 전달. 빠르고 저렴하지만 브로드캐스트 도메인을 나누지 못해 VLAN이 필요합니다.
- **L3 스위치**: L2 스위칭에 3계층 IP 라우팅을 결합. 라우팅을 하드웨어(ASIC) 중심으로 처리해 일반 라우터보다 훨씬 빠르며, VLAN 간 라우팅에 널리 쓰입니다.
- **L4 스위치**: 4계층 TCP/UDP 포트 번호까지 보고 트래픽을 분배. 대표 용도는 서버 부하 분산(SLB)이며, 세션 유지·헬스 체크 기능을 갖춥니다.
- **L7 스위치**: 7계층의 URL·쿠키·HTTP 헤더 같은 실제 내용까지 들여다보고 분배하는 가장 지능적인 스위치. 콘텐츠 기반 분배와 공격 패턴 차단(웹 방화벽에 준하는 역할)까지 수행합니다.

| 구분 | L4 스위치 | L7 스위치 |
|---|---|---|
| 판단 기준 | TCP/UDP 포트 번호 | URL·쿠키·HTTP 헤더 등 응용 내용 |
| 분석 깊이 | 헤더 수준 | 페이로드(내용)까지 |
| 대표 기능 | 포트 기반 부하 분산 | 콘텐츠 기반 분배, 보안 필터링 |
| 부하/정교함 | 가볍고 빠름 | 무겁지만 정교함 |

_표 4-1. L4 스위치와 L7 스위치의 비교_

### (2) 브리지·스위치의 5대 기능

| 기능 | 동작 |
|---|---|
| Learning(학습) | 수신 프레임의 출발지 MAC과 포트를 주소 테이블에 기록 |
| Flooding(플러딩) | 목적지 MAC을 모르거나 브로드캐스트일 때, 수신 포트를 뺀 모든 포트로 전송 |
| Forwarding(전달) | 목적지 MAC을 알고 있으면 해당 포트로만 전달 |
| Filtering(필터링) | 목적지가 출발지와 같은 세그먼트에 있으면 차단 |
| Aging(에이징) | 일정 시간 사용되지 않은 MAC 항목을 테이블에서 삭제 |

_표 4-2. 브리지·스위치의 5대 기능_

트래픽 모니터링에는 두 방법이 있습니다. **SPAN 포트**(포트 미러링)는 스위치의 특정 포트·VLAN을 지나는 트래픽을 다른 포트로 복사해 분석 장비나 IDS에 연결하는 기능으로, 설정만으로 가능하지만 부하가 높으면 일부 패킷이 누락될 수 있습니다. **TAP 장비**는 회선 중간에 물리적으로 끼워 트래픽을 그대로 복사하는 별도 장비로, 스위치 자원을 쓰지 않아 부하가 없고 누락 없이 원본을 얻어 정밀 분석에 적합합니다.

### (3) 스위칭 방식 3종

스위치는 프레임을 ‘언제’ 전달하기 시작하는가에 따라 나뉩니다.

| 방식 | 전달 시점 | 오류 검사 | 지연/신뢰성 |
|---|---|---|---|
| Store-and-Forward | 프레임 전체 수신 후 | 함(FCS 검사) | 지연 큼 / 신뢰성 높음 |
| Cut-Through | 목적지 MAC(6바이트) 확인 후 | 안 함 | 지연 최소 / 신뢰성 낮음 |
| Fragment-Free | 앞 64바이트 수신 후(512비트) | 충돌 조각만 거름 | 중간 / 중간(절충) |

_표 4-3. 스위칭 방식 3종의 비교_

대부분의 충돌은 프레임 앞 64바이트 안에서 발생하므로, Fragment-Free는 충돌로 깨진 조각을 걸러내면서도 전체를 기다리지 않아 속도와 신뢰성을 절충합니다.

> **참고 — 스위치 이중화와 스패닝 트리** 안정성을 위해 스위치를 이중으로 연결하면 2계층에 루프가 생겨 브로드캐스트 폭풍이 일어납니다. 이를 막는 것이 3장에서 소개한 스패닝 트리 프로토콜(STP)로, 논리적으로 트리 하나만 남기고 나머지 경로를 차단해 두었다가 장애 시 살려 냅니다.
{: .prompt-info }

## 5. 라우터 (Router)

라우터는 서로 다른 네트워크를 연결하고 IP 주소를 기준으로 경로를 선택하는 **3계층(네트워크)** 장비입니다. 3장에서 배운 라우팅이 바로 이 장비의 핵심 기능이며, L3 스위치가 하드웨어 중심으로 속도에 집중한다면 라우터는 소프트웨어 기반 처리로 다양한 WAN 인터페이스와 정책을 유연하게 다룹니다.

| 구분 | 브리지/스위치 | 라우터 |
|---|---|---|
| 동작 계층 | 2계층(데이터 링크) | 3계층(네트워크) |
| 판단 기준 | MAC 주소 | IP 주소 |
| 충돌 도메인 | 포트별로 분리 | 인터페이스별로 분리 |
| 브로드캐스트 도메인 | 분리 못 함(하나) | 분리함(차단) |
| 처리 방식 | 하드웨어 중심(고속) | 소프트웨어 중심(유연) |

_표 4-4. 브리지·스위치와 라우터의 차이_

라우터의 주요 역할은 세 가지입니다. **브로드캐스트 차단**(브로드캐스트를 다른 네트워크로 통과시키지 않아 도메인을 분리), **접근 통제**(ACL로 특정 패킷을 허용·차단하는 기본 방화벽 역할), **네트워크 변경 정보 확인**(라우팅 프로토콜로 경로 변화를 감지해 테이블을 자동 갱신).

## 6. 게이트웨이 (Gateway)

게이트웨이는 서로 다른 프로토콜이나 구조를 가진 네트워크를 이어 주는 장비 또는 개념입니다. 앞의 장비들이 주로 하위 계층에서 동작하는 것과 달리, 게이트웨이는 필요하면 응용 계층까지 올라가 프로토콜 자체를 변환합니다(이메일 게이트웨이, VoIP 게이트웨이 등).

> **용어 참고 — 기본 게이트웨이** 넓은 의미의 게이트웨이는 프로토콜 변환 장비를 뜻하지만, 네트워크 설정에서 자주 보는 ‘기본 게이트웨이(Default Gateway)’는 내 네트워크 밖으로 나갈 때 거치는 라우터를 가리키는 좁은 의미로 쓰입니다.
{: .prompt-info }

> **참고 — 보안 장비도 계층으로 이해한다** 보안 장비도 같은 눈으로 볼 수 있습니다. 패킷의 IP·포트를 보고 차단하는 방화벽은 3~4계층에서, 트래픽 내용까지 검사하는 IDS/IPS와 웹 방화벽(WAF)은 7계층까지 다룹니다. ‘어느 계층의 정보를 보고 판단하는가’라는 이 장의 기준은 보안 장비에도 그대로 통합니다.
{: .prompt-info }

## 7. 계층별 장비 분류 정리

| 계층 | 장비 | 판단 기준 | 충돌/브로드캐스트 도메인 |
|---|---|---|---|
| 1계층(물리) | 허브, 리피터 | 전기 신호 | 둘 다 분리 못 함 |
| 2계층(데이터 링크) | 브리지, 스위치, 랜카드 | MAC 주소 | 충돌만 분리(브로드캐스트는 하나) |
| 3계층(네트워크) | 라우터, L3 스위치 | IP 주소 | 둘 다 분리 |
| 4계층(전송) | L4 스위치 | 포트 번호 | — |
| 7계층(응용) | L7 스위치, 게이트웨이 | 응용 데이터(URL 등) | — |

_표 4-5. OSI 계층별 네트워크 장비 분류_

핵심은 **‘충돌은 스위치가, 브로드캐스트는 라우터가 나눈다’** 는 것입니다. 도메인 개수를 직접 세어 보면 분명해집니다. 허브 1대에 PC 4대가 붙으면 충돌 도메인도 브로드캐스트 도메인도 각각 1개(모두 공유)입니다. 허브를 스위치로 바꾸면 포트마다 충돌 도메인이 생겨 충돌 도메인은 4개가 되지만 브로드캐스트 도메인은 여전히 1개입니다. 여기에 라우터를 두어 네트워크를 둘로 나누면 비로소 브로드캐스트 도메인이 2개로 나뉩니다.

## 8. 실습

> **실습 4-1. 허브와 스위치의 차이 관찰**  
> **실습 목표** 허브와 스위치가 프레임을 처리하는 방식(무조건 복제 vs 학습 후 전달)의 차이를 시뮬레이션으로 비교한다.  
> **주소 계획** 각 세트 PC 3대 = `192.168.10.1 ~ .3 / 255.255.255.0`
{: .prompt-tip }

**실습 절차**

1. 허브(Hub-PT) 1대에 PC 3대를 연결하고 IP를 설정한다.
2. `[Simulation]` 모드에서 PC0 → PC1로 ping을 보내고, 프레임이 허브에 연결된 모든 PC로 퍼지는 것을 관찰한다.
3. 같은 구성을 스위치(2960)로 바꿔 반복한다.
4. 스위치에서는 첫 프레임만 퍼지고, MAC 학습 이후에는 목적지(PC1)에게만 전달됨을 관찰한다.

> **결과 확인** 허브는 항상 모든 포트로, 스위치는 학습 후 목적지 포트로만 보냄을 확인하면 완료.  
> **계층 짚기** 허브(1계층)는 신호를 무조건 복제하고, 스위치(2계층)는 MAC을 보고 판단한다 — 충돌 도메인 분리의 차이다.
{: .prompt-tip }

![실습 4-1. 허브와 스위치의 프레임 처리 차이](/assets/img/posts/2026-03-09-netintro-c4-01.png)

> **실습 4-2. 스위치 포트 보안 (Port Security)**  
> **실습 목표** 스위치 포트에 연결 가능한 MAC 수를 제한하고, 위반 시 포트를 차단해 비인가 단말의 연결을 막는다.  
> **주소 계획** 정상 PC = `192.168.10.10`, 침입 PC = `192.168.10.99`(모두 255.255.255.0)
{: .prompt-tip }

**실습 절차**

1. 스위치에 정상 PC를 연결하고 해당 포트를 액세스 모드로 둔다: `interface f0/1 → switchport mode access`.
2. 포트 보안을 켜고 최대 MAC 수·위반 정책·자동 학습을 설정한다.

    ```text
    switchport port-security
    switchport port-security maximum 1
    switchport port-security violation shutdown
    switchport port-security mac-address sticky
    ```

3. 정상 PC로 통신을 한 번 일으켜 MAC이 sticky로 학습되게 한다.
4. 정상 PC를 떼고 침입 PC를 같은 포트에 연결한 뒤 통신을 시도한다.
5. `show port-security interface f0/1`로 포트가 `err-disabled`로 차단되었는지 확인한다(복구: 해당 인터페이스에서 `shutdown` 후 `no shutdown`).

> **결과 확인** 등록된 MAC은 정상 통신하고, 다른 MAC이 연결되면 포트가 차단되면 성공.  
> **계층 짚기** MAC(2계층)을 기준으로 포트 단위 접근을 통제하는 스위치의 기본 보안 기능이다.
{: .prompt-tip }

> **실습 4-3. 라우터 ACL — 트래픽 필터링**  
> **실습 목표** 라우터에 접근 제어 목록(ACL)을 걸어 특정 트래픽만 허용하거나 차단한다.  
> **주소 계획** LAN1 `192.168.10.0/24`, LAN2 `192.168.20.0/24`(실습 3-1과 동일)
{: .prompt-tip }

**실습 절차**

1. 실습 3-1(또는 OSPF) 상태에서 PC0(LAN1)과 PC1(LAN2)이 서로 ping되는 것을 확인한다.
2. R2에서 특정 호스트만 막는 표준 ACL을 만든다: `access-list 10 deny host 192.168.10.1` → `access-list 10 permit any`.
3. 이 ACL을 LAN2로 나가는 방향에 적용한다: `interface g0/0 → ip access-group 10 out`.
4. PC0(`192.168.10.1`)에서 PC1로 ping이 차단되고, LAN1의 다른 호스트는 통과함을 확인한다.
5. `show access-lists`로 규칙과 매칭 횟수(hit count)를 확인한다.

> **결과 확인** 지정한 호스트만 차단되고 나머지는 정상 통신하면 완료. 확장 ACL을 쓰면 포트·프로토콜 단위로도 제어할 수 있다.  
> **계층 짚기** ACL은 IP·포트(3~4계층)를 기준으로 패킷을 걸러내는 기본 방화벽이다. 라우터의 접근 통제 역할을 직접 구현했다.
{: .prompt-tip }
