## 1. 물리 계층

### (1) 개요

물리 계층(Physical Layer)은 TCP/IP 구조의 가장 아래 계층으로, 상위에서 내려온 비트를 실제 전송 매체에 실어 나릅니다. 전송 매체의 종류(구리선·광섬유·전파), 신호 방식, 데이터 전송률(bps), 커넥터·케이블의 물리적 규격을 다루며, 데이터의 내용이나 의미에는 관여하지 않고 오직 ‘어떻게 신호를 안전하게 전달할 것인가’만 책임집니다.

### (2) 데이터와 신호의 개념

데이터(Data)는 우리가 전달하려는 정보 그 자체이고, 신호(Signal)는 그 데이터를 전송 매체에 실어 보내기 위한 물리적 형태 — 전압의 높낮이·빛의 밝기·전파의 파형 — 입니다. 컴퓨터 안에서 0과 1의 비트로 표현된 데이터는 그대로는 케이블을 지날 수 없으므로 신호로 바꾸어야 하며, 이 과정을 인코딩(디지털) 또는 변조(아날로그)라고 합니다.

| 구분 | 데이터(Data) | 신호(Signal) |
|---|---|---|
| 정의 | 전달하려는 정보 자체 | 매체를 통해 전파되는 물리적 파형 |
| 예 | 문자, 숫자, 이미지의 비트열 | 전압 변화, 빛 펄스, 전자기파 |
| 존재 위치 | 컴퓨터·저장장치 내부 | 전송 매체(케이블·공기) 위 |

### (3) 아날로그와 디지털의 개념

아날로그(Analog)는 시간에 따라 값이 연속적으로, 끊김 없이 변하는 것(사람의 목소리, 전통적인 전화 음성)이고, 디지털(Digital)은 값이 불연속적으로 정해진 몇 개의 단계(대개 0과 1)로만 변하는 것(컴퓨터가 다루는 모든 데이터)입니다. 아날로그는 표현할 수 있는 값이 무한하지만 잡음에 약하고, 디지털은 값이 이산적이어서 잡음이 섞여도 원래 값으로 복원하기 쉽습니다. 오늘날 네트워크가 대부분 디지털 방식을 쓰는 이유가 여기에 있습니다.

| 구분 | 아날로그 | 디지털 |
|---|---|---|
| 값의 변화 | 연속적(끊김 없음) | 이산적(0, 1 등 단계별) |
| 표현 가능 값 | 무한 | 유한(정해진 상태) |
| 잡음 내성 | 약함(왜곡 누적) | 강함(원래 값 복원 용이) |
| 예시 | 사람 목소리, 아날로그 전화 | 컴퓨터 데이터, 디지털 통신 |

_표 2-2. 아날로그와 디지털의 비교_

### (4) 전송 매체

신호가 실제로 지나가는 길이 전송 매체입니다. 케이블을 쓰는 유도 매체와 공기 중 전파를 쓰는 비유도 매체로 나뉘며, 어떤 매체를 쓰느냐가 속도·거리, 그리고 도청의 난이도(보안)까지 좌우합니다.

- **트위스티드 페어(Twisted Pair)**: 두 가닥 구리선을 꼬아 간섭을 줄인 케이블로, 오늘날 LAN 배선의 표준입니다. 차폐가 없는 UTP와 차폐를 더한 STP가 있으며, 등급에 따라 Cat5e(1Gbps)·Cat6(10Gbps) 등으로 나뉩니다. RJ-45 커넥터를 씁니다.
- **동축 케이블(Coaxial)**: 중심 도체를 절연체·차폐막이 감싼 구조로 간섭에 강합니다. 초기 이더넷(10BASE5/10BASE2)과 케이블 TV망에 쓰였습니다.
- **광섬유(Optical Fiber)**: 전기가 아닌 빛으로 데이터를 보냅니다. 대역폭이 압도적으로 크고 전자기 간섭이 없으며 도청이 어려워, 장거리 백본과 고속 구간에 씁니다.
- **무선(전파)**: 케이블 없이 공기 중 전파로 신호를 보냅니다. 이동성이 뛰어나지만 전파가 공간에 개방되어 있어 도청·간섭에 근본적으로 취약합니다. 이 특성이 6장 무선통신보안의 출발점입니다.

## 2. 데이터 링크 계층

### (1) 개요

데이터 링크 계층(Data Link Layer)은 물리적으로 연결된 이웃 노드 사이에서 비트를 프레임 단위로 묶어 오류 없이 전달합니다(Link to Link 전달). 물리 계층이 신호를 ‘보내는 것’까지라면, 데이터 링크 계층은 바로 옆 장비까지 ‘정확하게’ 전달하는 것을 책임집니다. 이를 위해 물리 주소(MAC)를 사용하고, 오류 검출과 흐름 조절을 수행합니다.

### (2) 노드와 링크

노드(Node)는 네트워크에 연결되어 통신에 참여하는 장치(PC·서버·라우터)이고, 링크(Link)는 두 노드를 잇는 통신 경로입니다. 링크는 하나의 노드와 하나의 노드를 직접 잇는 점대점(Point-to-Point) 링크와, 여러 노드가 하나의 매체를 공유하는 브로드캐스트(Broadcast) 링크로 나뉩니다. 이렇게 하나의 통신 선로를 여러 장치가 나누어 쓰는 다중점(Multipoint) 환경에서는 데이터 충돌이 생길 수 있어, 주소를 구별하고 회선 접근 차례를 제어하는 규칙(MAC)이 핵심적으로 작용합니다.

![그림 2-2. 다중점 환경의 통신 선로 공유](/assets/img/posts/2026-03-09-netintro-c2-06.png)
_그림 2-2. 다중점 환경의 통신 선로 공유_

이런 회선 공유(Shared Medium) 환경에서는 링크의 대역폭을 나누어 쓰고, 데이터를 보낼 때 “누가 누구에게” 보내는지 명확히 하기 위해 프레임 헤더에 출발지·목적지 MAC 주소가 반드시 포함되어야 합니다. 대신 장치마다 독립된 회선을 깔 필요가 없어 구축·유지보수 비용이 크게 절감됩니다.

### (3) 매체 접근 제어(MAC)와 CSMA/CD

여러 장치가 동시에 데이터를 전송하면 충돌(Collision)이 발생합니다. 이를 제어하기 위해 회선이 비었는지 확인하고 선점하는 **경쟁 방식**(CSMA/CD·CSMA/CA), 주 장치가 차례로 송신 권한을 주는 **폴링 방식**, ‘토큰’을 가진 장치만 송신하는 **토큰 패싱**을 씁니다.

이 가운데 초기 버스형·허브 기반 이더넷에서 쓴 것이 **CSMA/CD**(Carrier Sense Multiple Access with Collision Detection)입니다. 절차는 이렇습니다. 먼저 프레임을 보내기 전 회선이 사용 중인지 확인하고(반송파 감지), 비어 있으면 전송합니다. 여러 장치가 같은 매체에서 이 규칙을 동시에 따르는데(다중 접근), 신호 전달 지연 때문에 두 장치가 거의 동시에 전송을 시작하면 충돌이 날 수 있으므로 송신 중에도 회선 전압을 감시합니다(충돌 검출). 충돌을 감지하면 즉시 멈추고 잼(Jam) 신호를 보내 다른 장치에도 알린 뒤, 임의의 시간만큼 기다렸다 재전송합니다. 이때 충돌이 반복될수록 대기 시간 범위를 지수적으로 늘리는 **이진 지수 백오프**로 재충돌 확률을 낮춥니다.

오늘날 스위치 기반의 전이중(Full-Duplex) 이더넷은 송신·수신 회선이 분리되어 충돌 자체가 일어나지 않으므로 CSMA/CD가 사실상 쓰이지 않습니다. 다만 허브를 사용하는 반이중(Half-Duplex) 환경의 동작 원리를 이해하는 데는 여전히 중요합니다. 오늘날에도 하나의 액세스 포인트(AP)에 여러 단말이 공기라는 공유 매체로 통신하는 Wi-Fi가 대표적인 공유 매체 환경입니다.

### (4) LLC와 MAC 부계층

IEEE 802 위원회는 데이터 링크 계층을 **LLC**(Logical Link Control, IEEE 802.2)와 **MAC**(Media Access Control) 두 부계층으로 나누어 표준화했습니다. 이더넷·무선랜처럼 매체별 접속 방식(MAC)은 저마다 다르지만, 상위 네트워크 계층과 주고받는 방식(LLC)은 공통으로 유지하기 위해서입니다. LLC는 프레임에 실린 데이터가 IP인지 ARP인지 등 상위 프로토콜을 구분하는 역할(다중화)을 하지만, TCP/IP 이더넷에서는 타입(Type) 필드로 상위 프로토콜을 직접 식별하는 경우가 많아 존재감이 약합니다. MAC 부계층은 실제로 프레임을 만들어 전송하고, 공유 매체 접근 권한을 제어하며, MAC 주소로 프레임을 목적지까지 전달합니다.

### (5) MAC 주소의 구조

MAC 주소는 네트워크 인터페이스(랜카드)에 하드웨어적으로 부여되는 48비트(6바이트) 고유 식별자로, 1바이트씩 16진수 두 자리로 표기하고 콜론(:)이나 하이픈(-)으로 구분합니다(예: `00:1A:2B:3C:4D:5E`). 앞쪽 24비트는 **OUI**(제조사 식별 코드), 뒤쪽 24비트는 제조사가 부여하는 일련번호라, 이 조합 덕분에 전 세계 모든 랜카드의 MAC 주소가 이론상 중복 없이 유일합니다. 첫 번째 바이트의 최하위 비트(I/G 비트)는 유니캐스트(0)인지 멀티캐스트(1)인지 구분하며, 모든 비트가 1인 `FF:FF:FF:FF:FF:FF`는 브로드캐스트 주소로 네트워크의 모든 장치에 전달됩니다. Windows에서는 `ipconfig /all`, Linux에서는 `ip link`로 자신의 MAC 주소를 확인할 수 있습니다.

### (6) 데이터 링크 계층의 서비스

데이터 링크 계층이 상위에 제공하는 서비스는 네 가지입니다.

- **프레이밍**: 프레임(Frame)은 상위에서 내려온 패킷 앞뒤에 헤더와 트레일러[^trailer]를 붙인 것으로, 연속된 비트 스트림을 수신 측이 구분하도록 시작·끝을 표시합니다. 경계를 나타내기 위해 특정 비트 패턴이 데이터에 우연히 나타나는 것을 막는 **비트 스터핑**(1이 5개 연속되면 뒤에 0을 강제 삽입)과 **바이트 스터핑**(플래그·제어 문자 앞에 이스케이프 문자를 삽입)을 씁니다. 이렇게 하면 사용자가 어떤 비트 패턴을 보내도 안전하게 전달되는 **데이터 투명성**이 확보됩니다.
- **흐름 제어(Flow Control)**: 송신자가 너무 빨리 보내 수신자 버퍼가 넘치는 것을 막습니다. 하나 보내고 응답을 기다리는 정지-대기(Stop-and-Wait), 응답을 기다리지 않고 연속 전송하는 슬라이딩 윈도우 방식이 있습니다.
- **오류 제어(Error Control)**: 손상·손실 프레임을 찾아 바로잡습니다. 패리티 비트·체크섬·CRC로 검출하고, 재전송을 요청하는 방식을 **ARQ**(자동 재전송 요구)라 합니다.
- **혼잡 제어**: 기본은 1:1 흐름 제어이지만, 스위치 버퍼 포화 시 프레임 폐기나 재전송 백오프 지연 등으로 네트워크 전체의 혼잡 완화에 간접적으로 기여합니다.

| 서비스 | 목적 | 대표 기법 |
|---|---|---|
| 프레이밍 | 비트 스트림을 프레임으로 구분 | 바이트/비트 채우기 |
| 흐름 제어 | 수신자 버퍼 넘침 방지 | 정지-대기, 슬라이딩 윈도우 |
| 오류 제어 | 손상·손실 프레임 검출·재전송 | 패리티, 체크섬, CRC, ARQ |
| 혼잡 제어 | 네트워크 과부하 방지 | 전송률 조절 |

_표 2-4. 데이터 링크 계층의 4가지 서비스_

### (7) 이더넷 프레임과 MTU

데이터 링크 계층의 실제 모습은 이더넷 프레임에서 가장 잘 드러납니다. 2계층 장비(4장)와 패킷 분석 실습에서 반복해 만나므로 구조를 익혀 둡니다.

| 필드 | 크기 | 역할 |
|---|---|---|
| 프리앰블 | 8바이트 | 프레임 시작을 알리고 송수신 동기를 맞춤 |
| 목적지·출발지 MAC | 각 6바이트 | 수신·송신 장비의 물리 주소(순서 유의) |
| 타입(Type) | 2바이트 | 상위 프로토콜 식별(IPv4=0x0800, ARP=0x0806) |
| 데이터(Payload) | 46~1500바이트 | 상위 계층에서 내려온 패킷 |
| FCS | 4바이트 | CRC 기반 오류 검출값(트레일러 자리의 공식 명칭) |

_표 2-5. 이더넷 프레임의 구조_

![그림 2-6. 이더넷 프레임의 구조](/assets/img/posts/2026-03-09-netintro-c2-10.png)
_그림 2-6. 이더넷 프레임의 구조_

> **참고 — MTU와 단편화** 데이터 필드의 최대 크기 1500바이트를 **MTU**(Maximum Transmission Unit)라 합니다. 이보다 큰 IP 패킷은 여러 조각으로 나뉘어 전송되는데(단편화), 다음 편에서 배우는 IP 헤더의 식별자·플래그·오프셋 필드가 존재하는 이유가 바로 이것입니다.
{: .prompt-info }

이더넷 표준 이름은 대체로 ‘속도-신호방식-매체’ 순서를 따릅니다. 예를 들어 `100BASE-TX`는 100Mbps 속도, 베이스밴드 신호 방식(BASE), UTP 케이블(TX)을 뜻합니다. 10BASE-T(10Mbps)에서 100BASE-TX(Fast Ethernet), 1000BASE-T(Gigabit)를 거쳐 오늘날 데이터센터·백본에서는 10GBASE-T 이상까지 쓰입니다. 또한 이더넷은 반이중과 전이중으로 나뉘는데, 허브를 쓰던 초기 반이중 환경에서는 CSMA/CD로 충돌을 관리해야 했지만, 스위치가 보편화된 오늘날 전이중 환경에서는 송신·수신 회선이 분리되어 충돌이 일어나지 않아 CSMA/CD가 사실상 비활성화됩니다.

![그림 2-7. 반이중 및 전이중 통신 비교](/assets/img/posts/2026-03-09-netintro-c2-11.png)
_그림 2-7. 반이중 및 전이중 통신 비교_

> **실습 2-2. 데이터 링크 계층 — 스위치의 MAC 주소 학습**  
> **실습 목표** 스위치가 프레임의 출발지 MAC을 학습해 MAC 주소 테이블을 채우는 과정을 관찰한다.  
> **주소 계획** PC0 `.1` / PC1 `.2` / PC2 `.3` (모두 255.255.255.0)
{: .prompt-tip }

**실습 절차**

1. 실습 2-1의 구성에 PC를 하나 더 붙여 PC 3대를 스위치에 연결하고, IP를 위 계획대로 설정한다.
2. 스위치를 클릭 → `[CLI]`에서 `show mac-address-table`을 입력해 테이블이 비어 있음을 확인한다.
3. PC0에서 `ping 192.168.10.2`로 PC1에 통신을 보낸다.
4. 다시 `show mac-address-table`을 입력해, 학습된 MAC 주소와 연결 포트를 확인한다.
5. `[Simulation]` 모드에서 ACL Filter를 ICMP만 선택하고, Play 버튼을 하나씩 누르며 패킷 이동을 확인한다. 첫 프레임은 모든 포트로 퍼지고(플러딩) 이후에는 해당 포트로만 전달됨을 볼 수 있다.

> **결과 확인** MAC 주소 테이블에 각 PC의 MAC과 포트가 나타나면 성공이다.  
> **계층 짚기** 스위치는 IP가 아니라 MAC(2계층 주소)으로 판단한다. 4장에서 다루는 스위치 동작의 핵심을 미리 확인한 것이다.
{: .prompt-tip }
