4강에서 스위치는 충돌 도메인은 나누지만 브로드캐스트 도메인은 나누지 못한다고 배웠습니다. **VLAN**은 바로 이 한계를 소프트웨어로 해결하는 기술입니다. 대회 도면의 본사·지사에는 층별·용도별 VLAN(사무실·음성)이 반드시 등장하므로, 이 강의 내용은 특히 중요합니다.

## 1. VLAN이란

**VLAN(Virtual LAN, 가상 랜)** 은 하나의 물리적 스위치를 논리적으로 여러 개의 LAN으로 나누는 기술입니다. 장비가 어느 포트에 꽂혀 있느냐와 상관없이, 관리자가 정한 기준으로 논리적인 그룹을 묶습니다. 같은 스위치에 있어도 다른 VLAN이면 직접 통신할 수 없고, 다른 스위치에 있어도 같은 VLAN이면 하나의 LAN처럼 통신합니다.

VLAN의 필요성을 제대로 이해하려면, VLAN이 **없는** 네트워크가 어떤 문제를 겪는지부터 봐야 합니다. 4강에서 배웠듯 스위치는 충돌 도메인은 포트마다 나누지만 **브로드캐스트 도메인은 나누지 못해, 스위치에 연결된 전체가 하나의 큰 네트워크**가 됩니다. 직원이 몇 명뿐일 때는 문제가 없지만, 회사가 커지면 세 가지 문제가 드러납니다.

**① 성능 — 브로드캐스트가 모두에게 퍼진다.** 2강에서 배운 ARP 요청이나 DHCP Discover 같은 브로드캐스트는 ‘네트워크 전체’에 뿌려집니다. 한 네트워크에 장비가 200대 있으면, 한 대가 보낸 브로드캐스트 하나를 나머지 199대가 모두 받아 처리해야 합니다. 장비가 늘수록 이런 트래픽이 쌓여 대역폭과 각 PC의 성능을 갉아먹고, 심하면 브로드캐스트가 폭주해 네트워크가 마비되기도 합니다(브로드캐스트 폭풍).

**② 보안 — 모두가 한 방에 있다.** 하나의 큰 네트워크에서는 모든 장비가 같은 2계층 공간에 있습니다. 회계팀 PC와 외부 방문객 PC가 논리적으로 같은 ‘방’에 있는 셈이라, 한 대가 악성코드에 감염되면 같은 네트워크의 다른 장비를 곧바로 노릴 수 있고, 4강에서 본 ARP 스푸핑 같은 공격도 같은 네트워크 안이라면 그대로 통합니다. 민감한 부서를 따로 떼어 놓을 방법이 없습니다.

**③ 관리 — 자리를 옮기면 배선을 바꿔야 한다.** 부서별로 네트워크를 나누고 싶어도 물리적 위치에 묶여 있습니다. 영업팀이 여러 층에 흩어져 앉아 있다면 이들을 하나로 묶기 위해 층마다 케이블을 따로 끌어와야 하고, 사람이 자리를 옮길 때마다 배선을 다시 해야 합니다.

VLAN이 없던 시절에는 이 문제들을 **물리적으로** 해결했습니다. 부서마다 스위치를 따로 사서 케이블로 분리하고, 그 사이를 라우터로 이은 것입니다. 하지만 이 방식은 스위치를 여러 대 사야 하고(비용), 자리 배치가 바뀔 때마다 배선을 손봐야 했습니다(경직성).

**VLAN은 바로 이 문제들을 ‘논리적으로’ 해결합니다.** 스위치 한 대 안에서 포트들을 소프트웨어로 그룹 지어, 마치 여러 대의 독립된 스위치가 있는 것처럼 나눕니다. 그러면 ① 브로드캐스트가 같은 그룹 안에만 퍼지고, ② 다른 그룹과는 기본적으로 통신이 차단되며, ③ 그룹을 케이블이 아니라 설정으로 정하므로 자리와 상관없이 묶을 수 있습니다. 요컨대 VLAN은 하나의 브로드캐스트 도메인을 논리적으로 여러 개로 쪼개어 **성능·보안·관리를 한꺼번에 개선**하는 기술입니다.

| 장점 | 설명 |
|---|---|
| 브로드캐스트 감소 | 브로드캐스트 도메인이 작아져 성능 향상 |
| 보안 향상 | VLAN 간 통신이 기본 차단되어 민감 부서를 격리 |
| 유연한 관리 | 장비를 물리적으로 옮기지 않고 설정만으로 그룹 재구성 |

_표 5-1. VLAN의 장점_

3층 회사에 영업·개발·회계 직원이 층에 섞여 앉아 있다고 합시다. VLAN 10(영업)·20(개발)·30(회계)으로 나누면, 자리가 어느 층이든 같은 부서끼리 하나의 논리 네트워크로 묶이고 다른 부서와는 기본 격리됩니다. 부서 이동이 생겨도 케이블을 옮길 필요 없이 포트의 VLAN 설정만 바꾸면 됩니다.

## 2. 액세스 포트와 트렁크 포트

스위치 포트는 두 종류로 나뉩니다. **액세스(Access) 포트** 는 하나의 VLAN에만 속하며 단말(PC·전화기)을 연결합니다. **트렁크(Trunk) 포트** 는 여러 VLAN의 프레임을 한꺼번에 실어 나르며, 스위치와 스위치, 스위치와 라우터를 잇습니다.

| 구분 | 액세스 포트 | 트렁크 포트 |
|---|---|---|
| 소속 VLAN | 하나 | 여러 개 |
| 태그 | 없음(일반 프레임) | 802.1Q 태그 사용 |
| 연결 대상 | 단말(PC·프린터·전화기) | 스위치·라우터 |

_표 5-2. 액세스 포트와 트렁크 포트_

트렁크에서는 어느 프레임이 어느 VLAN 소속인지 구별해야 하므로, 프레임에 4바이트짜리 **802.1Q 태그**(VLAN 번호)를 붙입니다. 다만 태그 없이 다니도록 예약된 **native VLAN**이 있는데, 설정이 어긋나면 보안 허점(이중 태깅 공격)이 되므로 기본값(VLAN 1)에서 사용하지 않는 별도 VLAN으로 바꿔 두는 것이 안전합니다.

> **보안 유의 — VLAN 홉핑** VLAN은 격리로 보안을 높이지만, 잘못 설정하면 공격자가 자신이 속하지 않은 VLAN에 접근하는 **VLAN 홉핑**이 가능합니다. 스위치인 척 트렁크를 협상하는 ‘스위치 스푸핑’, 태그를 이중으로 붙이는 ‘이중 태깅’이 대표적입니다. 대응책은 미사용 포트 비활성화, 트렁크 자동협상 끄기, native VLAN을 별도 VLAN으로 지정하기입니다.
{: .prompt-warning }

## 3. VTP — VLAN 정보를 자동으로 공유

스위치가 여러 대인 회사에서 VLAN을 새로 만들 때마다 모든 스위치에 똑같이 입력하는 것은 번거롭고 실수도 잦습니다. **VTP**(VLAN Trunking Protocol)는 한 스위치에서 만든 VLAN 정보를 같은 도메인의 다른 스위치들에 자동으로 전파하는 기술입니다. 대회 도면에서도 “A-S2는 VTP 서버, A-S1·A-S3는 클라이언트”처럼 VTP 구성이 요구됩니다.

| 모드 | 하는 일 |
|---|---|
| Server(서버) | VLAN을 만들고·수정하고·삭제할 수 있으며, 그 정보를 다른 스위치에 전파 |
| Client(클라이언트) | 서버가 보낸 VLAN 정보를 받아 따르기만 함(직접 만들 수 없음) |
| Transparent(투명) | 전파에 참여하지 않고 자기 VLAN만 독립 관리 |

_표 5-3. VTP 모드_

VTP가 동작하려면 세 가지 조건이 맞아야 합니다. ① 스위치 간 연결이 **트렁크**여야 하고, ② **VTP 도메인 이름**이 같아야 하며(예: `secu.com`), ③ 서버에서 만든 VLAN이라야 클라이언트로 전파됩니다.

## 4. 음성 VLAN(Voice VLAN)

IP 전화기는 데이터(PC)와 다른 VLAN으로 분리해 관리하는 것이 좋습니다. 통화 품질을 위해 음성 트래픽을 우선 처리해야 하고, 보안상으로도 분리가 유리하기 때문입니다. 그래서 하나의 포트에 IP 전화기와 PC를 함께 연결할 때, 전화기는 **음성 VLAN**(대회 도면에서는 VLAN 150 VOICE), PC는 데이터 VLAN으로 나누어 태그를 붙입니다. 실제 설정은 9강(VoIP)에서 전화 서비스와 함께 다룹니다.

## 5. STP PortFast

4강에서 배운 스패닝 트리(STP)는 루프를 막기 위해, 포트가 켜지면 몇 단계를 거쳐 천천히 통신 가능 상태(포워딩)로 바뀝니다. 그런데 PC나 서버가 연결된 액세스 포트는 루프를 만들 일이 없으므로 이 지연이 불필요합니다. **PortFast**는 이런 포트가 켜지자마자 즉시 포워딩 상태가 되게 하는 기능입니다. 대회 도면에서 “모든 인터페이스가 up 될 때 즉시 포워딩 상태가 되도록 하라”는 조건이 바로 PortFast 설정을 뜻합니다.

## 6. VLAN 간 라우팅

서로 다른 VLAN은 2계층에서 완전히 격리되므로, 통신하려면 반드시 3계층 장비(라우터·L3 스위치)를 거쳐야 합니다. 가장 널리 쓰는 방법이 **라우터 온 어 스틱(Router on a Stick)** 입니다. 라우터의 물리 인터페이스 하나를 트렁크로 스위치에 연결하고, 그 위에 VLAN마다 논리(서브) 인터페이스를 만들어 각 VLAN의 게이트웨이 역할을 맡깁니다.

> **생각해 보기 — 같은 스위치인데 왜 통신이 안 될까?**
> VLAN 10과 VLAN 20의 PC가 같은 스위치에 나란히 꽂혀 있는데도 서로 ping이 되지 않습니다. 물리적으로는 한 대의 스위치인데 왜 그럴까요? 그리고 이 둘을 통신시키려면 왜 하필 3계층 장비(라우터)가 필요할까요? 2강에서 배운 ‘서로 다른 서브넷은 라우터가 필요하다’와 이 문제가 어떻게 연결되는지 생각해 보세요. 실제로 VLAN마다 서로 다른 IP 대역(서브넷)을 씁니다.
{: .prompt-info }
