> **실습 문제 사용법**
> 대회 문제지와 비슷한 형식의 과제입니다. 이번 과제는 대회 도면의 본사–지사 GRE/IPSec 터널을 단순화한 것입니다. 요구사항만 보고 직접 구성한 뒤 ‘완성 기준’으로 스스로 채점하세요.
{: .prompt-info }

---

## 1. 과제 개요

당신은 본사와 지사를 잇는 담당자입니다. 두 지점은 인터넷(공인망)으로 떨어져 있으나, 내부 사설망끼리 직접 통신할 수 있어야 하고, 그 통신은 IPSec으로 안전하게 보호되어야 합니다.

## 2. 지급재료

- 패킷 트레이서 9.0
- 제출 파일명: `학번_이름_실습12.pkt`

## 3. 네트워크 구성

| 구분 | 본사 `R-HQ` | 지사 `R-BR` |
|---|---|---|
| 공인 IP | 100.0.0.9 | 100.0.0.66 |
| 사설 LAN | 172.16.10.0/24 (R .1) | 172.16.20.0/24 (R .1) |
| 터널 IP | 200.0.0.1 | 200.0.0.2 |

_표 12-6. 구성_

- 터널 번호: **10**, 터널 네트워크 `200.0.0.0/30`
- IPSec: 정책 번호 **10**, 암호화 **aes 256**, 해시 **sha**, crypto map 이름 **`MAP`**

## 4. 요구사항

### 4-1. GRE 터널

① 두 라우터에 터널 인터페이스 10을 만들고, 표 12-6의 터널 IP를 설정하시오.
② 터널의 출발지·목적지를 각 라우터의 공인 IP로 지정하시오.
③ 상대 사설망으로 가는 트래픽이 터널을 통하도록 경로를 설정하시오.

### 4-2. IPSec 보호

① ISAKMP 정책(번호 10, aes 256, sha, 사전 공유 키)을 양쪽에 설정하시오.
② transform-set과 crypto map(`MAP`)을 구성하여 공인 인터페이스에 적용하시오.
③ 공인 구간(사설 IP·터널 구간이 아닌)에 대해서만 보호가 이루어지도록 하시오.

### 4-3. 동작 확인

① 본사 PC(172.16.10.x)에서 지사 PC(172.16.20.x)로 ping이 성공해야 한다.
② `show crypto ipsec sa`에서 encrypt/decrypt 카운터가 증가해야 한다.

## 5. 선수 유의사항

1. crypto map 이름(`MAP`)과 정책 번호(10)를 정확히 사용하시오.
2. IPSec 정책·키·transform-set은 양쪽 라우터가 정확히 일치해야 한다.
3. **공인 네트워크 구간에 터널 구간·사설 IP가 라우팅되면 감점될 수 있으니**, 사설망은 반드시 터널을 통해서만 통신되도록 하시오.
4. 반드시 설정을 저장한 뒤 제출하시오.

## 6. 완성 기준 (스스로 채점)

| 확인 항목 | 완성 여부 |
|---|---|
| 양쪽 터널 인터페이스(10)와 출발지·목적지가 올바른가 | ☐ |
| 상대 사설망 경로가 터널로 향하는가 | ☐ |
| ISAKMP 정책(10/aes256/sha)과 키가 양쪽 일치하는가 | ☐ |
| crypto map `MAP`이 공인 인터페이스에 적용되었는가 | ☐ |
| 사설망 ping 성공 + encrypt/decrypt 카운터 증가가 확인되는가 | ☐ |

> **생각해 보기 — 왜 사설 IP가 공인망에 라우팅되면 안 될까?**
> 유의사항 3번은 “사설 IP가 공인망에 라우팅되면 감점”이라고 경고합니다. 사설 IP(172.16.x)는 원래 인터넷에서 라우팅되지 않는데(2강), 만약 실수로 공인망 구간에 사설망 경로가 새어 나간다면 무엇이 문제일까요? VPN의 목적(사설망은 ‘터널 안에서만’ 오간다)과, 터널 밖으로 사설 트래픽이 나가면 보호(IPSec)를 못 받는다는 점을 연결해 생각해 보세요.
{: .prompt-info }
