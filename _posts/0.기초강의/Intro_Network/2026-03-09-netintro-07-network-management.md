## 1. 네트워크 관리 개요

**네트워크 관리(Network Management)** 란 네트워크를 이루는 자원(장비·회선·서비스)을 감시(Monitoring)·제어(Control)·유지(Maintenance)해, 네트워크가 안정적이고 효율적으로 동작하도록 보장하는 활동입니다. 단순히 고장을 고치는 데 그치지 않고 성능 관리·자산 파악·보안 유지까지 포함합니다. 규모와 복잡성이 커질수록(사람이 일일이 살피기 어려움), 장애의 파급 효과가 클수록(장애=업무 중단), 성능·품질(SLA) 보장·보안 위협 대응·자산 비용 관리를 위해 관리의 중요성은 커집니다.

국제표준화기구(ISO)는 네트워크 관리의 범위를 다섯 기능 영역으로 정리하고, 머리글자를 따 **FCAPS**라 부릅니다.

| 관리기능 | 영문 | 주요 내용 | 예 |
|---|---|---|---|
| 장애 관리 | Fault | 장애 탐지·격리, 원인 파악·복구, 로그·알람 처리 | 회선 다운 알람, 장애 티켓 |
| 구성 관리 | Configuration | 장비 설정·자산 현황 파악, 변경 이력 관리 | 설정 백업, 버전 관리 |
| 계정 관리 | Accounting | 자원 사용량 측정 → 과금·할당 근거 | 트래픽량 집계, 부서별 과금 |
| 성능 관리 | Performance | 처리량·지연·이용률 감시와 튜닝 | 대역폭 모니터링, 임계치 경보 |
| 보안 관리 | Security | 접근 통제·인증·감사, 보안 정책 적용 | 계정 권한, 접근 로그 감사 |

## 2. SNMP

**SNMP(Simple Network Management Protocol)** 는 네트워크 장비의 상태를 수집·감시하고 설정을 제어하기 위한 TCP/IP 표준 관리 프로토콜입니다. 응용 계층에서 동작하며, 상태 조회·설정에는 UDP 161번을, 장비가 스스로 보내는 경보(트랩)에는 UDP 162번을 씁니다. 버전은 v1·v2c·v3가 있고, v3에서 인증·암호화 보안 기능이 크게 강화되었습니다. SNMP로 정보를 수집해 그래프·경보로 보여 주는 소프트웨어를 통합 관리 시스템(NMS)이라 하며, MRTG·Cacti(트래픽 그래프), Nagios(가용성 감시), Zabbix(통합 NMS), PRTG·SolarWinds(상용) 등이 있습니다.

### (1) 관리자와 에이전트

SNMP는 **관리자(Manager)** 와 **에이전트(Agent)** 의 역할 분담으로 동작합니다. 관리자는 NMS가 설치된 중앙 서버로 여러 장비에 정보를 요청·수집하고, 에이전트는 라우터·스위치·서버 안에서 동작하며 자기 장비의 정보를 제공합니다. 통신은 관리자가 주기적으로 상태를 묻는 **폴링(Polling, 요청–응답)** 과, 에이전트가 임계치 초과·장애 같은 사건이 생기면 스스로 알리는 **트랩(Trap)** 으로 이루어집니다(폴링=정기 점검, 트랩=긴급 보고).

### (2) SNMP·SMI·MIB

SNMP 관리는 세 요소가 맞물려 동작합니다. 언어에 비유하면 SNMP는 ‘대화 방법’, SMI는 ‘문법’, MIB는 ‘사전’입니다.

| 구성요소 | 역할 | 비유 |
|---|---|---|
| SNMP | 관리자·에이전트가 정보를 주고받는 통신 규약 | 대화 방법 |
| SMI | 관리 정보의 이름·표현 규칙(ASN.1 기반, OID 체계) | 문법 |
| MIB | 관리 대상 객체(포트 상태·트래픽량 등)를 계층적으로 모은 DB | 사전 |

_표 7-3. SNMP 관리의 3대 구성요소_

MIB의 각 객체는 점으로 이어진 숫자 주소인 **OID(Object Identifier)** 로 지정됩니다. 예를 들어 시스템 설명 정보는 `1.3.6.1.2.1.1.1`처럼 트리 구조 경로로 표현됩니다. `sysDescr`(장비 종류·OS), `sysUpTime`(가동 시간), `ifInOctets`(포트로 들어온 바이트 수) 등이 자주 쓰이며, 트래픽 그래프 도구는 `ifInOctets`·`ifOutOctets`를 주기적으로 읽어 그 차이로 초당 전송량을 계산합니다.

### (3) SNMP 메시지와 커뮤니티 스트링

| 메시지 | 방향 | 용도 |
|---|---|---|
| GetRequest | 관리자 → 에이전트 | 지정 OID 값 조회 |
| GetNextRequest | 관리자 → 에이전트 | 다음 객체 조회(MIB 순회) |
| GetBulkRequest | 관리자 → 에이전트 | 여러 객체 대량 조회(v2c부터) |
| SetRequest | 관리자 → 에이전트 | 객체 값 설정·변경 |
| Response | 에이전트 → 관리자 | 요청에 대한 응답 |
| Trap | 에이전트 → 관리자 | 사건 발생을 비동기 통보(비확인) |
| InformRequest | 관리자 ↔ 관리자 | 확인 응답이 있는 트랩(v2c부터) |

_표 7-4. 주요 SNMP 메시지(PDU)_

**커뮤니티 스트링(Community String)** 은 SNMP v1·v2c에서 관리자·에이전트가 공유하는 일종의 암호입니다. 값이 일치해야 정보를 주고받으며, 읽기 전용(RO, 관례상 `public`)과 읽기·쓰기(RW, 관례상 `private`)가 있습니다.

| 버전 | 인증·보안 | 특징 |
|---|---|---|
| v1 | 커뮤니티 스트링(평문) | 가장 오래된 기본 버전 |
| v2c | 커뮤니티 스트링(평문) | GetBulk·Inform 추가, 성능 개선 |
| v3 | 사용자 기반 보안(USM) — 인증+암호화 | 도청·위조를 막는 현대 표준 |

_표 7-5. SNMP 버전 비교_

> **보안 유의 — 커뮤니티 스트링의 위험** v1·v2c의 커뮤니티 스트링은 평문으로 오가 도청되면 그대로 노출됩니다. 기본값(public·private)을 그대로 두면 누구나 장비 정보를 읽거나 설정을 바꿀 수 있습니다. 대응책은 ① 기본 커뮤니티 값 변경, ② 접근 가능한 관리자 IP를 ACL로 제한, ③ 가능하면 인증·암호화를 제공하는 **SNMPv3** 사용입니다.
{: .prompt-warning }

> **실습 7-1. SNMP로 장비 상태 조회하기**  
> **실습 목표** 라우터에 SNMP 에이전트를 설정하고, 관리 PC에서 커뮤니티 스트링으로 장비 정보를 조회한다.  
> **주소 계획** R1 관리 IP = `192.168.10.254`, 관리 PC0 = `192.168.10.1`(실습 3-1과 동일)
{: .prompt-tip }

**실습 절차**

1. R1에 읽기 전용 커뮤니티와 위치·담당자 정보를 설정한다.

    ```text
    snmp-server community public ro
    snmp-server location Seoul-IDC
    snmp-server contact admin@lab.local
    ```

2. 트랩을 받을 관리자를 지정한다: `snmp-server host 192.168.10.1 version 2c public`.
3. 관리 PC0의 `[Desktop] > [MIB Browser]`를 연다. Advanced에서 대상 IP `192.168.10.254`, Read Community `public`, 버전 v2c를 입력한다.
4. MIB 트리에서 `system` 그룹을 펼쳐 `sysName`·`sysDescr`·`sysUpTime` 등을 골라 Get으로 조회한다.
5. 커뮤니티를 일부러 틀리게(`private` 등) 바꿔 조회하면 응답이 없음을 확인한다. (MIB Browser가 없는 버전이라면 R1에서 `show snmp`로 설정을 확인한다.)

> **결과 확인** `sysDescr`(장비 설명)·`sysUpTime`(가동 시간) 같은 값이 조회되고, 틀린 커뮤니티로는 조회되지 않으면 성공.  
> **계층 짚기** 관리자(MIB Browser)가 에이전트(R1)의 MIB 객체를 OID로 조회하는 SNMP의 실제 동작이다. 본문에서 배운 관리자·에이전트·MIB·커뮤니티 스트링이 그대로 대응된다.
{: .prompt-tip }

## 3. 원격 접속 서비스

네트워크 장비는 대개 사람이 옆에 없는 곳에 설치되므로, 멀리서 접속해 명령을 내리는 원격 접속 프로토콜이 관리의 필수 도구입니다. 대표적으로 TELNET·Rlogin·SSH가 있는데, 앞의 둘은 평문이라 위험하고 오늘날은 SSH가 표준입니다.

- **TELNET**: 가장 오래된 원격 접속 프로토콜(TCP 23). 서로 다른 기종이 통신하도록 네트워크 가상 터미널(NVT) 공통 문자 체계를 쓰지만, ID·비밀번호를 포함한 모든 데이터를 평문으로 주고받아 도청에 매우 취약합니다.
- **Rlogin**: BSD 유닉스 계열의 원격 로그인(TCP 513). 신뢰 호스트 목록(`.rhosts`)에 등록되면 비밀번호 없이 접속을 허용하는 신뢰 기반 인증을 쓰는데, 이 구조가 위조에 취약합니다. 역시 평문입니다.
- **SSH(Secure Shell)**: TELNET·Rlogin의 보안 문제를 해결한 암호화 원격 접속 프로토콜(TCP 22). 접속 과정과 이후 모든 데이터를 암호화해 도청·위조·가로채기를 막습니다. SSH-1을 개선한 SSH-2가 오늘날 표준입니다.

SSH는 역할이 다른 여러 하위 프로토콜로 이루어집니다.

| 컴포넌트 | 역할 |
|---|---|
| SSH-TRANS (전송 계층) | 서버 인증, 암호화·무결성이 보장되는 안전한 채널 생성 |
| SSH-AUTH (사용자 인증) | 그 채널 위에서 클라이언트를 인증(비밀번호·공개키 등) |
| SSH-CONN (연결) | 하나의 암호화 채널을 여러 논리 채널로 다중화(셸·포트 전달 동시 사용) |
| SSH-APPLICATION (응용) | 원격 셸, 파일 전송(SFTP·SCP) 등 |

_표 7-6. SSH의 4대 컴포넌트_

SSH는 원격 접속뿐 아니라 다른 프로그램의 트래픽을 SSH 암호화 채널에 실어 나르는 **포트 전달(터널링)** 기능도 제공합니다. 방향에 따라 로컬 포트 전달(내 포트로 들어온 연결을 원격 너머 목적지로 — 방화벽 우회 접속), 원격 포트 전달(원격 서버 포트로 들어온 연결을 내 쪽으로), 동적 포트 전달(SOCKS 프록시처럼 여러 목적지로 유연하게)로 나뉩니다. SSH의 안전성은 키 교환(Diffie-Hellman)으로 세션 키를 안전하게 만들고, 이후 데이터를 그 세션 키로 대칭키 암호화하며, 서버가 호스트 키(공개키)로 신원을 증명하고, 사용자 인증에 공개키 인증을 쓸 수 있는 데서 나옵니다.

| 구분 | TELNET / Rlogin | SSH |
|---|---|---|
| 포트 | 23(TELNET) / 513(Rlogin) | 22 |
| 암호화 | 없음(전 구간 평문) | 전 구간 암호화 |
| 인증 | 평문 ID·PW / 신뢰 호스트 | 비밀번호 또는 공개키 인증 |
| 사용 원칙 | 사용 지양(폐쇄망·실습 한정) | 원격 관리의 표준 |

_표 7-7. TELNET·Rlogin과 SSH의 비교_

> **실습 7-2. SSH로 라우터 안전하게 원격 관리하기**  
> **실습 목표** 라우터에 SSH를 설정해, 평문인 Telnet 대신 암호화된 원격 접속으로 장비를 관리한다.  
> **주소 계획** R1 관리 IP = `192.168.10.254`, 관리 PC0 = `192.168.10.1`(실습 3-1과 동일)
{: .prompt-tip }

**실습 절차**

1. R1에 호스트명과 도메인 이름을 설정한다(RSA 키 생성에 도메인이 필요): `hostname R1` → `ip domain-name lab.local`.
2. 암호화 키를 만들고 SSH 버전을 지정한다: `crypto key generate rsa`(모듈러스 1024 이상) → `ip ssh version 2`.
3. 로컬 관리 계정을 만든다: `username admin privilege 15 secret cisco123`.
4. VTY 라인에서 SSH만 허용하고 로컬 인증을 쓰도록 한다: `line vty 0 4 → transport input ssh → login local`.
5. PC0의 `[Command Prompt]`에서 `ssh -l admin 192.168.10.254`로 접속하고, `telnet 192.168.10.254`는 거부되는지 확인한다. `show ip ssh`로 활성화 상태도 확인한다.

> **결과 확인** SSH로는 로그인되고 Telnet은 차단되면 성공.  
> **계층 짚기** SSH는 응용 계층에서 동작하지만 전송 구간을 암호화해, 평문 Telnet의 도청 위험을 없앤다. 원격 관리는 곧 보안 관리(FCAPS의 S)의 실천이다.
{: .prompt-tip }
