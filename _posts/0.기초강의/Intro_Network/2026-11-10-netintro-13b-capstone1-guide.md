> **이 편의 목적**
> 종합실습 ①(본사·외부망)을 막힘없이 완성하도록, **권장 구축 순서**와 각 단계의 검증 포인트, 흔한 실패를 정리했습니다. 정답 설정 파일을 그대로 주지는 않습니다. 각 단계는 해당 강의 명령을 그대로 활용하면 됩니다.
{: .prompt-info }

## 1. 구축의 큰 원칙 — 아래에서 위로

큰 과제는 **계층 순서(아래→위)** 로 쌓아야 각 단계를 바로 검증할 수 있습니다. 라우팅이 안 되는데 전화·DNS를 테스트할 수는 없기 때문입니다. 권장 순서는 다음과 같습니다.

```
① 이름·주소 계획(모든 장비 hostname, IP 표 채우기 — 특히 "마지막 주소")
        ↓
② 스위칭(VLAN·VTP·트렁크·PortFast)
        ↓
③ 라우팅(본사 VLAN간·RIPv2 / 외부 OSPF / 프레임릴레이 / HSRP)
        ↓
④ 서비스(DHCP·DNS·메일·VoIP)
        ↓
⑤ 보안(ASA 방화벽·포트포워딩·B-R3 ACL)
        ↓
⑥ 전체 검증(끝단 PC/전화기 간 통신 확인)
```

## 2. 단계별 가이드와 검증

### 1단계 — 주소 계획 (2강)

가장 먼저 표 13-1·13-4의 “사용 가능한 마지막 주소”를 모두 계산해 종이에 적어 둡니다. 예: `172.16.8.0/23`의 마지막 = `172.16.9.254`(A-Call-R), `192.168.10.0/24`의 마지막 = `192.168.10.254`(A-ASA DMZ). **이 계산을 먼저 끝내야 나머지가 막히지 않습니다.**

### 2단계 — 스위칭 (5강)

VTP부터 세웁니다(도메인 `secu.com`, A-S2 서버). 서버에서 VLAN 10·20·150을 만들고, 트렁크를 올린 뒤 클라이언트(A-S1·A-S3)에서 `show vlan brief`로 전파를 확인합니다. 그 다음 액세스 포트를 배정하고 PortFast를 겁니다.

> **검증**: 클라이언트 스위치에 VLAN이 자동으로 보이면 VTP 성공. 안 보이면 트렁크·도메인 이름부터 점검.

### 3단계 — 라우팅

- **본사(6강)**: A-Call-R에 VLAN별 서브인터페이스(게이트웨이)를 만들고, A-Call-R·A-ASA에 RIPv2를 설정합니다.
- **외부 OSPF(6강)**: 공인망 라우터에 OSPF 10 area 0를 설정하되, **공인 네트워크만** 선언합니다(사설망 선언 시 0점).
- **프레임릴레이(7강)**: Cloud0에 DLCI를 매핑하고, B-R1·R2·R3에 `frame-relay map`을 넣습니다.
- **HSRP(7강)**: A-R1·A-R2에 가상 IP 100.0.0.1, A-R1 우선순위 높게 + preempt.

> **검증**: 각 라우터 `show ip route`에 원격 네트워크가 학습되고, 라우터 간 ping이 되면 성공. HSRP는 `show standby brief`로 R1=Active 확인.

### 4단계 — 서비스

- **DNS(3강)**: A-DNS에 `intra.secu.com`→A-Main, B-SRV에 `www/smtp/pop3/mail.skills.com`→B-SRV, `www.secu.com`→ASA 포트포워딩 주소.
- **DHCP(3·8강)**: B-SRV 내부/외부 풀. VoIP용 DHCP는 A-Call-R에 `option 150` 포함.
- **VoIP(9강)**: A-Call-R를 CME로 만들어 A-Phone1·2에 번호 할당.
- **메일(8강)**: B-SRV 메일 서비스.

> **검증**: PC에서 `nslookup intra.secu.com`이 A-Main IP를 응답하고, 전화기에 번호가 뜨면 성공.

### 5단계 — 보안

- **ASA(11강)**: 세 존·security-level·디폴트 라우팅. 그다음 `100.0.0.8`(또는 지정 공인 주소) 웹 → A-Main 포트포워딩 + ACL.
- **B-R3 ACL(11강)**: Home-RT 방향 in에 확장 ACL `IN->PERMIT`으로 DHCP·메일만 허용, 나머지 차단.

> **검증**: 외부 PC에서 `http://100.0.0.8`로 A-Main 페이지가 열리고, 내부→외부는 되며 외부→내부(웹 외)는 막히면 성공.

### 6단계 — 전체 검증

끝단(A-PC, A-Phone, B-Laptop 등)에서 서로·서버·전화까지 통신을 확인합니다. 하나라도 안 되면, 그 경로를 계층 순서로 되짚어 어느 단계에서 끊기는지 좁힙니다(1강의 계층별 문제 해결).

## 3. 자주 겪는 실패 모음

| 증상 | 흔한 원인 |
|---|---|
| VLAN이 클라이언트에 안 뜸 | VTP 도메인 불일치, 스위치 간 포트가 트렁크가 아님 |
| VLAN 간 통신 실패 | 서브인터페이스 `encapsulation dot1Q` 번호·PC 게이트웨이 오류 |
| 원격 네트워크 학습 안 됨 | OSPF에 network 누락, area 불일치, 사설망을 잘못 선언 |
| 전화기에 번호 안 뜸 | DHCP `option 150` 누락, telephony-service의 source-address 오류 |
| 외부에서 웹 접속 안 됨 | ASA 포트포워딩(정적 NAT) 또는 OUTSIDE ACL 누락 |
| 저장 안 해서 재부팅 후 사라짐 | `write memory`를 단계마다 습관화 |

> **생각해 보기 — 왜 저장을 자주 해야 할까?**
> 3시간짜리 과제에서 마지막에 한 번만 저장하려다, 중간에 실수로 장비를 재부팅하면 그동안의 작업이 모두 사라집니다. 실제 대회 유의사항에도 “파일 재시작은 1회”라는 제약이 있습니다. 왜 ‘큰 단계를 마칠 때마다 저장’하는 습관이 중요한지, 그리고 running-config와 startup-config의 차이(4강)와 어떻게 연결되는지 생각해 보세요.
{: .prompt-info }
