> **실습 문제 사용법**
> 대회 문제지와 비슷한 형식의 과제입니다. 이번 과제는 대회 외부망의 게이트웨이 이중화 조건을 단순화한 것입니다. 요구사항만 보고 직접 구성한 뒤 ‘완성 기준’으로 스스로 채점하세요.
{: .prompt-info }

---

## 1. 과제 개요

당신은 본사의 인터넷 관문을 담당합니다. 관문 라우터가 한 대뿐이면 고장 시 전체가 끊기므로, 두 대를 두어 게이트웨이 이중화를 구성해야 합니다. 평소에는 성능이 좋은 주 라우터가 동작하고, 그 라우터가 복구되면 다시 주 라우터를 통해 통신되어야 합니다.

## 2. 지급재료

- 패킷 트레이서 9.0
- 제출 파일명: `학번_이름_실습07.pkt`

## 3. 네트워크 구성

| 장치 | 이름 | IP |
|---|---|---|
| 주 라우터 | `R-MAIN` | 192.168.100.11 / 255.255.255.0 |
| 예비 라우터 | `R-BACKUP` | 192.168.100.12 / 255.255.255.0 |
| 가상 게이트웨이 | (HSRP) | 192.168.100.1 |
| PC | `PC-1` | 192.168.100.50, GW = 192.168.100.1 |

_표 7-3. 구성_

## 4. 요구사항

### 4-1. 기본 설정

① 라우터 2대와 스위치 1대, PC 1대를 배치하고 이름을 표대로 변경하시오.
② 각 라우터의 LAN 인터페이스와 PC에 표 7-3의 IP를 설정하시오. PC의 게이트웨이는 가상 IP `192.168.100.1`로 지정하시오.

### 4-2. HSRP 이중화

- 두 라우터가 가상 IP **`192.168.100.1`** 을 공유하도록 HSRP를 구성하시오.
- **`R-MAIN`** 이 평소 **액티브**로 동작하도록 우선순위를 높게 설정하시오.
- `R-MAIN`이 복구되면 **다시 액티브가 되도록**(선점) 설정하시오.

### 4-3. 동작 확인

① `show standby brief`로 R-MAIN=Active, R-BACKUP=Standby가 확인되어야 한다.
② PC에서 지속 ping을 건 상태에서 R-MAIN의 LAN 인터페이스를 shutdown하면, 통신이 유지되어야 한다(R-BACKUP이 인수).
③ R-MAIN을 복구하면 다시 R-MAIN이 액티브가 되어야 한다.

## 5. 선수 유의사항

1. 라우터 이름의 대소문자·하이픈을 정확히 구별하여 작성하시오.
2. PC의 게이트웨이는 실제 라우터 IP가 아니라 가상 IP여야 한다.
3. 반드시 설정을 저장한 뒤 제출하시오.

## 6. 완성 기준 (스스로 채점)

| 확인 항목 | 완성 여부 |
|---|---|
| 두 라우터가 가상 IP `192.168.100.1`을 공유하는가 | ☐ |
| R-MAIN이 우선순위가 높아 액티브로 동작하는가 | ☐ |
| 선점(preempt)이 설정되었는가 | ☐ |
| R-MAIN 장애 시 통신이 유지되는가 | ☐ |
| R-MAIN 복구 시 다시 액티브가 되는가 | ☐ |

> **생각해 보기 — 이중화의 대가**
> 게이트웨이 이중화는 안정성을 크게 높이지만, 라우터 한 대를 더 사야 하고 설정도 복잡해집니다. 모든 라우터를 이렇게 이중화해야 할까요? ‘고장 나면 피해가 큰 곳’과 ‘잠깐 끊겨도 괜찮은 곳’을 구분한다면, 회사의 어느 지점을 우선 이중화해야 할지 생각해 보세요. (핵심 관문일수록 이중화의 가치가 큽니다.)
{: .prompt-info }
