지금까지 우리는 데이터(문자·웹·메일)를 나르는 네트워크를 만들었습니다. 이 강에서는 그 위에 **음성(전화)** 까지 얹습니다. 대회 도면의 본사·지사에는 IP 전화기가 있고, 이들이 서로 통화할 수 있어야 합니다.

## 1. VoIP란

**VoIP**(Voice over IP)는 음성을 잘게 나눠 데이터 패킷으로 바꿔 IP 네트워크로 전달하는 기술입니다. 예전에는 전화망과 데이터망이 완전히 따로였지만, VoIP 덕분에 하나의 네트워크로 전화와 인터넷을 함께 쓸 수 있게 되었습니다.

음성은 실시간성이 생명이라, 3강에서 배운 대로 **UDP** 위에서 전달됩니다(정확함보다 제때 도착함이 중요). 실제로는 음성 데이터를 실어 나르는 RTP라는 프로토콜이 UDP 위에서 동작합니다.

## 2. 구성요소

VoIP를 구성하는 세 가지를 알아 둡니다.

| 구성요소 | 역할 |
|---|---|
| IP 전화기 | 음성을 패킷으로 바꿔 주고받는 단말(예: Cisco 7960) |
| 통화 관리자(CME) | 전화번호를 나눠 주고 통화를 연결하는 ‘전화 교환실’ 역할. 라우터가 담당 |
| 음성 VLAN | 음성 트래픽을 데이터와 분리해 우선 처리하는 별도 VLAN(대회 VLAN 150) |

_표 9-1. VoIP의 구성요소_

**CME**(Call Manager Express)는 시스코 라우터에 내장된 소형 통화 관리자입니다. 라우터가 각 전화기에 전화번호를 할당하고, 어느 번호가 어느 번호로 걸면 연결해 주는 교환실 역할을 합니다. 별도의 값비싼 전화 서버 없이 라우터 하나로 소규모 IP 전화망을 꾸릴 수 있습니다.

## 3. 전화기가 켜지면 벌어지는 일

IP 전화기는 전원이 들어오면 스스로 설정을 받아 와야 합니다. 이 과정이 데이터 PC와 다릅니다.

① 전화기가 켜지면 **DHCP**로 IP 주소를 받습니다. 이때 일반 정보(IP·게이트웨이) 외에 **option 150**이라는 특별한 항목으로 “설정 파일을 어디서 받아야 하는지(TFTP 서버 주소)”를 함께 받습니다. ② 전화기는 그 주소(대개 CME 라우터)에서 자신의 설정과 전화번호를 내려받습니다. ③ 이제 전화기가 번호를 갖고 통화할 준비가 됩니다.

그래서 VoIP용 DHCP에는 반드시 **option 150**을 넣어야 합니다. 이것이 데이터용 DHCP와 다른 핵심입니다.

## 4. 전화번호 할당 — ephone-dn

CME에서 전화번호는 **ephone-dn**(전화기의 디렉터리 번호)으로 만듭니다. 예를 들어 `ephone-dn 1`에 번호 `1001`을, `ephone-dn 2`에 `1002`를 지정하면, 두 전화기가 각각 1001·1002번을 갖게 됩니다. 그리고 `telephony-service`에서 전화기들이 자동으로 이 번호를 배정받도록 설정합니다.

> **참고 — 다른 지점과의 통화** 같은 라우터에 물린 전화기끼리는 CME가 바로 연결해 줍니다. 그런데 본사와 멀리 떨어진 지사의 전화기와 통화하려면, 두 지점을 잇는 통로(대회에서는 GRE 터널, 11·12강)와, “어떤 번호로 걸면 어느 지점으로 보내라”를 정하는 **dial-peer** 설정이 필요합니다. 이 강에서는 우선 한 지점 안의 통화에 집중합니다.
{: .prompt-info }

> **생각해 보기 — 왜 음성을 데이터와 다른 VLAN에 둘까?**
> 5강에서 음성 VLAN(150)을 따로 만들었습니다. 전화 통화가 웹 다운로드·동영상 같은 데이터와 같은 길을 함께 쓴다면 어떤 일이 생길까요? 큰 파일을 내려받는 동안 통화 음성이 뒤로 밀려 끊긴다면 곤란할 것입니다. 음성을 별도 VLAN으로 분리하면 ‘우선 처리’와 ‘보안 분리’ 두 가지를 얻습니다. 이것이 3강에서 배운 ‘음성은 제때 도착이 중요하다(UDP)’와 어떻게 연결되는지 생각해 보세요.
{: .prompt-info }
