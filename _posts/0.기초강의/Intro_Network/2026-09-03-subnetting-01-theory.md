## 1. 왜 하나의 네트워크를 여러 개로 나누는가

회사에 PC가 300대 있다고 생각해 봅시다. 이 300대를 아무 구분 없이 하나의 네트워크에 몽땅 넣으면 어떤 일이 벌어질까요.

첫째, **소란스러워집니다.** 네트워크에는 특정 상대가 아니라 모두에게 외치는 통신, 즉 브로드캐스트가 끊임없이 오갑니다. 한 PC가 "192.168.0.50 쓰시는 분 계신가요?"라고 외치면 300대 전부가 그 소리를 듣고 확인해야 합니다. 300대가 저마다 외치면 네트워크는 잡담으로 가득 차고, 정작 중요한 데이터가 지나갈 자리가 좁아집니다. 이렇게 외침이 도달하는 범위를 **브로드캐스트 도메인**이라고 하는데, 이 범위가 넓어질수록 네트워크는 느려집니다.

둘째, **위험합니다.** 회계팀 PC와 손님용 PC가 같은 네트워크에 있으면, 손님용 PC에서 회계 서버로 바로 접근할 수 있습니다. 중간에 아무 관문도 없기 때문입니다. 네트워크를 나누어 두면 그 사이를 라우터나 방화벽이 지키게 되고, 거기서 통과와 차단의 규칙을 걸 수 있습니다.

셋째, **주소가 아깝습니다.** 라우터끼리 연결하는 구간은 주소가 딱 2개만 있으면 됩니다. 그런데 여기에 254개짜리 네트워크를 통째로 배정하면 252개가 그냥 버려집니다.

이 세 가지 문제를 한 번에 해결하는 방법이 **서브네팅(Subnetting)**, 즉 큰 주소 덩어리를 목적에 맞는 작은 덩어리로 쪼개는 일입니다. 오늘 우리가 배울 것은 결국 다음 한 문장으로 요약됩니다.

> **"여기에 장비를 몇 대 연결할 것인가"를 세어, 그 대수에 딱 맞는 크기의 주소 덩어리를 만들고, 그 안의 주소를 장비에 하나씩 나눠 주는 일.**
{: .prompt-tip }

## 2. IP 주소와 서브넷 마스크

IPv4 주소는 32개의 0과 1(32비트)로 되어 있습니다. 사람이 읽기 어려우니 8비트씩 네 덩어리로 끊고, 각 덩어리를 10진수로 바꿔 점으로 이어 `192.168.10.77`처럼 씁니다. 이 한 덩어리를 **옥텟(octet)**이라 부르며, 8비트이므로 0부터 255까지의 값을 가집니다.

IP 주소는 두 부분으로 나뉩니다.

| 부분 | 뜻 | 아파트에 비유하면 |
|---|---|---|
| 네트워크부 | 어느 네트워크에 속하는가 | ○○아파트 **101동** |
| 호스트부 | 그 네트워크 안의 몇 번째 장치인가 | **502호** |

_표 2. IP 주소의 두 부분_

![](/assets/img/posts/2026-09-03-subnetting-01-theory-1788434937971.png)

같은 동에 사는 사람끼리는 정문을 거치지 않고 바로 오갈 수 있듯이, **네트워크부가 같은 장치끼리는 라우터 없이 바로 통신**합니다. 반대로 네트워크부가 다르면 반드시 라우터(정문)를 거쳐야 합니다.

그렇다면 32비트 중 어디까지가 동(네트워크부)이고 어디부터가 호수(호스트부)일까요. 그것을 알려 주는 값이 **서브넷 마스크**입니다. 마스크를 2진수로 펼쳤을 때 **1인 자리가 네트워크부, 0인 자리가 호스트부**입니다.

```text
IP     192.168.10.77  = 11000000.10101000.00001010.01001101
마스크  255.255.255.0  = 11111111.11111111.11111111.00000000
                         |------- 네트워크부 24비트 -------||호스트부 8비트|
```


마스크의 1이 24개이므로 `255.255.255.0`을 짧게 **`/24`**라고도 씁니다. 이 표기를 **CIDR**라고 하며, `255.255.255.0`과 `/24`는 완전히 같은 말입니다. 실무와 시험에서는 `/24` 쪽을 훨씬 자주 씁니다.

여기서 꼭 기억할 점이 하나 있습니다. **마스크의 1을 늘리면(/24 → /25 → /26 …) 네트워크는 잘게 쪼개지고, 한 네트워크에 들어갈 수 있는 장비 수는 줄어듭니다.** 오늘 우리가 하는 모든 계산은 이 저울질입니다.

> **생각해 보기 — 마스크를 왜 따로 알려 줘야 할까요?**
> `192.168.10.77`이라는 IP만 보고는 어디까지가 동인지 알 수 없습니다. 마스크가 `/24`라면 `192.168.10.0`이 동 번호이고, `/26`이라면 `192.168.10.64`가 동 번호가 됩니다. 똑같은 IP인데 마스크에 따라 소속이 달라지는 셈입니다. 그래서 IP를 적을 때는 항상 마스크를 함께 적습니다.
{: .prompt-info }

### 손으로 해 보기 ① — CIDR과 마스크 바꾸기

> **푸는 법(예시).** `/26`은 1이 26개라는 뜻입니다. 앞 24개는 `255.255.255`로 채워지고, 남은 2개가 네 번째 옥텟의 앞쪽에 놓입니다. 8칸 중 앞 2칸이 1이면 `11000000`이고 이는 10진수로 **192**입니다. 따라서 `/26` = **255.255.255.192**입니다.
> 반대로 `255.255.255.240`이라면 240 = `11110000`이므로 1이 4개, 앞의 24개와 합쳐 **/28**입니다.
{: .prompt-tip }

네 번째 옥텟에 자주 나오는 값은 아래 여덟 개뿐입니다. 이것만 외우면 변환은 암산으로 끝납니다.

`128 · 192 · 224 · 240 · 248 · 252 · 254 · 255`

**아래 표의 빈칸을 손으로 채우십시오.** 

| CIDR | 서브넷 마스크 | 네 번째 옥텟의 2진수 |
|---|---|---|
| /26 | 255.255.255.192 | 11000000 |
| /25 | | |
| /27 | | |
| /28 | | |
| /30 | | |
| | 255.255.255.248 | |
| | 255.255.254.0 | (세 번째 옥텟) |

_연습 1. CIDR ↔ 서브넷 마스크 변환_

### 연습 1 정답

| CIDR | 서브넷 마스크 | 네 번째 옥텟의 2진수 |
|---|---|---|
| /25 | 255.255.255.128 | 10000000 |
| /27 | 255.255.255.224 | 11100000 |
| /28 | 255.255.255.240 | 11110000 |
| /30 | 255.255.255.252 | 11111100 |
| **/29** | 255.255.255.248 | 11111000 |
| **/23** | 255.255.254.0 | 11111110 (세 번째 옥텟) |

_연습 1-1. 정답_

마지막 줄이 가장 어려웠을 것입니다. `255.255.254.0`은 세 번째 옥텟이 254 = `11111110`이므로 그 자리에 1이 **7개** 있습니다. 앞 두 옥텟의 16개와 합쳐 **/23**입니다. 헷갈릴 때는 언제나 **1의 개수를 세는 것**으로 돌아가면 됩니다.

## 3. 한 서브넷에 장비 몇 대가 들어가는가

호스트부 비트가 h개일 때, 그 안에 들어가는 주소의 개수는 2의 h제곱 개입니다. 그런데 이 중 **두 개는 장비에 줄 수 없습니다.**

| 못 쓰는 주소 | 정체 | 예(`/24`인 192.168.10.0 대역) |
|---|---|---|
| 호스트부가 전부 0 | **네트워크 주소** — 네트워크 자체를 가리키는 이름표 | 192.168.10.0 |
| 호스트부가 전부 1 | **브로드캐스트 주소** — 이 네트워크 전체에게 외칠 때 쓰는 주소 | 192.168.10.255 |

_표 3. 장비에 배정할 수 없는 두 주소_

그래서 **실제로 장비에 줄 수 있는 주소 개수는 (2의 h제곱) − 2개**가 됩니다. `/24`라면 호스트 비트가 8개이므로 256 − 2 = 254개입니다.

여기에 실무에서 하나를 더 빼야 합니다. 바로 **게이트웨이(라우터 인터페이스)**입니다. 다른 네트워크와 통신하려면 그 네트워크의 관문 역할을 하는 라우터가 IP를 하나 가져가야 하기 때문입니다. 정리하면 이렇습니다.

> **PC·서버 등에 실제로 배정할 수 있는 대수 = (2의 h제곱) − 2 − 1(게이트웨이 몫)**
{: .prompt-tip }

`/24`라면 254개 중 1개를 게이트웨이가 쓰므로, 나머지 장비는 최대 253대까지 놓을 수 있습니다. 이 게이트웨이 한 자리를 빼먹는 실수가 대단히 흔하니, 지금부터는 **대수를 셀 때 항상 게이트웨이를 한 대로 세는 습관**을 들이시기 바랍니다.

### 손으로 해 보기 ② — 몇 대가 들어가는지 세기

> **푸는 법(예시).** `/27`이라면 32비트 중 27개가 네트워크부이므로 호스트 비트는 32 − 27 = **5개**입니다. 주소 개수는 2를 다섯 번 곱해 **32개**, 여기서 네트워크·브로드캐스트 2개를 빼면 사용 가능 주소는 **30개**, 다시 게이트웨이 1개를 빼면 PC·서버에 줄 수 있는 것은 **29대**입니다.
{: .prompt-tip }

2를 거듭 곱한 값은 아래 줄만 외워도 충분합니다.

`2 · 4 · 8 · 16 · 32 · 64 · 128 · 256 · 512 · 1024`

**빈칸을 손으로 채우십시오.**

| CIDR | 호스트 비트 | 주소 개수 | 사용 가능 주소 | PC에 줄 수 있는 대수(게이트웨이 제외) |
|---|---|---|---|---|
| /27 | 5 | 32 | 30 | 29 |
| /26 | | | | |
| /28 | | | | |
| /29 | | | | |
| /25 | | | | |
| /30 | | | | |

_연습 2. 서브넷 하나에 들어가는 대수_

### 연습 2 정답

| CIDR | 호스트 비트 | 주소 개수 | 사용 가능 주소 | PC에 줄 수 있는 대수 |
|---|---|---|---|---|
| /26 | 6 | 64 | 62 | 61 |
| /28 | 4 | 16 | 14 | 13 |
| /29 | 3 | 8 | 6 | 5 |
| /25 | 7 | 128 | 126 | 125 |
| /30 | 2 | 4 | 2 | **1 (사실상 0 — 라우터 전용)** |

_연습 2-1. 정답_

계산 순서는 늘 같습니다. **호스트 비트 = 32 − CIDR** → **주소 개수 = 2를 그만큼 곱함** → **사용 가능 = 주소 개수 − 2** → **PC 몫 = 사용 가능 − 1**. `/26`이라면 6 → 64 → 62 → 61이 되는 식입니다.

> **`/30`을 계산해 보면 왜 이 크기가 라우터 연결 전용인지 알게 됩니다.** 사용 가능 주소가 2개인데 게이트웨이를 빼면 PC 자리가 하나도 남지 않습니다. 즉 이 크기는 처음부터 장비 두 대(라우터 두 대)만 마주 보라고 만든 것입니다.
{: .prompt-info }

## 4. 핵심 ① — 장비 대수를 세어 마스크를 고르는 법

오늘 특강의 심장에 해당하는 부분입니다. 순서는 항상 다음 세 단계입니다.

### 4-1. 1단계 — 연결할 장비를 빠짐없이 센다

여기서 세는 대상은 **IP 주소를 하나 차지하는 것** 전부입니다. 눈에 보이는 PC만 세면 반드시 모자랍니다.

| 세어야 하는 것 | 세지 않는 것 |
|---|---|
| PC, 노트북 | 일반 스위치(L2)의 포트 |
| 서버, NAS(파일 저장 장치) | 허브, 케이블, 커넥터 |
| 네트워크 프린터, 복합기 | 스위치가 몇 대인지 자체는 무관 |
| IP 카메라, VoIP 전화기 | (단, 스위치에 원격 관리용 IP를 줄 계획이라면 그건 셈) |
| 무선 AP의 관리용 IP | |
| **라우터 인터페이스(게이트웨이) — 반드시 1개** | |

_표 4. 대수를 셀 때 포함할 장비_

예를 들어 어느 사무실의 장비 목록이 아래와 같다고 합시다.

| 장비 | 대수 |
|---|---|
| 직원 PC | 20 |
| 네트워크 프린터 | 2 |
| 파일 서버(NAS) | 1 |
| 무선 AP(관리용 IP) | 1 |
| 라우터 게이트웨이 | 1 |
| **합계(필요한 IP 개수)** | **25** |

_표 5. 장비 대수 산정 예시_

### 4-2. 2단계 — 여유분을 더한다

네트워크는 한번 설계하면 몇 년을 씁니다. 그 사이에 직원이 늘고 장비가 늘어납니다. 그래서 실무에서는 **산정한 대수에 20~30% 정도의 여유**를 얹어 계산합니다. 위 예시라면 25대에 여유를 더해 30대 정도로 보는 것이 안전합니다.

다만 오늘 실습과 대부분의 시험 문제에서는 **문제에 적힌 대수를 그대로** 쓰면 됩니다. 문제가 "최대 25대"라고 못박았다면 25대로 계산합니다. 여유를 더하는 것은 실무 감각이고, 시험은 주어진 조건을 지키는 것이 우선입니다.

### 4-3. 3단계 — 그 대수가 들어가는 가장 작은 서브넷을 고른다

이제 아래 표에서 필요한 개수를 담을 수 있는 **가장 작은 칸**을 고르면 끝입니다. 이 표는 반드시 외워야 합니다. 외우기 어렵다면 2, 6, 14, 30, 62, 126, 254라는 숫자 줄만 외워도 충분합니다.

| 필요한 IP 개수(게이트웨이 포함) | 호스트 비트 | CIDR | 서브넷 마스크 | 블록 크기 | 사용 가능 주소 |
|---|---|---|---|---|---|
| 1 ~ 2 | 2 | /30 | 255.255.255.252 | 4 | 2 |
| 3 ~ 6 | 3 | /29 | 255.255.255.248 | 8 | 6 |
| 7 ~ 14 | 4 | /28 | 255.255.255.240 | 16 | 14 |
| 15 ~ 30 | 5 | /27 | 255.255.255.224 | 32 | 30 |
| 31 ~ 62 | 6 | /26 | 255.255.255.192 | 64 | 62 |
| 63 ~ 126 | 7 | /25 | 255.255.255.128 | 128 | 126 |
| 127 ~ 254 | 8 | /24 | 255.255.255.0 | 256 | 254 |
| 255 ~ 510 | 9 | /23 | 255.255.254.0 | 512 | 510 |
| 511 ~ 1022 | 10 | /22 | 255.255.252.0 | 1024 | 1022 |

_표 6. **장비 대수 → 서브넷 마스크 결정표**(오늘 수업의 핵심 표)_

표를 보는 요령은 이렇습니다. 앞의 예시에서 필요한 IP는 25개였습니다. `/28`은 14개뿐이라 모자라고, `/27`은 30개라 충분합니다. 따라서 답은 **`/27`(255.255.255.224)**입니다. 그 위인 `/26`(62개)을 골라도 통신은 되지만, 37개를 놀리게 되므로 가장 작은 것을 고르는 쪽이 정답입니다.

| 후보 | 사용 가능 | 25개를 담을 수 있는가 | 판정 |
|---|---|---|---|
| /28 | 14 | 아니오 | 탈락(모자람) |
| **/27** | **30** | **예** | **채택(가장 작음)** |
| /26 | 62 | 예 | 낭비 |

_표 7. 마스크 선택 과정_


> **생각해 보기 — 왜 가장 작은 것을 골라야 할까요?**
> 큰 것을 고르면 지금 당장은 편합니다. 하지만 주소 대역은 유한합니다. 부서 하나에 `/24`를 통째로 주면 부서 254개를 만들 여지가 사라집니다. 필요한 만큼만, 여유는 조금만. 이것이 설계자의 태도입니다.
{: .prompt-info }

### 손으로 해 보기 ③ — 장비를 세어 마스크 고르기

> **푸는 법(예시) — 학교 도서관.** 장비를 하나씩 세어 봅니다. 열람용 PC 10대, 대출 단말 2대, 프린터 1대, 무선 AP 1대이므로 장비 합계는 14대입니다. 여기에 **게이트웨이 1개를 반드시 더해** 필요한 IP는 **15개**가 됩니다.
> 이제 표 6에서 15개를 담을 수 있는 가장 작은 칸을 찾습니다. `/28`은 14개라 **한 개가 모자라고**, `/27`은 30개라 충분합니다. 답은 **`/27`(255.255.255.224)**입니다.
> 게이트웨이를 빼먹었다면 14개로 계산해 `/28`을 골랐을 것이고, 실제로 배선하는 날 마지막 한 대가 들어갈 자리가 없어 낭패를 봅니다.
{: .prompt-tip }

**아래 세 가지 상황에 대해 빈칸을 손으로 채우십시오.**

**(1) 교무실** — 교사용 PC 12대, 프린터 2대, 출석 단말 3대, 무선 AP 1대

**(2) 컴퓨터 실습실** — 학생용 PC 40대, 교사용 PC 1대, 실습 서버 2대, 프린터 1대

**(3) 본관과 별관을 잇는 라우터 사이 구간** — 라우터 인터페이스 두 개만 마주 봄

| 구역 | 장비 합계 | + 게이트웨이 | 필요한 IP 개수 | 고른 CIDR | 서브넷 마스크 | 사용 가능 주소 | 남는 자리 |
|---|---|---|---|---|---|---|---|
| 예시(도서관) | 14 | 1 | 15 | /27 | 255.255.255.224 | 30 | 15 |
| (1) 교무실 | | | | | | | |
| (2) 실습실 | | | | | | | |
| (3) 라우터 구간 | | | | | | | |

_연습 3. 장비 대수로 마스크 고르기_

### 연습 3 정답

| 구역 | 장비 합계 | + 게이트웨이 | 필요한 IP | CIDR | 마스크 | 사용 가능 | 남는 자리 |
|---|---|---|---|---|---|---|---|
| (1) 교무실 | 18 | 1 | 19 | /27 | 255.255.255.224 | 30 | 11 |
| (2) 실습실 | 44 | 1 | 45 | /26 | 255.255.255.192 | 62 | 17 |
| (3) 라우터 구간 | 2 | (포함) | 2 | /30 | 255.255.255.252 | 2 | 0 |

_연습 3-1. 정답_

(3)번 라우터 구간에서 "+ 게이트웨이" 칸을 비워 둔 이유가 있습니다. 이 구간에는 라우터 인터페이스 두 개만 마주 보므로, **그 두 개가 곧 필요한 주소 전부**입니다. 따로 게이트웨이를 더할 대상이 없습니다.

> **한 걸음 더.** (2)번 실습실의 답을 구했으니, 이번에는 "만약 학생용 PC가 40대가 아니라 **62대**였다면 어떻게 달라지는가"를 계산해 보십시오. 한 대 차이로 마스크가 바뀌는 경계가 어디인지 알게 됩니다.
{: .prompt-info }

**한 걸음 더의 답.** 학생용 PC가 62대라면 장비 합계는 66대이고, 게이트웨이를 더해 **67개**가 필요합니다. `/26`은 62개라 모자라므로 **`/25`(126개)**로 한 단계 커집니다. 즉 필요 개수가 **62와 63 사이**를 지나는 순간 마스크가 바뀝니다. 표 6의 숫자 줄(2, 6, 14, 30, 62, 126, 254)이 바로 이 경계들입니다.

## 5. 핵심 ② — 서브넷의 주소 4종 세트 구하기

마스크를 정했으면, 이제 그 서브넷이 **어디서 시작해 어디서 끝나는지** 알아야 IP를 나눠 줄 수 있습니다. 구해야 할 것은 네 가지입니다.

| 이름 | 뜻 | 장비에 줄 수 있나 |
|---|---|---|
| 네트워크 주소 | 서브넷의 시작(이름표) | 아니오 |
| 첫 사용 가능 주소 | 네트워크 주소 + 1 | 예 |
| 마지막 사용 가능 주소 | 브로드캐스트 주소 − 1 | 예 |
| 브로드캐스트 주소 | 서브넷의 끝(전체 호출용) | 아니오 |

_표 8. 주소 4종 세트_

계산 방법은 2진수를 펼치지 않아도 됩니다. **블록 크기(증가값)** 하나만 구하면 암산으로 끝납니다.

> **블록 크기 = 256 − (마스크에서 255도 0도 아닌 옥텟의 값)**
{: .prompt-tip }

`/27`이면 마스크가 `255.255.255.224`이므로 블록 크기는 256 − 224 = 32입니다. 즉 이 대역의 서브넷들은 **0, 32, 64, 96, 128, 160, 192, 224**에서 시작합니다. 32칸씩 끊어진 눈금이라고 생각하면 쉽습니다.

### 예제 1 — `192.168.10.77 /27`은 어느 서브넷에 속하는가

| 단계 | 계산 | 결과 |
|---|---|---|
| ① 블록 크기 | 256 − 224 | **32** |
| ② 눈금 나열 | 0, 32, **64**, 96, … | 32의 배수 |
| ③ 네트워크 주소 | 77을 넘지 않는 가장 큰 눈금 = 64 | **192.168.10.64** |
| ④ 브로드캐스트 | 다음 눈금(96) − 1 = 95 | **192.168.10.95** |
| ⑤ 첫 사용 가능 | 64 + 1 | **192.168.10.65** |
| ⑥ 마지막 사용 가능 | 95 − 1 | **192.168.10.94** |

_표 9. 4종 세트 계산 절차(예제 1)_

즉 `192.168.10.77`은 `192.168.10.64 ~ 192.168.10.95` 구간에 사는 장비이고, 이 서브넷에는 65번부터 94번까지 30대가 들어갈 수 있습니다.


### 예제 2 — `172.16.1.100 /26`

블록 크기는 256 − 192 = 64입니다. 눈금은 0, 64, 128, 192입니다. 100을 넘지 않는 가장 큰 눈금은 64이므로 네트워크 주소는 `172.16.1.64`, 다음 눈금 128에서 1을 뺀 `172.16.1.127`이 브로드캐스트입니다. 따라서 사용 가능한 범위는 **`172.16.1.65` ~ `172.16.1.126`**, 총 62개입니다.

### 예제 3 — 세 번째 옥텟에서 끊기는 경우 `172.16.9.5 /23`

마스크는 `255.255.254.0`이고, 255도 0도 아닌 옥텟은 세 번째 자리의 254입니다. 블록 크기는 256 − 254 = 2이며, 이 눈금은 **세 번째 옥텟**에 적용됩니다. 눈금은 0, 2, 4, 6, **8**, 10…이고 9를 넘지 않는 가장 큰 눈금은 8이므로 네트워크 주소는 `172.16.8.0`입니다. 다음 눈금은 `172.16.10.0`이니 브로드캐스트는 그 바로 앞인 `172.16.9.255`, 사용 가능 범위는 `172.16.8.1 ~ 172.16.9.254`(510개)가 됩니다.

> **여기서 자주 틀립니다.** 블록 크기는 **마스크에서 값이 255도 0도 아닌 옥텟**에 적용됩니다. `/27`이면 네 번째 옥텟에, `/23`이면 세 번째 옥텟에 눈금을 긋습니다. 어느 옥텟에 눈금을 긋는지부터 확인하는 습관을 들이시기 바랍니다.
{: .prompt-warning }

### 손으로 해 보기 ④ — 주소 4종 세트 구하기

이 연습이 오늘 가장 많이 손을 쓰는 부분입니다. 다섯 문제를 **표를 덮어 두고** 네 단계로 풀어 보십시오.

> **푸는 법(예시) — `10.30.5.140 /28`**
> **① 블록 크기** 마스크는 `255.255.255.240`이고 255도 0도 아닌 옥텟은 네 번째 자리의 240입니다. 256 − 240 = **16**.
> **② 눈금** 16의 배수를 140 근처까지 세어 봅니다. …112, 128, **144**. 140을 넘지 않는 가장 큰 눈금은 **128**입니다.
> **③ 네트워크 주소와 브로드캐스트** 네트워크는 `10.30.5.128`, 다음 눈금 144에서 1을 뺀 `10.30.5.143`이 브로드캐스트입니다.
> **④ 첫·마지막 사용 가능** 128 + 1 = `10.30.5.129`, 143 − 1 = `10.30.5.142`. 사용 가능 주소는 14개입니다.
{: .prompt-tip }

**빈칸을 손으로 채우십시오.** 옆의 계산 칸에는 블록 크기와 눈금을 적으며 푸는 것이 좋습니다.

| 문제 | 블록 크기 | 네트워크 주소 | 첫 사용 가능 | 마지막 사용 가능 | 브로드캐스트 |
|---|---|---|---|---|---|
| 예시 `10.30.5.140 /28` | 16 | 10.30.5.128 | 10.30.5.129 | 10.30.5.142 | 10.30.5.143 |
| (1) `192.168.1.130 /26` | | | | | |
| (2) `10.0.0.55 /28` | | | | | |
| (3) `172.16.5.200 /27` | | | | | |
| (4) `192.168.7.90 /25` | | | | | |
| (5) `172.20.13.7 /22` | | | | | |

_연습 4. 주소 4종 세트 계산_

> **(5)번은 함정입니다.** `/22`의 마스크는 `255.255.252.0`이라 255도 0도 아닌 옥텟이 **세 번째 자리**입니다. 눈금을 네 번째 옥텟에 그으면 답이 완전히 달라지니, 어느 옥텟인지부터 확인하십시오.
{: .prompt-warning }

**검산하는 법.** 답을 구한 뒤 아래 두 가지가 맞는지 확인하면 실수를 거의 다 잡을 수 있습니다.

| 검산 항목 | 확인 내용 |
|---|---|
| 개수 | (브로드캐스트 − 네트워크 주소) + 1 = 블록 크기와 같은가 |
| 소속 | 문제의 IP가 첫 사용 가능과 마지막 사용 가능 **사이**에 들어 있는가 |

_연습 4-1. 4종 세트 검산법_

### 연습 4 정답

| 문제 | 블록 크기 | 네트워크 주소 | 첫 사용 가능 | 마지막 사용 가능 | 브로드캐스트 |
|---|---|---|---|---|---|
| (1) `192.168.1.130 /26` | 64 | 192.168.1.128 | 192.168.1.129 | 192.168.1.190 | 192.168.1.191 |
| (2) `10.0.0.55 /28` | 16 | 10.0.0.48 | 10.0.0.49 | 10.0.0.62 | 10.0.0.63 |

_연습 4-2. 정답_

**(4)번을 틀렸다면**, 눈금이 0과 128 두 개뿐이라는 점을 놓쳤을 가능성이 큽니다. 90은 128보다 작으므로 네트워크 주소는 `.0`입니다.

**(5)번을 틀렸다면**, 눈금을 네 번째 옥텟에 그었을 것입니다. `/22`는 **세 번째 옥텟**에 4칸 간격의 눈금을 긋습니다(0, 4, 8, **12**, 16). 그래서 네트워크 주소가 `172.20.12.0`이고, 다음 눈금인 `172.20.16.0` 바로 앞이 브로드캐스트입니다.

## 6. 핵심 ③ — 부서마다 대수가 다를 때(VLSM)

지금까지는 하나의 서브넷만 보았습니다. 그런데 실제 회사에는 부서가 여럿이고, 부서마다 장비 대수가 다릅니다. 영업부는 60대인데 관리부는 10대인 식입니다. 이때 모든 부서에 같은 크기를 주면(이를 **FLSM**, 고정 길이 방식이라 합니다) 관리부에서 주소가 대량으로 남습니다.

**필요한 대수에 맞춰 서브넷 크기를 제각각 다르게 나누는 방법**을 **VLSM**(Variable Length Subnet Mask, 가변 길이 서브넷 마스크)이라 합니다. 방법은 간단하지만 **순서가 절대적으로 중요**합니다.

> **VLSM의 철칙 — 큰 것부터 배치한다.**
{: .prompt-warning }

작은 것부터 배치하면 나중에 큰 덩어리를 넣을 자리가 조각나서 들어가지 않습니다. 책장에 두꺼운 책부터 꽂고 얇은 책을 나중에 끼워 넣는 것과 같은 이치입니다.

### 워크스루 — `192.168.100.0/24`를 아래 요구대로 나누기

| 구역 | 장비 대수 | 게이트웨이 | 필요한 IP 개수 |
|---|---|---|---|
| A동 | 50 | 1 | 51 |
| B동 | 20 | 1 | 21 |
| C동 | 5 | 1 | 6 |
| 라우터 간 연결 구간 | — | 2(양쪽 라우터) | 2 |

_표 10. 요구사항_

**1단계 — 큰 것부터 줄을 세웁니다.** A동(51) → B동(21) → C동(6) → 연결 구간(2) 순서입니다.

**2단계 — 각각 표 6에서 마스크를 고릅니다.** 51개는 `/26`(62개), 21개는 `/27`(30개), 6개는 `/29`(6개), 2개는 `/30`(2개)입니다.

**3단계 — 0번지부터 순서대로 붙여 나갑니다.** 앞 서브넷의 브로드캐스트 주소 바로 다음이 다음 서브넷의 네트워크 주소입니다.

| 순서 | 구역 | 필요 | CIDR | 네트워크 주소 | 사용 가능 범위 | 브로드캐스트 |
|---|---|---|---|---|---|---|
| 1 | A동 | 51 | /26 | 192.168.100.0 | .1 ~ .62 | 192.168.100.63 |
| 2 | B동 | 21 | /27 | 192.168.100.64 | .65 ~ .94 | 192.168.100.95 |
| 3 | C동 | 6 | /29 | 192.168.100.96 | .97 ~ .102 | 192.168.100.103 |
| 4 | 연결 구간 | 2 | /30 | 192.168.100.104 | .105 ~ .106 | 192.168.100.107 |

_표 11. VLSM 배치 결과_


`192.168.100.108`부터 `.255`까지는 아직 쓰지 않은 여유분으로 남습니다. 나중에 부서가 늘면 여기서 잘라 쓰면 됩니다.

라우터끼리 연결하는 구간에 `/30`을 쓰는 이유도 이제 분명합니다. 양쪽 라우터 인터페이스 두 개 말고는 아무것도 붙지 않으므로, 사용 가능 주소가 딱 2개인 `/30`이 정확히 들어맞기 때문입니다.

> **생각해 보기 — 작은 것부터 배치하면 정말 안 될까요?**
> 위 예시에서 C동(`/29`)을 0번지에 먼저 놓으면 `192.168.100.0 ~ .7`을 씁니다. 그 다음 A동에 `/26`을 주려면 `.8`부터 시작해야 하는데, `/26`의 눈금은 0, 64, 128, 192뿐이라 `.8`에서는 시작할 수 없습니다. 결국 `.64`로 밀려나고 `.8 ~ .63`의 56개가 조각으로 버려집니다. 큰 것부터 배치해야 하는 이유가 바로 이것입니다.
{: .prompt-info }

### 손으로 해 보기 ⑤ — VLSM으로 직접 나누기

바로 위의 워크스루(`192.168.100.0/24`)가 완성된 예시입니다. 이번에는 여러분이 다른 대역을 나눌 차례입니다.

## 7. 계산한 주소를 장비에 나눠 주는 규칙

서브넷을 나눴다면 이제 그 안의 주소를 실제 장비에 배정해야 합니다. 아무렇게나 줘도 통신은 되지만, 실무에서는 **다음에 이 네트워크를 볼 사람(또는 반년 뒤의 나)이 한눈에 알아볼 수 있도록** 자리를 정해 두고 씁니다. 널리 쓰이는 관례는 다음과 같습니다.

| 구간 | 용도 | 예(`/27`, 192.168.10.0 ~ .31) |
|---|---|---|
| 마지막 사용 가능 주소 | **게이트웨이(라우터 인터페이스)** | 192.168.10.30 |
| 첫 몇 개 | 서버·프린터 등 **고정 IP**가 필요한 장비 | 192.168.10.1 ~ .5 |
| 가운데 | 일반 PC(주로 **DHCP 자동 할당**) | 192.168.10.6 ~ .29 |

_표 12. 서브넷 내 주소 배정 관례_

게이트웨이를 첫 주소(`.1`)로 두는 회사도 많습니다. 어느 쪽이든 상관없지만, **하나를 정했으면 회사 전체에서 똑같이 지키는 것**이 중요합니다. 이 특강에서는 계산 연습을 겸해 **게이트웨이 = 그 서브넷의 마지막 사용 가능 주소**로 통일하겠습니다. 이렇게 하면 서브넷을 만들 때마다 마지막 사용 가능 주소를 자동으로 한 번씩 계산하게 됩니다.

### 고정(Static) 할당과 자동(DHCP) 할당

장비에 IP를 주는 방법은 두 가지입니다.

| 방식 | 방법 | 어떤 장비에 쓰나 | 장단점 |
|---|---|---|---|
| 고정(Static) | 사람이 직접 입력 | 서버, 프린터, 라우터, 스위치 관리 IP | 주소가 절대 바뀌지 않음 / 대수가 많으면 입력이 고통스럽고 실수하기 쉬움 |
| 자동(DHCP) | 서버(보통 라우터)가 자동으로 나눠 줌 | 일반 PC, 노트북, 스마트폰 | 손이 안 감 / 주소가 바뀔 수 있어 서버에는 부적합 |

_표 13. 정적 할당과 DHCP 할당_

DHCP를 쓸 때 반드시 함께 해야 하는 일이 **제외 주소(excluded-address) 지정**입니다. 고정 IP를 준 서버나 게이트웨이의 주소를 DHCP가 모르고 다른 PC에게 또 나눠 주면 **IP 충돌**이 일어나 두 장비 모두 통신이 끊깁니다. 그래서 이 범위는 손대지 말라고 미리 알려 줘야 합니다. 실습 세트 3에서 직접 설정해 보겠습니다.

### 손으로 해 보기 ⑥ — 서브넷 안에서 자리 나누기

서브넷의 범위를 구했다면 마지막 일은 그 안을 **용도별로 구획하는 것**입니다.

> **푸는 법(예시) — `10.5.9.0/27`인 어느 사무실**
> 먼저 범위를 구합니다. 블록 32, 사용 가능 주소는 `10.5.9.1 ~ 10.5.9.30`입니다.
> **게이트웨이**는 이 수업 규약대로 마지막 사용 가능 주소인 `10.5.9.30`입니다.
> **고정 IP 구간**은 서버·프린터 3대를 위해 첫 주소부터 `10.5.9.1 ~ 10.5.9.3`을 잡습니다.
> **DHCP 풀**은 그 다음부터 게이트웨이 바로 앞까지, 즉 `10.5.9.4 ~ 10.5.9.29`(26개)입니다.
{: .prompt-tip }

**연습 5에서 구한 `192.168.7.0/24`의 도서관 서브넷**에 대해 아래 빈칸을 채우십시오. 도서관에는 고정 IP가 필요한 장비가 **4대**(대출 서버 1, 프린터 2, 무선 AP 1) 있고, 나머지 열람용 PC는 DHCP로 받습니다.

| 항목 | 주소(범위) | 개수 |
|---|---|---|
| 서브넷 범위(네트워크 ~ 브로드캐스트) | | |
| 사용 가능 주소 범위 | | |
| 게이트웨이 | | 1 |
| 고정 IP 구간(서버·프린터·AP) | | 4 |
| DHCP 풀 구간 | | |

_연습 6. 서브넷 내부 자리 배정표_

### 연습 6 정답

| 항목 | 주소(범위) | 개수 |
|---|---|---|
| 서브넷 범위 | 192.168.7.64 ~ 192.168.7.95 | 32 |
| 사용 가능 주소 범위 | 192.168.7.65 ~ 192.168.7.94 | 30 |
| 게이트웨이 | 192.168.7.94 | 1 |
| 고정 IP 구간 | 192.168.7.65 ~ 192.168.7.68 | 4 |
| DHCP 풀 구간 | 192.168.7.69 ~ 192.168.7.93 | 25 |

_연습 6-1. 정답_

DHCP 풀은 고정 IP 구간이 끝난 `.69`부터, 게이트웨이(`.94`) **바로 앞**인 `.93`까지입니다. 게이트웨이 주소가 풀 안에 들어가면 IP 충돌이 나므로 반드시 제외해야 합니다. 개수는 93 − 69 + 1 = 25개입니다.

> **왜 굳이 구획을 나눌까요?** 나누지 않아도 통신은 됩니다. 그러나 반년 뒤 "프린터 IP가 몇 번이었지?"라는 질문을 받았을 때, 규칙이 있으면 "앞쪽 고정 구간"이라고 바로 답할 수 있고 없으면 30개를 전부 뒤져야 합니다. 규칙은 미래의 나를 위한 배려입니다.
{: .prompt-info }
