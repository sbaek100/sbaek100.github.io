> 시스코의 네트워크 시뮬레이터인 **패킷 트레이서(Packet Tracer) 9.0**을 설치·실행하고, PC 두 대를 케이블로 연결해 가장 단순한 네트워크를 만든 뒤 서로 통신(ping)이 되는지 확인합니다. 1강 이론에서 배운 ‘물리 계층(케이블)’과 ‘네트워크 계층(IP 주소)’이 실제로 함께 동작하는 모습을 눈으로 보게 됩니다.

## 1. 패킷 트레이서 9.0이란

이 과정의 모든 실습은 시스코의 무료 시뮬레이터인 **패킷 트레이서(Packet Tracer) 9.0**으로 진행합니다. 실제 장비 없이도 라우터·스위치·PC를 화면에 배치하고 케이블로 연결해, 데이터가 오가는 과정을 눈으로 확인할 수 있는 프로그램입니다. 실제 장비를 사려면 수백만 원이 들지만, 패킷 트레이서 안에서는 얼마든지 만들고 지우며 연습할 수 있습니다.

> **설치 안내** 시스코 네트워킹 아카데미(netacad.com)에서 무료로 내려받아 설치합니다. 계정을 만들어 로그인하거나, 로그인 창에서 `[Guest Login]`을 눌러 손님 모드로 실행할 수 있습니다. 이 과정은 9.0 버전을 기준으로 설명하지만, 8.x 버전에서도 대부분 동일하게 따라 할 수 있습니다.
{: .prompt-tip }

## 2. 화면 구성 익히기

실습을 시작하기 전에 화면이 어떻게 생겼는지 알아 둡니다. 처음에는 버튼이 많아 복잡해 보이지만, 실제로 자주 쓰는 곳은 몇 군데뿐입니다.

먼저 **왼쪽 아래의 큰 상자가 장치 선택 영역**입니다. 맨 아래 왼쪽 아이콘으로 장치의 종류(라우터·스위치·PC·서버 등)를 고르면, 그 오른쪽에 해당 종류의 장치 목록이 나타납니다. 여기서 원하는 장치를 골라 가운데의 넓은 작업 영역으로 끌어다(드래그) 놓습니다.

![](/assets/img/posts/2026-08-18-netintro-01b-lab-first-network-1786423839881.png)

장치를 한 번 클릭하면 설정 창이 열립니다. 창 위쪽에는 탭이 있는데, 라우터·스위치는 `[Physical]`·`[Config]`·`[CLI]` 탭이, PC는 `[Physical]`·`[Config]`·`[Desktop]` 탭이 있습니다. **PC의 IP 설정과 명령 프롬프트는 `[Desktop]` 탭에, 라우터·스위치의 명령 입력은 `[CLI]` 탭에** 있다는 것만 기억하면 됩니다.

![그림 1-12. 장치를 클릭하면 열리는 설정 창의 탭 구성](/assets/img/posts/2026-03-09-netintro-c1-12.png)
_그림 1-12. 장치를 클릭하면 열리는 설정 창의 탭 구성_

케이블은 장치 선택 영역에서 번개 모양 아이콘([Connections])을 고르면 나타납니다. 번개 모양(자동)을 쓰면 두 장치에 알맞은 케이블을 프로그램이 알아서 골라 주고, 직접 고를 때는 다이렉트(실선)·크로스오버(점선) 등을 선택합니다.

![그림 1-13. 케이블 선택 — 번개 아이콘(자동)과 케이블 종류 목록](/assets/img/posts/2026-03-09-netintro-c1-14.png)
_그림 1-13. 케이블 선택 — 번개 아이콘(자동)과 케이블 종류 목록_

마지막으로 오른쪽 아래의 `[Realtime]`/`[Simulation]` 버튼으로 모드를 바꿉니다. 평소에는 실시간(Realtime) 모드로 쓰다가, 데이터가 어떻게 흐르는지 한 단계씩 들여다보고 싶을 때 시뮬레이션(Simulation) 모드로 바꾸면 패킷이 봉투 모양으로 천천히 움직이는 것을 볼 수 있습니다.

![그림 1-14. 오른쪽 아래의 Realtime / Simulation 모드 전환 버튼](/assets/img/posts/2026-03-09-netintro-c1-15.png)
_그림 1-14. 오른쪽 아래의 Realtime / Simulation 모드 전환 버튼_

## 3. 실습 1-1. PC 두 대를 직접 연결하기

> **실습 목표** PC 두 대를 케이블로 직접 연결하고 IP 주소를 부여해, 서로 통신(ping)이 되는지 확인한다.
> **주소 계획** 이 주소는 우리가 학기 말에 완성할 회사 네트워크의 ‘본사 사무실 PC’ 대역을 미리 써 보는 것입니다.
>
> | 장치 | IP 주소 | 서브넷 마스크 |
> |---|---|---|
> | PC0 (A-PC1) | 172.16.8.1 | 255.255.254.0 |
> | PC1 (A-PC2) | 172.16.8.2 | 255.255.254.0 |
{: .prompt-tip }

> **잠깐 — 서브넷 마스크가 왜 255.255.254.0인가요?** 지금은 “두 PC가 같은 네트워크(172.16.8.0/23)에 속하도록 정해 준 값”이라고만 이해하면 충분합니다. `/23`이 왜 `255.255.254.0`이 되는지는 2강(IP 주소와 서브네팅)에서 계산법과 함께 자세히 배웁니다. 지금은 표의 값을 그대로 입력하세요.
{: .prompt-info }

**실습 절차**

**1단계 — PC 두 대 놓기.** 왼쪽 아래 장치 선택 영역에서 `[End Devices]`(단말) 아이콘을 고른 뒤, 오른쪽 목록의 `[PC]`를 작업 영역으로 두 번 끌어다 놓습니다. `PC0`과 `PC1`이 생깁니다.

![그림 1-15. 작업 영역에 PC 두 대(PC0, PC1)를 배치](/assets/img/posts/2026-03-09-netintro-c1-16.png)
_그림 1-15. 작업 영역에 PC 두 대(PC0, PC1)를 배치_

**2단계 — 케이블로 잇기.** 번개 아이콘([Connections])을 고르고 목록에서 `[Copper Cross-Over]`(구리 크로스오버, 점선)를 선택합니다. PC0을 클릭하면 포트 목록이 뜨는데 `FastEthernet0`을 고르고, 이어 PC1을 클릭해 마찬가지로 `FastEthernet0`을 고르면 두 PC가 케이블로 이어집니다.

> **왜 크로스오버 케이블인가요?** PC와 PC처럼 같은 종류의 장치를 직접 연결할 때는 원래 크로스오버 케이블을 씁니다. 패킷 트레이서는 자동(번개 모양) 케이블도 지원하므로, 종류를 고르기 번거로우면 자동을 써도 됩니다. 케이블 양 끝에 초록색 삼각형이 뜨면 물리적으로 잘 연결된 것입니다.
{: .prompt-info }

![그림 1-16. 크로스오버 케이블로 두 PC의 FastEthernet0 포트를 연결](/assets/img/posts/2026-03-09-netintro-c1-17.png)
_그림 1-16. 크로스오버 케이블로 두 PC의 FastEthernet0 포트를 연결_

**3단계 — PC0에 IP 주소 넣기.** PC0을 클릭한 뒤 `[Desktop]` 탭 → `[IP Configuration]`을 엽니다. `[Static]`(고정)을 고르고, IP Address 칸에 `172.16.8.1`, Subnet Mask 칸에 `255.255.254.0`을 입력합니다. (서브넷 마스크는 IP를 입력하고 칸을 벗어나면 자동으로 채워지기도 하는데, 값이 다르면 표대로 고쳐 줍니다.) 창을 닫습니다.

![](/assets/img/posts/2026-08-18-netintro-01b-lab-first-network-1786423935739.png)

**4단계 — PC1에 IP 주소 넣기.** 같은 방법으로 PC1은 IP `172.16.8.2`, Subnet Mask `255.255.254.0`을 입력합니다.

**5단계 — 통신 확인(ping).** 다시 PC0을 클릭 → `[Desktop]` 탭 → `[Command Prompt]`를 엽니다. 아래 명령을 입력하고 Enter를 누릅니다.

```text
ping 172.16.8.2
```



상대 PC가 응답하면 다음과 비슷한 결과가 나옵니다. `Reply from ...`이 네 줄 보이고 `Lost = 0`이면 성공입니다.

```text
Pinging 172.16.8.2 with 32 bytes of data:

Reply from 172.16.8.2: bytes=32 time<1ms TTL=128
Reply from 172.16.8.2: bytes=32 time<1ms TTL=128
Reply from 172.16.8.2: bytes=32 time<1ms TTL=128
Reply from 172.16.8.2: bytes=32 time<1ms TTL=128

Ping statistics for 172.16.8.2:
    Packets: Sent = 4, Received = 4, Lost = 0 (0% loss),
```

![](/assets/img/posts/2026-08-18-netintro-01b-lab-first-network-1786424015087.png) 


> **결과 확인** 케이블 양 끝의 점이 초록 삼각형이 되고, Command Prompt에 `Reply from 172.16.8.2`가 4줄 나오면 통신 성공입니다. 이 구성은 **물리 계층(케이블)과 네트워크 계층(IP)이 함께 동작한 결과**입니다. 두 PC가 같은 네트워크에 속해 있어서 중간에 라우터 없이도 바로 대화할 수 있었습니다.
{: .prompt-tip }

## 4. 실습 1-2. 스위치를 가운데 두고 연결하기 (확장)

실제 사무실에서는 PC를 서로 직접 잇지 않고, 가운데에 **스위치**를 두어 여러 대를 한꺼번에 연결합니다. 우리가 만들 회사 네트워크의 본사 PC들도 스위치에 물려 있습니다. 이번에는 스위치를 하나 두고 PC 두 대를 연결해 봅니다.

**실습 절차**

**1단계.** 왼쪽 아래에서 `[Network Devices] > [Switches]`를 고르고 `2960` 스위치 한 대를 작업 영역에 놓습니다.

![](/assets/img/posts/2026-08-18-netintro-01b-lab-first-network-1786424078370.png)



**2단계.** 번개 아이콘에서 `[Copper Straight-Through]`(구리 다이렉트, 실선)를 골라, PC0의 `FastEthernet0`을 스위치의 `FastEthernet0/1`에, PC1의 `FastEthernet0`을 스위치의 `FastEthernet0/2`에 연결합니다.

![](/assets/img/posts/2026-08-18-netintro-01b-lab-first-network-1786424121007.png)

> **PC–스위치는 왜 다이렉트 케이블인가요?** PC와 스위치처럼 서로 다른 종류의 장치를 이을 때는 다이렉트(Straight-Through) 케이블을 씁니다. ‘같은 종류끼리는 크로스오버, 다른 종류끼리는 다이렉트’로 기억하면 쉽습니다. (역시 자동 케이블을 써도 됩니다.)
{: .prompt-info }

**3단계.** IP 주소는 실습 1-1에서 넣은 값(172.16.8.1, 172.16.8.2)을 그대로 씁니다. 스위치는 지금 단계에서는 아무 설정 없이도 동작하므로, 별도 설정이 필요 없습니다.

**4단계.** PC0의 Command Prompt에서 다시 `ping 172.16.8.2`를 실행해, 스위치를 거쳐도 통신이 되는지 확인합니다. 처음 한두 개가 `Request timed out`으로 나오고 나머지가 성공하는 경우가 있는데, 이는 스위치가 상대의 위치(MAC 주소)를 처음 배우는 데 잠깐 시간이 걸리기 때문입니다. 정상입니다.

> **결과 확인** 스위치를 거쳐도 ping이 성공하면 완료입니다. 스위치가 왜 필요하고 내부에서 어떻게 동작하는지(MAC 주소 학습)는 4강(네트워크 장비와 스위칭)에서 자세히 배웁니다.
{: .prompt-tip }

> **생각해 보기 — 첫 ping은 왜 한두 개가 실패했을까?**
> 스위치를 거친 첫 통신에서 처음 한두 개가 `Request timed out`으로 나오는 일이 있습니다. 케이블도 IP도 정상인데 왜 그럴까요? 힌트는 “상대의 위치(MAC 주소)를 아직 모른다”는 데 있습니다. 스위치와 PC가 상대를 처음 ‘알아 가는’ 데 아주 짧은 시간이 걸리기 때문인데, 이 과정의 정체는 2강에서 배우는 ARP입니다. 즉 실패가 아니라 ‘서로 인사하는 시간’인 셈입니다.
{: .prompt-info }

## 5. 잘 안 될 때 점검 순서

실습이 처음이면 대부분 아래 세 가지 중 하나가 원인입니다. 위에서부터 차례로 확인해 보세요.

| 증상 | 점검할 것 |
|---|---|
| 케이블 끝이 빨간 점(연결 안 됨) | 케이블 종류가 맞는지(PC끼리=크로스오버, PC–스위치=다이렉트), 올바른 포트(FastEthernet0)에 꽂았는지 |
| `Request timed out`이 계속 나옴 | 두 PC의 IP·서브넷 마스크를 표대로 정확히 입력했는지(오타·마스크 값), 두 PC가 같은 네트워크(172.16.8.x)인지 |
| `Ping request could not find host` | IP가 아니라 이름을 입력했는지 확인. `ping` 뒤에는 반드시 IP 주소(172.16.8.2)를 쓴다 |

축하합니다. 방금 여러분은 가장 작은 네트워크를 직접 만들었습니다. 겉으로는 PC 두 대를 이은 것뿐이지만, 그 안에서는 1강 이론에서 배운 물리 계층과 네트워크 계층이 실제로 협력하고 있습니다. 다음 편([1강 실습 문제])에서는 배운 내용을 스스로 적용해 보는 과제에 도전합니다. 그리고 2강부터는 이 IP 주소가 어떻게 정해지는지 — 서브네팅 — 를 본격적으로 배웁니다.
