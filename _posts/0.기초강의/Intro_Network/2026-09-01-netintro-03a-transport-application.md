> **학습목표**
> 1. 포트 번호의 구조와 대표 포트를 설명할 수 있다.
> 2. TCP와 UDP의 차이를 설명하고, 각각 어디에 쓰이는지 예를 들 수 있다.
> 3. TCP 3-way 핸드셰이크와 주요 제어 플래그의 역할을 설명할 수 있다.
> 4. HTTP·DNS·DHCP·메일(SMTP/POP3)의 역할과 Telnet·SSH의 차이를 설명할 수 있다.
{: .prompt-info }

2강에서 네트워크 계층이 ‘컴퓨터(호스트)까지’ 데이터를 날라 주었다면, 이 강의 **전송 계층**은 그 컴퓨터 안의 정확한 ‘프로그램(프로세스)까지’ 데이터를 전달합니다. 그리고 그 위의 **응용 계층**에는 우리가 매일 쓰는 웹·메일·이름 조회(DNS)·주소 자동 배정(DHCP) 같은 서비스가 있습니다. 이 강에서 배우는 서비스들은 8강(네트워크 서비스 구축)에서 직접 서버로 만들게 되므로, 여기서 개념을 확실히 잡아 둡시다.

## 1. 포트 번호

한 대의 컴퓨터는 IP 주소 하나만 가지고도 웹 브라우저·메일·메신저를 동시에 켤 수 있습니다. 이때 어떤 데이터가 어떤 프로그램의 것인지 구분해 주는 것이 **포트 번호**입니다. IP 주소가 ‘건물’이라면 포트 번호는 그 건물 안의 ‘호실’입니다. 포트 번호는 용도에 따라 세 구간으로 나뉩니다.

| 구간                   | 범위            | 용도                                |
| -------------------- | ------------- | --------------------------------- |
| 잘 알려진 포트(Well-known) | 0 ~ 1023      | HTTP(80)·DNS(53) 등 표준 서비스가 예약해 사용 |
| 등록된 포트(Registered)   | 1024 ~ 49151  | 특정 응용 프로그램이 등록해 사용                |
| 동적 포트(Dynamic)       | 49152 ~ 65535 | 클라이언트가 통신할 때 임시로 사용               |

_표 3-1. 포트 번호의 세 구간_

서버는 미리 정해진 번호(웹=80, DNS=53)로 서비스를 열어 두고 기다립니다. 그래서 우리는 서버의 IP만 알면 “80번으로 요청하면 웹이 응답할 것”이라고 확신할 수 있습니다. 반면 클라이언트(내 PC)는 접속할 때마다 임시 번호(동적 포트)를 받아 쓰고 통신이 끝나면 반납합니다.

## 2. TCP와 UDP

전송 계층에는 성격이 정반대인 두 프로토콜이 있습니다. **TCP**는 연결을 맺고 데이터가 순서대로, 빠짐없이 도착하도록 보장합니다(느려도 정확). **UDP**는 연결도 맺지 않고 도착 보장도 하지 않는 대신 매우 빠르고 가볍습니다(조금 잃어도 빠르게).

| 구분 | TCP | UDP |
|---|---|---|
| 연결 방식 | 연결형(연결 설정 후 전송) | 비연결형(바로 전송) |
| 신뢰성 | 높음(순서·재전송 보장) | 낮음(보장 없음) |
| 속도 | 상대적으로 느림 | 빠름 |
| 헤더 크기 | 20~60바이트 | 8바이트 |
| 대표 용도 | 웹·메일·파일 전송 | 실시간 스트리밍·DNS·인터넷 전화(VoIP) |

_표 3-2. TCP와 UDP의 비교_

> **생각해 보기 — 인터넷 전화는 TCP일까 UDP일까?**
> 파일을 내려받을 때는 한 글자라도 틀리면 안 되니 재전송으로 정확성을 보장하는 TCP가 맞습니다. 그런데 우리가 9강에서 만들 인터넷 전화(VoIP)는 어떨까요? 통화 중 아주 짧은 소리 한 조각이 사라졌다고 그것을 ‘재전송’해서 뒤늦게 들려준다면 오히려 더 어색할 것입니다. 실시간 통화·게임이 왜 TCP가 아니라 UDP를 쓰는지, ‘정확함’과 ‘제때 도착함’ 중 무엇이 더 중요한지 생각해 보세요.
{: .prompt-info }

## 3. TCP의 연결 과정

### (1) 3-way 핸드셰이크

TCP는 데이터를 보내기 전에 먼저 상대와 연결을 맺는데, 이 과정을 **3-way 핸드셰이크**라 합니다. 세 번의 인사로 서로의 대화 기준점(순서 번호)을 맞추는 과정입니다. ① 클라이언트가 “연결하고 싶다”는 SYN을 보내면, ② 서버가 “좋다(ACK), 나도 연결하겠다(SYN)”고 답하고, ③ 클라이언트가 “확인했다(ACK)”고 응답하면 연결이 성립합니다.

![그림 3-1. TCP 3-way 핸드셰이크](/assets/img/posts/2026-03-09-netintro-c2-33.png)
_그림 3-1. TCP 3-way 핸드셰이크_

### (2) 제어 플래그

TCP 세그먼트의 헤더에는 연결과 전송을 제어하는 6개의 플래그가 있습니다. 이 플래그를 읽을 줄 아는 것은 패킷 분석과 공격 이해의 핵심입니다.

![그림 3-2. TCP 세그먼트 헤더 형식](/assets/img/posts/2026-03-09-netintro-c2-32.png)
_그림 3-2. TCP 세그먼트 헤더 형식_

| 플래그 | 의미 |
|---|---|
| SYN | 연결을 설정하고 순서 번호를 동기화 |
| ACK | 확인 응답이 유효함(연결 중 대부분 켜짐) |
| FIN | 더 보낼 데이터가 없으니 연결을 종료 |
| RST | 연결을 강제로 끊거나 비정상 연결을 거부 |
| PSH | 버퍼에 쌓지 말고 즉시 응용 계층으로 전달 |
| URG | 긴급 데이터가 있음 |

_표 3-3. TCP 제어 플래그_

> **보안 유의 — SYN 플러딩** 3-way 핸드셰이크의 허점을 노린 공격이 SYN 플러딩입니다. 공격자가 SYN만 잔뜩 보내고 마지막 ACK를 보내지 않으면, 서버는 완성되지 않은 ‘반쯤 열린’ 연결을 계속 쌓아 두다가 결국 정상 사용자의 접속까지 거부하게 됩니다(서비스 거부, DoS). 이 공격은 10강에서 다시 다룹니다.
{: .prompt-warning }

## 4. 응용 계층의 주요 서비스

응용 계층은 사용자와 가장 가까운 계층으로, 우리가 쓰는 프로그램에 네트워크 서비스를 제공합니다. 대회에서 만들 서비스들을 중심으로 살펴봅니다.

| 프로토콜 | 포트 | 전송 계층 | 기능 |
|---|---|---|---|
| HTTP / HTTPS | 80 / 443 | TCP | 웹 페이지 요청·응답 |
| DNS | 53 | UDP/TCP | 도메인 이름 ↔ IP 변환 |
| DHCP | 67·68 | UDP | IP 주소 자동 배정 |
| SMTP | 25 | TCP | 메일 발송 |
| POP3 | 110 | TCP | 메일 수신(내려받기) |
| Telnet | 23 | TCP | 원격 접속(평문) |
| SSH | 22 | TCP | 원격 접속(암호화) |

_표 3-4. 대표적인 응용 계층 프로토콜_

### (1) DNS — 이름을 주소로

사람은 `www.secu.com` 같은 이름을 기억하지만, 컴퓨터는 IP 주소로만 통신합니다. **DNS**(Domain Name System)는 이 이름을 IP 주소로 바꿔 주는 ‘인터넷의 전화번호부’입니다. 우리가 8강에서 DNS 서버를 만들 때, `intra.secu.com`이라는 이름에 특정 서버의 IP를 연결하는 ‘A 레코드’를 직접 등록하게 됩니다.

### (2) DHCP — 주소를 자동으로

지금까지 우리는 PC마다 IP를 손으로 하나씩 넣었습니다. 하지만 PC가 수백 대라면 이는 불가능합니다. **DHCP**(Dynamic Host Configuration Protocol)는 새로 연결된 단말에 IP·서브넷 마스크·게이트웨이·DNS 주소를 자동으로 배부합니다. 네 단계의 머리글자를 따 **DORA**라 부릅니다.

| 단계         | 동작                             |
| ---------- | ------------------------------ |
| ① Discover | 단말이 ‘DHCP 서버 있나요?’를 전체에 브로드캐스트 |
| ② Offer    | 서버가 사용 가능한 IP를 제안              |
| ③ Request  | 단말이 그 IP를 쓰겠다고 요청              |
| ④ Ack      | 서버가 확정하고 임대 기간을 부여             |
|            |                                |

_표 3-5. DHCP의 4단계(DORA)_

### (3) 이메일 — 보낼 때와 받을 때가 다르다

이메일에서 가장 헷갈리는 점은, **보낼 때와 받을 때 쓰는 프로토콜이 다르다**는 것입니다. 편지를 부칠 때는 우체통(발송)으로, 받을 때는 우편함(수신)으로 가는 것과 같습니다. 보낼 때는 **SMTP**, 받을 때는 **POP3** 또는 **IMAP**을 씁니다.

| 프로토콜 | 포트 | 방향 | 역할 |
|---|---|---|---|
| SMTP | 25 | 보내기 | 메일을 서버로 올리고, 서버끼리 목적지까지 전달 |
| POP3 | 110 | 받기 | 서버의 메일을 내 기기로 내려받음(보통 서버에서는 삭제) |
| IMAP | 143 | 받기 | 메일을 서버에 둔 채 여러 기기에서 동기화 |

_표 3-6. 이메일 프로토콜_

**한 통의 메일이 오가는 흐름**을 따라가 봅시다. user01이 user02에게 메일을 보낸다고 합시다.

1. user01이 메일을 작성해 ‘보내기’를 누르면, user01의 메일 프로그램이 **SMTP**로 자신의 메일 서버에 메일을 올립니다.
2. user01의 메일 서버는 받는 주소(`user02@...`)를 보고, 다시 **SMTP**로 user02의 메일 서버까지 전달합니다(서버끼리도 SMTP를 씁니다).
3. user02의 메일 서버는 받은 메일을 user02의 **우편함(mailbox)** 에 저장해 둡니다.
4. user02가 자기 메일 프로그램에서 ‘받기’를 누르면, **POP3**(또는 IMAP)로 서버의 우편함에서 메일을 가져옵니다.

![](/assets/img/posts/2026-09-01-netintro-03a-transport-application-1786427624791.png)

여기서 핵심은 **보낼 때는 처음부터 끝까지 SMTP, 받을 때만 POP3/IMAP**이라는 점입니다. 그래서 메일 프로그램을 설정할 때 ‘보내는 메일 서버(SMTP)’와 ‘받는 메일 서버(POP3)’ 주소를 **각각** 입력해야 합니다.

**POP3와 IMAP은 어떻게 다를까요?** 둘 다 메일을 받는 프로토콜이지만 동작이 다릅니다. **POP3**는 서버의 메일을 내 기기로 내려받고 보통 서버에서는 지웁니다. 한 기기에서만 메일을 관리할 때는 단순하고 좋지만, 다른 기기에서는 그 메일을 볼 수 없습니다. 반면 **IMAP**은 메일을 서버에 그대로 두고 각 기기가 그 상태를 동기화하므로, 휴대폰·노트북·회사 PC 어디서 열어도 읽음·삭제 상태가 똑같이 유지됩니다. 여러 기기로 메일을 보는 오늘날에는 IMAP이 널리 쓰입니다.

> 대회 도면의 홈 사용자(H-Laptop·H-PC)가 메일을 주고받으려면, 보내는 서버 `smtp.skills.com`과 받는 서버 `pop3.skills.com`을 메일 프로그램에 각각 지정하고, 계정(`user01@skills.com` 등)을 설정해야 합니다. 실제 구성은 8강에서 직접 해 봅니다.
{: .prompt-info }


### (4) 원격 접속 — Telnet과 SSH

네트워크 장비는 대개 사람이 없는 곳에 설치되므로, 멀리서 접속해 관리하는 원격 접속이 필수입니다. 여기서 보안이 극명하게 갈립니다.

| 구분 | Telnet | SSH |
|---|---|---|
| 포트 | 23 | 22 |
| 암호화 | 없음(전 구간 평문) | 전 구간 암호화 |
| 사용 원칙 | 사용 지양 | 원격 관리의 표준 |
_표 3-7. Telnet과 SSH의 비교_

> **생각해 보기 — 왜 Telnet을 쓰면 안 될까?**
> Telnet은 아이디와 비밀번호를 포함한 모든 내용을 ‘평문’ 그대로 전송합니다. 같은 네트워크에서 누군가 지나가는 패킷을 엿본다면(2강의 ARP 스푸핑을 떠올려 보세요), 관리자의 비밀번호가 그대로 노출됩니다. 대회 지사 라우터에서 “SSHv2로만 접속을 허용하라”는 조건이 왜 붙는지, 그 이유를 한 문장으로 설명해 보세요. SSH 설정은 10강에서 직접 하게 됩니다.
{: .prompt-info }
