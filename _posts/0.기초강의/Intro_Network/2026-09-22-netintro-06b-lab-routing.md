> **이 실습에서 하는 일**
> 라우터 두 대로 서로 다른 두 네트워크를 잇습니다. 같은 목표(양쪽 PC 통신)를 정적 라우팅 → RIPv2 → OSPF 세 가지 방법으로 차례로 달성하며, 각 방식의 차이를 눈으로 확인합니다.
{: .prompt-info }

> **공통 토폴로지·주소 계획**
> `PC0 – SW1 – R1 – R2 – SW2 – PC1` 구조. LAN1 `192.168.10.0/24`(R1 g0/0 .254), LAN2 `192.168.20.0/24`(R2 g0/0 .254), R1–R2 구간 `10.0.0.0/30`(R1 g0/1 .1, R2 g0/1 .2). PC0 `192.168.10.1`(GW .254), PC1 `192.168.20.1`(GW .254).
{: .prompt-tip }

## 실습 6-1. 정적 라우팅

**1단계 — 배치·기본 설정.** 라우터(2911) 2대, 스위치 2대, PC 2대를 위 구조로 연결합니다. 각 라우터의 인터페이스에 IP를 설정하고 켭니다(R1 예).

```text
R1(config)# interface g0/0
R1(config-if)# ip address 192.168.10.254 255.255.255.0
R1(config-if)# no shutdown
R1(config-if)# exit
R1(config)# interface g0/1
R1(config-if)# ip address 10.0.0.1 255.255.255.252
R1(config-if)# no shutdown
```
R2도 같은 방식으로 g0/0=192.168.20.254, g0/1=10.0.0.2를 설정합니다. `show ip interface brief`로 두 인터페이스가 `up/up`인지 확인합니다.

**2단계 — 정적 경로 전 확인.** PC0에서 `ping 192.168.20.1`은 실패합니다. R1·R2가 아직 상대편 LAN으로 가는 길을 모르기 때문입니다.

**3단계 — 정적 경로 입력.** 각 라우터에 상대편 LAN으로 가는 경로를 넣습니다. 명령 구조는 `ip route [목적지] [마스크] [넥스트 홉]`입니다.

```text
R1(config)# ip route 192.168.20.0 255.255.255.0 10.0.0.2
R2(config)# ip route 192.168.10.0 255.255.255.0 10.0.0.1
```

**4단계 — 확인.** `show ip route`에 `S 192.168.20.0/24 [1/0] via 10.0.0.2` 형태의 경로(S=정적)가 보이고, PC0↔PC1 양방향 ping이 성공하면 완료입니다.

> **결과 확인** 정적 경로를 넣기 전에는 실패, 넣은 뒤에는 성공하면 완료입니다. 실패 시 ① PC의 IP·게이트웨이, ② 인터페이스 `no shutdown`, ③ `ip route`의 목적지·마스크·넥스트 홉을 점검합니다.
{: .prompt-tip }

## 실습 6-2. RIPv2로 바꾸기

**1단계.** 앞의 정적 경로를 지웁니다: R1 `no ip route 192.168.20.0 255.255.255.0 10.0.0.2`, R2 `no ip route 192.168.10.0 255.255.255.0 10.0.0.1`. ping이 다시 실패하는지 확인합니다.

**2단계.** RIPv2를 설정합니다. `network` 뒤에는 그 인터페이스가 속한 주요 네트워크를 적고, `version 2`로 지정합니다.

```text
R1(config)# router rip
R1(config-router)# version 2
R1(config-router)# network 192.168.10.0
R1(config-router)# network 10.0.0.0
```
R2도 `router rip → version 2 → network 192.168.20.0 → network 10.0.0.0`.

**3단계.** 30~60초 기다린 뒤 `show ip route`에 `R`로 표시된 경로가 학습됐는지 확인하고, 양방향 ping을 확인합니다.

```text
R1# show ip route
R    192.168.20.0/24 [120/1] via 10.0.0.2, 00:00:12, GigabitEthernet0/1
```

> **결과 확인** 정적 경로 없이 RIP 학습 경로(`R`)로 ping이 성공하면 완료입니다. `R`이 안 보이면 두 라우터 모두 `network`에 연결 구간(10.0.0.0)을 넣었는지, 양쪽 `version 2`인지, 정적 경로가 완전히 지워졌는지 확인합니다.
{: .prompt-tip }

## 실습 6-3. OSPF로 바꾸기

**1단계.** RIP를 지웁니다: 양쪽 라우터에서 `no router rip`.

**2단계.** OSPF를 설정합니다. 여기서는 마스크가 아니라 **와일드카드 마스크**를 씁니다(255.255.255.0 → `0.0.0.255`, /30 → `0.0.0.3`). 그리고 `area 0`으로 맞춥니다.

```text
R1(config)# router ospf 1
R1(config-router)# network 192.168.10.0 0.0.0.255 area 0
R1(config-router)# network 10.0.0.0 0.0.0.3 area 0
```
R2도 `router ospf 1 → network 192.168.20.0 0.0.0.255 area 0 → network 10.0.0.0 0.0.0.3 area 0`.

**3단계.** `show ip ospf neighbor`로 이웃 관계(State가 `FULL`)를 확인하고, `show ip route`에 `O` 경로가 학습됐는지 봅니다. 양방향 ping을 확인합니다.

> **[화면 삽입]** PT 9.0 — R1에서 `show ip ospf neighbor`에 R2와의 관계가 `FULL`로 표시되고, `show ip route`에 `O 192.168.20.0/24`가 나타난 화면.
> _(그림 파일 예정: `netintro-06b-01.png`)_

> **결과 확인** 이웃이 `FULL`이 되고 `O` 경로로 ping이 성공하면 완료입니다. `FULL`이 아니면 ① area 번호 일치, ② 와일드카드 마스크가 인터페이스 대역과 일치, ③ 인터페이스 up 상태를 점검합니다.
{: .prompt-tip }

> **생각해 보기 — 같은 목표, 세 가지 방법**
> 실습 6-1·6-2·6-3은 모두 ‘PC0과 PC1을 통신시킨다’는 똑같은 목표를 달성했습니다. 그런데 만약 R1–R2 사이에 우회 경로가 하나 더 생긴다면(라우터가 3대 이상), 세 방법의 차이가 드러납니다. 정적 라우팅은 사람이 다시 고쳐 줘야 하지만, RIP·OSPF는 스스로 새 경로를 찾습니다. 소규모 실습에서는 셋 다 똑같아 보이는데, 실제 큰 망에서는 왜 동적 라우팅이 필요한지 생각해 보세요.
{: .prompt-info }
