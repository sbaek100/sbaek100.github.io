> 1. IP 주소의 구조(네트워크부·호스트부)와 클래스, 사설 주소를 설명할 수 있다.

> 4. ARP·ICMP·NAT의 역할을 설명할 수 있다.
{: .prompt-info }

1강에서 우리는 PC에 `172.16.8.1`, 마스크 `255.255.254.0` 같은 값을 아무 설명 없이 입력했습니다. 이 강에서는 그 숫자들이 정확히 무엇을 뜻하는지 배웁니다. 특히 대회 문제지에 자주 나오는 **“사용 가능한 마지막 주소”** 를 계산하는 방법은 이 과정에서 반드시 손에 익혀야 할 핵심 기술입니다. 조금 계산이 나오지만, 규칙만 익히면 누구나 할 수 있으니 천천히 따라와 보세요.

## 1. IP 주소의 구조

IPv4 주소는 32비트로 이루어집니다. 사람이 보기 쉽도록 8비트씩 네 덩어리로 나누고, 각 덩어리를 10진수로 바꿔 점(.)으로 잇습니다. 그래서 `172.16.8.1`처럼 보이는 것이고, 각 덩어리(옥텟)는 0부터 255까지의 값을 가집니다.

IP 주소는 두 부분으로 나뉩니다. 앞부분은 **네트워크부**(어느 네트워크인가)이고, 뒷부분은 **호스트부**(그 네트워크 안의 몇 번째 장치인가)입니다. 아파트 주소에 비유하면, 네트워크부는 ‘○○아파트 △△동’이고 호스트부는 ‘몇 호’에 해당합니다. 같은 동(같은 네트워크)에 사는 사람끼리는 관리사무소를 거치지 않고 바로 왕래할 수 있지만, 다른 동으로 가려면 정문(라우터)을 거쳐야 합니다. 1강 실습에서 두 PC가 라우터 없이 통신할 수 있었던 것은 둘이 ‘같은 동(같은 네트워크)’에 속했기 때문입니다.

![](/assets/img/posts/2026-08-25-netintro-02a-ip-subnetting-1786424643685.png)


어디까지가 네트워크부이고 어디부터가 호스트부인지를 알려 주는 것이 바로 **서브넷 마스크**입니다.

## 2. 클래스 기반 주소와 사설 주소

인터넷 초기에는 네트워크부와 호스트부의 경계를 A부터 E까지 다섯 개의 고정된 클래스로 나누어 정했습니다. 첫 번째 옥텟 값만 보면 클래스를 알 수 있습니다.

| 클래스 | 첫 옥텟 범위 | 네트워크/호스트 비트 | 용도 |
|---|---|---|---|
| A | 0 ~ 127 | 8 / 24 | 대형 네트워크(호스트 약 1,600만) |
| B | 128 ~ 191 | 16 / 16 | 중형 네트워크(호스트 약 6.5만) |
| C | 192 ~ 223 | 24 / 8 | 소형 네트워크(호스트 254) |
| D | 224 ~ 239 | — | 멀티캐스트용 |
| E | 240 ~ 255 | — | 연구·예약용 |

_표 2-1. IPv4 주소 클래스_

우리가 실습에서 쓰는 `172.16.x.x`는 첫 옥텟이 172이므로 **B 클래스**이고, `192.168.x.x`는 **C 클래스**입니다. 이 두 대역에는 공통점이 하나 있습니다. 바로 **사설(Private) 주소**라는 점입니다. 사설 주소는 회사나 가정의 내부망에서만 쓰는 주소로, 인터넷에서는 라우팅되지 않습니다. 그래서 전 세계 수많은 회사가 똑같이 `192.168.0.0`을 써도 서로 충돌하지 않습니다.

| 클래스 | 사설 주소 범위 |
|---|---|
| A | 10.0.0.0 ~ 10.255.255.255 |
| B | 172.16.0.0 ~ 172.31.255.255 |
| C | 192.168.0.0 ~ 192.168.255.255 |

_표 2-2. 사설 IP 주소 대역_

우리가 만들 회사 네트워크의 본사·지사 내부는 이 사설 주소(172.16 대역)를 쓰고, 인터넷 구간(공인망)은 별도의 공인 주소(100.x 대역)를 씁니다. 사설망을 공인망으로 내보낼 때 필요한 것이 바로 뒤에서 배울 NAT입니다.

## 3. 서브넷 마스크와 CIDR

**서브넷 마스크**는 IP 주소에서 어디까지가 네트워크부인지 알려 주는 값입니다. 이해하는 열쇠는 **‘1의 개수’** 입니다. 마스크를 2진수로 폈을 때 1인 부분이 네트워크부, 0인 부분이 호스트부입니다.

예를 들어 마스크 `255.255.255.0`을 2진수로 펴면 앞의 24자리가 1, 뒤의 8자리가 0입니다. 즉 앞 24비트가 네트워크부입니다. 이렇게 1의 개수가 24개라는 뜻으로 `/24`라고 짧게 쓰기도 하는데, 이 표기법을 **CIDR**(Classless Inter-Domain Routing)이라 합니다. `255.255.255.0`과 `/24`는 완전히 같은 말입니다.

![](/assets/img/posts/2026-08-25-netintro-02a-ip-subnetting-1786424736069.png)

| CIDR | 서브넷 마스크 | 네트워크 비트 | 호스트 비트 |
|---|---|---|---|
| /24 | 255.255.255.0 | 24 | 8 |
| /25 | 255.255.255.128 | 25 | 7 |
| /26 | 255.255.255.192 | 26 | 6 |
| /27 | 255.255.255.224 | 27 | 5 |
| /23 | 255.255.254.0 | 23 | 9 |

_표 2-3. 자주 쓰는 CIDR ↔ 서브넷 마스크 변환_

이제 1강에서 썼던 `/23`(255.255.254.0)의 정체가 보입니다. `/23`은 네트워크 비트가 23개, 호스트 비트가 9개라는 뜻입니다. 호스트 비트가 9개이므로 이 네트워크에는 2⁹ = 512개의 주소가 들어갑니다.

## 4. 서브네팅 계산 — 이 과정의 핵심 기술

**서브네팅(Subnetting)** 은 하나의 큰 네트워크를 여러 개의 작은 네트워크로 쪼개는 것입니다. 그리고 대회 문제를 풀려면 반대로, 주어진 네트워크에서 **네트워크 주소·브로드캐스트 주소·첫 번째와 마지막으로 쓸 수 있는 주소** 를 정확히 찾아낼 수 있어야 합니다. 아래 4단계 규칙만 익히면 됩니다.

### (1) 한 네트워크 안의 네 가지 주소

어떤 네트워크든, 그 안의 주소는 다음과 같이 나뉩니다.

| 주소 | 규칙 | 쓸 수 있나? |
|---|---|---|
| 네트워크 주소 | 호스트부가 전부 0 (그 네트워크의 첫 주소) | ✗ (네트워크 자체를 가리킴) |
| 첫 사용 가능 주소 | 네트워크 주소 + 1 | ✓ |
| 마지막 사용 가능 주소 | 브로드캐스트 주소 − 1 | ✓ |
| 브로드캐스트 주소 | 호스트부가 전부 1 (그 네트워크의 마지막 주소) | ✗ (전체에게 보내는 특수 주소) |

_표 2-4. 한 네트워크를 이루는 네 가지 주소_

즉 실제 장치(PC·라우터)에 줄 수 있는 주소는 **네트워크 주소와 브로드캐스트 주소 사이**에 있는 것들입니다. 대회에서 “사용 가능한 마지막 주소”라고 하면, 곧 **브로드캐스트 주소 바로 앞 주소**를 뜻합니다.

> **생각해 보기 — 왜 첫 주소와 끝 주소는 못 쓸까?**
> 한 네트워크에서 네트워크 주소(맨 앞)와 브로드캐스트 주소(맨 끝)는 장치에 줄 수 없습니다. 왜 하필 이 두 개일까요? 네트워크 주소는 ‘이 네트워크 전체’를 가리키는 이름표라서 특정 한 대에 주면 이름과 구성원이 헷갈립니다. 브로드캐스트 주소는 ‘이 네트워크의 모두에게’ 보낼 때 쓰는 특수 주소라, 한 대에 주면 그 한 대에게 보낸 것인지 전체에게 보낸 것인지 알 수 없게 됩니다. 그래서 `/24`는 256개 주소 중 2개를 빼 254대만 쓸 수 있습니다. 그렇다면 라우터끼리 잇는 데 자주 쓰는 `/30`(주소 4개)은 실제로 몇 대에 줄 수 있을지 계산해 보세요.
{: .prompt-info }

### (2) 블록 크기로 경계 찾기

핵심 계산은 **블록 크기**입니다. 블록 크기란 한 네트워크가 차지하는 주소의 개수로, 다음처럼 구합니다.

> **블록 크기 = 256 − (서브넷 마스크에서 0이 아닌 마지막 옥텟 값)**

예를 들어 `/26`(255.255.255.192)이라면, 마지막으로 값이 있는 옥텟이 192이므로 블록 크기는 256 − 192 = **64**입니다. 그래서 네트워크의 경계가 마지막 옥텟 기준으로 0, 64, 128, 192마다 생깁니다.

### (3) 예제로 익히기 — 실제 시험 대역

**예제 ①: 192.168.10.0 /24** (마스크 255.255.255.0)
- 블록 크기 = 256 − 0 = 256 → 한 네트워크가 마지막 옥텟 0~255를 전부 차지
- 네트워크 주소: `192.168.10.0`
- 브로드캐스트 주소: `192.168.10.255`
  (해당 **네트워크 안에 속한 모든 장치에게 동시에 데이터를 전송**하기 위한 주소)
- 첫 사용 가능 주소: `192.168.10.1`
- **마지막 사용 가능 주소: `192.168.10.254`**

이 값은 실제 대회 도면에서 방화벽(A-ASA)의 DMZ 주소가 “192.168.10.0/24의 사용 가능한 마지막 주소”로 주어지는 것과 정확히 일치합니다. 즉 `192.168.10.254`입니다.

**예제 ②: 172.16.8.0 /23** (마스크 255.255.254.0)
- 블록 크기(세 번째 옥텟 기준) = 256 − 254 = 2 → 세 번째 옥텟이 2씩 증가(…, 8, 10, 12, …)
- 네트워크 주소: `172.16.8.0` (다음 네트워크는 172.16.10.0)
- 브로드캐스트 주소: 다음 네트워크 바로 앞 = `172.16.9.255`
- 첫 사용 가능 주소: `172.16.8.1`
- **마지막 사용 가능 주소: `172.16.9.254`**

`/23`은 두 개의 옥텟 묶음(8.x와 9.x)을 한 네트워크로 쓴다는 점이 처음엔 헷갈립니다. 하지만 “블록 크기가 2이므로 8.0부터 9.255까지가 한 네트워크”라고 생각하면 명확합니다. 대회 도면에서 본사 전화 라우터(A-Call-R)의 주소가 “172.16.8.0/23의 사용 가능한 마지막 주소”로 주어지는데, 그 답이 바로 `172.16.9.254`입니다.

![그림 2-1. 서브네팅 계산 및 결과 예시](/assets/img/posts/2026-03-09-netintro-c2-20.png)
_그림 2-1. 서브네팅 계산 및 결과 예시_

> **계산 팁 — 필요한 호스트 수로 마스크 정하기** 반대로 “100대를 수용할 네트워크”처럼 대수가 주어지면, ‘2^(호스트비트) − 2 ≥ 필요 대수’를 만족하는 가장 작은 호스트 비트를 고릅니다. 100대라면 2⁷ − 2 = 126 ≥ 100이므로 호스트 7비트, 즉 `/25`가 답입니다. (−2는 네트워크 주소와 브로드캐스트 주소를 뺀 것입니다.)
{: .prompt-tip }

### (4) 서브네팅 — 하나를 여럿으로 쪼개기

큰 네트워크를 잘게 나눌 때는 호스트 비트를 네트워크 비트로 빌려 옵니다. 예로 `192.168.10.0/24`를 4개(=2²)로 나누면 호스트부에서 2비트를 빌려 `/26`이 되고, 블록 크기 64짜리 네트워크 4개가 만들어집니다.

| 서브넷 | 네트워크 주소 | 사용 가능 범위 | 브로드캐스트 |
|---|---|---|---|
| 1번 | 192.168.10.0/26 | .1 ~ .62 | 192.168.10.63 |
| 2번 | 192.168.10.64/26 | .65 ~ .126 | 192.168.10.127 |
| 3번 | 192.168.10.128/26 | .129 ~ .190 | 192.168.10.191 |
| 4번 | 192.168.10.192/26 | .193 ~ .254 | 192.168.10.255 |

_표 2-5. 192.168.10.0/24를 /26 서브넷 4개로 분할한 결과_

## 5. VLSM — 서브넷마다 다른 크기

### (1) 왜 VLSM이 필요한가

4절에서는 `192.168.10.0/24`를 똑같은 크기(`/26`)의 서브넷 4개로 나눴습니다. 그런데 실제 회사에서는 부서마다 필요한 대수가 제각각입니다. 어떤 부서는 100대, 어떤 팀은 50대, 라우터끼리 잇는 구간은 딱 2대만 있으면 됩니다. 이때 모든 서브넷을 똑같은 크기로 나누면 낭비가 큽니다. 예를 들어 전부 `/26`(62대)으로 통일하면, 주소가 2개만 필요한 라우터 구간에도 62개를 통째로 배정해 60개가 그냥 버려집니다.

**VLSM**(Variable Length Subnet Mask, 가변 길이 서브넷 마스크)은 같은 네트워크 안에서도 **서브넷마다 필요한 크기에 맞춰 다른 마스크**를 적용해 이 낭비를 없앱니다. 큰 부서에는 큰 블록을, 작은 구간에는 작은 블록을 주는 것입니다. 아래는 `192.168.1.0/24` 하나를 세 가지 크기로 나눈 예입니다.

| 용도 | 필요 대수 | 배정한 블록 | 사용 가능 대수 |
|---|---|---|---|
| 부서 A | 100대 | 192.168.1.0/25 | 126대 |
| 부서 B | 50대 | 192.168.1.128/26 | 62대 |
| 라우터 연결 구간 | 2대 | 192.168.1.192/30 | 2대 |

_표 2-6. VLSM으로 한 네트워크를 서로 다른 크기로 나눈 예_

같은 `/24` 안에서 `/25`·`/26`·`/30`이 함께 쓰인 것이 바로 VLSM입니다. 대회 도면에서도 사무실 대역은 `/23`·`/24`로 넉넉하게, 라우터 간 연결 구간은 `/30`으로 작게 나누는 것을 볼 수 있습니다.

### (2) CIDR과 무엇이 다른가

VLSM과 CIDR은 ‘클래스에 얽매이지 않고 `/n`으로 경계를 자유롭게 정한다’는 같은 뿌리에서 나왔습니다. 그래서 헷갈리기 쉬운데, 둘은 쓰는 **방향이 반대**입니다. **CIDR**는 여러 네트워크를 하나의 큰 덩어리로 **묶어(집약)** 라우팅 정보를 줄이는 쪽 — 바깥으로 합치기 — 이고, **VLSM**은 하나의 네트워크를 조직 안에서 서로 다른 크기로 **잘게 쪼개는** 쪽 — 안으로 나누기 — 입니다.

예를 들어 `192.168.0.0/24`부터 `192.168.3.0/24`까지 네 개를 `192.168.0.0/22` 한 줄로 합치는 것이 CIDR(집약)이고, 반대로 `/24` 하나를 위 표처럼 `/25`·`/26`·`/30`으로 쪼개는 것이 VLSM입니다. 즉 VLSM은 CIDR이 열어 준 ‘클래스 없는 세계’ 위에서 동작하는, 조직 내부의 효율적 분할 기법이라고 이해하면 됩니다.

## 7. 논리 주소를 물리 주소로 — ARP(IP-->MAC)

같은 네트워크 안에서 실제로 프레임을 주고받으려면 물리 주소(MAC)가 필요합니다. 그런데 우리는 IP 주소로 통신하므로, IP 주소를 MAC 주소로 바꾸는 과정이 필요합니다. 이 일을 하는 것이 **ARP**(Address Resolution Protocol)입니다.

예를 들어 PC(`172.16.8.1`)가 같은 네트워크의 다른 PC(`172.16.8.2`)와 처음 통신하려 하면, ① PC는 ‘172.16.8.2를 쓰는 분, MAC 주소 알려 주세요’를 네트워크 전체에 브로드캐스트합니다(ARP 요청). ② 해당 IP의 주인만 ‘제 MAC은 …입니다’라고 답합니다(ARP 응답). ③ PC는 이 IP-MAC 쌍을 잠시 저장(ARP 캐시)해 두고 재사용합니다. 1강 실습 1-2에서 스위치를 거친 첫 ping의 앞부분이 잠깐 실패했던 것도, 바로 이 ARP 과정이 먼저 일어나느라 생긴 지연이었습니다.

> **보안 유의 — ARP 스푸핑** ARP는 응답의 진위를 검증하지 않습니다. 공격자가 위조된 ARP 응답을 보내 피해자의 캐시를 오염시키면, 트래픽이 공격자를 거쳐 가도록 만들 수 있습니다(중간자 공격). 이 ARP 스푸핑은 10강(정보보안)에서 다시 자세히 다룹니다.

## 8. 오류 보고와 진단 — ICMP

**ICMP**(Internet Control Message Protocol)는 네트워크 상태를 진단하고 오류를 보고하는 보조 프로토콜입니다. 우리가 통신 확인에 쓰는 `ping`이 바로 이 ICMP를 이용한 것으로, 상대에게 ‘에코 요청’을 보내고 ‘에코 응답’을 받아 살아 있는지와 왕복 시간을 확인합니다.

| Type | 이름 | 의미 |
|---|---|---|
| 8 / 0 | Echo 요청 / 응답 | ping의 왕복 확인 |
| 3 | Destination Unreachable | 목적지에 닿을 수 없음 |
| 11 | Time Exceeded | 패킷 수명(TTL)이 다 됨(경로 추적 tracert의 원리) |

## 9. 사설망을 공인망으로 — NAT

**NAT**(Network Address Translation)는 내부에서 쓰는 사설 IP 주소를 외부로 나갈 때 공인 IP 주소로 바꿔 주는 기술입니다. IPv4 주소가 부족해지자 등장한 기술로, 가정의 공유기부터 기업망까지 어디에나 있습니다. 내부 호스트가 밖으로 패킷을 보내면 NAT 장비가 출발지 주소를 자신의 공인 IP로 바꾸고, 응답이 돌아오면 다시 원래 내부 주소로 되돌려 전달합니다.

| 종류 | 설명 |
|---|---|
| 정적 NAT | 사설 IP 하나와 공인 IP 하나를 1:1 고정 매핑(내부 서버 공개용) |
| 동적 NAT | 공인 IP 여러 개를 모아 두고 그때그때 하나를 골라 매핑 |
| PAT | 공인 IP 하나를 포트 번호로 구분해 여러 내부 호스트가 공유(가정용 공유기 방식) |

_표 2-9. NAT의 종류_

지금은 NAT가 ‘사설 주소를 공인 주소로 바꿔 주는 것’이라는 개념만 이해하면 충분합니다. 우리 회사 네트워크에서 외부 사용자가 내부 웹 서버에 접속하도록 하는 ‘정적 NAT(포트 포워딩)’는 11강(방화벽)에서 직접 설정하게 됩니다.

> **생각해 보기 — NAT가 있으면 방화벽은 필요 없을까?**
> NAT는 내부 주소를 밖에서 볼 수 없게 감추므로 “공격자가 내부 IP를 모른다”는 부수적인 보안 효과가 있습니다. 그렇다면 NAT만 있으면 방화벽은 없어도 될까요? 그렇지 않습니다. NAT는 어디까지나 ‘주소를 바꾸는 기술’이지 ‘허용할지 차단할지 판단하는 장치’가 아닙니다. NAT와 방화벽은 목적이 어떻게 다른지 한 문장으로 구분해 보세요. (이 질문의 답은 11강에서 방화벽을 직접 만들며 확인합니다.)
{: .prompt-info }
