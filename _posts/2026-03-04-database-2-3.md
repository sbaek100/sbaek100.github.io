# 셀프체크 풀이(p.87) — coffees 테이블 CRUD 실습

## 문제 개요

`starbuuks` DB를 생성하고, 아래 구조의 `coffees` 테이블을 만들어 데이터를 관리하는 쿼리를 작성함.

### 테이블 구조

|칼럼|자료형|설명|
|---|---|---|
|id|INT (기본키)|각 커피의 고유 식별자, 정수|
|name|VARCHAR(20)|커피 이름, 최대 20자|
|price|INT|커피 가격, 정수|

### 초기 데이터

|id|name|price|
|---|---|---|
|1|아메리카노|3800|
|2|카페라떼|4000|
|3|콜드브루|3500|
|4|카페모카|4500|
|5|카푸치노|5000|

---

## 문제 1. starbuuks DB를 생성하고 진입하세요.

```sql
CREATE DATABASE starbuuks;
USE starbuuks;
```

> **설명**
> 
> - `CREATE DATABASE`로 새 데이터베이스를 생성함
> - `USE`로 해당 DB에 진입해야 이후 테이블 생성·조작이 해당 DB 안에서 실행됨
> - 💡 `starbuuks`는 오타처럼 보이지만 문제에 명시된 이름 그대로 사용해야 함 (Fact)

---

## 문제 2. coffees 테이블을 만드세요.

```sql
CREATE TABLE coffees (
    id    INT          NOT NULL AUTO_INCREMENT,
    name  VARCHAR(20)  NOT NULL,
    price INT          NOT NULL,
    PRIMARY KEY (id)
);
```

> **설명**
> 
> - `id`: 정수형(`INT`), 기본키(Primary Key), `AUTO_INCREMENT`로 자동 증가 지정
> - `name`: 최대 20자 문자열 → `VARCHAR(20)` 사용
> - `price`: 정수형(`INT`)
> - `NOT NULL`: 모든 칼럼이 필수 입력 항목이므로 지정
> - `PRIMARY KEY(id)`: id를 기본키로 지정 → 자동으로 중복 불가 + NULL 불가 조건 강제됨

---

## 문제 3. coffees 테이블에 아메리카노부터 카푸치노까지 모든 데이터를 삽입하세요.

```sql
INSERT INTO coffees (name, price) VALUES
    ('아메리카노', 3800),
    ('카페라떼',   4000),
    ('콜드브루',   3500),
    ('카페모카',   4500),
    ('카푸치노',   5000);
```

> **설명**
> 
> - `id`는 `AUTO_INCREMENT`로 지정되었으므로 생략하면 자동으로 1부터 순서대로 부여됨
> - 여러 행을 한 번에 삽입할 때 `VALUES` 뒤에 `,`로 구분하여 나열하면 효율적임
> - 문자열 값은 반드시 `'작은따옴표'`로 감싸야 함

---

## 문제 4. coffees 테이블의 모든 커피 이름을 조회하세요.

```sql
SELECT name FROM coffees;
```

> **설명**
> 
> - `SELECT *`는 모든 칼럼을 조회하지만, 여기서는 **이름(name)만** 요구하므로 칼럼명을 명시함
> - `WHERE` 조건 없이 실행하면 테이블의 모든 행에서 `name` 칼럼만 출력됨
> 
> **예상 출력 결과:**
> 
> |name|
> |---|
> |아메리카노|
> |카페라떼|
> |콜드브루|
> |카페모카|
> |카푸치노|

---

## 문제 5. 카푸치노의 가격을 200원 인상하세요.

```sql
UPDATE coffees
SET price = price + 200
WHERE name = '카푸치노';
```

> **설명**
> 
> - `SET price = price + 200`: 기존 가격(5000)에 200을 더한 값(5200)으로 업데이트함
> - `WHERE name = '카푸치노'`: 반드시 조건을 명시해야 카푸치노 행만 수정됨
> - WHERE 절 없이 실행하면 **모든 커피 가격이 일괄 인상**되므로 주의
> - 💡 [Opinion] 실무에서는 `WHERE id = 5`처럼 기본키 조건을 사용하는 것이 더 안전함

---

## 문제 6. 콜드브루를 삭제하세요.

```sql
DELETE FROM coffees
WHERE name = '콜드브루';
```

> **설명**
> 
> - `DELETE FROM`은 행(Row) 단위로 데이터를 삭제함
> - `WHERE name = '콜드브루'`: 이름이 '콜드브루'인 행만 삭제
> - WHERE 절 없이 실행하면 **테이블의 모든 데이터가 삭제**되므로 극히 주의
> - 💡 [Opinion] `WHERE id = 3`처럼 기본키 조건 사용을 권장함

---

## 문제 7. 모든 커피 데이터를 조회하세요.

```sql
SELECT * FROM coffees;
```

> **설명**
> 
> - `SELECT *`: 모든 칼럼(id, name, price) 조회
> - `WHERE` 조건 없이 실행하면 전체 행 반환
> - 5번(카푸치노 가격 인상)과 6번(콜드브루 삭제) 작업이 정상 반영되었는지 최종 확인하는 쿼리
> 
> **예상 출력 결과 (5번·6번 반영 후):**
> 
> |id|name|price|
> |---|---|---|
> |1|아메리카노|3800|
> |2|카페라떼|4000|
> |4|카페모카|4500|
> |5|카푸치노|**5200**|

> 💡 **[Fact]** id=3(콜드브루)이 삭제되어 결과에 없음. `AUTO_INCREMENT`는 삭제된 번호를 재사용하지 않으므로 id 순서에 3이 빠진 채로 출력됨.

## 전체 쿼리 통합본

```sql
-- 1. DB 생성 및 진입
CREATE DATABASE starbuuks;
USE starbuuks;

-- 2. 테이블 생성
CREATE TABLE coffees (
    id    INT          NOT NULL AUTO_INCREMENT,
    name  VARCHAR(20)  NOT NULL,
    price INT          NOT NULL,
    PRIMARY KEY (id)
);

-- 3. 데이터 삽입
INSERT INTO coffees (name, price) VALUES
    ('아메리카노', 3800),
    ('카페라떼',   4000),
    ('콜드브루',   3500),
    ('카페모카',   4500),
    ('카푸치노',   5000);

-- 4. 커피 이름만 조회
SELECT name FROM coffees;

-- 5. 카푸치노 가격 200원 인상
UPDATE coffees
SET price = price + 200
WHERE name = '카푸치노';

-- 6. 콜드브루 삭제
DELETE FROM coffees
WHERE name = '콜드브루';

-- 7. 전체 데이터 조회
SELECT * FROM coffees;
```
