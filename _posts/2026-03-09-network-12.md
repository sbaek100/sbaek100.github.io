# 라우터 WAN 구간 변경 & Static Route 과제

---

# 1장. 오늘 과제의 핵심

---

11강에서 했던 실습을 그대로 두고, **WAN 주소만 바꾼 뒤 다시 통신되게 만드는 과제**임.

오늘 기억할 흐름은 이 3단계면 충분함.

1. 시리얼 인터페이스 IP 주소를 바꾼다
2. 예전 Static Route를 지운다
3. 새 WAN 주소에 맞게 Static Route를 다시 넣는다

### 이 과제에서 학생이 꼭 느껴야 하는 것

- 주소를 바꾸면 끝이 아님
- 라우터가 참고하는 길 안내표도 같이 바꿔야 함
- 즉, **인터페이스 주소 변경**과 **Static Route 변경**은 같이 가는 작업임

---

# 2장. 바뀌는 부분만 보기

---

기존 WAN 주소:

```
Router0 = 10.0.0.1/30
Router1 = 10.0.0.2/30
```

이번 과제에서 바꿀 WAN 주소:

```
Router0 = 172.16.0.1/30
Router1 = 172.16.0.2/30
```

> LAN 주소는 그대로 둠.  
> 바뀌는 것은 **시리얼 구간과 Static Route의 다음 홉 주소**뿐임.

---

# 3장. 그대로 따라 하는 과제

---

## Step 1 — Router0 WAN 주소 변경

`Router0` CLI에서 입력:

```
enable
configure terminal
interface s0/0/0
ip address 172.16.0.1 255.255.255.252
no shutdown
exit
```

### 실제로 누르는 순서

1. `Router0` 더블클릭
2. `CLI` 탭 클릭
3. 명령어를 한 줄씩 입력
4. 입력 후 `show ip interface brief`로 바뀐 IP 확인

## Step 2 — Router1 WAN 주소 변경

`Router1` CLI에서 입력:

```
enable
configure terminal
interface s0/0/0
ip address 172.16.0.2 255.255.255.252
no shutdown
exit
```

### 여기서 꼭 볼 포인트

- Router0는 `172.16.0.1`
- Router1는 `172.16.0.2`
- 둘 다 서브넷 마스크는 `255.255.255.252`
- 예전 `10.0.0.x` 주소가 아니라는 점이 핵심임

## Step 3 — Router0의 예전 길 안내 지우고 새로 넣기

```
no ip route 192.168.2.0 255.255.255.0 10.0.0.2
ip route 192.168.2.0 255.255.255.0 172.16.0.2
end
```

### 여기서 학생이 꼭 이해할 것

- `no ip route ... 10.0.0.2`는 예전 길 삭제
- `ip route ... 172.16.0.2`는 새 길 추가
- 목적지 LAN은 그대로지만, 다음 홉만 바뀜

## Step 4 — Router1의 예전 길 안내 지우고 새로 넣기

```
enable
configure terminal
no ip route 192.168.1.0 255.255.255.0 10.0.0.1
ip route 192.168.1.0 255.255.255.0 172.16.0.1
end
```

> 초보자 기준으로는 `no ip route` 한 줄로 예전 길을 지우고,  
> `ip route` 한 줄로 새 길을 다시 넣는다고 이해하면 됨.

### 실수하기 쉬운 부분

- `enable`, `configure terminal`을 빼먹지 않기
- 예전 경로를 안 지우면 라우팅 테이블이 헷갈릴 수 있음
- 새 다음 홉 주소를 반대편 시리얼 IP로 정확히 넣기

---

# 4장. 확인도 쉬운 순서로

---

## Step 5 — Router끼리 먼저 확인

Router0에서:

```
ping 172.16.0.2
```

이게 성공하면 WAN 자체는 살아 있는 것임.

### 왜 이 Ping을 먼저 하나?

- PC까지 보기 전에 라우터끼리 먼저 확인하면 문제를 좁히기 쉬움
- 이것이 안 되면 아직 WAN 구간 설정이 끝나지 않은 것임

## Step 6 — 마지막 통신 확인

PC0에서:

```
ping 192.168.2.10
```

`Reply from` 이 보이면 과제 성공임.

### PC0에서 실제로 누르는 순서

1. `PC0` 더블클릭
2. `Desktop` 클릭
3. `Command Prompt` 클릭
4. `ping 192.168.2.10` 입력

## Step 7 — 라우팅 테이블 확인

각 라우터에서:

```
show ip route
```

### 반드시 찾아야 하는 줄

Router0:

```
S    192.168.2.0/24 [1/0] via 172.16.0.2
```

Router1:

```
S    192.168.1.0/24 [1/0] via 172.16.0.1
```

### 학생이 여기서 꼭 봐야 하는 포인트

- `S` 줄의 다음 홉이 더 이상 `10.0.0.x`가 아니어야 함
- 두 라우터 모두 `172.16.0.x` 기준으로 바뀌어 있어야 함
- 주소는 바뀌었는데 route가 그대로면 마지막 Ping이 실패함

# 7장. 자주 막히는 부분

---

| 증상 | 먼저 확인할 것 |
|---|---|
| Router0에서 172.16.0.2 Ping 실패 | Router1 시리얼 IP가 172.16.0.2인지 |
| 마지막 Ping 실패 | `ip route` 다음 홉 주소가 새 WAN 주소로 바뀌었는지 |
| 여전히 10.0.0.x 경로가 보임 | 예전 Static Route 삭제를 빼먹지 않았는지 |
| 시리얼 포트가 down | `no shutdown` 과 `clock rate 64000` 확인 |

# 정리

오늘 과제의 핵심은 이것임.  
라우터 사이 주소가 바뀌면, 라우터가 참고하는 길 안내표도 같이 바꿔야 함.  
즉, **주소가 바뀌면 경로도 같이 바뀐다**는 감각을 익히면 됨.
