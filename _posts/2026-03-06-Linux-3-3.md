## 실습 1. 사용자 및 그룹 관리 종합 실습

```bash
# 실습용 사용자 3명 생성
sudo adduser pig
sudo adduser mango
sudo adduser dog

# 생성된 사용자 정보 확인
grep -E "pig|mango|dog" /etc/passwd
id pig
id mango
id dog

# animals 그룹 생성 및 사용자 추가
sudo addgroup animals
sudo adduser pig animals
sudo adduser mango animals
sudo adduser dog animals

# 그룹 구성원 확인
grep animals /etc/group
```

예상 화면

```text
$ grep -E "pig|mango|dog" /etc/passwd
pig:x:1001:1001:...:/home/pig:/bin/bash
mango:x:1002:1002:...:/home/mango:/bin/bash
dog:x:1003:1003:...:/home/dog:/bin/bash

$ id pig
uid=1001(pig) gid=1001(pig) groups=1001(pig),2001(animals)
```

## 실습 2. 파일 소유권 및 권한 설정

```bash
# 공유 디렉터리 생성
sudo mkdir -p /tmp/shared
sudo chmod 777 /tmp/shared

# dog 사용자로 파일 생성
su dog
echo "dog가 만든 파일" > /tmp/shared/msg_from_dog
ls -l /tmp/shared/msg_from_dog
exit

# mango 사용자로 읽기 시도
su mango
cat /tmp/shared/msg_from_dog    # 성공
exit

# dog 사용자로 읽기 권한 제거
su dog
chmod o-r /tmp/shared/msg_from_dog
exit

# mango 사용자로 읽기 재시도
su mango
cat /tmp/shared/msg_from_dog    # Permission denied
exit
```

예상 화면

```text
$ ls -l /tmp/shared/msg_from_dog
-rw-r--r-- 1 dog dog ... /tmp/shared/msg_from_dog

$ cat /tmp/shared/msg_from_dog
dog가 만든 파일

$ chmod o-r /tmp/shared/msg_from_dog
$ ls -l /tmp/shared/msg_from_dog
-rw-r----- 1 dog dog ... /tmp/shared/msg_from_dog

$ cat /tmp/shared/msg_from_dog
cat: /tmp/shared/msg_from_dog: Permission denied
```

## 실습 3. chmod 8진수 표기법

```bash
touch /tmp/chmod_test.txt

chmod 644 /tmp/chmod_test.txt   # -rw-r--r--
ls -l /tmp/chmod_test.txt

chmod 755 /tmp/chmod_test.txt   # -rwxr-xr-x
```

## 실습 4. Sticky bit 이론 + 보안 실습

### 4.1 Sticky bit 이론

- Sticky bit는 **주로 공유 디렉터리**에서 사용한다.
- 디렉터리에 Sticky bit가 설정되면, 해당 디렉터리에 쓰기 권한이 있어도 **파일 소유자/디렉터리 소유자/root만 삭제/이름변경**할 수 있다.
- 대표 예시는 `/tmp` 이며 권한이 보통 `drwxrwxrwt` 형태다.

왜 써야 하나?

- 팀 공유 폴더를 `777`로 열어두면 누구나 다른 사람 파일을 삭제할 수 있다.
- Sticky bit는 공유는 유지하면서도, **서로의 파일 파괴(삭제/이름변경)를 차단**한다.

보안상 중요한 포인트

- `w` 권한이 있는 디렉터리는 파일 삭제 위험이 크다.  
- Sticky bit는 실수/악의적 삭제를 줄여 **가용성(Availability)** 을 보호한다.
- `/tmp` 같은 공용 디렉터리에 Sticky bit가 없으면 사용자 간 간섭 위험이 커진다.

---

### 4.2 실습: Sticky bit 전/후 비교

```bash
# 1) 공유 디렉터리 준비 (sticky bit 없음)
sudo mkdir -p /tmp/sticky-lab
sudo chmod 777 /tmp/sticky-lab
ls -ld /tmp/sticky-lab

# 2) pig가 파일 생성
su - pig -c 'echo "pig file" > /tmp/sticky-lab/pig.txt'
ls -l /tmp/sticky-lab

# 3) mango가 pig 파일 삭제 시도 (sticky bit 없으므로 성공 가능)
su - mango -c 'rm -f /tmp/sticky-lab/pig.txt'
ls -l /tmp/sticky-lab

# 4) 다시 파일 생성 후 sticky bit 설정
su - pig -c 'echo "pig file 2" > /tmp/sticky-lab/pig.txt'
sudo chmod 1777 /tmp/sticky-lab
ls -ld /tmp/sticky-lab

# 5) mango가 pig 파일 삭제 재시도 (sticky bit 때문에 실패)
su - mango -c 'rm -f /tmp/sticky-lab/pig.txt'
ls -l /tmp/sticky-lab
```

예상 결과

```text
# sticky bit 설정 전
drwxrwxrwx ... /tmp/sticky-lab
(mango가 pig.txt 삭제 성공)

# sticky bit 설정 후
drwxrwxrwt ... /tmp/sticky-lab
rm: cannot remove '/tmp/sticky-lab/pig.txt': Operation not permitted
(pig.txt 파일이 그대로 남아 있음)
```

확인 명령 요약

```bash
ls -ld /tmp /tmp/sticky-lab
stat -c '%A %a %n' /tmp /tmp/sticky-lab
```

`t`가 보이면 Sticky bit가 켜진 상태이며, 숫자 권한으로는 맨 앞자리 `1`(예: `1777`)을 사용한다.

## 실습 5. 특수 비트 종합 실습 (SGID + SUID 관찰)

### 5.1 SGID 디렉터리로 그룹 상속 확인

```bash
# 1) 팀 공유 디렉터리 준비
sudo mkdir -p /tmp/team-share
sudo chown root:animals /tmp/team-share
sudo chmod 2775 /tmp/team-share
ls -ld /tmp/team-share

# 2) pig, mango가 각각 파일 생성
su - pig -c 'echo "pig note" > /tmp/team-share/pig_note.txt'
su - mango -c 'echo "mango note" > /tmp/team-share/mango_note.txt'
ls -l /tmp/team-share
```

예상 화면

```text
$ ls -ld /tmp/team-share
drwxrwsr-x 2 root animals ... /tmp/team-share

$ ls -l /tmp/team-share
-rw-r--r-- 1 pig   animals ... pig_note.txt
-rw-r--r-- 1 mango animals ... mango_note.txt
```

핵심 해석

- 디렉터리에 SGID(`g+s`)가 설정되어 새 파일의 그룹이 `animals`로 통일된다.
- 팀 협업에서 "내 파일만 내 기본 그룹으로 생성"되는 문제를 줄인다.

### 5.2 SUID 파일 관찰 (운영체제 기본 바이너리)

```bash
ls -l /usr/bin/passwd
stat -c '%A %a %U:%G %n' /usr/bin/passwd
```

예상 화면

```text
$ ls -l /usr/bin/passwd
-rwsr-xr-x 1 root root ... /usr/bin/passwd

$ stat -c '%A %a %U:%G %n' /usr/bin/passwd
-rwsr-xr-x 4755 root:root /usr/bin/passwd
```

핵심 해석

- 소유자 실행 자리의 `s`는 SUID를 의미한다.
- 일반 사용자가 `passwd`를 실행해도, 비밀번호 변경에 필요한 일부 동작은 파일 소유자(root) 권한으로 수행된다.
- 보안상 SUID는 필요한 파일에만 제한적으로 허용해야 한다.
