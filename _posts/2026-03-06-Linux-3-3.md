# 사용자 및 파일 권한 관리 — 3-3 실습편 (초보자 버전)

> 이 실습은 3-1 → 3-2 → 3-3 순서로 진행해야 한다.  
> 아직 3-1을 완료하지 않았다면 먼저 사용자/그룹 생성 실습을 마치고 돌아올 것.
{: .prompt-warning }

> **`su -` 사용 안내**  
> `su - 사용자명` 을 실행하면 해당 사용자의 셸로 전환된다.  
> 작업을 마쳤으면 반드시 `exit` 를 입력해서 원래 사용자로 돌아와야 한다.  
> `exit` 를 빠뜨리면 이후 `sudo` 명령이 실패할 수 있다.
{: .prompt-tip }

## Step 0. 터미널 시작 확인

가장 먼저 내가 누구로 로그인했는지, 어디에 있는지 확인한다.

```bash
whoami          # 현재 로그인한 사용자 이름 출력
echo $SHELL     # 현재 사용 중인 로그인 셸 확인 (예: /bin/bash)
pwd             # 현재 위치(작업 디렉터리) 출력
```

## Step 1. 실습 폴더 만들기

```bash
mkdir ~/linux-journey                # 홈 디렉터리 아래 실습 폴더 생성 (~는 홈 디렉터리를 의미)
mkdir ~/linux-journey/docs           # 문서 저장용 폴더
mkdir ~/linux-journey/tmp            # 임시 파일용 폴더
mkdir ~/linux-journey/bin            # 스크립트 저장용 폴더

cd ~/linux-journey                   # 실습 폴더로 이동
pwd                                  # 이동이 잘 됐는지 확인
ls                                   # 현재 폴더 목록 확인 (docs, tmp, bin 이 보여야 정상)
```

## Step 2. 파일 기본 명령 익히기

```bash
touch docs/intro.txt                                    # 빈 파일 생성
echo "Linux Fresh Install Lab" > docs/intro.txt         # > 기호는 출력을 파일에 저장하는 리다이렉션
cat docs/intro.txt                                      # 파일 내용 확인

cp docs/intro.txt docs/intro_copy.txt                   # 파일 복사
mv docs/intro_copy.txt docs/intro_moved.txt             # 파일 이름 변경 (mv = 이동/이름변경)
ls -l docs                                              # docs 폴더 상세 목록 확인

touch tmp/remove_me.txt                                 # 삭제 연습용 파일 생성
rm tmp/remove_me.txt                                    # 파일 삭제
ls tmp                                                  # 삭제 확인 (아무것도 출력되지 않으면 정상)
```

## Step 3. 링크(soft/hard) 아주 쉽게 확인

링크는 파일의 "별명"을 만드는 기능이다.  
소프트 링크는 원본을 삭제하면 깨지고, 하드 링크는 원본을 삭제해도 내용이 남는다.

```bash
echo "link-test" > docs/original.txt         # 링크 실험용 원본 파일 생성

ln -s docs/original.txt docs/soft_link.txt   # -s: 소프트(심볼릭) 링크 생성
ln docs/original.txt docs/hard_link.txt      # -s 없이: 하드 링크 생성

ls -l docs/original.txt                      # 원본 파일 정보 확인
ls -l docs/soft_link.txt                     # 소프트 링크 확인 (→ original.txt 형태로 표시)
ls -l docs/hard_link.txt                     # 하드 링크 확인

# inode 번호 비교 (ls -i: inode 번호를 맨 앞에 표시)
# 하드 링크는 original.txt 와 같은 번호, 소프트 링크는 다른 번호여야 정상
ls -i docs/original.txt
ls -i docs/soft_link.txt
ls -i docs/hard_link.txt

# 원본 삭제 후 링크 동작 차이 확인
rm docs/original.txt                         # 원본 삭제
cat docs/soft_link.txt                       # 소프트 링크: "No such file or directory" 오류 발생
cat docs/hard_link.txt                       # 하드 링크: 내용이 그대로 출력됨 (정상)
```

> 소프트 링크가 깨져서 오류가 나는 것이 **정상적인 결과**다.  
> 하드 링크는 원본이 삭제되어도 데이터가 유지되는 것이 **정상적인 결과**다.
{: .prompt-info }

## Step 4. 아주 간단한 스크립트 실행

```bash
nano bin/week3_bootstrap.sh   # nano 편집기로 파일 생성 (Ctrl+O 저장, Ctrl+X 종료)
```

아래 내용을 입력:

```bash
#!/bin/bash
# #!/bin/bash: 이 스크립트를 bash로 실행하라는 선언 (첫 줄에 반드시 있어야 함)
echo "=== Week3 Bootstrap ==="
echo "USER: $(whoami)"        # $(명령어): 명령어 실행 결과를 문자열 안에 넣는 방법
echo "SHELL: $SHELL"
echo "PWD: $(pwd)"
date                          # 현재 날짜/시간 출력
```

저장(Ctrl+O → Enter) 후 종료(Ctrl+X), 그리고 실행:

```bash
chmod +x bin/week3_bootstrap.sh    # +x: 실행 권한 추가 (없으면 Permission denied 오류)
./bin/week3_bootstrap.sh           # ./: 현재 디렉터리에서 직접 실행
```

## Step 5. 사용자/그룹 만들기 (3-1 내용 복습)

이미 3-1에서 생성했다면 이 단계는 건너뛰어도 된다.  
`id pig` 결과에 `animals` 그룹이 포함되어 있으면 이미 완료된 것이다.

```bash
sudo adduser pig              # pig 사용자 생성 (이미 있으면 "user already exists" 메시지)
sudo adduser mango
sudo adduser dog

sudo addgroup animals         # animals 그룹 생성
sudo adduser pig animals      # pig를 animals 그룹에 추가
sudo adduser mango animals
sudo adduser dog animals

# 생성 결과 확인
id pig                        # 출력에 "animals" 가 보이면 정상
id mango
id dog

grep pig /etc/passwd          # /etc/passwd 에서 pig 행 확인 (7개 필드 콜론 구분)
grep animals /etc/group       # animals 그룹에 세 사용자가 모두 있는지 확인
```

## Step 6. 소유권/권한 적용 (3-2 내용 복습)

```bash
# 실습 디렉터리 준비
sudo mkdir /tmp/lab-perm                        # 공용 실습 디렉터리 생성
sudo chown root:animals /tmp/lab-perm           # 소유자=root, 소유그룹=animals 로 설정
sudo chmod 775 /tmp/lab-perm                    # 775 = 소유자/그룹 전체 권한, 기타 읽기+실행

# dog 계정으로 전환해서 파일 생성
su - dog
# ↑ 이 시점부터 dog 계정의 셸이 시작됨. 프롬프트가 "dog@..." 형태로 바뀜
echo "dog baseline" > /tmp/lab-perm/from_dog.txt
# dog는 animals 그룹 멤버이므로 775 디렉터리에 파일 생성 가능
exit
# ↑ exit를 입력해서 dog 세션 종료. 프롬프트가 원래 사용자로 돌아와야 함
# whoami 로 확인해볼 것

# 파일 소유권/권한 정리 (원래 사용자로 돌아와서 실행)
sudo chown dog:animals /tmp/lab-perm/from_dog.txt    # 소유그룹을 animals 로 통일
sudo chmod 640 /tmp/lab-perm/from_dog.txt            # 640 = 소유자 rw, 그룹 r, 기타 ---

# 결과 확인
ls -ld /tmp/lab-perm                    # 디렉터리 권한/소유 확인
ls -l /tmp/lab-perm/from_dog.txt        # 파일 권한/소유 확인

# mango는 animals 그룹 멤버이므로 파일을 읽을 수 있는지 테스트
su - mango
# ↑ mango 계정으로 전환
cat /tmp/lab-perm/from_dog.txt          # "dog baseline" 이 출력되면 권한 설정 성공
exit
# ↑ 반드시 exit 로 mango 세션 종료 후 원래 사용자로 복귀
```

> `su - 사용자명` 으로 전환한 후에는 **반드시 `exit` 를 입력**해야 원래 사용자로 돌아온다.  
> 전환 후 `whoami` 로 현재 사용자를 확인하는 습관을 들일 것.
{: .prompt-danger }

## Step 7. Sticky bit 확인

```bash
# Sticky bit 없이 → 다른 사람 파일도 삭제 가능 (취약 상태 재현)
sudo mkdir /tmp/sticky-lab
sudo chmod 777 /tmp/sticky-lab        # 777 = 모든 사용자 모든 권한 (Sticky 없음)

su - pig
echo "pig file" > /tmp/sticky-lab/pig.txt    # pig가 파일 생성
exit
# ↑ pig 세션 종료, 원래 사용자로 복귀

su - mango
rm /tmp/sticky-lab/pig.txt            # Sticky 없으면 mango가 pig 파일을 삭제 가능
exit
# ↑ mango 세션 종료, 원래 사용자로 복귀

# Sticky bit 적용 → 본인 파일만 삭제 가능
su - pig
echo "pig file 2" > /tmp/sticky-lab/pig.txt  # pig가 파일 재생성
exit

sudo chmod 1777 /tmp/sticky-lab       # 1777 = Sticky bit(1) + 777

su - mango
rm /tmp/sticky-lab/pig.txt            # 이번에는 "Permission denied" 오류가 나야 정상
exit

ls -ld /tmp/sticky-lab                # drwxrwxrwt 형태 (끝이 t 이면 Sticky bit 적용 확인)
ls -l /tmp/sticky-lab                 # pig.txt 가 아직 남아있어야 정상
```

## Step 8. SGID 확인 (협업 디렉터리 그룹 상속)

```bash
sudo mkdir /tmp/team-share
sudo chown root:animals /tmp/team-share    # 소유그룹=animals
sudo chmod 2775 /tmp/team-share            # 2775 = SGID(2) + 775

su - pig
echo "pig note" > /tmp/team-share/pig_note.txt
exit
# ↑ pig 세션 종료

su - mango
echo "mango note" > /tmp/team-share/mango_note.txt
exit
# ↑ mango 세션 종료

ls -ld /tmp/team-share                    # drwxrwsr-x 형태 (s 가 있으면 SGID 적용 확인)
ls -l /tmp/team-share                     # pig_note.txt 와 mango_note.txt 모두 그룹이 animals 여야 정상

# SUID 예시 확인 (시스템 파일)
ls -l /usr/bin/passwd                     # -rwsr-xr-x 형태 (소유자 x 자리에 s 가 있으면 SUID 적용)
stat /usr/bin/passwd                      # 파일 상세 메타데이터 확인
```

## 완료 확인

```bash
whoami                    # 반드시 원래 계정인지 확인 (su 후 exit 를 빠뜨렸을 수 있음)

id pig
id mango
id dog

ls -ld /tmp/lab-perm      # drwxrwxr-x  root animals 형태
ls -ld /tmp/sticky-lab    # drwxrwxrwt  형태 (t 확인)
ls -ld /tmp/team-share    # drwxrwsr-x  형태 (s 확인)

ls -l /tmp/lab-perm
ls -l /tmp/sticky-lab
ls -l /tmp/team-share
```

**완료 기준:**

- `mango` 가 `/tmp/lab-perm/from_dog.txt` 를 읽을 수 있다.
- `sticky-lab` 는 끝에 `t` 가 보이고, `mango` 가 `pig.txt` 를 지울 수 없다.
- `team-share` 는 `s` 가 보이고, 생성된 파일의 그룹이 모두 `animals` 다.
