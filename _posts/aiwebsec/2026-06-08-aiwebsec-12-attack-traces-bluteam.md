# 자동 공격의 흔적 — 보안 로그와 방어자 탐지

지금까지 11개 강의는 **공격자(점검자)의 시점**이었다. 이제 시점을 **방어자**로 옮긴다.  
우리가 Kali(192.168.0.10)에서 돌린 자동 점검은, 대상 서버(192.168.0.30)의 입장에서 보면 **수상한 트래픽의 폭격**이었다.  
**"자동 공격하면 이렇게 된다"** — 그 흔적을 서버 로그에서 직접 확인하고, 그것으로 공격을 탐지하는 법을 배운다.

> 이 강의는 **Kali가 아니라 Ubuntu 서버(192.168.0.30)**에서 진행한다. 방어자의 자리에 앉는 것이다.
{: .prompt-tip }

> **🎯 우리가 지금 왜 이걸 하나요?**  
> 지금까지는 줄곧 공격(점검)하는 사람의 자리에 있었어요. 이제 자리를 바꿔 **방어자의 눈**으로 봅니다. 우리가 돌린 자동 점검이 상대 서버 로그에 **어떤 흔적**을 남기는지 직접 보면, *"아, 공격은 결국 흔적을 남기는구나"* 하고 깨닫게 돼요. 바로 이 깨달음이 방어의 출발점이에요. **공격을 아는 사람이 가장 잘 막아요.**
{: .prompt-info }

다룰 내용:

1. 보안 로그는 어디에 있는가
2. 각 도구가 남기는 흔적 (nmap·nikto·gobuster·sqlmap·XSS·명령삽입)
3. 자동 공격의 3대 특징 — 속도·양·서명
4. 로그로 공격 탐지하기
5. 방어자도 AI를 쓴다 — 로그를 LLM에게 분석시키기
6. 점검 인사이트 — 모든 행동은 흔적을 남긴다

## 1. 보안 로그는 어디에 있는가

Ubuntu + Apache 환경의 주요 로그 위치다. (Ubuntu 서버에서 실행)

```bash
# 웹 접근 로그 — 모든 HTTP 요청이 한 줄씩 기록된다
sudo tail -f /var/log/apache2/access.log

# 웹 에러 로그 — 비정상 요청·서버 오류
sudo tail -f /var/log/apache2/error.log

# 인증/시스템 로그
sudo tail -f /var/log/auth.log
```

> **`tail -f`** 는 로그 파일의 끝을 **실시간으로 따라가며** 보여 준다. 이 상태로 두고, Kali에서 점검을 돌리면 흔적이 **실시간으로 쌓이는** 것을 볼 수 있다. 공격과 로그를 나란히 놓고 보는 것이 이 강의의 핵심 실습이다.
{: .prompt-info }

Apache 접근 로그 한 줄의 구조는 이렇다.

```text
192.168.0.10 - - [08/Jun/2026:21:03:11 +0900] "GET /DVWA/login.php HTTP/1.1" 200 1523 "-" "Mozilla/5.0"
└─ 출발지 IP ──┘             └─ 시각 ─────┘  └─ 요청 ───────────┘ └상태┘└크기┘      └─ User-Agent ─┘
```

기억할 네 가지: **출발지 IP / 시각 / 요청 내용 / User-Agent(클라이언트 종류)**. 공격 탐지의 단서가 모두 여기 있다.

## 2. 각 도구가 남기는 흔적

Kali에서 우리가 돌린 도구들이 access.log에 어떻게 보이는지, 도구별로 정리한다.

### nikto (06강)

```text
192.168.0.10 - - [...] "GET /DVWA/admin.php HTTP/1.1" 404 ...  "... Nikto/2.5.0"
192.168.0.10 - - [...] "GET /DVWA/test.php HTTP/1.1" 404 ...   "... Nikto/2.5.0"
192.168.0.10 - - [...] "GET /DVWA/backup.sql HTTP/1.1" 404 ... "... Nikto/2.5.0"
... (수천 줄) ...
```

- **User-Agent에 `Nikto`** 가 그대로 박힌다. 도구가 자기 이름을 광고한다.
- 존재하지 않는 경로를 **수천 개** 두드려 **404가 폭증**한다.

### gobuster (05강)

```text
192.168.0.10 - - [...] "GET /DVWA/admin HTTP/1.1" 404 ...  "gobuster/3.6"
192.168.0.10 - - [...] "GET /DVWA/config HTTP/1.1" 301 ...  "gobuster/3.6"
... 초당 수십~수백 줄 ...
```

- 역시 **User-Agent에 `gobuster`**. 짧은 시간에 **엄청난 요청 수**.

### sqlmap (07강)

```text
192.168.0.10 - - [...] "GET /DVWA/vulnerabilities/sqli/?id=1%27%20AND%201%3D1 ..." 200 ...
192.168.0.10 - - [...] "GET /DVWA/vulnerabilities/sqli/?id=1%20UNION%20SELECT ..." 200 ...
192.168.0.10 - - [...] "... id=1%27%20OR%20%271%27%3D%271 ..." 500 ...   "sqlmap/1.8"
```

- URL에 `%27`(작은따옴표), `UNION SELECT`, `OR 1=1` 같은 **주입 패턴**이 인코딩되어 남는다.
- **상태 코드 500(서버 오류)**이 섞여 나타난다 — 주입이 쿼리를 깨뜨린 흔적.

### XSS / 명령 삽입 (08강)

```text
"GET /DVWA/vulnerabilities/xss_r/?name=<script>alert(1)</script> ..." 200 ...
"POST /DVWA/vulnerabilities/exec/  ... ip=127.0.0.1;id ..." 200 ...
```

- 요청 파라미터에 `<script>`, `onerror=`, `;id`, `&&` 같은 **특수문자 패턴**이 그대로 보인다.

> **핵심**: 자동화 도구는 대부분 **자기 이름을 User-Agent에 남기고**, **사람이 불가능한 속도와 양**으로 요청한다. 이 두 가지가 곧 탐지의 출발점이다.
{: .prompt-info }

## 3. 자동 공격의 3대 특징 — 속도·양·서명

사람이 브라우저로 둘러보는 것과, 자동 도구가 점검하는 것은 로그에서 확연히 다르다.

| 특징 | 사람(정상 사용자) | 자동 공격 도구 |
|---|---|---|
| **속도** | 클릭 사이 수 초 | 초당 수십~수백 요청 |
| **양** | 수십 건 | 수천~수만 건 |
| **서명** | 브라우저 User-Agent | `Nikto`, `sqlmap`, `gobuster` 등 |
| **패턴** | 정상 경로 | 404 폭증, 주입 문자열, 비정상 메서드 |

> **"자동 공격하면 이렇게 된다"의 핵심**: **빠르고, 많고, 티가 난다.** 속도와 양 자체가 자동화의 증거다. 그래서 공격자는 일부러 느리게(저속 스캔), User-Agent를 위장해 흔적을 줄이려 한다 — 이는 곧 방어자가 **속도·양·서명**을 핵심 탐지 지표로 삼아야 한다는 뜻이다.
{: .prompt-warning }

## 4. 로그로 공격 탐지하기

이제 방어자로서, 로그를 분석해 공격 흔적을 찾아본다. (Ubuntu 서버에서 실행)

**① 도구 서명(User-Agent)으로 찾기**

```bash
# 알려진 공격 도구 이름이 User-Agent에 있는 요청 찾기
grep -Ei "nikto|sqlmap|gobuster|nmap" /var/log/apache2/access.log
```

**② 요청을 많이 보낸 IP 순위 (속도·양)**

```bash
# 출발지 IP별 요청 수를 세어 많은 순으로 정렬
awk '{print $1}' /var/log/apache2/access.log | sort | uniq -c | sort -rn | head
```

**예상 결과:**

```text
  8412 192.168.0.10      ← 우리 Kali. 압도적으로 많다 = 자동 공격 의심
    23 192.168.0.50
```

**③ 404 폭증 찾기 (디렉터리 탐색 흔적)**

```bash
# 상태 코드가 404인 요청 수를 IP별로 집계
grep '" 404 ' /var/log/apache2/access.log | awk '{print $1}' | sort | uniq -c | sort -rn | head
```

**④ 주입 패턴 찾기 (SQLi/XSS)**

```bash
# URL에 주입 흔적이 있는 요청 찾기
grep -Ei "union|select|%27|<script|onerror|;id" /var/log/apache2/access.log
```

> 단 한 IP가 **수천 건의 404와 주입 패턴**을 짧은 시간에 남겼다면, 그것은 **자동 점검(또는 공격)**이 일어났다는 명백한 신호다. 방어자는 이 IP를 차단하고 경보를 발령한다.
{: .prompt-tip }

## 5. 방어자도 AI를 쓴다 — 로그를 LLM에게 분석시키기

흥미로운 대칭이 있다. 공격을 자동화했듯, **방어자도 로그 분석을 LLM으로 자동화**할 수 있다.  
03강에서 배운 "수집 → 해석" 패턴을 그대로, 이번엔 **방어 목적**으로 쓴다. (Ubuntu 또는 Kali에서, ollama가 있는 곳에서 실행)

```python
# log_triage.py — 보안 로그를 LLM에게 분석시키기 (방어자 관점)
import ollama

# 의심스러운 로그 일부를 읽어 온다
with open("/var/log/apache2/access.log") as f:
    lines = f.readlines()
sample = "".join(lines[-200:])   # 최근 200줄

SYSTEM = """너는 침해사고 분석가(Blue Team)다. 아래 웹 접근 로그를 보고
(1) 자동화 공격 도구의 흔적이 있는가, (2) 어떤 공격 유형으로 보이는가,
(3) 출발지 IP와 차단 권고를 한국어로 요약하라."""

resp = ollama.chat(model="qwen2.5:7b", messages=[
    {"role": "system", "content": SYSTEM},
    {"role": "user", "content": sample},
])
print(resp["message"]["content"])
```

**예상 결과** (요지):

```text
- 자동화 흔적: User-Agent에 'sqlmap', 'Nikto'가 확인됨. 자동 도구 사용 확실.
- 공격 유형: 디렉터리 탐색(404 다수) + SQL Injection 시도(UNION SELECT, %27).
- 출발지: 192.168.0.10 단일 IP가 단시간에 수천 건. 즉시 차단 권고.
```

> **공격과 방어는 같은 기술을 쓴다.** 우리가 04~10강에서 만든 "수집→LLM 해석" 구조는, 입력만 바꾸면 그대로 **방어용 로그 분석기**가 된다. 이것이 다음 13강의 핵심 주제인 **Purple Team**(공격·방어의 결합)의 씨앗이다.
{: .prompt-info }

## 6. 점검 인사이트 — 모든 행동은 흔적을 남긴다

> **점검 인사이트 — 공격자는 보이지 않으려 하고, 방어자는 보려 한다**  
> 이 강의의 교훈은 단순하다. **자동화된 모든 행동은 로그라는 흔적을 남긴다.**  
> - **공격자 관점**: 우리가 만든 도구는 빠르고 시끄럽다. 실제 공격자는 이를 알기에 **속도를 낮추고, User-Agent를 위장하고, 여러 IP에 분산**해 흔적을 지운다.  
> - **방어자 관점**: 그래서 방어자는 **로그를 반드시 켜고, 보존하고, 분석**해야 한다. 로그가 없으면 침해를 당하고도 알 수 없다. **로그는 사고 후 유일한 진실**이다.  
>
> 점검을 자동화할 줄 아는 사람이라야, 그 점검이 **어떤 흔적을 남기는지** 알고, **방어 로그를 어떻게 설계할지** 안다. 공격을 이해하는 것이 최고의 방어 설계다.
{: .prompt-info }
