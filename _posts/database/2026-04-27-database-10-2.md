# 10-2 계정 관리와 권한 — `CREATE USER`, `GRANT`, `REVOKE`

> 이번 시간 학습 목표
> - MySQL에서 **사용자 계정을 생성/삭제** 할 수 있다.
> - `GRANT` 로 **필요한 권한만** 부여하고, `REVOKE` 로 회수할 수 있다.
> - **최소 권한 원칙**(Principle of Least Privilege) 의 의미와 실무적 중요성을 이해한다.
> - Python 스크립트로 사용자와 권한을 관리할 수 있다.
{: .prompt-tip }

---

## 1. 왜 계정을 나눠야 하는가?

지금까지 우리는 모든 작업을 `root` 계정으로 했다.  
하지만 실무에서 `root` 는 **서버 관리자만** 쓴다. 그 이유는:

- `root` 는 **모든 DB의 모든 작업**을 할 수 있다.
- 만약 `root` 비밀번호가 유출되면 **회사 전체 데이터가 위험**하다.
- 그래서 역할별로 계정을 나누고, **그 역할에 필요한 최소한의 권한만** 준다.

> 💡 **최소 권한 원칙**: 사용자에게는 **꼭 필요한 권한만** 준다.  
> 이 원칙은 DB뿐 아니라 운영체제, 클라우드, 웹 서비스 등 모든 보안의 기본이다.
{: .prompt-info }

### 실무 예시

| 계정 | 하는 일 | 필요한 권한 |
|---|---|---|
| `app_user` | 웹 서비스가 쓰는 계정 | `SELECT`, `INSERT`, `UPDATE` |
| `reporter` | 보고서 뽑는 담당자 | `SELECT` 만 |
| `backup_bot` | 밤마다 백업 돌리는 스크립트 | `SELECT`, `LOCK TABLES` |
| `dba` | DBA | `ALL PRIVILEGES` |

## 3. 사용자(계정) 만들기 — `CREATE USER`

### 3-1. 기본 문법

```sql
CREATE USER '사용자이름'@'호스트' IDENTIFIED BY '비밀번호';
```

- `사용자이름` : 로그인 ID
- `호스트` : 어디서 접속할 수 있는지. `localhost` 면 이 PC에서만.
- `IDENTIFIED BY` : 비밀번호

### 3-2. 실습 — 조회 전용 사용자 만들기

```sql
DROP USER IF EXISTS 'viewer'@'localhost';
CREATE USER 'viewer'@'localhost' IDENTIFIED BY 'viewer_pw_1234';
```

### 3-3. 현재 계정 목록 확인

```sql
SELECT user, host FROM mysql.user;
```

방금 만든 `viewer` 가 보이면 성공이다.

## 4. 권한 부여 — `GRANT`

### 4-1. 기본 문법

```sql
GRANT 권한목록 ON DB이름.테이블이름 TO '사용자'@'호스트';
```

### 4-2. 주요 권한

| 권한 | 설명 |
|---|---|
| `SELECT` | 조회 |
| `INSERT` | 추가 |
| `UPDATE` | 수정 |
| `DELETE` | 삭제 |
| `CREATE`, `ALTER`, `DROP` | 테이블 구조 변경 |
| `ALL PRIVILEGES` | 해당 DB의 모든 권한 |

### 4-3. 실습 1 — 읽기 전용 권한 주기

`viewer` 에게 `view_db` 의 **모든 테이블 SELECT만** 허용한다.

```sql
GRANT SELECT ON view_db.* TO 'viewer'@'localhost';
FLUSH PRIVILEGES;   -- 권한 변경 즉시 반영
```

> 💡 `view_db.*` 에서 `*` 은 **해당 DB의 모든 테이블**을 의미한다.
{: .prompt-info }

### 4-4. 권한 확인

```sql
SHOW GRANTS FOR 'viewer'@'localhost';
```

결과 예시:

```
GRANT USAGE ON *.* TO `viewer`@`localhost`
GRANT SELECT ON `view_db`.* TO `viewer`@`localhost`
```

## 6. 특정 컬럼만 허용하기 (컬럼 수준 권한)

`viewer` 에게 `students` 의 `resident_no` 는 숨기고 나머지만 보여 주고 싶다면?

### 방법 A — 9-1에서 만든 VIEW를 사용한다 (추천)

```sql
-- root로 다시 로그인해서 실행
USE view_db;

-- 4장에서 준 DB 전체 SELECT 권한을 먼저 회수한다.
-- 이 권한이 남아 있으면 원본 students도 계속 볼 수 있다.
REVOKE SELECT ON view_db.* FROM 'viewer'@'localhost';

-- 그다음 공개 VIEW만 허용한다.
GRANT SELECT ON view_db.v_student_public TO 'viewer'@'localhost';
FLUSH PRIVILEGES;
```

이제 `viewer` 는 `students` 원본은 못 보고, 9-1에서 만든 `v_student_public` 만 볼 수 있다.  
**→ 민감 컬럼(`resident_no`)이 원천적으로 차단된다.**

### 방법 B — 컬럼 단위 GRANT

방법 B를 쓰는 경우에도, 먼저 4장에서 준 DB 전체 SELECT 권한을 회수해야 한다.

```sql
REVOKE SELECT ON view_db.* FROM 'viewer'@'localhost';

GRANT SELECT (student_no, name, phone) ON view_db.students
TO 'viewer'@'localhost';

FLUSH PRIVILEGES;
```

`viewer` 가 `SELECT resident_no FROM students` 를 시도하면 차단된다.

## 7. 권한 회수 — `REVOKE`

### 7-1. 기본 문법

```sql
REVOKE 권한목록 ON DB이름.테이블이름 FROM '사용자'@'호스트';
```

### 7-2. 실습 — `viewer` 의 전체 SELECT 권한 회수

```sql
-- 4-3에서 부여한 DB 전체 SELECT 권한을 회수하는 예시
REVOKE SELECT ON view_db.* FROM 'viewer'@'localhost';
FLUSH PRIVILEGES;
```

> ⚠️ 이미 회수한 권한을 다시 `REVOKE` 하면 MySQL에서 `Error Code: 1141` 이 날 수 있다.  
> `SHOW GRANTS FOR 'viewer'@'localhost';` 로 현재 권한을 먼저 확인하고 회수하자.
{: .prompt-warning }

### 7-3. 전체 권한 회수

```sql
REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'viewer'@'localhost';
FLUSH PRIVILEGES;
```

## 10. 실습 시나리오 — 역할별 계정 3개 만들기

아래 세 계정을 **직접 만들어 보자.**

| 계정 | 권한 |
|---|---|
| `app_user` | `view_db` 에 `SELECT, INSERT, UPDATE` |
| `reporter` | `view_db` 의 **VIEW만** `SELECT` |
| `cleaner`  | `view_db.scores` 에 `DELETE` 만 |

```sql
DROP USER IF EXISTS 'app_user'@'localhost';
DROP USER IF EXISTS 'reporter'@'localhost';
DROP USER IF EXISTS 'cleaner'@'localhost';

-- 1) app_user
CREATE USER 'app_user'@'localhost' IDENTIFIED BY 'app_pw_1234';
GRANT SELECT, INSERT, UPDATE ON view_db.* TO 'app_user'@'localhost';

-- 2) reporter
CREATE USER 'reporter'@'localhost' IDENTIFIED BY 'report_pw_1234';
GRANT SELECT ON view_db.v_student_masked TO 'reporter'@'localhost';
GRANT SELECT ON view_db.v_student_avg    TO 'reporter'@'localhost';

-- 3) cleaner
CREATE USER 'cleaner'@'localhost' IDENTIFIED BY 'clean_pw_1234';
GRANT DELETE ON view_db.scores TO 'cleaner'@'localhost';

FLUSH PRIVILEGES;
```

확인:

```sql
SHOW GRANTS FOR 'app_user'@'localhost';
SHOW GRANTS FOR 'reporter'@'localhost';
SHOW GRANTS FOR 'cleaner'@'localhost';
```

## 11. Python 으로 계정 관리 자동화

학교·회사에서는 수십 개 계정을 손으로 만들면 실수가 많다. Python으로 돌리자.

### 11-1. 계정 일괄 생성 스크립트

```python
# create_users.py
import mysql.connector

admin = mysql.connector.connect(
    host="localhost", user="root",
    password="root_비밀번호"
)
cursor = admin.cursor()

users = [
    # (username, password, grants)
    ("app_user", "app_pw_1234",
     "GRANT SELECT, INSERT, UPDATE ON view_db.* TO %s@'localhost'"),
    ("reporter", "report_pw_1234",
     "GRANT SELECT ON view_db.v_student_masked TO %s@'localhost'"),
    ("cleaner",  "clean_pw_1234",
     "GRANT DELETE ON view_db.scores TO %s@'localhost'"),
]

for name, pw, grant_tpl in users:
    # 1) 이미 있으면 지우고 다시 만든다
    cursor.execute(f"DROP USER IF EXISTS '{name}'@'localhost'")
    cursor.execute(
        f"CREATE USER '{name}'@'localhost' IDENTIFIED BY '{pw}'"
    )
    # 2) 권한 부여
    #    (GRANT 구문은 '이름' 자리에 파라미터 바인딩이 안 되므로
    #     여기서는 관리자 권한 스크립트로만 제한적으로 사용한다)
    cursor.execute(grant_tpl.replace("%s", f"'{name}'"))
    print(f"[OK] {name} 계정 생성 및 권한 부여")

cursor.execute("FLUSH PRIVILEGES")
admin.commit()

cursor.close()
admin.close()
```

> ⚠️ `CREATE USER`, `GRANT` 같은 DCL은 **문자열 포맷**으로 처리해야 한다.  
> 일반적인 DML은 **반드시 `%s` 파라미터 바인딩**을 써야 하지만 (다음 시간 SQL Injection 참고),  
> DCL은 사용자가 아니라 **관리자**가 직접 쓰는 스크립트이므로 관리 범위 내에서만 실행한다.
{: .prompt-warning }

### 11-2. 각 계정으로 실제 로그인 테스트

```python
# login_test.py
import mysql.connector

for name, pw in [("app_user","app_pw_1234"),
                 ("reporter","report_pw_1234"),
                 ("cleaner", "clean_pw_1234")]:

            host="localhost", user=name, password=pw,
            database="view_db"

        c.close()
    except mysql.connector.Error as e:
        print(f"[{name}] 접속 실패: {e}")
```

### 문제 3
"왜 최소 권한 원칙이 중요한가?" 를 **두 문장 이내**로 설명하시오.

<details>
<summary>정답 예시</summary>

계정에 불필요한 권한이 많을수록, **해당 계정이 탈취되었을 때 피해 범위**가 넓어진다.  
필요한 권한만 부여하면 사고가 나도 **피해를 한정**할 수 있어 보안과 안정성이 크게 향상된다.
</details>

## 13. 정리

- `CREATE USER` / `DROP USER` / `ALTER USER` 로 계정을 관리한다.
- `GRANT` / `REVOKE` 는 **DCL** 의 핵심이다.
- **최소 권한 원칙** — 필요한 만큼만 준다.
- **민감 컬럼은 VIEW로 가리고, VIEW에만 권한을 준다.** (9-1 + 10-2의 결합)
- Python에서도 관리자 스크립트로 계정/권한을 자동화할 수 있다.

다음 시간([10-3](/posts/database-10-3))에는 **권한이 있어도 코드가 허술하면 뚫린다** — **SQL Injection** 공격과 방어를 직접 실습한다.
