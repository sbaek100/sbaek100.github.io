# 리눅스 입문 — Shell 과 File System

# 1장. 쉘 (Shell)

---

## 1.1 터미널과 쉘

### 터미널 (Terminal)

터미널은 사용자와 컴퓨터가 상호작용할 수 있도록 연결하는 장치다.

- **입력 장치**: 사용자가 컴퓨터에 명령을 전달하는 장치 (키보드)
- **출력 장치**: 컴퓨터가 사용자에게 결과를 보여주는 장치 (화면)

과거에는 물리적인 하드웨어 터미널이 존재했으나, 현재는 소프트웨어로 구현한 **가상 터미널(Virtual Terminal)** 을 사용한다.  
Ubuntu 24에서는 기본 터미널 프로그램으로 **GNOME Terminal** 을 제공한다.

> Ubuntu 24에서 터미널 여는 방법
> 
> - 단축키: `Ctrl + Alt + T`
> - 앱 메뉴 -> Terminal 검색

---

### 쉘 (Shell)

쉘은 운영체제(OS)가 제공하는 **명령어 기반 인터페이스(CLI, Command Line Interface)** 다.

![](/assets/img/posts/2026-03-06-Linux-1-1772778391426.png)

사용자가 터미널에 명령어를 입력하면, 쉘이 그 명령어를 해석하여 **커널(Kernel)** 에 전달하고, 실행 결과를 다시 터미널 화면으로 출력한다.

```
사용자  ->  터미널  ->  쉘(Shell)  ->  커널(Kernel)  ->  하드웨어
사용자  <-  터미널  <-  쉘(Shell)  <-  커널(Kernel)  <-  결과 반환
```

리눅스에서 가장 널리 사용하는 쉘은 **Bash (Bourne Again Shell)** 이다.  
리누스 토르발즈가 리눅스를 처음 개발할 때 포팅한 프로그램으로, Ubuntu의 기본 쉘이다.

**현재 사용 중인 쉘 확인 방법:**

```bash
echo $SHELL
# 출력 예: /bin/bash
```

---

### 터미널과 쉘의 관계 정리

|구분|역할|비유|
|---|---|---|
|터미널 (Terminal)|사용자와 컴퓨터가 상호작용하기 위한 매체 (입력/출력 도구)|창문|
|쉘 (Shell)|터미널로 들어온 명령어를 해석해 OS에 전달하는 프로그램|통역사|

터미널이 없으면 쉘을 실행할 수 없고, 쉘이 없으면 터미널에서 명령어를 실행할 수 없다.  
두 개념은 함께 동작하지만, 서로 다른 구성 요소다.

## 1.2 쉘 스크립트

### 쉘 스크립트 (Shell Script) 란?

쉘 스크립트는 **쉘에서 실행 가능한 명령어를 순서대로 모아놓은 텍스트 파일**이다.

- 여러 명령어를 하나의 파일로 묶어 자동 실행할 수 있음
- 반복 작업을 자동화하는 데 활용
- 파일 확장자는 관례적으로 `.sh` 를 사용
  
  ![](/assets/img/posts/2026-03-06-Linux-1-1772778469562.png)

---

### 쉘 스크립트 작성 절차

|단계|설명|
|---|---|
|1|터미널 실행|
|2|`nano` 편집기로 `.sh` 파일 생성|
|3|스크립트 코드 작성|
|4|`Ctrl + O` 로 저장, `Ctrl + X` 로 nano 종료|
|5|`chmod +x 파일명.sh` 로 실행 권한 부여|
|6|`./파일명.sh` 로 실행|

---

### 실습: hello.sh 작성

**1단계 — nano로 파일 생성**

```bash
nano hello.sh
```

**2단계 — 아래 내용 입력**

```bash
#!/bin/bash

# 주석: 첫 번째 쉘 스크립트
echo "안녕하세요, 리눅스!"
echo "현재 날짜: $(date)"
echo "현재 경로: $(pwd)"
echo "현재 사용자: $(whoami)"
```

> `#!/bin/bash` — 쉬뱅(Shebang)이라고 하며, 이 스크립트를 실행할 쉘의 경로를 지정한다.  
> 반드시 파일 첫 번째 줄에 작성해야 한다.

**3단계 — 저장 후 종료**

```
Ctrl + O   -> 저장 (파일명 확인 후 Enter)
Ctrl + X   -> nano 종료
```

**4단계 — 실행 권한 부여**

```bash
chmod +x hello.sh
```

**5단계 — 실행**

```bash
./hello.sh
```

**출력 예시:**

```
안녕하세요, 리눅스!
현재 날짜: Fri Mar  6 10:00:00 KST 2026
현재 경로: /home/user
현재 사용자: user
```

## 1.3 기본 명령어

### 명령어 기본 형식

리눅스 명령어는 아래 형식을 따른다.

```
명령어  [옵션]  [인수]
```

|구성 요소|설명|예시|
|---|---|---|
|명령어|실행할 프로그램 이름|`ls`, `cd`, `cp`|
|옵션|동작 방식을 변경하는 설정 값, `-` (하이픈) 으로 시작|`-l`, `-a`, `-r`|
|인수|명령어가 처리할 대상 (파일명, 경로 등)|`/home`, `file.txt`|

**예시 분석:**

```bash
ls  -l  /home/user
# ls     : 명령어 (파일 목록 출력)
# -l     : 옵션   (상세 형식으로 출력)
# /home/user : 인수  (조회할 디렉터리 경로)
```

> 옵션은 여러 개를 동시에 사용할 수 있다.  
> 예) `ls -l -a` 는 `ls -la` 로 줄여 쓸 수 있다.

### man — 명령어 매뉴얼 조회

**개념**

`man` 은 **manual** 의 약자로, 리눅스에 내장된 명령어 매뉴얼(man page)을 조회하는 명령어다.  
명령어의 사용법, 옵션, 예시를 화면에 출력해준다.

인터넷 없이도 터미널에서 즉시 모든 명령어의 상세 설명을 확인할 수 있다.

**형식**

```
man  [섹션 번호]  명령어
```

**섹션 번호 의미**

|번호|내용|
|---|---|
|1|일반 명령어 (shell commands)|
|2|시스템 콜 (system calls)|
|3|라이브러리 함수|
|4|장치 파일|
|5|설정 파일 형식|
|8|시스템 관리 명령어 (root 전용)|

**사용 예시**

```bash
man ls
# ls 명령어 매뉴얼 조회

man 1 passwd
# 섹션 1 의 passwd 명령어 매뉴얼 조회

man 5 passwd
# 섹션 5 의 passwd 설정 파일 형식 조회
```

**매뉴얼 내 이동 단축키**

|단축키|기능|
|---|---|
|방향키 위/아래|한 줄씩 이동|
|`Space`|다음 페이지|
|`b`|이전 페이지|
|`/검색어`|검색|
|`n`|다음 검색 결과|
|`q`|매뉴얼 종료|

### ls — 파일 목록 출력

**개념**

`ls` 는 **list** 의 약자로, 현재 또는 지정한 디렉터리의 파일·디렉터리 목록을 화면에 출력하는 명령어다.

리눅스에서 가장 빈번하게 사용하는 기본 명령어 중 하나다.

**형식**

```
ls  [옵션]  [경로]
```

**주요 옵션**

|옵션|설명|
|---|---|
|`-l`|상세 정보 출력 (권한, 소유자, 파일 크기, 수정 날짜 포함)|
|`-a`|숨김 파일 포함 전체 출력 (`.` 으로 시작하는 파일)|
|`-h`|`-l` 과 함께 사용, 파일 크기를 사람이 읽기 쉬운 단위로 표시 (KB, MB, GB)|
|`-r`|역순 정렬 출력|
|`-t`|수정 시간 기준 최신 순으로 정렬 출력|
|`-R`|하위 디렉터리까지 재귀적으로 출력|

**사용 예시**

```bash
ls
# 현재 디렉터리의 파일 목록 출력

ls /home
# /home 디렉터리의 파일 목록 출력

ls -l
# 상세 정보 출력 (권한, 소유자, 크기, 날짜 포함)

ls -a
# 숨김 파일 포함 전체 출력

ls -la
# 상세 정보 + 숨김 파일 모두 출력 (가장 자주 사용)

ls -lh
# 파일 크기를 KB / MB 단위로 표시

ls -lt
# 최근 수정된 파일 순으로 정렬 출력
```

**ls -l 출력 결과 해석**

```
-rw-r--r--  1  user  user  4096  Mar  1  10:00  hello.sh
|---------|  |  |     |     |     |-----------|  |-------|
  권한       링크수 소유자 그룹  크기(bytes)   수정날짜    파일명
```

- 첫 번째 문자: 파일 종류 (`-` 일반 파일, `d` 디렉터리, `l` 링크)
- 이후 9자리: 소유자(3자리) / 그룹(3자리) / 기타(3자리) 권한
    - `r` = 읽기 (read), `w` = 쓰기 (write), `x` = 실행 (execute), `-` = 권한 없음

**실습 순서**

```bash
ls                    # 1. 기본 목록 확인
ls -l                 # 2. 상세 정보 확인
ls -la                # 3. 숨김 파일까지 확인
ls -lh /etc           # 4. /etc 디렉터리 크기 단위 확인
```

### cd — 디렉터리 이동

**개념**

`cd` 는 **change directory** 의 약자로, 현재 작업 디렉터리(CWD, Current Working Directory)의 위치를 변경하는 명령어다.

**형식**

```
cd  [경로]
```

**경로(Path) 개념 이해**

경로란 파일 또는 디렉터리의 위치 정보를 표현한 것이다.

**절대 경로 (Absolute Path)**

- 루트 디렉터리 `/` 를 기준으로 파일의 전체 경로를 표현
- 어느 위치에 있든 항상 같은 경로를 가리킴
- 예) `/home/user/documents`, `/etc/passwd`, `/var/log`

**상대 경로 (Relative Path)**

- 현재 작업 디렉터리를 기준으로 경로를 표현
- 현재 위치에 따라 가리키는 대상이 달라짐
- `.` : 현재 디렉터리
- `..` : 상위 디렉터리
- 예) `./documents`, `../`, `../../etc`

**사용 예시**

```bash
cd /home/user
# 절대 경로로 /home/user 디렉터리로 이동

cd documents
# 상대 경로: 현재 위치 기준 documents 디렉터리로 이동

cd ..
# 상위 디렉터리로 이동
# 예) 현재 /home/user 이면 -> /home 으로 이동

cd ../..
# 상위의 상위 디렉터리로 이동
# 예) 현재 /home/user 이면 -> / (루트) 로 이동

cd ~
# 홈 디렉터리로 이동 (= cd /home/현재사용자)

cd -
# 바로 이전에 있었던 디렉터리로 이동
```

**실습 순서**

```bash
pwd                   # 1. 현재 위치 확인
cd /var/log           # 2. 절대 경로로 이동
pwd                   # 3. 이동 확인
cd ..                 # 4. 상위 디렉터리로 이동
pwd                   # 5. 위치 확인 (/var)
cd ~                  # 6. 홈 디렉터리로 복귀
pwd                   # 7. 위치 확인 (/home/user)
cd -                  # 8. 이전 디렉터리(/var)로 복귀
```

### pwd — 현재 작업 디렉터리 출력

**개념**

`pwd` 는 **print working directory** 의 약자로, 현재 자신이 위치한 작업 디렉터리를 **절대 경로**로 출력하는 명령어다.

`cd` 로 이동 후 현재 위치를 확인할 때 자주 사용한다.

**형식**

```
pwd
```

별도 옵션이나 인수 없이 단독으로 사용한다.

**사용 예시**

```bash
pwd
# 출력 예: /home/user

cd /etc
pwd
# 출력: /etc

cd /var/log/apt
pwd
# 출력: /var/log/apt
```

**cd + pwd 조합 실습**

```bash
pwd                    # 현재 위치 확인  ->  /home/user
cd /var/log            # /var/log 로 이동
pwd                    # 현재 위치 확인  ->  /var/log
cd ..                  # 상위 디렉터리로 이동
pwd                    # 현재 위치 확인  ->  /var
cd ~                   # 홈 디렉터리로 복귀
pwd                    # 현재 위치 확인  ->  /home/user
```

### cat — 파일 내용 출력·연결

**개념**

`cat` 은 **concatenate(연결하다)** 또는 **catenate** 의 약자로, 파일의 내용을 화면에 출력하거나 여러 파일을 연결(합치기)하는 명령어다.

**형식**

```
cat  [옵션]  [파일명 ...]
```

**주요 옵션**

|옵션|설명|
|---|---|
|`-n`|출력할 때 각 줄 앞에 줄 번호를 표시|
|`-b`|빈 줄을 제외하고 줄 번호 표시|
|`-A`|탭, 줄바꿈 등 특수 문자까지 표시|

**사용 예시**

```bash
cat hello.sh
cat /etc/hostname
cat -n hello.sh
cat file1.txt file2.txt
cat file1.txt > output.txt
cat file2.txt >> output.txt
cat file1.txt file2.txt > merged.txt
```

**실습 순서**

```bash
echo "첫 번째 줄" > test1.txt
echo "두 번째 줄" > test2.txt
cat test1.txt
cat test1.txt test2.txt
cat test1.txt test2.txt > all.txt
cat all.txt
```

### exit — 쉘 종료

**개념**

`exit` 은 현재 실행 중인 쉘을 종료하는 명령어다.

**형식**

```
exit  [종료 코드]
```

**종료 코드 (Exit Code) 의미**

|코드|의미|
|---|---|
|`0`|정상 종료 (성공)|
|`1`|일반 오류|
|`2`|잘못된 사용법|
|그 외|비정상 종료 (오류 코드)|

**사용 예시**

```bash
exit
exit 0
exit 1
```

**스크립트 내 사용 예시**

```bash
#!/bin/bash

ping -c 1 google.com > /dev/null 2>&1

if [ $? -eq 0 ]; then
    echo "네트워크 연결 성공"
    exit 0
else
    echo "네트워크 연결 실패"
    exit 1
fi
```

> `$?` : 직전 명령어의 종료 코드를 저장하는 특수 변수

### echo — 문자열 출력

**개념**

`echo` 는 인수로 전달된 문자열을 화면(표준 출력)에 출력하는 명령어다.

쉘 스크립트에서 메시지 출력, 변수 값 확인, 디버깅에 가장 많이 사용하는 명령어다.

**형식**

```
echo  [옵션]  [문자열]
```

**주요 옵션**

|옵션|설명|
|---|---|
|`-n`|출력 후 줄바꿈(newline)을 하지 않음|
|`-e`|이스케이프 문자 (`\n`, `\t` 등) 해석|

**사용 예시**

```bash
echo "Hello, Linux"
echo "현재 경로: $(pwd)"
echo $HOME
echo $USER
echo -n "줄바꿈 없이 출력"
echo -e "첫 번째 줄\n두 번째 줄\n세 번째 줄"
echo "텍스트" > file.txt
```

**주요 환경 변수**

```bash
echo $HOME    # 현재 사용자의 홈 디렉터리 경로
echo $USER    # 현재 로그인된 사용자명
echo $SHELL   # 현재 사용 중인 쉘의 경로
echo $PATH    # 명령어 검색 경로 목록
echo $PWD     # 현재 작업 디렉터리 (pwd 명령어와 동일)
```

### nano — 텍스트 편집기

**개념**

`nano` 는 터미널 환경에서 사용하는 텍스트 편집기다.

`vi/vim` 에 비해 사용법이 직관적이며, Ubuntu에 기본 설치되어 있어 입문자가 가장 쉽게 접근할 수 있는 편집기다.

**형식**

```
nano  [파일명]
```

**nano 내 주요 단축키(중요)**

|단축키|기능|
|---|---|
|`Ctrl + O`|파일 저장 (Write Out)|
|`Ctrl + X`|nano 종료|
|`Ctrl + K`|현재 줄 잘라내기|
|`Ctrl + U`|붙여넣기|
|`Ctrl + W`|텍스트 검색|
|`Ctrl + G`|도움말 표시|
|`Alt + U`|실행 취소 (Undo)|

**사용 예시**

```bash
nano test.txt
nano /etc/hosts
sudo nano /etc/hosts
```

**실습 순서**

```bash
nano hello.txt          # 1. 새 파일 열기
# 2. 화면에 원하는 내용 입력
# 3. Ctrl + O 로 저장 -> Enter 로 파일명 확인
# 4. Ctrl + X 로 종료
cat hello.txt           # 5. 저장된 내용 확인
```

## 2.1 파일 시스템

![](/assets/img/posts/2026-03-06-Linux-1-1772776437276.png)

### 파일과 파일 시스템의 개념

**파일 (File)**  
컴퓨터에서 데이터를 저장하고 조직화하는 기본 단위다.  
텍스트, 이미지, 실행 파일, 설정 파일 등 모든 데이터가 파일 형태로 저장된다.

**파일 시스템 (File System)**  
파일에 대한 정보를 관리하는 소프트웨어다.  
파일의 이름, 크기, 저장 위치, 권한을 관리하고, 저장 장치에 대한 읽기/쓰기 접근을 제어한다.

---

### 파일 시스템의 종류

![](/assets/img/posts/2026-03-06-Linux-1-1772776473461.png)

**1. 디스크 기반 파일 시스템 (Disk-based File System)**

HDD, SSD 같은 물리적 저장 장치를 위한 파일 시스템이다.  
저장 장치를 사용하기 위해 먼저 **포맷(Format)** — 파일 시스템 설치 — 을 해야 한다.

| OS             | 주로 사용하는 파일 시스템     |
| -------------- | ------------------ |
| Linux (Ubuntu) | ext4               |
| Windows        | NTFS, FAT32, exFAT |
| macOS          | APFS, HFS+         |


**2. 네트워크 기반 파일 시스템 (Network-based File System)**

원격 컴퓨터(서버)에 연결된 저장 장치를 네트워크를 통해 로컬 컴퓨터(클라이언트)에서 마치 내 디스크처럼 사용하는 파일 시스템이다.

- **NFS (Network File System)**: 리눅스/유닉스 환경의 대표적인 네트워크 파일 시스템
- **SMB/CIFS**: Windows 파일 공유 프로토콜 (삼바 서버)

서버-클라이언트 구조로 동작하며, 마운트(mount) 과정을 통해 로컬 디렉터리에 연결한다.

**3. 가상 파일 시스템 (Pseudo File System)**

실제 파일이 디스크에 저장되지 않고, OS의 실시간 상태 정보를 디렉터리와 파일 구조로 노출하는 파일 시스템이다.

|경로|역할|
|---|---|
|`/proc`|실행 중인 프로세스 정보, 커널 파라미터|
|`/sys`|커널이 인식한 하드웨어 장치 정보|
|`/dev`|장치 파일 (디스크, 키보드, 터미널 등)|

**가상 파일 시스템 실습:**

```bash
cat /proc/cpuinfo      # CPU 정보 조회
cat /proc/meminfo      # 메모리 정보 조회
cat /proc/version      # 커널 버전 확인
ls /dev                # 장치 파일 목록 확인
```

## 2.2 리눅스 파일 계층 구조 (FHS)

리눅스는 **FHS (Filesystem Hierarchy Standard)** 에 따라 파일과 디렉터리를 계층적으로 구성한다.

![](/assets/img/posts/2026-03-06-Linux-1-1772776502335.png)

모든 파일과 디렉터리는 최상단의 루트 디렉터리 `/` 에서 시작하는 트리 구조를 가진다.

```
/
├── bin       실행 파일 (ls, cp, mv 등 기본 명령어)
├── boot      부트 로더, 커널 이미지
├── dev       장치 파일
├── etc       시스템 전체 설정 파일
├── home      일반 사용자 홈 디렉터리
│   └── user  특정 사용자의 홈 디렉터리
├── lib       공유 라이브러리
├── media     CD, USB 등 이동식 미디어 마운트 지점
├── mnt       임시 파일 시스템 마운트 지점
├── opt       선택적으로 설치하는 소프트웨어
├── proc      가상 파일 시스템 (프로세스 정보)
├── root      root 계정의 홈 디렉터리
├── run       실행 중인 프로세스 관련 데이터
├── sbin      시스템 관리용 실행 파일 (root 전용)
├── srv       서비스 데이터 저장
├── sys       가상 파일 시스템 (커널/하드웨어 정보)
├── tmp       임시 파일 저장 (재부팅 시 삭제)
├── usr       사용자용 실행 파일, 라이브러리
│   ├── bin   일반 사용자 실행 파일
│   └── lib   라이브러리
└── var       자주 변경되는 데이터 (로그, 메일 등)
    └── log   시스템 로그 파일
```

**주요 디렉터리 상세 설명**

|디렉터리|역할|실습 예시|
|---|---|---|
|`/`|루트 디렉터리. 모든 경로의 시작점|`cd /`|
|`/home`|일반 사용자의 홈 디렉터리 모음|`ls /home`|
|`/root`|root(관리자) 계정의 홈 디렉터리|`sudo ls /root`|
|`/etc`|시스템 전체 설정 파일 저장소|`cat /etc/hostname`|
|`/var/log`|시스템 및 애플리케이션 로그 파일|`ls /var/log`|
|`/tmp`|임시 파일. 재부팅 시 삭제됨|`touch /tmp/test.txt`|
|`/bin`|기본 실행 파일 (ls, cat, cp 등)|`ls /bin`|
|`/usr/bin`|일반 사용자용 추가 실행 파일|`ls /usr/bin`|
|`/proc`|가상 파일 시스템 (프로세스 정보)|`cat /proc/version`|

**실습:**

```bash
ls /              # 루트 디렉터리 구조 확인
ls /etc           # 설정 파일 목록 확인
cat /etc/hostname # 시스템 호스트명 확인
cat /etc/os-release # Ubuntu 버전 정보 확인
ls /var/log       # 로그 파일 목록 확인
```

## 2.3 파일의 종류

리눅스에서 파일은 크게 5가지 종류로 구분된다.  
`ls -l` 명령어 출력의 **첫 번째 문자**로 파일 종류를 식별한다.

|표시 문자|파일 종류|설명|
|---|---|---|
|`-`|일반 파일 (Regular File)|텍스트, 이미지, 실행 파일, 바이너리 등 일반 데이터 파일|
|`d`|디렉터리 (Directory)|파일을 계층적으로 관리하는 디렉터리|
|`l`|심볼릭 링크 (Symbolic Link)|다른 파일·디렉터리를 가리키는 링크 파일 (바로가기)|
|`c`|문자 장치 파일 (Character Device)|키보드, 터미널 등 문자 단위로 처리하는 장치|
|`b`|블록 장치 파일 (Block Device)|HDD, SSD 등 블록 단위로 처리하는 장치|
|`p`|파이프 파일 (Named Pipe)|프로세스 간 통신(IPC)에 사용|
|`s`|소켓 파일 (Socket)|네트워크 통신에 사용|

**실습: 파일 종류 확인**

```bash
ls -l /
ls -l /dev
ls -l /etc/alternatives
```

**ls -l 출력 예시:**

```
drwxr-xr-x  2 root root 4096 Mar 1 10:00 documents   <- d: 디렉터리
-rw-r--r--  1 user user  512 Mar 1 10:00 hello.txt    <- -: 일반 파일
lrwxrwxrwx  1 user user   11 Mar 1 10:00 link -> hello.txt  <- l: 심볼릭 링크
crw-rw-rw-  1 root tty  5, 0 Mar 1 10:00 /dev/tty     <- c: 문자 장치
brw-rw----  1 root disk 8, 0 Mar 1 10:00 /dev/sda     <- b: 블록 장치
```

## 2.4 디렉터리

### 루트 디렉터리, 홈 디렉터리, 현재 작업 디렉터리

**루트 디렉터리 (Root Directory)**

- 파일 시스템의 최상단에 위치하는 디렉터리
- 경로 표기: `/`
- 모든 파일과 디렉터리는 루트 디렉터리 하위에 존재
- Windows의 `C:\` 에 해당하는 개념

```bash
cd /      # 루트 디렉터리로 이동
ls /      # 루트 디렉터리 내용 확인
```

**홈 디렉터리 (Home Directory)**

- 리눅스에서 사용자를 추가하면 개별로 할당하는 디렉터리
- 경로: `/home/사용자명`
- `~` (틸드, tilde) 기호로 표현 가능
- 사용자의 개인 파일, 설정 파일 저장 공간

```bash
cd ~              # 홈 디렉터리로 이동 (= cd /home/현재사용자)
echo $HOME        # 홈 디렉터리 경로 출력
ls ~              # 홈 디렉터리 내용 확인
```

**현재 작업 디렉터리 (CWD, Current Working Directory)**

- 현재 쉘이 실행되고 있는 디렉터리
- `.` (점 하나) 로 표현
- `pwd` 명령어로 확인

```bash
pwd               # 현재 작업 디렉터리 출력
ls .              # 현재 디렉터리 내용 출력 (= ls)
cp file.txt .     # 파일을 현재 디렉터리로 복사
```

---

### 절대 경로와 상대 경로 심화

**절대 경로 예시:**

```bash
cd /home/user/documents   # 절대 경로로 이동
cat /etc/passwd           # 절대 경로로 파일 읽기
ls /var/log               # 절대 경로로 목록 확인
```

**상대 경로 예시:**

현재 위치가 `/home/user` 일 때:

```bash
cd documents          # = cd /home/user/documents
cd ../                # = cd /home
cd ../../             # = cd /
cd ../other_user      # = cd /home/other_user
```

**경로 표현 특수 기호 정리**

|기호|의미|예시|
|---|---|---|
|`/`|루트 디렉터리 또는 경로 구분자|`/home/user`, `cd /`|
|`.`|현재 작업 디렉터리|`./script.sh`, `ls .`|
|`..`|상위(부모) 디렉터리|`cd ..`, `cp ../file.txt .`|
|`~`|홈 디렉터리|`cd ~`, `ls ~/documents`|
|`-`|(cd에서) 이전 디렉터리|`cd -`|

## 2.5 파일과 디렉터리 다루기

---

### mkdir — 디렉터리 생성

**개념**

`mkdir` 은 **make directory** 의 약자로, 새 디렉터리를 생성하는 명령어다.

**형식**

```
mkdir  [옵션]  디렉터리명 [디렉터리명 ...]
```

**주요 옵션**

|옵션|설명|
|---|---|
|`-p`|중간 경로가 없어도 필요한 상위 디렉터리를 자동으로 함께 생성 (parents)|
|`-v`|생성 과정을 화면에 출력 (verbose)|
|`-m`|생성 시 권한(mode)을 지정|

**사용 예시**

```bash
mkdir animals
mkdir dog cat cow
mkdir -p fruits/apple
mkdir -p projects/2026/spring
mkdir -v newdir
```

**실습 순서**

```bash
ls
mkdir animals
mkdir -p animals/dog animals/cat animals/cow
ls animals
mkdir -p fruits/apple
ls fruits
mkdir -p fruits/apple
```

> **-p 옵션 주의**: `-p` 옵션 없이 `mkdir fruits/apple` 을 실행하면 `fruits` 디렉터리가 없을 경우 오류가 발생한다. 중첩 경로를 생성할 때는 반드시 `-p` 옵션을 사용한다.

---

### rmdir — 빈 디렉터리 삭제

**개념**

`rmdir` 은 **remove directory** 의 약자로, **비어 있는 디렉터리만** 삭제하는 명령어다.

내용이 있는 디렉터리는 삭제할 수 없다. 내용이 있는 디렉터리를 삭제하려면 `rm -r` 을 사용한다.

**형식**

```
rmdir  [옵션]  디렉터리명 [디렉터리명 ...]
```

**주요 옵션**

|옵션|설명|
|---|---|
|`-p`|지정한 디렉터리 삭제 후 비어있는 상위 디렉터리까지 순서대로 삭제|
|`-v`|삭제 과정을 화면에 출력|

**사용 예시**

```bash
rmdir cat
rmdir dog cow snake
rmdir -p fruits/apple
rmdir animals
# 오류 메시지: rmdir: failed to remove 'animals': Directory not empty
```

**실습 순서**

```bash
mkdir -p test/sub
ls test
rmdir test/sub
rmdir test
mkdir -p a/b/c
rmdir -p a/b/c
```

---

### cp — 파일 복사

**개념**

`cp` 는 **copy** 의 약자로, 파일 또는 디렉터리를 복사하는 명령어다.

원본 파일은 그대로 유지되고, 지정한 위치에 복사본이 생성된다.

**형식**

```
cp  [옵션]  원본  대상
cp  [옵션]  원본1 원본2 ...  대상디렉터리
```

**주요 옵션**

|옵션|설명|
|---|---|
|`-r`|디렉터리와 그 하위 내용을 재귀적으로 복사 (directory copy 시 필수)|
|`-i`|대상 파일이 이미 존재하면 덮어쓸지 여부를 확인 (interactive)|
|`-p`|원본 파일의 권한, 타임스탬프, 소유자 정보를 유지하여 복사 (preserve)|
|`-v`|복사 과정을 화면에 출력 (verbose)|
|`-u`|원본이 대상보다 새로운 경우에만 복사 (update)|

**사용 예시**

```bash
cp hello.sh backup.sh
cp hello.sh /tmp/
cp hello.sh /tmp/hello_copy.sh
cp -r mydir/ /tmp/mydir_copy
cp -i source.txt dest.txt
cp -p original.txt preserved.txt
cp file1.txt file2.txt file3.txt /tmp/
```

**실습 순서**

```bash
echo "원본 내용" > original.txt
cp original.txt copy.txt
ls -l original.txt copy.txt
cp original.txt /tmp/
ls /tmp/original.txt
mkdir testdir
cp -r testdir/ /tmp/testdir_backup
```

---

### mv — 파일 이동·이름 변경

**개념**

`mv` 는 **move** 의 약자로, 파일 또는 디렉터리의 위치를 이동하거나 이름을 변경하는 명령어다.

`cp` 와 달리 원본 파일이 삭제된다는 점을 주의해야 한다.

**형식**

```
mv  [옵션]  원본  대상
mv  [옵션]  원본1 원본2 ...  대상디렉터리
```

**동작 방식 구분**

- 대상이 **디렉터리**이면 → 해당 디렉터리로 **이동**
- 대상이 **파일명**이면 → **이름 변경** (또는 이동 + 이름 변경 동시)

**주요 옵션**

|옵션|설명|
|---|---|
|`-i`|대상 파일이 이미 존재하면 덮어쓸지 확인 (interactive)|
|`-u`|원본이 대상보다 새로운 경우에만 이동 (update)|
|`-v`|이동 과정을 화면에 출력 (verbose)|

**사용 예시**

```bash
mv say-hi.txt greetings.txt
mv hello.txt /tmp/
mv hello.txt /tmp/hi.txt
mv olddir/ newdir/
mv mydir/ /home/user/
mv file1.txt file2.txt /tmp/
mv -i source.txt dest.txt
```

**실습 순서**

```bash
touch file1.txt file2.txt
ls
mv file1.txt renamed.txt
ls
mkdir destination
mv renamed.txt destination/
ls destination/
mv destination/ moved_dir/
```

### rm — 파일·디렉터리 삭제

**개념**

`rm` 은 **remove** 의 약자로, 파일 또는 디렉터리를 삭제하는 명령어다.

> **주의**: 리눅스에서 `rm` 으로 삭제된 파일은 휴지통 없이 즉시 제거된다. 복구가 매우 어려우므로 사용 전 반드시 삭제 대상을 확인해야 한다.

**형식**

```
rm  [옵션]  파일명 [파일명 ...]
```

**주요 옵션**

|옵션|설명|
|---|---|
|`-r`|디렉터리와 하위 내용을 재귀적으로 삭제 (recursive). 디렉터리 삭제 시 필수|
|`-i`|파일마다 삭제 여부를 하나씩 확인 (interactive)|
|`-f`|확인 없이 강제 삭제 (force). 없는 파일도 오류 없이 무시|
|`-d`|비어 있는 디렉터리를 삭제|
|`-v`|삭제 과정을 화면에 출력 (verbose)|

**사용 예시**

```bash
rm say-hi.txt
rm -i hello.txt
rm file1.txt file2.txt file3.txt
rm -d emptydir/
rm -r mydir/
rm -rf mydir/
```

**실습 순서**

```bash
touch test1.txt test2.txt test3.txt
ls
rm test1.txt
rm -i test2.txt
mkdir -p testdir/subdir
touch testdir/subdir/file.txt
rm testdir
rm -r testdir/
ls
```

> `rm -rf /` 또는 `rm -rf /*` 는 시스템 전체를 삭제하는 매우 위험한 명령어다. 절대 실행해서는 안 된다.

### touch — 빈 파일 생성·타임스탬프 갱신

**개념**

`touch` 명령어는 두 가지 기능을 수행한다.

1. **파일이 없을 때**: 지정한 이름의 빈 파일을 새로 생성
2. **파일이 이미 있을 때**: 파일 내용을 변경하지 않고, 마지막 수정 시간(타임스탬프)만 현재 시각으로 갱신

**형식**

```
touch  [옵션]  파일명 [파일명 ...]
```

**주요 옵션**

|옵션|설명|
|---|---|
|`-a`|접근 시간(access time)만 갱신|
|`-m`|수정 시간(modification time)만 갱신|
|`-t`|특정 날짜·시간으로 타임스탬프 지정 (형식: `[[CC]YY]MMDDhhmm[.ss]`)|

**사용 예시**

```bash
touch newfile.txt
touch file1.txt file2.txt file3.txt
touch existing.txt
touch -t 202601010000 oldfile.txt
```

**실습 순서**

```bash
ls -l
touch test.txt
ls -l test.txt
cat test.txt
touch test.txt
ls -l test.txt
touch a.txt b.txt c.txt
ls -l *.txt
```

### 아이노드(inode)와 덴트리(dentry)

링크를 이해하려면 먼저 inode와 dentry 개념을 알아야 한다.

![](/assets/img/posts/2026-03-06-Linux-1-1772776557838.png)


**아이노드 (inode, index node)**

각 파일에 대한 **메타데이터**를 저장하는 자료구조다.

inode에 저장되는 정보:

| 항목           | 설명                           |
| ------------ | ---------------------------- |
| **파일 유형**    | **일반 파일, 디렉터리, 링크, 장치 파일 등** |
| 파일 크기        | 바이트 단위                       |
| 파일 권한        | 읽기/쓰기/실행 권한                  |
| **소유자 / 그룹** | **UID, GID**                 |
| 타임스탬프        | 생성, 수정, 접근 시간                |
| 데이터 블록 위치    | 실제 파일 내용이 저장된 디스크 위치         |
| 링크 수         | 이 inode를 참조하는 덴트리 수          |

> 중요: **파일명은 inode에 저장되지 않는다.** 파일명은 dentry에 저장된다.

```bash
ls -i 파일명     # inode 번호 확인
stat 파일명      # 파일의 inode 상세 정보 확인
```

**덴트리 (dentry, directory entry)**

파일명과 inode 번호를 연결하는 자료구조다.

```
파일명 (dentry)  --->  inode 번호  --->  실제 데이터 블록
hello.txt              123456             /dev/sda1의 특정 위치
```

비유:

- **inode** = 도서관의 실제 책 (내용이 담긴 실체)
- **dentry** = 도서관 목록 카드 (제목으로 책의 위치를 알려주는 도구)

**실습:**

```bash
echo "테스트" > test.txt
ls -i test.txt            # inode 번호 확인
stat test.txt             # 상세 inode 정보 확인
```

## 1. 소프트 링크 (Soft Link / Symbolic Link)

**"파일의 주소(경로)를 적어놓은 포스트잇"**

소프트 링크는 윈도우의 **'바로가기 아이콘'**과 거의 동일한 개념입니다. 원본 파일이 어디에 있는지를 나타내는 **경로 정보**만을 담고 있는 별도의 파일입니다.

- **특징**: 원본 파일과 다른 별개의 아이노드 번호를 가집니다.
    
- **원본 삭제 시**: 소프트 링크는 여전히 존재하지만, 가리키고 있는 주소에 파일이 없으므로 **연결이 끊어집니다(Broken Link).**
    
- **용도**: 긴 경로를 짧게 줄여서 사용하거나, 라이브러리 버전 관리 시 사용합니다.
    

---

## 2. 하드 링크 (Hard Link)

**"데이터 몸체에 붙인 또 다른 이름표"**

하드 링크는 원본 파일과 **완전히 동일한 아이노드**를 공유합니다. 즉, 하나의 데이터(몸체)를 가리키는 이름표가 여러 개 생기는 것입니다.

- **특징**: 원본 파일과 하드 링크 파일은 시스템 입장에서 **동일한 파일**입니다. 아이노드 번호가 같습니다.
    
- **원본 삭제 시**: 파일의 이름표가 하나 줄어들 뿐입니다. 모든 하드 링크(이름표)가 삭제되어야만 실제 데이터가 지워집니다.
    
- **제약 사항**: 파일 시스템(파티션)을 넘나들며 생성할 수 없으며, 디렉터리에는 생성할 수 없습니다


---

### ln -s — 소프트 링크 생성

**개념**

소프트 링크(Soft Link)는 **대상 파일의 경로(path)를 저장**하는 링크 파일이다.  
심볼릭 링크(Symbolic Link) 또는 심링크(symlink)라고도 한다.  
Windows의 바로가기(.lnk) 파일과 동일한 개념이다.

**소프트 링크의 구조:**

```
소프트 링크 파일 (link.txt)   -> 경로 저장: /home/user/original.txt
                                    |
                                    v
                             original.txt (inode: 123456)
                                    |
                                    v
                              실제 데이터 블록
```

**소프트 링크의 특징:**

- 원본 파일과 **다른 inode** 번호를 가짐
- 원본 파일이 삭제되면 링크가 **깨진 상태(broken)** 가 됨
- 디렉터리에도 소프트 링크 생성 가능
- 다른 파티션, 다른 파일 시스템의 파일도 연결 가능
- `ls -l` 에서 `l` 로 표시되며 `->` 로 원본 경로를 보여줌

**형식**

```
ln  -s  대상파일(원본경로)  링크파일명
```

**주요 옵션**

|옵션|설명|
|---|---|
|`-s`|소프트 링크 생성 (없으면 하드 링크 생성)|
|`-f`|대상에 이미 링크가 있으면 강제로 덮어씀|
|`-v`|링크 생성 과정 출력|

**사용 예시**

```bash
ln -s /etc/passwd passwd_link
ln -s /var/log logs
ln -s ../original.txt link.txt
```

**실습 순서**

```bash
echo "원본 내용" > original.txt
ln -s original.txt soft_link.txt
ls -l
cat soft_link.txt
ls -i original.txt soft_link.txt
rm original.txt
cat soft_link.txt
ls -l soft_link.txt
```

---

### ln — 하드 링크 생성

**개념**

하드 링크(Hard Link)는 대상 파일과 **동일한 inode를 공유**하는 파일이다.  
원본 파일의 완전한 복제본(clone)이자 별칭(alias)이다.

**하드 링크의 구조:**

```
original.txt  (inode: 123456)  --|
                                  |--> inode 123456 --> 실제 데이터 블록
hard_link.txt (inode: 123456)  --|
```

두 파일명이 동일한 inode를 가리키며, 실제 데이터는 하나다.  
둘 중 하나를 수정하면 다른 파일에도 동일하게 반영된다.

**하드 링크의 특징:**

- 원본과 **동일한 inode** 번호 공유
- 원본 파일을 삭제해도 **데이터가 유지**됨 (inode의 링크 수가 0이 될 때 실제 삭제)
- 동일 파일 시스템·파티션 내에서만 생성 가능
- 디렉터리에는 생성 불가
- `ls -l` 에서 일반 파일(`-`)과 동일하게 표시됨

**형식**

```
ln  대상파일  링크파일명
```

`-s` 옵션 없이 사용하면 하드 링크가 생성된다.

**사용 예시**

```bash
ln original.txt hard_link.txt
```

**실습 순서**

```bash
echo "하드 링크 테스트" > original.txt
ln original.txt hard_link.txt
ls -i original.txt hard_link.txt
ls -l original.txt hard_link.txt
echo "내용 추가" >> original.txt
cat hard_link.txt
rm original.txt
cat hard_link.txt
ls -l hard_link.txt
```

### 소프트 링크 vs 하드 링크 비교

|비교 항목|소프트 링크 (Symlink)|하드 링크 (Hard Link)|
|---|---|---|
|inode 공유 여부|X — 별도 inode 생성|O — 동일 inode 공유|
|원본 파일 삭제 시|링크가 깨짐 (broken 상태)|데이터가 그대로 유지됨|
|디렉터리 연결|가능|불가|
|다른 파티션·파일 시스템|가능|불가|
|용도 범위|파일, 디렉터리 모두|일반 파일만|
|`ls -l` 표시|`l` 로 시작, `->` 로 원본 표시|`-` 로 시작, 일반 파일과 동일|
|링크 생성 명령어|`ln -s 원본 링크명`|`ln 원본 링크명`|
|주요 사용처|설정 파일 참조, 경로 단축|중요 파일 보호·백업|

**inode 번호 비교 실습:**

```bash
echo "비교 테스트" > compare.txt
ln -s compare.txt soft.txt
ln compare.txt hard.txt

ls -il compare.txt soft.txt hard.txt
# compare.txt 와 hard.txt 는 inode 번호 동일
# soft.txt 는 inode 번호 다름
```
