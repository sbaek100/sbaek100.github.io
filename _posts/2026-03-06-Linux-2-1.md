# 리눅스 입문 — Shell 과 File System

# 1장. 쉘 (Shell)

---

## 1.1 터미널과 쉘

### 터미널 (Terminal)

터미널은 사용자와 컴퓨터가 상호작용할 수 있도록 연결하는 장치다.

- **입력 장치**: 사용자가 컴퓨터에 명령을 전달하는 장치 (키보드)
- **출력 장치**: 컴퓨터가 사용자에게 결과를 보여주는 장치 (화면)

과거에는 물리적인 하드웨어 터미널이 존재했으나, 현재는 소프트웨어로 구현한 **가상 터미널(Virtual Terminal)** 을 사용한다.  
Ubuntu 24에서는 기본 터미널 프로그램으로 **GNOME Terminal** 을 제공한다.

> Ubuntu 24에서 터미널 여는 방법
> 
> - 단축키: `Ctrl + Alt + T`
> - 앱 메뉴 -> Terminal 검색

---

### 쉘 (Shell)

쉘은 운영체제(OS)가 제공하는 **명령어 기반 인터페이스(CLI, Command Line Interface)** 다.

![](/assets/img/posts/2026-03-06-Linux-1-1772778391426.png)

사용자가 터미널에 명령어를 입력하면, 쉘이 그 명령어를 해석하여 **커널(Kernel)** 에 전달하고, 실행 결과를 다시 터미널 화면으로 출력한다.

```
사용자  ->  터미널  ->  쉘(Shell)  ->  커널(Kernel)  ->  하드웨어
사용자  <-  터미널  <-  쉘(Shell)  <-  커널(Kernel)  <-  결과 반환
```

리눅스에서 가장 널리 사용하는 쉘은 **Bash (Bourne Again Shell)** 이다.  
리누스 토르발즈가 리눅스를 처음 개발할 때 포팅한 프로그램으로, Ubuntu의 기본 쉘이다.

**현재 사용 중인 쉘 확인 방법:**

```bash
echo $SHELL
# 출력 예: /bin/bash
```

---

### 터미널과 쉘의 관계 정리

|구분|역할|비유|
|---|---|---|
|터미널 (Terminal)|사용자와 컴퓨터가 상호작용하기 위한 매체 (입력/출력 도구)|창문|
|쉘 (Shell)|터미널로 들어온 명령어를 해석해 OS에 전달하는 프로그램|통역사|

## 1.2 쉘 스크립트

### 쉘 스크립트 (Shell Script) 란?

쉘 스크립트는 **쉘에서 실행 가능한 명령어를 순서대로 모아놓은 텍스트 파일**이다.

- 여러 명령어를 하나의 파일로 묶어 자동 실행할 수 있음
- 반복 작업을 자동화하는 데 활용
- 파일 확장자는 관례적으로 `.sh` 를 사용

---

### 실습: hello.sh 작성 : 그냥 따라해 보세요

```bash
nano hello.sh
```

```bash
#!/bin/bash
echo "안녕하세요, 리눅스!"
echo "현재 날짜: $(date)"
echo "현재 경로: $(pwd)"
echo "현재 사용자: $(whoami)"
```

```bash
chmod +x hello.sh
./hello.sh
```

## 1.3 기본 명령어

### man — 명령어 매뉴얼 조회

```bash
man ls
man 5 passwd

# 5는 메뉴얼 섹션 번호 man 5 passwd → /etc/passwd 파일 포맷 설명
# man 1 passwd → 사용자 명령어 passwd
```

---

### ls — 파일 목록 출력

|옵션|설명|
|---|---|
|`-l`|상세 정보 출력|
|`-a`|숨김 파일 포함|
|`-h`|파일 크기를 읽기 쉬운 단위로|
|`-t`|수정 시간 기준 정렬|

```bash
ls -la
ls -lh /etc
```

---

### cd — 디렉터리 이동

```bash
cd /var/log    # 절대 경로
cd ..          # 상위 디렉터리
cd ~           # 홈 디렉터리
cd -           # 이전 디렉터리
```

---

### pwd — 현재 작업 디렉터리 출력

```bash
pwd
# 출력 예: /home/user
```

---

### cat — 파일 내용 출력

```bash
cat hello.sh
cat -n hello.sh        # 줄 번호 포함
cat file1.txt file2.txt > merged.txt
```

---

### echo — 문자열 출력

```bash
echo "Hello, Linux"
echo $HOME
echo $USER
echo $SHELL
echo $PATH
echo $PWD
```

---

### mkdir / rmdir — 디렉터리 생성/삭제

```bash
mkdir -p fruits/apple
rmdir -p a/b/c
```

---

### cp / mv / rm — 파일 복사/이동/삭제

```bash
cp -r mydir/ /tmp/mydir_copy
mv file1.txt renamed.txt
rm -rf mydir/
```

> `rm -rf /` 는 시스템 전체를 삭제하는 매우 위험한 명령어다. 절대 실행해서는 안 된다.
{: .prompt-danger }

---

### touch — 빈 파일 생성

```bash
touch newfile.txt
touch a.txt b.txt c.txt
```

|경로|역할|
|---|---|
|`/proc`|실행 중인 프로세스 정보|

---

## 2.2 리눅스 파일 계층 구조 (FHS)

![](/assets/img/posts/2026-03-06-Linux-1-1772776502335.png)

```
/
├── bin       실행 파일 (ls, cp, mv 등)
├── etc       시스템 전체 설정 파일
├── home      일반 사용자 홈 디렉터리
├── proc      가상 파일 시스템 (프로세스 정보)
├── tmp       임시 파일 (재부팅 시 삭제)
├── usr       사용자용 실행 파일, 라이브러리
└── var       자주 변경되는 데이터 (로그 등)
```

## 2.6 소프트 링크와 하드 링크

![](/assets/img/posts/2026-03-06-Linux-1-1772778697579.png)

### 소프트 링크 (Symbolic Link)

```bash
ln -s original.txt soft_link.txt
ls -l
```

- 원본 파일과 **다른 inode** 번호
  ![](/assets/img/posts/2026-03-06-Linux-2-1-1773317006644.png)
- 원본 삭제 시 **링크가 깨짐**
- 디렉터리에도 생성 가능

### 하드 링크 (Hard Link)

```bash
ln original.txt hard_link.txt
ls -i original.txt hard_link.txt
```

- 원본과 **동일한 inode** 공유
  ![](/assets/img/posts/2026-03-06-Linux-2-1-1773316927752.png)
- 원본 삭제해도 **데이터 유지**
- 동일 파일 시스템 내에서만 생성 가능

|비교 항목|소프트 링크|하드 링크|
|---|---|---|
|inode 공유 여부|X|O|
|원본 삭제 시|링크 깨짐|데이터 유지|
|디렉터리 연결|가능|불가|
|다른 파티션|가능|불가|

  
**[참고] cp와 hard link 차이 
: 핵심적으로 데이터를 복제하느냐, 같은 데이터를 가리키느냐

- **cp fileA fileB**
    
    - 새 파일을 만들어 **내용을 복사**합니다.
    - fileA, fileB는 서로 독립적입니다.
    - 한쪽 수정해도 다른 쪽은 안 바뀝니다.
    - inode도 보통 다릅니다.
      
- **ln fileA fileB (hard link)**
    
    - 파일 내용을 복사하지 않고, 같은 inode를 가리키는 **이름(디렉터리 엔트리) 하나 추가**입니다.
    - 사실상 같은 파일을 두 이름으로 부르는 것.
    - 한쪽 수정하면 다른 이름으로 봐도 같이 바뀝니다.
    - 둘 다 삭제되어야(링크 카운트 0) 실제 데이터가 지워집니다.

제약:

- hard link는 보통 **같은 파일시스템 내에서만** 가능
- 일반적으로 **디렉터리에는 hard link 불가** (특수 경우 제외)
