# 📖 풀이 및 해설

---

### 문제 1 해설 — grep 옵션별 역할

**정답: ② `grep -c "bash" /etc/passwd`**

| 옵션 | 기능 |
|---|---|
| `-c` | 매칭된 줄의 **개수**만 출력 |
| `-n` | 줄 번호와 함께 출력 |
| `-l` | 매칭된 파일명만 출력 |
| `| wc` | 줄 수 세기 (가능하지만 `-c` 가 더 간결) |

```bash
grep -c "bash" /etc/passwd    # 숫자만 출력 (예: 3)
grep "bash" /etc/passwd | wc  # 줄 수, 단어 수, 바이트 수 모두 출력
```

`-c` 옵션이 가장 직접적으로 개수만 출력함.

---

### 문제 2 해설 — -v 반전 옵션

**정답: ② `/etc/passwd` 에서 `nologin` 문자열이 없는 줄만 출력한다.**

`-v` (invert)는 **패턴과 일치하지 않는 줄만 출력**하는 반전 옵션임.

```bash
grep "nologin" /etc/passwd     # nologin 포함 줄 (시스템 계정들)
grep -v "nologin" /etc/passwd  # nologin 미포함 줄 (로그인 가능한 계정들)
```

실무에서 로그인 가능한 계정만 추려볼 때 자주 사용함.

---

### 문제 3 해설 — -r과 -l 옵션 조합

**정답: ② `grep -rl "error" /var/log`**

| 명령 | 설명 |
|---|---|
| `grep -r "error" /var/log` | 매칭된 줄 전체 출력 (파일명 포함) |
| `grep -rl "error" /var/log` | **파일명만** 출력 |
| `grep -rn "error" /var/log` | 줄 번호와 함께 출력 |
| `grep -rc "error" /var/log` | 파일별 매칭 개수 출력 |

`-l` (lowercase L) 은 list의 의미로, 파일 이름만 출력함.

---

### 문제 4 해설 — -i 대소문자 무시

**정답: ② `syslog` 파일에서 `error`, `Error`, `ERROR` 등 대소문자를 무시하고 검색한다.**

`-i` (ignore-case)는 대소문자를 구분하지 않고 검색함.

```bash
grep "error" syslog      # "error" 만 매칭
grep -i "error" syslog   # "error", "Error", "ERROR", "eRrOr" 등 모두 매칭
```

로그 파일에서 에러 메시지는 작성 프로그램마다 대소문자가 다를 수 있으므로 `-i` 옵션이 유용함.

---

### 문제 5 해설 — -E ERE와 OR 연산자

**정답: ② ERE(확장 정규표현식)을 사용하여 `error` 또는 `warning` 이 포함된 줄을 출력한다.**

`-E` 옵션은 ERE(Extended Regular Expression)를 활성화함. ERE에서 `|` 는 OR 연산자임.

```bash
grep -E "error|warning" syslog   # ERE: | 직접 사용
grep "error\|warning" syslog     # BRE: | 앞에 역슬래시 필요
```

두 명령은 동일한 결과를 출력함. ERE가 더 직관적임.

---

### 문제 6 해설 — find -name 와일드카드

**정답: ② `find /home -name "*.txt"`**

`find` 의 `-name` 옵션에서 와일드카드(`*`)를 사용할 때 **반드시 따옴표로 감싸야 함**. 따옴표 없이 쓰면 셸이 먼저 글로빙(globbing)을 수행함.

```bash
find /home -name "*.txt"   # 올바른 사용법
find /home -name *.txt     # 셸이 먼저 글로빙 → 의도와 다른 결과 가능
```

### 문제 7 해설 — SetUID 파일 검색

**정답: ③ SetUID 비트가 설정된 일반 파일을 검색한다.**

`-perm -4000` 에서 `-` 는 "이 비트가 설정되어 있으면"을 의미함. `4000` 은 SetUID 비트 값임.

| 특수 권한 | 8진수 값 | 의미 |
|---|---|---|
| SetUID | 4000 | 실행 시 파일 소유자 권한으로 실행 |
| SetGID | 2000 | 실행 시 파일 그룹 권한으로 실행 |
| Sticky Bit | 1000 | 디렉터리에서 자신의 파일만 삭제 가능 |

SetUID가 설정된 실행 파일(`/usr/bin/passwd` 등)을 악용하면 권한 상승이 가능하므로 보안 점검 시 필수 항목임.

### 문제 8 해설 — -mtime 옵션

**정답: ③ `find /home -mtime -7`**

`-mtime` 의 부호 의미:

| 표현 | 의미 |
|---|---|
| `-mtime -7` | **7일 이내** 수정된 파일 (음수 = 이내) |
| `-mtime 7` | 정확히 7일 전에 수정된 파일 |
| `-mtime +7` | **7일 이전** 수정된 파일 (양수 = 초과) |

직관과 반대로 기억하기 쉽도록: "빼기(`-`)는 최근, 더하기(`+`)는 오래된 것"으로 기억할 것.

### 문제 9 해설 — -exec {} \; 의미

**정답: ② `{}` 는 찾은 파일의 경로가 대체되는 자리, `\;` 는 `-exec` 의 종료를 의미한다.**

`-exec 명령어 {} \;` 구조:
- `{}` : find 가 찾은 파일 경로로 자동 대체되는 플레이스홀더
- `\;` : `-exec` 절의 끝을 나타내는 종료 표시 (셸이 `;` 를 처리하지 못하게 `\` 로 이스케이프)

```bash
find /etc -name "*.conf" -exec ls -lh {} \;
# → 찾은 각 파일에 ls -lh 실행
# → {} 에 실제 파일 경로가 들어감
```

### 문제 17 해설 — ^ 앵커

**정답: ③ 줄의 처음이 `root` 인 줄을 검색한다.**

`^` 는 **줄의 시작**을 의미하는 앵커(Anchor)임.

```bash
grep "root" /etc/passwd    # root 가 줄 어디에든 있으면 매칭
grep "^root" /etc/passwd   # root 로 줄이 시작하는 경우만 매칭
```

`/etc/passwd` 에서 `^root` 는 root 계정 줄만 출력함 (일반 사용자 줄은 root 를 포함하더라도 줄 앞에 없으면 제외됨).

### 문제 18 해설 — . 임의 문자

**정답: ② 줄바꿈을 제외한 임의의 문자 하나를 의미한다.**

정규표현식에서 `.` 는 메타문자(Meta Character)임. 실제 점(.)을 검색하려면 `\.` 로 이스케이프해야 함.

```bash
grep "c.t" words.txt    # cat, cut, cot, c-t, c3t 등 모두 매칭
grep "c\.t" words.txt   # c.t 만 매칭 (정확히 점 문자)
```

`[0-9]` 는 **문자 클래스**로, 0부터 9까지 숫자 중 **하나**와 매칭됨. `/etc/passwd` 의 거의 모든 줄에는 UID, GID 숫자가 포함되므로 대부분의 줄이 매칭됨.

### 문제 20 해설 — + 수량자

**정답: ④ `b`**

`ba+` 패턴 분석:
- `b` : 문자 b
- `a+` : a가 **1번 이상** 반복

따라서 `b` 뒤에 `a` 가 최소 1번은 있어야 함:
- `ba` → 매칭 (a가 1번)
- `baa` → 매칭 (a가 2번)
- `baaa` → 매칭 (a가 3번)
- `b` → **미매칭** (a가 0번)

`b` (a가 없음)는 `ba+` 패턴에 매칭되지 않음. `ba*` 였다면 b도 매칭됨.

### 문제 22 해설 — \b 단어 경계

**정답: ② `cat` 이라는 완전한 단어만 검색하고 `category`, `concatenate` 는 제외한다.**

`\b` (Word Boundary)는 단어와 비단어(공백, 구두점 등) 사이의 경계를 의미함. 완전한 단어만 매칭하고 싶을 때 사용함.

```bash
grep "cat" file.txt          # cat, category, concatenate 모두 매칭
grep -E "\bcat\b" file.txt   # "cat" 단어만 매칭 (category, concatenate 제외)
```

`\b` 는 공백을 포함하지 않으므로 `cat ` (공백 포함) 가 아닌 `cat` 만 필요함.

| Perl 단축 표기 | 의미 | 동등한 표현 |
|---|---|---|
| `\d` | **숫자** | `[0-9]` |
| `\D` | 숫자 아닌 문자 | `[^0-9]` |
| `\w` | 단어 문자 | `[a-zA-Z0-9_]` |
| `\s` | 공백 | `[ \t\n\r]` |
| `\b` | 단어 경계 | — |

`\b` 는 **단어 경계**임. `\d` 와 혼동하지 말 것.

### 문제 24 해설 — BRE와 ERE의 | 차이

**정답: ② BRE 에서는 `\|` 로 이스케이프해야 하고, ERE 에서는 `|` 를 그대로 사용한다.**

```bash
# BRE — 역슬래시 이스케이프 필요
grep "error\|warning" /var/log/syslog

# ERE — 역슬래시 없이 직접 사용
grep -E "error|warning" /var/log/syslog
```

두 명령의 결과는 동일함. ERE가 더 직관적이고 사용하기 편함.

### 문제 25 해설 — {} 수량자

**정답: ② `a` 가 2번 이상 4번 이하 반복되는 패턴**

중괄호 수량자 패턴:

| 표현 | 의미 |
|---|---|
| `{n}` | 정확히 n번 반복 |
| `{n,}` | n번 이상 반복 |
| `{n,m}` | n번 이상 m번 이하 반복 |

`a{2,4}` → `aa`, `aaa`, `aaaa` 에 매칭됨. `a` (1번)나 `aaaaa` (5번)는 미매칭.

### 문제 26 해설 — Perl 정규표현식 \d{n}

**정답: ① `/etc/passwd` 에서 숫자 3개가 연속으로 나타나는 줄을 검색한다.**

```bash
grep -P "\d{3}" /etc/passwd
```

`\d{3}` 은 숫자 3개가 연속으로 나타나는 패턴임. `/etc/passwd` 에는 UID, GID 같은 숫자가 있어 3자리 이상이면 매칭됨.

> `-P` 옵션 없이 `grep "\d{3}"` 으로 쓰면 `\d` 가 메타문자로 해석되지 않아 `d{3}` 리터럴로 검색됨. Perl 정규표현식 단축 표기는 반드시 `-P` 옵션이 필요함.

### 문제 27 해설 — ? 수량자

**정답: ② ⓐ, ⓑ**

`colou?r` 패턴 분석:
- `colou` : 문자 그대로 매칭
- `u?` : `u` 가 0번 또는 1번 (0 or 1)
- `r` : 문자 r

| 단어 | 분석 | 매칭 여부 |
|---|---|---|
| `color` | u가 0번 | ✅ |
| `colour` | u가 1번 | ✅ |
| `colouur` | u가 2번 | ❌ (`?` 는 최대 1번) |
| `coloour` | oo — 패턴 불일치 | ❌ |

`?` 는 0 또는 1번이므로 `color`(u 없음)와 `colour`(u 1번)만 매칭됨. 영국 영어/미국 영어 표기 차이를 모두 처리할 때 유용한 패턴임.
