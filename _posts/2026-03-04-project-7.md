# 7부. 프롬프트 엔지니어링 기초
---
## 1. 프롬프트 엔지니어링이란?

### 프롬프트란?

> **프롬프트(prompt)** 는 LLM에게 내가 원하는 작업을 전달하는 입력 문장임.

우리가 AI에게 질문하거나 지시할 때 입력하는 모든 문장이 프롬프트라고 볼 수 있음.

예를 들어 아래 문장도 모두 프롬프트임.

- "파이썬이 뭐야?"
- "이 문장을 3줄로 요약해줘."
- "너는 네트워크 보안 강사야. 초보자에게 쉽게 설명해줘."

### 프롬프트 엔지니어링이란?

프롬프트 엔지니어링은 **LLM이 더 정확하고, 더 유용하고, 더 원하는 방식으로 답하도록 입력을 설계하는 방법**임.

즉, 단순히 질문만 던지는 것이 아니라 다음을 함께 고려하는 것임.

- 어떤 역할로 답하게 할 것인가
- 무엇을 하라고 요청할 것인가
- 어떤 형식으로 답하게 할 것인가
- 어느 수준까지 자세히 설명하게 할 것인가
- 무엇은 하지 말라고 제한할 것인가

### 왜 중요한가?

같은 모델이라도 프롬프트를 어떻게 쓰느냐에 따라 답변 품질이 크게 달라질 수 있음.

| 프롬프트 수준 | 결과 경향 |
| --- | --- |
| **짧고 모호한 프롬프트** | 답변이 두루뭉술하거나, 내가 원하는 방향과 어긋날 수 있음 |
| **구체적이고 정교한 프롬프트** | 목적에 맞고, 형식이 정리되며, 실무적으로 더 쓸모 있는 답이 나올 가능성이 높음 |

### 이번 실습의 목표

이번 장에서는 학생들이 Ollama에 설치된 로컬 LLM을 대상으로 직접 연습하면서 다음을 익히는 것이 목표임.

1. 단순 프롬프트와 정교한 프롬프트의 차이 이해
2. 역할(Role)을 부여하는 방법 익히기
3. 목적, 대상, 형식, 제한 조건을 넣는 방법 익히기
4. 시스템 프롬프트의 의미 이해하기
5. Python 코드에서 시스템 프롬프트와 사용자 프롬프트를 함께 사용하는 방법 익히기

## 2. 실습 준비

### 사용할 환경

이번 실습은 앞 장에서 설치한 Ollama 환경을 그대로 사용함.

준비 예시:

- Ollama 설치 완료
- 소형 LLM 다운로드 완료
- PowerShell 사용 가능
- 필요 시 Python 설치 완료

### 권장 모델

이번 장의 실습 기준 모델은 **`gemma3:4b`** 로 통일함. 너무 무겁지 않으면서도 프롬프트 차이에 따른 응답 변화를 비교하기 좋고, 학생들이 따라 하기에도 비교적 안정적인 편임.

| 모델 | 용도 |
| --- | --- |
| `gemma3:4b` | project-7 전체 실습 기준 모델 |

### 실행 명령 예시

```powershell
ollama run gemma3:4b
```

설치와 실행이 정상인지 먼저 확인한 뒤, 아래 프롬프트 실습을 진행하면 됨.

```powershell
ollama ls
ollama run gemma3:4b
```

### 실습할 때 기억할 점

이번 실습의 핵심은 "정답 맞히기"가 아니라, **프롬프트를 바꾸면 답변이 어떻게 달라지는지 관찰하는 것**임.

즉, 아래를 계속 비교해 보는 것이 중요함.

- 답변 길이
- 설명의 구조
- 난이도 수준
- 말투
- 예시 포함 여부
- 표나 목록 같은 출력 형식

## 3. 단순 프롬프트와 정교한 프롬프트 비교

### 실습 1. 아주 단순한 질문

먼저 아래처럼 매우 짧은 프롬프트를 입력해 보자.

```text
파이썬 설명해줘.
```

- 설명이 일반적임
- 대상 독자가 누구인지 모름
- 분량이 들쭉날쭉함
- 예시가 없을 수 있음
- 내가 원하는 형식이 아닐 수 있음

## 4. 좋은 프롬프트의 기본 구조

### 좋은 프롬프트를 만드는 5가지 요소

LLM과 잘 의사소통하려면 아래 5가지를 의식하면 좋음.

| 요소 | 질문 예시 |
| --- | --- |
| **역할(Role)** | 누구처럼 답해야 하는가? |
| **목적(Task)** | 무엇을 해야 하는가? |
| **대상(Audience)** | 누구 눈높이에 맞춰야 하는가? |
| **형식(Format)** | 표, 목록, 단계별 설명 등 어떤 형태로 답해야 하는가? |
| **제한(Constraint)** | 길이, 금지사항, 포함 요소는 무엇인가? |

### 기본 템플릿

아래 템플릿은 학생들이 가장 쉽게 따라 할 수 있는 기본 형태임.

```text
너는 [역할]이다.
[대상]이 이해할 수 있도록 설명해줘.
주제는 [주제]이다.
다음 조건을 지켜줘.
1. [형식 조건]
2. [길이 조건]
3. [포함해야 할 내용]
4. [피해야 할 내용]
```

### 예시 1. 개념 설명용

```text
너는 정보보안 강사다.
대학생 초보자가 이해할 수 있도록 VPN을 설명해줘.
다음 조건을 지켜줘.
1. 6문장 이내로 설명
2. 어려운 용어는 쉬운 말로 풀기
3. 마지막에 실생활 예시 1개 포함
```

### 예시 2. 요약용

```text
너는 문서 요약 도우미다.
아래 글을 초보자도 이해할 수 있게 3줄로 요약해줘.
핵심 개념이 빠지지 않게 해줘.
```

### 예시 3. 비교 설명용

```text
너는 친절한 IT 튜터다.
리스트와 튜플의 차이를 표로 정리해줘.
초보자가 많이 헷갈리는 부분도 한 줄로 추가해줘.
```

## 5. 역할(Role) 부여하기

### 왜 역할을 부여할까?

역할을 주면 모델이 "어떤 관점으로", "어떤 말투로", "어떤 깊이로" 답할지 더 잘 맞출 수 있음.

예를 들어 같은 주제라도 역할에 따라 답변 스타일이 달라질 수 있음.

| 역할 | 기대되는 답변 스타일 |
| --- | --- |
| **교사** | 쉽게 설명, 단계적 설명 |
| **개발자** | 실습 중심, 코드 예시 포함 |
| **보안 컨설턴트** | 위험 요소, 대응 방안 중심 |
| **면접관** | 질문 중심, 평가 기준 포함 |
| **문서 작성자** | 형식적이고 정리된 문장 |

### 실습 1. 역할 없이 질문하기

```text
SQL 인젝션 설명해줘.
```

### 실습 2. 역할을 넣어서 질문하기

```text
너는 웹 보안 강사다.
SQL 인젝션이 무엇인지 초보 개발자가 이해할 수 있게 설명해줘.
공격 원리, 위험성, 방어 방법을 순서대로 설명해줘.
```

### 실습 3. 역할을 바꿔 보기

같은 주제를 아래처럼 바꿔서 입력해 보자.

```text
너는 보안 면접관이다.
SQL 인젝션에 대해 신입 개발자 면접에서 답할 수 있을 정도로 핵심만 정리해줘.
답변은 5개 bullet로 작성해줘.
```

또는

```text
너는 백엔드 개발 멘토다.
SQL 인젝션을 막는 코딩 습관을 예시와 함께 설명해줘.
```

### 실습 포인트

학생들은 같은 주제로 역할만 바꿔도 결과가 달라지는지 확인해야 함.

- 강사 역할: 이해 중심 설명
- 면접관 역할: 핵심 요약 중심
- 멘토 역할: 실무 조언 중심

### 역할을 부여할 때 좋은 표현

아래와 같은 문장은 실습에서 자주 쓸 수 있음.

- "너는 초보자를 가르치는 IT 강사다."
- "너는 친절한 Python 튜터다."
- "너는 실무 중심의 백엔드 개발자다."
- "너는 정보보안 컨설턴트다."
- "너는 보고서를 작성하는 기술 문서 전문가다."

## 6. 의미를 분명하게 전달하는 방법

### LLM은 "마음 읽기"를 하지 못함

학생들이 자주 하는 실수는 "내가 원하는 걸 AI가 알아서 이해하겠지"라고 생각하는 것임. 하지만 LLM은 문맥을 바탕으로 확률적으로 답을 생성할 뿐, 사용자의 숨은 의도를 완벽히 읽지 못함.

따라서 의미를 분명히 전달하려면 아래를 명확히 써야 함.

- 왜 필요한지
- 누구를 위한 답인지
- 어느 수준으로 설명할지
- 결과를 어떤 형태로 받을지

### 예시 1. 의미가 모호한 프롬프트

```text
네트워크 정리해줘.
```

이 프롬프트는 너무 넓음.

- 컴퓨터 네트워크 전체를 말하는지
- 시험 대비 요약인지
- 초보자용 설명인지
- 표가 필요한지

를 알 수 없음.

### 예시 2. 의미가 분명한 프롬프트

```text
너는 네트워크 기초를 가르치는 강사다.
비전공 대학생이 시험 전에 빠르게 복습할 수 있도록
컴퓨터 네트워크의 핵심 개념을 정리해줘.
다음 조건을 지켜줘.
1. 5개 주제로 나누기
2. 각 주제는 2문장 이내
3. 마지막에 꼭 외워야 할 키워드 5개 제시
```

### 왜 더 좋은가?

위 프롬프트는 다음을 분명히 알려줌.

| 요소 | 내용 |
| --- | --- |
| 역할 | 네트워크 강사 |
| 대상 | 비전공 대학생 |
| 목적 | 시험 전 빠른 복습 |
| 형식 | 5개 주제 |
| 제한 | 각 주제 2문장 이내 |
| 추가 요구 | 키워드 5개 |

### 학생 실습 과제

아래의 짧은 프롬프트를 더 좋은 프롬프트로 바꿔 보자.

| 원래 프롬프트 | 개선 목표 |
| --- | --- |
| "보안 설명해줘" | 초보자 대상, 핵심 개념 중심 |
| "파이썬 알려줘" | 입문자용, 단계별 학습 계획 포함 |
| "데이터베이스 요약해줘" | 시험 대비용, 표 형식으로 정리 |

## 7. 출력 형식까지 지정하기

### 왜 형식을 지정해야 할까?

LLM은 기본적으로 자유로운 문장으로 대답하려는 경향이 있음. 하지만 실습이나 과제, 보고서, 시험 정리에는 특정 형식이 더 유용함.

예를 들어 우리는 아래 형식을 원할 수 있음.

- 표 형식
- 번호 목록
- 단계별 절차
- 체크리스트
- 코드 예시 포함

### 실습 1. 형식 없이 요청하기

```text
리눅스와 윈도우의 차이를 설명해줘.
```

### 실습 2. 표 형식으로 요청하기

```text
너는 운영체제 강사다.
리눅스와 윈도우의 차이를 초보자 눈높이에서 표로 정리해줘.
다음 항목을 포함해줘.
- 사용 목적
- 사용자 인터페이스
- 보안
- 비용
- 서버 활용도
```

### 실습 3. 단계별 절차 형식으로 요청하기

```text
너는 Python 튜터다.
Python 설치 후 첫 프로그램을 실행하는 과정을
학생이 따라할 수 있게 1단계부터 5단계까지 번호 목록으로 설명해줘.
각 단계는 2문장 이내로 작성해줘.
```

### 실습 4. 체크리스트 형식으로 요청하기

```text
너는 프로젝트 코치다.
웹 프로젝트를 시작하기 전에 준비할 항목을 체크리스트 형식으로 정리해줘.
기획, 개발, 테스트, 배포 준비를 모두 포함해줘.
```

### 핵심 정리

> 원하는 결과가 있다면, **내용만 말하지 말고 출력 형식까지 함께 지정하는 습관**이 중요함.

## 8. 제한 조건과 금지 조건 넣기

### 제한 조건이 필요한 이유

LLM은 요청이 없으면 장황하게 설명하거나, 반대로 너무 짧게 끝낼 수 있음. 따라서 길이, 수준, 포함 요소, 제외 요소를 적어 주는 것이 좋음.

### 예시 1. 길이 제한

```text
HTTP와 HTTPS의 차이를 설명해줘.
3문장 이내로 써줘.
```

### 예시 2. 포함 조건

```text
HTTP와 HTTPS의 차이를 설명해줘.
반드시 인증서와 암호화 개념을 포함해줘.
```

### 예시 3. 제외 조건

```text
HTTP와 HTTPS의 차이를 설명해줘.
전문 용어를 너무 많이 쓰지 말고, 수학적 설명은 제외해줘.
```

### 실습용 템플릿

```text
너는 [역할]이다.
[주제]를 [대상]이 이해할 수 있게 설명해줘.
다음 조건을 지켜줘.
1. [길이 제한]
2. [포함 요소]
3. [제외 요소]
4. [출력 형식]
```

### 학생 실습

다음 요구를 만족하는 프롬프트를 직접 작성해 보자.

- 역할: 정보보안 강사
- 주제: 방화벽
- 대상: 고등학생
- 길이: 4문장
- 포함: 실생활 예시 1개
- 형식: 마지막 문장에 요약 한 줄

## 9. 시스템 프롬프트(System Prompt)란?

### 시스템 프롬프트의 의미

> **시스템 프롬프트(system prompt)** 는 모델이 전체 대화에서 어떤 원칙과 역할을 기본적으로 따를지 정해 주는 상위 지시문임.

쉽게 말하면, 사용자 질문보다 한 단계 위에서 모델의 기본 행동 방향을 설정하는 문장임.

### 사용자 프롬프트와의 차이

| 종류 | 역할 |
| --- | --- |
| **시스템 프롬프트** | 모델의 기본 태도, 역할, 응답 원칙 설정 |
| **사용자 프롬프트** | 지금 당장 수행할 구체적 작업 요청 |

예를 들어 아래처럼 나눠 생각할 수 있음.

- 시스템 프롬프트: "너는 초보자를 가르치는 친절한 Python 강사다. 어려운 용어는 쉽게 설명한다."
- 사용자 프롬프트: "리스트와 튜플의 차이를 설명해줘."

### 왜 시스템 프롬프트가 중요한가?

시스템 프롬프트를 잘 설정하면 여러 질문을 이어가더라도 응답 스타일을 어느 정도 일관되게 유지할 수 있음.

예를 들어 다음 상황에 유용함.

- 계속 초보자 수준으로 설명하게 하고 싶을 때
- 항상 표 형식으로 정리하게 하고 싶을 때
- 과도하게 어려운 용어를 쓰지 않게 하고 싶을 때
- 특정 역할을 오래 유지하게 하고 싶을 때

### 시스템 프롬프트 예시

#### 예시 1. 초보자 강사형

```text
너는 초보자를 위한 친절한 IT 강사다.
모든 설명은 쉬운 한국어로 하고,
어려운 용어가 나오면 짧게 뜻을 덧붙여라.
답변은 가능한 한 구조적으로 정리하라.
```

#### 예시 2. 실습 코치형

```text
너는 학생 실습을 돕는 프로그래밍 코치다.
답변할 때는 항상 단계별 절차를 우선 제시하고,
필요하면 간단한 예제를 포함하라.
학생이 바로 따라 할 수 있게 설명하라.
```

#### 예시 3. 요약 전문가형

```text
너는 긴 문서를 짧고 명확하게 요약하는 도우미다.
핵심을 먼저 제시하고,
불필요한 장황한 설명은 줄여라.
```

### 중요한 점

시스템 프롬프트를 넣는다고 해서 모델이 항상 완벽히 따르는 것은 아님. 하지만 아무 설정 없이 쓰는 것보다 **일관된 결과를 얻는 데 훨씬 유리함**.

## 10. Ollama에서 시스템 프롬프트처럼 연습하는 방법

### CLI에서 가장 쉬운 연습 방법

Ollama CLI에서는 일단 사용자 프롬프트 안에 역할과 지침을 함께 써서 연습해 볼 수 있음.

예:

```text
너는 초보자를 위한 Python 강사다.
앞으로 내가 묻는 내용은 쉬운 한국어로 설명하고,
예제가 가능하면 같이 제시해줘.
리스트와 튜플의 차이를 알려줘.
```

이 방식은 엄밀한 의미의 분리된 시스템 프롬프트라기보다, **사용자 메시지 안에 시스템에 가까운 지침을 같이 넣는 연습**이라고 보면 됨.

### 반복 실습 방법

학생들은 아래 순서로 연습하면 좋음.

1. 역할 없이 질문하기
2. 역할을 넣고 다시 질문하기
3. 대상과 형식을 추가하기
4. 길이 제한과 포함 조건을 추가하기
5. 결과 차이 비교하기

### 실습 예제 세트

#### 1단계

```text
리스트와 튜플 차이 설명해줘.
```

#### 2단계

```text
너는 Python 강사다.
리스트와 튜플 차이를 설명해줘.
```

#### 3단계

```text
너는 Python 강사다.
초보자가 이해할 수 있게 리스트와 튜플의 차이를 설명해줘.
표로 정리해줘.
```

#### 4단계

```text
너는 초보자를 가르치는 Python 강사다.
리스트와 튜플의 차이를 표로 정리해줘.
다음 조건을 지켜줘.
1. 변경 가능 여부를 포함
2. 사용 예시를 포함
3. 마지막에 초보자가 자주 헷갈리는 포인트 1개 추가
```

학생들은 각 단계의 답변이 어떻게 달라지는지 반드시 비교해 보아야 함.

## 11. Python에서 시스템 프롬프트와 사용자 프롬프트 사용하기

### 가장 기본적인 예제

아래 예제는 Python 코드에서 `system` 역할과 `user` 역할을 함께 사용하는 방식임.

```python
from ollama import chat

response = chat(
    model='gemma3:4b',
    messages=[
        {
            'role': 'system',
            'content': '너는 초보자를 위한 친절한 Python 강사다. 어려운 용어는 쉽게 풀어서 설명해라.'
        },
        {
            'role': 'user',
            'content': '리스트와 튜플의 차이를 설명해줘.'
        }
    ]
)

print(response.message.content)
```

### 코드 해설

| 요소 | 설명 |
| --- | --- |
| `role='system'` | 모델의 기본 역할과 응답 원칙을 설정 |
| `role='user'` | 지금 수행할 실제 질문을 전달 |
| `messages` | 대화 메시지를 순서대로 전달 |
| `model='gemma3:4b'` | 사용할 로컬 LLM 지정 |

### 실습 1. 시스템 프롬프트를 바꿔 보기

아래의 시스템 프롬프트를 각각 적용해 보고 답변 차이를 비교해 보자.

#### 버전 A: 초보자 강사형

```python
{'role': 'system', 'content': '너는 초보자를 위한 친절한 Python 강사다. 쉬운 말로 설명하라.'}
```

#### 버전 B: 면접 대비형

```python
{'role': 'system', 'content': '너는 Python 면접 코치다. 핵심만 짧고 정확하게 정리하라.'}
```

#### 버전 C: 실무 개발자형

```python
{'role': 'system', 'content': '너는 실무 중심의 백엔드 개발자다. 설명할 때 코드 예시와 주의점을 포함하라.'}
```

### 관찰 질문

학생들은 아래 질문에 답해 보자.

- 어느 시스템 프롬프트에서 설명이 가장 쉬웠는가?
- 어느 시스템 프롬프트에서 가장 실무적인 느낌이 났는가?
- 같은 사용자 질문인데도 답변 구조가 달라졌는가?

### 실습 2. 사용자 프롬프트를 구체화하기

아래 코드는 시스템 프롬프트는 유지하고, 사용자 프롬프트만 더 구체화한 예시임.

```python
from ollama import chat

response = chat(
    model='gemma3:4b',
    messages=[
        {
            'role': 'system',
            'content': '너는 초보자를 위한 친절한 Python 강사다. 어려운 용어는 쉽게 풀어서 설명해라.'
        },
        {
            'role': 'user',
            'content': '리스트와 튜플의 차이를 표로 설명하고, 마지막에 어떤 상황에서 리스트를 쓰고 어떤 상황에서 튜플을 쓰는지 한 줄 조언을 추가해줘.'
        }
    ]
)

print(response.message.content)
```

### 핵심 포인트

여기서 중요한 것은 다음 두 가지가 함께 작동한다는 점임.

- 시스템 프롬프트: 전체 답변 스타일을 정함
- 사용자 프롬프트: 지금 필요한 작업의 구체적 내용을 정함

---
### 마무리

프롬프트 엔지니어링은 어려운 기술처럼 보일 수 있지만, 실제로는 **LLM에게 일을 잘 시키는 방법을 배우는 과정**이라고 생각하면 됨. 특히 Ollama처럼 로컬 LLM을 사용할 때는 같은 질문을 여러 번 바꾸어 실험하기 좋기 때문에, 학생들이 직접 프롬프트를 수정하며 비교해 보는 연습이 매우 효과적임.
