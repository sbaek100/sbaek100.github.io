# 프로그래밍 일반 기출 핵심 정리

2025년 2회 프로그래밍 일반은 코딩 자체보다 **운영체제 기초**, **언어 문법**, **번역 과정**, **기억장치 관리**를 정확히 구분하는 문제가 많았습니다.  
핵심요약집과 연결해 보면 특히 **스케줄링**, **페이지 교체**, **토큰**, **링커와 로더**, **C 언어 기본 문법**이 직접 출제되었습니다.


## 1. 운영체제는 스케줄링과 기억장치 관리가 핵심이다

41번은 선점 스케줄링이 아닌 것을 고르는 문제였고 정답은 **HRN(Highest Response-ratio)**입니다.  **응답비율이 가장 높은 작업을 다음에 실행하는 방식**
핵심요약집에서는 스케줄링 알고리즘을 선점형과 비선점형으로 구분해서 정리하는데, **RR**, **SRT**, **다단계 큐**는 선점형으로 자주 묶이고 **HRN**은 비선점형으로 묶입니다.

* RR(Round Robin)은 각 작업에 일정 시간만 CPU를 주고, 시간이 끝나면 다음 작업으로 넘기는 방식입니다. 그래서 실행 중간에 다른 작업으로 바뀔 수 있어 **선점형**
* SRT(Shortest Remaining Time)은 남은 실행 시간이 가장 짧은 작업을 우선 실행하는 방식입니다. 더 짧은 작업이 새로 들어오면 현재 작업을 멈추고 바꿀 수 있어서 **선점형**
* 다단계 큐(Multi-level Queue)는 작업을 여러 큐로 나누고, 큐 우선순위에 따라 CPU를 배정하는 방식입니다. 높은 우선순위 큐가 낮은 큐의 작업을 밀어낼 수 있어서 보통 **선점형**으로 봅니다.
* HRN(Highest Response-ratio Next)은 응답비율이 가장 높은 작업을 선택하는 방식입니다. 한 번 선택된 작업은 끝날 때까지 실행하므로 **비선점형**


42번은 빈 공간 30K, 16K, 50K 중에서 16K 작업을 어디에 넣을지 묻는 문제였습니다.  
이 경우 가장 알맞게 맞는 공간을 선택하는 **Best Fit**이 출제 포인트입니다. 

* 메모리 배치 방식 중 하나, 들어갈 수 있는 빈 공간 중에서 **가장 크기가 알맞은 곳**에 배치, 남는 공간을 최소화하려는 방식

- 페이지 크기가 커질수록 **내부 단편화**는 커집니다
- **LRU(Least Recently Used)**는 가장 오랫동안 사용하지 않은 페이지를 교체합니다

핵심 키워드:
- **HRN**
- **Best Fit**
- **LRU**
- **내부 단편화** : 메모리를 할당받았지만, 할당된 공간 안에서 일부가 남아 **사용되지 못하는 낭비**

## 2. 인터럽트는 원인을 기준으로 분류해야 한다

56번은 시스템 타이머 만료나 콘솔 인터럽트 키 입력에 의해 발생하는 인터럽트를 묻는 문제였습니다.  
이것은 **외부 인터럽트**입니다.

시험에서는 인터럽트를 입출력, 외부, SVC, 프로그램 검사 인터럽트처럼 나누어 놓고 헷갈리게 만듭니다.  
따라서 장치 이상, 타이머, 콘솔 신호처럼 프로그램 바깥에서 들어오면 **외부 인터럽트**로 정리하면 됩니다.

핵심 키워드:
- **외부 인터럽트**
- **타이머 인터럽트**
- **콘솔 인터럽트**

## 3. 토큰은 문법을 구성하는 최소 단위다

50번은 `a[index]=1+2;` 문장에서 **토큰** 개수를 묻는 문제였습니다.  
핵심요약집에서도 **토큰(Token)** 은 프로그램을 구성하는 최소 단위라고 설명합니다.

이 문장은 보통 다음처럼 나눕니다.

- `a`
- `[`
- `index`
- `]`
- `=`
- `1`
- `+`
- `2`
- `;`

즉 토큰 수는 **9개**입니다.  
토큰 문제는 실제 코딩 실력보다 **기호와 식별자를 어디까지 따로 보느냐**를 묻는 문제입니다.

핵심 키워드:
- **토큰**
- **최소 문법 단위**

## 4. 번역 과정은 컴파일러 -> 링커 -> 로더 순서로 이해해야 한다

54번은 프로그램 수행 순서를 묻는 문제였습니다.  
이 파트는 핵심요약집의 **링커**, **로더** 개념과 그대로 연결됩니다.

- **컴파일러**: 고급언어를 목적 프로그램으로 번역
- **링커**: 목적 프로그램과 라이브러리를 연결
- **로더**: 실행 프로그램을 메모리에 적재

따라서 순서는 **컴파일러 -> 링커 -> 로더**입니다.  
링커와 로더를 뒤집어서 외우면 시험에서 자주 틀립니다.

## 5. C 언어 기본 문법은 짧게 나오지만 자주 틀린다

52번은 **do~while** 문 설명 문제였습니다.  
핵심은 조건을 나중에 검사하므로 **최소 1번은 실행**된다는 점입니다. 그래서 "조건이 거짓인 동안 반복한다"는 식의 설명은 틀립니다.

58번은 C 언어에서 생략할 수 없는 것을 묻는 문제였고, 정답은 **main 함수**입니다.  
60번은 관계 연산자 **`!=`** 의 의미를 묻는 문제로, 뜻은 **같지 않다**입니다.

짧고 쉬워 보이는 문제지만, 이런 파트는 점수 확보용이라 오히려 더 중요합니다.

핵심 키워드:

- **최소 1회 실행**
- **main 함수**
- **!=**

## 6. 객체지향 언어의 장점도 기본 개념으로 정리해 두자

43번은 객체지향 프로그래밍 언어가 절차지향 언어보다 가지는 장점을 묻는 문제였습니다.  
핵심은 **유지보수성**과 **재사용성**입니다.

객체지향은 함수나 클래스 단위로 모듈화가 쉬워서 코드를 다시 쓰기 좋고, 수정이 필요한 범위를 줄이기 쉽습니다.  
그래서 시험에서는 보통 **재사용성**, **유지보수성**, **확장성** 쪽이 정답 포인트로 나옵니다.

핵심 키워드:
