# 📖 풀이 및 해설

---

### 문제 1 해설 — apt purge

**정답: ④ `apt-get purge vsftpd`**

| 명령 | 설명 |
|---|---|
| `apt-get remove` | 패키지 삭제 (설정 파일 **유지**) |
| `apt-get purge` | 패키지 + **설정 파일까지** 삭제 |
| `apt-get autoremove` | 의존성으로만 설치된 불필요 패키지 삭제 |

`erase`, `delete`는 apt-get에 없는 옵션임.

---

### 문제 2 해설 — 데비안 계열 패키지 관리

**정답: ③ dpkg, apt-get**

| 배포판 계열 | 저수준 도구 | 고수준 도구 |
|---|---|---|
| 데비안/우분투 | `dpkg` | `apt`, `apt-get` |
| 레드햇/CentOS | `rpm` | `yum`, `dnf` |
| SUSE | `rpm` | `YaST`, `zypper` |

---

### 문제 3 해설 — 온라인 vs 오프라인 패키지 관리

**정답: ④ dpkg**

- `dpkg` = **오프라인** 저수준 패키지 관리 도구 (저장소 연결 기능 없음)
- `dnf`, `apt-get`, `zypper` = 저장소에서 자동으로 패키지를 내려받는 **온라인** 도구

---

### 문제 4 해설 — SUSE 패키지 관리

**정답: ④ YaST, zypper**

YaST(Yet Another Setup Tool)는 SUSE Linux 전용 GUI/CLI 통합 관리 도구임.

---

### 문제 5 해설 — tar 압축 옵션

**정답: ④ `-J`**

| 옵션 | 압축 방식 | 확장자 |
|---|---|---|
| `-z` | gzip | `.tar.gz` |
| `-j` | bzip2 | `.tar.bz2` |
| `-J` | **xz** | `.tar.xz` |
| `-x` | e**x**tract (압축 해제 동작, 압축 방식 아님) |

---

### 문제 6 해설 — 압축 효율성 순서

**정답: ④ `.xz` > `.bz2` > `.gz`**

압축 효율(높을수록 파일 크기 작음):

```
xz > bzip2 > gzip
```

반대로 압축/해제 속도:

```
gzip > bzip2 > xz
```

---

### 문제 7 해설 — tar 파일 묶기

**정답: ④ `tar cvf source.tar *.c`**

- `-c` = create (생성)
- `-v` = verbose (목록 출력)
- `-f` = file (파일명 지정) → **반드시 바로 뒤에 파일명**
- 형식: `tar [옵션] 아카이브파일명 대상파일`

---

### 문제 8 해설 — tar gzip/bzip2 옵션

**정답: ④ ㉠ -z, ㉡ -j**

- `-z` = **gzip** 압축/해제
- `-j` = **bzip2** 압축/해제

---

### 문제 9 해설 — 소스 설치 순서

**정답: ④ `configure` → `make` → `make install`**

| 단계 | 설명 |
|---|---|
| `./configure` | 시스템 환경 검사, `Makefile` 생성 |
| `make` | 소스 컴파일 |
| `make install` | 컴파일된 바이너리를 시스템에 설치 |

---

### 문제 10 해설 — 데몬

**정답: ④ daemon**

- **데몬(daemon)**: 백그라운드에서 실행되며 직접적인 사용자 상호작용 없이 서비스를 제공하는 프로세스
- `inetd`/`xinetd`: 인터넷 슈퍼 데몬 (요청이 올 때만 서비스 실행)
- `standalone`: 항상 실행 중인 방식

---

### 문제 11 해설 — systemd PID

**정답: ④ ㉠ systemd, ㉡ 1**

- 현대 리눅스는 init 대신 **systemd**가 첫 번째 프로세스로 실행됨
- PID(Process ID) 1번은 모든 프로세스의 최상위 조상
- `ps -p 1` 로 확인 가능

---

### 문제 12 해설 — systemctl reload vs restart

**정답: ④ `systemctl reload 서비스명` — 서비스를 완전히 재시작한다.**

- `reload` = 서비스를 **중단하지 않고** 설정 파일만 다시 읽음 (nginx의 `nginx -s reload` 같은 방식)
- `restart` = 서비스를 **완전히 중지 후 재시작**

### 문제 14 해설 — inetd vs standalone

**정답: ④ inetd 방식이 standalone 방식보다 메모리 관리가 더 효율적이다.**

| 구분 | standalone | inetd |
|---|---|---|

### 문제 18 해설 — 로그인 셸 기록 파일

**정답: ② `/etc/passwd`**

`/etc/passwd`의 7번째 필드가 **로그인 셸**임:
```
root:x:0:0:root:/root:/bin/bash
                              ↑
                         로그인 셸
```

`/etc/shells`는 **사용 가능한 셸 목록**이고, 특정 사용자의 로그인 셸은 `/etc/passwd`에 있음.

### 문제 19 해설 — alias 무시하고 원래 명령 실행

**정답: ③ `\ls`**

```bash
alias ls='ls --color=auto'

ls          # alias가 적용된 ls 실행
\ls         # alias를 무시하고 원래 ls 실행
command ls  # 또 다른 방법
```

`\` (백슬래시)를 명령어 앞에 붙이면 alias를 우회함.

### 문제 22 해설 — du -s 옵션

**정답: ③ `du -s` 옵션은 하위 디렉터리를 포함한 전체 합계만 출력한다.**

- `-s`(summary): 하위 항목을 모두 합산해 **총합 하나만** 출력
- `-a`: 모든 파일을 개별 출력
- `df -i`: inode 사용량 확인 가능 (②번은 틀림)

### 문제 23 해설 — find -mtime

**정답: ③ `find . -mtime -7`**

| 옵션 | 의미 |
|---|---|
| `-mtime -7` | **7일 이내** 수정된 파일 (7일 미만) |
| `-mtime +7` | **7일 초과** 전에 수정된 파일 |
| `-mtime 7` | **정확히 7일 전**에 수정된 파일 |
| `-atime` | 접근(access) 시간 기준 |

### 문제 24 해설 — find -exec

**정답: ③ `-exec`**

```bash
find . -name "*.sh" -exec chmod +x {} \;
#                          ↑       ↑  ↑
#                       명령어   파일명  종료
```

- `{}` = 찾은 파일명이 들어가는 자리
- `\;` = 명령 종료 (파일 하나씩 실행)
- `+` = 파일을 묶어서 한 번에 실행

### 문제 30 해설 — daemon-reload

**정답: ③ 새로 추가하거나 수정한 유닛 파일을 systemd에 반영한다.**

```bash
# 유닛 파일 수정 후 반드시 실행해야 함
sudo systemctl daemon-reload

# 이후 서비스 재시작
sudo systemctl restart 서비스명
```

> `daemon-reload` 없이 유닛 파일을 수정하면 systemd가 변경 내용을 인식하지 못함.
